# 0.4.0 release notes draft

This draft preserves the final user-visible changes collected before the release workflow stopped using Changesets. The first planned Core target is `@defjs/core@0.4.0`. Packages remain independently versioned and tagged; a package appearing in this document does not mean that every package is published together or receives the same version bump.

## `@defjs/core`

### Breaking API changes

- `createClient` is the only client factory. `createHttpClient`, client snapshot helpers, `cloneClient`, and the global client getters, setters, and reset helper were removed.
- Import Core APIs from `@defjs/core`; `@defjs/core/http` is not a public package subpath.
- `Client.execute` now exposes command-specific HTTP, SSE, and WebSocket overloads. Execution options are passed as the second argument. Endpoints accept input only and no longer carry a `config` field.
- HTTP and SSE executions no longer accept an open-ended `context` bag. Use a static command `operation`, command headers, or a client scoped to the environment instead.
- `withSSEOptions` and `withWebSocketOptions` were removed. Configure transports with the individual option helpers.
- Struct decoding is strict and fail-fast. Required object fields and declared request sections must be present; nullable fields remain required, optional and nullish fields may be omitted, tuples require their exact length, and composite parsing stops at the first determined issue. Zero-value construction was removed, while `struct.or` and `struct.discriminatedUnion` remain available.
- `struct.parse(schema, input)` returns an error-first tuple and returns `undefined` for the value on failure. Struct error maps are scoped to each parse call, and `StructError.format()` and `flatten()` are safe for prototype-like property names.
- Responses are declared with one `output` Struct for the 2xx body and one `error` Struct for everything else. The status-keyed `output` table — both the `{ [status]: Struct }` map and the `{ status, body }[]` list — was removed, along with `RequestOutputShape` and `ResponseGroupItem`. `ok` is the only fork and only one side ever decodes; omitting a side means that body is never read at all.
- Failures are one closed `FaultCode` set shared by HTTP, SSE, and WebSocket. `RequestError`, `HttpStatusError`, `TransportError`, `DefinitionError`, the `kind` field, and the parallel `EventStreamErrorCode` set were all removed in favour of `Fault`, whose class is the segment before the first `_` in its code. `RESPONSE_VALIDATION_FAILED` and `UNDECLARED_STATUS` no longer exist: every non-2xx status is `HTTP_STATUS`, and unreadable bodies split into `RES_MEDIA_TYPE_INVALID`, `RES_DECODE_FAILED`, and `RES_STRUCT_MISMATCH`.
- A failed decode has no body, enforced by the type system rather than by convention. A decode fault's `response` is `HttpMeta`, which has no `body` field; a success carries `DecodedResponse<T>`. `SettledResponse` was replaced by `HttpResponse` for the wire shape transports produce.
- HTTP failure tuples are now `[error, undefined, undefined]`. The fault carries whatever response metadata existed, so it travels with the value you pass to a handler, log, or rethrow.
- The media type is checked **before** the body is read, so "I asked for JSON and received HTML" is one precise `RES_MEDIA_TYPE_INVALID` instead of a parser error — and the read, parse, and Struct are skipped entirely.
- `HttpResponse.error` and the `status: 0` transport-failure sentinel from `makeResponse` were removed, along with `MakeResponseOptions.error`. A transport failure is a fault, never a response. Interceptors that want to observe one wrap `next` in `try` / `catch`; a rejection that came from the transport stays a `NET_*` fault rather than being blamed on the interceptor.
- Fault factories are `createHttpStatusFault`, `createUndecodedHttpStatusFault`, `createDecodeFault`, `createNetworkFault`, and `createPreflightFault`, replacing `createHttpStatusError`, `createTransportError`, and `createDefinitionError`.
- Path placeholders accept raw values, reject empty and dot-segment values, and encode each segment exactly once.
- `build(request, input)` and the bound-view request plan were removed. An optional pure `builder(input)` returns `{ path?, query?, headers?, body? }`. Omitting `builder` is identity placement when the input already has that shape. `defineRequest`, `defineEventStream`, and `defineWebSocket` return endpoints (`RequestEndpoint`, `EventStreamEndpoint`, `WebSocketEndpoint`). Calling an endpoint returns a command; `client.execute(command, options)` runs it.
- `struct.request`, `struct.json`, and `struct.text` were removed. `struct.formData` and `struct.urlencoded` are object structs with a codec tag that applies only when that value is the body root. Inbound HTTP bodies and SSE handshake error bodies choose their representation from the struct kind: `string` is raw text, `blob` / `file` are blobs, `arrayBuffer` is bytes, and every other kind is JSON. SSE event data keeps `string` raw and JSON-parses every other kind. The `responseType` option was removed.
- `withQueryParamsSerializer` was replaced by `withQuerySerializer((query) => string)`. The function receives the encoded wire object. It is not called when the request has no query. A `URLSearchParams` returned by the builder skips it. Interceptors see `queryParams` as `new URLSearchParams(queryString)` unless the builder already returned that instance.
- WebSocket `incoming` and `outgoing` are each one struct. Message maps, the type envelope, `normalizeIncoming`, `normalizeOutgoing`, and `withWebSocketOnInvalidEvent` were removed. Invalid frames go to the session `onRuntimeError` listener and are not queued. Query placement uses the same rules as HTTP.
- When an SSE endpoint declares `error`, a startup failure is `Fault<TError>`. Omitting `error` keeps `Fault<undefined>`.

### Transport behavior and typing

- Responses with no declared Struct for the relevant side are cancelled instead of being downloaded. A declared `error` body keeps its decoded value on `HTTP_STATUS`, and the bundled 204 response contract is corrected.
- Unsafe HTTP methods are protected by configured XSRF handling.
- SSE streams close when their iterator returns. Startup data and terminal error codes are explicit, network and stream-read retries require `withSSEReconnect`, and lifecycle, parsing, queues, hook cancellation, and single-consumer violations fail deterministically.
- SSE endpoints expose explicit buffer and queue limits. Reconnect jitter now follows the WebSocket behavior, and shared reconnect wait/backoff replaces duplicate internal paths.
- WebSocket endpoints expose explicit incoming limits, while outgoing reconnect buffering defaults to disabled. Compatible WebSocket constructor implementations are accepted.
- Named SSE events form a discriminated union when no `default` Struct is declared. Numeric event keys use their wire-format string names, union event tables distribute correctly, inherited event properties are ignored, and `__proto__` event declarations must use a computed own property.
- Static `operation` identities are available on HTTP, SSE, and WebSocket definitions.
- Optional input fields may be omitted. A request-shaped input uses ordinary object fields named `path`, `query`, `headers`, and `body`. Mark a field `.optional()` when the caller may leave it out.
- Public declarations now export `StructInput`, `ObjectStruct`, `StructLike`, `StructMethods`, `BuilderInput`, `HttpRequestShape`, `EventStreamRequestShape`, and `WebSocketRequestShape`. `RequestStruct` was removed with `struct.request`. Typed `execute` diagnostics remain for packed consumers.
- Unused internal transport wrappers and the public `StreamRefState` declaration were removed.

## Framework adapters

- `@defjs/react` `ClientProvider` and the `@defjs/vue` plugin now require an existing `Client`. Applications own client creation, lifetime, requests, streams, and sessions.
- `@defjs/vue` no longer exposes `provideGlobalClient`; use `createClientPlugin(client)` or Vue's native `provide(HTTP_CLIENT, client)`.
- React and Vue continue to consume the same required Core peer range, `@defjs/core: ^0.4.0`.

## `@defjs/opentelemetry-server`

- HTTP, SSE, and WebSocket response hooks receive the original request. Static `operation` identities drive low-cardinality span names, attributes, and metrics.
- HTTP failures without a response are classified without a fabricated status code.
- WebSocket query propagation defaults to disabled and must be enabled explicitly after reviewing URL disclosure risks.
- Async hooks are observed without blocking transports or leaking rejected promises, and WebSocket telemetry classifies the discriminated close outcome directly.
- Transport configuration shares one public options shape, and internal URL joining reuses Core behavior.
- Core is a required peer with the range `^0.4.0`.

## Packages and documentation

- Published manifests point to built JavaScript and declaration entries. Packed-consumer verification installs all four tarballs outside the workspace, typechecks their public declarations, and runs a Bun 1.4 smoke test.
- Every package tarball retains that package's `README.md` and the repository `LICENSE`. Repository-wide `doc/` and examples are not copied into package tarballs; versioned guidance remains on the documentation site and in the source repository.
- Lifecycle, reliability, diagnostics, runtime, package-consumer, observability, and Vue reactive-cancellation guidance was updated for the final APIs above.
