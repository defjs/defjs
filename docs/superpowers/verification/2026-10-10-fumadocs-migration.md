## Incremental Acceptance for Navigation Feedback (2026-10-11)

Users reported that the home-page sidebar was not intuitive. This round only adjusted reading-area navigation: use native `DocsLayout` top tabs and remove the duplicate `links`; place the existing home page in the docs reading area, and order the sidebar as "Overview → Quick start → Chapter index → existing chapters/integrations". Recipes/API indexes are labeled "Overview" in their own sidebars. All URLs, all 11 languages, and the tutorial body text stay unchanged. Mobile continues to use the native reading-area dropdown, without rewriting the sidebar or adding a dependency.

In native Fumadocs 16.17.1, top tabs share `grid-area:main` with the body. On first enable, the background stretched to the full body height, pushing tab links off the first screen and covering content. An independent auto-height tabs row was added through `containerProps`, keeping native column widths; local CSS places the native tabs div in that row, with no fixed-height compensation and no dependency changes.

TDD evidence is kept in the same progress directory:

- `navigation-tree-red.log`: the original tree still had the home page plus three reading areas, four root nodes in total, and the regression failed; `navigation-tree-green.log`: 11 languages, 121 assertions passed, the URL set unchanged, the source tree not mutated, and home/quick start/chapter index trigger the docs tab's native active state.
- `navigation-browser-red.log`: the old site's home sidebar was missing "Overview", and both browsers failed.
- `navigation-layout-red.log`: the first-screen position regression actually got the tab at `y=2541.78`, above the 100px threshold. After the fix, tab/H1 being on the first screen was verified together with the JS/no-JS H1 center being hit by `elementFromPoint` on itself, so DOM visibility is not mistaken for user readability.
- Navigation tests wait until the target area's overview link has `data-active=true` before checking chapters, so waiting only for the URL does not read the old sidebar; clicks were not forced and errors were not filtered.
