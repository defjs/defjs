# الاتفاقيات الهندسية [#engineering-conventions]

سواء كنت تكتب يدوياً طبقة طلبات HTTP داخل تطبيق واجهة أمامية أو خلفية، أو تنشر حزمة TypeScript SDK رسمية لواجهة برمجة التطبيقات العامة لشركتك، فإن مشاريع Defjs تتبع البنية المعيارية ذاتها: **نماذج بيانات `struct` مشتركة (`models/`) مقترنة بتعريفات عمليات نقية (`services/`)**.

---

## 1. طريقتان لاستخدام Defjs

تتبنى معظم الفرق Defjs في أحد سيناريوهين. كلاهما ينظّم العقود داخل `models/` و`services/`، ويختلفان فقط في المكان الذي يُنشأ فيه `createClient(...)`:

| السيناريو                                                                                     | هيكل المجلدات                                                     | من يملك `createClient(...)`؟                                                       | الدليل                                            |
| :-------------------------------------------------------------------------------------------- | :---------------------------------------------------------------- | :--------------------------------------------------------------------------------- | :------------------------------------------------ |
| **[طبقة API داخل التطبيق](/ar/docs/application-api)** (طلبات HTTP والوقت الفعلي داخل المشروع) | `src/api/models/` + `src/api/services/` + `src/api/client.ts`     | تطبيقك (`src/api/client.ts` يُصدّر نسخة مفردة للمتصفح أو دالة مصنع لكل طلب في SSR) | [طبقة API داخل التطبيق](/ar/docs/application-api) |
| **[تصميم حزم SDK العامة](/ar/docs/public-sdk)** (حزمة npm خارجية لواجهات API العامة)          | `src/models/` + `src/services/` + `src/index.ts` (`package.json`) | تطبيق المستهلك الخارجي (حزمة SDK المنشورة لا تنشئ ولا تحتفظ بأي `Client`)          | [تصميم حزم SDK العامة](/ar/docs/public-sdk)       |

## 2. أربع اتفاقيات هندسية أساسية

### الاتفاقية 1: صدِّر دوال عمليات نقية، ولا تستخدم أصناف `Service`

تغلّف مولّدات OpenAPI التقليدية نقاط النهاية داخل أصناف `Service` ذات حالة أو ثابتة (`OrdersService.getOrder(id)` أو `new S3Client().send(...)`). في Defjs، كل عملية تُنشأ عبر `defineRequest` أو `defineEventStream` أو `defineWebSocket` هي بالفعل **دالة مستقلة قابلة للاستدعاء**:

```ts
// تجنّب: تغليف التعريفات داخل صنف أو كائن مساحة أسماء
export class OrdersService {
  // يخفي اشتقاق client(options) لكل استدعاء ويعطّل التقليم الشجري (tree-shaking) في أدوات الحزم
}

// الموصى به: تصدير تعريفات عمليات مستقلة من services/*.ts
export const getOrder = defineRequest({
  meta: { operation: "orders.get" },
  method: "GET",
  path: "/orders/:id",
  input: GetOrderInput,
  builder: (input) => ({ path: { id: input.id } }),
  output: Order,
  error: ApiError,
});
```

إن استدعاء العملية المصدَّرة مباشرةً (`await getOrder(client, { id: 42 })` أو `await getOrder(client({ signal }), { id: 42 })`) يحافظ على نمط استدعاء موحّد عبر كامل قاعدة الشفرة، ويتيح لأدوات تجميع الحزم استبعاد العمليات غير المستخدمة (tree-shaking) عند ضبط `"sideEffects": false`.

### الاتفاقية 2: تصدير `struct` و`Infer` بالاسم نفسه في `models/`

في ملفات `models/*.ts`، صدِّر كلاً من مخطط `struct` لوقت التشغيل ونوع TypeScript المستنتج منه تحت **المعرّف نفسه**. يدمج TypeScript تصريحات القيم والأنواع في النطاق ذاته، مما يتيح للمستدعين استيراد رمز واحد للتحقق وقت التشغيل وللتعليقات التوضيحية للأنواع الثابتة معاً:

```ts
import { struct, type Infer } from "@defjs/core";

export const Order = struct.object({
  id: struct.number(),
  customerName: struct.string().alias("customer_name"),
  totalCents: struct.number().alias("total_cents"),
});
export type Order = Infer<typeof Order>;
```

### الاتفاقية 3: أبقِ ملفات `services/*.ts` خالية من نسخ العميل

حتى عند كتابة [طبقة API داخل التطبيق](/ar/docs/application-api) ضمن مستودع واحد (`src/api/`)، **لا** تستورد `apiClient` داخل `src/api/services/*.ts` لتغليف تعريفاتك. إبقاء `services/*.ts` كتعريفات نقية يمنحك ثلاث مزايا فورية:

1. **اختبارات حتمية دون اتصال بالشبكة**: يمكن لاختبارات الوحدات تمرير `createClient(withEndpoint(...), withHTTPHandle(...))` محلي مباشرةً إلى أي عملية دون محاكاة الوحدات (module mocking).
2. **أمان في SSR والبيئات متعددة المستأجرين (Multi-tenant)**: يمكن لمحمّلات الخادم تمرير `Client` مخصّص للطلب يحمل ملفات تعريف الارتباط الخاصة بالمستخدم الحالي أو رمز المستأجر إلى تعريف العملية ذاته الذي تستخدمه مكوّنات المتصفح.
3. **الترقية دون تكلفة إلى حزمة مشتركة**: إذا قرر فريقك لاحقاً نقل `src/api/models/` و`src/api/services/` إلى حزمة مساحة عمل في مستودع أحادي (monorepo) أو حزمة npm SDK عامة، فلن يحتاج أي ملف عمليات إلى التعديل.

### الاتفاقية 4: افصل توزيع البيانات في `builder` عن سياسات المعترضات

ضع كل مسؤولية في طبقتها المخصّصة:

| المسؤولية                                                                                               | مكانها الصحيح                                                               | السبب                                                        |
| :------------------------------------------------------------------------------------------------------ | :-------------------------------------------------------------------------- | :----------------------------------------------------------- |
| توجيه معاملات المستدعي إلى `path` و`query` و`headers` و`body`                                           | دالة `builder` للعملية في `services/*.ts`                                   | دالة نقية متزامنة تعتمد فقط على `input` الحالي               |
| سياق يعرّفه التطبيق للمعترضات (`{ operation: "orders.create" }`)                                        | حقل `meta` للعملية في `services/*.ts`                                       | `{ [key: string]: unknown }`؛ داخلي فقط ولا يُرسل عبر الشبكة |
| عناوين URL الأساسية، وترويسات المصادقة (`Authorization` والتواقيع وXSRF)، وإعادة المحاولة، وتوزيع الحمل | `createClient(...)` في `client.ts`                                          | سياسة تنفيذ مرتبطة بالبيئة والجلسة                           |
| المهل الزمنية لكل استدعاء، والإلغاء (`signal`)، ونداءات تقدّم النقل                                     | استدعاء `client({ signal, onDownloadProgress })` مباشرةً عند موقع الاستدعاء | محصورة في استدعاء واحد دون تعديل العميل المشترك              |
