# معالجة الأخطاء

في Defjs، لا تؤدي إخفاقات الطلبات أو وسائل النقل أو فك الترميز إلى إلقاء استثناءات (exceptions) عند نقطة الاستدعاء. بل تُرجع كل عملية مصفوفة الخطأ أولاً (`[error, ...]`) حيث تكون قيمة `error` إما `null` أو كائن `Fault` محدد الأنواع (وهو نسخة أصلية من `Error` يتم تمييزها بخاصية `error.code`).

إساءة الاستخدام البرمجية هي الاستثناء. فهي ترفض عادةً بـ `TypeError` بدلًا من إرجاع `Fault`: خيار `signal` ليس `AbortSignal`، وعملية HTTP يكون `output` أو `error` فيها ليس `struct`، واستدعاء عملية بلا عميل.

### لماذا يحمل `error` بيانات الاستجابة الوصفية عند فشل طلبات HTTP

عند فشل طلب HTTP، يكون شكل مصفوفة النتائج `[error, undefined, undefined]`. وتُرفق أي بيانات وصفية استُلمت مع الاستجابة (`status`، و`statusText`، و`headers`، و`url`) مباشرة بكائن `error.response` حتى تتمكن من تمرير كائن `error` بمفرده إلى مسجل السجلات أو معالج الأخطاء دون فقدان السياق.

## 2. فئات الأخطاء ومجموعة الرموز المغلقة

تُحدد البادئة التي تسبق أول شرطة سفلية `_` فئة الخطأ (`HTTP`، و`REQ`، و`NET`، و`RES`، و`EXT`، و`CAP`، و`ENV`)، بينما يشكل رمز `code` الكامل اتحاداً مغلقاً يتيح استخدام جمل `switch` الشاملة:

| الفئة  | رموز الأخطاء                                                           | المعنى وطريقة المعالجة                                                                                                                                                                                                                                                                                                       |
| ------ | ---------------------------------------------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `HTTP` | `HTTP_STATUS`                                                          | أجاب الخادم بحالة غير `2xx` (`3xx` أو `4xx` أو `5xx`) وفُك ترميز بنية `error` المعلنة إن وجدت.                                                                                                                                                                                                                               |
| `REQ`  | `REQ_INPUT_INVALID`، `REQ_BUILD_FAILED`                                | فشل التحقق من مدخلات المستدعي، أو كان المسار/الرابط غير صالح، أو ألقت دالة `builder` استثناءً، أو تعذّر بناء الطلب (HTTP: تدفق الجسم مستخدم أصلًا، أو طريقة غير صالحة أو ممنوعة، أو جسم GET/HEAD، أو `Content-Type` غير صالح؛ HTTP وSSE: عنوان URL فيه بيانات اعتماد، أو قيمة ترويسة ترفضها المنصة). لا تُعد المحاولة أبداً. |
| `RES`  | `RES_MEDIA_TYPE_INVALID`، `RES_DECODE_FAILED`، `RES_STRUCT_MISMATCH`   | خالفت استجابة الخادم نوع الوسائط المعلن، أو التمثيل، أو عقد بنية `struct`.                                                                                                                                                                                                                                                   |
| `NET`  | `NET_ABORTED`، `NET_TIMEOUT`، `NET_UNREACHABLE`، `NET_BODY_INCOMPLETE` | ألغى المستدعي الطلب (`NET_ABORTED`)، أو انتهت المهلة (`NET_TIMEOUT`)، أو فشل الاتصال، أو انقطع التدفق أثناء القراءة.                                                                                                                                                                                                         |
| `EXT`  | `EXT_INTERCEPTOR_FAILED`، `EXT_HOOK_FAILED`، `EXT_OBSERVER_FAILED`     | ألقى معترض تطبيق أو خطاف أو مراقب تقدم/حالة خطأه الخاص، أو مرّر معترض إلى `next()` إشارة `signal` ليست `AbortSignal`.                                                                                                                                                                                                        |
| `CAP`  | `CAP_BUFFER_EXCEEDED`                                                  | تجاوز المخزن المؤقت لإطار SSE حده المضبوط.                                                                                                                                                                                                                                                                                   |
| `ENV`  | `ENV_UNSUPPORTED`                                                      | تفتقر بيئة تشغيل المضيف إلى واجهات ويب برمجية مطلوبة (مثل تدفق جسم الطلب في Firefox).                                                                                                                                                                                                                                        |

يسمّي الرمز ما فشل، لا من وفّر القيمة. في HTTP، الطلب الذي لا تستطيع المنصة بناءه هو `REQ_BUILD_FAILED` سواء جاءت القيمة السيئة من `builder` أو من إعداد العميل أو من معترض. يطبّق SSE القاعدة نفسها على قيم الترويسات وعنوان URL غير الصالح وعنوان URL فيه بيانات اعتماد، في المحاولة الأولى وفي كل إعادة اتصال. تفحص المكتبة هذا الأخير بنفسها لأن Bun يقبل مثل هذا العنوان ويرسل الطلب. القيم الأخرى التي قد ترفضها المنصة لا تفحصها المكتبة على SSE وWebSocket (طريقة غير صالحة على SSE؛ وعنوان URL فيه بيانات اعتماد، أو بروتوكول فرعي غير صالح، أو مخطط غير مدعوم على WebSocket)، فيُبلَّغ الرفض هناك كـ `NET_UNREACHABLE` مع خطأ المنصة في `cause`، وبيئة التشغيل التي تقبل القيمة (Bun، لطريقة SSE غير صالحة) ترسل الطلب. يغطي `EXT_INTERCEPTOR_FAILED` سلوك المعترض نفسه: خطأ يرميه، أو `signal` ليس `AbortSignal` (قناة الإلغاء، لا محتوى الطلب).

### خصائص كائن الخطأ حسب الرمز

| رمز الخطأ     | `status`  | `response`                                      | `data`                              | `cause`                            |
| ------------- | --------- | ----------------------------------------------- | ----------------------------------- | ---------------------------------- |
| `HTTP_STATUS` | `number`  | `DecodedResponse<TErr>` أو `HttpMeta`           | بنية `error` مفكوكة، أو `undefined` | السبب الأساسي إن وجد               |
| `RES_*`       | `number`  | `HttpMeta` (**لا يوجد حقل `body`**)             | غير موجود                           | كائن `StructError` أو خطأ المحلل   |
| باقي الرموز   | غير موجود | `HttpMeta` إذا وصلت الترويسات، وإلا `undefined` | غير موجود                           | كائن `Error` الأساسي / سبب الإلغاء |

## 4. أخطاء بدء التشغيل مقابل أخطاء ما بعد الفتح في SSE وWebSocket

بالنسبة للاتصالات طويلة العمر، تُبلغ مصفوفة نتائج العملية عن إخفاقات **بدء التشغيل** فقط (قبل فتح التدفق أو المقبس). وبمجرد الفتح، تُسلّم الإخفاقات اللاحقة وقت التشغيل عبر المقبض أو دورة حياة الجلسة:

| وسيلة النقل   | إخفاق بدء التشغيل (يُرجع في المصفوفة)                                                                                                           | إخفاق ما بعد الفتح (بعد حل المصفوفة)                                                                                                                                                                                                                  |
| ------------- | ----------------------------------------------------------------------------------------------------------------------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| **HTTP**      | تُحل جميع الإخفاقات في مصفوفة العملية مرة واحدة.                                                                                                | لا ينطبق                                                                                                                                                                                                                                              |
| **SSE**       | استجابة غير `2xx` (`HTTP_STATUS`، أو خطأ الفك عندما يتعذّر فك جسم `error` المعلَن)، أو مصافحة `2xx` بنوع وسائط خاطئ (`RES_MEDIA_TYPE_INVALID`). | يرفض مكرر الأحداث غير المتزامن الاستمرار؛ وتُحل `stream.closed` بـ `{ kind: 'error', code }`.                                                                                                                                                         |
| **WebSocket** | إغلاق قبل الفتح، أو فشل دالة البناء، أو إلغاء أثناء المصافحة.                                                                                   | تُطلق أخطاء الإطارات غير الفادحة حدث `session.onRuntimeError`؛ بينما ترفض الأخطاء الفادحة `session.receive` وتُحل `session.closed` بـ `{ kind: 'error', cause }`. تحتفظ مهلة نبضات القلب وإعادات المحاولة المستنفدة بأسباب `Error` عادية وقت التشغيل. |
