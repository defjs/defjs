# تدفقات أحداث SSE (Server-Sent Events)

تُصرّح حزمة SDK عن نقطة نهاية Server-Sent Events باستخدام `defineEventStream`، حيث تُحدد المسار، والمدخلات الاختيارية مع دالة التجميع، وقاموس بنى الأحداث `events`، وحدود المخزن المؤقت وقائمة الانتظار. ويتولى التطبيق المستهلك ضبط المصادقة وخيارات إعادة الاتصال على عميله، وفتح التدفق، والتكرار على الأحداث محددة الأنواع، كما يملك مسؤولية إغلاق التدفق وتحرير موارده.

## 1. تعريف تدفق الأحداث واستهلاكه

احرص دائماً على تحرير مقبض التدفق المفتوح `EventStreamHandle` باستخدام `await using` (أو استدعاء `stream.close()` متبوعاً بـ `await stream.closed` داخل كتلة `finally`):

<Tabs items={["sdk/orders-stream.ts", "app/watch-orders.ts", "Single-file quick look"]}>
<Tab value="sdk/orders-stream.ts">

```ts
import { defineEventStream, struct } from "@defjs/core";

export const watchOrders = defineEventStream({
  path: "/orders/events",
  operation: "orders.watch",
  events: {
    updated: struct.object({
      id: struct.number(),
      status: struct.string(),
    }),
  },
});
```

</Tab>
<Tab value="app/watch-orders.ts">

```ts
import { createClient, withEndpoint } from "@defjs/core";
import { watchOrders } from "../sdk/orders-stream.ts";

const client = createClient(withEndpoint("https://api.example.com"));

async function main() {
  const [error, stream] = await watchOrders(client);
  if (error) {
    console.error(error.code);
    return;
  }

  await using active = stream;
  for await (const event of active) {
    console.log(event.event, event.data.id, event.data.status);
    break;
  }
}

void main();
```

## 2. مصافحة بدء الاتصال وشكل مصفوفة النتائج

لا ينتج عن استدعاء العملية مصفوفة `[error, stream, startupOpen]` إلا بعد التحقق من أن استجابة HTTP الأولية هي `2xx`، وتحمل نوع الوسائط `text/event-stream`، ولديها جسم قابل للقراءة:

- **مصافحة غير `2xx`**: تُرجع خطأ `HTTP_STATUS` (مع فك ترميز كائن `error.data` عند الإعلان عن بنية `error` في التعريف).
- **نوع محتوى خاطئ أو جسم غير قابل للقراءة**: يُرجع خطأ `RES_MEDIA_TYPE_INVALID` أو `RES_DECODE_FAILED`.
- **الفرق بين `startupOpen` و`stream.open`**: يُمثل العنصر الثالث في المصفوفة (`startupOpen`) لقطة لاستجابة المصافحة الأولى؛ بينما يتحدث `stream.open` حياً إذا أُعيد اتصال التدفق لاحقاً.

## 3. توزيع الأحداث وفك ترميزها

عند وصول إطار SSE (المنتهي بسطر فارغ وفق معايير WHATWG):

1. **توجيه الحدث**: يحدد حقل `event:` القادم سلكياً البنية المطابقة من `events[eventName]`، ويتراجع إلى `events.default` إذا كانت معلنة. وإذا أُغفل حقل `event:`، تُعتمد القيمة الافتراضية `"message"`. ويتم إسقاط الأحداث غير المعلنة إذا لم تتوفر `events.default`.
2. **فك ترميز الحمولة**: يستلم مخطط `struct.string()` النص الخام في `data:`. وتُحلل أي بنية struct أخرى قيمة `data:` كـ JSON أولاً، ثم تتحقق من صحتها عبر المخطط.
3. **مراقبة الأحداث غير الصالحة**: تُسقط الأحداث غير الصالحة أو غير المعلنة دون إغلاق التدفق أو إنهاء عمله. يمكنك إرفاق `withSSEOnInvalidEvent(...)` على العميل لأغراض التشخيص المحدودة:

## 4. إعادة الاتصال وتتبع `Last-Event-ID` [#reconnect]

إعادة اتصال SSE هي ميزة **اختيارية صريحة (opt-in)**. فبدون ضبط `withSSEReconnect(...)`، يؤدي أي انقطاع في الشبكة أو خطأ في قراءة التدفق إلى إنهاء التدفق فوراً.

<include cwd>examples/sse/reconnect.ts#example</include>

- **ميزانية المحاولات (`attempts`)**: القيمة الافتراضية هي `3` عند تمرير كائن خيارات إلى `withSSEReconnect`. وتعيد المصافحة الناجحة ضبط عداد المحاولات وأس التراجع الزمني (backoff). ونهاية الملف الطبيعية من الخادم (EOF) **ليست** فشلاً ولا تُطلق إعادة الاتصال.
- **تتبع المؤشر (`Last-Event-ID`)**: يُعتمد المؤشر بمجرد تحليل السطر الفارغ المنهي للحدث، ويُرسل تلقائياً كترويسة `Last-Event-ID` عند إعادة الاتصال.
- **سلامة إعادة المحاولة للطرق متساوية الأثر (Idempotency)**: افتراضياً، تُعاد المحاولة تلقائياً للطرق المتماثلة فقط (`GET` و`HEAD` و`OPTIONS` و`PUT` و`DELETE`). أما الطرق غير المتماثلة (`POST` و`PATCH` — مثل طلبات التدفق في نماذج الذكاء الاصطناعي LLM) فلا يُعاد اتصالها إلا إذا أرجعت دالة رد النداء المخصصة `shouldReconnect` القيمة `true` صراحة. وتُستهلك أجسام الطلبات من نوع `ReadableStream` في المحاولة الأولى ولا يُعاد اتصالها أبداً.
- **مهلة المصافحة الزمنية (`connectTimeoutMs`)**: عند توفيرها يجب أن تكون محدودة وموجبة ولا تزيد على 2147483647 (حد المؤقت)؛ وإلا تُرجع العملية `REQ_OPTIONS_INVALID`. تقيّد زمن كل مصافحة بدءاً من استدعاء Fetch حتى استلام ترويسات الاستجابة دون تحديد المدة التي يظل فيها التدفق القائم مفتوحاً.

## 5. حدود المخزن المؤقت وقائمة الانتظار

يجب أن يكون كلا الحدين أعداداً صحيحة موجبة وآمنة. ويُعد تجاوز أيٍّ منهما خطأ فادحاً ينهي التدفق (يُحل `stream.closed` بـ `kind: "error"` ويرفض مكرر الأحداث الاستمرار — ولا تُسقط الأحداث بصمت أبداً):

| خيار التعريف    | ما يقيده الخيار                                                   | رمز الخطأ النهائي     |
| --------------- | ----------------------------------------------------------------- | --------------------- |
| `maxBufferSize` | بايتات إطار SSE غير المكتمل أو الزائد عن الحجم قبل السطر الفارغ   | `CAP_BUFFER_EXCEEDED` |
| `maxQueueSize`  | الأحداث التي تم التحقق منها وبانتظار المستهلك في حلقة `for await` | `CAP_QUEUE_OVERFLOW`  |

## 6. الإغلاق وتحرير الموارد [#close-and-dispose]
