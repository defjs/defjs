# البدء: تعريف SDK وتنفيذه في التطبيق [#البدء-طلب-http-واحد]

في هذا المثال ستصدّر تعريفًا محدَّد الأنواع لـ `GET /users/:id` بصفتك مؤلف SDK، ثم تنشئ Defjs Client في ملف مستقل بصفتك مطوّر التطبيق المستهلك. ابدأ بمعالج Fetch محلي لفحص `200` و`404` المعلَن. عند الانتقال إلى API حقيقي، غيّر إعداد Client في التطبيق مع الإبقاء على التعريف نفسه.

## الخطوة 1 — التثبيت

`@defjs/core` هو ESM ويعمل على Node.js أو Bun. يشغّل Node.js 22.18+ (أو 24+) ملف `.ts` مباشرة عبر type stripping؛ أما إصدارات 22.x الأقدم فتحتاج `--experimental-strip-types`. ضع `"type": "module"` في package.json. في المتصفح ما زلت تحتاج المُجمّع وFetch.

## الخطوة 2 — صدّر تعريف SDK [#الخطوة-2--عرّف-الطلب]

أنشئ `src/define-request.ts` ليصدّر SDK الدالة `getUser`. يعلن Struct المدخل القيمة التي يمرّرها المستدعي، ويحدّد `builder` موضعها في الطلب. هنا يُمرَّر المدخل كاملًا بوصفه كائن المسار، فتملأ الحقول ذات القيم المفردة بلا alias الموضع `:id`. أبقِ عناوين الخدمة وبيانات الاعتماد الخاصة بالبيئة خارج التعريف.

<include cwd meta="src/define-request.ts">
  examples/start/define-request.ts#example
</include>

`output` هو جسم 2xx. `error` هو كل حالة أخرى. struct واحد لكل منهما. استخدم `struct.or(...)` أو اتحادًا مميّزًا عندما تختلف تلك الأجسام.

`defineRequest(...)` يُرجع نقطة نهاية. استدعاء `getUser(...)` يبني الأمر المعتم الذي ستمرّره إلى `client.execute(...)`. الـ `builder` أعلاه هو الدالة التي تضع المدخل؛ وليس نقطة النهاية.

## الخطوة 3 — نفّذ باستخدام Client التطبيق [#الخطوة-3--نفّذه-محليًا]

عند النجاح: `error` هو `null`، و`user` هو مخرج Struct لـ `200`، و`response` هو `DecodedResponse`. عند `404` معلَن: `error.code` هو `'HTTP_STATUS'`، و`error.status` هو `404`، و`error.data` محدَّد النوع كـ `NotFound`. العنصر الثاني في الـ tuple هو `undefined` عند الفشل.

## الخطوة 4 — وجّه إلى API حقيقي

عندما تنفّذ الخدمة `GET /v1/users/:id` بعقد الاستجابة نفسه، احذف `withHTTPHandle(...)` من إعداد التطبيق واضبط عنوان الأساس الحقيقي. احفظ المثال التالي في `src/real-api.ts` ليستورد التعريف نفسه من `./define-request.ts`. استبدل عنوان المثال بعنوان خدمتك.

## عندما تختلف النتيجة

- مدخل سيئ ← `REQ_INPUT_INVALID`؛ خيارات إلغاء متعارضة ← `REQ_OPTIONS_INVALID`؛ فشل
  `builder` → `REQ_BUILD_FAILED`
- حالة غير-2xx → `HTTP_STATUS`، مع `error.data` محدَّد النوع عند إعلان `error` وفكّ جسمه
- جسم JSON معلَن بنوع وسائط آخر ← `RES_MEDIA_TYPE_INVALID`، يُبلَّغ قبل قراءة الجسم
- جسم معلَن (`output` لـ 2xx، و`error` فيما عداها) لا يُفكّ ← `RES_DECODE_FAILED` أو `RES_STRUCT_MISMATCH`، أيًّا كانت الحالة
- فشل Fetch / إلغاء / مهلة ← `NET_UNREACHABLE` / `NET_ABORTED` / `NET_TIMEOUT`

يجب أن يكون `timeout` عددًا صحيحًا آمنًا موجبًا في `1..2_147_483_647`. أشكال الإلغاء الصالحة: `{ signal }`، `{ timeout }`، `{ abort }`، أو `{ signal, timeout }` / `{ signal, abort }`. `{ abort, timeout }` معًا غير صالح. الإلغاء يخبرك بما رآه المستدعي — لا ما إذا كانت كتابة الخادم قد اكتملت.
