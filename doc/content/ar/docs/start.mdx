# البدء: أول عملية في SDK [#getting-started-one-http-request]

ستكتب ملفين: وحدة SDK تصدّر `GET /users/:id`، وتطبيقًا يستوردها ويملك العميل. معالج Fetch المحلي يُبقي التشغيل الأول دون شبكة. ثم يعمل تعريف API نفسه مع عميل موجَّه إلى خدمتك.

## الممارسة الموصى بها

يبقى التعريف مستقلاً عن العميل. استدعِ العملية بعميل التطبيق، كما في `getUser(client, { id: 7 })`. لا وسيط ثالث للخيارات. استدعاء العملية يبدأها؛ و`await` ينتظر فقط. يملك التطبيق أيضًا عنوان الخدمة وبيانات الاعتماد. افحص صف error-first أولًا. عندما تكون `error` موجودة، أبلغ `error.code` وعُد من الدالة قبل قراءة قيمة النجاح.

## الخطوة 1 — التثبيت

`@defjs/core` هو ESM ويعمل على Node.js أو Bun. يشغّل Node.js 22.18+ (أو 24+) ملف `.ts` مباشرة عبر type stripping؛ أما إصدارات 22.x الأقدم فتحتاج `--experimental-strip-types`. أبقِ `"type": "module"` في package.json. في المتصفح ما زلت تحتاج المُجمّع وFetch.

```sh
bun add @defjs/core
```

## الخطوة 2 — عرّف الطلب

أنشئ `src/define-request.ts`. هذه وحدة مؤلف SDK: تصدّر `getUser` دون إنشاء عميل. struct المدخل هو قيمة المستدعي. يضع `builder` تلك القيمة على الطلب. هنا المدخل كاملًا هو كائن المسار، فتملأ الحقول ذات القيم المفردة بلا alias الموضع `:id`.

<include cwd meta="define-request.ts">
  examples/start/define-request.ts#example
</include>

`output` هو جسم 2xx. `error` هو كل حالة أخرى. struct واحد لكل منهما. استخدم `struct.or(...)` أو اتحادًا مميّزًا عندما تختلف تلك الأجسام.

`defineRequest(...)` يُرجع عملية. استدعاء `getUser(client, input)` يبدأ الطلب. الـ `builder` أعلاه هو الدالة التي تضع المدخل؛ وليس العملية. حيث يُعلَن `input`، يكون `builder` مطلوبًا ومتزامنًا ونقيًا.

## الخطوة 3 — استدعها محليًا

أنشئ `src/execute-locally.ts` بجانب التعريف. هذا هو التطبيق المستهلك: يستورد `getUser`، وينشئ عميله، ويوفّر معالج Fetch محليًا. يظل Defjs يتحقق من المدخل، ويبني `Request`، ويتفرّع بحسب الحالة، ويحلّل الجسم.

<include cwd meta="execute-locally.ts">
  examples/start/execute-locally.ts#example
</include>

شغّله:

```sh
bun src/execute-locally.ts
```

```txt
Loaded Ada from 200
```

جرّب مستخدمًا مفقودًا — غيّر معرّف المسار إلى `8` وشغّل مجددًا:

```txt
User not found
```

عند النجاح: `error` هو `null`، و`user` هو مخرج Struct لـ `200`، و`response` هو `DecodedResponse<User>`. عند `404` معلَن: `error.code` هو `'HTTP_STATUS'`، و`error.status` هو `404`، و`error.data` محدَّد النوع كـ `NotFound`. العنصر الثاني في الـ tuple هو `undefined` عند الفشل.

## الخطوة 4 — وجّه إلى API حقيقي

في `src/real-api.ts`، استورد `getUser` نفسه وأنشئ عميلًا بعنوان الأساس لخدمتك. شغّل هذه النسخة فقط بعد استبدال عنوان المثال بخدمة تنفّذ `GET /v1/users/:id` بتلك الأجسام.

<include cwd>examples/start/real-api.ts#example</include>

يبقى تعريف API في وحدة SDK. تبقى عناوين الخدمة وبيانات الاعتماد والمعترضات وعمر التنفيذ مع التطبيق. يستخدم العميلان عقد نقطة نهاية Defjs نفسه.

## انشر التعريف

انقل التعريف إلى حزمة SDK عندما تحتاجه تطبيقات أكثر. صدّر `getUser`، وأدرج تصريحات TypeScript، وأعلن إصدار Core المتوافق. يستورد المستهلكون بعد ذلك من الحزمة بدل `./define-request.ts`؛ ويبقى إعداد عميلهم ملكهم. اتبع [بناء SDK ونشره](/ar/recipes/publish-http-sdk) لإعداد الحزمة كاملًا.

## عندما تختلف النتيجة

- مدخل سيئ ← `REQ_INPUT_INVALID`؛ فشل `builder` ← `REQ_BUILD_FAILED`
- حالة غير-2xx ← `HTTP_STATUS`، مع `error.data` محدَّد النوع عندما يُعلَن `error` ويُفك جسمه
- جسم JSON معلَن بنوع وسائط آخر ← `RES_MEDIA_TYPE_INVALID`، يُبلَّغ قبل قراءة الجسم
- جسم معلَن (`output` لـ 2xx، و`error` فيما عداها) لا يُفك ← `RES_DECODE_FAILED` أو `RES_STRUCT_MISMATCH`، أيًّا كانت الحالة
- فشل Fetch / إلغاء / مهلة ← `NET_UNREACHABLE` / `NET_ABORTED` / `NET_TIMEOUT`

المهلة هي `client({ signal: AbortSignal.timeout(ms) })` وتُصنَّف `NET_TIMEOUT`. الإجهاض اليدوي هو `NET_ABORTED`. لا توجد مهلة افتراضية على مستوى العميل. اشتق عميلًا عندما يحتاج استدعاء واحد إلى `signal` خاص به؛ انظر [العميل](/ar/docs/client). يخبرك الإلغاء بما رآه المستدعي — لا ما إذا كانت كتابة الخادم قد اكتملت.
