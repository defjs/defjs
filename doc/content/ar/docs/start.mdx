# البدء السريع: عمليتك الأولى في حزمة SDK [#getting-started-one-http-request]

في هذا الدليل، ستنشئ وحدة SDK برمجية تعرّف العملية `GET /orders/:id` وتستدعيها من وحدتي تطبيق منفصلتين: الأولى تستخدم وسيلة نقل محلية للمحاكاة دون اتصال بالشبكة، والثانية تتصل بواجهة برمجة تطبيقات (API) حية.

## 1. تثبيت `@defjs/core`

حزمة `@defjs/core` هي حزمة ESM خالصة لا تحتوي على أي اعتماديات خارجية، وتعمل في المتصفحات وبيئات Bun وNode.js (الإصدارات 22.18+ أو 24+ تشغّل ملفات `.ts` مباشرة). تأكد من ضبط `"type": "module"` في ملف `package.json` لديك.

```sh
bun add @defjs/core
```

### كيف تعمل الملفات الثلاثة معاً

1. **`src/define-request.ts` (تعريف حزمة SDK)**:
   - يصرّح عن مخططات المدخلات `input`، والمخرجات `output` (لاستجابات النجاح `2xx`)، والأخطاء `error` (للاستجابات غير `2xx`) باستخدام `struct`.
   - يوفّر دالة بناء `builder` تزامنية ونقية تُحوّل `input` إلى `{ path }`. متى ما تم الإعلان عن `input`، يلزم تقديم دالة `builder` صريحة.
   - يصدّر العملية `getOrder` دون إنشاء أو التقاط أي عميل.
2. **`src/execute-locally.ts` (تنفيذ الاختبار دون اتصال بالشبكة)**:
   - يضبط عميلاً باستخدام `withHTTPHandle(...)` لتشغيل خط أنابيب Defjs بالكامل (التحقق من المدخلات، وتحديد الروابط، وتوزيع حالات الاستجابة، وتفكيك بنية كائنات الاستجابة) دون إجراء أي اتصال بالشبكة.
3. **`src/real-api.ts` (التنفيذ الفعلي للإنتاج)**:
   - يستورد نفس العملية `getOrder` تماماً ويستدعيها مقابل عنوان أساسي فعّال تم ضبطه عبر `withEndpoint(...)`.

## 3. تشغيل المثال المحلي

شغّل ملف `src/execute-locally.ts` باستخدام Bun:

```sh
bun src/execute-locally.ts
```

```txt
Loaded paid from 200
```

إذا قمت بتغيير المدخلات من `{ id: 7 }` إلى `{ id: 8 }`، فستُرجع المحاكاة استجابة `404`، وسيقوم Defjs بفك تشفير بنية `error` المعلنة ووضعها داخل `error.data`:

```txt
Order not found
```

## 4. فهم مصفوفة الخطأ أولاً (Error-First Tuple)

تُرجع كل عملية استدعاء لطلب HTTP مصفوفة من الشكل `[error, data, response]`:

- **عند النجاح بحالة `2xx`**: تكون قيمة `error` هي `null`، وتكون `data` هي القيمة المفكوكة والمطابقة لمخطط `output` المحدد (`Order`)، وتكون `response` من نوع `DecodedResponse<Order>`.
- **عند استلام حالة خطأ معلنة غير `2xx`**: يحمل `error.code` القيمة `'HTTP_STATUS'`، ويحتوي `error.status` على رقم الحالة (مثل `404`)، وتحتوي `error.data` على كائن الخطأ المطابق لمخطط `error` المعلن (`NotFound`).
- **عند حدوث أخطاء في المدخلات أو فك التشفير أو الشبكة**: يحدد رمز `error.code` المرحلة الدقيقة التي وقع فيها الفشل:
  - `REQ_INPUT_INVALID` / `REQ_BUILD_FAILED` — مدخلات مستدعي غير صالحة أو فشل/خطأ داخل دالة `builder`.
  - `RES_MEDIA_TYPE_INVALID` — تم استلام استجابة معلنة كـ JSON ولكن بترويسة `Content-Type` غير مطابقة لـ JSON (يتم الرفض قبل قراءة جسم الاستجابة).
  - `RES_DECODE_FAILED` / `RES_STRUCT_MISMATCH` — جسم الاستجابة غير قابل للقراءة أو غير متطابق مع مخطط البنية المعلن.
  - `NET_UNREACHABLE` / `NET_ABORTED` / `NET_TIMEOUT` — خطأ في وسيلة النقل، أو إلغاء يدوي للطلب، أو انتهاء المهلة المحددة عبر `AbortSignal.timeout(ms)`.

يمكنك تمرير مهلة زمنية أو إشارة إلغاء لكل استدعاء منفرد عبر اشتقاق عميل مخصص للاستدعاء: `getOrder(client({ signal: AbortSignal.timeout(5_000) }), { id: 7 })`.
