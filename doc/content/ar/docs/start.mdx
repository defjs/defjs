# البدء: طلب HTTP واحد

ستعرّف `GET /users/:id`، وتنفّذه عبر عميل صريح، وتفكك `200` و`404` المعلَن معًا. المعالج المحلي يبقي أول تشغيل دون شبكة؛ الأمر يبقى كما هو عندما تستبدل بخدمة حقيقية.

## الخطوة 1 — التثبيت

`@defjs/core` هو ESM ويعمل على Node.js أو Bun أو Deno. يشغّل Node.js 22.18+ (أو 24+) ملف `.ts` مباشرة عبر type stripping؛ أما إصدارات 22.x الأقدم فتحتاج `--experimental-strip-types`. ضع `"type": "module"` في package.json. في المتصفح ما زلت تحتاج المُجمّع وFetch.

## الخطوة 2 — عرّف الطلب

أنشئ `src/get-user.ts`. struct المدخل هو قيمة المستدعي. `builder` يضع تلك القيمة على الطلب. هنا المدخل كله هو كائن المسار، فالحقول ذات القيم المفردة (scalar) بلا alias تملأ `:id`.

<include cwd meta="get-user.ts">
  examples/start/define-request.ts#example
</include>

`output` هو جسم 2xx. `error` هو كل حالة أخرى. struct واحد لكل منهما. استخدم `struct.or(...)` أو اتحادًا مميّزًا عندما تختلف تلك الأجسام.

`defineRequest(...)` يُرجع نقطة نهاية. استدعاء `getUser(...)` يبني الأمر المعتم الذي ستمرّره إلى `client.execute(...)`. الـ `builder` أعلاه هو الدالة التي تضع المدخل؛ وليس نقطة النهاية.

## عندما تختلف النتيجة

- مدخل سيئ ← `REQ_INPUT_INVALID`؛ خيارات إلغاء متعارضة ← `REQ_OPTIONS_INVALID`؛ فشل
  `builder` → `REQ_BUILD_FAILED`
- حالة غير-2xx → `HTTP_STATUS`، مع `error.data` محدَّد النوع عند إعلان `error` وفكّ جسمه
- جسم JSON معلَن بنوع وسائط آخر ← `RES_MEDIA_TYPE_INVALID`، يُبلَّغ قبل قراءة الجسم
- جسم معلَن (`output` لـ 2xx، و`error` فيما عداها) لا يُفكّ ← `RES_DECODE_FAILED` أو `RES_STRUCT_MISMATCH`، أيًّا كانت الحالة
- فشل Fetch / إلغاء / مهلة ← `NET_UNREACHABLE` / `NET_ABORTED` / `NET_TIMEOUT`

يجب أن يكون `timeout` عددًا صحيحًا آمنًا موجبًا في `1..2_147_483_647`. أشكال الإلغاء الصالحة: `{ timeout }`، `{ abort }`، أو `{ signal, timeout }` / `{ signal, abort }`. `{ abort, timeout }` معًا غير صالح. الإلغاء يخبرك بما رآه المستدعي — لا ما إذا كانت كتابة الخادم قد اكتملت.
