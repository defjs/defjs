# تصميم حزم SDK العامة [#public-sdk-design]

عندما تنشر شركتك أو فريق المنصة حزمة TypeScript SDK رسمية للمطورين الخارجيين (على سبيل المثال: حزمة SDK لتخزين الكائنات، أو لبوابة دفع، أو لمنصة SaaS)، يجب أن **تعرّف حزمة SDK عقد الشبكة دون فرض بيئة التشغيل**.

باستخدام **حزمة SDK متوافقة مع Amazon S3 (`@company/s3-sdk`)** كمخطط عملي، يوضّح هذا الدليل كيفية تصميم حزمة SDK عامة متعددة الوحدات تضم `schema/` وعمليات كدوال نقية في `request/`.

---

## 1. لماذا تستفيد حزم SDK العامة من الفصل في Defjs

تحزم أدوات SDK التقليدية صنف عميل ثقيل (`new S3Client({ region, credentials })`) مرتبطاً بإحكام بأصناف الأوامر أو أصناف الخدمات الثابتة. إن بناء حزمة SDK العامة باستخدام `@defjs/core` يحل أربع مشكلات متكررة لمستخدميك الخارجيين:

1. **مرونة تعدد البيئات وصناديق الاختبار (Sandboxes)**: لأن `@company/s3-sdk` لا يربط أي نقطة نهاية أو عميل، يمكن للعميل توجيه تعريفات العمليات ذاتها إلى بيئة الإنتاج (`https://s3.us-east-1.amazonaws.com`)، أو بيئة الاختبار المرحلي، أو Cloudflare R2، أو حاوية MinIO محلية أثناء اختبارات التكامل المستمر (CI).
2. **تقليم شجري (Tree-shaking) بنسبة 100% في أدوات الحزم**: يضمن تصدير دوال نقية مستقلة (`listBuckets` و`listObjectsV2` و`getObject` و`putObject` و`deleteObject`) مع `"sideEffects": false` أن حزمة المتصفح التي تستدعي `getObject` و`putObject` فقط تستبعد كل نقطة نهاية ونموذج آخر.
3. **تحقق وقت التشغيل + أنواع ثابتة من مصدر واحد**: يحصل المستهلكون الخارجيون على كلٍّ من أنواع TypeScript وقت الترجمة (`Infer<typeof ...>`) والتحقق من الاستجابات والأخطاء وقت التشغيل (`struct`)، مما يحميهم من حمولات الشبكة غير المتوقعة ويحوّل حقول `snake_case` أو سلاسل تواريخ ISO تلقائياً.
4. **تحكم كامل في المصادقة وإعادة المحاولة والقياسات عن بُعد**: يربط العملاء معترضات تدوير بيانات الاعتماد الخاصة بهم، أو سياسات `withRetry(...)`، أو موزّعات الحمل متعددة المناطق (`withBalancer(...)`)، أو تتبّع OpenTelemetry على الخادم (`@defjs/opentelemetry-server`) على نسخة `Client` الخاصة بهم.

## 2. هيكل مجلدات الحزمة

قسّم حزمة SDK إلى `src/schema/` (هياكل البيانات) و`src/request/` (تعريفات عمليات نقية مجمّعة حسب المورد)، مع ملف تصدير مسطح `src/index.ts`:

```text
@company/s3-sdk/
├── src/
│   ├── schema/                 # 1. مخططات struct المشتركة + أنواع Infer<typeof ...>
│   │   ├── common.ts           #    StorageClass, S3Error
│   │   ├── bucket.ts           #    Bucket, ListBucketsOutput
│   │   └── object.ts           #    ObjectSummary, ListObjectsOutput
│   ├── request/               # 2. دوال defineRequest نقية حسب نطاق المورد
│   │   ├── buckets.ts          #    BucketInput, listBuckets, headBucket, deleteBucket
│   │   └── objects.ts          #    listObjectsV2, headObject, getObject, putObject, deleteObject
│   └── index.ts                # 3. تصديرات مجمّعة للاستيراد الجذري والقابل للتقليم الشجري
├── package.json                # sideEffects: false, peerDependencies: { "@defjs/core": "^0.8.0" }
└── tsconfig.json
```

### تصميم عقود عمليات مريحة للاستخدام

- **سطِّح مدخلات المستدعي ووزِّعها داخل `builder`**: في `putObject`، يمرّر المستدعون كائناً واحداً مريحاً (`{ bucket, key, body, contentType, storageClass }`). يقسّم `builder` المتزامن هذا المدخل إلى `path` (`:bucket/:key`) و`headers` (`content-type` و`x-amz-storage-class`) و`body` الثنائي (`Blob`). وفي `listObjectsV2`، يربط `builder` كلاً من `continuationToken` و`maxKeys` بمعاملات استعلام S3 المسماة `continuation-token` و`max-keys` إلى جانب `list-type: 2`.
- **طابق `output` مع حمولة الشبكة**:
  - **بيانات JSON مهيكلة (`listBuckets` و`listObjectsV2`)**: صرّح عن `struct.object(...)` مع تعيينات `.alias()` وحقول `struct.date()`.
  - **حمولة ثنائية (`getObject`)**: صرّح عن `output: struct.blob()` (أو `struct.arrayBuffer()`).
  - **متن فارغ (`headBucket` و`headObject` و`putObject` و`deleteObject`)**: احذف `output` حتى تنجح استجابات `HEAD` و`200` و`204` الخالية من البايتات دون محاولة فك ترميز JSON، بينما يظل بإمكان المستدعين قراءة ترويسات الاستجابة (`response.headers.get("etag")`) من الخانة الثالثة في الصف (tuple).

## 4. كيف يستهلك المطورون الخارجيون حزمة SDK الخاصة بك

تثبّت التطبيقات الخارجية `@company/s3-sdk` إلى جانب `@defjs/core`، وتضبط `Client` الخاص بها مع نقطة النهاية ومعترض التوقيع، وتستدعي العمليات المصدَّرة مباشرةً كدوال نقية. يتبع المثال معالجة الأخطاء بأسلوب Go: تجري `syncReport` ثلاثة استدعاءات، لذلك تسمي كل خطأ باسم خطوته (`putErr` و`listErr` و`getErr`)، وتُرجع مصفوفة يكون الخطأ في أولها، وتغلّف الخطوة الفاشلة بـ `new Error("put object", { cause: putErr })`، على غرار `fmt.Errorf("put object: %w", err)` في Go. أما `main`، وهي أعلى البرنامج، فهي وحدها من تعالج الخطأ بتسجيله:
