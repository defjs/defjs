# جلسات WebSocket

تُصرّح `defineWebSocket` عن عقد ثنائي الاتجاه لـ WebSocket في حزمة SDK الخاصة بك: قالب المسار، والمدخلات الاختيارية `input` ودالة `builder` (`path` و`query` فقط)، ومخططات الرسائل الواردة `incoming` والصادرة `outgoing`، وحدود قوائم الانتظار، والبروتوكولات الفرعية الثابتة. ويتولى التطبيق المستهلك ضبط نبضات القلب (heartbeat)، وإعادة الاتصال، وإدارة دورة حياة الجلسة وإنهائها عبر عميله.

## 2. التحقق من صحة الرسائل وقواعد الاتجاهين

- **الإطارات الواردة (`session.receive`)**: يتم فك ترميز إطارات النصوص، و`ArrayBuffer`، والمصفوفات ذات الأنواع، وإطارات `Blob` كـ UTF-8، ثم تحليلها كـ JSON، والتحقق منها مقابل مخطط `incoming`. تُبلَّغ أخطاء JSON أو عدم تطابق المخطط إلى `session.onRuntimeError` وتُسقط دون إغلاق الجلسة. خاصية `session.receive` مخصصة لمستهلك واحد فقط (single-consumer)؛ ويُلقي طلب مكرر ثانٍ خطأ `TypeError`.
- **الإطارات الصادرة (`session.send(payload)`)**: يتم التحقق منها تزامناً مقابل مخطط `outgoing`، وتطبيق `.alias()` والمحولات، وتسلسلها عبر `JSON.stringify`. وتُرسل فوراً إذا كانت الحالة `open`، أو تُوضع في قائمة الانتظار أثناء حالة `reconnecting` (إذا كانت `maxOutgoingQueueSize > 0`)، وتلقي استثناءً تزامناً إذا كانت الحمولة غير صالحة، أو كانت القائمة ممتلئة/معطلة، أو كانت الجلسة مغلقة.

## 3. حالة الجلسة والمراقبون (Observers)

| العضو                | الوصف                                                                                                 |
| -------------------- | ----------------------------------------------------------------------------------------------------- |
| `state`              | `'idle' \| 'connecting' \| 'open' \| 'reconnecting' \| 'closing' \| 'closed' \| 'aborted' \| 'error'` |
| `connection`         | لقطة حية لأحدث مقبس فيزيائي (`generation`، و`url`، و`protocol`، و`extensions`)                        |
| `bufferedAmount`     | عدد البايتات غير المرسلة على المقبس النشط (`0` عند انقطاع الاتصال)                                    |
| `receive`            | مكرر غير متزامن لمستهلك واحد للرسائل الواردة المعتمدة `incoming`                                      |
| `onStateChange(fn)`  | للاشتراك في تغييرات الحالة؛ يُرجع دالة إلغاء الاشتراك `unsubscribe`                                   |
| `onRuntimeError(fn)` | للاشتراك في أخطاء الإطارات والتحليل غير المتعلقة ببدء التشغيل؛ يُرجع دالة `unsubscribe`               |
| `closed`             | وعد (Promise) يُحل بالنتيجة النهائية للجلسة (`kind: 'closed' \| 'aborted' \| 'error'`)                |

## 4. إعادة الاتصال، نبضات القلب، وقوائم الانتظار

- **إعادة الاتصال**: الإعدادات الافتراضية عند التفعيل هي: `attempts: 3`، و`delayMs: 1000`، و`factor: 2`، و`maxDelayMs: 30000`، و`jitter: 0`. وكل فتح فيزيائي ناجح `open` يعيد ضبط ميزانية الانقطاع. وتُنفذ الدالة `beforeConnect({ attempt, signal })` قبل الاتصال الأولي وقبل كل محاولة إعادة اتصال.
- **مهلة المصافحة الزمنية (`connectTimeoutMs`)**: عند توفيرها يجب أن تكون محدودة وموجبة ولا تزيد على 2147483647 (حد المؤقت)؛ وإلا تُرجع العملية `REQ_OPTIONS_INVALID`. تحدّ البناء حتى `open` وتُمسح بعد المصافحة.
- **نبضات القلب (Heartbeat)**: ترسل بصفة دورية `message()` عبر بنية `outgoing` وتنتظر حتى `timeoutMs` لاستلام إطار يطابق شرط `isAck(msg)`. تُستهلك إطارات التأكيد المطابقة بواسطة مراقب نبضات القلب ولا تُمرر إلى `session.receive`. ويُعد تفويت الرد على نبضة القلب خطأ فادحاً ينهي الجلسة المنطقية: تكون `closed.kind` هي `"error"` و`closed.cause` هي `Error("WebSocket heartbeat timeout")` العادي؛ ولا يبدأ إعادة الاتصال. تتبع إخفاقات تسلسل نبضات القلب المسار الفادح نفسه مع سببها الأصلي.
- **حدود قوائم الانتظار**:
  - `maxIncomingQueueSize` (عدد صحيح موجب إلزامي): يقيّد الإطارات الخام التي تنتظر فك الترميز والرسائل المفكوكة التي تنتظر المستهلك معًا. يؤدي تجاوز الحد إلى إنهاء الجلسة بكائن Fault ذي الرمز `CAP_QUEUE_OVERFLOW` في `closed.cause`؛ ويُرسل السبب نفسه إلى `onRuntimeError` ويرفض `session.receive`. حافظ على استهلاك `session.receive` طوال فترة فتح الجلسة.
  - `maxOutgoingQueueSize` (عدد صحيح غير سالب اختياري، افتراضياً `0`): يخزن مؤقتاً استدعاءات `session.send()` فقط عندما تكون الحالة `state === 'reconnecting'` ويقوم بإرسالها وتفريغها قبل نشر حالة `open` التالية.

تستقبل `shouldReconnect` رمز الإغلاق الأصلي و`wasClean`. يمكن للخادم إكمال مصافحة إغلاق نظيفة برمز خطأ تطبيق `1011`، لذا لا تعني `wasClean === true` نجاح التطبيق. يسمح المثال صراحة بالرمز `1011`؛ اختر رموز التطبيق وفق بروتوكولك بدلاً من الاعتماد على `!wasClean` وحده.

## 5. البروتوكولات الفرعية والمصادقة [#protocols-and-authentication]

لا تدعم مقابس WebSocket في المتصفح ترويسات مصافحة مخصصة أو اعتباطية، لذا تُرجع دوال `builder` في WebSocket الموضعين `{ path?, query? }` فقط.

- **أسبقية البروتوكولات الفرعية**: يتجاوز `client({ protocols })` الإعداد `withWebSocketProtocols(...)`، والذي بدوره يتجاوز `defineWebSocket({ protocols })`.
- **تحويل الروابط**: يُحول Defjs تلقائياً `http:` ← `ws:` و`https:` ← `wss:` عند حل نقطة النهاية.
- **بيانات الاعتماد**: ينطبق `withCredentials(true)` على Fetch فقط (HTTP وSSE). قم بمصادقة مقابس WebSocket باستخدام ملفات تعريف الارتباط أو سياسات الجلسات أو البروتوكولات الفرعية أو تذاكر الاتصال قصيرة العمر — وتجنب وضع الأسرار الدائمة في معلمات الاستعلام.
- **`beforeConnect` ليس معدِّلاً للطلب**: يعمل تحليل المدخلات ودالة `builder` التزامنية النقية وسلسلة المعترضات مرة واحدة لكل عملية. إذا لم يستبدل معترض نقطة النهاية الأساسية للطلب، تعيد كل محاولة اتصال اختيار نقطة نهاية وتعيد بناء عنوان URL باستخدامها، لكنها تعيد استخدام المسار والاستعلام المبنيين وقائمة البروتوكولات الملتقطة. يُثبَّت عنوان URL قبل تشغيل `beforeConnect` لتلك المحاولة، سواء على نقطة النهاية نفسها أم بعد التبديل عند الفشل. لا يمكن لتغيير متغير في النطاق المغلق أو المدخلات أو مصفوفة البروتوكولات داخل الخطاف تقديم تذكرة جديدة للمصافحة الحالية. تبديل بيانات اعتماد عنوان URL أو البروتوكول الفرعي داخل جلسة واحدة غير مدعوم؛ احصل على بيانات الاعتماد الجديدة أولاً، ومرّرها كمدخلات أو إعدادات عميل إلى عملية جديدة، ثم تولَّ مسؤولية تنظيف الجلسة البديلة.

## 6. الإغلاق والمِلكية

استدعِ `session.close(code?, reason?)` (حيث يكون `code` هو `1000` أو ضمن المدى `3000..4999`، ولا يتجاوز `reason` 123 بايت UTF-8) وانتظر `await session.closed`، أو استخدم `await using`:

عندما يستنفد انقطاع إعادة الاتصال محاولاته، تنتهي الجلسة بـ `closed.kind: "error"`، ولقطة الإغلاق الأصلية (غالبًا الرمز `1006` لترقية اتصال فاشلة)، وخطأ النقل العادي في `closed.cause`؛ ولا تعرض رمزًا ثابتًا منفصلاً للاستنفاد. احرص دائماً على إلغاء اشتراك مستمعي `onStateChange` و`onRuntimeError` عند انتهاء دورة حياة المكون أو مهمة العمل الخلفية.
