# WebSocket

ينشر مؤلف SDK عبر `defineWebSocket` المسار ومواضع المدخلات وStruct للرسائل الواردة والصادرة. يضبط التطبيق عنوان الاتصال وتنفيذ WebSocket المناسب للمنصة وسياسة التنفيذ، ويتولى الإرسال والاستقبال وإنهاء الجلسة.

ابدأ ← استقبل ← أرسل ← أطلق بـ `await using`. أنت تملك إلغاء الاشتراك والتخلّص. يبقى `close()` / `closed` اليدوي متاحًا؛ والعملاء والمزوّدون والمعترضات لا تغلق الجلسات تلقائيًا.

## struct واحد لكل اتجاه

`incoming` هو struct واحد لكل إطار نص. `outgoing` هو struct واحد لـ `session.send(...)`. نمذج عدة أنواع بـ `struct.discriminatedUnion`. الـ alias على تلك الحقول هو اسم الحقل بصيغة النقل في الاتجاهين. لا يوجد غلاف نوع منفصل ولا مُطبّع.

```json
{ "type": "message", "text": "Hello" }
```

إطارات النص الواردة و`ArrayBuffer` والمصفوفات المُنمَّطة و`Blob` تُقرأ كـ UTF-8، ثم تُحلَّل JSON، ثم تُفحص مقابل `incoming`. JSON التالف وأعطال الـ struct تذهب إلى `session.onRuntimeError` ولا تُصفّ. الجلسة تبقى قائمة. الإطارات التي ليست نصًا أو بايتات أو `Blob` تُتجاهل. لا يوجد `withWebSocketOnInvalidEvent`.

`session.send(...)` يتحقق ويُسلسل بشكل متزامن: ترميز الـ struct، ثم `JSON.stringify`. يرسل فورًا عندما يكون مفتوحًا، ويصف أثناء `reconnecting` عندما يُفعَّل طابور صادر، ويرمي `InvalidStateError` عندما لا يكون قابلاً للكتابة. يرمي أيضًا عندما لا يوجد struct صادر، أو تفشل الحمولة في الـ struct، أو يكون الطابور الصادر معطّلًا أو ممتلئًا، أو يفشل الإرسال الأصلي. قائمة `protocols` الثابتة على التعريف هي عقد نقطة النهاية (مثل `graphql-transport-ws`). خيارات التنفيذ و`withWebSocketProtocols` ما زالا يستطيعان تجاوزها. وهذه الخيارات وحدها تختار البروتوكولات الفرعية: فالـ builder و`beforeConnect` والمعترضات لا تستطيع تغييرها، لذا يُمرَّر الرمز داخل بروتوكول فرعي كخيار `protocols` في `execute` لذلك الاستدعاء. الـ builder قد يُرجع `path` و`query` فقط.

بعد ترميز الـ struct، ترمي القيم التي لا يستطيع JSON تمثيلها بأمانة `TypeError` قبل الإرسال أو الدخول في طابور إعادة الاتصال: الأعداد غير المنتهية والدوال والرموز و`Map` و`Set` والتدفقات ونسخ الأصناف التي لا تملك تمثيل JSON. تتبع القيم المتداخلة القاعدة نفسها لأجسام HTTP JSON. ما زال `struct.number()` يقبل اللانهايات ويرفض `NaN`؛ وقبول قيمة في طبقة struct لا يجعلها JSON صالحًا. يستخدم النبض المُسلسِل نفسه؛ وفشل تسلسله ينهي الجلسة المنطقية.

`receive` لمستهلك واحد. طلب مكرّر ثانٍ يرمي `TypeError`.

## لقطات الحالة

| العضو                      | المعنى                                                                                              |
| -------------------------- | --------------------------------------------------------------------------------------------------- |
| `state`                    | `idle` أو `connecting` أو `open` أو `reconnecting` أو `closing` أو `closed` أو `aborted` أو `error` |
| `connection`               | أحدث اتصال مادي: `generation`، وURL، والبروتوكول المتفاوض، والامتدادات عند التوفر                   |
| `bufferedAmount`           | عدد البايتات الأصلية غير المرسلة، أو `0` بلا مقبس مادي                                              |
| `receive`                  | قابل للتكرار غير متزامن لمستهلك واحد من الرسائل الواردة المتحقَّق منها                              |
| `onStateChange(listener)`  | اشترك في انتقالات الحالة المنطقية؛ يُرجع إلغاء الاشتراك                                             |
| `onRuntimeError(listener)` | اشترك في أخطاء وقت التشغيل غير بدء التشغيل؛ يُرجع إلغاء الاشتراك                                    |
| `closed`                   | وعد لنتيجة الإغلاق النهائي المنطقي                                                                  |

`open` = المقبس المادي مفتوح. `reconnecting` يشمل التحضير + التأخير قبل البديل. `connection.generation` يزيد لكل مقبس مادي يصل إلى `open`. `session.connection` تتحدّث عند إعادة الاتصال. لا تحتفظ `startupConnection` في الـ tuple بلقطة أول اتصال ناجح إلا مع جلسة Defjs أصلية أو غلاف يمرّر كائن `connection` الحي نفسه. أما الجلسات المخصّصة والأغلفة التي تحوّل `connection` فتستخدم قيمة `connection` العامة الحالية للجلسة المُعادة. مشاركة `closed` لا تسمح بتجاوز تنقية URL أو ترشيح البيانات الوصفية، ولا يعيد Defjs بناء البيانات الوصفية للاتصال الأول من تحويلات اعتباطية.

فشل البدء ← `[error, undefined, connection?]`. فشل المُنشئ قبل الفتح قد يكون بلا اتصال؛ والمهلة/الإغلاق أثناء البدء قد يوفّران لقطة. بعد إرجاع الجلسة، تسير أخطاء وقت التشغيل عبر المراقبين و`receive` و`closed` — لا عبر tuple تنفيذ ثانٍ.

## أعد الاتصال

إعادة الاتصال اختيارية. بلا كائن `reconnect` ← الإغلاق المادي ينهي الجلسة المنطقية. عند الضبط، القيم الافتراضية هي `attempts: 3` و`delayMs: 1000` و`factor: 2` و`maxDelayMs: 30000` و`jitter: 0`. `attempts` هو عدد إعادات المحاولة المسموح به لكل انقطاع؛ ويعيد `open` الناجح ضبط هذا العدد وأُسّ التراجع. لذلك يبدأ كل انقطاع لاحق من جديد بإعادة المحاولة 1 وبأساس `delayMs`. `attempts: 0` يعطّل إعادة المحاولة. يقبل المسند الافتراضي كل نتيجة إغلاق غير يدوي ضمن العدد المسموح لذلك الانقطاع. لا تخضع الفتحات الناجحة المتكررة لحد إعادة محاولة طوال عمر الجلسة. المقبس الذي يُفتح بنجاح ثم يغلقه الخادم فورًا مرة أخرى قد يواصل إعادة الاتصال بتأخير الأساس (مع مراعاة jitter والحدود)، لأن كل فتح يعيد ضبط الميزانية؛ أوقفه بـ `shouldReconnect`.

<include cwd>examples/web-socket/reconnect.ts#example</include>

`shouldReconnect` يحصل على محاولة إعادة المحاولة التالية وسبب الإغلاق والرمز والسبب و`wasClean`. `session.close(...)` اليدوي لا يدخل المسند. رمي التحضير/السياسة ينهي الجلسة المنطقية بخطأ.

تذبذب تراجع WebSocket **ضربي** (`jitter: 0.2` يضرب الأساس المحدود بعامل بين `0.8x` و`1.2x` قبل التقريب). يُحدّ التأخير النهائي مرة أخرى بـ `maxDelayMs` وبحد مؤقت المنصة البالغ `2_147_483_647` مللي ثانية، لذلك قد يُقتطع الجزء الأعلى من ذلك النطاق. يبقى الأساس الصفري صفرًا؛ ويُحصر تجاوز النطاق الناتج عن أعداد صالحة بدل رمي استثناء. يستخدم SSE قاعدة التذبذب نفسها بين 0 و1. تُفحص خيارات إعادة الاتصال قبل المُنشئ: يجب أن يكون `attempts` عددًا صحيحًا آمنًا غير سالب؛ وأن يكون `delayMs` عددًا منتهيًا غير سالب؛ وأن يكون `maxDelayMs` عددًا منتهيًا غير سالب أو `Infinity` الموجبة، التي تزيل السقف المضبوط دون أن تلغي حد المنصة البالغ `2_147_483_647` مللي ثانية للتأخير النهائي؛ و`factor` منتهٍ وموجب؛ و`jitter` منتهٍ وبين 0 و1. تُعيد القيم غير الصالحة `REQ_OPTIONS_INVALID`. يعطّل `attempts: 0` في WebSocket المحاولات اللاحقة، لكن جميع حقول إعادة الاتصال المقدّمة صراحةً تظل خاضعة للتحقق قبل الاتصال الأول، كما في SSE.

`beforeConnect({ attempt, signal })` يعمل قبل المُنشئ الأولي وكل إعادة اتصال. مرّر إشارته إلى تحديث الرمز حتى يوقف الإلغاء التحضير والاتصال معًا.

## نبض القلب

اختياري عند التنفيذ أو نطاق العميل. الفاصل يرسل `message()` عبر الـ struct الصادر. `isAck(message)` الاختياري يتعرّف على إقرار — تلك الرسالة تمسح المهلة و**لا** تُسلَّم إلى `receive`.

<include cwd>examples/web-socket/heartbeat.ts#example</include>

`intervalMs` و`timeoutMs` يجب أن يكونا مؤقتين محدودين موجبين ≤ `2_147_483_647`. رسالة النبض يجب أن تكون صالحة للـ struct الصادر. التسلسل والإرسال الأصلي وتصنيف الإقرار وأعطال المهلة قاتلة للجلسة المنطقية — ولا تصبح إعادة اتصال عادية.

## الطوابير

| الإعداد                | القيمة المطلوبة                              | السلوك                                                                                                   |
| ---------------------- | -------------------------------------------- | -------------------------------------------------------------------------------------------------------- |
| `maxIncomingQueueSize` | عدد صحيح آمن موجب                            | يحد الرسائل المحلَّلة المنتظرة لـ `receive` والإطارات الخام المنتظرة للتحويل. الفيضان ← `state: 'error'` |
| `maxOutgoingQueueSize` | عدد صحيح آمن غير سالب اختياري؛ الافتراضي `0` | FIFO فقط بينما `state === 'reconnecting'`. ممتلئ/معطّل ← `send(...)` يرمي                                |

الإطارات الصادرة المصطفّة تُفرَّغ قبل أن ينشر المقبس البديل `open`. الإطارات المرسلة أصلًا على مقبس سابق لا تُعاد تلقائيًا أبدًا. طوابير إعادة الاتصال للرسائل التي ترسلها أثناء إعادة الاتصال — لا لإعادة بناء حالة التطبيق.

فيضان الوارد يمسح التسلسل المعلّق، ويفشل `receive`، ويوقف الجلسة، ويحل `session.closed` بـ `kind: 'error'`. أبقِ المستهلك سريعًا بما يكفي أو ارفع الحد من الحجم/الذاكرة المقاسة.

## البروتوكولات والمصادقة

`protocols` في التعريف، و`withWebSocketProtocols(...)` في العميل، و`protocols` في التنفيذ تضبط قائمة البروتوكول الفرعي للمُنشئ. الأسبقية: التنفيذ ← العميل ← التعريف. أول قائمة معرّفة تُنسخ للجلسة المنطقية وتُعاد استخدامها عند إعادة الاتصال.

مُنشئات WebSocket في المتصفح لا تقبل رؤوس مصافحة عشوائية، والـ builder لا يمكنه إرجاع `headers` أو `body`. Defjs تحوّل `http:` → `ws:` و`https:` → `wss:`، وترمّز عناصر المسار النائبة مرة واحدة، وتستخدم قواعد الاستعلام نفسها كـ HTTP: قيم مفردة (scalar) ومفاتيح مكررة افتراضيًا، و`withQuerySerializer` للكائنات المتداخلة، وبلا استدعاء للمُسلسِل عندما لا يوجد استعلام.

كما في HTTP وSSE، إذا كانت نقطة النهاية الأساسية غائبة أو نسبية أو غير صالحة، أو كان المسار غير قانوني، يفشل البناء بـ `REQ_BUILD_FAILED` قبل تشغيل أي معترض أو وسيلة نقل، حتى لو كان المعترض سيُنهي السلسلة مبكرًا. يجب أن يحتفظ URL المحلول بأصل نقطة النهاية الأساسية ويبقى ضمن مجلدها؛ وتُرفض محارف التحكم C0 (بما فيها tab وCR وLF) والشرطات المائلة العكسية و`?` و`#` والخروج من المجلد في المسار. تُرفض الأشكال الشبيهة بـ scheme والنسبية إلى البروتوكول حتى مع مسافات بادئة؛ ويُسمح بمسافة عادية داخل المسار وتُرسَل كـ `%20`. يُفحص `req.endpoint` النهائي للمعترض مقابل `req.baseEndpoint` النهائي بالقاعدة نفسها؛ ويُسمح باستبدال الأساس عمدًا بعنوان URL مطلق صالح آخر. لا تُعاد محاولة أخطاء URL الحتمية أبدًا.

`withCredentials(true)` هو بيانات اعتماد Fetch لـ HTTP/SSE — وليست مصادقة WebSocket. استخدم سياسة ملف تعريف ارتباط/جلسة مراجعة، أو بروتوكولًا فرعيًا، أو تذكرة اتصال قصيرة العمر. لا تضع بيانات اعتماد عامة أو أسرارًا طويلة العمر في سلسلة الاستعلام.

## الإغلاق والملكية

`session.close(code?, reason?)` يطلب إغلاقًا نهائيًا ويوقف النبض. الرمز يجب أن يكون `1000` أو `3000..4999`؛ والسبب ≤ 123 بايت UTF-8. وسائط الإغلاق غير الصالحة ترمي قبل تغيير الحالة. استخدمه مع `await session.closed` عندما تحتاج سبب إغلاق يدويًا أو النتيجة النهائية المنطقية.

يظل `signal` أو `abort` الممرَّر إلى `execute` مرتبطًا بالجلسة المفتوحة. بعد فتح الجلسة، الإجهاض بشكل مهلة (`TimeoutError` أو `ERR_TIMEOUT`) ينتهي كـ `kind` بقيمة `error` (`NET_TIMEOUT`). وأي سبب إجهاض آخر ينتهي كـ `kind` بقيمة `aborted`، ويرفض `receive` بذلك السبب نفسه لا بـ `AbortError` جديد.

<include cwd lang="typescript">
  examples/web-socket/closure-and-ownership.ts#example
</include>

`session.closed` هو لقطة النهاية المنطقية: `'closed'` أو `'aborted'` أو `'error'`، مع `code` / `reason` / `wasClean` أصلي اختياري و`cause` للإلغاء/الخطأ. حقول الإغلاق الأصلية المرصودة تفوز على احتياطي المالك المطلوب.

المتخلّص غير المتزامن القياسي يطلب إغلاقًا أصليًا بأفضل جهد، ثم ينتظر teardown المملوك لـ Defjs لدورة الحياة ومضخة الرسائل والمؤقت والمستمع والطابور ومرجع المقبس. إن لم يُرصد حدث إغلاق خلال ثانية واحدة، يُفرض الـ teardown وقد يرفض المتخلّص بـ `DOMException` اسمه `TimeoutError`؛ وهذا لا يثبت أن اتصال TCP المادي أُغلق. استدعاءات المتخلّص المتكررة تشترك في الـ teardown نفسه. تطبيقات الجلسة الهيكلية المخصصة يجب أن توفّر الآن عقد `[Symbol.asyncDispose](): PromiseLike<void>` نفسه.

## حد GraphQL

Defjs توفّر struct واردًا واحدًا، وstruct صادرًا واحدًا، ودورة حياة جلسة منطقية. وهي **لا** تنفّذ بروتوكول تطبيق WebSocket. ميزات GraphQL-over-WebSocket — تهيئة الاتصال، ومعرّفات العملية، و`next`/`error`/`complete`، والتخلّص، وإعادة تشغيل الاشتراك — خارج العقد الأساسي.

استخدم عميل بروتوكول مثل `graphql-ws` عندما يتطلب الخادم ذلك البروتوكول، أو نمذج الإطارات بـ `defineWebSocket(...)`. ضع بروتوكولًا فرعيًا ثابتًا مثل `graphql-transport-ws` على `protocols`. الـ struct وحده لا يتفاوض دلالات GraphQL.
