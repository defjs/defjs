# WebSocket

يعرّف SDK مسار عملية WebSocket ومدخلاتها والرسائل الواردة والصادرة وحد الطابور. يضبط التطبيق المستهلك عميله، ويستدعي العملية، ويختار خيارات الاتصال الخاصة بالاستدعاء على عميل مشتق. صدّر العملية إلى جانب عمليات HTTP أو SSE في SDK.

البدء ← الاستقبال ← الإرسال ← الإطلاق بـ `await using`. أنت تملك إلغاء الاشتراك والتخلص. يبقى `close()` / `closed` اليدويان متاحين؛ ولا يغلق العملاء والموفّرون والمعترضون الجلسات تلقائيًا.

## struct واحد لكل اتجاه

`incoming` هو struct واحد لكل إطار نصي. `outgoing` هو struct واحد لـ `session.send(...)`. نمذج عدة أنواع بـ `struct.discriminatedUnion`. alias على تلك الحقول هو اسم السلك في الاتجاهين. لا يوجد ظرف نوع منفصل ولا مطبّع.

```json
{ "type": "tick", "symbol": "ACME", "price": 142.5 }
```

تُقرأ إطارات النص الواردة و`ArrayBuffer` والمصفوفة محدَّدة النوع و`Blob` كـ UTF-8، ثم تُحلَّل JSON، ثم تُفحص مقابل `incoming`. يذهب JSON المشوّه وإخفاقات الـ struct إلى `session.onRuntimeError` ولا تُوضَع في الطابور. تبقى الجلسة قائمة. تُتجاهل الإطارات التي ليست نصًا أو بايتات أو `Blob`.

يتحقق `session.send(...)` ويسلسل بشكل متزامن: ترميز الـ struct، ثم `JSON.stringify`. يرسل فورًا عندما يكون مفتوحًا، ويضع في الطابور أثناء `reconnecting` عندما يكون طابور الصادر مفعّلًا، ويرمي `InvalidStateError` عندما لا يكون قابلًا للكتابة. ويرمي أيضًا عندما لا يوجد struct صادر، أو تفشل الحمولة في الـ struct، أو يكون طابور الصادر معطّلًا أو ممتلئًا، أو يفشل الإرسال الأصلي. قائمة `protocols` ثابتة على التعريف هي عقد نقطة النهاية (مثل `graphql-transport-ws`). ما زال يستطيع `protocols` على عميل مشتق و`withWebSocketProtocols` تغليبها. تلك الخيارات وحدها تختار البروتوكولات الفرعية: لا يستطيع الـ builder ولا `beforeConnect` ولا المعترضون تغييرها، فيُمرَّر الرمز داخل بروتوكول فرعي كـ `protocols` على العميل المشتق لذلك الاستدعاء. يجوز للـ builder إرجاع `path` و`query` فقط.

بعد ترميز الـ struct، ترمي القيم التي لا يستطيع JSON تمثيلها بأمانة `TypeError` قبل الإرسال أو دخول طابور إعادة الاتصال: الأعداد غير المحدودة والدوال والرموز و`Map` و`Set` والتدفقات ونسخ الأصناف بلا تمثيل JSON. تتبع القيم المتداخلة القاعدة نفسها لأجسام JSON في HTTP. ما زال `struct.number()` يقبل اللانهايات ويرفض `NaN`؛ وقبول قيمة في طبقة الـ struct لا يجعلها JSON صالحة. يستخدم النبض المسلسِل نفسه؛ وفشل تسلسله ينهي الجلسة المنطقية.

`receive` لمستهلك واحد. طلب مكرّر ثانٍ يرمي `TypeError`.

## لقطات الحالة

| العضو                      | المعنى                                                                                              |
| -------------------------- | --------------------------------------------------------------------------------------------------- |
| `state`                    | `idle` أو `connecting` أو `open` أو `reconnecting` أو `closing` أو `closed` أو `aborted` أو `error` |
| `connection`               | آخر اتصال فيزيائي: `generation` وعنوان URL والبروتوكول المتفاوض عليه والامتدادات عند توفرها         |
| `bufferedAmount`           | عدد البايتات الأصلية غير المرسلة، أو `0` بلا مقبس فيزيائي                                           |
| `receive`                  | قابل للتكرار غير متزامن لمستهلك واحد من الرسائل الواردة المتحقَّق منها                              |
| `onStateChange(listener)`  | اشترك في انتقالات الحالة المنطقية؛ يُرجع إلغاء الاشتراك                                             |
| `onRuntimeError(listener)` | اشترك في أخطاء وقت التشغيل التي ليست من البدء؛ يُرجع إلغاء الاشتراك                                 |
| `closed`                   | وعد لنتيجة الإغلاق النهائي المنطقي                                                                  |

`open` = فتح المقبس الفيزيائي. يشمل `reconnecting` التحضير + التأخير قبل البديل. يزيد `connection.generation` لكل مقبس فيزيائي يصل إلى `open`. يتقدّم `session.connection` عند إعادة الاتصال. يحفظ `startupConnection` في الـ tuple أول لقطة ناجحة فقط لجلسة Defjs أصلية أو غلاف يمرّر كائن `connection` الحي نفسه. تستخدم الجلسات المخصصة والأغلفة التي تحوّل `connection` بدل ذلك `connection` العام الحالي للجلسة المُرجَعة في الـ tuple. مشاركة `closed` لا تستطيع تجاوز تنظيف عنوان URL أو ترشيح البيانات الوصفية، ولا يعيد Defjs بناء بيانات أول اتصال الوصفية من تحويلات اعتباطية.

فشل البدء ← `[error, undefined, connection?]`. قد لا يكون لفشل المُنشئ قبل الفتح اتصال؛ وقد يوفّر الإجهاض أو الإغلاق أثناء البدء لقطة مع ذلك. بعد أن تُرجع الجلسة، تنتقل أخطاء وقت التشغيل عبر المراقبين و`receive` و`closed` — لا عبر tuple نتيجة ثانٍ.

## إعادة الاتصال

اضبط `connectTimeoutMs` داخل سياسة إعادة الاتصال لحدّ كل مصافحة من بناء المقبس إلى `open`. يجب أن يكون محدودًا وموجبًا؛ والقيم غير الصالحة تُرجع `REQ_OPTIONS_INVALID`. لا افتراضي له ويُمسح بعد المصافحة، فالجلسات القائمة لا تتأثر. تبلّغ المصافحة التي انتهت مهلتها عن `NET_UNREACHABLE` للموازن وتتبع ميزانية إعادة الاتصال القائمة؛ وتنتهي إعادات المحاولة المستنفَدة بـ `NET_TIMEOUT`.

إعادة الاتصال اختيارية. بلا كائن `reconnect` ← ينهي الإغلاق الفيزيائي الجلسة المنطقية. عند الضبط، الافتراضيات هي `attempts: 3` و`delayMs: 1000` و`factor: 2` و`maxDelayMs: 30000` و`jitter: 0`. `attempts` هي ميزانية إعادة المحاولة لكل انقطاع؛ ويعيد `open` الناجح ضبط الميزانية وأُس التراجع. لذلك يبدأ كل انقطاع لاحق من جديد بإعادة المحاولة 1 وأساس `delayMs`. تعطّل `attempts: 0`. يقبل المسند الافتراضي كل نتيجة إغلاق غير يدوية ضمن ميزانية ذلك الانقطاع. الفتحات الناجحة المتكررة ليس لها حد إعادة محاولة لعمر الجلسة. المقبس الذي يفتح بنجاح ويغلقه الخادم فورًا مرة أخرى يمكن أن يواصل إعادة الاتصال عند تأخير الأساس (مع مراعاة الاهتزاز والسقوف)، لأن كل فتح يصفّر الميزانية؛ استخدم `shouldReconnect` لإيقافه.

<include cwd>examples/web-socket/reconnect.ts#example</include>

يتلقى `shouldReconnect` محاولة إعادة المحاولة التالية وسبب الإغلاق والرمز والسبب و`wasClean`. لا يدخل `session.close(...)` اليدوي المسند. ينهي التحضير/السياسة الذي يرمي الجلسة المنطقية بخطأ.

اهتزاز التراجع في WebSocket **ضربي** (`jitter: 0.2` يوسّع الأساس المقيَّد بـ `0.8x`–`1.2x` قبل التقريب). يُقيَّد التأخير النهائي مرة أخرى عند `maxDelayMs` وحد مؤقت المنصة `2_147_483_647` مللي ثانية، فيمكن اقتطاع الجزء الأعلى من ذلك المدى. الأساس الصفري يبقى صفرًا؛ ويُثبَّت الفيض من أعداد صالحة بدل أن يرمي. تستخدم SSE قاعدة الاهتزاز 0–1 نفسها. تُتحقق خيارات إعادة الاتصال قبل المُنشئ: `attempts` عدد صحيح آمن غير سالب؛ ويجب أن تكون `delayMs` محدودة وغير سالبة؛ ويجب أن تكون `maxDelayMs` عددًا محدودًا غير سالب أو `Infinity` موجبًا، ما يزيل السقف المضبوط لا حد المنصة `2_147_483_647` مللي ثانية؛ و`factor` محدود وموجب؛ و`jitter` محدود وضمن 0–1. تُرجع القيم غير الصالحة `REQ_OPTIONS_INVALID`. تعطّل `attempts: 0` في WebSocket إعادات المحاولة اللاحقة، لكن كل حقول إعادة الاتصال الممرَّرة صراحةً ما زالت تُتحقق قبل الاتصال الأولي، كما في SSE.

يعمل `beforeConnect({ attempt, signal })` قبل المُنشئ الأولي وكل إعادة اتصال. مرّر إشارته إلى تحديث الرمز حتى يوقف الإلغاء التحضير والاتصال معًا.

## النبض

اختياري على العميل أو على عميل مشتق. ترسل الفترة `message()` عبر الـ struct الصادر. يتعرّف `isAck(message)` الاختياري على إقرار — تلك الرسالة تمسح انتظار الإقرار و**لا** تُسلَّم إلى `receive`. يُستبدل `heartbeat` كقيمة كاملة. `timeoutMs` هو مدة انتظار ذلك الإقرار. وهو ليس مهلة للطلب.

<include cwd>examples/web-socket/heartbeat.ts#example</include>

يجب أن يكون `intervalMs` و`timeoutMs` مؤقتين محدودين موجبين ≤ `2_147_483_647`. يجب أن تكون رسالة النبض صالحة للـ struct الصادر. إخفاقات التسلسل والإرسال الأصلي وتصنيف الإقرار والمهلة قاتلة للجلسة المنطقية — ولا تصبح إعادات اتصال عادية.

## الطوابير

| الإعداد                | القيمة المطلوبة                              | السلوك                                                                                                 |
| ---------------------- | -------------------------------------------- | ------------------------------------------------------------------------------------------------------ |
| `maxIncomingQueueSize` | عدد صحيح آمن موجب                            | يحد الرسائل المحلَّلة المنتظرة لـ `receive` والإطارات الخام المنتظرة للتحويل. الفيض ← `state: 'error'` |
| `maxOutgoingQueueSize` | عدد صحيح آمن غير سالب اختياري؛ الافتراضي `0` | FIFO فقط ما دام `state === 'reconnecting'`. الامتلاء/التعطيل ← يرمي `send(...)`                        |

تُفرَّغ إطارات الصادر في الطابور قبل أن ينشر المقبس البديل `open`. الإطارات التي أُرسلت أصلًا على مقبس سابق لا تُعاد تشغيلها تلقائيًا أبدًا. طوابير إعادة الاتصال للرسائل التي ترسلها أثناء إعادة الاتصال — لا لإعادة بناء حالة التطبيق.

يمسح فيض الوارد التسلسل المعلَّق، ويُفشل `receive`، ويوقف الجلسة، ويحل `session.closed` بـ `kind: 'error'`. أبقِ المستهلك سريعًا بما يكفي أو ارفع الحد من حجم/ذاكرة مقيسين.

## البروتوكولات والمصادقة

تضبط `protocols` في التعريف و`withWebSocketProtocols(...)` على العميل و`protocols` على العميل المشتق قائمة البروتوكول الفرعي للمنشئ. الأسبقية: العميل المشتق ← العميل ← التعريف. تستبدل القائمة المشتقة قائمة العميل؛ وهي لا تُلحَق. ينسخ `defineWebSocket` مصفوفة protocols عند إنشاء التعريف. ينسخها `withWebSocketProtocols` عند تطبيق الخيار، وينسخها `client({ protocols })` عند إنشاء قيمة العميل. لا يغيّر تعديل لاحق للمصفوفة الأصلية ذلك الحاوي الملتقَط. تُنسَخ القائمة المختارة لاستدعاء مرة أخرى للجلسة المنطقية وتُعاد استخدامها عند إعادة الاتصال. لا تُنشَر قيمة ليست مصفوفة بـ spread عند حد الالتقاط؛ وما زال التنفيذ يتحقق منها.

لا تقبل منشئات WebSocket في المتصفح رؤوس مصافحة اعتباطية، ولا يستطيع الـ builder إرجاع `headers` أو `body`. يحوّل Defjs `http:` ← `ws:` و`https:` ← `wss:`، ويرمّز عناصر المسار النائبة مرة واحدة، ويستخدم قواعد الاستعلام نفسها كما في HTTP: القيم المفردة والمفاتيح المتكررة افتراضيًا، و`withQuerySerializer` للكائنات المتداخلة، وبلا استدعاء للمسلسِل عندما لا يوجد استعلام.

كما في HTTP وSSE، تفشل نقطة النهاية الأساسية الغائبة أو النسبية أو غير الصالحة أو المسار غير القانوني بـ `REQ_BUILD_FAILED` أثناء البناء، قبل تشغيل أي معترض أو نقل، حتى لو كان المعترض سيُنهي السلسلة مبكرًا. يجب أن يُبقي عنوان URL المحلول أصل الأساس ويبقى تحت مجلده؛ وتُرفض محارف التحكم C0 (بما فيها tab وCR وLF) والشرطات المائلة العكسية و`?` و`#` والخروج من المجلد في المسار. تُرفض الأشكال الشبيهة بالمخطط والنسبية إلى البروتوكول حتى مع مسافات بادئة؛ ويُسمح بمسافة عادية داخل المسار وتُرسَل كـ `%20`. يُتحقق من `req.endpoint` النهائي للمعترض مقابل `req.baseEndpoint` النهائي بالقاعدة نفسها، لكن يجوز له استبدال الأساس عمدًا بعنوان URL مطلق صالح آخر. أخطاء URL الحتمية لا تُعاد محاولتها أبدًا.

`withCredentials(true)` هو بيانات اعتماد Fetch لـ HTTP/SSE — لا مصادقة WebSocket. استخدم سياسة ملف تعريف ارتباط/جلسة مُراجَعة، أو بروتوكولًا فرعيًا، أو تذكرة اتصال قصيرة العمر. لا تضع بيانات اعتماد عامة أو أسرارًا طويلة العمر في سلسلة الاستعلام.

## الإغلاق والملكية

يطلب `session.close(code?, reason?)` إغلاقًا نهائيًا ويوقف النبض. يجب أن يكون الرمز `1000` أو `3000..4999`؛ والسبب ≤ 123 بايت UTF-8. ترمي وسائط الإغلاق غير الصالحة قبل تغيير الحالة. استخدمه مع `await session.closed` عندما تحتاج سبب إغلاق يدوي أو النتيجة النهائية المنطقية.

تبقى إشارة `signal` الممرَّرة إلى العملية مرفقة بالجلسة المفتوحة وتغطي الاتصال كاملًا، بما فيه ما بعد فتحه. ينهيه إجهاض بشكل مهلة (`TimeoutError` أو `ERR_TIMEOUT`، بما فيه `AbortSignal.timeout(...)`) كـ `'error'` (`NET_TIMEOUT`). وأي سبب آخر ينهيه كـ `'aborted'`، ويرفض `receive` بذلك السبب نفسه، لا بـ `AbortError` جديد. لا توجد مهلة للبدء فقط. التطبيق الذي يريد واحدة ينشئ `AbortController` خاصًا به، ويجهضه بـ `new DOMException("...", "TimeoutError")` من مؤقت، ويمسح المؤقت بعد أن يُرجع `await`. انظر [SSE](/ar/docs/sse#close-and-dispose).

`session.closed` هو اللقطة النهائية المنطقية: `'closed'` أو `'aborted'` أو `'error'`، مع `code` / `reason` / `wasClean` الأصلية الاختيارية و`cause` للإجهاض/الخطأ. تغلب حقول الإغلاق الأصلية الملاحَظة على الاحتياط الذي طلبه المالك.

يطلب المتخلّص غير المتزامن القياسي إغلاقًا أصليًا بأفضل جهد، ثم ينتظر تفكيك دورة الحياة ومضخة الرسائل والمؤقت والمستمع والطابور ومرجع المقبس التي يملكها Defjs. إذا لم يُلاحَظ حدث إغلاق خلال ثانية واحدة، يُفرَض التفكيك وقد يرفض المتخلّص بـ `DOMException` باسم `TimeoutError`؛ وهذا لا يثبت أن اتصال TCP الفيزيائي أُغلق. تشترك استدعاءات المتخلّص المتكررة في التفكيك نفسه. يجب أن توفّر تطبيقات الجلسة الهيكلية المخصصة الآن عقد `[Symbol.asyncDispose](): PromiseLike<void>` نفسه.

## حد GraphQL

يوفّر Defjs struct واردًا واحدًا وstruct صادرًا واحدًا ودورة حياة جلسة منطقية. وهو **لا** ينفّذ بروتوكول تطبيق WebSocket. ميزات GraphQL عبر WebSocket — تهيئة الاتصال ومعرّفات العمليات و`next`/`error`/`complete` والتخلص وإعادة تشغيل الاشتراك — خارج العقد الأساسي.

استخدم عميل بروتوكول مثل `graphql-ws` عندما يتطلب الخادم ذلك البروتوكول، أو نمذج الإطارات بـ `defineWebSocket(...)`. ضع بروتوكولًا فرعيًا ثابتًا مثل `graphql-transport-ws` على `protocols`. الـ struct وحده لا يتفاوض على دلالات GraphQL.
