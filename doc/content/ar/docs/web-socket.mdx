# جلسات WebSocket

تُصرّح `defineWebSocket` عن عقد ثنائي الاتجاه لـ WebSocket في حزمة SDK الخاصة بك: قالب المسار، والمدخلات الاختيارية ودالة التجميع (`path` و`query` فقط)، ومخططات الرسائل الواردة `incoming` والصادرة `outgoing`، وحدود قوائم الانتظار، والبروتوكولات الفرعية الثابتة. ويتولى التطبيق المستهلك ضبط نبضات القلب (heartbeat)، وإعادة الاتصال، وإدارة دورة حياة الجلسة وإنهائها عبر عميله.

## 1. تعريف العقد وتشغيل الجلسة

صمّم أنواعاً متعددة للإطارات على `incoming` أو `outgoing` باستخدام `struct.discriminatedUnion(...)`. وحرّر كائن الجلسة `WebSocketSession` المُرجع باستخدام `await using` أو عبر الاستدعاء الصريح لـ `session.close()` متبوعاً بـ `await session.closed`:

<Tabs items={["sdk/ticks-socket.ts", "app/session.ts", "Single-file quick look"]}>
<Tab value="sdk/ticks-socket.ts">

```ts
import { defineWebSocket, struct } from "@defjs/core";

export const TickFrame = struct.discriminatedUnion("type", [
  struct.object({
    type: struct.literal("tick"),
    symbol: struct.string(),
    price: struct.number(),
  }),
  struct.object({
    type: struct.literal("subscribed"),
    symbol: struct.string(),
  }),
]);

export const SubscribeCommand = struct.object({
  type: struct.literal("subscribe"),
  symbol: struct.string(),
});

export const openTicker = defineWebSocket({
  path: "/market/ws",
  operation: "market.ticker",
  incoming: TickFrame,
  outgoing: SubscribeCommand,
  maxIncomingQueueSize: 64,
});
```

</Tab>
<Tab value="app/session.ts">

```ts
import { createClient, withEndpoint } from "@defjs/core";
import { openTicker } from "../sdk/ticks-socket.ts";

const client = createClient(withEndpoint("https://api.example.com"));

async function main() {
  const [error, session] = await openTicker(client);
  if (error) {
    console.error(error.code);
    return;
  }

  await using active = session;
  active.send({ type: "subscribe", symbol: "ACME" });

  for await (const message of active.receive) {
    if (message.type === "tick") {
      console.log(message.symbol, message.price);
      break;
    }
  }
}

void main();
```

## 2. التحقق من صحة الرسائل وقواعد الاتجاهين

- **الإطارات الواردة (`session.receive`)**: يتم فك ترميز إطارات النصوص، و`ArrayBuffer`، والمصفوفات ذات الأنواع، وإطارات `Blob` كـ UTF-8، ثم تحليلها كـ JSON، والتحقق منها مقابل مخطط `incoming`. تُبلّغ أخطاء JSON أو عدم تطابق المخطط إلى `session.onRuntimeError` وتُسقط دون إغلاق الجلسة. خاصية `session.receive` مخصصة لمستهلك واحد فقط (single-consumer)؛ وطلب مكرر ثانٍ يلقي خطأ `TypeError`.
- **الإطارات الصادرة (`session.send(payload)`)**: يتم التحقق منها تزامناً مقابل مخطط `outgoing`، وتطبيق `.alias()` والمحولات، وتسلسلها عبر `JSON.stringify`. وتُرسل فوراً إذا كانت الحالة `open`، أو تُوضع في قائمة الانتظار أثناء حالة `reconnecting` (إذا كانت `maxOutgoingQueueSize > 0`)، وتلقي استثناءً تزامناً إذا كانت الحمولة غير صالحة، أو كانت القائمة ممتلئة/معطلة، أو كانت الجلسة مغلقة.

## 3. حالة الجلسة والمراقبون (Observers)

| العضو                | الوصف                                                                                                 |
| -------------------- | ----------------------------------------------------------------------------------------------------- |
| `state`              | `'idle' \| 'connecting' \| 'open' \| 'reconnecting' \| 'closing' \| 'closed' \| 'aborted' \| 'error'` |
| `connection`         | لقطة حية لأحدث مقبس فيزيائي (`generation`، و`url`، و`protocol`، و`extensions`)                        |
| `bufferedAmount`     | عدد البايتات غير المرسلة على المقبس النشط (`0` عند انقطاع الاتصال)                                    |
| `receive`            | مكرر غير متزامن لمستهلك واحد للرسائل الواردة المعتمدة `incoming`                                      |
| `onStateChange(fn)`  | للاشتراك في تغييرات الحالة؛ يُرجع دالة إلغاء الاشتراك `unsubscribe`                                   |
| `onRuntimeError(fn)` | للاشتراك في أخطاء الإطارات والتحليل اللاحقة للبدء؛ يُرجع دالة `unsubscribe`                           |
| `closed`             | وعد (Promise) يُحل بالنتيجة النهائية للجلسة (`kind: 'closed' \| 'aborted' \| 'error'`)                |

## 4. إعادة الاتصال، نبضات القلب، وقوائم الانتظار

تُعد ميزتا إعادة الاتصال ونبضات القلب (Heartbeat) اختياريتين صراحة عبر خيارات العميل (`withWebSocketReconnect` و`withWebSocketHeartbeat`) أو عبر خيارات العميل المشتقة لكل استدعاء (`client({ reconnect, heartbeat })`):

- **إعادة الاتصال**: الإعدادات الافتراضية عند التفعيل هي: `attempts: 3`، و`delayMs: 1000`، و`factor: 2`، و`maxDelayMs: 30000`، و`jitter: 0`. وكل فتح فيزيائي ناجح `open` يعيد ضبط ميزانية المحاولات. وتُنفذ الدالة `beforeConnect({ attempt, signal })` قبل الاتصال الأولي وقبل كل محاولة إعادة اتصال.
- **مهلة المصافحة الزمنية (`connectTimeoutMs`)**: عند توفيرها يجب أن تكون محدودة وموجبة ولا تزيد على 2147483647 (حد المؤقت)؛ وإلا تُرجع العملية `REQ_OPTIONS_INVALID`. تحدّ البناء حتى `open` وتُمسح بعد المصافحة.
- **نبضات القلب (Heartbeat)**: ترسل بصفة دورية `message()` عبر بنية `outgoing` وتنتظر حتى `timeoutMs` لاستلام إطار يطابق شرط `isAck(msg)`. تُستهلك إطارات التأكيد المطابقة بواسطة مراقب نبضات القلب ولا تُمرر إلى `session.receive`. ويُعد تفويت الرد على نبضة القلب خطأ فادحاً ينهي الجلسة.
- **حدود قوائم الانتظار**:
  - `maxIncomingQueueSize` (عدد صحيح موجب إلزامي): يؤدي الفائض وتجاوز الحد إلى إنهاء الجلسة بخطأ `CAP_QUEUE_OVERFLOW`. حافظ على استهلاك `session.receive` طوال فترة فتح الجلسة.
  - `maxOutgoingQueueSize` (عدد صحيح غير سالب اختياري، افتراضياً `0`): يخزن مؤقتاً استدعاءات `session.send()` فقط عندما تكون الحالة `state === 'reconnecting'` ويقوم بإرسالها وتفريغها قبل نشر حالة `open` التالية.

## 5. البروتوكولات الفرعية والمصادقة [#protocols-and-authentication]

لا تدعم مقابس WebSocket في المتصفح ترويسات مصافحة مخصصة وعشوائية، لذا تُرجع دوال `builder` في WebSocket الموضعين `{ path?, query? }` فقط.

- **أسبقية البروتوكولات الفرعية**: يتجاوز `client({ protocols })` الإعداد `withWebSocketProtocols(...)`، والذي بدوره يتجاوز `defineWebSocket({ protocols })`.
- **تحويل الروابط**: يُحول Defjs تلقائياً `http:` ← `ws:` و`https:` ← `wss:` عند حل نقطة النهاية.
- **بيانات الاعتماد**: ينطبق `withCredentials(true)` على Fetch فقط (HTTP وSSE). قم بمصادقة مقابس WebSocket باستخدام ملفات تعريف الارتباط أو سياسات الجلسات أو البروتوكولات الفرعية أو تذاكر الاتصال قصيرة العمر — وتجنب وضع الأسرار الدائمة في معلمات الاستعلام.
