# المقارنة والمعمارية الهجينة

يقع Defjs عند نقطة التقاء منظومتين: **عملاء HTTP للمتصفح وNode** (`fetch` و`ky` و`ofetch` و`axios` و`openapi-fetch`) و**أطر عمل RPC القائمة على العقد أولاً (contract-first)** (`oRPC` وtRPC). يوضح هذا الدليل أين يتناسب كل خيار، ومتى يكون Defjs عبئاً غير ضروري، وكيف تجمع الفرق بينها في بيئات الإنتاج.

### متى تختار بديلاً آخر

- **اختر `fetch` الخام أو `ofetch` أو `ky`** عندما يستدعي التطبيق عدداً محدوداً من نقاط النهاية على نفس الأصل دون نشر حزمة SDK، ودون الحاجة إلى التبديل عند الفشل عبر خوادم متعددة أو التحقق من المخطط وقت التشغيل (~4–10 KB brotli).
- **اختر `openapi-fetch`** عندما تدير بالفعل أنواع `openapi-typescript` وتريد فقط أنواع وقت التصريف مع أغلفة Fetch طفيفة ودون فك ترميز سلكي وقت التشغيل.
- **اختر `oRPC` (أو Hono RPC)** لـ **تواصل الطرف الأول بين الواجهة الأمامية وBFF / RPC متكامل** حيث يمتلك فريقك كلاً من خادم TypeScript وعميل المتصفح ويريد استنتاج الإجراءات من الطرف إلى الطرف دون صيانة عقود HTTP منفصلة.

## مخطط BFF الهجين: oRPC / Hono على الحافة، وDefjs للخدمات الخلفية

النمط الإنتاجي الأوسع انتشاراً عند الأحمال العالية لا يضع Defjs في مواجهة `oRPC` أو `Hono` — بل يجمع بينهما عبر حد الثقة:

```txt
┌──────────────┐   First-party RPC (oRPC / Hono)   ┌─────────────────────────────────┐
│ Browser /    │ ────────────────────────────────▶ │ BFF (Hono / oRPC Server)        │
│ Mobile App   │ ◀──────────────────────────────── │                                 │
└──────────────┘                                   │  @defjs/core Client:            │
                                                   │  • undici.Pool handle           │
                                                   │  • p2cBalancer({                │
                                                   │      outlierDetection: {        │
                                                   │        halfOpen: true           │
                                                   │      }                          │
                                                   │    })                           │
                                                   │  • withRetry (429 / 503)        │
                                                   │  • bulkhead + idempotency       │
                                                   │  • @defjs/opentelemetry-server  │
                                                   └────────────────┬────────────────┘
                                                                    │
                                        Downstream REST / SSE / WS  │
                               ┌────────────────────────────────────┴────────┐
                               ▼                                             ▼
                    Third-party SaaS APIs                        Internal Microservices
                    (generated via @defjs/cli)                   (Nodes A, B, C failover)
```

في هذا التقسيم:

1. **المتصفح ↔ BFF** يستخدم `oRPC` أو `Hono` لتطوير سريع لواجهات RPC الداخلية.
2. **BFF ↔ الواجهات الخلفية** يستخدم `@defjs/core` (غالباً مع عمليات مولَّدة عبر `@defjs/cli` من مواصفات OpenAPI للمزودين، ومجمَّعة عبر [`undici.Pool`](/ar/recipes/undici-pool)) بحيث يُعزَل أي مثيل خلفي بطيء (`B`) أو مثيل مُقيَّد بالمعدل (`429` / `503`) (`C`) عبر `p2cBalancer` + `outlierDetection` قبل أن يستنزف سعة عمال BFF.

| البُعد                       | السيناريو                                                                                                                       | النتيجة البارزة                                                                                                                                                                                                                                                              | المنهجية وملاحظة الإنصاف                                                                                                                                                                                |
| ---------------------------- | ------------------------------------------------------------------------------------------------------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| المرونة عبر خوادم متعددة     | 200 استدعاء بتزامن 8 عبر سليم `A` (5 ms)، وذيل طويل `B` (40% عند 300 ms)، ومتقلب `C` (40% `503`، و40% `429` + `Retry-After: 1`) | `@defjs/core` (`p2c` + `outlierDetection` + `withRetry`): **نسبة نجاح 100.0%**، وتضخيم سلكي **1.03x**، و**11.01 ms p95** (`A:195 / B:3 / C:9`) مقابل `ky`: **81.5%**، و**1.49x**، و**1626.30 ms p95** (`A:67 / B:67 / C:163`) و`fetch` المجرد: **71.0%**، و**302.18 ms p95** | تُعاد تهيئة حالة PRNG وعدادات الخوادم الخلفية بشكل متطابق قبل تشغيل كل عميل؛ كما يتحقق `@defjs/core` من الاستجابات عبر `struct`.                                                                        |
