## اقرأ العطل قبل القيمة [#fault-first]

تُرجع كل عملية `[error, data, response]`. وقيمة النجاح لا معنى لها إلا عندما يكون العنصر الأول `null`.

فضّل:

```ts
const [error, order] = await getOrder(client, { id: 1 });
if (error) return handleOrderFault(error);
console.log(order.status);
```

تجنّب:

```ts
const [, order] = await getOrder(client, { id: 1 });
console.log(order.status); // order is undefined when the call failed
```

## ضيِّق بـ code ثم بالبيانات [#narrow]

يختار `fault.code` صنف الفشل. اقرأ `status` من أجل `HTTP_STATUS`، و`data` من أجل جسم خطأ مفكوك، و`response` من أجل البيانات الوصفية. ويحتفظ `cause` بفشل المحلّل أو النقل الأساسي؛ فلا تستبدله برسالة عامة.

```ts
if (error.code === "HTTP_STATUS" && error.status === 404) {
  console.log(error.data?.message);
}
```

تعني رموز `RES_*` أن الاستجابة لم تُقرأ كما أُعلنت. وتعني رموز `NET_*` أن الطلب لم يُنتج استجابة صالحة للاستخدام. لا تعِد محاولة فشل فك أو فشل عقد كما لو كان فشل شبكة.

## سجّل مرة واحدة عند الحد الذي يملك النتيجة [#logging]

سجّل في الطبقة التي تقرر ما يحدث بعد ذلك: معالِج الطلب أو مشغّل المهام أو حد الواجهة. استخدم إضافة OpenTelemetry أو معترضًا للقياس عن بُعد؛ ويبقى التعريف خاليًا من التسجيل. ونقِّح عناوين URL وسلاسل الاستعلام والرؤوس والأجسام قبل أن تصل إلى سجل.

## أعد المحاولة فيما يُؤمَن إعادة إرساله فقط [#retry]

لا يعيد Defjs محاولة HTTP من تلقاء نفسه. فإعادة المحاولة تنتمي إلى التطبيق أو إلى سياسة صريحة لتجاوز فشل نقاط النهاية. أعد محاولة طريقة آمنة أو عملية توثّق الخدمة أنها متماثلة. و`POST` قد يكون بدأ عملًا قابلًا للفوترة ليس آمنًا لتكراره دون عقد إعادة إرسال.

## لا تبتلع [#no-swallow]

إرجاع النجاح بعد خطأ يخفي عقدًا مكسورًا. حوّل العطل إلى نتيجة تطبيق، أو أعد رمي خطأ برمجي، أو أنهِ العملية بفشل محدَّد النوع. ولا تلتقط عطلًا فقط لتسجيله والمتابعة بقيمة غير معرّفة.
