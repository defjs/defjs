## املك المقبض [#ownership]

تدفق الأحداث أو جلسة WebSocket ملك للمستدعي الذي فتحها. أغلقها عندما ينتهي العمل، واستخدم `await using` عندما يملكها النطاق المحيط، فيُتخلَّص من المقبض على كل مسار خروج.

```ts
const [error, stream] = await deployEvents(client);
if (error) return;
await using ownedStream = stream;
for await (const event of ownedStream) {
  if (event.event === "line") console.log(event.data.text);
}
```

## اقرأ حتى الاكتمال أو EOF [#read-to-end]

حدث واحد ليس استجابة كاملة. في SSE، واصل القراءة حتى ينتهي التدفق أو يُجهض المستدعي أو تتولى سياسة إعادة الاتصال. وفي WebSocket، اقرأ طابور الاستقبال حتى تُغلق الجلسة أو يتوقف المستدعي.

## حدّد المخازن المؤقتة والطوابير [#bounds]

اضبط `maxIncomingQueueSize` لجلسات WebSocket و`maxBufferSize` / `maxQueueSize` لـ SSE. فالحدّ يحوّل المستهلك البطيء إلى عطل بدل نمو ذاكرة بلا سقف. اختر الحدّ من حجم الرسالة وسرعة المستهلك، ثم اختبر مسار الفيض.

## قرّر إعادة الاتصال وإعادة الإرسال صراحة [#reconnect]

إعادة اتصال SSE متوقفة حتى يفعّلها التطبيق. و`POST` أو أي طريقة غير متماثلة أخرى لا يُعاد إرسالها إلا إذا سمحت السياسة بذلك. ومحاولة بث فاشلة قد تكون بدأت عملًا على الخادم؛ اقرأ قواعد إعادة الاتصال في [تدفقات أحداث SSE](/ar/docs/sse) وقواعد إعادة الإرسال في [طلبات HTTP](/ar/docs/http) قبل تفعيل سياسة.

## أغلق، ولا تسرّب [#close]

يبدأ `close()` التفكيك؛ ويبلّغ `closed` عن الحالة النهائية. انتظر `closed` عندما تعتمد الخطوة التالية على تحرير النقل. والإجهاض ينهي العمل المحلي؛ لكنه ليس دليلًا على أن الخدمة أوقفت عملًا قبلته أصلًا.
