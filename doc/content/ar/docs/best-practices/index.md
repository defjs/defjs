هذه الممارسات ليست شرطًا لعمل Defjs. إنها تُبقي SDK متوقّع السلوك عندما يتشارك عدة أشخاص ملكية التعريف والتطبيق والنقل. تبدأ كل صفحة بقاعدة، وتعرض صيغة مفضّلة وأخرى يجب تجنّبها، وتشرح الحدّ الكامن خلفها.

## أبقِ التعريف والتنفيذ منفصلين [#definition-execution]

التعريف بيانات. يعلن الطريقة والمسار والمدخل والمخرج وعقد الخطأ. وهو لا ينشئ عميلًا، ولا يقرأ بيانات اعتماد، ولا يبدأ إدخالًا/إخراجًا. ينشئ التطبيق العميل ويستدعي العملية. واستدعاء العملية هو ما ينفّذ الطلب.

يتيح هذا الفصل شحن حزمة SDK بلا نقطة نهاية وبلا بيانات اعتماد، ويتيح تشغيل التعريف نفسه بنقاط نهاية مختلفة في متصفح أو خادم أو اختبار.

## أعلن المدخل وضعه صراحة [#input-builder]

يصف `input` القيم التي يوفّرها المستدعي. ويقرر `builder` أين تذهب كل قيمة: المسار أو الاستعلام أو الرؤوس أو الجسم. لا يُستنتج الموضع أبدًا من اسم حقل أو من قالب المسار.

`builder` دالة نقية متزامنة. تعمل وقت التنفيذ. وأي رمي فيها يصبح `REQ_BUILD_FAILED`.

## اقرأ خانة الخطأ أولًا [#error-first]

تُرجع كل عملية tuple يضع الخطأ أولًا. العنصر الأول عطل أو `null`. وإخفاقات الطلب والاستجابة والنقل لا تُرمى عند موقع الاستدعاء.

اقرأ العطل قبل استخدام قيمة النجاح. وضيِّق بـ `code`، ثم اقرأ الحقول التي تنتمي إلى ذلك العطل.

## التطبيق يملك العميل [#client-ownership]

يملك التطبيق نقطة النهاية وبيانات الاعتماد والمعترضات ووسائل النقل وعمر التدفقات والجلسات. ويملك SDK العقد. ويجوز للإضافات تمرير عميل التطبيق عبر شجرة إطار؛ لكنها لا تنشئ عميلًا ولا تخزّنه مؤقتًا.
