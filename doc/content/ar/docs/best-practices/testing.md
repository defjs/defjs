## احقن وسيلة النقل [#inject]

استخدم `withHTTPHandle` أو `withSSEHandle` أو `withWebSocketHandle` لاستبدال وسيلة نقل المنصة. فالعملية ما زالت تبني الطلب وتشغّل المعترضات وتفك الاستجابة، فيمارس الاختبار حد العقد الحقيقي.

```ts
const client = createClient(
  withEndpoint("https://fixture.invalid"),
  withHTTPHandle(async () => Response.json({ id: 7, status: "paid" })),
);
const [error, order] = await getOrder(client, { id: 7 });
expect(error).toBeNull();
expect(order?.status).toBe("paid");
```

## افحص الـ tuple لا الدواخل [#tuple]

افحص رمز العطل والقيمة المفكوكة. فالاختبار الذي يفحص استدعاء مساعد خاصًا أو تفصيل تنفيذ في وسيلة نقل ينكسر عندما يتغيّر التنفيذ دون تغيّر العقد. وعند وجود عطل، افحص `code` والحقول ذات الصلة وهوية `cause` عندما يكون السبب جزءًا من العقد.

## أبقِ تركيبات العقد حقيقية [#fixtures]

شغّل اختبار تكامل واحدًا على خادم حقيقي لكل وسيلة نقل عندما يمسّ التغيير بناء الطلب أو الفك أو تفكيك التدفق. واستخدم خوادم التركيب الموجودة أصلًا في المستودع بدل بروتوكول محاكاة ثانٍ. فالسلوك الخاص بالمتصفح ينتمي إلى مشروع متصفح؛ والسلوك الخاص بالخادم ينتمي إلى مشروع الخادم.

## اضبط الوقت صراحة [#time]

استخدم مؤقتات وهمية للمهل والتراجع وإعادة الاتصال والنبض. وتقدّم بالوقت بعد أن يحدث الحدث قيد الاختبار، وافحص مسار الشيفرة الذي كان يجب أن يعمل. لا تفحص أبدًا الزمن الفعلي المنقضي. ولمقبس حقيقي، انتظر حدثًا محددًا مثل `open` أو `closed` أو أول إطار.

## اختبر SDK كمستهلك [#consumer]

يجب أن يستورد اختبار SDK التعريفات التي يستوردها التطبيق، وينشئ عميلًا بوسيلة نقل الاختبار، ويستدعي العملية. ويجب ألا يعيد بناء الطلب يدويًا؛ فذلك يختبر الاختبار، لا SDK.
