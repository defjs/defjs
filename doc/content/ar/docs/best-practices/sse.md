## امتلك المقبض [#ownership]

تدفق الأحداث ملك المستدعي الذي فتحه. أغلقْه عندما ينتهي العمل، واستخدم `await using` عندما يملكه النطاق المحيط، حتى يُطلَق المقبض في كل مسار خروج.

```ts
const [error, stream] = await deployEvents(client);
if (error) return;
await using ownedStream = stream;
for await (const event of ownedStream) {
  if (event.event === "line") console.log(event.data.text);
}
```

## اقرأ حتى الاكتمال أو EOF [#read-to-end]

حدث واحد ليس استجابة كاملة. واصل القراءة حتى ينتهي التدفق، أو يُجهض المستدعي، أو تتولّى سياسة إعادة الاتصال الأمر. تعامل مع فشل القراءة كفشل نقل، لا كنهاية نظيفة.

## حدّد المخزن المؤقت والطابور [#bounds]

اضبط `maxBufferSize` و`maxQueueSize` وفق حجم الرسالة وسرعة المستهلك. فالحد يحوّل المستهلك البطيء إلى عطل بدل نمو غير محدود للذاكرة. اختبر مسار الفيض بالحدود نفسها التي يستخدمها الإنتاج.

## قرّر سياسة إعادة الاتصال صراحة [#reconnect]

إعادة اتصال SSE معطّلة حتى يفعّلها التطبيق. لا تُعاد طريقة غير متماثلة مثل POST إلا إذا سمحت السياسة بذلك. قد تكون المحاولة الفاشلة قد بدأت عملًا على الخادم بالفعل؛ اقرأ قواعد إعادة الاتصال في [تدفقات أحداث SSE](/ar/docs/sse) قبل تفعيل سياسة.

## أغلق، لا تُسرّب [#close]

يبدأ `close()` التفكيك؛ ويبلّغ `closed` عن الحالة النهائية. انتظر `closed` عندما تعتمد الخطوة التالية على تحرّر وسيلة النقل. الإجهاض ينهي العمل المحلي؛ وهو ليس دليلًا على أن الخدمة أوقفت عملًا قبلته بالفعل.
