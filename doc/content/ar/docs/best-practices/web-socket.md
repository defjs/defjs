## امتلك الجلسة [#ownership]

جلسة WebSocket ملك المستدعي الذي فتحها. أغلقها عندما ينتهي العمل، واستخدم `await using` عندما يملكها النطاق المحيط، حتى تُطلَق الجلسة في كل مسار خروج.

```ts
const [error, session] = await quotes(client);
if (error) return;
await using ownedSession = session;
ownedSession.send({ type: "subscribe", symbol: "ACME" });
```

## اقرأ حتى تُغلق الجلسة [#read-to-end]

اقرأ `session.receive` حتى تُغلق الجلسة أو يتوقف المستدعي. لا تفترض أن الرسالة الأولى هي الأخيرة. سجّل `onRuntimeError` عندما يجب على التطبيق ملاحظة فشل نقل يحدث بعد فتح الجلسة.

## حدّد الطابورين [#bounds]

اضبط `maxIncomingQueueSize` للرسائل المنتظرة للمستهلك، و`maxOutgoingQueueSize` للرسائل الموضوعة في الطابور أثناء إعادة الاتصال. فالحد يحوّل المستهلك البطيء أو إعادة الاتصال الطويلة إلى عطل بدل نمو غير محدود للذاكرة. اختبر مسار الفيض بالحدود نفسها التي يستخدمها الإنتاج.

## اجعل إعادة الاتصال والنبض مقصودين [#reconnect]

إعادة الاتصال والنبض خياران على العميل. إعادة الاتصال تنشئ محاولة اتصال جديدة؛ وتتبع الرسائل الصادرة الموضوعة في الطابور سياسة الطابور. النبض الذي لا يتلقى إقرارًا فشل يجب على التطبيق تصنيفه، وليس سببًا لمواصلة الإرسال إلى ما لا نهاية.

## أغلق، لا تُسرّب [#close]

يبدأ `close()` التفكيك؛ ويبلّغ `closed` عن الحالة النهائية. الإرسال بعد أن تصبح الجلسة غير قابلة للكتابة يرمي؛ افحص الحالة أو تعامل مع الرمي. انتظر `closed` عندما تعتمد الخطوة التالية على تحرّر وسيلة النقل.
