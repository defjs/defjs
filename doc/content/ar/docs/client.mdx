# العميل (Client)

يحمل كائن `Client` إعدادات تنفيذ التطبيق المستهلك: العناوين الأساسية (base URLs)، والترويسات الافتراضية، وبيانات الاعتماد، والمعترضات (Interceptors)، وتسلسل معلمات الاستعلام، ومقابض وسائل النقل.

تُرجع الدالة `createClient(...options)` عميلاً مشتقاً من نوع [`DerivableClient`](/ar/api/core/derivableclient-type):

- مرّر `client` مباشرة إلى أي عملية (`getOrder(client, { id: 1 })`) عند عدم الحاجة إلى خيارات طلب خاصة بكل استدعاء.
- استدعِ `client(requestOptions)` لاشتقاق قيمة `Client` مخصصة لاستدعاء واحد (`getOrder(client({ signal }), { id: 1 })`). لا تُجري عملية الاشتقاق أي إدخال/إخراج، وتكون القيمة المشتقة كائناً عادياً (غير قابل للاستدعاء كدالة).

### قواعد تركيب الخيارات

- تُطبّق الخيارات بترتيب ورودها **من اليسار إلى اليمين**.
- دوال ضبط القيمة المفردة (`withEndpoint`، و`withHeaders`، و`withQuerySerializer`، و`withCredentials`، و`withXSRF`) **تستبدل** القيم السابقة.
- الدالة `withInterceptors(...items)` **تُلحق** المعترضات بالقائمة الحالية وتُرشحها حسب وسيلة النقل (`http` و`sse` و`web-socket`) عند تشغيل العملية.

> [!IMPORTANT]
> نظراً لأن `createClient(...)` تُرجع دالة قابلة للاستدعاء (`DerivableClient`)، **لا** تمررها مباشرة إلى دوال تحديث الحالة مثل `setState(client)` في React أو إلى مصادر المراقبة والحساب مثل `watch(client)` أو `computed(client)` في Vue، حيث تعامل تلك الأطر الدوال كمعاملات تحديث أو دوال جلب (getters).

### مرجع خيارات الطلب المخصص `RequestOptions`

يحتوي كائن `RequestOptions` على سبعة حقول مسطحة. وتقرأ كل وسيلة نقل الحقول الخاصة بها فقط وتتجاهل الباقي:

| الحقل                | مستخدم بواسطة          | السلوك                                                                                                            |
| -------------------- | ---------------------- | ----------------------------------------------------------------------------------------------------------------- |
| `signal`             | HTTP، وSSE، وWebSocket | لإلغاء الاستدعاء (`AbortSignal.timeout(ms)` ← `NET_TIMEOUT`؛ والإلغاء اليدوي ← `NET_ABORTED`).                    |
| `onUploadProgress`   | HTTP                   | يبلّغ عن تقدم رفع جسم الطلب المتدفق.                                                                              |
| `onDownloadProgress` | HTTP                   | يبلّغ عن تقدم تنزيل جسم الاستجابة المعلن.                                                                         |
| `beforeConnect`      | WebSocket              | يستبدل خطاف `beforeConnect` المضبوط على مستوى العميل لهذه الجلسة.                                                 |
| `protocols`          | WebSocket              | يستبدل قائمة البروتوكولات الفرعية للعميل لهذه الجلسة.                                                             |
| `heartbeat`          | WebSocket              | يستبدل إعدادات نبضات القلب الخاصة بالعميل لهذه الجلسة.                                                            |
| `reconnect`          | WebSocket              | يستبدل سياسة إعادة اتصال WebSocket للعميل لهذه الجلسة. (تُضبط إعادة اتصال SSE على العميل عبر `withSSEReconnect`). |

## 3. العميل العام في المتصفح مقابل نطاق طلب الخادم

- **تطبيقات المتصفح**: شارك كائن `DerivableClient` واحداً على نطاق الوحدة عندما تكون نقطة النهاية والمعترضات وبيانات الاعتماد مشتركة عبر التطبيق بأكمله.
- **تطبيقات الخادم والمعالجة من جهة الخادم (SSR)**: أنشئ عميلاً جديداً **داخل حدود كل طلب وارد** كلما كانت الترويسات أو ملفات تعريف الارتباط أو رموز المصادقة أو سياق المستأجر مخصصة لكل طلب. ولا تخزن أبداً بيانات اعتماد مستخدم محدد على عميل مشترك على مستوى العملية.

## 4. نقاط نهاية متعددة وتوزيع الحمل [#multiple-endpoints]

تقبل الدالة `withEndpoint(...urls)` عنواناً أساسياً واحداً أو أكثر كمرشحين. وافتراضياً:

- يستخدم كل عميل [`pickFirstBalancer`](/ar/api/core/pickfirstbalancer)، ويلتزم بالعنوان الأول حتى يتقدّم عند `NET_UNREACHABLE` أو `NET_UNAVAILABLE` (HTTP 502 أو 503 أو 504).
- **إعادة محاولة HTTP في نفس الاستدعاء معطّلة افتراضياً.** `withRetry()` يعادل `withRetry({})` ويفعّل محاولة ثانية على نقطة نهاية لم تُجرَّب عند فشل الاتصال للطرق الآمنة (`GET` و`HEAD` و`OPTIONS` و`TRACE`)، مع backoff. ميزانية إعادة المحاولة بنمط Finagle تملكها إعدادات العميل، ويشاركها العملاء المشتقون من ذلك الإعداد، بمعزل عن هوية الموازن.

<include cwd lang="typescript">
  examples/client/multiple-endpoints.ts#example
</include>

عند ضبط نقطة نهاية واحدة فقط، لا يعيد `withRetry` تشغيل الطلب لأن كل إعادة محاولة تستبعد نقاط النهاية التي جُرِّبت. يجب أن يكون `attemptTimeoutMs` و`connectTimeoutMs`، عند توفيرهما، محدودين وموجبين ولا يزيدان على 2147483647 (حد المؤقت)؛ وإلا تُرجع العملية `REQ_OPTIONS_INVALID`.

### فحص السلامة وخوارزمية p2c [#health-filtering-and-p2c]

بالنسبة للنسخ المتطابقة من الخوادم النظيرة، تُفعل أدوات التوزيع [`roundRobinBalancer`](/ar/api/core/roundrobinbalancer) و[`p2cBalancer`](/ar/api/core/p2cbalancer) (خوارزمية ذروة Ewma لزمن الرحلة RTT × الحمل اللحظي) قاطع الدائرة للأخطاء المتتالية على طراز Linkerd (عبر `outlierDetection`) افتراضياً. يحصي `NET_UNREACHABLE` و`NET_UNAVAILABLE` و`NET_SERVER_ERROR`؛ و`status` الخام للاستجابة مخصص فقط لموازنات الحمل المخصصة.

راجع دليل [توزيع الحمل والتبديل عند الفشل](/ar/docs/load-balancing) للاطلاع على التفاصيل الكاملة لميزانيات إعادة المحاولة، وفحوصات السلامة النشطة والسلبية، وتقدير الحمل بخوارزمية P2C، وموازنات الحمل المخصصة.

## 6. مرجع دوال ضبط خيارات العميل المساعدة

| الدالة المساعدة                                                                                               | الغرض                                                                                               |
| ------------------------------------------------------------------------------------------------------------- | --------------------------------------------------------------------------------------------------- |
| `withEndpoint(...urls)`                                                                                       | تضبط عنواناً أساسياً واحداً أو أكثر كمرشحين (تستبدل القائمة السابقة).                               |
| `withHeaders(HeadersInit)`                                                                                    | تضبط ترويسات افتراضية ثابتة لـ HTTP وSSE (تتجاوزها ترويسات `builder`).                              |
| `withInterceptors(...items)`                                                                                  | تُلحق معترضات لـ HTTP وSSE وWebSocket بنمط طبقات البصلة (onion order).                              |
| `withQuerySerializer(fn)`                                                                                     | تُسلسل كائنات معلمات الاستعلام ذات الأسماء البديلة إلى نص استعلام سلكي.                             |
| `withCredentials(boolean)`                                                                                    | تضبط خيار Fetch على `credentials: "include"` لـ HTTP وSSE عند التعيين إلى `true`.                   |
| `withXSRF(options?)`                                                                                          | تنسخ ملف تعريف ارتباط XSRF إلى ترويسة الطلب لطلبات HTTP المعدِّلة من نفس المصدر.                    |
| `withBalancer(balancer)`                                                                                      | تستبدل استراتيجية اختيار نقطة النهاية (`pickFirstBalancer`، و`roundRobinBalancer`، و`p2cBalancer`). |
| `withRetry(options?)`                                                                                         | تضبط شروط إعادة محاولة HTTP الاختيارية، والطرق، وbackoff، ومهلة المحاولة، وميزانية يملكها العميل.   |
| `withSSEReconnect` / `withSSEOnInvalidEvent`                                                                  | تضبط إعادة اتصال SSE ومراقبة الأحداث غير الصالحة.                                                   |
| `withWebSocketReconnect` / `withWebSocketHeartbeat` / `withWebSocketProtocols` / `withWebSocketBeforeConnect` | تضبط الخيارات الافتراضية لجلسة WebSocket.                                                           |
| `withHTTPHandle` / `withSSEHandle` / `withWebSocketHandle`                                                    | تحقن تطبيقات وسائل نقل مخصصة أو وهمية للاختبار.                                                     |
