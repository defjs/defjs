# Struct

تعبّر الـ Structs عن عقد البيانات الذي يعد به SDK: مدخل المستدعي واستجابات الخدمة والأخطاء المعلَنة والرسائل الآنية. أعد استخدامها عبر العمليات المصدَّرة حتى يحصل المستهلكون على أنواع TypeScript متسقة وتحقق وقت التشغيل، باستقلال عن العميل الذي يضبطونه.

تحصل على أنواع TypeScript عبر `Infer`، وفحوص وقت التشغيل عبر `struct.parse(...)` — بلا رمي، وtuple يضع الخطأ أولًا.

## الإعداد الأساسي

</include>

يُبقي المخرج المحلَّل الحقول المعلَنة فقط. الحقول المطلوبة الغائبة، أو البدائيات الخاطئة، أو القيم المتداخلة السيئة، أو طول tuple خاطئ، أو `null` غير مسموح ← `StructError`، بلا قيمة جزئية. الـ Structs غير قابلة للتغيير؛ وتُرجع `.optional()` وأشباهها Struct جديدًا.

## المطلوب والاختياري وnull

الحضور وقابلية الإفراغ منفصلان:

| الإعلان                      | الغائب / `undefined`          | `null` | قيمة صالحة        |
| ---------------------------- | ----------------------------- | ------ | ----------------- |
| `struct.string()`            | يرفض                          | يرفض   | يقبل سلسلة        |
| `struct.string().optional()` | يقبل؛ ويحذف حقل الكائن الغائب | يرفض   | يقبل سلسلة        |
| `struct.string().null()`     | يرفض                          | يقبل   | يقبل سلسلة        |
| `struct.string().nullish()`  | يقبل؛ ويحذف حقل الكائن الغائب | يقبل   | يقبل سلسلة        |
| `struct.null()`              | يرفض                          | يقبل   | يرفض القيم الأخرى |

<include cwd lang="typescript">
  examples/struct/required-optional-null.ts#example
</include>

`struct.any()` و`struct.unknown()` يرفضان `null` و`undefined` أيضًا. سلسِل `.null()` أو `.optional()` أو `.nullish()` لقبولهما.

في الجذر، يمكن أن يكون الاختياري `undefined`. داخل كائن، تبقى حقول optional/nullish المحذوفة غائبة. يتبع حقل كائن متداخل القاعدة نفسها: وسِمه `.optional()` عندما يجوز للمستدعي حذفه. يبقى حقل الكائن المطلوب مطلوبًا حتى عندما يكون كل حقل داخله اختياريًا.

## موضع الطلب

المسار والاستعلام والرؤوس والجسم حقول يُرجعها الـ builder، لا struct طلب. `input` المعلَن يتطلب دائمًا `builder` صريحًا. يقتصر `input` على تعريف المعاملات؛ والـ builder وحده يقرر أين تذهب كل قيمة. يمكن حذف `builder` فقط من التعريفات التي لا تعلن `input`. `struct.urlencoded(shape)` و`struct.formData(shape)` هما structا كائن بوسم ترميز. يعمل الوسم فقط عندما تكون تلك القيمة جذر الجسم: تستخدم المفاتيح الأسماء المستعارة، وتكرر المصفوفات اسم الحقل.

<include cwd lang="typescript">
  examples/struct/request-placement.ts#example
</include>

| جذر الجسم                                           | يُرسَل كـ         | نوع المحتوى الافتراضي                             |
| --------------------------------------------------- | ----------------- | ------------------------------------------------- |
| كائن محدَّد النوع، مصفوفة، عدد محدود، منطقي، `null` | نص JSON           | `application/json`                                |
| struct `string` أو سلسلة خام                        | نص                | `text/plain;charset=UTF-8`                        |
| `struct.urlencoded(shape)` عند الجذر                | `URLSearchParams` | `application/x-www-form-urlencoded;charset=UTF-8` |
| `struct.formData(shape)` عند الجذر                  | `FormData`        | حد multipart للمنصة                               |
| `Blob` / `File`                                     | الـ blob          | نوع الـ blob أو `application/octet-stream`        |
| `ArrayBuffer` / عرض / تدفق                          | بايتات            | `application/octet-stream`                        |

يفشل `NaN` و`±Infinity`، بما في ذلك داخل مصفوفة أو كائن، بـ `REQ_BUILD_FAILED`.

`struct.file()` هو struct قيمة لحقل نموذج ولجسم ملف خام. لا يستطيع بناة WebSocket إرجاع `headers` أو `body`. يستطيع HTTP وSSE ذلك. لا يستطيع `GET` و`HEAD`.

## الأسماء المستعارة

تفصل `.alias(...)` الأسماء المنطقية عن أسماء السلك. يستخدم `struct.parse(...)` المفاتيح المنطقية إلا إذا مرّرت `{ aliases: true }`. ترمّز JSON وترميزات الطلب المسطحة الأسماء المستعارة؛ ويعيد فك استجابة JSON مفاتيح السلك إلى الحقول المنطقية.

<include cwd lang="typescript">
  examples/struct/aliases.ts#example
</include>

| الحد                                     | الحقل                      |
| ---------------------------------------- | -------------------------- |
| `struct.parse(Order, ...)` ومدخل العملية | منطقي `customerName`       |
| كائن محدَّد النوع يُرجعه الـ builder     | سلك `customer_name`        |
| فك JSON / SSE / WebSocket                | سلك ← منطقي `customerName` |
| كائن مجهول مكتوب في الـ builder          | المفتاح الذي كتبته         |

يقرأ الـ builder نفسه الأسماء المنطقية (`input.order.customerName`)؛ ويظهر اسم السلك فقط عندما يرمّز المسلسِل الكائن محدَّد النوع الذي يُرجعه الـ builder.

تعمل الأسماء المستعارة على الحقول المتداخلة والمصفوفات والكائنات والاتحادات والمميِّزات. أبقِ الأسماء المنطقية في شيفرة التطبيق؛ وضع الاسم الخارجي على الـ struct مرة واحدة. نشر كائن محدَّد النوع يُبقي ذلك الترميز. ضبط الحقل المنطقي ومفتاح سلكه معًا في الكائن نفسه هو `REQ_BUILD_FAILED`. `JSON.stringify` لقيمة بنفسك يغادر هذا المسار: يرى المسلسِل الأسماء المنطقية.

يُختار الدليل عند كل عقدة، لا عند الجذر فقط. يُبقي كائن جديد تحت أب مجهول المفاتيح التي كتبتها. ويستخدم الكائن نفسه تحت أب محدَّد النوع struct ذلك الحقل.

```ts
body: { row: { id: '42' } }              // Anonymous root: emits id
body: { ...input, row: { id: '42' } }    // Typed root, row field declares alias: emits wire_id
```

عندما يطابق دليل اتحاد أكثر من فرع، يُرمَّز كل فرع ويُقارَن. يُحفَظ مخرج السلك المتطابق؛ والاختلاف هو `REQ_BUILD_FAILED`.

التقاطع المختلط الذي يحتوي جزءًا ليس كائنًا يُوسَم، عند التحليل، باقتران الوسوم من الأجزاء التي طابقت؛ والقيمة المكتوبة حديثًا لتقاطع مختلط لم تُحلَّل هي كائن مجهول.

## إخفاقات التحليل

يُرجع `struct.parse(...)` القيمة `[null, value]` أو `[StructError, undefined]`. يمتد `StructError` من `Error` ويعرض `issues`، إضافة إلى `format()` و`flatten()` و`prettify()`.

<include cwd lang="typescript">
  examples/struct/parse-failures.ts#example
</include>

لـ `StructIssue` الحقول `code` و`expected` و`message` و`path` و`received`. `code` هو `custom` أو `invalid_enum` أو `invalid_intersection` أو `invalid_literal` أو `invalid_type` أو `invalid_union` أو `missing_key`. تسمّي الرسائل الافتراضية نوع القيمة المستلَمة، لا قيمتها أبدًا: `Expected number at id, received string`. مسارات المشكلة بنيوية وتحتفظ بمفاتيح record: يمكن أن ينتج `struct.record(...)` الرسالة `Expected number at alice@example.com, received string`، لذا قد تظل المفاتيح حساسة في الرسائل الافتراضية و`prettify()` و`String(fault)`. لذلك يحذف `message` و`prettify()` الحمولات المستلَمة؛ ويُبقي `received` القيمة الأصلية ويحتاج حجبًا قبل التسجيل أو الإرجاع. يعيد `struct.parse(..., { errorMap })` كتابة الرسائل لذلك الاستدعاء فقط، بما فيه إخفاقات تحويل bigint/date في struct من نسخة Core أخرى. أي سلسلة مُرجَعة، بما فيها `''`، تستبدل الافتراضي؛ و`undefined` وحده يبقيه. يُستخدم النص المخصص كما هو وقد يكشف قيمًا إذا ضمّنتها الخريطة.

التحقق من Struct بنيوي فقط. بلا قواعد عامة للنطاق أو التنسيق أو التحسين أو المصادقة أو انتقال الحالة. افعل تلك الفحوص قبل أن تستدعي عملية.

## مرجع

المنشئات العامة على `@defjs/core` (الداخليات ليست واجهات الـ facade):

<include cwd lang="typescript">
  examples/struct/any.ts#example
</include>

| المنشئ                           | المدخل                                 | المخرج المستنتج               |
| -------------------------------- | -------------------------------------- | ----------------------------- |
| `struct.number()`                | عدد غير `NaN`                          | `number`، بما فيه ±`Infinity` |
| `struct.date()`                  | `Date` أو عدد أو سلسلة تاريخ           | `Date` صالح                   |
| `struct.bigint()`                | `bigint` أو سلسلة يقبلها `BigInt(...)` | `bigint`                      |
| `struct.enum(...)`               | عضو سلسلة أو عدد معلَن                 | اتحاد تلك القيم الحرفية       |
| `struct.discriminatedUnion(...)` | كائن بمميِّز حرفي مطلوب                | فرع الكائن المختار            |
| `struct.or(...)`                 | أول فرع مطابق؛ والترميز يفحص الالتباس  | اتحاد مخرجات الفروع           |
| `struct.intersection(...)`       | قيم يقبلها كل عضو                      | تقاطع المخرجات                |
| `struct.record(value)`           | كائن عادي تطابق قيمه `value`           | record للقيم المحلَّلة        |
| `struct.tuple(items)`            | مصفوفة بالطول المعلَن تمامًا           | tuple بطول ثابت               |

يدعم كل Struct الدوال `.alias(name)` و`.optional()` و`.null()` و`.nullish()`. يحتاج `struct.discriminatedUnion` خيارات كائن بمميِّز حرفي مطلوب ويرفض التكرار.

استورد `struct` و`Infer` و`Struct` و`StructError` والأنواع العامة ذات الصلة من `@defjs/core`. استخدم `struct.parse(...)` كالمحلّل. لا تستورد `createObjectStruct` ولا رموز التعريف ولا داخليات الترميز ولا `packages/core/src`.

ما لا تعد به الواجهة:

- مخرجات الكائن/record تستخدم نموذجًا أوليًا null — لا تفترض طرائق `Object.prototype`.
- تُسقَط مفاتيح الكائن غير المعروفة.
- يرفض `struct.number()` القيمة `NaN`، ويقبل اللانهايات.
- يجرّب `struct.or(...)` الفروع بالترتيب؛ ويرفض الترميزات الملتبسة عندما تختلف الفروع.
- يحلّل `struct.intersection(...)` الأعضاء بترتيب الإعلان.
- يدمج التقاطع مخرجات الأعضاء بعمق (تبقى القيم المتساوية بـ `Object.is` والتواريخ متساوية الوقت، وتندمج الكائنات العادية والمصفوفات متساوية الطول تعاوديًا، وأي تعارض آخر هو `invalid_intersection` عند ذلك المسار)، ولا يساهم `unknown`/`any` بشيء، ويجوز لمفتاح منطقي واحد أن يقابل عدة مفاتيح سلك. تتعارض فقط القيم غير المتساوية المكتوبة على مفتاح السلك نفسه.
- يتحقق الـ Struct من حد؛ وهو لا يخزّن مؤقتًا ولا يفوّض ولا يملك مورد نقل.
