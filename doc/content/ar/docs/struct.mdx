# Struct

يستخدم مؤلف SDK أدوات Struct لتعريف عقود مدخلات API ومخرجاته وأخطائه، وأحداث SSE ورسائل WebSocket. يرتبط استنتاج الأنواع والتحقق وقت التشغيل بالتصريح نفسه، فينفّذ التطبيق التعريفات المنشورة مباشرة. يحدّد Struct تمثيل القيمة، ويحدّد `builder` موضعها في الطلب.

نمذج طلبًا (واستجاباته) كـ Structs. تحصل على أنواع TypeScript عبر `Infer`، وفحوص وقت التشغيل عبر `struct.parse(...)` — بلا رمي، tuple يضع الخطأ أولاً.

المخرج المحلَّل يحتفظ فقط بالحقول المعلَنة. حقول مطلوبة مفقودة، أو بدائيات خاطئة، أو قيم متداخلة سيئة، أو طول tuple خاطئ، أو `null` غير مسموح ← `StructError`، بلا قيمة جزئية. Structs غير قابلة للتغيير؛ `.optional()` وأصدقاؤها تُرجع Struct جديدًا.

## مطلوب، اختياري، null

الوجود والقابلية لـ null منفصلان:

| الإعلان                      | مفقود / `undefined`          | `null` | قيمة صالحة        |
| ---------------------------- | ---------------------------- | ------ | ----------------- |
| `struct.string()`            | ارفض                         | ارفض   | اقبل سلسلة        |
| `struct.string().optional()` | اقبل؛ احذف حقل الكائن الغائب | ارفض   | اقبل سلسلة        |
| `struct.string().null()`     | ارفض                         | اقبل   | اقبل سلسلة        |
| `struct.string().nullish()`  | اقبل؛ احذف حقل الكائن الغائب | اقبل   | اقبل سلسلة        |
| `struct.null()`              | ارفض                         | اقبل   | ارفض القيم الأخرى |

<include cwd lang="typescript">
  examples/struct/required-optional-null.ts#example
</include>

`struct.any()` و`struct.unknown()` يرفضان `null` و`undefined` أيضًا. أضف `.null()` أو `.optional()` أو `.nullish()` لقبولهما.

في الجذر، الاختياري يمكن أن يكون `undefined`. داخل كائن، الحقول الاختيارية/nullish المحذوفة تبقى غائبة. حقل الكائن المتداخل يتبع القاعدة نفسها: علّمه `.optional()` عندما يجوز للمستدعي حذفه. حقل الكائن المطلوب يبقى مطلوبًا حتى لو كان كل حقل داخله اختياريًا.

## وضع الطلب

المسار والاستعلام والرؤوس والجسم حقول يُرجعها الـ builder، وليست struct طلب. عند التصريح بـ `input`، يجب دائمًا توفير `builder` صريح. يقتصر `input` على تعريف المعاملات، والـ builder وحده يقرر أين تذهب كل قيمة. يمكن حذف `builder` فقط من التعريفات التي لا تصرّح بـ `input`. `struct.urlencoded(shape)` و`struct.formData(shape)` هما struct كائن مع وسم ترميز. الوسم يعمل فقط عندما تكون تلك القيمة جذر الجسم: المفاتيح تستخدم الأسماء المستعارة، والمصفوفات تكرر اسم الحقل.

<include cwd lang="typescript">
  examples/struct/request-placement.ts#example
</include>

| جذر الجسم                                                 | يُرسَل كـ         | نوع المحتوى الافتراضي                             |
| --------------------------------------------------------- | ----------------- | ------------------------------------------------- |
| كائن محدَّد النوع، مصفوفة، عدد منتهٍ، قيمة منطقية، `null` | نص JSON           | `application/json`                                |
| struct `string` أو سلسلة خام                              | نص                | `text/plain;charset=UTF-8`                        |
| `struct.urlencoded(shape)` عند الجذر                      | `URLSearchParams` | `application/x-www-form-urlencoded;charset=UTF-8` |
| `struct.formData(shape)` عند الجذر                        | `FormData`        | فاصل multipart للمنصة                             |
| `Blob` / `File`                                           | الـ blob          | نوع الـ blob أو `application/octet-stream`        |
| `ArrayBuffer` / عرض / تدفق                                | بايتات            | `application/octet-stream`                        |

لا يُرمَّز كـ JSON إلا العدد المنتهي. يفشل `NaN` و±`Infinity`، بما في ذلك داخل مصفوفة أو كائن، بـ `REQ_BUILD_FAILED`.

`struct.file()` هو struct قيمة لحقل نموذج ولجسم ملف خام. لا يمكن لـ builder في WebSocket إرجاع `headers` أو `body`. HTTP وSSE يستطيعان. `GET` و`HEAD` لا يستطيعان.

## الأسماء المستعارة

`.alias(...)` يفصل الأسماء المنطقية عن أسماء الحقول بصيغة النقل. `struct.parse(...)` يستخدم المفاتيح المنطقية ما لم يمرّر المستدعي `{ aliases: true }`. ترميزات JSON والطلب المسطّح ترمّز الأسماء المستعارة؛ وفك استجابة JSON يعيّن مفاتيح السلك إلى الحقول المنطقية.

<include cwd lang="typescript">
  examples/struct/aliases.ts#example
</include>

| الحد                                  | الحقل                                   |
| ------------------------------------- | --------------------------------------- |
| `struct.parse(User, ...)` ومدخل الأمر | منطقي `displayName`                     |
| كائن محدَّد النوع يُرجعه الـ builder  | اسم النقل `display_name`                |
| فك JSON / SSE / WebSocket             | اسم النقل ← الاسم المنطقي `displayName` |
| كائن مجهول مكتوب في الـ builder       | المفتاح الذي كتبته                      |

يقرأ الـ builder نفسه الأسماء المنطقية (`input.user.displayName`)؛ ولا يظهر اسم الحقل بصيغة النقل إلا عندما يرمّز المُسلسِل الكائن محدَّد النوع الذي يُرجعه الـ builder.

الأسماء المستعارة تعمل على الحقول المتداخلة والمصفوفات والكائنات والاتحادات والمميّزات. أبقِ الأسماء المنطقية في كود التطبيق؛ ضع الاسم الخارجي على الـ struct مرة واحدة. نشر كائن محدَّد النوع يُبقي ذلك الترميز. تعيين الحقل المنطقي ومفتاح سلكه معًا في الكائن نفسه هو `REQ_BUILD_FAILED`. `JSON.stringify` لقيمة بنفسك يغادر هذا المسار: المُسلسِل يرى الأسماء المنطقية.

يُختار الدليل عند كل عقدة، لا عند الجذر فقط. الكائن الجديد تحت أب مجهول يُبقي المفاتيح التي كتبتها. الكائن نفسه تحت أب محدَّد النوع يستخدم struct ذلك الحقل.

```ts
body: { row: { id: '42' } }              // Anonymous root: emits id
body: { ...input, row: { id: '42' } }    // Typed root, row field declares alias: emits wire_id
```

عندما يطابق دليل الاتحاد أكثر من فرع، يُرمَّز كل فرع ثم تُقارَن النتائج. يُبقى الخرج السلكي المتطابق؛ والاختلاف هو `REQ_BUILD_FAILED`.

التقاطع المختلط الذي يتضمن جزءًا غير كائن يُوسَم عند التحليل باقتران وسوم الأجزاء المطابقة؛ وقيمة التقاطع المختلط المكتوبة من جديد دون تحليل تُعامَل ككائن مجهول.

## أعطال التحليل

`struct.parse(...)` يُرجع `[null, value]` أو `[StructError, undefined]`. `StructError` يمتد من `Error` ويعرض `issues`، مع `format()` و`flatten()` و`prettify()`.

<include cwd lang="typescript">
  examples/struct/parse-failures.ts#example
</include>

`StructIssue` يملك `code` و`expected` و`message` و`path` و`received`. `code` هو `custom` أو `invalid_enum` أو `invalid_intersection` أو `invalid_literal` أو `invalid_type` أو `invalid_union` أو `missing_key`. تذكر الرسائل الافتراضية نوع القيمة المستلَمة، ولا تذكر قيمتها أبدًا: `Expected number at id, received string`. مسارات المشكلة بنيوية وتحتفظ بمفاتيح record: يمكن أن ينتج `struct.record(...)` الرسالة `Expected number at alice@example.com, received string`، لذا قد تظل المفاتيح حساسة في الرسائل الافتراضية و`prettify()` و`String(fault)`. لذلك لا تتضمن `message` و`prettify()` الحمولات المستلَمة؛ أما `received` فيحتفظ بالقيمة الأصلية ويحتاج إلى الحجب قبل التسجيل أو الإرجاع. `struct.parse(..., { errorMap })` يعيد كتابة الرسائل لذلك الاستدعاء فقط، بما في ذلك فشل تحويل bigint/date في struct من نسخة Core أخرى. أي سلسلة نصية مُعادة، بما فيها `''`، تستبدل الرسالة الافتراضية؛ وحده `undefined` يُبقيها. يُستخدم النص المخصص كما هو، وقد يكشف القيم إذا تضمّنها الـ map.

تحقق Struct بنيوي فقط. بلا قواعد عامة للنطاق أو التنسيق أو التحسين أو المصادقة أو انتقال الحالة. افعل تلك الفحوص قبل أن تبني أمرًا.

## المرجع

مُنشئات عامة على `@defjs/core` (الداخلية ليست واجهات الواجهة):

<include cwd lang="typescript">
  examples/struct/any.ts#example
</include>

| المُنشئ                          | المدخل                                 | المخرج المستنتج                  |
| -------------------------------- | -------------------------------------- | -------------------------------- |
| `struct.number()`                | عدد غير `NaN`                          | `number`، بما في ذلك ±`Infinity` |
| `struct.date()`                  | `Date` أو عدد أو سلسلة تاريخ           | `Date` صالح                      |
| `struct.bigint()`                | `bigint` أو سلسلة يقبلها `BigInt(...)` | `bigint`                         |
| `struct.enum(...)`               | عضو سلسلة أو عدد معلَن                 | اتحاد ذلك الحرفي                 |
| `struct.discriminatedUnion(...)` | كائن بمميّز حرفي مطلوب                 | فرع الكائن المختار               |
| `struct.or(...)`                 | أول فرع مطابق؛ والترميز يفحص الغموض    | اتحاد مخرجات الفروع              |
| `struct.intersection(...)`       | قيم يقبلها كل عضو                      | تقاطع المخرجات                   |
| `struct.record(value)`           | كائن عادي تطابق قيمه `value`           | Record من القيم المحلَّلة        |
| `struct.tuple(items)`            | مصفوفة بالطول المعلَن بالضبط           | tuple بطول ثابت                  |

كل Struct يدعم `.alias(name)` و`.optional()` و`.null()` و`.nullish()`. `struct.discriminatedUnion` يحتاج خيارات كائن بمميّز حرفي مطلوب ويرفض التكرارات.

استورد `struct` و`Infer` و`Struct` و`StructError` والأنواع العامة ذات الصلة من `@defjs/core`. استخدم `struct.parse(...)` كالمحلّل. لا تستورد `createObjectStruct` أو رموز التعريف أو داخلية الترميز أو `packages/core/src`.

غير وعود الواجهة:

- مخرجات الكائن/السجل تستخدم نموذجًا أوليًا null — لا تفترض طرائق `Object.prototype`.
- مفاتيح الكائن المجهولة تُسقط.
- `struct.number()` يرفض `NaN`، ويقبل اللانهائيات.
- `struct.or(...)` يجرّب الفروع بالترتيب؛ ويرفض الترميزات الغامضة عندما تختلف الفروع.
- `struct.intersection(...)` يحلّل الأعضاء بترتيب الإعلان.
- intersection يدمج مخرجات الأعضاء بعمق (القيم المتساوية عبر `Object.is` والتواريخ ذات الوقت نفسه تبقى، والكائنات العادية والمصفوفات متساوية الطول تُدمج تكراريًا، وأي تعارض آخر هو `invalid_intersection` عند ذلك path)، و`unknown` / `any` لا يساهمان بشيء، ويمكن أن يقابل المفتاح المنطقي الواحد عدة مفاتيح wire؛ والتعارض يكون فقط عندما تُكتب قيم غير متساوية على مفتاح wire واحد.
- Struct يتحقق من حد؛ ولا يخزّن، ولا يفوّض، ولا يملك مورد نقل.
