### ثلاث نقاط مهمة أثناء كتابة الاختبار

- **لماذا نغلف `(input, init)` داخل `new Request(input, init)`**: تستقبل `withHTTPHandle` نفس توقيع `fetch(input, init)` القياسي، وتغليفها في `new Request(input, init)` يمنحك واجهة موحدة لقراءة `method` و`url` و`headers` و`await request.json()`.
- **لماذا نمرر `withEndpoint("https://fixture.invalid")`**: تتحقق `createClient` من رابط الأساس قبل استدعاء `withHTTPHandle`، والنطاق `.invalid` محجوز حسب RFC فلا يرسل استعلام DNS حقيقياً أبداً.
- **كيف تحاكي نتائج HTTP الثلاث الشائعة**:
  - نجاح `2xx`: أعد `Response.json(...)` -> `[null, data, response]`
  - خطأ `4xx` / `5xx`: أعد `Response.json(..., { status: 422 })` -> `err.code === "HTTP_STATUS"`
  - فشل الشبكة: ارفض الوعد أو ارمِ خطأ (`Promise.reject(new TypeError("fetch failed"))`) -> `err.code === "NET_UNREACHABLE"`. **لا** تعد `Response.error()` لأن أي كائن `Response` (حتى بالحالة `0`) يُعامل كاستجابة HTTP (`HTTP_STATUS`).

في الإنتاج استدعِ نفس العملية `getOrder` بعميل مضبوط عبر `withEndpoint(...)`. راجع [الاختبارات](/ar/docs/testing) و[العميل](/ar/docs/client).
