# استهلاك تدفق أحداث SSE

يوفر كل مقبض تدفق `EventStreamHandle` مكرراً غير متزامن مفرد الاستهلاك. احرص دائماً على وضع `stream.close(...)` متبوعاً بـ `await stream.closed` داخل كتلة `finally` حتى لا تؤدي عبارات `break` أو `return` المبكرة إلى تسريب تدفق Fetch الأساسي:

<Tabs items={["sdk/deployments.ts", "app/main.ts", "deploy-events.ts"]}>
  <Tab value="sdk/deployments.ts">
```ts
import { defineEventStream, struct } from "@defjs/core";

export const deployEvents = defineEventStream({
  path: "/deployments/events",
  events: {
    line: struct.object({ text: struct.string() }),
  },
});
```
  </Tab>
  <Tab value="app/main.ts">
```ts
import { createClient, withEndpoint } from "@defjs/core";
import { deployEvents } from "../sdk/deployments.ts";

const client = createClient(withEndpoint("https://api.example.com"));

async function main() {
const [error, stream] = await deployEvents(client);
if (error) {
console.error(error.code);
return;
}
try {
for await (const event of stream) {
if (event.event === "line") {
console.log(event.data.text);
break;
}
}
} finally {
stream.close("consumer-finished");
await stream.closed;
}
}

void main();

````

عندما يرسل الخادم الحدث الأول كـ `line` مع بيانات `{ "text": "build started" }`، يطبع البرنامج:

```txt
build started
````

- لا يُعيد SSE الاتصال تلقائياً عند حدوث إخفاقات في الشبكة أو القراءة ما لم تضبط [`withSSEReconnect(...)`](/ar/api/core/withssereconnect) على العميل.
- عند تفعيل `withSSEReconnect` بتمرير كائن خيارات، تكون القيمة الافتراضية لـ `attempts` هي `3` لكل انقطاع وتُعاد ضبطها عند كل مصافحة ناجحة (بينما تعطل `attempts: 0` إعادة الاتصال). ودون دالة `shouldReconnect` مخصصة، يُعاد الاتصال تلقائياً لطلبات `GET` و`HEAD` و`OPTIONS` و`PUT` و`DELETE` ذات الأجسام القابلة لإعادة الإرسال فقط. راجع [تدفقات أحداث SSE](/ar/docs/sse).
