# فك تغليف غلاف GraphQL عبر HTTP

لا يدمج Defjs عميل GraphQL ولا يفرض سياسة `errorPolicy`. بل صمّم GraphQL عبر HTTP كعملية `POST` قياسية تُرسل دالة `builder` الخاصة بها الكائن `{ query, operationName, variables }`. عيّن `data` كـ `.nullish()` في بنية الغلاف (Struct envelope) بحيث تجتاز كل من `data` المحذوفة و`data: null` التحقق البنيوي بنجاح، ثم فك تغليف `errors[]` عبر دالة مساعدة في كود التطبيق:

<Tabs items={["sdk/viewer.ts", "app/load-viewer.ts", "graphql-viewer.ts"]}>
  <Tab value="sdk/viewer.ts">
```ts
import { defineRequest, struct } from "@defjs/core";

const VIEWER_QUERY = "query Viewer { viewer { id login } }" as const;

export const runViewer = defineRequest({
  method: "POST",
  path: "/graphql",
  builder: () => ({
    body: { query: VIEWER_QUERY, operationName: "Viewer" },
  }),
  output: struct.object({
    data: struct
      .object({
        viewer: struct
          .object({ id: struct.string(), login: struct.string() })
          .null(),
      })
      .nullish(),
    errors: struct
      .array(struct.object({ message: struct.string() }))
      .optional(),
  }),
});
```
  </Tab>
  <Tab value="app/load-viewer.ts">
```ts
import type { Client } from "@defjs/core";
import { runViewer } from "../sdk/viewer.ts";

export async function loadViewer(client: Client) {
  const [error, result] = await runViewer(client);
  if (error) throw error;
  if (result.errors?.length) {
    throw new Error(result.errors.map((item) => item.message).join("; "));
  }
  if (!result.data) {
    throw new Error("GraphQL response contained neither data nor errors");
  }
  return result.data.viewer;
}
```

- تعني استجابة HTTP `200` فقط أن غلاف GraphQL قد وصل سليماً عبر الشبكة. أما أخطاء النطاق داخل مصفوفة `errors[]` (حتى عندما تصاحبها `data: null`) فهي نتائج على مستوى التطبيق وليست أخطاء بنيوية `RES_STRUCT_MISMATCH`.
- راجع [الهندسة المعمارية وقرارات التصميم](/ar/docs/design-decisions) لمعرفة سبب إبقاء أغلفة البروتوكولات الخاصة داخل دوال مساعدة في التطبيق.
