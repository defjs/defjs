# بناء SDK ونشره [#انشر-sdk-لـ-http-دون-إخفاء-execute]

يجمع SDK واجهات API التي يقدّمها فريقك في حزمة. مع Defjs، صدّر تعريفات نقاط النهاية وعقود بياناتها، واترك إعداد Client وتوقيت التنفيذ للتطبيقات المستهلكة. يستخدم هذا المثال HTTP، وينطبق الفصل نفسه بين الحزمة والتطبيق على تعريفات SSE وWebSocket.

## 1. عرّف عمليات SDK

أنشئ `src/users.ts` في مشروع SDK. ضع فيه المسارات وتوزيع المدخلات والاستجابات وعقود أخطاء الخدمة. لا تحتاج إلى نسخة Client أو عنوان نشر أو بيانات اعتماد حالية لتعريف العملية.

<include cwd meta='title="src/users.ts"'>
  examples/recipes/publish-http-sdk/users-sdk.ts#example
</include>

صدّرها من `src/index.ts`:

```ts
export { getUser } from "./users.js";
```

الامتداد `.js` هو المسار داخل حزمة ESM المترجَمة. يحلّه TypeScript إلى `users.ts` وقت البناء. مع نمو SDK، أضف وحدات للعمليات وأعد تصدير نقاط نهايتها من المدخل نفسه.

## 2. جهّز JavaScript وتصريحات الأنواع للتوزيع

استخدم `package.json` التالي، مع استبدال اسم المثال باسم ضمن نطاق حزم تملكه:

```json
{
  "name": "@company/users-sdk",
  "version": "0.1.0",
  "type": "module",
  "sideEffects": false,
  "files": ["dist"],
  "exports": {
    ".": {
      "types": "./dist/index.d.ts",
      "default": "./dist/index.js"
    }
  },
  "scripts": {
    "build": "tsc -p tsconfig.json"
  },
  "peerDependencies": {
    "@defjs/core": "^0.4.0"
  },
  "devDependencies": {
    "@defjs/core": "^0.4.0",
    "typescript": "^7.0.2"
  }
}
```

يبقى Core اعتمادًا خارجيًا وقت التشغيل تشترك فيه الحزمة والتطبيق. يحدّد نطاق peer إصدارات Core التي يدعمها SDK، ويتيح اعتماد التطوير البناء والاختبار ضمن ذلك النطاق. يطابق هذا المثال عقد `0.4.x` الحالي. اختر نطاق الدعم واختبره قبل النشر؛ فتصريحات الأنواع والسلوك وقت التشغيل يعتمدان عليه.

أضف `tsconfig.json`:

```json
{
  "compilerOptions": {
    "target": "ES2022",
    "module": "NodeNext",
    "moduleResolution": "NodeNext",
    "lib": ["ES2022", "ESNext.Disposable", "DOM", "DOM.Iterable"],
    "strict": true,
    "declaration": true,
    "rootDir": "src",
    "outDir": "dist"
  },
  "include": ["src/**/*.ts"]
}
```

توفّر قيم `lib` تصريحات الأنواع، ولا تضيف polyfills وقت التشغيل. ما زال التطبيق يحتاج إلى Web APIs التي تستخدمها وسائل النقل المختارة.

ابنِ الحزمة وافحص محتوياتها:

```sh
npm install
npm run build
npm pack --dry-run
npm pack
```

تأكّد من أن الأرشيف يحتوي على `dist/index.js` و`dist/index.d.ts` ووحدات العمليات التي يشيران إليها. ثبّت الأرشيف في تطبيق مستقل وتحقّق من الأنواع والتنفيذ معًا قبل النشر. وثّق في README الخاص بـ SDK واجهات الخدمة وإصدارات Core المتوافقة والمصادقة المطلوبة وأي إعدادات افتراضية اختيارية.

## 3. نفّذ من التطبيق المستهلك

يحفظ المثال المحلي القابل للتشغيل دون شبكة التعريف في `users-sdk.ts` بجانب `app.ts`. لا ينشئ الاستيراد Client؛ بل يضبط التطبيق معالج Fetch محليًا وينفّذ العملية المستوردة:

<include cwd meta='title="app.ts"'>

</include>

```txt
Ada
```

عند استخدام الحزمة، ثبّتها مع إصدار متوافق من Core:

```sh
npm install @company/users-sdk @defjs/core@^0.4.0
```

استبدل الاستيراد النسبي في المثال بما يلي:

```ts
import { getUser } from "@company/users-sdk";
```

اضبط عنوان الخدمة والمصادقة على Client التطبيق. أبقِ `withHTTPHandle(...)` للاختبارات المحلية، واحذفه لاستخدام Fetch الذي توفّره المنصة. يمكن لتطبيق آخر استيراد نقطة النهاية نفسها واختيار إعدادات Client مختلفة دون تعديل تعريف SDK.

## 4. تحقّق وانشر

استخدم [اختبارات العميل المحلية](/ar/recipes/test-with-handle) لفحص التعريف المصدَّر وتوزيع المدخلات والتحقق من الاستجابة والأخطاء المعلنة. اختبر نقطة النهاية نفسها بعميلين ذوي عنوانَي خدمة وبيانات اعتماد مختلفين. أبقِ معالجة `HTTP_STATUS` محدَّدة الأنواع متاحة عند الاستدعاء، واختبر الإلغاء وتنظيف التدفقات لوسائل النقل التي يصدّرها SDK.

بعد اجتياز الفحوص، انشر من مجلد SDK باستخدام حساب npm الخاص بك:

```sh
npm publish --access public
```

ينشر هذا الأمر حزمة عامة. اتبع سجل الحزم وسياسة الوصول الخاصة بمؤسستك إذا كان SDK خاصًا. لا يولّد Defjs الحزمة أو ينشرها نيابةً عنك.

مصانع Client وطرق التسهيل إضافات اختيارية. يمكنها توفير إعدادات افتراضية للخدمة أو سلوك خاص بالمجال مع قبول إعدادات المستدعي والحفاظ على تصدير نقاط النهاية مباشرة. وثّق أي تحويل للأخطاء أو سياسة لدورة الحياة تضيفها. لا يلزم أي منهما لبناء SDK قابل لإعادة الاستخدام.

راجع [الأوامر](/ar/docs/commands) و[العميل](/ar/docs/client) و[قرارات التصميم](/ar/docs/design-decisions) للعقود الأساسية.
