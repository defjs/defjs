# بناء حزمة SDK ونشرها [#publish-an-http-sdk-without-hiding-execute]

تُصدّر حزمة Defjs SDK تعريفات عمليات نقية ومخططات Struct كحزمة npm مع ترك استدعاء `createClient(...)` وعناوين نقاط النهاية وبيانات الاعتماد والمعترضات بالكامل للتطبيق المستهلك.

---

## 1. تعريف حزمة SDK

احتفظ بتعريفات العمليات، وملف التصدير الشامل (barrel export)، وملفي `package.json` و`tsconfig.json` في دليل حزمة مخصص، مع التصريح عن `@defjs/core` كاعتمادية نظيرة `peerDependency`:

- تبقى `@defjs/core` اعتمادية تشغيل نظيرة خارجية `peerDependency` مشتركة مع التطبيق المستهلك.
- يتيح الخيار `"sideEffects": false` لأدوات الحزم استبعاد العمليات غير المستخدمة (tree-shaking) عندما يستورد التطبيق مجموعة فرعية فقط من العمليات.

## 2. بناء الحزمة والتحقق من أرشيف النشر (Tarball)

احزم ملفي `dist/index.js` و`dist/index.d.ts` باستخدام `tsdown`، ثم افحص محتويات الحزمة قبل النشر:

```sh
bun install
bun run build
bun pm pack --dry-run
bun pm pack
```

تحقق من تضمين `dist/index.js` و`dist/index.d.ts` داخل أرشيف الحزمة.

---

## 3. استهلاك حزمة SDK داخل التطبيق

ثبّت حزمة SDK الخاصة بك إلى جانب `@defjs/core`:

```sh
bun add @company/orders-sdk @defjs/core@^0.7.0
```

ينشئ التطبيق عميله الخاص `Client` ويمرره إلى العملية المستوردة:

<include cwd meta='title="app.ts"'>

</include>

```txt
paid
```

في كود الإنتاج، استبدل الاستيراد النسبي `./src/orders.ts` باسم الحزمة `@company/orders-sdk` وأزل `withHTTPHandle(...)` لاستخدام دالة `fetch` الأصلية في بيئة التشغيل.

## 4. الاختبار والنشر

اختبر تعريفاتك المصدّرة عبر [اختبارات المقبض في الذاكرة](/ar/recipes/test-with-handle) لتغطية تعيين الطلبات، وفك ترميز `output`، وأخطاء `HTTP_STATUS` المعلنة، والإلغاء. وبمجرد التحقق، انشر الحزمة:

```sh
bun publish --access public
```

راجع أدلة [عمليات HTTP](/ar/docs/http)، و[العميل](/ar/docs/client)، و[الاختبارات](/ar/docs/testing)، و[معمارية النواة](/ar/docs/design-decisions).
