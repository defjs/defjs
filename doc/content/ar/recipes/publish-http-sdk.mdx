# بناء حزمة SDK ونشرها [#publish-an-http-sdk-without-hiding-execute]

تُنظّم حزمة Defjs SDK نماذج `struct` المشتركة (`src/models/`) ووحدات عمليات النطاق (`src/services/`) في حزمة npm قابلة للتقليم الشجري (tree-shakable) مع ترك استدعاء `createClient(...)` وعناوين نقاط النهاية وبيانات الاعتماد والمعترضات بالكامل للتطبيق المستهلك.

وعلى خلاف مولّدات OpenAPI التقليدية التي تغلّف نقاط النهاية داخل أصناف `Service` ذات حالة (`ObjectsService.putObject(...)`)، تُصدّر حزمة Defjs SDK **دوال عمليات نقية مستقلة** (`putObject` و`getObject` و`listObjectsV2`) تُستدعى مباشرةً مع عميل التطبيق.

---

## 1. هيكلة حزمة SDK وتعريفها

باستخدام حزمة SDK لتخزين الكائنات المتوافق مع Amazon S3 (`@company/s3-sdk`) كمثال، قسّم الحزمة إلى طبقتين:

- **`src/models/`**: مخططات `struct` المشتركة وأنواع TypeScript المستنتجة عبر `Infer<typeof ...>` (باستخدام تصدير القيمة والنوع بالاسم نفسه حتى يتمكن المستهلكون من استيراد معرّف واحد لكلٍّ من مخططات وقت التشغيل والأنواع الثابتة).
- **`src/services/`**: وحدات نطاق مجمّعة حسب المورد (`buckets.ts` و`objects.ts`). تُصدّر كل وحدة دوال `defineRequest` مستقلة يوزّع بانيها المتزامن `builder` مدخلات الاستدعاء المسطحة على `path` و`query` و`headers` و`body` الثنائي.

- **دوال نقية، وليس أصناف `Service` أبدًا**: تُصدَّر كل عملية (`listBuckets` و`listObjectsV2` و`getObject` و`putObject` و`deleteObject`) كقيمة `defineRequest` مستقلة. لا تغلّفها داخل `class` أو كائن مساحة أسماء—فالدوال المستقلة تحافظ على أسلوب الاستدعاء مطابقًا لحزمة `@defjs/core` (`await putObject(client, input)`) وتسمح لأدوات الحزم باستبعاد نقاط النهاية غير المستخدمة (tree-shaking) عند ضبط `"sideEffects": false`.
- **الاستجابات الفارغة مقابل الثنائية مقابل المهيكلة**: تفك `listBuckets` و`listObjectsV2` ترميز هياكل JSON مع تعيينات الأسلاك `.alias()`؛ وتفك `getObject` ترميز كائن `Blob` ثنائي (`output: struct.blob()`)؛ بينما تغفل `putObject` و`headObject` و`deleteObject` الحقل `output` لأجسام الاستجابة الفارغة مع الاستمرار في إتاحة `response.headers` (مثل `etag`) في الخانة الثالثة من الصف.
- **اعتمادية تشغيل نظيرة خارجية**: تبقى `@defjs/core` اعتمادية نظيرة `peerDependency` مشتركة مع التطبيق المستهلك.

## 2. بناء الحزمة والتحقق من أرشيف النشر (Tarball)

احزم ملفي `dist/index.js` و`dist/index.d.ts` باستخدام `tsdown`، ثم افحص محتويات الحزمة قبل النشر:

```sh
bun install
bun run build
bun pm pack --dry-run
bun pm pack
```

تحقق من تضمين `dist/index.js` و`dist/index.d.ts` داخل أرشيف الحزمة.

## 3. استهلاك حزمة SDK داخل التطبيق

ثبّت حزمة SDK الخاصة بك إلى جانب `@defjs/core`:

```sh
bun add @company/s3-sdk @defjs/core@^0.8.0
```

نظرًا لأن حزمة SDK لا تربط أي عميل، يمتلك التطبيق المستهلك نقطة النهاية (AWS S3 أو Cloudflare R2 أو MinIO)، ومعترض التوقيع، وسياسة إعادة المحاولة، ويستدعي كل عملية مستوردة مباشرةً كدالة نقية:

## 4. الاختبار والنشر

اختبر تعريفاتك المصدّرة عبر [اختبارات المقبض في الذاكرة](/ar/recipes/test-with-handle) لتغطية تعيين المسار والاستعلام والترويسات والجسم الثنائي، وفك ترميز `output`، وترويسات استجابة `ETag`، وأخطاء `HTTP_STATUS` (`S3Error`) المعلنة، والإلغاء. وبمجرد التحقق، انشر الحزمة:

```sh
bun publish --access public
```

راجع أدلة [عمليات HTTP](/ar/docs/http)، و[العميل](/ar/docs/client)، و[الاختبارات](/ar/docs/testing)، و[معمارية النواة](/ar/docs/design-decisions).
