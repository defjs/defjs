```ts
function defineRequest<
  const M extends string,
  const P extends string,
  TInput extends AnyStruct | undefined = undefined,
  TOutput extends AnyStruct | undefined = undefined,
  TError extends AnyStruct | undefined = undefined,
>(
  definition: ResponseDeclaration<TOutput, TError> & {
    input?: TInput
    method: M
    operation?: string
    path: P
  } & BuilderField<NoInfer<TInput>, HttpRequestShape<NoInfer<P>, NoInfer<M>>>,
): RequestEndpoint<TInput, TOutput, TError>
```

- **definition** — `method` و`path`، وstruct `input` اختياري، وstructs `output` و`error` اختيارية، و`operation` اختياري. عند التصريح بـ `input`، يجب دائمًا توفير `builder` صريح، حتى لو كان المدخل يطابق شكل الطلب أصلًا. يمكن حذف `builder` فقط من التعريفات التي لا تصرّح بـ `input`.
- **يُرجع** نقطة نهاية. استدعِها بالمدخل لتحصل على `HttpCommand`.

`ResponseDeclaration` و`BuilderField` نوعان مساعدان داخليان: فـ `output` و`error` إلزاميان فقط عندما تكون معاملة النوع المقابلة struct، و`builder` هو `(input: BuilderInput<TInput>) => HttpRequestShape` عند التصريح بـ `input`.
