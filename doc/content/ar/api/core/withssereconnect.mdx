```ts
function withSSEReconnect(options: ClientSSEOptions['reconnect']): ClientOption
```

يضبط إعادة الاتصال التلقائية بعد فشل تدفق SSE. إعادة الاتصال اختيارية: بدون هذا الخيار لا تُعاد محاولة الاتصال بالتدفق الفاشل. تمرير `undefined` يمسح إعدادًا سابقًا.

```ts
type SSEReconnect = {
  attempts?: number
  delayMs?: number
  factor?: number
  jitter?: number
  maxDelayMs?: number
  shouldReconnect?: (context: {
    attempt: number
    cause?: unknown
    lastEventId: string
    method: string
    open?: { response: { status: number; statusText: string; url: string }; url: string }
  }) => boolean | Promise<boolean>
}
```

- `attempts` هو ميزانية إعادة المحاولة لكل انقطاع. قيمته الافتراضية `3` عند ضبط `reconnect`، و`0` يعطّل إعادة المحاولة. تعيد المصافحة الناجحة ضبط الميزانية وقيمة `attempt` التي يتلقاها ردّ النداء وأسّ التراجع. عدم تحديده لا يتيح محاولات غير محدودة خلال الانقطاع الواحد. الفتحات الناجحة المتكررة التي يليها فورًا فشل تدفق قابل لإعادة المحاولة قد تواصل إعادة الاتصال بتأخير الأساس الحالي (مع مراعاة jitter والحدود)، لأن كل فتح يعيد ضبط الميزانية؛ أوقفها بـ `shouldReconnect`. يبقى EOF العادي نهائيًا.
- في غياب `shouldReconnect`، تقتصر إعادة الاتصال على طلبات `GET` و`HEAD` و`OPTIONS` و`PUT` و`DELETE`. وعند توفيره، تحدّد نتيجته قرار إعادة الاتصال لكل طريقة، بما فيها `POST`؛ ويتيح الحقل `method` في السياق التمييز بين نقاط النهاية. أرجِع `false` لوقف إعادة المحاولة عند هذا الفشل. ويُستدعى ردّ النداء قبل التحقق من حد المحاولات.
- لا تُعاد محاولة الاتصال لأي طلب جسمه `ReadableStream`، ولا يُستدعى `shouldReconnect` لهذا الطلب.
- `delayMs` و`factor` و`jitter` (من 0 إلى 1) و`maxDelayMs` تشكّل التراجع. القيمة الافتراضية لـ `factor` هي `1` ولـ `jitter` هي `0`. يحدّ `maxDelayMs` التأخير النهائي بعد تطبيق `jitter` والتقريب. وفي غياب حد مُهيَّأ، يبقى حد مؤقت المنصة البالغ `2_147_483_647` مللي ثانية ساريًا. يبقى التأخير الأساسي الصفري صفرًا؛ وإذا تجاوز الحساب سعة الأرقام مع مدخلات عددية صالحة، تستقر النتيجة عند الحدود القصوى.
- `delayMs` هو التأخير الأساسي الابتدائي فقط (`1000` افتراضيًا). ويستبدله الحقل `retry:` الذي يرسله الخادم (أرقام فقط، بالمللي ثانية) في المحاولات اللاحقة.
- يُرسل آخر معرّف حدث مرة أخرى على هيئة بايتات UTF-8 في `Last-Event-ID` عند المحاولة التالية. يمسحه حقل `id:` الفارغ؛ ويُتجاهل المعرّف الذي يحتوي على NUL.
- تُفحَص خيارات إعادة الاتصال قبل المعترضات أو Fetch: يجب أن يكون `attempts` عددًا صحيحًا آمنًا غير سالب؛ وأن يكون `delayMs` و`maxDelayMs` المحدَّد صراحةً منتهيين وغير سالبين؛ وأن يكون `factor` منتهيًا وموجبًا؛ وأن يكون `jitter` منتهيًا وضمن 0–1. تُرجع القيم غير الصالحة `REQ_OPTIONS_INVALID` عند التنفيذ.
