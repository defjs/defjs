```ts
type RequestDefinition<
  TInput extends AnyStruct | undefined = undefined,
  TOutput extends AnyStruct | undefined = undefined,
  TError extends AnyStruct | undefined = undefined,
> = ResponseDeclaration<TOutput, TError> & {
  builder?: OutboundBuilder
  input?: TInput
  method: string
  operation?: string
  path: string
}
```

يعلن `output` جسم استجابة 2xx، ويعلن `error` جسم أي استجابة أخرى. يعمل أحدهما فقط في كل مرة، وإغفال أحدهما يعني أن ذلك الجسم لا يُقرأ أبدًا. `ResponseDeclaration` نوع مساعد داخلي: لا يكون `output` و`error` مطلوبين إلا عندما يكون معامل النوع المقابل struct. لا يوجد `responseType`: نوع الـ struct هو الذي يحدد كيف يُقرأ الجسم المعلَن. أما `input` المعلَن فيتطلب دائمًا `builder` صريحًا، حتى لو كان مطابقًا أصلًا لشكل الطلب. وحدها التعريفات التي لا تملك `input` يجوز أن تُغفل `builder`.
