# SSE

أعلن تدفق أحداث، نفّذه، كرّر الأحداث، ثم أغلق.

## defineEventStream()

```ts
function defineEventStream(definition: EventStreamDefinition): EventStreamEndpoint
```

- **definition** — `path`، وخريطة `events`، والحدّان المطلوبان `maxBufferSize` و`maxQueueSize` (عددان صحيحان موجبان)؛ و`method` اختياري (الافتراضي `'GET'`)، و`operation` و`input` و`error` اختيارية. عند التصريح بـ `input`، يجب دائمًا توفير `builder` صريح، حتى لو كان المدخل يطابق شكل الطلب أصلًا. يمكن حذف `builder` فقط من التعريفات التي لا تصرّح بـ `input`.
- **يُرجع** نقطة نهاية. استدعِها بالمدخل لتحصل على `EventStreamCommand`.

## executeEventStreamCommand()

```ts
function executeEventStreamCommand(
  clientConfig: ClientConfig,
  command: EventStreamCommand,
  options?: EventStreamExecuteOptions,
): Promise<StreamAwaitResult>
```

مدخل منخفض المستوى لـ `client.execute`. فضّل العميل في شيفرة التطبيق.

- **يُرجع** `[null, stream, open]` أو `[error, undefined, open?]`. عند إعلان `error` يكون الخطأ `Fault` لذلك الـ struct؛ وإلا فهو `Fault<undefined>`.

## خيارات التنفيذ

## EventStreamExecuteOptions

```ts
type EventStreamExecuteOptions = ({ abort?: AbortSignal; timeout?: never } | { abort?: never; timeout?: number }) & {
  signal?: AbortSignal
}
```

نفس قواعد إلغاء HTTP: `abort` أو `timeout`، لا كلاهما (النوع يرفض الاثنين معًا، وتمريرهما معًا وقت التشغيل يفشل بـ `REQ_OPTIONS_INVALID`)؛ ويتحد `signal` مع أيٍّ منهما. `timeout` مهلة بدء: تشمل تحليل المدخل والـ `builder` والمعترضات والمصافحة، ولا تُجهض تدفقًا مفتوحًا. `withTimeout` لا يُطبَّق على SSE.

## EventStreamHandle

```ts
interface EventStreamHandle<TEvent> extends AsyncIterable<TEvent>, AsyncDisposable {
  readonly open: EventStreamOpenInfo
  readonly closed: Promise<EventStreamCloseInfo>
  close(reason?: unknown): void
  [Symbol.asyncDispose](): PromiseLike<void>
}
```

الخانة الثالثة في الـ tuple هي لقطة البدء لـ `open`؛ أما `stream.open` فيتبع أحدث اتصال بعد إعادة الاتصال. فضّل `await using stream = handle` لتنظيف النطاق المملوك. المتخلّص يوقف قراءة Defjs وعمل إعادة الاتصال وينتظر تحرير قفل القارئ؛ ولا يعد بأن وعد `ReadableStream.cancel()` العالق الذي يتحكم به المزوّد سينتهي. يبقى `close()` / `closed` اليدويان متاحين.

```ts
async function consume(handle: EventStreamHandle<unknown>): Promise<void> {
  await using stream = handle
  for await (const event of stream) console.log(event)
}
```

التطبيقات البنيوية لـ `EventStreamHandle` يجب أن تنفّذ الآن `[Symbol.asyncDispose]()` وتُرجع مسار التخلّص المملوك نفسه. هذا تغيير كاسر وقت الترجمة للمقابض المخصصة؛ والكود الذي يستقبل فقط مقابض تعيدها Defjs بلا متطلب استدعاء وقت تشغيل جديد.

### EventStreamOpenInfo

```ts
interface EventStreamOpenInfo {
  response: HttpResponse<unknown>
  url: string
}
```

### EventStreamCloseInfo

```ts
type EventStreamCloseInfo =
  | { kind: 'eof'; reason?: string; cause?: unknown }
  | { kind: 'aborted'; reason?: string; cause?: unknown }
  | { kind: 'error'; code: EventStreamFaultCode; reason?: string; cause?: unknown }
```

`EventStreamFaultCode`: `'CAP_BUFFER_EXCEEDED' | 'CAP_QUEUE_OVERFLOW' | 'EXT_HOOK_FAILED' | 'EXT_OBSERVER_FAILED' | 'NET_TIMEOUT' | 'NET_UNREACHABLE' | 'RES_DECODE_FAILED' | 'RES_MEDIA_TYPE_INVALID'`.

## خريطة الأحداث

## EventStructs

```ts
type EventStructs = { [eventName: string]: AnyStruct }
```

المفتاح هو اسم حدث SSE؛ والرسالة التي لا تحمل حقل `event:` اسمها `message`. عندما لا يطابق أي مفتاح، يُستخدم struct الـ `default`. struct حدث من نوع `string` يُبقي نص `data` الخام. كل نوع آخر هو نص JSON: `JSON.parse`، ثم الـ struct. لذلك يحتاج `struct.literal` العاري نص JSON، لا رمزًا بلا اقتباس. أجسام `error` في المصافحة تستخدم قاعدة النوع نفسها كـ HTTP: `string` نص، و`blob` / `file` blobs، و`arrayBuffer` بايتات، وكل ما عدا ذلك JSON.

إعادة الاتصال تعيش على العميل (`withSSEReconnect`). `jitter` في SSE **عامل ضربي بين 0 و1**، مثل WebSocket.

انظر [دليل SSE](/ar/docs/sse) و[استهلاك تدفق SSE](/ar/recipes/consume-sse).

## EventStreamDefinition

`path` و`events`، و`maxBufferSize` و`maxQueueSize` مطلوبان، و`method` / `operation` / `input` / `error` اختيارية. شكل الطلب يطابق HTTP، بما في ذلك `body`. `GET` و`HEAD` لا يمكنهما إرجاع جسم. عند التصريح بـ `input`، يجب دائمًا توفير `builder` صريح، حتى لو كان المدخل يطابق شكل الطلب أصلًا. يمكن حذف `builder` فقط من التعريفات التي لا تصرّح بـ `input`.

## EventStreamEndpoint

يعيده `defineEventStream`. استدعه بالمدخل لتحصل على `EventStreamCommand`.

## EventStreamRequestShape

نفس حقول `HttpRequestShape` لطريقة التدفق ومساره.

## EventStreamCommand

أمر SSE معتم. مرّره إلى `client.execute`.

## StreamAwaitResult

`[null, stream, open]` أو `[error, undefined, open?]`.

## EventStreamData

حمولة الحدث المحللة المستنتجة من خريطة `EventStructs`.
