# WebSocket

أعلن مقبسًا، واستدعِ العملية بعميل، وأرسل رسائل محدَّدة الأنواع واستقبلها، ثم أغلق.

## defineWebSocket()

<ApiSignature name="defineWebSocket" />

- **definition** — `path` وstruct `incoming` واحد والعدد الصحيح الموجب المطلوب `maxIncomingQueueSize`؛ وstructا `outgoing` و`input` اختياريان و`operation` و`protocols` ثابتة و`maxOutgoingQueueSize` غير سالب. `input` المعلَن يتطلب دائمًا `builder` صريحًا. يقتصر `input` على تعريف المعاملات؛ والـ builder وحده يقرر أين تذهب كل قيمة. يمكن حذف `builder` فقط من التعريفات التي لا تعلن `input`. أعضاء `definition` هذه موثّقة تحت [`WebSocketDefinition`](/ar/api/core/websocketdefinition-type). `builder` مطلوب تمامًا عندما يُعلَن `input`.
- **يُرجع** عملية. الوسيط الأول هو [`Client`](/ar/api/core/client-type). الوسائط التالية هي المدخل فقط. استدعاؤها يفتح الجلسة.

<include cwd>examples/api/define-web-socket.ts#example</include>

يُرجع الاستدعاء `[null, session, connection]` أو `[error, undefined, connection?]`. مرّر خيارات كل استدعاء باشتقاق عميل من [`RequestOptions`](/ar/api/core/requestoptions-type). يقرأ WebSocket الحقول `abort` و`beforeConnect` و`heartbeat` و`protocols` و`reconnect`، ويتجاهل حقول تقدّم HTTP.

يستبدل كل من `beforeConnect` و`heartbeat` و`protocols` و`reconnect` قيمة العميل لذلك الاستدعاء كاملة. أسبقية البروتوكول هي العميل المشتق، ثم `withWebSocketProtocols`، ثم `protocols` في التعريف. `heartbeat.timeoutMs` هو انتظار الإقرار، وليس مهلة للطلب.

## WebSocketSession

<ApiSignature name="WebSocketSession" />

فضّل `await using ownedSession = session` لتنظيف النطاق المملوك. يبقى `session.close()` اليدوي و`await session.closed` متاحين.

```ts
async function consume(
  session: WebSocketSession<unknown, never>,
): Promise<void> {
  await using ownedSession = session;
  for await (const message of ownedSession.receive) console.log(message);
}
```

يبلّغ `closed` عن الحالة النهائية المنطقية. يطلب المتخلّص غير المتزامن إغلاقًا أصليًا وينتظر تفكيك ما يملكه Defjs، لكنه يحدّ حدث الإغلاق الغائب بثانية واحدة وقد يرفض بـ `DOMException` باسم `TimeoutError`. وهو لا يستطيع إثبات أن اتصال TCP الفيزيائي أُغلق.

### WebSocketState

`'idle' | 'connecting' | 'open' | 'closing' | 'closed' | 'reconnecting' | 'aborted' | 'error'`

### WebSocketConnectionInfo

`generation` (يزيد عند إعادة الاتصال)، وعند المعرفة `url` و`protocol` و`extensions`.

### WebSocketCloseInfo

<ApiSignature name="WebSocketCloseInfo" />

`kind` هو `closed` أو `aborted` أو `error`. `cause` غائب في `closed`، واختياري في `aborted`، ومطلوب في `error`. قد تظهر `code` و`reason` و`wasClean` في كل صيغة. يملأ `session.close()` اليدوي `code` و`reason` على `{ kind: "closed" }` عندما لا يحمل حدث الإغلاق أيًا منهما.

## WebSocketExecuteOptions

<ApiSignature name="WebSocketExecuteOptions" />

`WebSocketExecuteOptions` هو [`UseWebSocketConfig`](/ar/api/core/usewebsocketconfig-type): `beforeConnect` و`heartbeat` و`protocols` و`reconnect` و`abort`. `WebSocketHeartbeatConfig`: `intervalMs`، و`message` و`isAck` و`timeoutMs` الاختيارية. لا يوجد حقل `timeout` أو `signal`.

يغطي `abort` الجلسة كاملة، بما فيها ما بعد فتحها. المهلة هي `AbortSignal.timeout(ms)` وتُصنَّف `NET_TIMEOUT`. الإجهاض اليدوي هو `NET_ABORTED`. لا توجد مهلة للبدء فقط ولا مهلة افتراضية على مستوى العميل. `abort` هو إشارة الاستدعاء؛ اجمع الإشارات بـ `AbortSignal.any` في شيفرة التطبيق. يُستبدل `heartbeat` كاملًا؛ وينتظر `timeoutMs` فيه إقرارًا وليس مهلة للطلب.

عندما يُضبط `reconnect`، تكون `attempts` افتراضيًا 3 لكل انقطاع؛ و`0` يعطّل. يعيد `open` الناجح ضبط الميزانية وأُس التراجع، فيبدأ كل انقطاع جديد عند إعادة المحاولة 1. حذف `attempts` لا يمنح محاولات غير محدودة داخل انقطاع واحد. انظر [العميل](/ar/api/client) للافتراضيات وقواعد التحقق.

## الرسائل

`incoming` هو struct واحد. تُقرأ إطارات النص و`ArrayBuffer` والمصفوفة محدَّدة النوع و`Blob` كـ UTF-8، ثم تُحلَّل JSON، ثم تُفحص مقابل ذلك الـ struct. الإطار الذي يفشل في تحليل JSON أو الـ struct يُبلَّغ إلى `session.onRuntimeError` ولا يُوضَع في الطابور. لا يوجد خيار إطار غير صالح على العميل.

`outgoing` هو struct واحد. يقبل `session.send` القيمة `StructInput` لذلك الـ struct، ويرمّز الأسماء المستعارة، ثم `JSON.stringify`. القيم التي لا يستطيع JSON تمثيلها بأمانة بعد الترميز ترمي `TypeError` قبل الإرسال أو دخول طابور إعادة الاتصال، بما فيها الأعداد غير المحدودة والدوال والرموز و`Map` و`Set` والتدفقات ونسخ الأصناف بلا تمثيل JSON. تستخدم القيم المتداخلة الحارس نفسه لأجسام JSON في HTTP. يستخدم النبض ذلك الحارس أيضًا؛ وفشل تسلسل النبض ينهي الجلسة. عدة أنواع رسائل هي `struct.discriminatedUnion`.

```ts
session.send({ type: "message", text: "Hello" });
```

انظر [دليل WebSocket](/ar/docs/web-socket) و[فتح جلسة WebSocket](/ar/recipes/websocket-session).

## WebSocketDefinition

`path` و`incoming` و`maxIncomingQueueSize` المطلوب، و`outgoing` / `input` / `operation` / `protocols` / `maxOutgoingQueueSize` الاختيارية. يجوز للـ builder إرجاع `path` و`query` فقط. `input` المعلَن يتطلب دائمًا `builder` صريحًا. يقتصر `input` على تعريف المعاملات؛ والـ builder وحده يقرر أين تذهب كل قيمة. يمكن حذف `builder` فقط من التعريفات التي لا تعلن `input`.

## WebSocketEndpoint

يُرجعه `defineWebSocket`. الوسيط الأول عميل. الوسائط التالية هي المدخل فقط.

## WebSocketRequestShape

`path` و`query` فقط. `headers` و`body` هما `never`.

## UseWebSocketConfig

`beforeConnect` و`heartbeat` و`protocols` و`reconnect` و`abort`. `WebSocketExecuteOptions` هو هذه الشريحة. لا يوجد حقل `signal`.

## SocketAwaitResult

`[null, session, connection]` أو `[error, undefined, connection?]`.

## ManualSocketCloseReason

السبب المسجَّل عند إغلاق الجلسة عبر `session.close()`.

## WebSocketHeartbeatConfig

`intervalMs`، و`message` و`isAck` و`timeoutMs` الاختيارية.

## WebSocketIncomingData

الإطار الوارد المفكوك: `Infer` لـ struct `incoming`.

## WebSocketOutgoingData

القيمة التي يقبلها `session.send`: `StructInput` لـ struct `outgoing`، أو `never` عندما لا يُعلَن شيء.

## SocketLifecycleOutcome

نتيجة محاولة اتصال واحدة (`closeInfo` و`connection` و`cause` و`opened`)، يستخدمها منطق إعادة الاتصال. وهي ليست النتيجة النهائية للجلسة؛ انظر `WebSocketCloseInfo` لذلك.
