```ts
interface OpenTelemetryServerWebSocketOptions extends OpenTelemetryServerTransportOptions<WebSocketSessionLike> {
  queryPropagation?: boolean
}
```

تُضبط على `webSocket` في `OpenTelemetryServerOptions`. تأتي `enabled` و`startSpanHook` و`requestHook` و`responseHook` من `OpenTelemetryServerTransportOptions`؛ ويستقبل `responseHook(span, session, req)` الـ `WebSocketSessionLike` المفتوحة و`HttpRequest` الأصلي.

`queryPropagation` افتراضيًا `false`: تُترك سلسلة استعلام WebSocket دون تغيير ولا يُكتب سياق تتبع أو baggage في عنوان URL. عملاء WebSocket في المتصفح لا يستطيعون عادة تعيين الرؤوس، لذا يُلحق تفعيله السياقَ المنشور بسلسلة الاستعلام. قد تسجّل الوكلاء وسجلات الوصول وأدوات APM سلاسل الاستعلام، وقد تكون قيم baggage حسّاسة. فعّله فقط بعد أن تقبل هذا الانكشاف.

يُتتبَّع WebSocket على مستوى الاتصال. يبقى الـ span مفتوحًا حتى يستقر `session.closed`. ويسجّل `websocket.connected`، ثم `websocket.closed` للإغلاق الطبيعي أو `websocket.error`. ويُعدّ إطار الإغلاق (close frame) القادم من الخادم إغلاقًا طبيعيًا بأي رمز، بما في ذلك 1011. أما الانقطاع المفاجئ بلا إطار إغلاق (1006) فهو إغلاق طبيعي فقط حيث لا تُبلغ بيئة التشغيل عن `error` في المقبس قبل `close` (Bun)؛ وحيث تفعل (Node.js) تنتهي الجلسة بخطأ وتُسجَّل مرة واحدة. وإلغاء المستدعي لجلسة مفتوحة هو أيضًا `websocket.error`: ينتهي الـ span بحالة `ERROR` ولا يُصدَر سجل. ويتبع `error.type` سبب الإلغاء: `AbortError` للاستدعاء الافتراضي `abort()`، و`Error.name` لسبب من نوع `Error`، و`string` لسبب نصي. أما الإلغاء بينما لا يزال WebSocket قيد الاتصال فينهي الـ span بحالة `ERROR` مع `error.type` بقيمة `DefjsFault`. لا تُنشأ spans لكل رسالة.

مرّر `{ enabled: false }` لتخطي رصد WebSocket. لا تعمل خطافات span إلا عند تمرير `tracer`.
