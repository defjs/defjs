# Сессии WebSocket

Функция `defineWebSocket` объявляет двунаправленный контракт WebSocket в вашем SDK: шаблон пути, опциональные `input` и `builder` (только для `path` и `query`), структуры входящих `incoming` и исходящих `outgoing` сообщений, ограничения очереди и статические субпротоколы. Использующее приложение настраивает heartbeat, повторные подключения и очистку ресурсов на клиенте.

## 1. Объявление контракта и запуск сессии

Моделируйте различные типы кадров для `incoming` или `outgoing` с помощью `struct.discriminatedUnion(...)`. Освобождайте возвращённый объект `WebSocketSession` с помощью `await using` либо явного вызова `session.close()` + `await session.closed`:

<Tabs items={["sdk/ticks-socket.ts", "app/session.ts", "Single-file quick look"]}>
<Tab value="sdk/ticks-socket.ts">

```ts
import { defineWebSocket, struct } from "@defjs/core";

export const TickFrame = struct.discriminatedUnion("type", [
  struct.object({
    type: struct.literal("tick"),
    symbol: struct.string(),
    price: struct.number(),
  }),
  struct.object({
    type: struct.literal("subscribed"),
    symbol: struct.string(),
  }),
]);

export const SubscribeCommand = struct.object({
  type: struct.literal("subscribe"),
  symbol: struct.string(),
});

export const openTicker = defineWebSocket({
  path: "/market/ws",
  operation: "market.ticker",
  incoming: TickFrame,
  outgoing: SubscribeCommand,
  maxIncomingQueueSize: 64,
});
```

</Tab>
<Tab value="app/session.ts">

```ts
import { createClient, withEndpoint } from "@defjs/core";
import { openTicker } from "../sdk/ticks-socket.ts";

const client = createClient(withEndpoint("https://api.example.com"));

async function main() {
  const [error, session] = await openTicker(client);
  if (error) {
    console.error(error.code);
    return;
  }

  await using active = session;
  active.send({ type: "subscribe", symbol: "ACME" });

  for await (const message of active.receive) {
    if (message.type === "tick") {
      console.log(message.symbol, message.price);
      break;
    }
  }
}

void main();
```

## 2. Валидация сообщений и правила направлений

- **Входящие кадры (`session.receive`)**: текстовые кадры, `ArrayBuffer`, типизированные массивы и `Blob` декодируются в UTF-8, парсятся как JSON и валидируются структурой `incoming`. Невалидный JSON или несоответствие схеме передаются в `session.onRuntimeError` и отбрасываются без закрытия сессии. Очередь `session.receive` рассчитана на одного потребителя: попытка получить второй итератор выбрасывает `TypeError`.
- **Исходящие кадры (`session.send(payload)`)**: синхронно валидируются схемой `outgoing`, применяют `.alias()` и кодеки и сериализуются через `JSON.stringify`. Отправляются немедленно в состоянии `open`, встают в очередь при `reconnecting` (если `maxOutgoingQueueSize > 0`) и выбрасывают синхронную ошибку, если полезная нагрузка невалидна, очередь переполнена/отключена или сессия закрыта.

## 3. Состояние сессии и наблюдатели

| Член                 | Описание                                                                                              |
| -------------------- | ----------------------------------------------------------------------------------------------------- |
| `state`              | `'idle' \| 'connecting' \| 'open' \| 'reconnecting' \| 'closing' \| 'closed' \| 'aborted' \| 'error'` |
| `connection`         | Живой снимок последнего физического сокета (`generation`, `url`, `protocol`, `extensions`)            |
| `bufferedAmount`     | Количество неотправленных байтов в активном физическом сокете (`0` при отключении)                    |
| `receive`            | Асинхронный итерируемый объект валидированных сообщений `incoming` (один потребитель)                 |
| `onStateChange(fn)`  | Подписка на переходы состояний; возвращает функцию отписки `unsubscribe`                              |
| `onRuntimeError(fn)` | Подписка на ошибки разбора кадров не при старте; возвращает функцию отписки `unsubscribe`             |
| `closed`             | Promise, разрешающийся терминальным исходом (`kind: 'closed' \| 'aborted' \| 'error'`)                |

## 4. Повторное подключение, heartbeat и очереди

- **Повторное подключение**: значения по умолчанию при включении: `attempts: 3`, `delayMs: 1000`, `factor: 2`, `maxDelayMs: 30000`, `jitter: 0`. Каждое физическое открытие сокета (`open`) сбрасывает лимит попыток. Колбэк `beforeConnect({ attempt, signal })` вызывается перед первоначальным подключением и перед каждой попыткой повторного соединения.
- **Heartbeat**: периодически отправляет сообщение `message()` через структуру `outgoing` и ожидает до `timeoutMs` кадр, удовлетворяющий условию `isAck(msg)`. Подходящие ack-кадры поглощаются монитором heartbeat и не передаются в `session.receive`. Пропущенный ack приводит к фатальному завершению сессии.
- **Ограничения очередей**:
  - `maxIncomingQueueSize` (обязательное положительное целое): переполнение фатально завершает сессию ошибкой `CAP_QUEUE_OVERFLOW`. Продолжайте читать `session.receive`, пока сессия открыта.
  - `maxOutgoingQueueSize` (опциональное неотрицательное целое, по умолчанию `0`): буферизует вызовы `session.send()` только пока `state === 'reconnecting'` и сбрасывает их перед публикацией следующего события `open`.

## 5. Субпротоколы и аутентификация [#protocols-and-authentication]

Браузерные WebSocket не поддерживают произвольные заголовки хэндшейка, поэтому функция `builder` для WebSocket возвращает только `{ path?, query? }`.

- **Приоритет субпротоколов**: `client({ protocols })` переопределяет `withWebSocketProtocols(...)`, который переопределяет `defineWebSocket({ protocols })`.
- **Преобразование протокола URL**: Defjs автоматически преобразует `http:` → `ws:` и `https:` → `wss:` в разрешённом эндпоинте.
- **Учётные данные**: опция `withCredentials(true)` относится только к Fetch (HTTP/SSE). Аутентифицируйте соединения WebSocket с помощью cookies/сессионных политик, субпротоколов или короткоживущих тикетов подключения — избегайте передачи долгоживущих секретов в параметрах запроса query.

## 6. Закрытие и владение сессией

Вызовите `session.close(code?, reason?)` (где `code` равен `1000` или лежит в диапазоне `3000..4999`, а `reason` не превышает 123 байт UTF-8) и дождитесь `await session.closed`, либо используйте `await using`:
