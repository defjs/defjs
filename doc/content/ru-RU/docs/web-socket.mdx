# Сессии WebSocket

Функция `defineWebSocket` объявляет двунаправленный контракт WebSocket в вашем SDK: шаблон пути, опциональные `input` и `builder` (только для `path` и `query`), структуры входящих `incoming` и исходящих `outgoing` сообщений, ограничения очереди и статические субпротоколы. Использующее приложение настраивает heartbeat, повторные подключения и очистку ресурсов на клиенте.

## 2. Валидация сообщений и правила направлений

- **Входящие кадры (`session.receive`)**: текстовые кадры, `ArrayBuffer`, типизированные массивы и `Blob` декодируются в UTF-8, парсятся как JSON и валидируются структурой `incoming`. Невалидный JSON или несоответствие схеме передаются в `session.onRuntimeError` и отбрасываются без закрытия сессии. Очередь `session.receive` рассчитана на одного потребителя: попытка получить второй итератор выбрасывает `TypeError`.
- **Исходящие кадры (`session.send(payload)`)**: синхронно валидируются схемой `outgoing`, применяют `.alias()` и кодеки и сериализуются через `JSON.stringify`. Отправляются немедленно в состоянии `open`, встают в очередь при `reconnecting` (если `maxOutgoingQueueSize > 0`) и выбрасывают синхронную ошибку, если полезная нагрузка невалидна, очередь переполнена/отключена или сессия закрыта.

## 3. Состояние сессии и наблюдатели

| Член                 | Описание                                                                                              |
| -------------------- | ----------------------------------------------------------------------------------------------------- |
| `state`              | `'idle' \| 'connecting' \| 'open' \| 'reconnecting' \| 'closing' \| 'closed' \| 'aborted' \| 'error'` |
| `connection`         | Живой снимок последнего физического сокета (`generation`, `url`, `protocol`, `extensions`)            |
| `bufferedAmount`     | Количество неотправленных байтов в активном физическом сокете (`0` при отключении)                    |
| `receive`            | Асинхронный итерируемый объект валидированных сообщений `incoming` (один потребитель)                 |
| `onStateChange(fn)`  | Подписка на переходы состояний; возвращает функцию отписки `unsubscribe`                              |
| `onRuntimeError(fn)` | Подписка на ошибки разбора кадров не при старте; возвращает функцию отписки `unsubscribe`             |
| `closed`             | Promise, разрешающийся терминальным исходом (`kind: 'closed' \| 'aborted' \| 'error'`)                |

- **Повторное подключение**: значения по умолчанию при включении: `attempts: 3`, `delayMs: 1000`, `factor: 2`, `maxDelayMs: 30000`, `jitter: 0`. Каждое физическое открытие сокета (`open`) сбрасывает бюджет попыток. Колбэк `beforeConnect({ attempt, signal })` вызывается перед первоначальным подключением и перед каждой попыткой повторного соединения.
- **Таймаут хэндшейка (`connectTimeoutMs`)**: если задан, он должен быть конечным, положительным и не больше 2147483647 (предел таймера); иначе операция возвращает `REQ_OPTIONS_INVALID`. Ограничивает конструирование до `open` и сбрасывается после хэндшейка.
- **Heartbeat**: Периодически отправляет сообщение `message()` через структуру `outgoing` и ожидает до `timeoutMs` кадр, удовлетворяющий условию `isAck(msg)`. Подходящие ack-кадры поглощаются монитором heartbeat и не передаются в `session.receive`. Пропущенный ack фатален для логической сессии: `closed.kind` равен `"error"`, а `closed.cause` — обычный `Error("WebSocket heartbeat timeout")`; переподключение не запускается. Ошибки сериализации heartbeat идут по тому же фатальному пути с исходной причиной.
- **Ограничения очередей**:
  - `maxIncomingQueueSize` (обязательное положительное целое): Ограничивает и сырые кадры, ожидающие декодирования, и декодированные сообщения, ожидающие потребителя. Переполнение завершает сессию с Fault `CAP_QUEUE_OVERFLOW` в `closed.cause`; та же причина передаётся в `onRuntimeError` и отклоняет `session.receive`. Продолжайте читать `session.receive`, пока сессия открыта.
  - `maxOutgoingQueueSize` (опциональное неотрицательное целое, по умолчанию `0`): буферизует вызовы `session.send()` только пока `state === 'reconnecting'` и сбрасывает их перед публикацией следующего события `open`.

`shouldReconnect` получает нативный код закрытия и `wasClean`. Сервер может завершить штатный хэндшейк закрытия с кодом ошибки приложения `1011`, поэтому `wasClean === true` не означает успех приложения. Пример явно допускает `1011`; выбирайте коды приложения по своему протоколу, а не полагайтесь лишь на `!wasClean`.

## 5. Субпротоколы и аутентификация [#protocols-and-authentication]

Браузерные WebSocket не поддерживают произвольные заголовки хэндшейка, поэтому функция `builder` для WebSocket возвращает только `{ path?, query? }`.

- **Приоритет субпротоколов**: `client({ protocols })` переопределяет `withWebSocketProtocols(...)`, который переопределяет `defineWebSocket({ protocols })`.
- **Преобразование URL**: Defjs автоматически преобразует `http:` → `ws:` и `https:` → `wss:` в разрешённом эндпоинте.
- **Учётные данные**: опция `withCredentials(true)` относится только к Fetch (HTTP/SSE). Аутентифицируйте соединения WebSocket с помощью cookies/сессионных политик, субпротоколов или короткоживущих тикетов подключения — избегайте передачи долгоживущих секретов в параметрах запроса query.
- **`beforeConnect` не изменяет запрос**: Разбор входных данных, синхронный чистый `builder` и цепочка перехватчиков выполняются один раз на операцию. Для запроса, базовый эндпоинт которого не заменён перехватчиком, каждое переподключение заново выбирает эндпоинт и пересобирает URL с ним, но повторно использует собранные path/query и зафиксированный список протоколов. URL фиксируется до выполнения `beforeConnect` этой попытки как на том же эндпоинте, так и после переключения на резервный. Изменение переменной замыкания, входных данных или массива протоколов в хуке не может предоставить свежий тикет текущему хэндшейку. Обновление учётных данных URL/субпротокола внутри одной сессии не поддерживается; сначала получите новые учётные данные, передайте их как входные данные или конфигурацию клиента в новую операцию, затем возьмите на себя очистку заменяющей сессии.

## 6. Закрытие и владение сессией

Вызовите `session.close(code?, reason?)` (где `code` равен `1000` или лежит в диапазоне `3000..4999`, а `reason` не превышает 123 байт UTF-8) и дождитесь `await session.closed`, либо используйте `await using`:

Когда при обрыве исчерпаны попытки переподключения, сессия завершается с `closed.kind: "error"`, нативным снимком закрытия (часто код `1006` при неудачном upgrade) и обычной транспортной ошибкой в `closed.cause`; отдельного стабильного кода исчерпания нет. Всегда отписывайте слушателей `onStateChange` и `onRuntimeError`, когда работа компонента или воркера завершена.
