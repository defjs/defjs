# Перехватчики

Перехватчики (interceptors) подключают сквозные политики выполнения — заголовки аутентификации, подпись запросов, прерывание на время регламентных работ или повтор безопасных чтений — к `Client` приложения без изменения определений операций SDK.

Валидация входных данных и маппинг в `builder` выполняются **до** цепочки перехватчиков; маршрутизация по HTTP-статусу и валидация структур `output` / `error` выполняются **после** цепочки.

### Правила конвейера перехватчиков

- **Луковичная модель (onion order)**: перехватчики выполняются в порядке регистрации на пути к транспорту (`до next(req)`) и в обратном порядке на пути обратно (`после await next(req)`). Размещайте общие перехватчики логирования и трассировки снаружи относительно более узких перехватчиков аутентификации или повторов.
- **Соглашение о неизменяемости запроса**: всегда клонируйте заголовки `req.headers` (`new Headers(req.headers)`) и передавайте новый объект запроса (`{ ...req, headers }`) в `next(...)`, чтобы внешние повторные попытки видели чистые заголовки.
- **`content-type` и `bodyContentType`**: Defjs сохраняет выведенный тип контента тела в `req.bodyContentType` без мутации `req.headers`. Механизмы подписи запросов должны читать `req.headers.get("content-type") ?? req.bodyContentType`. Если перехватчик заменяет `req.body` новым форматом, установите явный заголовок `content-type`.

## 3. Повтор безопасных HTTP-запросов на чтение

Повторы HTTP выключены по умолчанию. Для переключения на другой эндпоинт при `502`, `503` или `504` используйте [`withRetry({ on: ["gateway-error"] })`](/ru-RU/docs/load-balancing). Он заново выбирает ещё не опробованный эндпоинт, пересобирает запрос и повторно выполняет всю цепочку перехватчиков.

Вместо этого перехватчик приложения может обрабатывать статусы на том же эндпоинте, например `429` и `Retry-After`. Этот ограниченный рецепт безопасных чтений также обрабатывает `502`/`503`/`504`:

<include cwd lang="typescript">
  examples/interceptors/retry-safe-reads.ts#example
</include>

- **Два слоя повторов**: Этот цикл `next(request)` остаётся на выбранном эндпоинте и не запускает заново внешнюю аутентификацию или builder. Сочетание трёх внутренних отправок с `withRetry({ maxAttempts: 2, on: ["gateway-error"] })` может отправить четыре HTTP-запроса (три на сбойный основной узел и один на исправный резервный); `maxAttempts` ограничивает внешние попытки, а не физические отправки. Определите, какой слой отвечает за каждое условие, вместо случайного наложения слоёв.
- **Политика `Retry-After`**: Core `withRetry` не читает этот заголовок. Предел 30 секунд и резервная задержка 250 мс в рецепте — решения приложения. Ограничение более долгой серверной задержки может запустить повтор раньше, чем запрошено; если это недопустимо, выждите весь срок или верните ответ.
- **Записи после 401**: [Рецепт обновления Bearer](/ru-RU/recipes/refresh-bearer-once) может доставить JSON POST дважды. Требуйте отказа аутентификации до бизнес-обработки и стабильного ключа идемпотентности с серверной дедупликацией либо не повторяйте записи автоматически. Потоковые тела запросов не повторяются.

- **Обработка отклонений транспорта**: вызов `next(request)` отклоняется промисом при возникновении сетевой ошибки (ответа со статусом 0 не существует). Перехват и повторный выброс этого исключения сохраняют оригинальный код ошибки `NET_*`.
- **Выброс ошибок внутри перехватчика**: необработанное исключение (или возврат значения, не являющегося ответом) разрешает кортеж операции сбоем `EXT_INTERCEPTOR_FAILED` и устанавливает `fault.cause`. Выброс `ERR_ABORTED` или `ERR_TIMEOUT` разрешается как `NET_ABORTED` или `NET_TIMEOUT`.

Для SSE предпочитайте `withSSEReconnect` перехватчику, многократно вызывающему `next()`. Вызов `next()` перехватчика больше одного раза отключает привязку к эндпоинту и его повторный выбор для этих заменяющих потоков; это не связано с чтением событий через `next()` итератора.

## 4. Оборачивание WebSocket-сессий

WebSocket-перехватчик может вызвать `next(req)` **не более одного раза**. ## 5. Встроенные фабрики и хелперы

| Экспорт                                        | Транспорт | Описание                                                                   |
| ---------------------------------------------- | --------- | -------------------------------------------------------------------------- |
| `createHttpInterceptor(fn)`                    | HTTP      | Оборачивает `(req, next) => Promise<HttpResponse<unknown>>`                |
| `createSSEInterceptor(fn)`                     | SSE       | Оборачивает `(req, next) => Promise<EventStreamHandle<unknown>>`           |
| `createWebSocketInterceptor(fn)`               | WebSocket | Оборачивает `(req, next) => Promise<WebSocketSessionLike>`                 |
| `basicAuthHttpInterceptor(provider, options?)` | HTTP      | Внедряет `Authorization: Basic ...` из синхронного/асинхронного провайдера |
| `basicAuthSSEInterceptor(provider, options?)`  | SSE       | Внедряет `Authorization: Basic ...` в хэндшейк SSE                         |
