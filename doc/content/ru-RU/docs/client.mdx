# Клиент

`Client` — это настройка выполнения приложения-потребителя. `createClient(...)` возвращает [`DerivableClient`](/ru-RU/api/core/derivableclient-type). Вызов фабрики с опциями запроса возвращает значение `Client`, и именно `Client` принимают операции. Оно не вызываемое. Импортируй операции из SDK, выбери адрес сервиса, учётные данные, перехватчики и транспорт, затем вызови операцию с клиентом. `getOrder(client({ signal }), { id: 1 })` начинает вызов, у которого объявлен input. `health(client)` начинает вызов без input. Когда весь входной struct необязателен, допустимы и `search(client)`, и `search(client, input)`. Третьего аргумента с опциями нет. Вызов операции её начинает. `await` только ждёт кортеж error-first.

Определения SDK не привязаны к этому экземпляру. Браузер, серверный запрос и локальный тест могут использовать одну экспортированную операцию с разными клиентами. Все по-прежнему следуют одному контракту Defjs и совместимым версиям Core. Настрой адрес сервиса каждого клиента для операций, которые через него вызываешь.

Одно и то же значение клиента можно передать многим операциям. Кеш и политику повторов выбирает приложение, и оно владеет работой, которую начинает. HTTP автоматически не повторяется. Переподключение потока включается явно.

Фабрика — функция и одновременно `Client` без опций запроса. Не передавай фабрику в setter состояния React: `setState(factory)` вызовет её как updater. Не используй её как источник Vue `watch` или `computed`: они вызывают функцию. Выведенное значение клиента — обычный объект.

## Выведи клиент

`client(options?)` возвращает значение `Client` для одного вызова. `client()` и `client(undefined)` не сохраняют опции запроса. `client({})` оставляет пустой снимок; Defjs не отбрасывает его проверкой ключей. При вызове `client(options)` каждое поле запроса верхнего уровня читается один раз и кладётся в новый объект опций. Массив `protocols` копируется. `heartbeat` копирует `intervalMs`, `isAck`, `message` и `timeoutMs`. `reconnect` копирует `attempts`, `delayMs`, `factor`, `jitter`, `maxDelayMs` и `shouldReconnect`. Отсутствующие вложенные блоки остаются отсутствующими, поэтому не включают heartbeat или повторные попытки. `signal`, `beforeConnect` и каждый колбэк сохраняют свою идентичность. Тот же объект опций можно передать снова; каждый вызов захватывает собственные контейнеры. Вывод не делает I/O. Геттер на этих фиксированных полях выполняется во время `client(options)`. Если он бросает, исключение выходит из этого вызова и оставляет фабрику рабочей. Оно не превращается в fault. Числа вне диапазона по-прежнему проверяются, когда выполняется операция, и по-прежнему возвращают `REQ_OPTIONS_INVALID`. Значение клиента не вызываемое; создавай его на каждый вызов.

`signal` не объединяется. Повторное использование значения клиента с `signal` делит этот сигнал между вызовами, поэтому создавай значение клиента на каждый вызов. Объединяй сигналы через `AbortSignal.any` в коде приложения.

Базовая конфигурация из `createClient` общая для каждого значения клиента и во время выполнения не заморожена. Она фиксирована по соглашению: библиотека её не меняет, и приложению тоже не следует. Стандартные хелперы, такие как `withWebSocketHeartbeat`, `withWebSocketReconnect`, `withSSEReconnect` и `withWebSocketProtocols`, копируют свои фиксированные records, когда хелпер применяется. Свой client option всё ещё может хранить собственную ссылку. `withInterceptors` добавляет для каждого элемента свежий record `{ kind, fn }` и оставляет сам `fn`. Выведенный клиент несёт захваченный объект [`RequestOptions`](/ru-RU/api/core/requestoptions-type) только если опции были переданы. У фабрики, `client()` и `client(undefined)` его нет. Код приложения передаёт клиент операции. Это внутреннее состояние он не читает.

## Опции запроса

У [`RequestOptions`](/ru-RU/api/core/requestoptions-type) семь плоских полей. Каждый протокол читает только известные ему поля и игнорирует остальные. Передать `heartbeat` в HTTP-операцию — значит, что поле игнорируется, а не что это fault. SSE читает из опций запроса только `signal`. Переподключение SSE берётся из конфигурации клиента (`withSSEReconnect`), поэтому `client({ reconnect })` влияет только на WebSocket. Фильтра протокола на этапе компиляции нет.

| Поле                 | Кто использует       | Правило                                                                                             |
| -------------------- | -------------------- | --------------------------------------------------------------------------------------------------- |
| `signal`             | HTTP, SSE, WebSocket | Прерывает вызов. Дедлайн — `AbortSignal.timeout(ms)` (`NET_TIMEOUT`). Ручной abort — `NET_ABORTED`. |
| `onUploadProgress`   | HTTP                 | SSE и WebSocket игнорируют.                                                                         |
| `onDownloadProgress` | HTTP                 | SSE и WebSocket игнорируют.                                                                         |
| `beforeConnect`      | WebSocket            | Заменяет настройку клиента для этого вызова.                                                        |
| `protocols`          | WebSocket            | Заменяет список клиента. Он не дописывается.                                                        |
| `heartbeat`          | WebSocket            | Заменяется целиком. `timeoutMs` — ожидание подтверждения heartbeat, а не дедлайн запроса.           |
| `reconnect`          | WebSocket            | Заменяется целиком.                                                                                 |

Поля `timeout` нет, поля `abort` нет, и дедлайна по умолчанию на уровне клиента нет. Для SSE и WebSocket `signal` покрывает всё соединение, в том числе после открытия. Дедлайна только на старт нет. Приложение, которому он нужен, создаёт свой `AbortController`, прерывает его через `new DOMException("...", "TimeoutError")` из таймера и сбрасывает таймер после того, как `await` вернулся. См. [SSE](/ru-RU/docs/sse#close-and-dispose).

`HttpExecuteOptions` — срез HTTP: `signal` плюс колбэки прогресса. `EventStreamExecuteOptions` — это `{ signal? }`. `WebSocketExecuteOptions` — срез WebSocket плюс `signal`.

## Результаты по транспорту

- HTTP → `[error, data, response]`
- SSE → `[error, stream, open]`. `open` — снимок первого успешного handshake возвращённого соединения для нативных handle Defjs или обёрток, передающих тот же живой объект `open`; пользовательские handle или обёртки, переопределяющие `open`, используют свой текущий публичный `open` даже после переподключения, а `stream.open` остаётся живым (см. [SSE](/ru-RU/docs/sse)).
- WebSocket → `[error, session, connection]`

Вернись до использования успешного значения, если задан `error`.

Очистка на тебе: abort HTTP, close SSE + `await stream.closed`, close WebSocket + `await session.closed`.

## Scope на сервере и в браузере

На сервере создавай клиент внутри границы запроса, когда опции или замыкания interceptor’ов захватывают auth, cookies, пользователей или tenants. Идентичность клиента сама по себе — не security boundary.
