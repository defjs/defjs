# Клиент

Объект `Client` хранит конфигурацию выполнения использующего приложения: базовые URL, заголовки по умолчанию, учётные данные, перехватчики, сериализацию query-параметров и транспортные хэндлы.

Функция `createClient(...options)` возвращает [`DerivableClient`](/ru-RU/api/core/derivableclient-type):

- Передавайте `client` напрямую в операцию (`getOrder(client, { id: 1 })`), если для конкретного вызова не требуются разовые опции.
- Вызывайте `client(requestOptions)`, чтобы получить производное значение `Client` на один вызов (`getOrder(client({ signal }), { id: 1 })`). Создание производного клиента не выполняет сетевого ввода-вывода, а возвращаемое значение является простым объектом (его нельзя вызвать как функцию).

### Правила композиции опций

- Опции применяются **слева направо**.
- Функции установки одиночных значений (`withEndpoint`, `withHeaders`, `withQuerySerializer`, `withCredentials` и `withXSRF` из `@defjs/core/xsrf`) **заменяют** ранее установленные значения.
- Вызов `withInterceptors(...items)` **добавляет** элементы в конец существующего списка перехватчиков и фильтрует их по транспорту (`http`, `sse`, `web-socket`) в момент выполнения операции.

### Справочник параметров `RequestOptions` на один вызов

Интерфейс `RequestOptions` содержит семь плоских полей. Каждый транспорт читает только относящиеся к нему поля и игнорирует остальные:

| Поле                 | Где используется     | Поведение                                                                                     |
| -------------------- | -------------------- | --------------------------------------------------------------------------------------------- |
| `signal`             | HTTP, SSE, WebSocket | Отменяет вызов (`AbortSignal.timeout(ms)` → `NET_TIMEOUT`; ручная отмена → `NET_ABORTED`).    |
| `onUploadProgress`   | HTTP                 | Сообщает о прогрессе потоковой отправки тела запроса.                                         |
| `onDownloadProgress` | HTTP                 | Сообщает о прогрессе скачивания объявленного тела ответа.                                     |
| `beforeConnect`      | WebSocket            | Заменяет хук `beforeConnect` уровня клиента для данной сессии.                                |
| `protocols`          | WebSocket            | Заменяет список субпротоколов уровня клиента для данной сессии.                               |
| `heartbeat`          | WebSocket            | Заменяет конфигурацию heartbeat уровня клиента для данной сессии.                             |
| `retry`              | HTTP, SSE, WebSocket | Заменяет политику повторов уровня клиента для этого вызова. HTTP `budget` остаётся у клиента. |

## 3. Синглтон в браузере и область запроса на сервере

- **Браузерные приложения**: используйте единый экземпляр `DerivableClient` уровня модуля, если базовый URL, перехватчики и учётные данные одинаковы для всего приложения.
- **Серверные приложения и SSR**: создавайте новый клиент **внутри границы каждого входящего запроса**, если заголовки, cookies, токены авторизации или контекст арендатора (tenant) привязаны к конкретному запросу. Никогда не сохраняйте пользовательские учётные данные в общем клиенте на уровне процесса.

## 4. Несколько эндпоинтов и балансировка нагрузки [#multiple-endpoints]

Функция `withEndpoint(...urls)` принимает один или несколько базовых URL-кандидатов. По умолчанию:

- Каждый клиент использует стратегию [`pickFirstBalancer`](/ru-RU/api/core/pickfirstbalancer) и остаётся на первом URL, пока не сдвинется на `NET_UNREACHABLE` или `NET_UNAVAILABLE` (HTTP 502, 503 или 504).
- **Повторы выключены по умолчанию.** Вызов делает одну попытку. `withRetry()` эквивалентен `withRetry({})`: до трёх повторов с backoff, одинаково для HTTP, SSE и WebSocket. После каждого сбоя балансировщик выбирает снова из всех эндпоинтов, поэтому повтор после отказа в соединении при pick-first доходит до следующего эндпоинта, а единственный эндпоинт пробуется снова после задержки. Бюджет повторов Finagle для HTTP принадлежит конфигурации клиента, и его делят производные клиенты этой конфигурации, независимо от идентичности балансировщика.

<include cwd lang="typescript">
  examples/client/multiple-endpoints.ts#example
</include>

`attemptTimeoutMs` ограничивает одну попытку: HTTP считает до конца тела ответа, SSE — до заголовков ответа, WebSocket — до `open`. Для ограничения по времени без повторов напишите `withRetry({ maxRetries: 0, attemptTimeoutMs })`. Опции повторов не проверяются во время выполнения. Порядок решения и переход с `withSSEReconnect` и `withWebSocketReconnect` см. в разделе [Балансировка нагрузки и отказоустойчивость](/ru-RU/docs/load-balancing#retries).

### Фильтрация доступности и P2C [#health-filtering-and-p2c]

Для пула равноправных реплик сервера балансировщики [`roundRobinBalancer`](/ru-RU/api/core/roundrobinbalancer) и [`p2cBalancer`](/ru-RU/api/core/p2cbalancer) (PeakEwma RTT × нагрузка в процессе) могут принимать опцию `outlierDetection`; она выключена, пока вы не передадите объект (`{}` — значения по умолчанию). Она считает сбои и на время исключает эндпоинт, а также пропускает эндпоинт, который отвергает ваша собственная функция `isHealthy`; Defjs не решает, что значит «здоровый». По умолчанию любой исход с кодом считается сбоем (включая `NET_TIMEOUT` и `NET_BODY_INCOMPLETE`), и это правило можно заменить через `isFailure`; сырой `status` ответа нужен только пользовательским балансировщикам.

Подробные сведения о бюджетах повторов, исключении по сбоям и вашей собственной функции здоровья, оценке нагрузки P2C и написании собственных балансировщиков см. в руководстве [Балансировка нагрузки и отказоустойчивость](/ru-RU/docs/load-balancing).

## 6. Справочник хелперов опций клиента

| Хелпер                                                                             | Назначение                                                                                                                                                                                                                                                                                                         |
| ---------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| `withEndpoint(...urls)`                                                            | Задаёт один или несколько базовых URL-кандидатов (заменяет предыдущий список).                                                                                                                                                                                                                                     |
| `withHeaders(HeadersInit)`                                                         | Задаёт статические заголовки по умолчанию для HTTP и SSE (заголовки из builder имеют приоритет).                                                                                                                                                                                                                   |
| `withInterceptors(...items)`                                                       | Добавляет перехватчики HTTP, SSE и WebSocket в порядке луковичной модели.                                                                                                                                                                                                                                          |
| `withQuerySerializer(fn)`                                                          | Сериализует объекты query с уже применёнными алиасами в строку запроса.                                                                                                                                                                                                                                            |
| `withCredentials(boolean)`                                                         | Устанавливает для Fetch `credentials: "include"` для HTTP и SSE при значении `true`.                                                                                                                                                                                                                               |
| `withXSRF(options?)`                                                               | Из `@defjs/core/xsrf`. В браузере копирует XSRF cookie в заголовок для мутирующих HTTP-запросов одного origin. `withXSRF()` бросает ошибку, если нет `location` или `document`, в том числе в Worker. Изоморфный код добавляет этот параметр только в браузере. Токен из другого источника задаётся интерцептором. |
| `withBalancer(balancer)`                                                           | Заменяет стратегию выбора эндпоинта (`pickFirstBalancer`, `roundRobinBalancer`, `p2cBalancer`).                                                                                                                                                                                                                    |
| `withRetry(options?)`                                                              | Задаёт opt-in повторы для HTTP, SSE и WebSocket: число повторов, backoff, методы, таймаут попытки, функцию `shouldRetry` и бюджет HTTP, принадлежащий клиенту.                                                                                                                                                     |
| `withSSEOnInvalidEvent`                                                            | Наблюдает за событиями SSE, у которых нет struct или которые не проходят валидацию.                                                                                                                                                                                                                                |
| `withWebSocketHeartbeat` / `withWebSocketProtocols` / `withWebSocketBeforeConnect` | Задаёт параметры сессии WebSocket по умолчанию.                                                                                                                                                                                                                                                                    |
| `withHTTPHandle` / `withSSEHandle` / `withWebSocketHandle`                         | Внедряет пользовательские или моковые реализации транспорта.                                                                                                                                                                                                                                                       |
