## Владей сессией [#ownership]

Сессия WebSocket принадлежит вызывающему, который её открыл. Закрывай её, когда работа закончена, и используй `await using`, когда ею владеет окружающая область, чтобы сессия освобождалась на каждом пути выхода.

```ts
const [error, session] = await quotes(client);
if (error) return;
await using ownedSession = session;
ownedSession.send({ type: "subscribe", symbol: "ACME" });
```

## Читай, пока сессия не закроется [#read-to-end]

Читай `session.receive`, пока сессия не закроется или вызывающий не остановится. Не считай первое сообщение последним. Регистрируй `onRuntimeError`, когда приложение должно увидеть транспортный сбой, случившийся после открытия сессии.

## Ограничь обе очереди [#bounds]

Задавай `maxIncomingQueueSize` для сообщений, ожидающих потребителя, и `maxOutgoingQueueSize` для сообщений, поставленных в очередь во время переподключения. Граница превращает медленного потребителя или долгое переподключение в fault, а не в неограниченный рост памяти. Тестируй путь переполнения с теми же лимитами, что и продакшен.

## Делай переподключение и heartbeat осознанными [#reconnect]

Переподключение и heartbeat — опции клиента. Переподключение создаёт новую попытку соединения; исходящие сообщения в очереди следуют политике очереди. Heartbeat, не получивший подтверждения, — это провал, который приложение должно классифицировать, а не повод слать вечно.

## Закрывай, а не утекай [#close]

`close()` запускает teardown; `closed` сообщает терминальное состояние. Отправка после того, как сессия перестала быть доступной для записи, бросает исключение; проверяй состояние или обрабатывай бросок. Дожидайся `closed`, когда следующий шаг зависит от освобождения транспорта.
