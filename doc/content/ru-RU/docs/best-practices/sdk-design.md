## Одна операция — одно определение [#one-operation]

Дай каждой операции собственное определение и модуль. У операции один метод, одна форма пути, один вход и один контракт выхода. Разделение по операциям сохраняет контракт читаемым и позволяет приложению импортировать только те операции, которые оно вызывает.

Предпочитай:

```ts
export const getOrder = defineRequest({
  method: "GET",
  path: "/orders/:id",
  operation: "orders.read",
  input: struct.object({ id: struct.number() }),
  builder: (input) => ({ path: input }),
  output: struct.object({ id: struct.number(), status: struct.string() }),
});
```

Избегай модуля, который создаёт клиент или хранит эндпоинт рядом с определениями.

## Сочетай input с явным builder [#builder]

Объявляй каждое значение вызывающего в `input` и раскладывай его в `builder`. Не полагайся на совпадение имени поля с параметром пути. `builder` синхронный и чистый: он может преобразовывать значения, но не должен читать учётные данные, обращаться к сети или менять общее состояние.

```ts
const updateOrder = defineRequest({
  method: "PATCH",
  path: "/orders/:id",
  input: struct.object({
    id: struct.number(),
    requestId: struct.string(),
    profile: struct.object({ name: struct.string() }),
  }),
  builder: (input) => ({
    path: { id: input.id },
    headers: { "x-request-id": input.requestId },
    body: input.profile,
  }),
});
```

## Struct описывает форму данных на проводе [#structs]

Используй Struct для данных, которые пересекают провод. Используй алиасы, когда имя на проводе отличается от имени в TypeScript. Считай бизнес-правила, проверку связей между полями и нормализацию политикой приложения, а не поведением Struct.

```ts
const profile = struct.object({
  customerName: struct.string().alias("customer_name"),
});
```

## Используй стабильное имя операции [#operation-name]

Задавай в `operation` идентичность с низкой кардинальностью, например `orders.read`. Она помечает телеметрию и диагностику, не неся в себе URL, пользовательский ввод или значение отдельного запроса.

## Держи SDK свободным от состояния выполнения [#no-client]

Пакет SDK экспортирует определения, Struct и типы. Он не вызывает `createClient`, не держит синглтон клиента и не читает переменные окружения. Эндпоинт и учётные данные выбирает приложение.

## Версионируй контракт осознанно [#versioning]

Считай ломающими удаление поля, смену метода или пути и сужение входа. Добавления обычно совместимы. Держи peer range пакета честным, публикуй с тем же текстом определения, против которого компилируется приложение, и записывай тег релиза опубликованного пакета.
