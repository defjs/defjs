## Подставляй транспорт [#inject]

Используй `withHTTPHandle`, `withSSEHandle` или `withWebSocketHandle`, чтобы заменить платформенный транспорт. Операция по-прежнему собирает запрос, запускает интерцепторы и декодирует ответ, поэтому тест проверяет настоящую границу контракта.

```ts
const client = createClient(
  withEndpoint("https://fixture.invalid"),
  withHTTPHandle(async () => Response.json({ id: 7, status: "paid" })),
);
const [error, order] = await getOrder(client, { id: 7 });
expect(error).toBeNull();
expect(order?.status).toBe("paid");
```

## Проверяй кортеж, а не внутренности [#tuple]

Проверяй код fault и декодированное значение. Тест, который проверяет вызов приватного хелпера или деталь реализации транспорта, ломается, когда реализация меняется без изменения контракта. Для fault проверяй `code`, относящиеся к нему поля и идентичность `cause`, когда причина — часть контракта.

## Держи контрактные фикстуры настоящими [#fixtures]

Запускай один интеграционный тест против настоящего сервера для каждого транспорта, когда изменение затрагивает сборку запроса, декодирование или разборку стрима. Используй фикстурные серверы, уже имеющиеся в репозитории, а не второй mock-протокол. Поведение, существующее только в браузере, принадлежит браузерному проекту; поведение только сервера — серверному.

## Управляй временем явно [#time]

Используй fake timers для таймаутов, backoff, задержки переподключения и heartbeat. Продвигай время после того, как произошло тестируемое событие, и проверяй путь кода, который должен был выполниться. Никогда не проверяй прошедшее реальное время. Для настоящего сокета жди конкретное событие, например `open`, `closed` или первый кадр.

## Тестируй SDK как потребитель [#consumer]

Тест SDK должен импортировать определения, которые импортирует приложение, создать клиент с тестовым транспортом и вызвать операцию. Он не должен воссоздавать запрос вручную; так проверяется тест, а не SDK.
