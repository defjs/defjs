## Владей handle [#ownership]

Стрим событий или сессия WebSocket принадлежит вызывающему, который их открыл. Закрывай их, когда работа закончена, и используй `await using`, когда владеет окружающая область, чтобы handle освобождался на любом пути выхода.

```ts
const [error, stream] = await deployEvents(client);
if (error) return;
await using ownedStream = stream;
for await (const event of ownedStream) {
  if (event.event === "line") console.log(event.data.text);
}
```

## Читай до завершения или EOF [#read-to-end]

Одно событие — не полный ответ. Для SSE читай, пока стрим не закончится, вызывающий не прервёт его или не вступит политика переподключения. Для WebSocket читай очередь приёма, пока сессия не закроется или вызывающий не остановится.

## Ограничивай буферы и очереди [#bounds]

Задавай `maxIncomingQueueSize` для сессий WebSocket и `maxBufferSize` / `maxQueueSize` для SSE. Предел превращает медленного потребителя в fault вместо неограниченного роста памяти. Выбирай предел по размеру сообщения и скорости потребителя, затем протестируй путь переполнения.

## Решай переподключение и воспроизведение явно [#reconnect]

Переподключение SSE выключено, пока приложение его не включит. POST или другой неидемпотентный метод не воспроизводится, если политика это не разрешает. Неудачная попытка стриминга могла уже начать работу на сервере; прочитай правила переподключения в [потоках событий SSE](/ru-RU/docs/sse) и правила воспроизведения в [HTTP-запросах](/ru-RU/docs/http), прежде чем включать политику.

## Закрывай и не допускай утечек [#close]

`close()` запускает разборку; `closed` сообщает терминальное состояние. Жди `closed`, когда следующий шаг зависит от освобождения транспорта. Abort завершает локальную работу; это не доказательство, что сервис остановил уже принятую работу.
