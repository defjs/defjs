## Создай клиент один раз на границе [#client-boundary]

Создавай клиент там, где приложение читает свою конфигурацию: в точке входа сервера, в модуле, который владеет развёртыванием, или в настройке теста. Передавай этот клиент коду, который вызывает операции.

```ts
const client = createClient(
  withEndpoint("https://api.example.com"),
  withInterceptors(auth),
);
```

Избегай клиента на уровне модуля внутри SDK, в теле компонента или в обработчике запроса. Клиент, созданный на каждый рендер или запрос, теряет общую конфигурацию и заставляет тесты зависеть от окружающего состояния.

## Помещай сквозную политику в интерцепторы [#interceptors]

Аутентификация, трассировка, значения заголовков по умолчанию и проверенная политика повторов принадлежат интерцептору. `builder` раскладывает текущий input; он ничего не знает об учётных данных или телеметрии приложения.

```ts
const auth = createHttpInterceptor(async (request, next) => {
  const response = await next(request);
  return response;
});
```

## Используй опции клиента для одного вызова [#per-call]

`client(options)` возвращает значение клиента для одного вызова. Это значение не вызываемое. Используй его для `signal`, колбэков прогресса или хука WebSocket, который действует только на этот вызов; для всего остального держи базовый клиент.

```ts
const [error, order] = await getOrder(
  client({ signal: AbortSignal.timeout(5_000) }),
  { id: 1 },
);
```

## Позволь плагинам фреймворка передавать клиент [#plugins]

`@defjs/react` и `@defjs/vue` передают клиент приложения через дерево фреймворка. Они его не создают, не кешируют, не повторяют и не освобождают. Передавай клиент, которым приложение уже владеет, и внедряй то же значение там, где оно нужно.

```tsx
<ClientProvider client={client}>
  <Orders />
</ClientProvider>
```

## Держи эндпоинт вне SDK [#endpoint]

Одно и то же определение может работать против продакшена, стейджинга, локальной фикстуры или тестового транспорта. Выбирай эндпоинт в приложении; не зашивай хост развёртывания в пакет SDK.
