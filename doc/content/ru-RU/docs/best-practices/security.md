## Держи секреты вне SDK и браузера [#secrets]

Определение SDK не содержит эндпоинта, токена или учётных данных. Приложение размещает учётные данные на клиенте, который работает там, где их разрешено использовать: в серверном процессе, воркере или доверенном тесте. Не помещай секрет провайдера в браузерный бандл, публичную переменную сборки или клиент, отправляемый в браузер.

```ts
const client = createClient(
  withEndpoint("https://api.example.com"),
  withInterceptors(serverAuth),
);
```

## Используй интерцептор для аутентификации [#auth]

Прикрепляй токен в интерцепторе, который выполняется на границе приложения. `builder` должен оставаться чистой функцией размещения; он не может читать хранилище токенов или менять заголовок, используемый другим вызовом.

## Настраивай XSRF на клиенте [#xsrf]

Когда сервис использует токен cookie-to-header, настрой `withXsrf` на клиенте приложения. `withCredentials` только выбирает режим cookie у Fetch; он не создаёт и не проверяет токен. Сервер по-прежнему должен выдавать и проверять токен.

## Проверяй то, чем управляет приложение [#urls]

Defjs отвергает недопустимые пути запроса, выход из каталога, обратные слеши, `?`, `#` и управляющие символы до запуска транспорта. Он не знает, каким хостам доверяет твоё приложение. Держи список эндпоинтов явным, проверяй значения от пользователя до того, как они попадут в `builder`, и не собирай базовый URL из недоверенного ввода.

## Редактируй до логирования или трассировки [#redaction]

URL, query-строки, заголовки и тела могут содержать секреты или персональные данные. Плагин OpenTelemetry по умолчанию не захватывает тела и полные заголовки; оставь так. Редактируй в `startSpanHook` или в экспортёре приложения и не копируй сырые значения запроса в собственную телеметрию.

## Считай abort локальным [#abort]

Отмена останавливает локальную работу. Она не доказывает, что сервис остановил уже принятую работу, и не откатывает серверный эффект. Для неидемпотентной операции сочетай отмену с собственным контрактом отмены сервиса.
