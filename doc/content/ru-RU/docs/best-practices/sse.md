## Владей handle [#ownership]

Поток событий принадлежит вызывающему, который его открыл. Закрывай его, когда работа закончена, и используй `await using`, когда им владеет окружающая область, чтобы handle освобождался на каждом пути выхода.

```ts
const [error, stream] = await deployEvents(client);
if (error) return;
await using ownedStream = stream;
for await (const event of ownedStream) {
  if (event.event === "line") console.log(event.data.text);
}
```

## Читай до конца или до EOF [#read-to-end]

Одно событие — не законченный ответ. Продолжай читать, пока поток не закончится, вызывающий не прервёт его или не вступит в силу политика переподключения. Считай провал чтения транспортным сбоем, а не чистым завершением.

## Ограничь буфер и очередь [#bounds]

Задавай `maxBufferSize` и `maxQueueSize` исходя из размера сообщения и скорости потребителя. Граница превращает медленного потребителя в fault, а не в неограниченный рост памяти. Тестируй путь переполнения с теми же лимитами, что и продакшен.

## Выбирай политику переподключения явно [#reconnect]

Переподключение SSE выключено, пока приложение его не включит. Неидемпотентный метод вроде POST не повторяется, если политика это не разрешает. Неудачная попытка могла уже запустить работу на сервере; прочитай правила переподключения в [потоках событий SSE](/ru-RU/docs/sse), прежде чем включать политику.

## Закрывай, а не утекай [#close]

`close()` запускает teardown; `closed` сообщает терминальное состояние. Дожидайся `closed`, когда следующий шаг зависит от освобождения транспорта. Abort завершает локальную работу; это не доказательство, что сервис остановил уже принятую работу.
