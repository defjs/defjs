# Команды

Автор SDK экспортирует эндпоинт, возвращаемый `defineRequest`, `defineEventStream` или `defineWebSocket`. Он описывает переиспользуемую операцию API, её контракты Struct и размещение входных данных через `builder`. Приложение вызывает эндпоинт со своими данными, получает непрозрачную команду и передаёт её своему клиенту.

Определение → экспортируемый эндпоинт → команда для одного вызова → `client.execute(...)`. Это разделение одинаково для HTTP, SSE и WebSocket. В примерах определение и выполнение показаны вместе для удобства чтения; при [публикации SDK](/ru-RU/recipes/publish-http-sdk) модуль эндпоинтов отделён от приложения.

Фабрики клиентов и вспомогательные методы — необязательные дополнения. Они могут предоставлять настройки сервиса по умолчанию или доменное поведение, принимать конфигурацию вызывающей стороны и сохранять прямые экспорты эндпоинтов. Документируй преобразование ошибок и правила жизненного цикла, которые они добавляют. Для переиспользуемого SDK фабрика не обязательна.

## Выбери определение

| Определение              | Контракт                                                                        | Успешное значение                      |
| ------------------------ | ------------------------------------------------------------------------------- | -------------------------------------- |
| `defineRequest(...)`     | Method, относительный path, опциональный input, опциональные `output` / `error` | Декодированные данные + response       |
| `defineEventStream(...)` | Path, лимиты buffer/queue, карта имя события → Struct                           | `EventStreamHandle` + снимок open      |
| `defineWebSocket(...)`   | Path, один incoming struct, опциональный outgoing struct, лимит очереди         | `WebSocketSession` + снимок connection |

Нет `input` → эндпоинт не принимает аргумент, а `builder` может быть `() => request`. С `input` → передай значение struct. Опциональное поле можно опустить; обязательное — нельзя.

Держи команды непрозрачными. Не копайся в tags или symbols.

## Куда ложатся значения

Struct решает, как значение кодируется. `builder` решает, куда оно ложится. `builder` — синхронная чистая функция от **распарсенного** input. Она выполняется при вызове execute. Throw становится `REQ_BUILD_FAILED` в кортеже — сам вызов эндпоинта не бросает.

При объявленном `input` всегда нужен явный `builder`. `input` только описывает параметры; куда пойдёт каждое значение, решает только builder. Опустить `builder` можно только в определениях без `input`.

Проводи типизированное значение насквозь. Алиас, `Date` → ISO и `bigint` → string применяются везде, где используется этот struct: раскладка запроса, декодирование ответа, события SSE и кадры WebSocket.

Тело — JSON `{"display_name":"…","email":"…"}`. Ключ, написанный руками, — запасной выход: `body: { name: input.user.displayName }` шлёт `name`, потому что родительский объект анонимный и алиас не применяется.

## Когда формы расходятся

`builder` — для placeholder’ов path, литералов и веток. Он получает настоящее значение, так что работают `if`, `??`, шаблоны и `switch`.

`query: input.filter` шлёт `page_size`. `headers: { 'x-api-version': '2' }` — литерал. Auth и tracing всё ещё живут в interceptors: они видят нативный request после того, как отработал builder.

## Формы `output` и `error`

`output` — один Struct для тела 2xx; `error` — один Struct для всего остального. `ok` — единственная развилка, и декодирует всегда одна сторона. Пропустить сторону значит, что это тело не прочитают: fault несёт status, а `data` остаётся `undefined`.
