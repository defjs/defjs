# Сравнение и гибридная архитектура

Defjs находится на стыке двух экосистем: **HTTP-клиентов для браузера и Node** (`fetch`, `ky`, `ofetch`, `axios`, `openapi-fetch`) и **RPC-фреймворков с подходом contract-first** (`oRPC`, tRPC). Это руководство помогает понять, где каждый инструмент уместен лучше всего, когда Defjs становится лишней прослойкой и как команды сочетают их в продакшене.

## Сравнение в экосистеме

| Возможность                            | Чистый `fetch`                    | `ky` / `ofetch`                           | `openapi-fetch`                                | `oRPC`                                    | Defjs (`@defjs/core`)                                                            |
| -------------------------------------- | --------------------------------- | ----------------------------------------- | ---------------------------------------------- | ----------------------------------------- | -------------------------------------------------------------------------------- |
| Основной фокус                         | Базовый примитив платформы        | Обёртка HTTP на уровне приложения         | Типизированный Fetch-клиент по OpenAPI         | Полностековый TS RPC-фреймворк            | Определения SDK + отказоустойчивый клиент                                        |
| Разделение определений и клиента       | Вручную                           | Экземпляр привязан к базовому URL         | Общие типы путей; вызовами владеет клиент      | Роутер и клиент связаны RPC-контрактом    | Первоклассное (`define*` данные vs `Client`)                                     |
| Единые транспорты                      | Только HTTP                       | Только HTTP                               | Только HTTP                                    | HTTP + SSE/итератор событий (на сервере)  | HTTP, SSE и WebSocket под одним клиентом                                         |
| Сетевые контракты и алиасы в рантайме  | Нет                               | Нет                                       | Опциональный middleware                        | Внешний валидатор (Zod/Valibot/ArkType)   | Нулевые зависимости `struct` с обратимым `.alias()`                              |
| Семантика сбоев                        | Reject при ошибке сети; `!res.ok` | Выбрасывает `HTTPError`                   | `{ data, error }` (бросает или сетевой reject) | Безопасные/выбрасываемые ошибки RPC       | Без исключений: Go-кортеж `[err, value, meta]`                                   |
| Балансировка по нескольким апстримам   | Нет                               | Нет                                       | Нет                                            | Плагины ссылок (нет встроенного P2C EWMA) | Встроенные `p2cBalancer` + `outlierDetection` (`halfOpen`, `maxEjectionPercent`) |
| `429` + `Retry-After` + correlation ID | Вручную                           | `ky` обрабатывает `Retry-After`; один URL | Нет из коробки                                 | Клиентский плагин повторов                | Нативный `429`/RFC `Retry-After`, бюджет повторов и `correlationId`              |
| Структурированная конкурентность       | Обычный `Promise.all`             | Обычный `Promise.all`                     | Обычный `Promise.all`                          | Batch-плагин / `Promise.all`              | `@defjs/core/concurrent` с привязкой к клиенту и отменой                         |
| Кодогенерация по OpenAPI               | Нет                               | Нет                                       | Только типы через `openapi-typescript`         | Экспорт OpenAPI-схемы из роутера oRPC     | `@defjs/cli` генерирует stateless ESM + `struct`                                 |
| Проксирование через границы контекстов | Ручной `postMessage`              | Вручную                                   | Вручную                                        | Адаптеры MessagePort / worker             | `@defjs/core/port` + `/webext` (HTTP, SSE, WS + default-deny origin)             |

### Когда лучше выбрать альтернативу

- **Выбирайте чистый `fetch`, `ofetch` или `ky`**, если приложение вызывает несколько same-origin эндпоинтов без публикации SDK, без отказоустойчивости по нескольким апстримам и без валидации схем в рантайме (~4–10 KB brotli).
- **Выбирайте `openapi-fetch`**, если вы уже поддерживаете типы `openapi-typescript` и хотите только статическую типизацию поверх тонкой обёртки над Fetch без декодирования ответов в рантайме.
- **Выбирайте `oRPC` (или Hono RPC)** для **внутрикомандного RPC между фронтендом и BFF / full-stack RPC**, когда ваша команда владеет и TypeScript-сервером, и браузерным клиентом и хочет сквозной вывод процедур без поддержки отдельных HTTP-контрактов.

## Гибридная схема BFF: oRPC / Hono на входе, Defjs для исходящих вызовов

Самый распространённый высоконагруженный паттерн в продакшене не противопоставляет Defjs и `oRPC` или `Hono`, а объединяет их по разные стороны границы доверия:

```txt
┌──────────────┐   Внутренний RPC (oRPC / Hono)    ┌─────────────────────────────────┐
│ Браузер /    │ ────────────────────────────────▶ │ BFF (сервер Hono / oRPC)        │
│ Мобильное    │ ◀──────────────────────────────── │                                 │
│ приложение   │                                   │  @defjs/core Client:            │
└──────────────┘                                   │  • undici.Pool хэндл            │
                                                   │  • p2cBalancer({                │
                                                   │      outlierDetection: {        │
                                                   │        halfOpen: true           │
                                                   │      }                          │
                                                   │    })                           │
                                                   │  • withRetry (429 / 503)        │
                                                   │  • bulkhead + идемпотентность   │
                                                   │  • @defjs/opentelemetry-server  │
                                                   └────────────────┬────────────────┘
                                                                    │
                                        Исходящие REST / SSE / WS   │
                               ┌────────────────────────────────────┴────────┐
                               ▼                                             ▼
                    Сторонние SaaS API                           Внутренние микросервисы
                  (генерация @defjs/cli)                       (отказоустойчивость A, B, C)
```

При таком разделении:

1. **Браузер ↔ BFF** использует `oRPC` или `Hono` для быстрой разработки внутреннего RPC.
2. **BFF ↔ внешние и нижестоящие API** использует `@defjs/core` (часто с операциями, сгенерированными `@defjs/cli` из OpenAPI-спецификаций поставщиков и пулом соединений на базе [`undici.Pool`](/ru-RU/recipes/undici-pool)), чтобы один медленный узел (`B`) или узел, отдающий `429` / `503` (`C`), изолировался с помощью `p2cBalancer` + `outlierDetection` до того, как исчерпает ресурсы воркеров BFF.
