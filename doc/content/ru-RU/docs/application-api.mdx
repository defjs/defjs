# API-слой приложения [#application-api-layer]

В большинстве проектов Defjs используется непосредственно внутри репозитория приложения (`src/api/`) взамен разрозненных обёрток вокруг `fetch` или `axios`. Даже если вы не планируете публиковать внешний npm-пакет, разделение на `src/api/models/`, `src/api/services/` и `src/api/client.ts` делает слой запросов строго типизированным, тестируемым в памяти и безопасным как в браузере, так и в SSR-окружении.

---

## 1. Рекомендуемая структура каталога `src/api/`

Разделите слой запросов проекта в `src/api/` на три сфокусированные части:

```text
src/
├── api/
│   ├── models/           # 1. Общие схемы struct + типы Infer<typeof ...>
│   │   └── order.ts      #    ApiError, OrderStatus, Order, OrderPage
│   ├── services/         # 2. Чистые определения операций, сгруппированные по доменам
│   │   └── orders.ts     #    getOrder, listOrders, createOrder
│   └── client.ts         # 3. Клиент приложения (эндпоинт, перехватчик авторизации, retry)
└── checkout.ts           # 4. Бизнес-логика / UI-компоненты, вызывающие операции
```

## 3. Ключевые паттерны для прикладных проектов

### Браузерный синглтон и SSR-клиент на каждый запрос

- **Браузер / SPA (`apiClient`)**: Экспортируйте один экземпляр `createClient(...)` на уровне модуля для каждого источника бэкенда. Совместное использование этого экземпляра сохраняет состояние здоровья балансировщика нагрузки и клиентский бюджет повторных попыток HTTP между взаимодействиями со страницей. В приложениях на React или Vue передавайте `apiClient` на корневом уровне через [`@defjs/react`](/ru-RU/docs/integrations/react) (`ClientProvider` / `useClient`) или [`@defjs/vue`](/ru-RU/docs/integrations/vue) (`createClientPlugin` / `injectClient`).
- **SSR / BFF (`createServerApiClient(accessToken)`)**: Когда учётные данные, cookie или заголовки тенанта различаются для каждого входящего HTTP-запроса, вызывайте фабричную функцию внутри серверного обработчика запросов для создания изолированного `Client`. Поскольку `getOrder`, `listOrders` и `createOrder` являются чистыми функциями, одни и те же определения из `services/orders.ts` работают как с `apiClient`, так и с `createServerApiClient(token)`.

### Тайм-ауты и отмена для отдельного вызова

Никогда не создавайте новый `Client` через `createClient(...)` только ради передачи тайм-аута или `AbortSignal`. Вместо этого создавайте производный одноразовый клиент прямо в месте вызова из общего клиента:

```ts
const [error, created] = await createOrder(
  apiClient({ signal: AbortSignal.timeout(5_000) }),
  {
    customerName: "Ada Lovelace",
    totalCents: 4200,
    idempotencyKey: "idem-2026-101",
  },
);
```

### Единый конверт ошибок (`ApiError`)

Объявите стандартную структуру ошибки вашего бэкенда один раз (`export const ApiError = struct.object(...)`) в `src/api/models/` и передавайте `error: ApiError` в каждый вызов `defineRequest` в `src/api/services/`. Когда запрос возвращает статус, отличный от `2xx`, сужение типа `if (error.code === "HTTP_STATUS")` даёт строго типизированный доступ к `error.data.code`, `error.data.message` и `error.data.requestId`.
