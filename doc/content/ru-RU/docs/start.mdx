# Начало работы: первая операция SDK [#getting-started-one-http-request]

В этом руководстве вы создадите модуль SDK с операцией `GET /orders/:id` и вызовете его из двух разных модулей приложения: один использует локальный мок без сети, а второй обращается к реальному API.

## 1. Установите `@defjs/core`

`@defjs/core` — это ESM-пакет без зависимостей, работающий в браузерах, Bun и Node.js (версии 22.18+ и 24+ умеют запускать `.ts` напрямую). Убедитесь, что в вашем `package.json` указано `"type": "module"`.

```sh
bun add @defjs/core
```

## 2. Объявите SDK и вызовите его из приложения

Храните определение операции в отдельном модуле SDK (`src/define-request.ts`), а клиент создавайте на стороне приложения (`src/execute-locally.ts` или `src/real-api.ts`):

### Как эти три файла работают вместе

1. **`src/define-request.ts` (определение SDK)**:
   - Объявляет входные данные `input`, успешный ответ `output` (для кодов `2xx`) и ошибку `error` (для ответов, отличных от `2xx`) с помощью `struct`.
   - Предоставляет синхронную чистую функцию `builder`, которая преобразует `input` в `{ path }`. Если объявлен `input`, явный `builder` обязателен.
   - Экспортирует операцию `getOrder`, не создавая и не захватывая клиент.
2. **`src/execute-locally.ts` (локальное выполнение без сети)**:
   - Настраивает клиент с помощью `withHTTPHandle(...)`, чтобы запустить полный конвейер Defjs (валидацию входа, построение URL, маршрутизацию по статусам и разбор структур ответа) без обращения к сети.
3. **`src/real-api.ts` (выполнение в продакшене)**:
   - Импортирует ту же самую операцию `getOrder` и вызывает её с реальным базовым URL, настроенным через `withEndpoint(...)`.

## 3. Запустите локальный пример

Выполните `src/execute-locally.ts` с помощью Bun:

```sh
bun src/execute-locally.ts
```

```txt
Loaded paid from 200
```

Если изменить входные данные с `{ id: 7 }` на `{ id: 8 }`, мок вернёт статус `404`, и Defjs декодирует объявленную структуру `error` в поле `error.data`:

```txt
Order not found
```

## 4. Разберитесь с error-first кортежем

Каждый HTTP-вызов возвращает кортеж `[error, data, response]`:

- **При успехе (`2xx`)**: `error` равен `null`, `data` содержит валидированное значение `output` (`Order`), а `response` — это `DecodedResponse<Order>`.
- **При объявленном статусе вне `2xx`**: `error.code` равен `'HTTP_STATUS'`, `error.status` содержит код ответа (`404`), а `error.data` — валидированную структуру `error` (`NotFound`).
- **При ошибках входа, декодирования или сети**: `error.code` точно указывает на этап сбоя:
  - `REQ_INPUT_INVALID` / `REQ_BUILD_FAILED` — невалидные входные данные или выброс исключения в `builder`
  - `RES_MEDIA_TYPE_INVALID` — ожидалось тело JSON, но пришёл неподдерживаемый `Content-Type` (отклоняется до чтения тела)
  - `RES_DECODE_FAILED` / `RES_STRUCT_MISMATCH` — невозможно прочитать тело или структура ответа не совпадает со схемой
  - `NET_UNREACHABLE` / `NET_ABORTED` / `NET_TIMEOUT` — сбой транспорта, ручная отмена или срабатывание `AbortSignal.timeout(ms)`

Передавайте дедлайны или сигналы отмены для конкретного вызова, порождая клиент на один запрос: `getOrder(client({ signal: AbortSignal.timeout(5_000) }), { id: 7 })`.
