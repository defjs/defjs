# Начало работы: один HTTP-запрос

Первый элемент SDK — экспортируемый эндпоинт `GET /users/:id`. Контракт находится в одном файле, а приложение выполняет его через свой клиент из второго. Локальный Fetch handler позволяет начать без сети; то же определение затем декодирует `200` и объявленный `404` реального сервиса.

## Рекомендуемая практика

Определение не зависит от клиента. Его вызов только создаёт command. Дай этой command имя и передай его в `client.execute` клиента, которым владеет приложение. Адрес сервиса и учётные данные тоже принадлежат приложению. Сначала прочитай кортеж error-first. Если `error` задан, сообщи `error.code` и вернись из функции до чтения успешного значения.

## Шаг 1 — Установка

## Шаг 2 — Опиши запрос

На стороне SDK создай `src/define-request.ts` и экспортируй `getUser`. Входной Struct описывает данные вызывающей стороны. `builder` размещает их в запросе. Здесь весь input — объект пути: скалярные поля без алиасов заполняют `:id`. Базовый URL и аутентификацию позже настроит приложение.

<include cwd meta="define-request.ts">
  examples/start/define-request.ts#example
</include>

`output` — тело 2xx. `error` — любой другой status. По одному struct. Когда эти тела различаются, используй `struct.or(...)` или размеченное объединение.

`defineRequest(...)` возвращает эндпоинт. Вызов `getUser(...)` собирает непрозрачную команду, которую отдашь в `client.execute(...)`. `builder` выше — функция, которая раскладывает input; это не эндпоинт.

## Шаг 3 — Выполни локально

Рядом создай `src/execute-locally.ts`. Приложение импортирует `getUser`, создаёт собственный клиент и передаёт ему локальный Fetch handler. Defjs по-прежнему проверяет входные данные, собирает `Request`, выбирает контракт по статусу и разбирает тело.

При успехе: `error` — `null`, `user` — output Struct для `200`, `response` — `DecodedResponse`. При объявленном `404`: `error.code` — `'HTTP_STATUS'`, `error.status` — `404`, а `error.data` типизирован как `NotFound`. Второй элемент кортежа при провале — `undefined`.

## Когда результат другой

- Плохой input → `REQ_INPUT_INVALID`; конфликтующие опции отмены → `REQ_OPTIONS_INVALID`; упавший `builder` → `REQ_BUILD_FAILED`
- Non-2xx статус → `HTTP_STATUS`, с типизированным `error.data`, если `error` был объявлен и его тело декодируется
- Объявленное JSON-тело с другим media type → `RES_MEDIA_TYPE_INVALID`, сообщается до чтения тела
- Объявленное тело (`output` для 2xx, иначе `error`), которое не декодируется → `RES_DECODE_FAILED` или `RES_STRUCT_MISMATCH`, каким бы ни был статус
- Сбой Fetch / отмена / timeout → `NET_UNREACHABLE` / `NET_ABORTED` / `NET_TIMEOUT`

`timeout` — положительное safe integer в `1..2_147_483_647`. Валидные формы отмены: `{ signal }`, `{ timeout }`, `{ abort }` или `{ signal, timeout }` / `{ signal, abort }`. `{ abort, timeout }` вместе невалидно. Отмена говорит, что увидел вызывающий, — не то, закоммитилась ли серверная запись.
