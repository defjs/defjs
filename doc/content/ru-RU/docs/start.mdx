# Начало работы: первая операция SDK [#getting-started-one-http-request]

Напиши два файла: модуль SDK, который экспортирует `GET /orders/:id`, и приложение, которое его импортирует и владеет клиентом. Локальный Fetch handle держит первый запуск без сети. То же определение API затем заработает с клиентом, направленным на твой сервис.

## Рекомендуемая практика

Определение не зависит от клиента. Вызывай операцию клиентом приложения, как в `getOrder(client, { id: 7 })`. Третьего аргумента с опциями нет. Вызов операции её начинает; `await` только ждёт. Адрес сервиса и учётные данные тоже принадлежат приложению. Сначала прочитай кортеж error-first. Если `error` задан, сообщи `error.code` и вернись из функции до чтения успешного значения.

## Шаг 1 — Установка

`@defjs/core` — ESM и работает на Node.js или Bun. Node.js 22.18+ (или 24+) запускает `.ts` напрямую через type stripping; более ранним релизам 22.x нужен `--experimental-strip-types`. Оставь в package.json `"type": "module"`. В браузере по-прежнему нужны бандлер и Fetch.

```sh
bun add @defjs/core
```

## Шаг 2 — Опиши запрос

Создай `src/define-request.ts`. Это модуль автора SDK: он экспортирует `getOrder` и не создаёт клиент. Входной struct — значение вызывающего. `builder` размещает это значение в запросе. Здесь весь input — объект пути, поэтому скалярные поля без алиасов заполняют `:id`.

<include cwd meta="define-request.ts">

</include>

`output` — тело 2xx. `error` — любой другой status. По одному struct. Когда эти тела различаются, используй `struct.or(...)` или размеченное объединение.

`defineRequest(...)` возвращает операцию. Вызов `getOrder(client, input)` начинает запрос. `builder` выше — функция, которая размещает input; это не операция. Где объявлен `input`, `builder` обязателен, синхронен и чист.

## Шаг 3 — Вызови локально

Рядом создай `src/execute-locally.ts`. Это приложение-потребитель: оно импортирует `getOrder`, создаёт собственный клиент и передаёт локальный Fetch handle. Defjs по-прежнему проверяет входные данные, собирает `Request`, выбирает контракт по статусу и разбирает тело.

<include cwd meta="execute-locally.ts">
  examples/start/execute-locally.ts#example
</include>

Запусти:

```sh
bun src/execute-locally.ts
```

```txt
Loaded paid from 200
```

Попробуй отсутствующий заказ — смени path id на `8` и запусти снова:

```txt
Order not found
```

При успехе: `error` — `null`, `order` — output Struct для `200`, `response` — `DecodedResponse<Order>`. При объявленном `404`: `error.code` — `'HTTP_STATUS'`, `error.status` — `404`, а `error.data` типизирован как `NotFound`. Второй элемент кортежа при провале — `undefined`.

## Шаг 4 — Укажи на реальный API

В `src/real-api.ts` импортируй тот же `getOrder` и создай клиент с базовым URL сервиса. Запускай эту версию только после того, как заменишь адрес из примера сервисом, который реализует `GET /v1/orders/:id` с этими телами.

Определение API остаётся в модуле SDK. Адреса сервиса, учётные данные, перехватчики и время жизни выполнения остаются у приложения. Оба клиента используют один контракт эндпоинта Defjs.

## Опубликуй определение

Перенеси определение в пакет SDK, когда оно нужно нескольким приложениям. Экспортируй `getOrder`, включи его декларации TypeScript и объяви совместимую версию Core. Потребители тогда импортируют из пакета, а не из `./define-request.ts`; настройка их клиента остаётся их собственной. Полную сборку пакета смотри в [Создании и публикации SDK](/ru-RU/recipes/publish-http-sdk).

## Когда результат другой

- Плохой input → `REQ_INPUT_INVALID`; упавший `builder` → `REQ_BUILD_FAILED`
- Non-2xx статус → `HTTP_STATUS`, с типизированным `error.data`, если `error` был объявлен и его тело декодируется
- Объявленное JSON-тело с другим media type → `RES_MEDIA_TYPE_INVALID`, сообщается до чтения тела
- Объявленное тело (`output` для 2xx, иначе `error`), которое не декодируется → `RES_DECODE_FAILED` или `RES_STRUCT_MISMATCH`, каким бы ни был статус
- Сбой Fetch / отмена / дедлайн → `NET_UNREACHABLE` / `NET_ABORTED` / `NET_TIMEOUT`

Дедлайн — это `client({ signal: AbortSignal.timeout(ms) })`, и он классифицируется как `NET_TIMEOUT`. Ручной abort — `NET_ABORTED`. Дедлайна по умолчанию на уровне клиента нет. Выведи клиент, когда одному вызову нужен свой `signal`; см. [Клиент](/ru-RU/docs/client). Отмена говорит, что увидел вызывающий, — не то, закоммитилась ли серверная запись.
