# Проектирование публичного SDK [#public-sdk-design]

Когда ваша компания или платформенная команда публикует официальный TypeScript SDK для внешних разработчиков (например, SDK объектного хранилища, платёжного шлюза или SaaS-платформы), пакет SDK должен **описывать сетевой контракт, не навязывая среду выполнения**.

На примере **совместимого с Amazon S3 SDK (`@company/s3-sdk`)** это руководство показывает, как спроектировать многомодульный публичный SDK с моделями в `models/` и чистыми функциями операций в `services/`.

---

## 1. Почему разделение в Defjs выгодно для публичных SDK

Традиционные SDK поставляют тяжеловесный класс клиента (`new S3Client({ region, credentials })`), жёстко связанный с классами команд или статическими классами сервисов. Создание публичного SDK на базе `@defjs/core` решает четыре типичные проблемы ваших внешних пользователей:

1. **Гибкость между окружениями и песочницами**: Поскольку `@company/s3-sdk` не привязывает ни эндпоинт, ни клиент, пользователь может направить одни и те же определения операций на продакшен (`https://s3.us-east-1.amazonaws.com`), стейджинг-песочницу, Cloudflare R2 или локальный контейнер MinIO в CI-тестах.
2. **100% tree-shaking в сборщиках**: Экспорт самостоятельных чистых функций (`listBuckets`, `listObjectsV2`, `getObject`, `putObject`, `deleteObject`) в сочетании с `"sideEffects": false` гарантирует, что браузерный бандл, вызывающий только `getObject` и `putObject`, отбросит все остальные эндпоинты и модели.
3. **Runtime-валидация и статические типы из одного источника**: Внешние потребители получают одновременно типы TypeScript на этапе компиляции (`Infer<typeof ...>`) и проверку ответов и ошибок во время выполнения (`struct`), что защищает их от неожиданных сетевых данных и автоматически преобразует поля в `snake_case` или строки дат ISO.
4. **Полный контроль над авторизацией, повторами и телеметрией**: Пользователи подключают собственные перехватчики ротации учётных данных, политики `withRetry(...)`, мультирегиональные балансировщики нагрузки (`withBalancer(...)`) или серверный OpenTelemetry (`@defjs/opentelemetry-server`) на своём собственном экземпляре `Client`.

## 2. Структура каталогов пакета

Разделите пакет SDK на `src/models/` (структуры данных) и `src/services/` (сгруппированные по ресурсам чистые определения операций) с плоским входным файлом `src/index.ts`:

```text
@company/s3-sdk/
├── src/
│   ├── models/                 # 1. Общие схемы struct + типы Infer<typeof ...>
│   │   ├── common.ts           #    StorageClass, S3Error
│   │   ├── bucket.ts           #    Bucket, ListBucketsOutput
│   │   └── object.ts           #    ObjectSummary, ListObjectsOutput
│   ├── services/               # 2. Чистые функции defineRequest по доменам ресурсов
│   │   ├── buckets.ts          #    BucketInput, listBuckets, headBucket, deleteBucket
│   │   └── objects.ts          #    listObjectsV2, headObject, getObject, putObject, deleteObject
│   └── index.ts                # 3. Реэкспорт (barrel) для корневого импорта и tree-shaking
├── package.json                # sideEffects: false, peerDependencies: { "@defjs/core": "^0.8.0" }
└── tsconfig.json
```

### Проектирование эргономичных контрактов операций

- **Принимайте плоский входной объект и распределяйте его в `builder`**: В `putObject` вызывающий код передаёт единый удобный объект (`{ bucket, key, body, contentType, storageClass }`). Синхронный `builder` распределяет эти поля по `path` (`:bucket/:key`), `headers` (`content-type`, `x-amz-storage-class`) и бинарному `body` (`Blob`). В `listObjectsV2` функция `builder` сопоставляет `continuationToken` и `maxKeys` с query-параметрами S3 `continuation-token` и `max-keys` наряду с `list-type: 2`.
- **Сопоставляйте `output` с форматом ответа по сети**:
  - **Структурированный JSON (`listBuckets`, `listObjectsV2`)**: Объявляйте `struct.object(...)` с маппингом `.alias()` и полями `struct.date()`.
  - **Бинарные данные (`getObject`)**: Указывайте `output: struct.blob()` (или `struct.arrayBuffer()`).
  - **Пустое тело ответа (`headBucket`, `headObject`, `putObject`, `deleteObject`)**: Не указывайте `output`, чтобы ответы `HEAD`, `200` и `204` с нулевой длиной успешно завершались без попытки декодирования JSON, а вызывающий код по-прежнему мог прочитать заголовки ответа (`response.headers.get("etag")`) из третьего элемента кортежа.

## 4. Как внешние разработчики используют ваш SDK

Внешние приложения устанавливают `@company/s3-sdk` вместе с `@defjs/core`, настраивают собственный `Client` со своим эндпоинтом и перехватчиком подписи запросов и вызывают экспортированные операции напрямую как чистые функции. Пример следует обработке ошибок в стиле Go: `syncReport` делает три вызова, поэтому называет каждую ошибку по шагу (`putErr`, `listErr`, `getErr`), возвращает error-first кортеж и оборачивает сбойный шаг через `new Error("put object", { cause: putErr })`, как `fmt.Errorf("put object: %w", err)` в Go. Только `main`, верхний уровень программы, обрабатывает ошибку, записывая её в лог:
