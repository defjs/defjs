# Vue

Пакет `@defjs/vue` подключает клиент `@defjs/core`, принадлежащий приложению, к приложению Vue 3.2+ с помощью `createClientPlugin(client)`, константы `HTTP_CLIENT` и функции `injectClient()`. При этом определения вашего SDK остаются чистыми модулями `@defjs/core` без каких-либо зависимостей от Vue.

```sh
bun add @defjs/core @defjs/vue vue
```

## Зоны ответственности: что даёт `@defjs/vue`, а чем владеете вы

- **Предоставляет `@defjs/vue`**: функции `createClientPlugin(client)`, константы `HTTP_CLIENT` (`InjectionKey<DerivableClient>`) и функции `injectClient(key?)`.
- **Владеет ваше приложение**: создание экземпляра [`DerivableClient`](/ru-RU/api/core/derivableclient-type), отмена выполняемой работы в вотчерах (`onCleanup`) или компосаблах (`onScopeDispose`), закрытие хэндлов SSE/WebSocket и интеграция с библиотеками запросов (например, Vue Query).
- **Важно**: функция `injectClient()` возвращает объект-функцию `DerivableClient`. Вызывайте `client({ signal })` непосредственно там, где выполняется операция (`getOrder(client({ signal }), input)`). Никогда не передавайте `client` первым аргументом в `watch(client, ...)` или `computed(client)`, так как Vue воспринимает переданную функцию как реактивный геттер.

## 2. Внедрение и переопределение в поддеревьях

Функция `injectClient(key?)` находит ближайшего провайдера по ключу `key` (по умолчанию `HTTP_CLIENT`) и выбрасывает `Error`, если вызвана вне активного контекста внедрения Vue (`setup()` или `app.runWithContext()`), либо если по данному ключу клиент не был предоставлен.

Вы можете переопределить клиент для поддерева компонентов с помощью стандартного `provide(HTTP_CLIENT, childClient)`:

<include cwd>examples/vue/inject-and-override.vue#example</include>

- Дочерние компоненты получат `childClient`, в то время как соседние поддеревья продолжат использовать корневой клиент.
- Если вспомогательная функция принимает опциональный явный клиент (`explicitClient ?? injectClient()`), только ветка с вызовом `injectClient()` требует активного контекста внедрения Vue. Получайте клиент синхронно во время `setup()` до первого оператора `await`.

## 3. Очистка потоков SSE и WebSocket при уничтожении скоупа

Для операций, запущенных внутри composable или компонента вне watcher, используйте связку `AbortController` и `onScopeDispose`. Прерывайте запуск, закрывайте любой хэндл, разрешившийся после уничтожения скоупа, читайте единственный асинхронный итератор и дожидайтесь завершения через `.closed`:

<include cwd>examples/vue/realtime-scope.vue#example</include>

- Ветка ошибки кортежа показывает сбои первоначального хэндшейка (включая HTTP 503). Блок `catch` итератора показывает сбои после старта; блок `finally` по-прежнему закрывает поток и дожидается его завершения.

- Остановка скоупа штатно завершает цикл `for await` потока SSE.
- Прерывание сессии WebSocket завершает её в статусе `aborted` и отклоняет `session.receive` ошибкой `AbortError`, поэтому обрабатывайте блок `catch` после уничтожения скоупа и обязательно отписывайте слушателей `onStateChange` / `onRuntimeError` в блоке `finally`.

## 4. SSR и область видимости приложения

- **Браузер**: используйте один клиент на всё приложение Vue, если базовый эндпоинт и перехватчики не зависят от запроса.
- **SSR**: создавайте и подключайте отдельный клиент на каждый входящий SSR-запрос, если заголовки, cookies, тенанты или учётные данные различаются.
- Размонтирование приложения Vue или уничтожение скоупа компонента **не** отменяет HTTP-запросы автоматически, не закрывает потоки SSE/WebSocket и не уничтожает базовый клиент.
