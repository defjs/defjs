# Vue

Приложение Vue импортирует эндпоинты SDK и выполняет их через внедрённый клиент. SDK остаётся независимым от Vue. Создай и настрой клиент в подходящей области приложения или запроса; плагин фреймворка предоставит его компонентам.

Эти плагины — необязательные помощники для предоставления и получения существующего `Client`. Можно напрямую импортировать фиксированный клиент приложения, явно передавать Client переиспользуемой логике, использовать внедрение фреймворка для значений по умолчанию в дереве и переопределений в поддеревьях или выбрать свою организацию. Определения SDK не требуют этих плагинов.

Подключи существующий `@defjs/core` client к Vue. Получаешь плагин, injection key и `injectClient()`. Пакет **не** создаёт клиентов, не кеширует результаты, не ретраит команды и не закрывает ресурсы транспорта на unmount.

## Базовая настройка

Поставь `@defjs/core`, `@defjs/vue` и Vue 3.2+ (плагину нужны только `provide` / `inject`, но в примерах используются `<script setup>` и `onScopeDispose`, появившиеся в 3.2). ESM:

`bun add @defjs/core @defjs/vue vue`

`createClientPlugin(client)` отдаёт ровно тот объект, который ты передал. Без clone, без хука disposal. Опции core и interceptors настраивай, когда создаёшь клиент.

`onCleanup` бежит до повторного запуска watcher и когда он останавливается. Зарегистрируй его до старта async-работы. Error-first кортеж остаётся данными приложения.

## Inject и override

`injectClient(key)` читает ближайший провайдер для этого ключа; без аргумента или с `undefined` использует `HTTP_CLIENT`. Вызывай в действующем контексте внедрения Vue: синхронном `setup()` или `app.runWithContext()` (Vue 3.3+). Последний даёт только синхронный контекст приложения, без переопределений поддерева и без сохранения через обычный `await`. Контекст, восстановленный компилятором после верхнеуровневого `await` в `<script setup>`, по-прежнему подходит.

Для своего `InjectionKey<Client>` используй `app.provide(key, client)` или `provide(key, client)` в компоненте-предке. Обе стороны должны разделять один и тот же объект `Symbol`; одинаковые описания не делают ключи равными. `createClientPlugin(client)` по-прежнему принимает только клиент и предоставляет только `HTTP_CLIENT`.

Бросает `Error`, если нет активного контекста внедрения или клиента по выбранному ключу. Отсутствующий свой ключ не приводит к откату на `HTTP_CLIENT`; одна установка плагина не создаёт контекст внедрения.

Функция приложения, которая только получает клиент, может использовать `explicitClient ?? injectClient()`: контекст внедрения нужен лишь запасной ветке. Другие lifecycle API в том же composable сохраняют свои требования к контексту. Получи клиент в действующем контексте до async-работы и переиспользуй этот объект.

## Владей HTTP-работой вне watcher

Для работы, которую стартует composable или компонент вне watcher, используй `AbortController` + `onScopeDispose`. Abort старта и активной работы; проверь signal, прежде чем писать в реактивное состояние. Плагин или injection scope не выводит, кто владеет командой. Для страниц-списков оберни `execute` в Vue Query (или похожее) — `@defjs/vue` остаётся только DI и **не** предоставляет `useRequest`.

Когда scope владеет клиентом, держи его независимым от запроса для переиспользования на весь браузер. Если он захватывает заголовки, cookies, пользователей, tenants или credentials, создай его на релевантной границе запроса app/SSR и отдай этот экземпляр там.

## Чисти realtime scope

Закрой стрим или сессию, даже если scope исчез посреди connect. Abort старта, закрой поздно приехавший handle, потреби единственный iterator, дождись терминального promise:

<include cwd>examples/vue/realtime-scope.vue#example</include>

Фатальные ошибки стрима и переполнение очереди reject’ят iterator, поэтому у цикла есть `catch`; иначе этот reject окажется unhandled. Пример хранит только последние 100 сообщений и ключует строки по id, потому что одинаковые payload дали бы дублирующиеся ключи. Остановка scope штатно завершает итерацию для SSE; прерванная сессия WebSocket вместо этого reject’ит `receive` с `AbortError`, так что защищай `catch` так же.

WebSocket: та же последовательность — abort подготовки, закрой позднюю сессию, потреби `session.receive`, отпиши `onStateChange` / `onRuntimeError`, close, await `session.closed`. Держи cleanup идемпотентным; disposal и завершение iterator могут встретиться.

## Scope SSR

`createClientPlugin(client)` отдаёт один экземпляр одному Vue-приложению. В браузере дели его, когда эндпоинт, interceptors и захваченное состояние безопасно делить. Во время SSR создавай и ставь отдельный клиент на запрос, когда различаются заголовки, cookies, пользователи, tenants или credentials.

Unmount приложения, снятие плагина и disposal scope компонента **не** abort’ят HTTP, не закрывают SSE/WebSocket, не отписывают listener’ы и не dispose’ят core client. Владелец, который стартовал работу, должен её закончить.

- `HTTP_CLIENT` — `InjectionKey<Client>` для нативных `provide` / `inject`
- `createClientPlugin(client)` — Vue `Plugin`, который отдаёт этот клиент

Клиентов и опции создавай в `@defjs/core`. См. [Клиент](/ru-RU/docs/client), [Команды](/ru-RU/docs/commands), [Interceptors](/ru-RU/docs/interceptors), [SSE](/ru-RU/docs/sse) и [WebSocket](/ru-RU/docs/web-socket).
