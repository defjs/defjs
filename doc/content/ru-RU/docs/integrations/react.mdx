# React

Импортируй операции из SDK или общего модуля определений. Приложение React владеет клиентом и предоставляет его через этот плагин фреймворка; пакет SDK может не зависеть от React и переиспользоваться другими приложениями.

Эти плагины — необязательные помощники для предоставления и получения существующего `Client`. Можно напрямую импортировать фиксированный клиент приложения, явно передавать Client переиспользуемой логике, использовать внедрение фреймворка для значений по умолчанию в дереве и переопределений в поддеревьях или выбрать свою организацию. Определения SDK не требуют этих плагинов.

Подключи существующий `@defjs/core` client к React-дереву. Получаешь Context и `useClient()`. Пакет **не** создаёт client, не вешает кеш, не ретраит операции и не dispose’ит ресурсы транспорта. Компонент, effect или data-библиотека, которые стартуют работу, ей владеют. Клиент из `useClient()` передаётся в операцию. Хук возвращает переданный [`DerivableClient`](/ru-RU/api/core/derivableclient-type). Для опций отдельного вызова, например `signal`, вызови его там, где выполняется операция: `getOrder(client({ signal }), input)`. Не передавай его в setter состояния, потому что `setState(client)` вызовет его как updater. Выведенное значение `Client` не принимается ни `ClientProvider`, ни `useClient`.

## Читай через `useClient`

`useClient(overrideClient)` отдаёт приоритет явному клиенту; без аргумента или с `undefined` читает ближайший `ClientProvider`. `Error` выбрасывается только тогда, когда ни один источник не предоставляет клиент. Вызов `useClient()` без аргумента по-прежнему допустим.

Всегда вызывай `useClient(explicitClient)` на верхнем уровне компонента или своего хука, даже с явным клиентом; не в обычной функции или обработчике события. `explicitClient ?? useClient()` условно вызывает хук и недопустим. Переопределение не пишет в Context и не создаёт провайдер; хук по-прежнему подписывается на Context.

<include cwd>examples/react/read-with-use-client.tsx#example</include>

## Владей query-работой

Query-библиотека может владеть кешем, ретраями, подавлением устаревшего результата и отменой. Передай сигнал, который она даёт, как `signal` на выведенном клиенте. Для страниц-списков вызывай операцию из TanStack Query (или похожего) — `@defjs/react` остаётся только DI и **не** предоставляет `useRequest`.

<include cwd>examples/react/own-query-work.tsx#example</include>

`throw error` здесь — канал отклонения query-функции, а не обычный вызов Defjs. Кортеж читается первым; отклоняет только этот адаптер, чтобы query-библиотека записала сбой.

Не стартуй ту же операцию во втором effect — два владельца делают отмену и обработку устаревшего результата неоднозначными.

## Владей realtime-работой

Handle SSE и WebSocket живут дольше вызова операции. Зарегистрируй cleanup до ожидания старта, закрой handle, который приехал после disposal, потреби единственный iterator, дождись терминального promise:

<include cwd>examples/react/own-realtime-work.tsx#example</include>

Переданный операции `signal` продолжает управлять открытой сессией. Его abort в cleanup завершает сессию как `aborted` и reject’ит `receive` с `AbortError`, поэтому `catch` выше игнорирует ошибки, когда effect уже disposed, и сообщает только настоящие сбои (переполнение очереди, таймаут подтверждения heartbeat). Прерванный SSE-стрим, наоборот, завершает свой iterator штатно. Без `catch` reject из цикла стал бы unhandled promise rejection.

То же правило для `EventStreamHandle`: close в `finally`, await `stream.closed`. Потребители WebSocket ещё должны отписать listener’ы state и runtime-error и продолжать читать `session.receive` — непрочитанная ограниченная очередь может переполниться.

## SSR и scope клиента

Точка входа пакета — граница Client Component. Браузерное приложение может делить клиент на уровне модуля, когда эндпоинт, interceptors и захваченное состояние безопасны для браузера и не зависят от запроса. Для SSR создавай отдельный клиент внутри каждой границы запроса, когда различаются заголовки, cookies, пользователи, tenants или credentials.

Unmount провайдера **не** abort’ит HTTP, не закрывает SSE/WebSocket, не отписывает listener’ы и не зовёт `dispose`. У `@defjs/react` такого lifecycle API нет. Код, который стартовал каждую операцию, должен её закончить или отменить.

## Справка

Публичные экспорты `@defjs/react`:

- `ClientProvider` — принимает `ClientProviderProps`, отдаёт переданный клиент
- `useClient` — сначала явный клиент, иначе клиент ближайшего провайдера; бросает, если оба отсутствуют
- `ClientProviderProps` — `{ client: Client; children?: ReactNode }`

Клиентов и опции создавай в `@defjs/core`. См. [Клиент](/ru-RU/docs/client), [Ошибки](/ru-RU/docs/errors), [SSE](/ru-RU/docs/sse) и [WebSocket](/ru-RU/docs/web-socket).
