# React

Пакет `@defjs/react` подключает клиент `@defjs/core`, принадлежащий приложению, к дереву компонентов React 18+ через React Context и хук `useClient()`. При этом определения вашего SDK остаются чистыми модулями `@defjs/core` без каких-либо зависимостей от React.

```sh
bun add @defjs/core @defjs/react react
```

## Зоны ответственности: что даёт `@defjs/react`, а чем владеете вы

- **Предоставляет `@defjs/react`**: компонент `ClientProvider` и хук `useClient(overrideClient?)`.
- **Владеет ваше приложение**: создание экземпляра [`DerivableClient`](/ru-RU/api/core/derivableclient-type), отмена выполняемых запросов при размонтировании или смене зависимостей (`AbortController`), закрытие хэндлов SSE/WebSocket и интеграция с библиотеками кэширования запросов (например, TanStack Query).
- **Важно**: хук `useClient()` возвращает объект-функцию `DerivableClient`. Вызывайте `client({ signal })` непосредственно в месте выполнения операции (`getOrder(client({ signal }), input)`). Никогда не передавайте `client` напрямую в `setState(client)`, так как React воспринимает переданную функцию как функцию обновления состояния (updater).

## 2. Чтение и переопределение с помощью `useClient`

Вызов `useClient(overrideClient)` возвращает `overrideClient`, если он передан, либо читает клиент из ближайшего `ClientProvider`, если аргумент опущен или равен `undefined`. Ошибка `Error` выбрасывается только в том случае, если клиент не был предоставлен ни одним из источников.

<include cwd>examples/react/read-with-use-client.tsx#example</include>

- Всегда вызывайте `useClient(explicitClient)` безусловно на верхнем уровне компонента или пользовательского хука. Никогда не пишите `explicitClient ?? useClient()`, так как это нарушает правила вызова хуков (Rules of Hooks).

## 3. Интеграция с TanStack Query

Пакет `@defjs/react` отвечает исключительно за внедрение зависимостей и **не** содержит встроенного хука `useRequest`. При использовании сторонних библиотек получения данных, таких как TanStack Query, пробрасывайте `signal` функции запроса через `client({ signal })` и преобразуйте error-first кортеж внутри адаптера:

## 4. Управление жизненным циклом SSE и WebSocket в эффектах

Хэндлы SSE и WebSocket продолжают жить после завершения вызова `openStream(...)` или `connectChat(...)`. Передайте в операцию сигнал `AbortController` и прерывайте его в функции очистки: сигнал покрывает и запуск, и открытую сессию. Владейте сессией через `await using` и читайте её единственный асинхронный итератор:

<include cwd>examples/react/own-realtime-work.tsx#example</include>

- Прерывание сигнала `signal`, переданного в операцию WebSocket, переводит сессию в статус `aborted` и отклоняет `session.receive` ошибкой `AbortError`. Проверяйте `controller.signal.aborted` в блоке `catch`, чтобы наружу всплывали только реальные ошибки времени выполнения (такие как таймаут heartbeat).
- Прерывание потока SSE завершает цикл `for await (const msg of stream)` штатно без выброса исключений.

## 5. SSR и область видимости провайдера

- **Браузер**: используйте общий клиент уровня модуля, если базовый эндпоинт и перехватчики не зависят от контекста запроса.
- **SSR**: создавайте отдельный клиент внутри границы каждого входящего серверного запроса, если заголовки, cookies, тенанты или учётные данные различаются между запросами.
- Размонтирование `<ClientProvider>` **не** отменяет активные HTTP-запросы, не закрывает соединения SSE/WebSocket и не освобождает клиент.

## Публичные экспорты и руководства

- `ClientProvider` — предоставляет `DerivableClient` (`ClientProviderProps: { client: DerivableClient; children?: ReactNode }`).
- `useClient(overrideClient?)` — считывает явно переданный клиент или клиент из ближайшего провайдера.
