# Struct и схемы

`struct` объявляет сетевой контракт данных, разделяемый между SDK и использующими приложениями: входные параметры вызывающего кода, успешные ответы `2xx`, объявленные сервисные ошибки, события SSE и кадры WebSocket.

- **Статический вывод типов**: выводите типы TypeScript с помощью `Infer<typeof Schema>`.
- **Error-first валидация**: проверяйте значения во время выполнения с помощью `struct.parse(Schema, value)` — возвращает `[null, data]` или `[StructError, undefined]` без выбрасывания исключений.

Распарсенные объекты сохраняют только явно объявленные поля (неизвестные свойства отсекаются) и создаются с прототипом `null`. Любой пропущенный обязательный ключ, несоответствие примитивного типа или невалидная ветка приводят к `StructError` без возврата частичных данных.

## 2. Обязательные, опциональные и nullable-поля

Defjs строго разделяет **наличие поля** (`undefined`) и **допустимость отсутствия значения** (`null`). Каждый конструктор `struct` по умолчанию строго обязателен и не допускает `null`:

| Объявление                   | Отсутствует / `undefined`               | `null`    | Допустимое значение |
| ---------------------------- | --------------------------------------- | --------- | ------------------- |
| `struct.string()`            | Ошибка                                  | Ошибка    | Принимает `string`  |
| `struct.string().optional()` | Принимает (опускается при сериализации) | Ошибка    | Принимает `string`  |
| `struct.string().null()`     | Ошибка                                  | Принимает | Принимает `string`  |
| `struct.string().nullish()`  | Принимает (опускается при сериализации) | Принимает | Принимает `string`  |
| `struct.null()`              | Ошибка                                  | Принимает | Отклоняет не-`null` |

<include cwd lang="typescript">
  examples/struct/required-optional-null.ts#example
</include>

Конструкторы `struct.any()` и `struct.unknown()` также отклоняют `null` и `undefined`, если к ним явно не добавлены `.null()`, `.optional()` или `.nullish()`.

## 3. Двунаправленные сетевые алиасы (`.alias()`)

Используйте `.alias("wire_name")`, когда бэкенд использует `snake_case` или заголовки, а ваш TypeScript SDK спроектирован в `camelCase`. Алиас объявляется у поля ровно один раз и прозрачно работает в обоих направлениях:

| Граница применения                                                                     | Используемый ключ                                   |
| -------------------------------------------------------------------------------------- | --------------------------------------------------- |
| Входные данные `input` и `struct.parse(Schema, value)`                                 | Логическое имя (`customerName`)                     |
| Типизированное значение struct, возвращаемое из `builder` (`body`, `query`, `headers`) | Сетевой алиас (`customer_name`)                     |
| Декодирование JSON-ответа / события SSE / кадра WebSocket                              | Сетевой `customer_name` → логический `customerName` |
| Анонимный ключ объекта, написанный прямо в `builder`                                   | Литеральный ключ как написан                        |

<include cwd lang="typescript">
  examples/struct/aliases.ts#example
</include>

Разворачивание (spread) типизированного объекта внутри `builder` (`{ ...input.order, extra: 1 }`) сохраняет кодирование структуры и все алиасы. Указание одновременно логического ключа и его сетевого алиаса в одном объекте приводит к ошибке `REQ_BUILD_FAILED`.

## 4. Размещение в запросе и кодеки форм

`input` объявляет параметры вызова, а `builder` распределяет их по объекту `{ path, query, headers, body }`. Для тел с кодированием форм конструкторы `struct.urlencoded(shape)` и `struct.formData(shape)` помечают корневой объект, благодаря чему транспорт автоматически сериализует его как `URLSearchParams` или `FormData`:

<include cwd lang="typescript">
  examples/struct/request-placement.ts#example
</include>

| Корень `body`, возвращённый из `builder`                       | Сетевой формат    | `Content-Type` по умолчанию                       |
| -------------------------------------------------------------- | ----------------- | ------------------------------------------------- |
| Типизированный объект, массив, конечное число, boolean, `null` | Текст JSON        | `application/json`                                |
| `string` struct или обычная `string`                           | Текст UTF-8       | `text/plain;charset=UTF-8`                        |
| `struct.urlencoded(shape)` в корне тела                        | `URLSearchParams` | `application/x-www-form-urlencoded;charset=UTF-8` |
| `struct.formData(shape)` в корне тела                          | `FormData`        | `multipart/form-data; boundary=...`               |
| `Blob` / `File` (`struct.file()`)                              | Бинарный blob     | `blob.type` или `application/octet-stream`        |
| `ArrayBuffer` / typed array view / `ReadableStream`            | Сырые байты       | `application/octet-stream`                        |

## 5. Обработка `StructError` и проблем валидации

При неудачной валидации вызов `struct.parse(Schema, data, { aliases?, errorMap? })` возвращает кортеж `[StructError, undefined]`. Класс `StructError` расширяет стандартный `Error` и предоставляет свойство `issues` и методы `format()`, `flatten()` и `prettify()`:

<include cwd lang="typescript">
  examples/struct/parse-failures.ts#example
</include>

Каждая запись `StructIssue` содержит `code` (`invalid_type`, `missing_key`, `invalid_literal`, `invalid_enum`, `invalid_union`, `invalid_intersection` или `custom`), `path`, `expected`, `received` и `message`. Сообщения по умолчанию опускают полученное значение и сообщают только его _тип_, но пути сохраняют динамические ключи record, которые могут содержать конфиденциальные значения. `String(err)` и `err.prettify()` не являются границей маскирования; при логировании используйте allowlist безопасных полей и считайте сырые значения `received` и пользовательские сообщения конфиденциальными.

| `struct.enum(values)`                                      | Объявленный строковый или числовой элемент | Объединение литералов                                        |
| `struct.array(item)` / `struct.tuple(items)`               | Массив / кортеж фиксированной длины        | `T[]` / `[...]`                                              |
| `struct.object(shape)` / `struct.record(val)`              | Простой объект                             | Типизированный объект / `Record<string, V>`                  |

### Рекурсивные struct

Самоссылающийся тип читает сам себя через свойство-геттер в shape. Геттеры выполняются один раз, при первом использовании объектного struct, а не при определении константы, поэтому константа может ссылаться на себя. Аннотируйте константу типом `Struct<T>`: TypeScript не может вывести тип, который ссылается на самого себя.

### Чего `struct` не делает

- `struct` только объявляет структуру. Длина строк, шаблоны, числовые диапазоны и бизнес-правила относятся к коду приложения после разбора.
- Разбор останавливается на первом недопустимом поле. Он никогда не подставляет нулевое значение вместо отсутствующего поля и не возвращает частичный результат.
