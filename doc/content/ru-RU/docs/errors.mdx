# Обработка ошибок

В Defjs сбои запросов, транспорта и декодирования не приводят к выбросу исключений в месте вызова. Каждая операция возвращает error-first кортеж (`[error, ...]`), где `error` равен либо `null`, либо типизированному объекту `Fault` (экземпляру нативного `Error`, дискриминируемому полем `error.code`).

Вызов, который отклоняет TypeScript, — исключение: его результат не определён, и это не `Fault`. На практике он обычно отклоняется с `TypeError` платформы.

### Почему при сбое HTTP метаданные ответа находятся в `error`

При сбое HTTP операция возвращает кортеж `[error, undefined, undefined]`. Любые поступившие метаданные ответа (`status`, `statusText`, `headers`, `url`) прикрепляются напрямую к свойству `error.response`. Это позволяет передавать только объект `error` в логгер или обработчик ошибок без потери контекста.

## 2. Классы сбоев и замкнутый набор кодов ошибок

Префикс до первого символа `_` определяет класс сбоя (`HTTP`, `REQ`, `NET`, `RES`, `EXT`, `CAP`, `ENV`), а полный `code` образует замкнутое объединение строковых литералов для исчерпывающих проверок в `switch`:

| Класс  | Коды сбоев                                                             | Значение и устранение                                                                                                                                                                                                                                                                                                                                                              |
| ------ | ---------------------------------------------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `HTTP` | `HTTP_STATUS`                                                          | Сервер вернул статус вне диапазона `2xx` (`3xx`, `4xx`, `5xx`), и объявленная структура `error` была успешно декодирована.                                                                                                                                                                                                                                                         |
| `REQ`  | `REQ_INPUT_INVALID`, `REQ_BUILD_FAILED`                                | Входные данные вызывающего кода не прошли валидацию, URL или путь был невалиден, `builder` бросил исключение, либо запрос не удалось собрать (HTTP: поток тела уже использован, недопустимый или запрещённый метод, тело у GET/HEAD, невалидный `Content-Type`; HTTP и SSE: URL с учётными данными, значение заголовка, которое отвергает платформа). Повторять запрос бесполезно. |
| `RES`  | `RES_MEDIA_TYPE_INVALID`, `RES_DECODE_FAILED`, `RES_STRUCT_MISMATCH`   | Ответ сервера нарушил объявленный Content-Type, формат представления или контракт структуры `struct`.                                                                                                                                                                                                                                                                              |
| `NET`  | `NET_ABORTED`, `NET_TIMEOUT`, `NET_UNREACHABLE`, `NET_BODY_INCOMPLETE` | Запрос отменён вызывающим кодом (`NET_ABORTED`), истёк дедлайн (`NET_TIMEOUT`), сбой соединения или обрыв потока данных.                                                                                                                                                                                                                                                           |
| `EXT`  | `EXT_INTERCEPTOR_FAILED`, `EXT_HOOK_FAILED`, `EXT_OBSERVER_FAILED`     | Перехватчик приложения, хук или наблюдатель прогресса/состояния бросил собственную ошибку, либо перехватчик передал в `next()` `signal`, который не является `AbortSignal`.                                                                                                                                                                                                        |
| `CAP`  | `CAP_BUFFER_EXCEEDED`                                                  | Буфер кадров SSE превысил заданный лимит.                                                                                                                                                                                                                                                                                                                                          |
| `ENV`  | `ENV_UNSUPPORTED`                                                      | В среде выполнения отсутствуют необходимые Web API (например, потоковая передача тела запроса в Firefox).                                                                                                                                                                                                                                                                          |

Код называет, что сломалось, а не кто передал значение. Для HTTP запрос, который платформа не может собрать, — это `REQ_BUILD_FAILED`, откуда бы ни пришло плохое значение: из `builder`, из конфигурации клиента или из перехватчика. SSE применяет то же правило к значениям заголовков, невалидному URL и URL с учётными данными — и на первой попытке, и при каждом переподключении. Последнее библиотека проверяет сама, потому что Bun принимает такой URL и отправил бы запрос. Другие значения, которые платформа может отвергнуть, библиотека на SSE и WebSocket не проверяет (недопустимый метод у SSE; URL с учётными данными, недопустимый субпротокол или неподдерживаемая схема у WebSocket), поэтому отказ там сообщается как `NET_UNREACHABLE` с ошибкой платформы в `cause`, а среда выполнения, которая значение принимает (Bun — для недопустимого метода SSE), отправляет запрос. `EXT_INTERCEPTOR_FAILED` покрывает собственное поведение перехватчика: ошибку, которую он бросает, или `signal`, который не является `AbortSignal` (канал отмены, а не содержимое запроса).

### Свойства объекта Fault в зависимости от кода ошибки

| Код ошибки    | `status`    | `response`                                           | `data`                                           | `cause`                           |
| ------------- | ----------- | ---------------------------------------------------- | ------------------------------------------------ | --------------------------------- |
| `HTTP_STATUS` | `number`    | `DecodedResponse<TErr>` или `HttpMeta`               | Декодированная структура `error` или `undefined` | Первопричина ошибки (если есть)   |
| `RES_*`       | `number`    | `HttpMeta` (**без свойства `body`**)                 | Отсутствует                                      | `StructError` или ошибка парсера  |
| Прочие коды   | Отсутствует | `HttpMeta` при наличии заголовков, иначе `undefined` | Отсутствует                                      | Исходный `Error` / причина отмены |

## 4. Ошибки старта и ошибки после открытия для SSE и WebSocket

Для долгоживущих соединений кортеж операции возвращает ошибки **старта** (возникшие до открытия потока или сокета). После успешного открытия ошибки времени выполнения доставляются через жизненный цикл хэндла или сессии:

| Транспорт     | Ошибка старта (возвращается в кортеже)                                                                                                                                                     | Ошибка после открытия (после разрешения кортежа)                                                                                                                                                                                                                               |
| ------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| **HTTP**      | Все сбои завершают кортеж операции ровно один раз.                                                                                                                                         | Не применимо                                                                                                                                                                                                                                                                   |
| **SSE**       | Статус вне `2xx` (`HTTP_STATUS`, либо сбой декодирования, когда объявленное тело `error` не удаётся декодировать) или хэндшейк `2xx` с неверным типом контента (`RES_MEDIA_TYPE_INVALID`). | Асинхронный итератор завершается с ошибкой; `stream.closed` разрешается значением `{ kind: 'error', code }`.                                                                                                                                                                   |
| **WebSocket** | Закрытие до открытия, сбой конструктора или отмена во время хэндшейка.                                                                                                                     | Нефатальные ошибки кадров вызывают `session.onRuntimeError`; фатальные сбои прерывают `session.receive` и разрешают `session.closed` со значением `{ kind: 'error', cause }`. Таймаут heartbeat и исчерпанные повторы сохраняют обычные причины типа `Error` среды выполнения. |

## 5. Безопасное структурированное логирование и анализ первопричин

Каждый `Fault` является экземпляром нативного `Error` (`instanceof Error === true`) с перечислимым свойством `code`. Наличие `status`, `response` и `data` зависит от кода, как показано в таблице выше: у `HTTP_STATUS` есть все три, у `RES_*` — `status` и `response`, а у любого другого кода только `response`, которое равно `undefined`, пока не пришли заголовки.
