Поручить помощнику написать код Defjs и вызвать службу ИИ из приложения — разные задачи. Эта страница описывает работу помощника. [Вызов API ИИ](/ru-RU/docs/ai-api) описывает работу приложения. Совместимый помощник может загрузить установленный Skill для подходящей задачи; автоматическая загрузка зависит от инструмента.

## Установить skill [#install]

CLI skills требует Node.js 22.20 или новее. Это требование установщика, а не среда выполнения `@defjs/core`. Среда выполнения описана в [быстром старте](/ru-RU/docs/start).

Запустите команду в нужном проекте. По умолчанию CLI устанавливает Skill в текущий проект и может определить текущего агента или предложить выбор; используйте `-a`, чтобы указать агента явно.

```sh
npx skills add defjs/defjs --skill defjs
```

После публикации инструкции skill можно прочитать в [skills/defjs/SKILL.md](https://github.com/defjs/defjs/blob/main/skills/defjs/SKILL.md). Исходный код на GitHub — это ветка по умолчанию, и она может не совпадать с версией `@defjs/core`, установленной в проекте.

## Попросить один эндпоинт [#prompt]

Дайте помощнику одну задачу. Этот запрос просит типизированный `GET /orders/:id`, клиент которого остаётся в приложении:

```txt
Use @defjs/core to define GET /orders/:id.
The input is { id: number }; a successful response is { id: number, status: string }.
Keep the SDK definition and application client in separate modules,
and verify the result with the project’s existing tests.
```

## Проверить результат [#verify]

Читайте определение и приложение отдельно. Определение экспортирует операцию и не создаёт client. Приложение создаёт client и вызывает операцию, например `getOrder(client, { id: 1 })`. Если объявлен `input`, `builder` — явная синхронная чистая функция. Успешное значение используется только когда слот ошибки пуст.

Затем запустите проверку типов этого проекта и тесты, которые действительно выполняют контракт. Установка зависимостей и правила CI остаются в том проекте.

## Английский Markdown для помощников [#resources]

Руководства, примеры и обзоры API на этом сайте написаны для людей и есть на каждом языке. Три адреса ниже собраны только из английских страниц. У них нет языкового префикса, и это не перевод страницы, которую вы читаете.

- [Указатель английских страниц](/llms.txt) перечисляет английские страницы и ссылается на их веб-адреса.
- [Собранные английские руководства](/llms-full.txt) соединяет эти страницы в один файл.
- [Быстрый старт в Markdown](/llms.mdx/docs/start/content.md) — английский текст одной страницы. Остальные английские страницы имеют ту же форму, `/llms.mdx/…/content.md`.

Читайте [быстрый старт](/ru-RU/docs/start), когда нужно руководство на этом языке. Передайте помощнику адрес Markdown, когда он должен следовать API. Он всё равно обязан соблюдать версию `@defjs/core`, установленную в проекте: документация сайта может отличаться от установленного выпуска, поэтому сверяйте API с этой версией. Исходный код документации на GitHub тоже относится к ветке по умолчанию и может не совпадать с установленной версией. Уберите секреты и проверьте политику данных проекта, прежде чем передавать код или контекст инструменту ИИ.
