Вызов службы ИИ из приложения — не то же самое, что поручить помощнику написать Defjs. [Разработка с помощью ИИ](/ru-RU/docs/ai) описывает работу помощника. Форматы API и событий SSE зависят от поставщика. Поток на этой странице — вымышленный сервер, а не протокол конкретного поставщика.

## Вызвать API ИИ из приложения [#call-an-api]

Опишите вызов тем же контрактом HTTP или SSE, которым уже пользуетесь, и вызовите операцию клиентом, которым владеет приложение. Начните с [HTTP-запросов](/ru-RU/docs/http) и [потоков событий SSE](/ru-RU/docs/sse). [Отправка JSON](/ru-RU/recipes/post-json) — обычное тело JSON. [Получение событий SSE](/ru-RU/recipes/consume-sse) показывает, как читать и закрывать поток, но останавливается после первого события. Этот пример — не полный ответ ИИ. Чтобы получить полный ответ ИИ, продолжайте чтение до сигнала завершения поставщика или EOF, обрабатывайте ошибки чтения и закрывайте поток; имена событий и схемы данных также согласуйте с форматом поставщика. [Отмена и таймауты](/ru-RU/recipes/cancel-http) показывают, как вызывающий останавливает HTTP-вызов.

Держите секрет службы на сервере, которому разрешено его тратить. Не кладите его в пакет браузера, в публичную переменную сборки и в клиент, который уезжает в браузер. Учётные данные принадлежат приложению: задайте их на серверном клиенте или добавьте в перехватчике, который работает только внутри этой серверной границы. Место для этого — [настройка клиента](/ru-RU/docs/client) и [перехватчики](/ru-RU/docs/interceptors). `withCredentials` только выбирает режим cookie у Fetch. Секрет службы он не хранит.

После возврата операции потоком владеет приложение. Для SSE прочитайте события, закройте дескриптор и дождитесь закрытия. Для HTTP прервите вызов, когда ответ больше не нужен. Прерывание не доказывает, что служба отменила уже принятую работу.

Не повторяйте потоковый POST только потому, что попытка не удалась. Defjs сам не повторяет HTTP. Повторное подключение SSE выключено, пока приложение его не включит, и метод вроде POST не отправляется снова, если эта политика явно это не разрешает. Неудачная попытка уже могла начать работу, за которую служба выставляет счёт. Повторная отправка того же POST может начать эту работу второй раз. Прежде чем добавлять повтор, прочитайте правила повторной отправки в [HTTP-запросах](/ru-RU/docs/http) и правила переподключения в [потоках событий SSE](/ru-RU/docs/sse).

## Вымышленный офлайн-поток [#fictional-stream]

Формат ниже вымышлен. Это не формат событий конкретного поставщика. Ответ даёт `withSSEHandle`, поэтому примеру не нужны сеть и настоящие учётные данные. Тело — два события `delta`, а затем событие завершения. Цикл сохраняет оба фрагмента текста. Он не останавливается после первого события.

<include cwd lang="typescript">
  examples/ai/fictional-completion.ts#example
</include>

В проекте с установленным `@defjs/core` сохраните пример как `fictional-completion.ts` и выполните:

```sh
bun fictional-completion.ts
```

Ожидаемый вывод:

```txt
Hello there
```
