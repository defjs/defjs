# Инженерные соглашения [#engineering-conventions]

Пишете ли вы вручную слой HTTP-запросов внутри фронтенд- или бэкенд-приложения или публикуете официальный TypeScript SDK для публичного API своей компании, проекты на Defjs следуют единой модульной архитектуре: **общие модели данных `struct` (`models/`) в паре с чистыми определениями операций (`services/`)**.

---

## 1. Два сценария использования Defjs

Большинство команд применяют Defjs в одном из двух сценариев. В обоих случаях контракты разделяются на `models/` и `services/`, а отличие заключается лишь в том, где создаётся `createClient(...)`:

| Сценарий                                                                                          | Структура каталогов                                               | Кто владеет `createClient(...)`?                                                                        | Руководство                                             |
| :------------------------------------------------------------------------------------------------ | :---------------------------------------------------------------- | :------------------------------------------------------------------------------------------------------ | :------------------------------------------------------ |
| **[API-слой приложения](/ru-RU/docs/application-api)** (HTTP- и realtime-запросы внутри проекта)  | `src/api/models/` + `src/api/services/` + `src/api/client.ts`     | Ваше приложение (`src/api/client.ts` экспортирует браузерный синглтон или SSR-фабрику на каждый запрос) | [API-слой приложения](/ru-RU/docs/application-api)      |
| **[Проектирование публичного SDK](/ru-RU/docs/public-sdk)** (внешний npm-пакет для публичных API) | `src/models/` + `src/services/` + `src/index.ts` (`package.json`) | Приложение внешнего потребителя (публикуемый SDK никогда не создаёт и не захватывает `Client`)          | [Проектирование публичного SDK](/ru-RU/docs/public-sdk) |

---

## 2. Четыре базовых инженерных соглашения

### Соглашение 1: Экспортируйте чистые функции операций, а не классы `Service`

Устаревшие генераторы OpenAPI оборачивают эндпоинты в хранящие состояние или статические классы `Service` (`OrdersService.getOrder(id)` или `new S3Client().send(...)`). В Defjs каждая операция, созданная с помощью `defineRequest`, `defineEventStream` или `defineWebSocket`, уже является **самостоятельной вызываемой функцией**:

```ts
// Избегайте: оборачивание определений в класс или объект пространства имён
export class OrdersService {
  // Скрывает передачу опций на вызов client(options) и мешает tree-shaking в бандлерах
}

// Рекомендуется: экспортируйте отдельные определения операций из services/*.ts
export const getOrder = defineRequest({
  meta: { operation: "orders.get" },
  method: "GET",
  path: "/orders/:id",
  input: GetOrderInput,
  builder: (input) => ({ path: { id: input.id } }),
  output: Order,
  error: ApiError,
});
```

Прямой вызов экспортированной операции (`await getOrder(client, { id: 42 })` или `await getOrder(client({ signal }), { id: 42 })`) сохраняет единообразный стиль вызова во всей кодовой базе и позволяет сборщикам отсекать неиспользуемые операции (tree-shaking) при указании `"sideEffects": false`.

### Соглашение 2: Одноимённый экспорт `struct` и `Infer` в `models/`

В файлах `models/*.ts` экспортируйте и runtime-схему `struct`, и выведенный из неё тип TypeScript под **одним и тем же именем**. TypeScript объединяет объявления значения и типа в одной области видимости, поэтому вызывающий код импортирует один символ как для валидации во время выполнения, так и для статических аннотаций типов:

```ts
import { struct, type Infer } from "@defjs/core";

export const Order = struct.object({
  id: struct.number(),
  customerName: struct.string().alias("customer_name"),
  totalCents: struct.number().alias("total_cents"),
});
export type Order = Infer<typeof Order>;
```

### Соглашение 3: Не импортируйте экземпляры клиента в `services/*.ts`

Даже при написании [API-слоя приложения](/ru-RU/docs/application-api) внутри одного репозитория (`src/api/`) **не** импортируйте `apiClient` в `src/api/services/*.ts` для оборачивания определений. Сохранение `services/*.ts` в виде чистых определений даёт три непосредственных преимущества:

1. **Детерминированные офлайн-тесты**: Юнит-тесты могут передавать локальный `createClient(withEndpoint(...), withHTTPHandle(...))` напрямую в любую операцию без мокирования модулей.
2. **Безопасность в SSR и мультитенантных средах**: Серверные загрузчики могут передавать привязанный к запросу `Client` с cookie текущего пользователя или токеном тенанта в то же самое определение операции, которое используют браузерные компоненты.
3. **Бесшовное выделение в общий пакет**: Если позже команда решит вынести `src/api/models/` и `src/api/services/` в пакет монорепозитория или публичный npm SDK, ни один файл операций менять не придётся.

### Соглашение 4: Отделяйте размещение данных в `builder` от политик перехватчиков

Держите каждую задачу на соответствующем архитектурном уровне:

| Задача                                                                                              | Где должна находиться                                          | Почему                                                                                                                                            |
| :-------------------------------------------------------------------------------------------------- | :------------------------------------------------------------- | :------------------------------------------------------------------------------------------------------------------------------------------------ |
| Распределение входных параметров по `path`, `query`, `headers` и `body`                             | Функция `builder` операции в `services/*.ts`                   | Синхронная чистая функция от текущего `input`                                                                                                     |
| Определяемый приложением контекст для перехватчиков (`{ operation: "orders.create" }`)              | Поле `meta` операции в `services/*.ts`                         | `{ [key: string]: unknown }`; только для чтения и общий для определения; никогда не отправляется вместе с запросом; сообщается как `defjs.meta.*` |
| Базовые URL, заголовки авторизации (`Authorization`, подписи, XSRF), повторы, балансировка нагрузки | `createClient(...)` в `client.ts`                              | Политика выполнения, зависящая от окружения и сессии                                                                                              |
| Тайм-ауты на конкретный вызов, отмена (`signal`) и колбэки прогресса передачи                       | Вызов `client({ signal, onDownloadProgress })` на месте вызова | Действует только на один вызов, не изменяя общий клиент                                                                                           |
