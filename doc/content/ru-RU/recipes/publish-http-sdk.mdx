# Создание и публикация SDK [#publish-an-http-sdk-without-hiding-execute]

SDK на базе Defjs объединяет общие модели `struct` (`src/models/`) и предметные модули операций (`src/services/`) в поддерживающий tree-shaking npm-пакет, оставляя `createClient(...)`, эндпоинты, учётные данные и перехватчики на стороне использующего приложения.

В отличие от устаревших генераторов OpenAPI, которые оборачивают эндпоинты в хранящие состояние классы `Service` (`ObjectsService.putObject(...)`), Defjs SDK экспортирует **отдельные чистые функции операций** (`putObject`, `getObject`, `listObjectsV2`), вызываемые напрямую с клиентом приложения.

---

## 1. Структура и определение пакета SDK

На примере совместимого с Amazon S3 SDK объектного хранилища (`@company/s3-sdk`) разделим пакет на два уровня:

- **`src/models/`**: Общие схемы `struct` и типы TypeScript `Infer<typeof ...>` (с одноимёнными экспортами значений и типов, чтобы потребители могли импортировать один идентификатор как для runtime-схем, так и для статических типов).
- **`src/services/`**: Предметные модули, сгруппированные по ресурсам (`buckets.ts`, `objects.ts`). Каждый модуль экспортирует самостоятельные функции `defineRequest`, чей синхронный `builder` распределяет плоский входной объект вызова по `path`, `query`, `headers` и бинарному `body`.

- **Чистые функции, а не классы `Service`**: Каждая операция (`listBuckets`, `listObjectsV2`, `getObject`, `putObject`, `deleteObject`) экспортируется как независимое значение `defineRequest`. Не оборачивайте их в `class` или объект пространства имён — отдельные функции сохраняют соглашение о вызове идентичным `@defjs/core` (`await putObject(client, input)`) и позволяют бандлерам удалять неиспользуемые эндпоинты с помощью tree-shaking при установленном `"sideEffects": false`.
- **Пустые, бинарные и структурированные ответы**: `listBuckets` и `listObjectsV2` декодируют JSON-структуры с маппингом полей через `.alias()`; `getObject` декодирует бинарный `Blob` (`output: struct.blob()`); `putObject`, `headObject` и `deleteObject` опускают `output` для пустых тел ответа, сохраняя при этом доступ к `response.headers` (например, `etag`) в третьем элементе кортежа.
- **Внешняя runtime-зависимость**: `@defjs/core` остаётся `peerDependency`, разделяемой с использующим приложением.

## 2. Сборка и проверка tarball-архива

Соберите `dist/index.js` и `dist/index.d.ts` с помощью `tsdown`, затем проверьте содержимое пакета перед публикацией:

```sh
bun install
bun run build
bun pm pack --dry-run
bun pm pack
```

Убедитесь, что файлы `dist/index.js` и `dist/index.d.ts` включены в tarball-архив.

---

## 3. Использование SDK в приложении

Установите ваш SDK вместе с `@defjs/core`:

```sh
bun add @company/s3-sdk @defjs/core@^0.8.0
```

Поскольку SDK не привязывает клиент, использующее приложение само управляет эндпоинтом (AWS S3, Cloudflare R2 или MinIO), перехватчиком подписи запросов и политикой повторов, вызывая каждую импортированную операцию напрямую как чистую функцию:

## 4. Тестирование и публикация

Проверьте экспортированные определения с помощью [тестов с хэндлами в памяти](/ru-RU/recipes/test-with-handle), охватывающих маппинг пути/query-параметров/заголовков/бинарного тела, декодирование `output`, заголовки ответа `ETag`, объявленные сбои `HTTP_STATUS` (`S3Error`) и отмену. После успешной проверки опубликуйте пакет:

```sh
bun publish --access public
```

См. разделы [HTTP-операции](/ru-RU/docs/http), [Клиент](/ru-RU/docs/client), [Тестирование](/ru-RU/docs/testing) и [Архитектура ядра](/ru-RU/docs/design-decisions).
