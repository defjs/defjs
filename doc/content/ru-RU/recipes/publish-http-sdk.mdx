# Создание и публикация SDK [#опубликуй-http-sdk-не-пряча-execute]

SDK на Defjs публикует переиспользуемые эндпоинты API. Автор задаёт входные данные, их размещение в запросах и контракты ответов; приложение импортирует эндпоинты, настраивает свой клиент и обрабатывает результаты. Рецепт проводит путь от модуля эндпоинтов до проверяемого npm-архива и его импорта в приложение.

## 1. Экспортируй эндпоинт

Создай каталог пакета `users-sdk` и сохрани определение в `src/users.ts`. Модуль экспортирует `getUser`; он не создаёт заранее настроенный клиент приложения и не запускает запросы.

`output` описывает тело 2xx, а `error` — тело остальных статусов. Приложение может обработать объявленный `404` по `error.code` и `error.status` и прочитать типизированный `error.data`. Результат `client.execute(...)` сохраняет эту информацию.

## 2. Задай точку входа пакета и сборку

Экспортируй публичный API через `src/index.ts`. Суффикс `.js` соответствует ESM-выводу TypeScript с `NodeNext`; исходный файл по-прежнему называется `users.ts`.

```ts title="src/index.ts"
export { getUser } from "./users.js";
```

Создай следующий `package.json` в каталоге пакета. Перед публикацией замени `@company` своим scope в npm. `@defjs/core` указан как peer-зависимость, чтобы SDK и приложение использовали совместимую версию среды выполнения. Зависимости разработки обеспечивают локальную сборку и проверку типов.

```json title="package.json"
{
  "name": "@company/users-sdk",
  "version": "0.1.0",
  "type": "module",
  "sideEffects": false,
  "files": ["dist"],
  "exports": {
    ".": {
      "types": "./dist/index.d.ts",
      "default": "./dist/index.js"
    }
  },
  "scripts": {
    "build": "tsc -p tsconfig.json"
  },
  "peerDependencies": {
    "@defjs/core": "^0.4.0"
  },
  "devDependencies": {
    "@defjs/core": "^0.4.0",
    "typescript": "^7.0.2"
  }
}
```

`files` ограничивает файлы SDK каталогом `dist`; npm также может включить метаданные пакета, README и лицензию. `exports` предоставляет JavaScript и декларации типов через одну точку входа. `sideEffects: false` подходит этому модулю, поскольку он только экспортирует определения.

```json title="tsconfig.json"
{
  "compilerOptions": {
    "target": "ES2022",
    "module": "NodeNext",
    "moduleResolution": "NodeNext",
    "lib": ["ES2022", "ESNext.Disposable", "DOM", "DOM.Iterable"],
    "strict": true,
    "declaration": true,
    "rootDir": "src",
    "outDir": "dist"
  },
  "include": ["src/**/*.ts"]
}
```

DOM-типы нужны публичным Web API Defjs; `ESNext.Disposable` добавляет типы освобождения ресурсов. Эти значения `lib` не устанавливают полифиллы для среды выполнения.

## 3. Собери и проверь пакет

В каталоге `users-sdk` выполни:

```sh
npm install
npm run build
npm pack --dry-run
npm pack
```

Проверь, что предварительный список включает `dist/index.js`, `dist/index.d.ts`, `dist/users.js` и `dist/users.d.ts`. Для имени из примера последняя команда создаст `company-users-sdk-0.1.0.tgz`. Так можно проверить фактически упакованные файлы из другого приложения. Перед публикацией [тест с локальным Fetch handler](/ru-RU/recipes/test-with-handle) должен проверить контракты успешного ответа и ошибки.

Также проверь один экспортируемый эндпоинт с двумя клиентами, у которых разные адреса сервиса и учётные данные. В отдельном проекте-потребителе проверь и типы, и выполнение кода из архива. Учти отмену и закрытие ресурсов потоковых API. В README SDK опиши API сервиса, совместимые версии Core и ожидаемую аутентификацию.

## 4. Подключи SDK в приложении

Установи архив и совместимую версию Defjs в отдельное ESM-приложение. Измени относительный путь под свою структуру каталогов:

```sh
npm install ../users-sdk/company-users-sdk-0.1.0.tgz @defjs/core@^0.4.0
```

Приложение импортирует точку входа пакета:

```ts
import { getUser } from "@company/users-sdk";
```

Исполняемый пример документации ниже использует относительный импорт `./users-sdk.ts`, поскольку оба файла находятся в каталоге примера. Для проверки npm-пакета замени только этот импорт на указанный выше. Клиент и локальный Fetch handler остаются в коде приложения.

Сохрани приложение как `app.ts` и запусти `bun app.ts` либо `node app.ts` с версией Node.js из [быстрого старта](/ru-RU/docs/start). Локальный handler позволяет выполнить тест без запущенного сервиса. Для реального API приложение убирает `withHTTPHandle(...)` и настраивает базовый URL, аутентификацию и перехватчики на своём клиенте. Обработка кортежей результата и отмена по-прежнему остаются в приложении.

## 5. Опубликуй в npm

Когда scope, имя, версия и архив проверены, а npm-аккаунт имеет право публикации в этом scope, выполни из каталога пакета:

```sh
npm publish --access public
```

После этого приложения устанавливают пакет командой `npm install @company/users-sdk @defjs/core@^0.4.0`. Изменения входных и выходных данных, ошибок и размещения параметров в запросе учитываются в версии контракта SDK. Эндпоинты Defjs по-прежнему выполняются клиентом Defjs; экспорт пакета не меняет этот контракт.

Фабрики клиентов и вспомогательные методы — необязательные дополнения. Они могут предоставлять настройки сервиса по умолчанию или доменное поведение, принимать конфигурацию вызывающей стороны и сохранять прямые экспорты эндпоинтов. Документируй преобразование ошибок и правила жизненного цикла, которые они добавляют. Для переиспользуемого SDK фабрика не обязательна.

См. [команды](/ru-RU/docs/commands), [клиент](/ru-RU/docs/client) и [проектные решения](/ru-RU/docs/design-decisions).
