# Создание и публикация SDK [#publish-an-http-sdk-without-hiding-execute]

SDK упаковывает API, который предлагает твоя группа. С Defjs экспортируй определения эндпоинтов и их контракты данных; приложения-потребители задают настройку клиента и решают, когда их вызывать. В этом рецепте HTTP, и та же граница пакета работает для определений SSE и WebSocket.

## 1. Опиши операции SDK

Создай `src/users.ts` в проекте SDK. Пути, размещение входа, ответы и ошибки сервиса держи здесь. Чтобы описать эту операцию, не нужны экземпляр клиента, адрес развёртывания и текущие учётные данные.

<include cwd meta='title="src/users.ts"'>
  examples/recipes/publish-http-sdk/users-sdk.ts#example
</include>

Открой её из `src/index.ts`:

```ts
export { getUser } from "./users";
```

Добавляй другие модули операций и реэкспортируй их эндпоинты, когда SDK растёт.

## 2. Упакуй JavaScript и декларации

У проекта SDK своя граница пакета:

```txt
users-sdk/
  package.json
  tsconfig.json
  src/
    index.ts
    users.ts
```

Используй этот `package.json`, заменив имя из примера на scope пакета, которым владеешь:

```json
{
  "name": "@company/users-sdk",
  "version": "0.1.0",
  "type": "module",
  "sideEffects": false,
  "files": ["dist"],
  "exports": {
    ".": {
      "types": "./dist/index.d.ts",
      "default": "./dist/index.js"
    }
  },
  "scripts": {
    "build": "tsdown --platform neutral"
  },
  "peerDependencies": {
    "@defjs/core": "^0.5.0"
  },
  "devDependencies": {
    "@defjs/core": "^0.5.0",
    "tsdown": "^0.23.3",
    "typescript": "^7.0.2"
  }
}
```

Core остаётся внешней runtime-зависимостью, общей с приложением. Диапазон peer говорит, какие выпуски Core поддерживает SDK; dev-зависимость позволяет собирать и тестировать против этого диапазона. Пример соответствует текущему контракту `0.4.x`. Перед публикацией выбери и проверь диапазон для своего SDK; от него зависят и декларации, и поведение в рантайме.

Добавь `tsconfig.json`:

```json
{
  "compilerOptions": {
    "target": "ES2022",
    "module": "ESNext",
    "moduleResolution": "bundler",
    "lib": ["ES2022", "ESNext.Disposable", "DOM", "DOM.Iterable"],
    "strict": true,
    "noEmit": true
  },
  "include": ["src/**/*.ts"]
}
```

Эти декларации библиотек дают типы, а не полифиллы рантайма. Приложению по-прежнему нужны Web API выбранных транспортов.

`tsdown` собирает точку входа в `dist/index.js` и выпускает `dist/index.d.ts`.

Собери пакет и посмотри его:

```sh
bun install
bun run build
bun pm pack --dry-run
bun pm pack
```

Проверь, что tarball содержит `dist/index.js` и `dist/index.d.ts`. Установи этот tarball в отдельное приложение и проверь и типы, и выполнение до публикации. README SDK должен описывать API сервиса, совместимые версии Core, ожидаемую аутентификацию и любые необязательные значения по умолчанию.

## 3. Вызови из приложения-потребителя

Локальный пример держит определение в `users-sdk.ts` рядом с `app.ts`, чтобы его можно было запустить без сети. Импорт не создаёт клиент; приложение настраивает локальный Fetch handle и вызывает импортированную операцию:

<include cwd meta='title="app.ts"'>
  examples/recipes/publish-http-sdk/app.ts#example
</include>

```txt
Ada
```

Для упакованного SDK установи его вместе с совместимым выпуском Core:

```sh
bun add @company/users-sdk @defjs/core@^0.5.0
```

Замени относительный импорт из примера на:

```ts
import { getUser } from "@company/users-sdk";
```

Настрой адрес сервиса и аутентификацию на клиенте приложения. Оставь `withHTTPHandle(...)` для локальных тестов; убери его, чтобы использовать платформенный Fetch. Второе приложение может импортировать тот же эндпоинт и выбрать другие настройки клиента, не меняя определение SDK.

## 4. Проверь и опубликуй

[Тестами на локальном клиенте](/ru-RU/recipes/test-with-handle) прогони экспортированное определение, размещение запроса, проверку ответа и объявленные ошибки. Проверь тот же эндпоинт двумя клиентами, настроенными на разные адреса сервиса и учётные данные. Оставь типизированную обработку `HTTP_STATUS` на месте вызова и проверь отмену и очистку потоков для транспортов, которые экспортирует SDK.

Когда пакет прошёл проверки, публикуй из каталога SDK своим аккаунтом npm:

```sh
bun publish --access public
```

Эта команда публикует публичный пакет. Для приватного SDK используй реестр и политику доступа своей организации. Defjs не генерирует и не публикует пакет за тебя.

Фабрики клиентов и удобные методы — необязательные добавки. Они могут давать значения сервиса по умолчанию или доменное поведение, принимая настройку вызывающего и сохраняя прямой экспорт эндпоинтов. Документируй любой маппинг ошибок или политику жизненного цикла, которые они вводят. Для переиспользуемого SDK ни то ни другое не обязательно.

Контракты под этим смотри в [HTTP](/ru-RU/docs/http), [Клиент](/ru-RU/docs/client) и [Проектные решения](/ru-RU/docs/design-decisions).
