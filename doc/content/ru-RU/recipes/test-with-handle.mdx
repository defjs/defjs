# Тест с локальным Fetch-хэндлом

### Три важные детали при написании тестов

- **Зачем оборачивать `(input, init)` в `new Request(input, init)`**: `withHTTPHandle` получает стандартную сигнатуру `fetch(input, init)`, а `new Request(input, init)` даёт единый доступ к `method`, `url`, `headers` и `await request.json()`.
- **Зачем передавать `withEndpoint("https://fixture.invalid")`**: `createClient` проверяет базовый URL до вызова `withHTTPHandle`; домен `.invalid` зарезервирован по RFC и никогда не уйдёт в реальный DNS.
- **Как смоделировать три основных исхода HTTP**:
  - Успех `2xx`: вернуть `Response.json(...)` -> `[null, data, response]`
  - Ошибка `4xx` / `5xx`: вернуть `Response.json(..., { status: 422 })` -> `err.code === "HTTP_STATUS"`
  - Сбой сети: отклонить промис или бросить ошибку (`Promise.reject(new TypeError("fetch failed"))`) -> `err.code === "NET_UNREACHABLE"`. **Не** возвращайте `Response.error()`, так как любой `Response` (даже со статусом `0`) считается HTTP-ответом (`HTTP_STATUS`).

В продакшене вызывайте ту же операцию `getOrder` с клиентом, настроенным через `withEndpoint(...)`. См. [Тестирование](/ru-RU/docs/testing) и [Клиент](/ru-RU/docs/client).
