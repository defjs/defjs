# Однократное обновление Bearer-токена при 401

В Defjs вызов `next(request)` передаёт управление внутрь оставшейся цепочки перехватчиков — он не перезапускает конвейер с самого внешнего перехватчика. Поместите установку токена, дедупликацию параллельных запросов на обновление (single-flight) и однократный повтор запроса при `401` внутрь **одного** HTTP-перехватчика, чтобы внешние перехватчики логирования или замера времени не выполнялись дважды:

```ts
import { createHttpInterceptor } from "@defjs/core";

export type Credential = { accessToken: string };

export function refreshingBearer(
  read: () => Credential,
  refresh: (stale: Credential) => Promise<Credential>,
) {
  let flight: Promise<Credential> | undefined;

return createHttpInterceptor(async (request, next) => {
const authorize = (credential: Credential) => {
const headers = new Headers(request.headers);
headers.set("authorization", `Bearer ${credential.accessToken}`);
return { ...request, headers };
};

    const used = read();
    const response = await next(authorize(used));
    const body = response.body;
    if (
      (typeof ReadableStream !== "undefined" &&
        request.body instanceof ReadableStream) ||
      response.status !== 401 ||
      typeof body !== "object" ||
      body === null ||
      !("code" in body) ||
      body.code !== "expired_token"
    ) {
      return response;
    }

    const current = read();
    if (current.accessToken !== used.accessToken) {
      return next(authorize(current));
    }

    flight ??= refresh(used).finally(() => {
      flight = undefined;
    });
    const refreshed = await flight;
    return next(authorize(refreshed));

});
}

````

Возможность повторить тело не означает, что можно повторить бизнес-операцию. Этот перехватчик также повторно отправляет JSON `POST` после подходящего ответа 401: две HTTP-доставки, сначала отклонённая, затем принятая. Используйте его для записей, только если аутентификация отклоняет первую доставку до запуска бизнес-обработчика; сохраняйте стабильный ключ идемпотентности в обеих доставках и используйте серверную дедупликацию. Если такого контракта нет, верните 401 вместо автоматического повтора записи. Полный пример не повторяет тело запроса `ReadableStream`.

См. раздел [Перехватчики](/ru-RU/docs/interceptors) для изучения луковичной модели вызовов и границ повторных попыток.
