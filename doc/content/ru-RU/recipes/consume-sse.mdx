# Чтение SSE-потока

Каждый `EventStreamHandle` предоставляет ровно один асинхронный итератор. Всегда помещайте `stream.close(...)` и `await stream.closed` в блок `finally`, чтобы ранний выход через `break` или `return` не приводил к утечке базового Fetch-потока:

<Tabs items={["sdk/deployments.ts", "app/main.ts", "deploy-events.ts"]}>
  <Tab value="sdk/deployments.ts">
```ts
import { defineEventStream, struct } from "@defjs/core";

export const deployEvents = defineEventStream({
  path: "/deployments/events",
  events: {
    line: struct.object({ text: struct.string() }),
  },
});
```
  </Tab>
  <Tab value="app/main.ts">
```ts
import { createClient, withEndpoint } from "@defjs/core";
import { deployEvents } from "../sdk/deployments.ts";

const client = createClient(withEndpoint("https://api.example.com"));

async function main() {
const [error, stream] = await deployEvents(client);
if (error) {
console.error(error.code);
return;
}
try {
for await (const event of stream) {
if (event.event === "line") {
console.log(event.data.text);
break;
}
}
} finally {
stream.close("consumer-finished");
await stream.closed;
}
}

void main();

````

Если сервер отправляет первым событие `line` с данными `{ "text": "build started" }`, скрипт выведет:

```txt
build started
````

- SSE не выполняет автоматических переподключений при сбоях сети или чтения, пока вы не настроите [`withSSEReconnect(...)`](/ru-RU/api/core/withssereconnect) на клиенте.
- При включении `withSSEReconnect` с объектом опций параметр `attempts` по умолчанию равен `3` на каждый сбой и сбрасывается при успешном хэндшейке (`attempts: 0` отключает переподключение). Без пользовательского колбэка `shouldReconnect` повторно подключаются только запросы `GET`, `HEAD`, `OPTIONS`, `PUT` и `DELETE` с повторяемым телом. См. раздел [Потоки событий SSE](/ru-RU/docs/sse).
