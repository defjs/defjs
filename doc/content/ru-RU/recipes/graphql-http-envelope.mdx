# Разбор HTTP-ответа GraphQL

В Defjs нет встроенного клиента GraphQL или встроенной политики `errorPolicy`. Моделируйте GraphQL поверх HTTP как стандартную операцию `POST`, чей `builder` отправляет `{ query, operationName, variables }`. Пометьте `data` как `.nullish()` в Struct-оболочке, чтобы как пропущенное `data`, так и `data: null` успешно проходили структурную валидацию, а затем распаковывайте `errors[]` во вспомогательной функции приложения:

- Статус HTTP `200` означает лишь то, что конверт GraphQL успешно доставлен. Доменные ошибки внутри `errors[]` (даже в сочетании с `data: null`) являются результатами уровня приложения, а не ошибками `RES_STRUCT_MISMATCH`.
- См. раздел [Архитектура ядра](/ru-RU/docs/design-decisions), где объясняется, почему протокольные конверты распаковываются во вспомогательных функциях приложения.
