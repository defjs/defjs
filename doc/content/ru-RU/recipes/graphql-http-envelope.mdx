# Разбор HTTP-ответа GraphQL

В Defjs нет встроенного клиента GraphQL или встроенной политики `errorPolicy`. Моделируйте GraphQL поверх HTTP как стандартную операцию `POST`, чей `builder` отправляет `{ query, operationName, variables }`. Пометьте `data` как `.nullish()` в Struct-оболочке, чтобы как пропущенное `data`, так и `data: null` успешно проходили структурную валидацию, а затем распаковывайте `errors[]` во вспомогательной функции приложения, которая возвращает error-first кортеж `Promise<[Error, undefined] | [null, Viewer | null]>`, чтобы вызывающий код обрабатывал один `err`, будь то сбой Defjs или ошибка GraphQL:

- Статус HTTP `200` означает лишь то, что конверт GraphQL успешно доставлен. Доменные ошибки внутри `errors[]` (даже в сочетании с `data: null`) являются результатами уровня приложения, а не ошибками `RES_STRUCT_MISMATCH`. Вспомогательная функция возвращает их как собственный `Error` (сообщения объединяются) и возвращает любой сбой Defjs из единственного вызова как есть. Она никогда не выбрасывает исключение и не возвращает `undefined` как признак сбоя.
- См. раздел [Архитектура ядра](/ru-RU/docs/design-decisions), где объясняется, почему протокольные конверты распаковываются во вспомогательных функциях приложения.
