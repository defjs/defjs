# Клиент

`createClient(...)` возвращает [`DerivableClient`](/ru-RU/api/core/derivableclient-type). Составляйте опции клиента слева направо, затем вызывайте `client(options?)`, чтобы получить значение [`Client`](/ru-RU/api/core/client-type), и передай его операции: `getOrder(client(options), input)`.

## createClient()

<ApiSignature name="createClient" />

Опции применяются по порядку. Клиент лучше создавать внутри границы запроса, если перехватчики захватывают учётные данные аутентификации или контекст арендаторов. Возвращённая фабрика — функция. Её вызов возвращает значение `Client` и не делает I/O. Сама фабрика тоже является `Client` и не несёт опций запроса.

- **options** — хелперы вроде `withEndpoint`.
- **Возвращает** вызываемую фабрику. Базовая конфигурация общая для каждого значения клиента и во время выполнения не заморожена. Она фиксирована по соглашению: библиотека её не меняет, и приложению тоже не следует.

## Хелперы опций

Все хелперы возвращают `ClientOption`. Более поздний вызов заменяет более ранний для той же настройки, кроме `withInterceptors`: он дописывает.

### withEndpoint()

<ApiSignature name="withEndpoint" />

Копирует базовые URL-кандидаты в порядке первого появления и отбрасывает более позднюю копию той же строки. Более поздний `withEndpoint` заменяет список. Он не проверяет URL и не заменяет балансировщик. Пустой список допустим и завершает вызов с `REQ_BUILD_FAILED`.

### withBalancer()

<ApiSignature name="withBalancer" />

Заменяет балансировщик для последующих вызовов. Объект хранится по ссылке. Без этой опции каждый клиент получает свой `pickFirstBalancer()`.

### withInterceptors()

<ApiSignature name="withInterceptors" />

Добавляет перехватчики в порядке регистрации. Перехватчики разных видов фильтруются по транспорту, когда выполняется операция.

### withQuerySerializer()

<ApiSignature name="withQuerySerializer" />

Заменяет кодирование query для HTTP, SSE и WebSocket. `serializer(query)` получает **уже закодированный сетевой объект** (алиасы применены, `Date` как ISO, `bigint` как строка) и должен вернуть строку запроса без ведущего `?`. Он не вызывается, когда у запроса нет query. Builder, возвращающий `URLSearchParams`, его пропускает.

### withHeaders()

<ApiSignature name="withHeaders" />

Задаёт статические заголовки по умолчанию для HTTP- и SSE-запросов. WebSocket-запросы их не используют. `headers` копируется в момент применения опции, поэтому последующие правки объекта до клиента не доходят. Второй `withHeaders` заменяет первый, а не сливается с ним.

Приоритет для одного запроса:

1. Значения по умолчанию — начальный набор заголовков.
2. `headers`, которые вернул builder запроса, заменяют заголовок по умолчанию с тем же именем. Первое значение этого имени заменяет значение по умолчанию; следующие значения того же массива добавляются только к этой замене. Скаляр или экземпляр `Headers` тоже заменяет. Остальные имена по умолчанию остаются.
3. Перехватчики получают объединённые заголовки и могут их менять.
4. С `@defjs/core/xsrf` XSRF-заголовок добавляется последним и только если его ещё нет (см. `withXSRF`).

Для значений, которые меняются от запроса к запросу, используйте перехватчик: обновлённый Bearer-токен или HMAC по сериализованному телу.

Дедлайна по умолчанию на уровне клиента нет. Передайте `signal: AbortSignal.timeout(ms)` через производный клиент, когда он нужен одному вызову. Ручной abort — `NET_ABORTED`. `AbortSignal.timeout` классифицируется как `NET_TIMEOUT`.

### withCredentials()

<ApiSignature name="withCredentials" />

Если `true`, Fetch ставит `credentials: 'include'` для HTTP и SSE. По умолчанию выключено. Соединения WebSocket это не затрагивает.

### withXSRF()

<ApiSignature name="withXSRF" />

Добавляет в браузерные HTTP-запросы заголовок с XSRF-токеном. Импортируйте его из `@defjs/core/xsrf`. `options` — это значение `XSRFOptions`: `cookieName` (по умолчанию `XSRF-TOKEN`) и `headerName` (по умолчанию `X-XSRF-TOKEN`). Вызов `withXSRF()` без аргумента включает эти значения по умолчанию и бросает ошибку, если нет `location` или `document`, в том числе в Worker. Изоморфный код добавляет этот параметр только в браузере. Токен из другого источника задаётся интерцептором. Запросы SSE и WebSocket это не затрагивает.

Заголовок устанавливается, когда выполняется всё перечисленное: метод не `GET`, `HEAD`, `OPTIONS` и не `TRACE`; у запроса ещё нет такого заголовка; origin итогового URL запроса равен origin страницы; и в `document.cookie` есть непустой токен. Запросы с другим origin не читают cookie. Исключение при чтении cookie считается отсутствием токена. Пустой токен не задаёт заголовок.

## Типы

### DerivableClient

<ApiSignature name="DerivableClient" />

Корневой клиент, который возвращает `createClient`, в двух видах. Фабрика — функция и одновременно `Client` без опций запроса, поэтому `getOrder(client, input)` работает напрямую. Её вызов с [`RequestOptions`](/ru-RU/api/core/requestoptions-type) возвращает обычное значение `Client` для одного вызова. Это значение не вызываемое: `client()()` не компилируется, а во время выполнения бросает `TypeError`. Вывод происходит один раз, из фабрики; цепочки нет. Записывайте тип как `DerivableClient`, а не `ReturnType<typeof createClient>`.

### Client

<ApiSignature name="Client" />

`Client` — значение, а не функция. Его возвращает вызов [`DerivableClient`](/ru-RU/api/core/derivableclient-type) с [`RequestOptions`](/ru-RU/api/core/requestoptions-type). `client()` и `client(undefined)` не сохраняют опции запроса. `client({})` оставляет пустой снимок. Вызов читает каждое поле верхнего уровня один раз. Массив `protocols` копируется. `heartbeat` и `reconnect` копируют свои известные поля. Отсутствующие вложенные блоки остаются отсутствующими. `signal`, `beforeConnect` и колбэки сохраняют свою идентичность. Геттер на захваченном поле выполняется во время этого вызова и, если бросает, выходит из вызова. Недопустимые числа по-прежнему позже завершаются `REQ_OPTIONS_INVALID`. Вывод не делает I/O. Значение клиента не вызываемое: его вызов не компилируется, а во время выполнения бросает `TypeError`. Создавайте значение клиента на каждый вызов. Одно и то же значение можно передать многим операциям, но повторное использование значения с `signal` делит этот сигнал между вызовами. `signal` не объединяется; объединяйте сигналы через `AbortSignal.any` в коде приложения. Базовая конфигурация фабрики остаётся общей и не заморожена. Стандартные хелперы `with*` копируют принадлежащие им фиксированные записи при применении.

Не передавайте фабрику в сеттер состояния React (`setState(factory)` вызовет её как функцию-обновление) и не используйте её как источник Vue `watch` или `computed` (они вызывают функцию).

### RequestOptions

<ApiSignature name="RequestOptions" />

Семь плоских полей. Каждый протокол читает поля, которые понимает, и игнорирует остальные. Передача `heartbeat` в HTTP означает, что поле игнорируется, а не что это сбой. `client(options)` при этом вызове копирует массив `protocols` и известные поля `heartbeat` и `reconnect`. Отсутствующие вложенные блоки остаются отсутствующими. `signal`, `beforeConnect` и колбэки сохраняют свою идентичность. SSE читает из опций запроса только `signal`. Переподключение SSE берётся из конфигурации клиента (`withSSEReconnect`), поэтому `client({ reconnect })` влияет только на WebSocket. Фильтра протокола на этапе компиляции нет, и полей `timeout` или `abort` нет.

| Поле                 | Протокол              | Замена                                                                                     |
| -------------------- | --------------------- | ------------------------------------------------------------------------------------------ |
| `signal`             | HTTP, SSE и WebSocket | Прерывает вызов. Для SSE и WebSocket покрывает всё соединение, в том числе после открытия. |
| `onUploadProgress`   | HTTP                  | Другие протоколы игнорируют.                                                               |
| `onDownloadProgress` | HTTP                  | Другие протоколы игнорируют.                                                               |
| `beforeConnect`      | WebSocket             | Заменяет настройку клиента для этого вызова.                                               |
| `protocols`          | WebSocket             | Заменяет список клиента.                                                                   |
| `heartbeat`          | WebSocket             | Заменяется целиком. `timeoutMs` — ожидание подтверждения, а не дедлайн запроса.            |
| `reconnect`          | WebSocket             | Заменяется целиком.                                                                        |

[`HttpExecuteOptions`](/ru-RU/api/core/httpexecuteoptions-type) — срез HTTP (`signal` плюс прогресс). [`EventStreamExecuteOptions`](/ru-RU/api/core/eventstreamexecuteoptions-type) — это `{ signal? }`. [`WebSocketExecuteOptions`](/ru-RU/api/core/websocketexecuteoptions-type) — срез WebSocket плюс `signal`.

### FetchHandle

<ApiSignature name="FetchHandle" />

Сигнатура вызова, которая нужна Defjs от реализации Fetch. Это не `typeof fetch`, поэтому моку не нужны хостовые добавки вроде `preconnect`. Обработчики HTTP/SSE по умолчанию получают `globalThis.fetch` при каждом вызове. HTTP передаёт `(url, init)` только неизменённой платформенной реализации Fetch; заменённая глобальная функция и пользовательские обработчики получают `Request`. SSE всегда передаёт `Request`. Core можно импортировать без Fetch; если Fetch отсутствует и при выполнении, обработчик по умолчанию возвращает `ENV_UNSUPPORTED`, а пользовательские обработчики по-прежнему доступны.

### ClientSSEOptions

### ClientWebSocketOptions

<ApiSignature name="ClientSSEOptions, ClientWebSocketOptions" />

Переподключение включается явно для обоих транспортов: без `withSSEReconnect` / `withWebSocketReconnect` повторов нет. Когда `reconnect` задан, действуют такие значения по умолчанию:

| Поле         | SSE                 | WebSocket           |
| ------------ | ------------------- | ------------------- |
| `attempts`   | `3` на каждый обрыв | `3` на каждый обрыв |
| `delayMs`    | `1000`              | `1000`              |
| `factor`     | `1`                 | `2`                 |
| `jitter`     | `0`                 | `0`                 |
| `maxDelayMs` | без лимита          | `30000`             |

`connectTimeoutMs` необязателен и должен быть конечным, положительным и не больше 2147483647 (предел таймера); иначе операция возвращает `REQ_OPTIONS_INVALID`. Он ограничивает Fetch до заголовков ответа у SSE и конструирование до `open` у WebSocket; после хэндшейка он сбрасывается. Истечение сообщает балансировщику `NET_UNREACHABLE`, чтобы переподключение могло выбрать следующий эндпоинт. Исчерпание повторов заканчивается `NET_TIMEOUT`. Он существует только внутри параметров переподключения, и так как при наличии этого объекта `attempts` по умолчанию равен `3`, один `connectTimeoutMs` тоже включает переподключение. Чтобы ограничить только хэндшейк, задайте ещё и `attempts: 0`.

Для обоих транспортов успешное установление соединения сбрасывает бюджет повторов для текущего обрыва, номер попытки в колбэке и показатель степени для задержки. `attempts: 0` отключает повторы; отсутствие `attempts` не означает неограниченные повторы в пределах одного обрыва. `maxDelayMs` ограничивает итоговую задержку после случайного отклонения и округления; действует также предел платформенного таймера `2_147_483_647` мс, даже если для SSE не задан собственный предел. Нулевая базовая задержка остаётся нулевой; при переполнении вычисления из допустимых чисел задержка ограничивается указанными пределами.

Настройки переподключения проверяются до обращения к транспорту: `attempts` должен быть неотрицательным безопасным целым числом; `delayMs` — конечным неотрицательным числом; `maxDelayMs` — конечным неотрицательным числом или положительной `Infinity`, которая снимает настроенный предел, но не платформенный предел `2_147_483_647` мс для итоговой задержки; `factor` — конечным и положительным; `jitter` — конечным и в пределах 0–1. Недопустимые значения возвращают `REQ_OPTIONS_INVALID`. Для WebSocket `attempts: 0` отключает последующие повторы, но все явно переданные поля переподключения всё равно проверяются до первого подключения, как и в SSE. Jitter масштабирует уже ограниченную базовую задержку в обе стороны, после чего применяется итоговый предел.

Для SSE `delayMs` — лишь начальная базовая задержка: поле `retry:` от сервера, состоящее только из цифр, заменяет её для последующих попыток, в том числе после восстановления соединения. Если `shouldReconnect` возвращает `false`, повторы прекращаются. Колбэк SSE дополнительно получает `lastEventId`, `method` запроса и последнюю информацию `open` и может быть асинхронным. Без этого колбэка SSE переподключается только для запросов `GET`, `HEAD`, `OPTIONS`, `PUT` и `DELETE`; если колбэк задан, его результат определяет, переподключаться ли для каждого метода. Последний ID события передаётся в `Last-Event-ID` как байты UTF-8; пустой ID очищает его, а ID с NUL игнорируется. Колбэк WebSocket вместо этого получает сведения о закрытии: `code`, `reason` и `wasClean`.

SSE `onInvalidEvent` обрабатывает событие, для которого нет подходящего struct, включая отсутствие `default` (`missing-struct`), или чьи данные не проходят свой struct (`validation-failed`). Событие всегда отбрасывается; возвращаемое значение обработчика игнорируется, а брошенная им ошибка поток не закрывает.

Для WebSocket `beforeConnect`, `heartbeat`, `protocols` и `reconnect` можно также передать на выведенном клиенте; каждое значение целиком заменяет значение клиента для этого вызова. `heartbeat.message` строит каждый ping; если он не задан или возвращает `undefined`, ничего не отправляется. `heartbeat.timeoutMs` ждёт подтверждения. Это не дедлайн запроса.

### ClientOptions

<ApiSignature name="ClientOptions" />

Показанные поля — `sse` и `webSocket`. Остальные шесть — `endpoints`, `headers`, `http`, `interceptors`, `querySerializer` и `withCredentials` — наследуются от неэкспортируемой HTTP-базы. `endpoints` — это `readonly string[]`. Готовое значение по умолчанию — `[]`. Пустой массив допустим и завершает вызов с `REQ_BUILD_FAILED`. `timeout` на уровне клиента нет. `createClient` этот объект не принимает; он принимает хелперы опций.

### ClientConfig

Готовый снимок, который изменяют хелперы опций и читает операция: `ClientOptions` после применения значений по умолчанию, где `http.handle`, `interceptors`, `sse` (`ClientSSEConfig`), `webSocket` и `balancer` присутствуют всегда. `http.retry` необязателен и по умолчанию `undefined` (одна попытка, без бюджета); его задаёт `withRetry(options?)`. `balancer` по умолчанию — новый `pickFirstBalancer()` для этого клиента. Это не поле [`RequestOptions`](/ru-RU/api/core/requestoptions-type).

### ClientSSEConfig

## Балансировщики

### pickFirstBalancer()

### roundRobinBalancer()

<ApiSignature name="pickFirstBalancer, roundRobinBalancer" />

`pickFirstBalancer` сдвигается на `NET_UNREACHABLE` или `NET_UNAVAILABLE` (HTTP 502, 503 или 504); повтор HTTP никогда не сдвигает его закреплённый эндпоинт, а порядок следует `members` — полному списку эндпоинтов клиента. Его необязательный положительный конечный `failbackMs` включает одну одновременную пробу первого эндпоинта после интервала; проба решается, когда начинается ответ узла (`end`), а `done` решает пробу, не дошедшую до `end`. Повторы HTTP — отдельная политика клиента, её задаёт `withRetry`. `roundRobinBalancer` идёт по списку. `weights` необязателен. См. [Несколько эндпоинтов](/ru-RU/docs/client#multiple-endpoints).

### p2cBalancer()

<ApiSignature name="p2cBalancer" />

Выбирает разных кандидатов без повторного выбора (в отличие от Envoy/gRPC A48), сравнивая PeakEwma из tower или нагрузку `pending`. Значения по умолчанию Linkerd — RTT 30 мс и decay 10 с. Pending резервируется, когда `pick` выбирает эндпоинт, а `end` отпускает его на заголовках или при открытии сокета и записывает настоящий RTT для каждого транспорта, включая ошибки. `done` без `end` отпускает pending без сэмпла RTT. Нет классификатора ошибок p2c и штрафа. `choiceCount` по умолчанию 2 и ограничен 10.

### outlierDetection()

<ApiSignature name="outlierDetection, OutlierDetectionOptions" />

Оборачивает дочерний балансировщик circuit breaking по последовательным сбоям в стиле Linkerd. Round robin и p2c включают его по умолчанию (как в Finagle); `false` выключает. Pick-first включает его объектом. Классификатор по умолчанию считает сбоем любой исход с кодом, включая `NET_TIMEOUT` и `NET_BODY_INCOMPLETE`; исход попытки без кода сбрасывает серию. После пяти ошибок штрафы начинаются с 1000 мс, удваиваются после неудачной пробы, добавляют положительный jitter до 0,5 базы и ограничены 60000 мс. Истечение допускает одну пробу, решение на `end` или на `done`, если `end` не пришёл. Успех сбрасывает backoff; отмена только освобождает слот. Нет таймаута, засчитывающего успех, квоты, защиты последнего хоста, сетки расчёта, процентного критерия и slow start. `isHealthy` читает кэш приложения и никогда не отменяет штраф. Разорваться может любой хост; локальный для списка fail-open в стиле Finagle всё равно отправляет запросы. В отличие от Envoy/gRPC A50 квоты выброса нет. См. [Фильтрация здоровья и p2c](/ru-RU/docs/client#health-filtering-and-p2c).

### withRetry()

<ApiSignature name="withRetry, RetryOptions, RetryContext, HttpRetryContext, SSERetryContext, WebSocketRetryContext" />

Включает повтор HTTP в рамках одного вызова независимо от выбора эндпоинта. Если опустить `withRetry`, это означает одну попытку и отсутствие бюджета. `withRetry()` эквивалентен `withRetry({})` и по умолчанию задаёт `maxAttempts: 2` (включая исходную), `on: ["connect-failure"]` и безопасные методы `GET`, `HEAD`, `OPTIONS`, `TRACE`. Методы без учёта регистра; `[]` отключает повторы. `maxAttempts` — безопасное целое число не меньше 1, и каждый эндпоинт пробуется не больше одного раза. `"gateway-error"` включает `NET_UNAVAILABLE` (HTTP 502/503/504) и тела шлюза, отклонённые декодированием `RES_*`; `"attempt-timeout"` использует `attemptTimeoutMs`. Потоковые тела запроса никогда не повторяются.

Backoff по умолчанию — `delayMs: 25`, `factor: 2`, `jitter: 0.2`, `maxDelayMs: 250`, с той же семантикой полей, что у переподключения SSE/WebSocket. `delayMs: 0` пропускает ожидание. `attemptTimeoutMs` должен быть конечным, положительным и не больше 2147483647 (предел таймера); иначе операция возвращает `REQ_OPTIONS_INVALID`. Он измеряет каждый Fetch, отправленный на выбранный эндпоинт, от вызова до полного чтения тела ответа; работа перехватчиков вокруг отправки и декодирование структуры не учитываются и никогда не засчитываются против эндпоинта. Сигнал вызывающего покрывает весь вызов, включая ожидания backoff. Если раунд повтора не может использовать ни один эндпоинт (выбор балансировщика не удался или URL следующего эндпоинта не разрешается), вызов возвращает сбой предыдущей попытки вместо `REQ_BUILD_FAILED`.

Клиентский бюджет Finagle по умолчанию — 20 % плюс резерв 10 повторов в секунду на TTL 10 с. И кредиты, и списания лениво истекают в десяти срезах по TTL/10. `budget: false` снимает лимит. Производные клиенты с одной конфигурацией делят её бюджет; разные клиенты — нет, даже с одним общим балансировщиком. Недопустимые опции возвращают `REQ_OPTIONS_INVALID` с `Invalid retry options`, когда выполняется HTTP. Опция фиксирует собственные поля, массивы и вложенный бюджет в момент применения. `withRetry()` и `withRetry(undefined)` ведут себя как `withRetry({})`. Поздний `withRetry` заменяет политику; `withRetry({ maxAttempts: 1 })` выключает повторы после того, как они были включены. У балансировщиков и обёрток здоровья нет настроек повтора. См. [Балансировка нагрузки и отказоустойчивость](/ru-RU/docs/load-balancing).

### Balancer

<ApiSignature name="Balancer, PickOutcome, PickInfo, PickResult, PickFaultCode, DoneInfo, ERR_NO_CANDIDATE, isNoCandidateCause" />

`pick` возвращает кортеж error-first. Необязательный `start` выполняется синхронно не больше одного раза непосредственно перед стартом выбранного транспорта; необязательный `end` выполняется один раз после `start` когда начинается ответ узла (или при сбое до ответа), а необязательный `done` — один раз при завершении. Fetch не может показать первый body-frame Linkerd или границы стрима Envoy. Броски всех хуков сдерживаются; возвращённый промис не ожидается. Выбор вне кандидатов завершается `REQ_BUILD_FAILED`, а его `done` вызывается с `{ attempted: false }`. `ERR_NO_CANDIDATE` — только `cause` у `REQ_BUILD_FAILED`. Это не `FaultCode`. [`isNoCandidateCause`](/ru-RU/api/core/isnocandidatecause) распознаёт его и из другой копии Core.

Балансировщик видит только нейтральные исходы; каждый транспорт переводит свои факты в `DoneInfo.code`. Обнаружение выбросов (`outlierDetection`) по умолчанию считает сбоем любой исход с кодом, включая `NET_TIMEOUT` и `NET_BODY_INCOMPLETE`. Сырой `DoneInfo.status` сохраняется только для пользовательских балансировщиков, и встроенные стратегии его не читают. `PickInfo` содержит кандидатов `endpoints` для одного выбора, `members` (полный список эндпоинтов клиента, одинаковый для всех попыток) и необязательный `operation`, без дискриминатора транспорта.

См. [руководство по клиенту](/ru-RU/docs/client).
