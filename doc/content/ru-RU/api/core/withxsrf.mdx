<ApiReference identity="@defjs/core:withXSRF" />

```ts
function withXSRF(options?: {
  cookieName?: string
  headerName?: string
  tokenProvider?: (context: { request: HttpRequest }) => string | null | undefined
}): ClientOption
```

Включает передачу XSRF-токена для **HTTP**-запросов. Запросы SSE и WebSocket этот заголовок не получают.

- `cookieName` по умолчанию `XSRF-TOKEN`, а `headerName` — `X-XSRF-TOKEN`.
- Заголовок ставится, только когда выполняется всё перечисленное: метод не `GET`, `HEAD`, `OPTIONS` и не `TRACE`; у запроса ещё нет такого заголовка; у клиента есть endpoint; а при наличии `location` (в Window или Worker) итоговый URL запроса имеет тот же origin, что и `location.origin`. Запрос к другому origin не вызывает провайдер.
- Без `tokenProvider` токен читается из `document.cookie` и URL-декодируется только при наличии `document`. В Worker и на сервере токен должен предоставлять провайдер.
- С `tokenProvider` cookie не читается никогда. Провайдер получает запрос, и его результат — токен. Пустая строка, `null` или `undefined` означают отсутствие заголовка.

О поведении на уровне запроса см. [гайд HTTP](/ru-RU/docs/http).
