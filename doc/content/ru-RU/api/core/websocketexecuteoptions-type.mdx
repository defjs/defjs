<ApiReference identity="@defjs/core:WebSocketExecuteOptions" />

```ts
type WebSocketExecuteOptions<TIncoming = unknown, TOutgoing = unknown> = UseWebSocketConfig<TIncoming, TOutgoing> & {
  signal?: AbortSignal
}
```

[`UseWebSocketConfig`](/ru-RU/api/core/usewebsocketconfig-type) плюс `signal`. В развёрнутом виде:

```ts
type WebSocketExecuteOptions<TIncoming = unknown, TOutgoing = unknown> = {
  beforeConnect?: (context: { attempt: number; signal: AbortSignal }) => void | Promise<void>
  heartbeat?: WebSocketHeartbeatConfig<TIncoming, TOutgoing>
  protocols?: readonly string[]
  reconnect?: ClientWebSocketOptions['reconnect']
  signal?: AbortSignal
} & ({ abort?: AbortSignal; timeout?: never } | { abort?: never; timeout?: number })
```

- `abort` и `timeout` взаимоисключающи. Тип отвергает оба сразу, а если передать оба в рантайме, вызов завершится fault’ом `REQ_OPTIONS_INVALID`.
- `signal` сочетается с любым из них; это не алиас `abort`.
- `timeout` должен быть положительным safe integer не больше `2_147_483_647`. Он ограничивает, сколько может занять открытие сессии, и при reconnect заново не применяется.
- `beforeConnect`, `heartbeat`, `protocols` и `reconnect` переопределяют опции уровня клиента для этого вызова.
- Когда `reconnect` задан, `attempts` по умолчанию `3`; `0` отключает. Опустить `attempts` — это не «без лимита».

См. [`WebSocketHeartbeatConfig`](/ru-RU/api/core/websocketheartbeatconfig-type).
