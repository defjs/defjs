<ApiReference identity="@defjs/core:withWebSocketReconnect" />

```ts
function withWebSocketReconnect(options: ClientWebSocketOptions['reconnect']): ClientOption
```

Настраивает автоматический reconnect, когда сокет закрывается по любой причине, кроме ручного `session.close()`. Reconnect включается явно: без этой опции закрытие завершает сессию. Передача `undefined` сбрасывает ранее заданное значение. Тип опции:

```ts
{
  attempts?: number
  delayMs?: number
  factor?: number
  jitter?: number
  maxDelayMs?: number
  shouldReconnect?: (context: { attempt: number; cause?: unknown; code?: number; reason?: string; wasClean?: boolean }) => boolean
}
```

- `attempts` — бюджет повторов для каждого периода недоступности соединения. По умолчанию `3`, а `0` отключает reconnect. Успешный `open` сбрасывает бюджет и показатель степени в расчёте задержки; следующий период недоступности начинается с повтора 1. Отсутствие `attempts` не даёт неограниченных повторов в пределах одного периода недоступности. Сокет, который успешно открывается и сразу снова закрывается сервером, может продолжать reconnect с базовой задержкой (с учётом jitter и пределов), потому что каждое открытие сбрасывает бюджет; останови его через `shouldReconnect`.
- `delayMs` по умолчанию `1000`, `factor` — `2`, `maxDelayMs` — `30000`, `jitter` (от 0 до 1) — `0`. Для повтора _n_ исходная задержка равна `delayMs * factor^(n-1)` с ограничением `maxDelayMs`; затем применяются jitter и округление, после чего итоговая задержка снова ограничивается `maxDelayMs` и `2_147_483_647` мс. Нулевая базовая задержка остаётся нулевой; при переполнении вычислений с допустимыми числами задержка ограничивается этими пределами.
- `shouldReconnect` может вернуть `false`, чтобы вместо этого завершить сессию. Без него каждое закрытие повторяется, пока хватает бюджета. Для ручного `session.close()` он не вызывается.
- При включённых повторах `attempts` должен быть неотрицательным безопасным целым числом; `delayMs` и `maxDelayMs` должны быть конечными и неотрицательными; `factor` — конечным и положительным; `jitter` — конечным и в пределах 0–1. Недопустимые значения приводят к `REQ_OPTIONS_INVALID` до подключения. `attempts: 0` немедленно отключает повторы, а неиспользуемые поля reconnect игнорируются.
- `reconnect` из execute-опций заменяет этот для данного вызова.
