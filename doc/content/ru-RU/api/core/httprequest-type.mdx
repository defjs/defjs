<ApiReference identity="@defjs/core:HttpRequest" />

```ts
interface HttpRequest {
  abort?: AbortSignal
  baseEndpoint?: string
  body?: Blob | ArrayBuffer | FormData | URLSearchParams | ReadableStream<Uint8Array> | object | string | number | boolean | null
  bodyContentType?: string | null
  downloadProgress?: HttpProgressFn
  endpoint: string
  headers?: Headers
  method: string
  operation?: string
  queryParams?: URLSearchParams
  queryString?: string
  readonly responseType?: HttpResponseType
  readonly errorResponseType?: HttpResponseType
  timeout?: number
  uploadProgress?: HttpProgressFn
  withCredentials?: boolean
  xsrf?: {
    cookieName: string
    headerName: string
    tokenProvider?: (context: { request: HttpRequest }) => string | null | undefined
  }
  // plus an @internal bodyContentTypeSource field
}
```

Request после работы builder’а, в том виде, в каком его используют handler’ы, interceptor’ы и `fetchHandler`.

- `body` — уже значение для передачи по сети. Для JSON это **строка с JSON-текстом**; подписывай HMAC или digest именно по этой строке, а не по исходному input struct.
- `endpoint` — path с подставленными path-параметрами; `baseEndpoint` — endpoint клиента.
- Interceptor’ы видят `queryParams` как `new URLSearchParams(queryString)`. Если builder возвращает `URLSearchParams`, этот экземпляр передаётся как есть.
- `operation` — статическая идентичность endpoint’а с низкой кардинальностью для телеметрии и диагностики.
- `downloadProgress` и `uploadProgress` — hook’и `onDownloadProgress` и `onUploadProgress` из `HttpExecuteOptions`.
- `responseType` и `errorResponseType` доступны только для чтения: они выводятся из видов struct’ов `output` и `error` endpoint’а, и менять их нельзя. Каждый задаётся, только если соответствующий struct объявлен. Interceptor, который прерывает цепочку через `makeResponse`, читает их, чтобы совпасть с транспортом.
