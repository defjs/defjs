```ts
function createResolvedRequestUrl(baseEndpoint: string, path: string, queryString?: string): URL
```

- **baseEndpoint** — корректный абсолютный endpoint клиента. Его query и hash отбрасываются, а к pathname добавляется завершающий слэш, чтобы сохранить базовый путь: `https://api.example.com/v1` и `/users` дают `https://api.example.com/v1/users`.
- **path** — относительный путь эндпоинта. Один ведущий слэш удаляется. После разрешения URL должен сохранять origin базового URL и оставаться в пределах его каталога. Абсолютные и протокольно-относительные пути, управляющие символы C0 (включая табуляцию, CR и LF), обратные слэши, `?`, `#` и выход за пределы каталога отклоняются. Похожие на схему и протокольно-относительные формы отклоняются даже с ведущими пробелами; обычный пробел внутри пути разрешён и отправляется как `%20`.
- **queryString** — query без ведущего `?`. Если строка не пуста, она записывается в search URL как есть.
- **Возвращает** разрешённый `URL`.

Выбрасывает `TypeError`, если базовый endpoint или путь некорректен. При `client.execute` отсутствующий, относительный или некорректный базовый URL либо недопустимый путь приводят к `REQ_BUILD_FAILED` до запуска любого interceptor’а или транспорта, включая interceptor, который возвращает ответ без продолжения цепочки. Это одинаково действует для HTTP, SSE и WebSocket. Итоговый `req.endpoint` после interceptor’а также проверяется относительно итогового `req.baseEndpoint`; намеренная замена базового URL на другой корректный абсолютный URL разрешена. Детерминированные ошибки URL никогда не приводят к повторным попыткам.
