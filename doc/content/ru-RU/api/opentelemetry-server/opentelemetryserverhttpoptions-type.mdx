<ApiReference identity="@defjs/opentelemetry-server:OpenTelemetryServerHttpOptions" />

```ts
type OpenTelemetryServerHttpOptions = OpenTelemetryServerTransportOptions<HttpResponse<unknown>>
```

Задаётся в `http` у `OpenTelemetryServerOptions`. Собственных полей у типа нет: `enabled`, `startSpanHook`, `requestHook` и `responseHook` приходят из `OpenTelemetryServerTransportOptions`.

- `responseHook(span, res, req)` получает `HttpResponse`, который вернулся через interceptor, до того как клиент декодирует объявленное тело, вместе с исходным `HttpRequest`. Идентичность запроса читай из `req.operation`; не восстанавливай её из эндпоинта или resolved URL.
- HTTP span завершается, как только `responseHook` вернул управление; hook не ожидается через await, поэтому span ещё может изменить только его синхронная часть. Статус 400 и выше завершает span как `ERROR`, а в `error.type` кладёт строку статуса; 100–399 оставляют статус не заданным. Асинхронный reject hook после завершения передаётся через `diag.error`; для его получения настройте `diag.setLogger(...)` из `@opentelemetry/api`. Добавить события в уже завершённый span нельзя.
- Reject через interceptor (сбой сети, отмена, таймаут или объявленное тело `output` / `error`, которое нельзя прочитать как JSON) не имеет статуса ответа и `responseHook` не вызывает. Span завершается как `ERROR`, а в `error.type` кладётся имя брошенного класса, например `TypeError`, `Error` или `BodyFailure`. Отмена вызывающим — это `Error`, какой бы ни была причина abort.

Передай `{ enabled: false }`, чтобы пропустить HTTP-инструментацию. Hooks для span вызываются только при переданном `tracer`.
