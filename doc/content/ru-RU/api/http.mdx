# HTTP

Объявите типизированный запрос, затем вызовите операцию с клиентом и её `input`.

## defineRequest()

<ApiSignature name="defineRequest" />

- **definition** — `method`, `path`, необязательный `input` struct, необязательные `output` и `error` structs, необязательный `operation`. При объявленном `input` всегда нужен явный `builder`. `input` только описывает параметры; куда пойдёт каждое значение, решает только builder. Опустить `builder` можно только в определениях без `input`. Эти члены `definition` описаны в [`RequestDefinition`](/ru-RU/api/core/requestdefinition-type). `builder` обязателен ровно тогда, когда объявлен `input`.
- **Возвращает** операцию. Вызывайте её как `getOrder(client, input)` или `health(client)`, если `input` не объявлен. Когда весь входной struct необязателен, аргумент `input` можно опустить. Вызов начинает запрос. Третьего аргумента с опциями нет.

<include cwd>examples/api/define-request.ts#example</include>

`output` — один struct для тела `2xx`; `error` — один struct для каждого тела вне `2xx`. Ни то ни другое не
привязано к статусу. Пропустить одну сторону значит, что это тело не читают — см.
[Объявление — это утверждение](/ru-RU/docs/design-decisions#declaration-is-an-assertion).

Вызов операции возвращает promise кортежа, описанного в [`HttpAwaitResult`](/ru-RU/api/core/httpawaitresult-type). Опции одного вызова передавайте, выводя клиент из [`RequestOptions`](/ru-RU/api/core/requestoptions-type). HTTP читает `signal` и колбэки прогресса и игнорирует остальные поля.

Статус вне `2xx` — это `HTTP_STATUS`, если struct `error` не объявлен или объявленное тело `error` декодируется. У сбоя поле `data` — декодированное
тело `error`, если оно было объявлено, иначе `undefined`. Если объявленное тело `error` не удаётся прочитать (неверный тип медиа, невалидный JSON) или
оно не соответствует своему struct, вместо этого возвращается сбой — `RES_MEDIA_TYPE_INVALID`, `RES_DECODE_FAILED` или `RES_STRUCT_MISMATCH`, а статус ответа по-прежнему
указан в его метаданных. При сбое третий слот кортежа — `undefined`; метаданные ответа несёт сбой.

## fetchHandler()

<ApiSignature name="fetchHandler" />

HTTP-транспорт по умолчанию. `fetchImpl` по умолчанию — глобальный `fetch`, получаемый в момент отправки; другой подставляет `withHTTPHandle`. Неизменённая платформенная реализация Fetch получает `(url, init)`, а заменённая глобальная функция и пользовательский обработчик — `Request`. Promise отклоняется, а не разрешается
синтетическим ответом, если ответ не дошёл до клиента или объявленное тело не удалось прочитать.

## makeResponse()

<ApiSignature name="makeResponse" />

Создайте `HttpResponse` без сетевого вызова (в перехватчиках, тестах). `status` по умолчанию — `0`. `ok`
истинен для 2xx. Возвращённое значение проходит ту же проверку типа медиа и тот же объявленный
struct, что и ответ из сети; доверенного short-circuit нет.

## HttpExecuteOptions

<ApiSignature name="HttpExecuteOptions" />

`HttpExecuteOptions` — срез HTTP у [`RequestOptions`](/ru-RU/api/core/requestoptions-type): [`UseRequestConfig`](/ru-RU/api/core/userequestconfig-type), то есть `signal` плюс `onDownloadProgress` и `onUploadProgress`. Полей `timeout` или `abort` нет. Дедлайн — это `signal: AbortSignal.timeout(ms)`, и он классифицируется как `NET_TIMEOUT`. Ручная отмена — `NET_ABORTED`. `signal` — сигнал вызова; объединяйте сигналы через `AbortSignal.any` в коде приложения. Дедлайна по умолчанию на уровне клиента нет. Остальные поля запроса, например `heartbeat`, игнорируются.

## Типы

### RequestDefinition

`method`, `path`, необязательные `input`, `output`, `error`, `operation` и `builder`. Вид struct выбирает, как читать объявленное тело. При объявленном `input` всегда нужен явный `builder`. `input` только описывает параметры; куда пойдёт каждое значение, решает только builder. Опустить `builder` можно только в определениях без `input`.

### HttpAwaitResult

<ApiSignature name="HttpAwaitResult" />

При успехе третий слот несёт `body`, только если был объявлен `output`. При сбое он
`undefined` — сбой уже держит те метаданные ответа, что были.

### HttpRequest

Нормализованный исходящий запрос: `method`, `endpoint`, `headers`, `body`, `signal`, `operation`, `withCredentials`, `finalizeHeaders`, `downloadProgress` / `uploadProgress`, `baseEndpoint`, `queryString` и `queryParams`. К моменту, когда перехватчики его видят, `body` уже имеет сетевое значение — для JSON это строка с JSON-текстом, — поэтому HMAC и дайджесты подписывайте по нему, а не по входному struct. Перехватчики видят `queryParams` как `new URLSearchParams(queryString)`. Builder, который возвращает `URLSearchParams`, передаёт этот же экземпляр. `responseType` и `errorResponseType` только для чтения: они выводятся из видов struct `output` и `error` в определении, и их нельзя менять.

### HttpMeta

<ApiSignature name="HttpMeta" />

Метаданные ответа, доступные, когда ответ дошёл до клиента. `body` тут **нет**: тело
существует, только когда объявленный struct его декодировал.

### DecodedResponse

<ApiSignature name="DecodedResponse" />

Ответ, чьё тело декодировалось против объявленного struct. Держать этот тип — доказательство, что
декодирование случилось; поэтому сбой декодирования сообщает один `HttpMeta`.

### HttpResponse

<ApiSignature name="HttpResponse" />

`body` равен `undefined`, если у ответа не было тела; JSON `null` остаётся `null`. Тип брендирован, поэтому создавайте его через `makeResponse`, а не литералом объекта. Сетевая форма, которую производят транспорты и видят перехватчики: `body` — текст или уже распарсенный JSON, не
декодированное значение. Для JSON-представления строка — это JSON-строка как корень и повторно не парсится; байты
и blob-значения сырые и парсятся один раз. До вызывающего доходит `DecodedResponse`.

### HttpProgressEvent

### HttpProgressFn

`loaded`, `total`, `lengthComputable`. Колбэки могут быть асинхронными. Если `onDownloadProgress` или `onUploadProgress` выбрасывает исключение, вызов завершается с
`EXT_OBSERVER_FAILED`, а выброшенное значение передаётся в `cause`; отмена по-прежнему сообщает `NET_ABORTED`, или `NET_TIMEOUT`, когда причина отмены — таймаут.
Прогресс загрузки превращает тела `Blob` / `File`, `ArrayBuffer` и `FormData` в поток там, где `fetch` поддерживает потоковое тело запроса. Chromium сообщает этот прогресс только на HTTP/2 и новее; на HTTP/1.1 загрузка с `onUploadProgress` завершается ошибкой (`NET_UNREACHABLE`). Firefox отправляет эти тела без изменений и не вызывает `onUploadProgress`.

Там, где выполняется это преобразование, `FormData` использует сериализованный поток без буферизации всего тела в `Blob` и сохраняет фактический разделитель multipart. Полный размер неизвестен, если его не задаёт корректный явный `Content-Length`. Явные типы контента сохраняются при преобразовании загрузки, кроме того что FormData должен использовать разделитель своей сериализации. `loaded` считает байты потока, а не подтверждения сервера. Скачивания с `Content-Encoding`, отличным от `identity`, сообщают `total: 0` и `lengthComputable: false`; байты их потока уже могут быть распакованы.

См. [руководство по HTTP](/ru-RU/docs/http) и [Клиент](/ru-RU/docs/client).

## RequestEndpoint

То, что возвращает `defineRequest`. Первый аргумент — [`Client`](/ru-RU/api/core/client-type). Дальше идёт только `input`.

## BuilderInput

Разобранный `input` операции, который видит `builder`. Узлы-объекты несут struct, который их произвёл, так что кодирование алиаса, `Date` и `bigint` следует за значением.

## HttpRequestShape

<ApiSignature name="HttpRequestShape" />

Все четыре поля необязательны. `query` — это `URLSearchParams` или record; вложенному объекту во время выполнения нужен `withQuerySerializer`. `headers` — это `HeadersInit` или record из скаляров либо массивов скаляров. `path` задаёт по одному скаляру на сегмент `:name`.

`body` для `GET` и `HEAD` равен `never`. Иначе это сетевое значение (`string`, `Blob`, `ArrayBuffer`, typed array или `DataView`, `FormData`, `URLSearchParams` или `ReadableStream<Uint8Array>`) либо JSON-данные (`number`, `boolean`, `bigint`, `Date`, `null`, массив или объект со строковыми ключами).

## UseRequestConfig

`signal` плюс необязательные `onDownloadProgress` и `onUploadProgress`. `HttpExecuteOptions` — этот срез. Полей `timeout` или `abort` нет.

## RequestSuccessData

Выведенное тело успешного ответа из объявленного struct `output`, или `undefined`, если он не объявлен.

## RequestErrorData

Выведенное тело ошибки из объявленного struct `error`, или `undefined`, если он не объявлен.

## HttpResponseType

`'arraybuffer' | 'blob' | 'json' | 'text'`

Выбирается по виду объявленного struct (`string` → `text`, `blob` / `file` → `blob`, `arrayBuffer` → `arraybuffer`, всё остальное → `json`). Это не поле `defineRequest`.

## MakeResponseOptions

Поля для `makeResponse`: `status`, `statusText`, `url`, `headers`, `body`, `request`.
