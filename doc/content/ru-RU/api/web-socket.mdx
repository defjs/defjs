# WebSocket

Объяви сокет, вызови операцию с клиентом, шли и принимай типизированные сообщения, потом закрой.

## defineWebSocket()

<ApiSignature name="defineWebSocket" />

- **definition** — `path`, один struct `incoming` и обязательный `maxIncomingQueueSize` (положительное целое); необязательные structs `outgoing` и `input`, `operation`, статические `protocols` и неотрицательный `maxOutgoingQueueSize`. При объявленном `input` всегда нужен явный `builder`. `input` только описывает параметры; куда пойдёт каждое значение, решает только builder. Опустить `builder` можно только в определениях без `input`. Эти члены `definition` описаны в [`WebSocketDefinition`](/ru-RU/api/core/websocketdefinition-type). `builder` обязателен ровно тогда, когда объявлен `input`.
- **Возвращает** операцию. Первый аргумент — [`Client`](/ru-RU/api/core/client-type). Дальше идёт только input. Вызов открывает сессию.

<include cwd>examples/api/define-web-socket.ts#example</include>

Вызов возвращает `[null, session, connection]` или `[error, undefined, connection?]`. Опции одного вызова передавай, выводя клиент из [`RequestOptions`](/ru-RU/api/core/requestoptions-type). WebSocket читает `abort`, `beforeConnect`, `heartbeat`, `protocols` и `reconnect` и игнорирует поля прогресса HTTP.

`beforeConnect`, `heartbeat`, `protocols` и `reconnect` каждое целиком заменяет значение клиента для этого вызова. Приоритет protocols: выведенный клиент, затем `withWebSocketProtocols`, затем `protocols` определения. `heartbeat.timeoutMs` — ожидание подтверждения, а не дедлайн запроса.

## WebSocketSession

<ApiSignature name="WebSocketSession" />

Для освобождения принадлежащих области видимости ресурсов предпочитай `await using ownedSession = session`. Ручные `session.close()` и `await session.closed` остаются доступны.

```ts
async function consume(
  session: WebSocketSession<unknown, never>,
): Promise<void> {
  await using ownedSession = session;
  for await (const message of ownedSession.receive) console.log(message);
}
```

`closed` сообщает окончательное логическое состояние. Асинхронное освобождение запрашивает нативное закрытие и ждёт освобождения ресурсов, которыми управляет Defjs, но при отсутствии события `close` ограничивает ожидание одной секундой и может завершиться отклонением Promise с `DOMException` с именем `TimeoutError`. Оно не доказывает, что физическое TCP-соединение закрылось.

### WebSocketState

`'idle' | 'connecting' | 'open' | 'closing' | 'closed' | 'reconnecting' | 'aborted' | 'error'`

### WebSocketConnectionInfo

`generation` (растёт на reconnect) и, когда они известны, `url`, `protocol` и `extensions`.

### WebSocketCloseInfo

<ApiSignature name="WebSocketCloseInfo" />

`kind` — это `closed`, `aborted` или `error`. `cause` отсутствует у `closed`, необязателен у `aborted` и обязателен у `error`. `code`, `reason` и `wasClean` могут быть у каждого варианта. Ручной `session.close()` заполняет `code` и `reason` у `{ kind: "closed" }`, если событие close их не несёт.

## WebSocketExecuteOptions

<ApiSignature name="WebSocketExecuteOptions" />

`WebSocketExecuteOptions` — это [`UseWebSocketConfig`](/ru-RU/api/core/usewebsocketconfig-type): `beforeConnect`, `heartbeat`, `protocols`, `reconnect` и `abort`. `WebSocketHeartbeatConfig`: `intervalMs`, необязательные `message`, `isAck`, `timeoutMs`. Полей `timeout` или `signal` нет.

`abort` покрывает всю сессию, в том числе после открытия. Дедлайн — `AbortSignal.timeout(ms)`, и он классифицируется как `NET_TIMEOUT`. Ручной abort — `NET_ABORTED`. Дедлайна только на старт нет, и дедлайна по умолчанию на уровне клиента нет. `abort` — сигнал вызова; объединяй сигналы через `AbortSignal.any` в коде приложения. `heartbeat` заменяется целиком; его `timeoutMs` ждёт подтверждения и не является дедлайном запроса.

Когда задан `reconnect`, `attempts` по умолчанию равен 3 на каждый обрыв; `0` отключает повторы. Успешный `open` сбрасывает бюджет и показатель степени для задержки, поэтому после каждого нового обрыва отсчёт начинается с попытки 1. Отсутствие `attempts` не означает неограниченные повторы в пределах одного обрыва. Значения по умолчанию и правила проверки см. в [Клиент](/ru-RU/api/client).

## Сообщения

`incoming` — один struct. Кадры text, `ArrayBuffer`, typed-array и `Blob` читаются как UTF-8, парсятся как JSON, потом проверяются этим struct. Кадр, который не прошёл JSON parse или struct, сообщается в `session.onRuntimeError` и в очередь не кладётся. Клиентской опции для невалидного кадра нет.

`outgoing` — один struct. `session.send` принимает `StructInput` этого struct, кодирует алиасы, затем вызывает `JSON.stringify`. Значения, которые после кодирования невозможно без искажений представить в JSON, вызывают `TypeError` до отправки или попадания в очередь переподключения: в том числе неконечные числа, функции, символы, `Map`, `Set`, потоки и экземпляры классов без JSON-представления. Вложенные значения проходят ту же проверку, что и HTTP-тела JSON. Heartbeat также использует эту проверку; ошибка сериализации heartbeat завершает сессию. Несколько видов сообщений — это `struct.discriminatedUnion`.

```ts
session.send({ type: "message", text: "Hello" });
```

См. [гайд WebSocket](/ru-RU/docs/web-socket) и [Открыть WebSocket-сессию](/ru-RU/recipes/websocket-session).

## WebSocketDefinition

`path`, `incoming`, обязательный `maxIncomingQueueSize`, необязательные `outgoing` / `input` / `operation` / `protocols` / `maxOutgoingQueueSize`. Builder может вернуть только `path` и `query`. При объявленном `input` всегда нужен явный `builder`. `input` только описывает параметры; куда пойдёт каждое значение, решает только builder. Опустить `builder` можно только в определениях без `input`.

## WebSocketEndpoint

То, что возвращает `defineWebSocket`. Первый аргумент — клиент. Дальше идёт только input.

## WebSocketRequestShape

Только `path` и `query`. `headers` и `body` — `never`.

## UseWebSocketConfig

`beforeConnect`, `heartbeat`, `protocols`, `reconnect` и `abort`. `WebSocketExecuteOptions` — этот срез. Поля `signal` нет.

## SocketAwaitResult

`[null, session, connection]` или `[error, undefined, connection?]`.

## ManualSocketCloseReason

Причина, записанная при закрытии сессии через `session.close()`.

## WebSocketHeartbeatConfig

`intervalMs`, необязательные `message`, `isAck`, `timeoutMs`.

## WebSocketIncomingData

Декодированный входящий кадр: `Infer` struct `incoming`.

## WebSocketOutgoingData

Значение, которое принимает `session.send`: `StructInput` struct `outgoing`, или `never`, если он не объявлен.

## SocketLifecycleOutcome

Итог одной попытки подключения (`closeInfo`, `connection`, `cause`, `opened`), который использует логика reconnect. Это не окончательный результат сессии; для него см. `WebSocketCloseInfo`.
