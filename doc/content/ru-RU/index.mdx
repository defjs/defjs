# Defjs

**TypeScript SDK & Resilient Client Kit — Опишите контракт API один раз. Настраивайте выполнение под каждое приложение.**

Defjs разделяет две стороны TypeScript SDK:

- **Определение SDK (`@defjs/core`, `@defjs/cli`)** — объявляйте типизированные операции HTTP, SSE и WebSocket вместе со схемами `struct` (вручную или генерируя как stateless ESM из спецификаций OpenAPI 2.0/3.0/3.1/3.2). Определение — это чистые данные: его импорт не запускает сетевой запрос и не привязывает глобальный клиент.
- **Отказоустойчивое выполнение в приложении (`@defjs/core`)** — приложения создают собственный `Client` (`createClient(withEndpoint(...))`), подключают учётные данные и перехватчики (`basicAuth*`, `idempotencyKeyHttpInterceptor`, `concurrencyLimitHttpInterceptor`), настраивают балансировку нагрузки P2C и `outlierDetection` (`halfOpen`, `maxEjectionPercent`), включают повторы для `429`/`Retry-After`, распараллеливают вызовы через `@defjs/core/concurrent` или пробрасывают их в воркеры и расширения через `@defjs/core/port`.

## Зачем разделять определения и клиенты?

| Зона ответственности | Автор SDK (определение)                                                                                                         | Приложение (выполнение)                                                                                        |
| -------------------- | ------------------------------------------------------------------------------------------------------------------------------- | -------------------------------------------------------------------------------------------------------------- |
| **Чем владеет**      | Метод, шаблон пути, схемы `input` / `output` / `error`, маппинг `builder` и необязательное определяемое приложением поле `meta` | Базовые URL, учётные данные, перехватчики авторизации, балансировка нагрузки, таймауты и освобождение ресурсов |
| **Что поставляет**   | Переиспользуемые ESM-модули и декларации `.d.ts`                                                                                | Конфигурация для браузера, сервера или тестового окружения                                                     |
| **Преимущество**     | Полная отвязка от среды выполнения; работает в браузере, SSR и тестах                                                           | Полный контроль над повторными попытками, отказоустойчивостью, телеметрией и жизненным циклом                  |

5. **[Клиент и выполнение](/ru-RU/docs/client)** — настраивайте [клиенты](/ru-RU/docs/client), обрабатывайте типизированные [ошибки](/ru-RU/docs/errors), подключайте [перехватчики](/ru-RU/docs/interceptors) и настраивайте [балансировку нагрузки и отказоустойчивость](/ru-RU/docs/load-balancing).
6. **[Практики и тестирование](/ru-RU/docs/best-practices)** — применяйте [инженерные соглашения](/ru-RU/docs/best-practices), организуйте [прикладной API-слой](/ru-RU/docs/application-api) или [публичный SDK](/ru-RU/docs/public-sdk) и пишите детерминированные [тесты](/ru-RU/docs/testing).

## Поддерживаемые транспорты и кортежи результатов

Каждая операция возвращает error-first кортеж из трёх элементов, адаптированный под жизненный цикл своего транспорта:

| Транспорт                               | Точка входа         | Форма кортежа                | Управление жизненным циклом                                                     |
| --------------------------------------- | ------------------- | ---------------------------- | ------------------------------------------------------------------------------- |
| **[HTTP](/ru-RU/docs/http)**            | `defineRequest`     | `[err, data, response]`      | Отмена выполняемого запроса через `client({ signal })`                          |
| **[SSE](/ru-RU/docs/sse)**              | `defineEventStream` | `[err, stream, open]`        | Освобождение через `await using` или `stream.close()` + `await stream.closed`   |
| **[WebSocket](/ru-RU/docs/web-socket)** | `defineWebSocket`   | `[err, session, connection]` | Освобождение через `await using` или `session.close()` + `await session.closed` |

При сбое HTTP кортеж принимает вид `[err, undefined, undefined]`, поскольку `err` уже содержит метаданные ответа `HttpMeta`. Для SSE и WebSocket третий слот хранит снимок старта, если он успел сформироваться до ошибки.
