# Defjs

**Создан для лучших SDK.**

Defjs означает **define js**: библиотека упрощает проектирование, написание и публикацию SDK для API. Автор SDK экспортирует типизированные переиспользуемые эндпоинты через `defineRequest`, `defineEventStream` и `defineWebSocket`. Приложение импортирует их и выполняет через собственный клиент Defjs.

| Автор SDK                                                                       | Приложение                                                               |
| ------------------------------------------------------------------------------- | ------------------------------------------------------------------------ |
| Определяет операции, методы и относительные пути API                            | Настраивает базовый URL и транспорт окружения                            |
| Описывает входные и выходные данные, ошибки, события и сообщения через Struct   | Настраивает аутентификацию, перехватчики и телеметрию                    |
| Раскладывает входные данные по запросу через `builder` и экспортирует эндпоинты | Выполняет команды, обрабатывает результаты, управляет отменой и потоками |

SDK экспортирует эндпоинт:

<include cwd meta="get-health.ts">
  examples/home/get-health.ts#example
</include>

Приложение создаёт клиент и выполняет команду:

<include cwd meta="app.ts">
  examples/home/app.ts#example
</include>

Определение и выполнение остаются частями контракта Defjs. Клиент приложения добавляет настройки выполнения; эндпоинты сохраняют методы, пути и транспортные контракты.

Начни с [быстрого старта](/ru-RU/docs/start), изучи [Struct](/ru-RU/docs/struct), [команды](/ru-RU/docs/commands) и [клиент](/ru-RU/docs/client), затем [опубликуй SDK](/ru-RU/recipes/publish-http-sdk). [Проектные решения](/ru-RU/docs/design-decisions) объясняют это разделение.

Defjs не кеширует результаты и не организует повторные попытки на уровне приложения. Эти правила, отмену и освобождение ресурсов определяет приложение.

## Выбери транспорт

| Тебе нужно                           | Начни с                             | Успешный результат                                                                     |
| ------------------------------------ | ----------------------------------- | -------------------------------------------------------------------------------------- |
| Запрос + ответ по статусу            | [HTTP](/ru-RU/docs/http)            | Декодированные данные + `DecodedResponse` (`HttpMeta`, если output struct не объявлен) |
| Долгоживущая лента событий с сервера | [SSE](/ru-RU/docs/sse)              | Один стрим + снимок `open` при старте                                                  |
| Двунаправленная сессия               | [WebSocket](/ru-RU/docs/web-socket) | Одна сессия + снимок `connection` при старте                                           |

## Выбери пакет

| Пакет                         | Когда                                                                                                       |
| ----------------------------- | ----------------------------------------------------------------------------------------------------------- |
| `@defjs/core`                 | `defineRequest`, `defineEventStream`, `defineWebSocket`, `struct` и `createClient`                          |
| `@defjs/react`                | `ClientProvider` / `useClient` — см. [React](/ru-RU/docs/integrations/react)                                |
| `@defjs/vue`                  | Плагин + `injectClient` — см. [Vue](/ru-RU/docs/integrations/vue)                                           |
| `@defjs/opentelemetry-server` | Исходящие spans, metrics и logs — см. [OpenTelemetry Server](/ru-RU/docs/integrations/opentelemetry-server) |

## Формы результатов

Все три транспорта возвращают error-first кортеж из трёх элементов. Позиции совпадают, смыслы — нет:

- HTTP → `[error, data, response]`
- SSE → `[error, stream, open]`
- WebSocket → `[error, session, connection]`

При ошибке второй элемент — `undefined`. Для HTTP третий элемент тоже `undefined`, потому что метаданные ответа несёт fault. Для SSE и WebSocket третий элемент — снимок старта, если он был получен до сбоя. См. [Ошибки](/ru-RU/docs/errors).

## Владение на одном дыхании

Отмени HTTP-запрос, когда он уже не нужен. Закрой SSE и дождись завершения (`await stream.closed`). Закрой WebSocket и дождись завершения (`await session.closed`). На сервере создавай клиент внутри границы запроса, если опции захватывают cookies, auth или tenant. Перед логом маскируй URL, заголовки и тела.
