# Defjs

**Создан для лучших SDK.**

Defjs помогает разработчикам превращать API своих сервисов в переиспользуемые TypeScript SDK. `def` значит `define`: опиши операции сервиса, экспортируй их из модуля или npm-пакета и дай каждому приложению настроить собственный клиент, чтобы их вызывать.

## Опиши SDK, настрой приложение

| Автор SDK                                                     | Потребитель SDK                                                  |
| ------------------------------------------------------------- | ---------------------------------------------------------------- |
| Описывает операции, вход, размещение запроса, ответы и ошибки | Выбирает адрес сервиса, учётные данные, перехватчики и транспорт |
| Экспортирует типизированные эндпоинты HTTP, SSE и WebSocket   | Импортирует эти эндпоинты и вызывает их клиентом Defjs           |
| Поддерживает и публикует контракт API                         | Обрабатывает результаты и владеет отменой, потоками и сессиями   |

Определение SDK не захватывает клиент приложения. Один и тот же экспортированный эндпоинт может обслуживать браузер, сервер или локальный тест с разными настройками клиента. Обе стороны по-прежнему используют контракт выполнения Defjs и совместимые версии Core.

SDK экспортирует операцию:

<include cwd meta="get-health.ts">
  examples/home/get-health.ts#example
</include>

Приложение импортирует её и владеет выполнением:

<include cwd meta="app.ts">
  examples/home/app.ts#example
</include>

Вызов `getHealth(client)` начинает запрос. Когда определение опубликовано, потребители импортируют его из пакета SDK, а не из локального файла.

## Рекомендуемая практика

Определение не зависит от клиента. Передай клиент приложения первым аргументом, как в `getHealth(client)`. Адрес сервиса и учётные данные тоже принадлежат приложению. Сначала прочитай кортеж error-first. Если `error` задан, сообщи `error.code` и вернись из функции до чтения успешного значения.

## Собери SDK

1. [Опиши и выполни первую операцию](/ru-RU/docs/start) в отдельных файлах SDK и приложения.
2. Опиши [контракты данных](/ru-RU/docs/struct) и [HTTP-операции](/ru-RU/docs/http), которые экспортирует SDK.
3. [Протестируй и опубликуй пакет SDK](/ru-RU/recipes/publish-http-sdk) с JavaScript, декларациями и совместимой зависимостью Core.
4. Настрой [клиент](/ru-RU/docs/client) приложения-потребителя, затем добавь интеграцию с фреймворком или наблюдаемость, где это нужно.

[Проектные решения](/ru-RU/docs/design-decisions) объясняют, почему у определений API и выполнения разные владельцы. Ту же структуру можно использовать внутри одного приложения ещё до публикации пакета.

## Выбери транспорт

| Тебе нужно                           | Начни с                             | Успешный результат                                                              |
| ------------------------------------ | ----------------------------------- | ------------------------------------------------------------------------------- |
| Запрос + ответ по статусу            | [HTTP](/ru-RU/docs/http)            | Декодированные данные + `DecodedResponse` (`HttpMeta`, если output не объявлен) |
| Долгоживущая лента событий с сервера | [SSE](/ru-RU/docs/sse)              | Один поток + снимок `open` при старте                                           |
| Двунаправленная сессия               | [WebSocket](/ru-RU/docs/web-socket) | Одна сессия + снимок `connection` при старте                                    |

Все три транспорта идут одной последовательностью: опиши операцию, затем вызови её клиентом приложения и входом вызывающего.

## Выбери пакет

| Пакет                         | Когда                                                                                                       |
| ----------------------------- | ----------------------------------------------------------------------------------------------------------- |
| `@defjs/core`                 | Описывай операции и контракты SDK; создавай клиенты и вызывай операции HTTP, SSE и WebSocket                |
| `@defjs/react`                | `ClientProvider` / `useClient` — см. [React](/ru-RU/docs/integrations/react)                                |
| `@defjs/vue`                  | Плагин + `injectClient` — см. [Vue](/ru-RU/docs/integrations/vue)                                           |
| `@defjs/opentelemetry-server` | Исходящие spans, metrics и logs — см. [OpenTelemetry Server](/ru-RU/docs/integrations/opentelemetry-server) |

## Формы результатов

Все три транспорта возвращают error-first кортеж из трёх элементов. Позиции совпадают, смыслы — нет:

- HTTP → `[error, data, response]`
- SSE → `[error, stream, open]`
- WebSocket → `[error, session, connection]`

При ошибке второй элемент — `undefined`. Для HTTP третий элемент тоже `undefined`, потому что метаданные ответа несёт fault. Для SSE и WebSocket третий элемент — снимок старта, если он был получен до сбоя. См. [Ошибки](/ru-RU/docs/errors).

## Владение на одном дыхании

Отмени HTTP, когда он уже не нужен. Закрой SSE и `await stream.closed`. Закрой WebSocket и `await session.closed`. На сервере создавай клиент внутри границы запроса, если опции захватывают cookies, auth или tenant. Перед логом маскируй URL, заголовки и тела.

Defjs даёт определения, проверку и выполнение. Кеш и политику повторов выбирает приложение; переподключение потока включается явно. Рукописные пакеты SDK поддерживаются уже сейчас. CLI и генерация OpenAPI/SDK остаются в планах.
