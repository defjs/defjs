# Vue

Importe les opérations de ton SDK ou d’un module de définition partagé. L’application Vue configure et fournit le client ; le paquet SDK peut rester indépendant de Vue. Les composants et les composables appellent ces opérations et possèdent le travail qu’ils démarrent. Le client issu de `injectClient()` est passé à l’opération.

Ces plugins sont des helpers facultatifs pour fournir et lire un `Client` existant. Importe un client fixe possédé par l’application, passe un `Client` explicitement à de la logique réutilisable, utilise l’injection du framework pour les défauts et les surcharges au niveau de l’arbre, ou choisis ta propre organisation. Les définitions de SDK n’exigent pas ces plugins.

Branche un client `@defjs/core` existant dans Vue. Tu obtiens un plugin, une clé d’injection et `injectClient()`. Le package ne **crée pas** de clients, ne met pas les résultats en cache, ne réessaie pas les opérations et ne ferme pas les ressources de transport au unmount. Un `Client` est une fonction : ne l’utilise pas comme source d’un `watch` ou d’un `computed`, car ceux-ci appellent une fonction.

## Mise en place

Installe `@defjs/core`, `@defjs/vue` et Vue 3.2+ (le plugin n’a besoin que de `provide` / `inject`, mais les exemples utilisent `<script setup>` et `onScopeDispose`, arrivés en 3.2). ESM :

`bun add @defjs/core @defjs/vue vue`

`createClientPlugin(client)` fournit l’objet exact que tu passes. Pas de clone, pas de hook de disposition. Configure les options core et les intercepteurs quand tu crées le client.

`onCleanup` tourne avant que le watcher se relance et quand il s’arrête. Enregistre-le avant de démarrer le travail async. Le tuple error-first reste de la data applicative.

## Injecter et surcharger

`injectClient(key)` lit le provider le plus proche pour cette clé ; omis ou `undefined`, il utilise `HTTP_CLIENT`. Appelle-le dans un contexte d’injection Vue valide : `setup()` synchrone ou `app.runWithContext()` (Vue 3.3+). Ce dernier ne fournit qu’un contexte synchrone au niveau de l’app, pas les surcharges de sous-arbre ni le contexte à travers un `await` ordinaire. Les contextes restaurés par le compilateur après un `await` de premier niveau dans `<script setup>` restent valides.

Pour une `InjectionKey<Client>` personnalisée, utilise `app.provide(key, client)` ou le `provide(key, client)` d’un ancêtre. Partage le même objet `Symbol` ; des descriptions identiques ne rendent pas les clés égales. `createClientPlugin(client)` ne prend toujours que le client et fournit `HTTP_CLIENT`.

Lève une `Error` sans contexte d’injection actif ou sans client pour la clé sélectionnée. Une clé personnalisée absente ne retombe jamais sur `HTTP_CLIENT` ; installer le plugin seul n’établit pas de contexte d’injection.

Une fonction applicative qui ne fait que récupérer un client peut utiliser `explicitClient ?? injectClient()` : seule la branche de repli a besoin du contexte d’injection. Les autres API de cycle de vie du même composable gardent leurs propres exigences de contexte. Lis le client dans un contexte valide avant le travail async et réutilise l’objet.

## Posséder le travail HTTP hors d’un watcher

Pour le travail démarré par un composable ou un composant hors d’un watcher, utilise `AbortController` + `onScopeDispose`. Abandonne le démarrage et le travail actif ; vérifie le signal avant d’assigner l’état réactif. Un plugin ou une portée d’injection n’infère pas qui possède une opération. Pour les pages de liste, appelle l’opération depuis Vue Query (ou équivalent) — `@defjs/vue` reste DI seulement et ne fournit **pas** `useRequest`.

Quand une portée possède un client, garde-le indépendant de la requête pour une réutilisation à l’échelle du navigateur. S’il capture des en-têtes, des cookies, des utilisateurs, des tenants ou des identifiants, crée-le dans la frontière de requête app/SSR concernée et fournis cette instance là.

## Nettoyer la portée temps réel

Ferme un flux ou une session même quand la portée disparaît en plein connect. Abandonne le démarrage, ferme un handle qui arrive tard, consomme l’unique itérateur, attends la promesse terminale :

<include cwd>examples/vue/realtime-scope.vue#example</include>

Les erreurs de flux fatales et le dépassement de file rejettent l’itérateur, donc la boucle a un `catch` ; sinon ce rejet n’est pas géré. L’exemple ne garde que les 100 derniers messages et clé les lignes par un id, parce que des payloads identiques donneraient des clés en double. Arrêter la portée termine l’itération normalement pour SSE ; une session WebSocket abandonnée rejette à la place `receive` avec `AbortError`, donc garde le `catch` de la même façon.

WebSocket : même séquence — abandonne la prep, ferme une session tardive, consomme `session.receive`, désabonne `onStateChange` / `onRuntimeError`, ferme, attends `session.closed`. Garde le cleanup idempotent ; la disposition et la fin de l’itérateur peuvent se rencontrer.

## Portée SSR

`createClientPlugin(client)` fournit une instance à une app Vue. Dans le navigateur, partage-la quand l’endpoint, les intercepteurs et l’état capturé peuvent être partagés sans risque. Pendant le SSR, crée et installe un client séparé par requête quand les en-têtes, cookies, utilisateurs, tenants ou identifiants diffèrent.

Le unmount de l’app, le retrait du plugin et la disposition de la portée d’un composant n’**abandonnent pas** HTTP, ne ferment pas SSE/WebSocket, ne désabonnent pas les listeners et ne disposent pas le client core. Le propriétaire qui démarre le travail doit le terminer.
