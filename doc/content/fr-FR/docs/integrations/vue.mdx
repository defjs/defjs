# Vue

`@defjs/vue` relie un client `@defjs/core` possédé par l'application dans une application Vue 3.2+ via `createClientPlugin(client)`, `HTTP_CLIENT` et `injectClient()`. Vos définitions de SDK restent de purs modules `@defjs/core` sans aucune dépendance à Vue.

```sh
bun add @defjs/core @defjs/vue vue
```

## Ce que `@defjs/vue` possède vs ce que vous possédez

- **Fourni par `@defjs/vue`** : `createClientPlugin(client)`, `HTTP_CLIENT` (`InjectionKey<DerivableClient>`) et `injectClient(key?)`.
- **Possédé par votre application** : création du [`DerivableClient`](/fr-FR/api/core/derivableclient-type), annulation du travail en cours dans les watchers (`onCleanup`) ou les composables (`onScopeDispose`), fermeture des handles SSE/WebSocket et intégration de bibliothèques de requêtes (telles que Vue Query).
- **Important** : `injectClient()` renvoie l'objet-fonction `DerivableClient`. Appelez `client({ signal })` là où l'opération s'exécute (`getOrder(client({ signal }), input)`). Ne passez jamais `client` comme premier argument à `watch(client, ...)` ou `computed(client)`, car Vue traite un argument fonctionnel comme un accesseur réactif (getter).

## 2. Injecter et surcharger dans les sous-arbres

`injectClient(key?)` recherche le provider le plus proche pour `key` (par défaut `HTTP_CLIENT`) et lève une `Error` s'il est appelé en dehors d'un contexte d'injection actif de Vue (`setup()` ou `app.runWithContext()`) ou si aucun client n'est associé à cette clé.

## 4. SSR et portée d'application

- **Navigateur** : partagez un client unique par application Vue lorsque l'endpoint et les intercepteurs ne dépendent pas de la requête.
- **SSR** : instanciez et installez un client neuf par requête SSR dès que les en-têtes, cookies, tenants ou identifiants diffèrent.
- Démonter l'application Vue ou détruire la portée d'un composant n'**annule pas** automatiquement les requêtes HTTP, ne ferme pas les flux SSE/WebSocket et ne libère pas le client Core.
