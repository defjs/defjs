# Vue d’ensemble des intégrations

Une intégration étend le `Client` applicatif à un point d'extension défini sans modifier `@defjs/core` ni coupler une définition de SDK à un framework ou à une pile de télémétrie. Vos définitions de SDK restent de purs modules `@defjs/core` ; l'application consommatrice choisit quelles intégrations installer.

Tout plugin Defjs respecte le contrat des **plugins légers (thin plugins)** :

- **Aucun cache ni état dissimulé** : les plugins ne stockent jamais de réponses, ne rejouent pas de requêtes et ne gèrent pas d'état de requêtage.
- **Aucune substitution de transport** : les plugins n'enveloppent ni ne remplacent les transports HTTP, SSE ou WebSocket sous-jacents.
- **Cycle de vie possédé par l'appelant** : démonter un provider d'interface ou éteindre un SDK de télémétrie n'annule pas automatiquement les requêtes en cours ni ne ferme les flux actifs.

## Deux architectures de plugins

### 1. Plugins de framework (`@defjs/react`, `@defjs/vue`)

Un plugin de framework transmet un [`DerivableClient`](/fr-FR/api/core/derivableclient-type) existant à l'arbre de composants via l'injection de dépendances native (React Context ou Vue `provide` / `inject`) :

<Tabs items={["sdk/orders.ts", "app/main.tsx", "app/OrderCard.tsx"]}>
<Tab value="sdk/orders.ts">

```ts
import { defineRequest, struct } from "@defjs/core";

export const Order = struct.object({
  id: struct.number(),
  status: struct.string(),
});

export const getOrder = defineRequest({
  method: "GET",
  path: "/orders/:id",
  input: struct.object({ id: struct.number() }),
  builder: (input) => ({ path: { id: input.id } }),
  output: Order,
});
```

</Tab>
<Tab value="app/main.tsx">

```tsx
import { createClient, withEndpoint } from "@defjs/core";
import { ClientProvider } from "@defjs/react";
import { OrderCard } from "./OrderCard.tsx";

const client = createClient(withEndpoint("https://api.example.com"));

export function App() {
  return (
    <ClientProvider client={client}>
      <OrderCard id={42} />
    </ClientProvider>
  );
}
```

</Tab>
<Tab value="app/OrderCard.tsx">

```tsx
import { useClient } from "@defjs/react";
import { getOrder } from "../sdk/orders.ts";

export function OrderCard({ id }: { id: number }) {
  const client = useClient();
  // Transmettez `client` ou `client({ signal })` à `getOrder(...)` dans un hook d'effet ou de requête
  void id;
  void getOrder;
  void client;
  return null;
}
```

</Tab>
</Tabs>

### 2. Plugins middleware (`@defjs/opentelemetry-server`)

Un plugin middleware est une fabrique renvoyant une [`ClientOption`](/fr-FR/api/core/clientoption-type). Lorsqu'elle est passée à `createClient(...)`, elle ajoute des intercepteurs HTTP, SSE et/ou WebSocket via `withInterceptors` :

<Tabs items={["plugins/request-id.ts", "app/client.ts"]}>
<Tab value="plugins/request-id.ts">

<include cwd lang="typescript">
  examples/integrations/request-id.ts#example
</include>

</Tab>
<Tab value="app/client.ts">

```ts
import { createClient, withEndpoint } from "@defjs/core";
import { withRequestIdHeader } from "../plugins/request-id.ts";

export const client = createClient(
  withEndpoint("https://api.example.com"),
  withRequestIdHeader(),
);
```

</Tabs>

Consultez [Intercepteurs](/fr-FR/docs/interceptors) pour découvrir les règles d'ordonnancement, les frontières de retry et les hooks de cycle de vie des flux.
