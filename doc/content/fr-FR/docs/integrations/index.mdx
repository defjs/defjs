# Vue d’ensemble des intégrations

Une intégration étend le `Client` applicatif à un point d'extension défini sans modifier `@defjs/core` ni coupler une définition de SDK à un framework ou à une stack de télémétrie. Vos définitions de SDK restent de purs modules `@defjs/core` ; l'application consommatrice choisit quelles intégrations installer.

Tout plugin Defjs respecte le contrat des **plugins légers (thin plugins)** :

- **Aucun cache ni état dissimulé** : les plugins ne stockent jamais de réponses, ne rejouent pas de requêtes et ne gèrent pas d'état des requêtes.
- **Aucune substitution de transport** : les plugins n'enveloppent ni ne remplacent les transports HTTP, SSE ou WebSocket sous-jacents.
- **Cycle de vie possédé par l'appelant** : démonter un provider d'interface ou éteindre un SDK de télémétrie n'annule pas automatiquement les requêtes en cours ni ne ferme les flux actifs.

## Deux architectures de plugins

### 1. Plugins de framework (`@defjs/react`, `@defjs/vue`)

Un plugin de framework transmet un [`DerivableClient`](/fr-FR/api/core/derivableclient-type) existant à l'arbre de composants via l'injection de dépendances native (React Context ou Vue `provide` / `inject`) :

### 2. Plugins middleware (`@defjs/opentelemetry-server`)

Un plugin middleware est une fabrique renvoyant une [`ClientOption`](/fr-FR/api/core/clientoption-type). Lorsqu'elle est passée à `createClient(...)`, elle ajoute des intercepteurs HTTP, SSE et/ou WebSocket via `withInterceptors` :
