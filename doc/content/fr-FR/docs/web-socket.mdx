# Sessions WebSocket

`defineWebSocket` déclare un contrat WebSocket bidirectionnel dans votre SDK : le patron de chemin, l'entrée et le builder optionnels (`path` et `query` uniquement), les structs de messages `incoming` et `outgoing`, les limites de file et les sous-protocoles statiques. L'application consommatrice configure le heartbeat, la reconnexion et le nettoyage du cycle de vie sur son propre client.

## 1. Définir le contrat et exécuter une session

Modélisez plusieurs types de trames pour `incoming` ou `outgoing` à l'aide de `struct.discriminatedUnion(...)`. Libérez la session `WebSocketSession` obtenue avec `await using` ou par un appel explicite à `session.close()` + `await session.closed` :

<Tabs items={["sdk/ticks-socket.ts", "app/session.ts", "Single-file quick look"]}>
<Tab value="sdk/ticks-socket.ts">

```ts
import { defineWebSocket, struct } from "@defjs/core";

export const TickFrame = struct.discriminatedUnion("type", [
  struct.object({
    type: struct.literal("tick"),
    symbol: struct.string(),
    price: struct.number(),
  }),
  struct.object({
    type: struct.literal("subscribed"),
    symbol: struct.string(),
  }),
]);

export const SubscribeCommand = struct.object({
  type: struct.literal("subscribe"),
  symbol: struct.string(),
});

export const openTicker = defineWebSocket({
  path: "/market/ws",
  operation: "market.ticker",
  incoming: TickFrame,
  outgoing: SubscribeCommand,
  maxIncomingQueueSize: 64,
});
```

</Tab>
<Tab value="app/session.ts">

```ts
import { createClient, withEndpoint } from "@defjs/core";
import { openTicker } from "../sdk/ticks-socket.ts";

const client = createClient(withEndpoint("https://api.example.com"));

async function main() {
  const [error, session] = await openTicker(client);
  if (error) {
    console.error(error.code);
    return;
  }

  await using active = session;
  active.send({ type: "subscribe", symbol: "ACME" });

  for await (const message of active.receive) {
    if (message.type === "tick") {
      console.log(message.symbol, message.price);
      break;
    }
  }
}

void main();
```

## 2. Validation des messages et sens d'échange

- **Trames entrantes (`session.receive`)** : Les trames texte, `ArrayBuffer`, vues typées et `Blob` sont décodées en UTF-8, analysées en JSON et validées selon `incoming`. Tout JSON malformé ou non-conformité de schéma est notifié à `session.onRuntimeError` et ignoré sans refermer la session. `session.receive` n'admet qu'un seul consommateur ; demander un second itérateur lève un `TypeError`.
- **Trames sortantes (`session.send(payload)`)** : Valide de manière synchrone selon `outgoing`, applique les `.alias()` et codecs, puis sérialise avec `JSON.stringify`. L'envoi est immédiat si l'état est `open`, mis en file pendant `reconnecting` (si `maxOutgoingQueueSize > 0`), et lève de manière synchrone si la charge utile est invalide, la file pleine/désactivée ou la session fermée.

## 3. États de session et observateurs

| Membre               | Description                                                                                              |
| -------------------- | -------------------------------------------------------------------------------------------------------- |
| `state`              | `'idle' \| 'connecting' \| 'open' \| 'reconnecting' \| 'closing' \| 'closed' \| 'aborted' \| 'error'`    |
| `connection`         | Instantané dynamique du dernier socket physique (`generation`, `url`, `protocol`, `extensions`)          |
| `bufferedAmount`     | Nombre d'octets natifs non envoyés sur le socket physique actif (`0` en l'absence de connexion)          |
| `receive`            | Itérable asynchrone à consommateur unique délivrant les messages validés par `incoming`                  |
| `onStateChange(fn)`  | S'abonne aux transitions d'état ; renvoie une fonction de désabonnement                                  |
| `onRuntimeError(fn)` | S'abonne aux erreurs d'analyse ou de trames hors phase de démarrage ; renvoie une fonction `unsubscribe` |
| `closed`             | Promesse résolue avec l'issue terminale (`kind: 'closed' \| 'aborted' \| 'error'`)                       |

## 4. Reconnexion, heartbeat et files d'attente

La reconnexion et le heartbeat sont activables à la demande via les options du client (`withWebSocketReconnect`, `withWebSocketHeartbeat`) ou sur un client dérivé par appel (`client({ reconnect, heartbeat })`) :

- **Reconnexion** : Les valeurs par défaut une fois activée sont `attempts: 3`, `delayMs: 1000`, `factor: 2`, `maxDelayMs: 30000`, `jitter: 0`. Chaque ouverture physique `open` réinitialise le budget de tentatives. `beforeConnect({ attempt, signal })` s'exécute avant la connexion initiale et chaque tentative de reconnexion.
- **Délai de handshake (`connectTimeoutMs`)** : Lorsqu'il est fourni, il doit être fini, positif et ne pas dépasser 2147483647 (la limite du minuteur) ; sinon l'opération renvoie `REQ_OPTIONS_INVALID`. Il borne la construction jusqu'à `open` et est effacé après le handshake.
- **Heartbeat** : Émet périodiquement `message()` à travers le struct `outgoing` et attend jusqu’à `timeoutMs` une trame satisfaisant `isAck(msg)`. Les trames d’acquittement correspondantes sont consommées par le moniteur de heartbeat et ne parviennent pas à `session.receive`. Un acquittement manqué est fatal à la session logique : `closed.kind` vaut `"error"` et `closed.cause` est l’ordinaire `Error("WebSocket heartbeat timeout")` ; cela ne déclenche pas de reconnexion. Les échecs de sérialisation du heartbeat suivent le même chemin fatal avec leur cause initiale.
- **Limites de file d'attente** :
  - `maxIncomingQueueSize` (entier positif obligatoire) : Borne à la fois les trames brutes en attente de décodage et les messages décodés en attente du consommateur. Un dépassement termine la session avec un Fault `CAP_QUEUE_OVERFLOW` comme `closed.cause` ; cette même cause parvient à `onRuntimeError` et rejette `session.receive`. Consommez régulièrement `session.receive` tant que la session est ouverte.
  - `maxOutgoingQueueSize` (entier non négatif facultatif, par défaut `0`) : Met en tampon les appels `session.send()` uniquement lorsque `state === 'reconnecting'` et les expédie avant de publier l'état `open` suivant.

`shouldReconnect` reçoit le code de fermeture natif et `wasClean`. Un serveur peut achever un handshake de fermeture normal avec le code d’erreur applicative `1011` ; `wasClean === true` ne signifie donc pas que l’application a réussi. L’exemple autorise explicitement `1011` ; choisissez les codes applicatifs selon votre protocole au lieu de vous fier uniquement à `!wasClean`.

## 5. Sous-protocoles et authentification [#protocols-and-authentication]

Les WebSocket de navigateur ne permettent pas de définir des en-têtes de handshake arbitraires, par conséquent les fonctions `builder` WebSocket renvoient exclusivement `{ path?, query? }`.

- **Priorité des sous-protocoles** : `client({ protocols })` l'emporte sur `withWebSocketProtocols(...)`, qui l'emporte sur `defineWebSocket({ protocols })`.
- **Conversion d'URL** : Defjs convertit automatiquement `http:` → `ws:` et `https:` → `wss:` sur l'endpoint résolu.
- **Identifiants** : `withCredentials(true)` s'applique exclusivement à Fetch (HTTP/SSE). Authentifiez les connexions WebSocket à l'aide de cookies/politiques de session, de sous-protocoles ou de jetons temporaires de connexion — évitez de placer des secrets pérennes dans les chaînes de requête.
- **`beforeConnect` n’est pas un mutateur de requête** : L’analyse d’entrée, le `builder` pur synchrone et la chaîne d’intercepteurs s’exécutent une fois par opération. Pour une requête dont l’endpoint de base n’est pas remplacé par un intercepteur, chaque reconnexion sélectionne à nouveau un endpoint et reconstruit l’URL avec cet endpoint, mais réutilise le chemin/la query construits et la liste de protocoles capturée. L’URL est fixée avant le `beforeConnect` de cette tentative, sur le même endpoint comme après un basculement. Modifier une variable de closure, l’entrée ou le tableau de protocoles dans le hook ne peut pas fournir un nouveau ticket au handshake courant. Le renouvellement d’un identifiant d’URL/sous-protocole au sein d’une session n’est pas pris en charge ; obtenez d’abord le nouvel identifiant, passez-le comme entrée ou configuration client à une nouvelle opération, puis prenez en charge le nettoyage de cette session de remplacement.

## 6. Fermeture et propriété

Appelez `session.close(code?, reason?)` (où `code` vaut `1000` ou `3000..4999` et `reason` ne dépasse pas 123 octets UTF-8) et attendez `await session.closed`, ou bien recourez à `await using` :

<include cwd lang="typescript">
  examples/web-socket/closure-and-ownership.ts#example
</include>

Lorsqu’une coupure de reconnexion épuise ses tentatives, la session se termine avec `closed.kind: "error"`, l’instantané de fermeture natif (souvent le code `1006` pour un upgrade échoué) et l’erreur de transport ordinaire comme `closed.cause` ; elle n’expose aucun code stable distinct d’épuisement. Désabonnez systématiquement vos écouteurs `onStateChange` et `onRuntimeError` dès la destruction de votre composant ou worker.
