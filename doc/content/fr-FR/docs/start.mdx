# Bien démarrer : une requête HTTP

Le premier élément du SDK est un endpoint exporté pour `GET /users/:id`. Tu écris le contrat dans un fichier, puis tu l’exécutes depuis un deuxième fichier avec le client de l’application. Le handler Fetch local permet un premier essai sans réseau ; la même définition décodera ensuite le `200` et le `404` déclaré du service réel.

## Bonne pratique

Une définition reste indépendante du client. L’appeler crée seulement une commande. Donne-lui un nom, puis passe ce nom à `client.execute` sur le client que l’application possède. L’application possède aussi l’adresse du service et les identifiants. Inspecte d’abord le tuple error-first. Quand `error` est présent, signale `error.code` et sors de la fonction avant de lire la valeur de succès.

## Étape 1 — Installer

`@defjs/core` est ESM et tourne sur Node.js ou Bun. Node.js 22.18+ (ou 24+) exécute le `.ts` directement grâce au type stripping ; les versions 22.x plus anciennes demandent `--experimental-strip-types`. Garde `"type": "module"` dans package.json. Dans un navigateur, tu as toujours besoin de ton bundler et de Fetch.

## Étape 2 — Définir la requête

Côté SDK, crée `src/define-request.ts` et exporte `getUser`. Le Struct d’entrée décrit la valeur fournie par l’appelant. `builder` place cette valeur dans la requête. Ici, toute l’entrée est l’objet de chemin : les champs scalaires sans alias remplissent `:id`. L’application configurera l’URL de base et l’authentification.

<include cwd meta="define-request.ts">
  examples/start/define-request.ts#example
</include>

`output` est le corps 2xx. `error` est tout autre statut. Un struct chacun. Utilise `struct.or(...)` ou une union discriminée quand ces corps diffèrent.

`defineRequest(...)` renvoie un endpoint. Appeler `getUser(...)` construit la commande opaque que tu passeras à `client.execute(...)`. Le `builder` ci-dessus est la fonction qui place l’entrée ; ce n’est pas l’endpoint.

## Étape 3 — L’exécuter en local

## Quand le résultat change

- Mauvaise entrée → `REQ_INPUT_INVALID` ; options d’annulation en conflit → `REQ_OPTIONS_INVALID` ; un
  `builder` qui échoue → `REQ_BUILD_FAILED`
- Un statut non-2xx → `HTTP_STATUS`, avec `error.data` typé quand `error` a été déclaré et que son corps décode
- Un corps JSON déclaré avec un autre media type → `RES_MEDIA_TYPE_INVALID`, signalé avant la lecture du corps
- Un corps déclaré (`output` pour un 2xx, `error` sinon) qui ne décode pas → `RES_DECODE_FAILED` ou `RES_STRUCT_MISMATCH`, quel que soit le statut
- Échec Fetch / annulation / timeout → `NET_UNREACHABLE` / `NET_ABORTED` / `NET_TIMEOUT`

`timeout` doit être un entier sûr positif dans `1..2_147_483_647`. Formes d’annulation valides : `{ signal }`, `{ timeout }`, `{ abort }`, ou `{ signal, timeout }` / `{ signal, abort }`. `{ abort, timeout }` ensemble est invalide. L’annulation te dit ce que l’appelant a vu — pas si une écriture serveur a été appliquée.
