# Bien démarrer : ta première opération de SDK [#getting-started-one-http-request]

Tu écriras deux fichiers : un module de SDK qui exporte `GET /users/:id`, et une application qui l’importe et possède le client. Le handle Fetch local garde le premier essai hors ligne. La même définition d’API fonctionnera ensuite avec un client pointé vers ton service.

## Bonne pratique

Une définition reste indépendante du client. Appelle l’opération avec le client de l’application, comme dans `getUser(client, { id: 7 })`. Il n’y a pas de troisième argument d’options. Appeler l’opération la démarre ; `await` ne fait qu’attendre. L’application possède aussi l’adresse du service et les identifiants. Inspecte d’abord le tuple error-first. Quand `error` est présent, signale `error.code` et sors de la fonction avant de lire la valeur de succès.

## Étape 1 — Installer

`@defjs/core` est ESM et tourne sur Node.js ou Bun. Node.js 22.18+ (ou 24+) exécute le fichier `.ts` directement grâce au type stripping ; les versions 22.x plus anciennes demandent `--experimental-strip-types`. Garde `"type": "module"` dans package.json. Dans un navigateur, tu as toujours besoin de ton bundler et de Fetch.

```sh
bun add @defjs/core
```

## Étape 2 — Définir la requête

Crée `src/define-request.ts`. C’est le module de l’auteur du SDK : il exporte `getUser` sans créer de client. Le struct d’entrée est la valeur de l’appelant. `builder` place cette valeur sur la requête. Ici, toute l’entrée est l’objet de chemin, donc les champs scalaires sans alias remplissent `:id`.

<include cwd meta="define-request.ts">
  examples/start/define-request.ts#example
</include>

`output` est le corps 2xx. `error` est tout autre statut. Un struct chacun. Utilise `struct.or(...)` ou une union discriminée quand ces corps diffèrent.

`defineRequest(...)` renvoie une opération. Appeler `getUser(client, input)` démarre la requête. Le `builder` ci-dessus est la fonction qui place l’entrée ; ce n’est pas l’opération. Là où `input` est déclaré, `builder` est obligatoire, synchrone et pur.

## Étape 3 — L’appeler en local

Crée `src/execute-locally.ts` à côté de la définition. C’est l’application consommatrice : elle importe `getUser`, crée son propre client et fournit un handle Fetch local. Defjs valide toujours l’entrée, construit la `Request`, dispatche selon le statut et parse le corps.

<include cwd meta="execute-locally.ts">
  examples/start/execute-locally.ts#example
</include>

Lance-le :

```sh
bun src/execute-locally.ts
```

```txt
Loaded Ada from 200
```

Essaie un utilisateur manquant — change l’id de path en `8` et relance :

```txt
User not found
```

En succès : `error` est `null`, `user` est la sortie Struct du `200`, `response` est un `DecodedResponse<User>`. Sur un `404` déclaré : `error.code` est `'HTTP_STATUS'`, `error.status` est `404`, et `error.data` est typé `NotFound`. Le deuxième élément du tuple est `undefined` en échec.

## Étape 4 — Pointer vers une vraie API

Dans `src/real-api.ts`, importe le même `getUser` et crée un client avec l’URL de base de ton service. N’exécute cette version qu’après avoir remplacé l’adresse d’exemple par un service qui implémente `GET /v1/users/:id` avec ces corps.

<include cwd>examples/start/real-api.ts#example</include>

La définition d’API reste dans le module SDK. Les adresses de service, les identifiants, les intercepteurs et la durée de vie de l’exécution restent dans l’application. Les deux clients utilisent le même contrat d’endpoint Defjs.

## Publier la définition

Déplace la définition dans un paquet SDK quand d’autres applications en ont besoin. Exporte `getUser`, inclus ses déclarations TypeScript et déclare la version de Core compatible. Les consommateurs importent alors depuis le paquet au lieu de `./define-request.ts` ; la configuration de leur client reste la leur. Suis [Créer et publier un SDK](/fr-FR/recipes/publish-http-sdk) pour la mise en place complète du paquet.

## Quand le résultat change

- Mauvaise entrée → `REQ_INPUT_INVALID` ; un `builder` qui échoue → `REQ_BUILD_FAILED`
- Un statut non-2xx → `HTTP_STATUS`, avec `error.data` typé quand `error` a été déclaré et que son corps décode
- Un corps JSON déclaré avec un autre media type → `RES_MEDIA_TYPE_INVALID`, signalé avant la lecture du corps
- Un corps déclaré (`output` pour un 2xx, `error` sinon) qui ne décode pas → `RES_DECODE_FAILED` ou `RES_STRUCT_MISMATCH`, quel que soit le statut
- Échec Fetch / annulation / échéance → `NET_UNREACHABLE` / `NET_ABORTED` / `NET_TIMEOUT`

Une échéance est `client({ signal: AbortSignal.timeout(ms) })` et se classe en `NET_TIMEOUT`. Un abort manuel est `NET_ABORTED`. Il n’y a pas d’échéance par défaut au niveau du client. Dérive un client quand un appel a besoin de son propre `signal` ; voir [Client](/fr-FR/docs/client). L’annulation te dit ce que l’appelant a vu — pas si une écriture serveur a été appliquée.
