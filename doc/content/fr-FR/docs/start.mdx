# Démarrage rapide : votre première opération de SDK [#getting-started-one-http-request]

Dans ce guide, vous allez créer un module SDK définissant `GET /orders/:id`, puis l'appeler depuis deux modules applicatifs distincts : l'un utilisant un transport simulé hors ligne et l'autre ciblant une véritable API en ligne.

## 1. Installer `@defjs/core`

`@defjs/core` est un package ESM sans aucune dépendance externe qui s'exécute dans les navigateurs, avec Bun ou avec Node.js (les versions 22.18+ et 24+ exécutent directement les fichiers `.ts`). Assurez-vous que `"type": "module"` est bien présent dans votre `package.json`.

```sh
bun add @defjs/core
```

### Comment ces trois fichiers collaborent

1. **`src/define-request.ts` (Définition du SDK)** :
   - Déclare `input`, `output` (pour les réponses `2xx`) et `error` (pour les réponses hors `2xx`) à l'aide de `struct`.
   - Fournit un `builder` synchrone et pur qui projette `input` dans `{ path }`. Dès lors qu'un `input` est déclaré, un `builder` explicite est obligatoire.
   - Exporte `getOrder` sans créer ni capturer le moindre client.
2. **`src/execute-locally.ts` (Exécution de test hors ligne)** :
   - Configure un client avec `withHTTPHandle(...)` pour exécuter l'ensemble du pipeline Defjs (validation de l'entrée, résolution d'URL, aiguillage par statut et analyse du struct de réponse) sans solliciter le réseau.
3. **`src/real-api.ts` (Exécution en production)** :
   - Importe très exactement la même opération `getOrder` et l'appelle contre une URL de base réelle configurée via `withEndpoint(...)`.

## 3. Lancer l'exemple local

Exécutez `src/execute-locally.ts` avec Bun :

```sh
bun src/execute-locally.ts
```

```txt
Loaded paid from 200
```

Si vous remplacez l'entrée `{ id: 7 }` par `{ id: 8 }`, le mock renvoie `404` et Defjs décode le struct `error` déclaré dans `error.data` :

```txt
Order not found
```

## 4. Comprendre le tuple error-first

Chaque appel HTTP résout un tuple `[error, data, response]` :

- **En cas de succès `2xx`** : `error` vaut `null`, `data` contient la valeur validée par `output` (`Order`), et `response` est un `DecodedResponse<Order>`.
- **En cas de statut hors `2xx` déclaré** : `error.code` vaut `'HTTP_STATUS'`, `error.status` indique le code statut (`404`), et `error.data` contient le struct `error` validé (`NotFound`).
- **En cas d'erreur de saisie, de décodage ou de réseau** : `error.code` identifie avec précision l'étape défaillante :
  - `REQ_INPUT_INVALID` / `REQ_BUILD_FAILED` — entrée appelante invalide ou exception levée dans le `builder`
  - `RES_MEDIA_TYPE_INVALID` — un corps JSON déclaré a été reçu avec un en-tête `Content-Type` non-JSON (rejeté avant toute lecture du flux)
  - `RES_DECODE_FAILED` / `RES_STRUCT_MISMATCH` — corps illisible ou non-conforme au schéma attendu
  - `NET_UNREACHABLE` / `NET_ABORTED` / `NET_TIMEOUT` — erreur de transport, annulation explicite ou expiration du délai `AbortSignal.timeout(ms)`

Transmettez des délais ou signaux d'annulation par appel en dérivant une valeur de client pour un appel unique : `getOrder(client({ signal: AbortSignal.timeout(5_000) }), { id: 7 })`.
