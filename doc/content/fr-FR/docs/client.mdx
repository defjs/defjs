# Client

Un `Client` est la configuration d’exécution de l’application consommatrice. `createClient(...)` renvoie un [`DerivableClient`](/fr-FR/api/core/derivableclient-type). Appeler la factory avec des options de requête renvoie une valeur `Client`, et c’est une valeur `Client` que les opérations acceptent. Elle n’est pas appelable. Importe les opérations de ton SDK, choisis l’adresse du service, les identifiants, les intercepteurs et le transport, puis appelle une opération avec le client. `getUser(client({ signal }), { id: 1 })` démarre un appel qui déclare une entrée. `health(client)` en démarre un qui n’en déclare pas. Quand tout le struct d’entrée est facultatif, `search(client)` et `search(client, input)` sont tous deux valides. Il n’y a pas de troisième argument d’options. Appeler l’opération la démarre. `await` n’attend que le tuple error-first.

Les définitions du SDK ne lient pas cette instance. Un navigateur, une requête serveur et un test local peuvent utiliser la même opération exportée avec des clients différents. Tous suivent quand même le même contrat Defjs et des versions de Core compatibles. Configure l’adresse de service de chaque client pour les opérations que tu appelles à travers lui.

La même valeur de client peut être passée à beaucoup d’opérations. Les applications choisissent les politiques de cache et de nouvelle tentative et possèdent le travail qu’elles démarrent. HTTP n’est pas réessayé automatiquement. La reconnexion des flux est opt-in.

La factory est une fonction et aussi un `Client` sans options de requête. Ne passe pas la factory à un setter d’état React : `setState(factory)` l’appellerait comme updater. Ne l’utilise pas comme source d’un `watch` ou d’un `computed` Vue : ceux-ci appellent une fonction. Une valeur de client dérivée est un objet simple.

## Dériver un client

`client(options?)` renvoie une valeur `Client` pour un seul appel. À l’appel de `client(options)`, les sept champs connus sont copiés depuis l’objet argument : un instantané de premier niveau dans un objet d’options neuf. Les champs inconnus sont ignorés et les champs dont la valeur est `undefined` sont omis. Il n’y a pas de superposition au parent : `client()`, `client(undefined)` et `client({})` renvoient un client sans options de requête. Les valeurs imbriquées `heartbeat`, `protocols` et `reconnect` sont conservées par référence, pas clonées. WebSocket les lit quand l’opération s’exécute (il copie alors les champs de heartbeat et la liste protocols), donc modifier ces objets après la dérivation peut encore affecter un appel ultérieur. Les applications doivent les traiter comme immuables après les avoir passés. Dériver ne fait aucune I/O. Un getter qui lève une exception s’échappe de `client(options)` et laisse la factory utilisable. La valeur de client n’est pas appelable ; crée-en une par appel.

`signal` n’est pas combiné. Réutiliser une valeur de client qui porte `signal` partage ce signal entre les appels, donc crée une valeur de client par appel. Combine les signaux avec `AbortSignal.any` dans le code applicatif.

La configuration de base issue de `createClient` est partagée par chaque valeur de client et n’est pas gelée à l’exécution. Elle est fixe par convention : rien dans la bibliothèque ne la change, et les applications ne devraient pas non plus. Les [`RequestOptions`](/fr-FR/api/core/requestoptions-type) d’un client sont cet instantané de premier niveau. Le code applicatif passe le client à une opération. Il ne lit pas cet état interne.

## Options de requête

[`RequestOptions`](/fr-FR/api/core/requestoptions-type) a sept champs plats. Chaque protocole ne lit que les champs qu’il connaît et ignore le reste. Passer `heartbeat` à une opération HTTP est ignoré, pas un fault. SSE ne lit que `signal` dans les options de requête. La reconnexion SSE vient de la configuration du client (`withSSEReconnect`), donc `client({ reconnect })` n’affecte que WebSocket. Il n’y a pas de filtre de protocole à la compilation.

| Champ                | Utilisé par          | Règle                                                                                                             |
| -------------------- | -------------------- | ----------------------------------------------------------------------------------------------------------------- |
| `signal`             | HTTP, SSE, WebSocket | Abandonne l’appel. Une échéance est `AbortSignal.timeout(ms)` (`NET_TIMEOUT`). Un abort manuel est `NET_ABORTED`. |
| `onUploadProgress`   | HTTP                 | Ignoré par SSE et WebSocket.                                                                                      |
| `onDownloadProgress` | HTTP                 | Ignoré par SSE et WebSocket.                                                                                      |
| `beforeConnect`      | WebSocket            | Remplace le réglage client pour cet appel.                                                                        |
| `protocols`          | WebSocket            | Remplace la liste du client. Elle n’est pas ajoutée.                                                              |
| `heartbeat`          | WebSocket            | Remplacé en entier. `timeoutMs` est l’attente d’acquittement du heartbeat, pas une échéance de requête.           |
| `reconnect`          | WebSocket            | Remplacé en entier.                                                                                               |

Il n’y a pas de champ `timeout`, pas de champ `abort`, et pas d’échéance par défaut au niveau du client. Pour SSE et WebSocket, `signal` couvre toute la connexion, y compris après son ouverture. Il n’y a pas d’échéance limitée au démarrage. Une application qui en veut une crée son propre `AbortController`, l’abandonne avec `new DOMException("...", "TimeoutError")` depuis un timer, et efface le timer après le retour de l’await. Voir [SSE](/fr-FR/docs/sse#close-and-dispose).

`HttpExecuteOptions` est la tranche HTTP : `signal` plus les callbacks de progression. `EventStreamExecuteOptions` est `{ signal? }`. `WebSocketExecuteOptions` est la tranche WebSocket plus `signal`.

## Résultats par transport

- HTTP → `[error, data, response]`
- SSE → `[error, stream, open]`. `open` est l’instantané du premier handshake réussi de la connexion renvoyée pour les handles natifs Defjs ou les wrappers qui transmettent le même objet `open` live ; les handles personnalisés ou les wrappers qui redéfinissent `open` utilisent leur `open` public courant même après une reconnexion, tandis que `stream.open` reste live (voir [SSE](/fr-FR/docs/sse)).
- WebSocket → `[error, session, connection]`

Reviens avant d’utiliser la valeur de succès quand `error` est défini.

Tu possèdes le nettoyage : abandonne HTTP, ferme SSE + `await stream.closed`, ferme WebSocket + `await session.closed`.

## Portée serveur vs navigateur

Sur un serveur, crée le client dans la frontière de la requête quand les options ou les closures d’intercepteur capturent l’auth, les cookies, les utilisateurs ou les tenants. L’identité du client n’est pas une frontière de sécurité à elle seule.

## Migration

| Ancien                                       | Nouveau                                                         |
| -------------------------------------------- | --------------------------------------------------------------- |
| `client.execute(getUser(input), options)`    | `getUser(client(options), input)`                               |
| `execute(cmd, { timeout: 5000 })`            | `client({ signal: AbortSignal.timeout(5000) })`                 |
| `execute(cmd, { signal })`                   | `client({ signal })`                                            |
| `client({ signal })({ onDownloadProgress })` | `client({ signal, onDownloadProgress })`                        |
| `createClient(withTimeout(5000), ...)`       | passe `signal` à l’appel, ou enveloppe une fonction applicative |

## Référence

| Helper                                                                                                        | Effet                                                                                |
| ------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------ |
| `withEndpoint(url)`                                                                                           | Endpoint de base absolu pour tous les transports                                     |
| `withHeaders(HeadersInit)`                                                                                    | En-têtes par défaut statiques pour HTTP/SSE ; les en-têtes du builder les remplacent |
| `withHTTPHandle(fetch)`                                                                                       | Remplace Fetch pour HTTP                                                             |
| `withSSEHandle(fetch)`                                                                                        | Remplace Fetch pour SSE                                                              |
| `withWebSocketHandle(WebSocket)`                                                                              | Remplace le constructeur WebSocket                                                   |
| `withInterceptors(...items)`                                                                                  | Ajoute des intercepteurs mixtes                                                      |
| `withQuerySerializer(fn)`                                                                                     | Encode un objet de query déjà aliasé en query string                                 |
| `withCredentials(boolean)`                                                                                    | Fetch `credentials: 'include'` pour HTTP/SSE quand true                              |
| `withXSRF(options?)`                                                                                          | Cookie XSRF HTTP → en-tête                                                           |
| `withSSEReconnect` / `withSSEOnInvalidEvent`                                                                  | Réglages SSE                                                                         |
| `withWebSocketReconnect` / `withWebSocketHeartbeat` / `withWebSocketProtocols` / `withWebSocketBeforeConnect` | Réglages WebSocket                                                                   |
