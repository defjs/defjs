# Client

Un `Client` porte la configuration d'exécution de l'application consommatrice : URL de base, en-têtes par défaut, identifiants, intercepteurs, sérialisation des requêtes et handles de transport.

`createClient(...options)` renvoie un [`DerivableClient`](/fr-FR/api/core/derivableclient-type) :

- Passez `client` directement à une opération (`getOrder(client, { id: 1 })`) lorsqu'aucune option de requête spécifique par appel n'est requise.
- Appelez `client(requestOptions)` pour dériver une valeur `Client` pour un appel unique (`getOrder(client({ signal }), { id: 1 })`). Dériver un client n'effectue aucune opération d'E/S, et la valeur résultante est un objet simple (non appelable).

### Règles de composition des options

- Les options s'appliquent de **gauche à droite**.
- Les setters à valeur unique (`withEndpoint`, `withHeaders`, `withQuerySerializer`, `withCredentials`, `withXSRF`) **remplacent** les valeurs antérieures.
- `withInterceptors(...items)` **ajoute** des éléments à la liste des intercepteurs existants et filtre par transport (`http`, `sse`, `web-socket`) lors de l'exécution de l'opération.

> [!IMPORTANT]

### Référence de `RequestOptions` par appel

`RequestOptions` comporte sept champs plats. Chaque transport lit uniquement les champs qui le concernent et ignore les autres :

| Champ                | Utilisé par          | Comportement                                                                                                                                              |
| -------------------- | -------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `signal`             | HTTP, SSE, WebSocket | Interrompt l'appel (`AbortSignal.timeout(ms)` → `NET_TIMEOUT` ; annulation manuelle → `NET_ABORTED`).                                                     |
| `onUploadProgress`   | HTTP                 | Notifie la progression d'envoi du corps de requête en flux continu.                                                                                       |
| `onDownloadProgress` | HTTP                 | Notifie la progression de téléchargement du corps de réponse déclaré.                                                                                     |
| `beforeConnect`      | WebSocket            | Remplace le hook `beforeConnect` configuré sur le client pour cette session.                                                                              |
| `protocols`          | WebSocket            | Remplace la liste de sous-protocoles du client pour cette session.                                                                                        |
| `heartbeat`          | WebSocket            | Remplace la configuration de heartbeat du client pour cette session.                                                                                      |
| `reconnect`          | WebSocket            | Remplace la politique de reconnexion WebSocket du client pour cette session (la reconnexion SSE se configure au niveau du client via `withSSEReconnect`). |

## 3. Singleton navigateur vs portée de requête serveur

- **Applications navigateur** : Partagez un `DerivableClient` unique au niveau du module lorsque l'endpoint, les intercepteurs et les identifiants s'appliquent à toute l'application.
- **Applications serveur / SSR** : Créez un client neuf **au sein de chaque frontière de requête entrante** dès que les en-têtes, cookies, jetons d'authentification ou contextes de tenant sont propres à la requête. Ne stockez jamais d'identifiants par utilisateur sur un client global au processus.

## 4. Plusieurs endpoints et répartition de charge [#multiple-endpoints]

`withEndpoint(...urls)` accepte une ou plusieurs URL de base candidates. Par défaut :

- Chaque client utilise [`pickFirstBalancer`](/fr-FR/api/core/pickfirstbalancer), restant fidèle à la première URL jusqu'à ce qu'un échec de connexion `NET_UNREACHABLE` ou une réponse non codée `502`/`503`/`504` ne le fasse avancer.
- Les méthodes HTTP sûres (`GET`, `HEAD`, `OPTIONS`, `TRACE`) exécutent automatiquement un **basculement au sein du même appel** vers un endpoint de secours non encore tenté en cas d'échec de connexion (`NET_UNREACHABLE`), sous le contrôle d'un budget de retry Finagle partagé (`withEndpointFailover`).

### Filtrage de santé et p2c [#health-filtering-and-p2c]

Pour des réplicas de serveurs équivalents, [`roundRobinBalancer`](/fr-FR/api/core/roundrobinbalancer) et [`p2cBalancer`](/fr-FR/api/core/p2cbalancer) (RTT PeakEwma × charge en cours) activent par défaut un coupe-circuit par échecs consécutifs inspiré de Linkerd (`outlierDetection`).

## 6. Référence des helpers d'options de client

| Helper                                                                                                        | Utilité                                                                                                   |
| ------------------------------------------------------------------------------------------------------------- | --------------------------------------------------------------------------------------------------------- |
| `withEndpoint(...urls)`                                                                                       | Définit une ou plusieurs URL de base candidates (remplace la liste précédente).                           |
| `withHeaders(HeadersInit)`                                                                                    | Définit des en-têtes statiques par défaut pour HTTP et SSE (les en-têtes du builder prévalent).           |
| `withInterceptors(...items)`                                                                                  | Ajoute des intercepteurs HTTP, SSE et WebSocket selon le modèle en oignon.                                |
| `withQuerySerializer(fn)`                                                                                     | Sérialise des objets de requête déjà aliasés en une chaîne de requête (query string).                     |
| `withCredentials(boolean)`                                                                                    | Active Fetch `credentials: "include"` pour HTTP et SSE lorsque `true`.                                    |
| `withXSRF(options?)`                                                                                          | Copie le cookie XSRF dans un en-tête pour les requêtes HTTP mutantes de même origine.                     |
| `withEndpointBalancer(balancer)`                                                                              | Remplace la stratégie de sélection d'endpoint (`pickFirstBalancer`, `roundRobinBalancer`, `p2cBalancer`). |
| `withEndpointFailover(options?)`                                                                              | Configure le basculement HTTP au sein du même appel et le budget de retry du client.                      |
| `withSSEReconnect` / `withSSEOnInvalidEvent`                                                                  | Configure la reconnexion SSE et l'observation d'événements invalides.                                     |
| `withWebSocketReconnect` / `withWebSocketHeartbeat` / `withWebSocketProtocols` / `withWebSocketBeforeConnect` | Configure les options de session WebSocket par défaut.                                                    |
| `withHTTPHandle` / `withSSEHandle` / `withWebSocketHandle`                                                    | Injecte des implémentations de transport personnalisées ou simulées (mocks).                              |
