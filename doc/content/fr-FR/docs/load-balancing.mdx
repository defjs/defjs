# Équilibrage de charge et basculement

Lorsqu'une application configure plusieurs URL de base avec `withEndpoint(...urls)`, Defjs peut distribuer les requêtes entre les différents réplicas, éjecter les hôtes défaillants par coupure de circuit passive ou vérifications de santé actives, et basculer automatiquement les méthodes HTTP sûres au sein d'un même appel.

## 1. Choisir une stratégie de répartition de charge

| Stratégie                                                                     | Cas d'usage idéal                                                            | Filtrage de santé par défaut                          |
| ----------------------------------------------------------------------------- | ---------------------------------------------------------------------------- | ----------------------------------------------------- |
| [`pickFirstBalancer(options?)`](/fr-FR/api/core/pickfirstbalancer) _(Défaut)_ | Applications navigateur avec liste ordonnée région primaire + secours        | Désactivé (activable via l'option `outlierDetection`) |
| [`roundRobinBalancer(options?)`](/fr-FR/api/core/roundrobinbalancer)          | Appels inter-serveurs entre réplicas équivalents (prend en charge `weights`) | Activé (`5` échecs consécutifs)                       |
| [`p2cBalancer(options?)`](/fr-FR/api/core/p2cbalancer)                        | Appels serveur où la latence ou la charge des réplicas varie                 | Activé (`5` échecs consécutifs)                       |

### Fonctionnement de `pickFirstBalancer` et `p2cBalancer`

- **`pickFirstBalancer`** : Reste positionné sur la première URL jusqu'à ce qu'un échec de connexion (`NET_UNREACHABLE`) ou une réponse `502`, `503` ou `504` sans code ne fasse basculer vers l'URL suivante. Configurez `failbackMs: 30_000` pour sonder à nouveau l'endpoint primaire après avoir passé cette durée sur un secours.
- **`p2cBalancer` (Power of Two Choices)** : Tire au sort deux candidats distincts sans remise et sélectionne celui affichant le score le plus faible : `RTT PeakEwma × (en_cours + 1)` (ou le compte `pending` en cours lorsque `load: "pending"`). Les valeurs par défaut (`defaultRttMs: 30`, `decayMs: 10000`) suivent les conventions de Linkerd/tower.

## 2. Basculement HTTP au sein d'un même appel et budget de retry

Par défaut, HTTP active le **basculement au sein du même appel** pour les méthodes sûres (`GET`, `HEAD`, `OPTIONS`, `TRACE`) : si le premier endpoint sélectionné échoue avec `NET_UNREACHABLE`, Defjs choisit un endpoint de secours non encore tenté et réexécute le builder, la chaîne d'intercepteurs et le transport au sein du même appel d'opération.

Personnalisez ou désactivez cette politique via [`withEndpointFailover(options)`](/fr-FR/api/core/withendpointfailover) :

<include cwd lang="typescript">
  examples/client/endpoint-failover.ts#example
</include>

- **Conditions de rejeu (`retryOn`)** : Vaut par défaut `["connect-failure"]`. Vous pouvez y ajouter `"gateway-error"` (`502`/`503`/`504` non codé, ou `502`/`503`/`504` dont le corps d'erreur a échoué au décodage `RES_*`) et `"attempt-timeout"` (lorsque `attemptTimeoutMs` est configuré).
- **Délai par tentative vs délai pour tout l'appel** : `attemptTimeoutMs` borne une tentative unique de l'invocation Fetch jusqu'au décodage du corps ; le `client({ signal: AbortSignal.timeout(ms) })` de l'appelant borne l'ensemble de l'appel à travers toutes ses tentatives.
- **Budget de retry Finagle / Linkerd** : Tous les appels sur un client partagent un budget de retry à seau de jetons (`percentCanRetry: 0.2`, `minRetriesPerSecond: 10`, `ttlMs: 10000`) afin que les rejeux ne puissent amplifier le trafic de plus de ~20 % en cas d'incident généralisé. Spécifiez `retryBudget: false` pour désactiver ce plafond.
- **Indication hors ligne navigateur** : Lorsque `navigator.onLine === false`, les échecs de connexion sont notifiés avec `{ attempted: false }` et ne font pas avancer les répartiteurs ni ne déclenchent de basculement.

## 3. Détection passive des anomalies et contrôles de santé actifs (`outlierDetection`)

`roundRobinBalancer()` et `p2cBalancer()` enveloppent par défaut leur sélection de candidats dans [`outlierDetection`](/fr-FR/api/core/outlierdetection) :

1. **Échecs consécutifs** : Après `consecutiveFailures` (par défaut `5`) erreurs `NET_UNREACHABLE` ou statuts HTTP `500+`, l'endpoint est éjecté pendant `min(minPenaltyMs × 2^level, maxPenaltyMs)` (`1000ms` à `60000ms`) additionné d'un jitter uniforme positif pouvant atteindre `50 %`.
2. **Rétablissement par sonde unique** : Dès expiration de la pénalité, une unique requête sonde l'hôte. Si son handshake de transport (`end` : en-têtes HTTP/SSE ou `open` WebSocket) réussit, le trafic normal reprend immédiatement et le niveau de pénalité retombe à `0` ; en cas d'échec, la pénalité est doublée.
3. **Mode panique fail-open** : Si chaque endpoint configuré est éjecté ou déclaré défaillant, le répartiteur bascule en fail-open sur l'ensemble de la liste des candidats du client plutôt que d'abandonner localement tout le trafic.

## 4. Cycle de comptabilité du transport (`pick` → `start` → `end` → `done`)

Les répartiteurs personnalisés implémentent la méthode synchrone `pick(context)` et les callbacks optionnels `start()`, `end(info)` et `done(info)` :

| Issue physique du transport                                               | Échantillon final `done(info)`                             |
| ------------------------------------------------------------------------- | ---------------------------------------------------------- |
| Le corps de réponse HTTP est tronqué en cours de flux                     | `{ attempted: true, code: "NET_BODY_INCOMPLETE", status }` |
| Handshake SSE réussi, puis rejet de `reader.read()`                       | `{ attempted: true, code: "NET_UNREACHABLE" }`             |
| EOF normal de SSE, échec de décodage du handshake ou file saturée         | `{ attempted: true, status }`                              |
| WebSocket ouvert se refermant avec le code `1006` ou `wasClean === false` | `{ attempted: true, code: "NET_UNREACHABLE" }`             |
| WebSocket ouvert se refermant proprement                                  | `{ attempted: true }`                                      |
| Annulation par l'appelant ou fermeture manuelle du flux/socket            | `{ attempted: false }`                                     |
| Expiration du délai de l'appelant après démarrage de la tentative         | `{ attempted: true, code: "NET_TIMEOUT" }`                 |
