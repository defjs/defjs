# Flux d'événements SSE

Un SDK déclare un endpoint Server-Sent Events avec `defineEventStream`, en spécifiant son chemin, une entrée et un builder facultatifs, un dictionnaire `events` de structs et des limites de tampon et de file. L'application consommatrice configure l'authentification et la reconnexion opt-in sur son propre client, ouvre le flux, itère sur les événements typés et prend en charge la fermeture du flux.

## 1. Définir le flux d'événements et le consommer

Libérez toujours un handle `EventStreamHandle` ouvert avec `await using` (ou par `stream.close()` + `await stream.closed` dans un bloc `finally`) :

<Tabs items={["sdk/orders-stream.ts", "app/watch-orders.ts", "Single-file quick look"]}>
<Tab value="sdk/orders-stream.ts">

```ts
import { defineEventStream, struct } from "@defjs/core";

export const watchOrders = defineEventStream({
  path: "/orders/events",
  operation: "orders.watch",
  events: {
    updated: struct.object({
      id: struct.number(),
      status: struct.string(),
    }),
  },
});
```

</Tab>
<Tab value="app/watch-orders.ts">

```ts
import { createClient, withEndpoint } from "@defjs/core";
import { watchOrders } from "../sdk/orders-stream.ts";

const client = createClient(withEndpoint("https://api.example.com"));

async function main() {
  const [error, stream] = await watchOrders(client);
  if (error) {
    console.error(error.code);
    return;
  }

  await using active = stream;
  for await (const event of active) {
    console.log(event.event, event.data.id, event.data.status);
    break;
  }
}

void main();
```

## 2. Handshake d'ouverture et forme du tuple

L'appel de l'opération ne résout `[error, stream, startupOpen]` qu'une fois que la réponse HTTP initiale est `2xx`, que son media type est `text/event-stream` et qu'elle présente un corps lisible :

- **Handshake hors `2xx`** : Renvoie `HTTP_STATUS` (avec `error.data` décodé lorsqu'un struct `error` est déclaré sur la définition).
- **Media type invalide ou corps illisible** : Renvoie `RES_MEDIA_TYPE_INVALID` ou `RES_DECODE_FAILED`.
- **`startupOpen` vs `stream.open`** : Le troisième élément du tuple (`startupOpen`) capture l'instantané de la première réponse du handshake ; `stream.open` est mis à jour dynamiquement si le flux se reconnecte ultérieurement.

## 3. Routage et décodage des événements

Lorsqu'une trame SSE arrive (terminée par une ligne vide selon les spécifications WHATWG) :

1. **Routage de l'événement** : Le champ réseau `event:` sélectionne `events[eventName]`, avec repli sur `events.default` s'il est déclaré. Un champ `event:` omis prend la valeur par défaut `"message"`. Les événements non déclarés en l'absence de `events.default` sont ignorés.
2. **Décodage de la charge utile** : Un schéma `struct.string()` reçoit le texte brut `data:`. Tout autre type de struct analyse d'abord `data:` en JSON, puis valide le résultat avec le struct.
3. **Observation des événements invalides** : Les événements invalides ou non déclarés sont écartés sans interrompre le flux. Associez `withSSEOnInvalidEvent(...)` sur le client pour des diagnostics délimités :

## 4. Reconnexion et `Last-Event-ID` [#reconnect]

La reconnexion SSE est **opt-in**. Sans `withSSEReconnect(...)`, toute perte réseau ou erreur de lecture du flux met fin au flux logique.

<include cwd>examples/sse/reconnect.ts#example</include>

- **Budget de tentatives (`attempts`)** : Vaut `3` par défaut lorsqu'un objet d'options est transmis à `withSSEReconnect`. Un handshake réussi réinitialise le compteur de tentatives et l'exposant de backoff. Une fin de flux serveur normale (EOF) **n'est pas** un échec et ne déclenche aucune reconnexion.
- **Suivi du curseur (`Last-Event-ID`)** : Validé dès lors que la ligne vide finale d'un événement est analysée, et automatiquement envoyé sous forme d'en-tête `Last-Event-ID` lors de la reconnexion.
- **Sécurité et idempotence** : Par défaut, seules les méthodes idempotentes (`GET`, `HEAD`, `OPTIONS`, `PUT`, `DELETE`) se reconnectent automatiquement. Les méthodes non idempotentes (`POST`, `PATCH` — comme les requêtes de génération en streaming pour LLM) ne se reconnectent que si un callback `shouldReconnect` personnalisé renvoie explicitement `true`. Les corps de requête `ReadableStream` sont consommés à la première tentative et ne se reconnectent jamais.
- **Délai de connexion (`connectTimeoutMs`)** : Lorsqu'il est fourni, il doit être fini, positif et ne pas dépasser 2147483647 (la limite du minuteur) ; sinon l'opération renvoie `REQ_OPTIONS_INVALID`. Délimite chaque handshake depuis l'appel Fetch jusqu'aux en-têtes de réponse, sans limiter la durée d'ouverture d'un flux établi.

## 5. Limites de tampon et de file

Les deux limites doivent être des entiers sûrs positifs. Dépasser l'une de ces limites est fatal (`stream.closed` résout avec `kind: "error"` et l'itérateur rejette — aucun événement n'est abandonné silencieusement) :

| Option de définition | Ce qu'elle délimite                                                    | Code de fault terminal |
| -------------------- | ---------------------------------------------------------------------- | ---------------------- |
| `maxBufferSize`      | Octets d'une trame SSE incomplète ou trop volumineuse avant ligne vide | `CAP_BUFFER_EXCEEDED`  |
| `maxQueueSize`       | Événements validés en attente de consommation par `for await`          | `CAP_QUEUE_OVERFLOW`   |

## 6. Fermer et disposer [#close-and-dispose]

L'appelant qui ouvre un flux possède son cycle de nettoyage. Quitter une boucle `for await` via `break`, `return` ou une exception ferme automatiquement le flux, ou vous pouvez utiliser `await using` / `stream.close()` :
