# Couche API d'application [#application-api-layer]

La plupart des projets utilisent Defjs directement au sein du dépôt d'une application (`src/api/`) pour remplacer des wrappers `fetch` ou `axios` dispersés. Même lorsque vous n'avez pas l'intention de publier un paquet npm externe, séparer `src/api/schema/`, `src/api/request/` et `src/api/client.ts` permet de garder votre couche de requêtes fortement typée, testable en mémoire et sûre aussi bien dans le navigateur qu'en SSR.

---

## 1. Structure de répertoires recommandée pour `src/api/`

Organisez la couche de requêtes de votre projet en trois parties ciblées sous `src/api/` :

```text
src/
├── api/
│   ├── schema/           # 1. Schémas struct partagés + types Infer<typeof ...>
│   │   └── order.ts      #    ApiError, OrderStatus, Order, OrderPage
│   ├── request/         # 2. Définitions d'opérations pures regroupées par domaine
│   │   └── orders.ts     #    getOrder, listOrders, createOrder
│   └── client.ts         # 3. Client détenu par l'application (endpoint, intercepteur d'auth, réessai)
└── checkout.ts           # 4. Logique métier / composants UI appelant les opérations
```

`src/checkout.ts` est de la logique métier, pas le sommet du programme : `placeAndLoadOrder` ne journalise donc rien. Elle renvoie un tuple error-first, `Promise<[Error, undefined] | [null, Checkout]>`, et enveloppe le fault de chaque étape avec l'étape en échec (`new Error("create order", { cause: createErr })`), comme le `fmt.Errorf("create order: %w", err)` de Go. L'appelant, par exemple un gestionnaire d'événements d'interface, vérifie `if (err)` et décide comment l'afficher.

## 3. Modèles clés pour les projets d'application

### Singleton navigateur vs client par requête en SSR

- **Navigateur / SPA (`apiClient`)** : Exportez une unique instance `createClient(...)` à portée de module par origine backend. Partager cette instance préserve l'état de santé du répartiteur de charge ainsi que le budget de réessais HTTP au niveau du client au fil des interactions sur la page. Dans les applications React ou Vue, fournissez `apiClient` à la racine via [`@defjs/react`](/fr-FR/docs/integrations/react) (`ClientProvider` / `useClient`) ou [`@defjs/vue`](/fr-FR/docs/integrations/vue) (`createClientPlugin` / `injectClient`).
- **SSR / BFF (`createServerApiClient(accessToken)`)** : Chaque fois que les identifiants, les cookies ou les en-têtes de locataire varient selon la requête HTTP entrante, appelez une fonction de fabrique dans votre gestionnaire de requêtes serveur afin de créer un `Client` isolé. Comme `getOrder`, `listOrders` et `createOrder` sont des fonctions pures, exactement les mêmes définitions de `request/orders.ts` fonctionnent à la fois avec `apiClient` et `createServerApiClient(token)`.

### Délais d'expiration et annulation par appel

Ne créez jamais un nouveau `Client` via `createClient(...)` uniquement pour passer un délai d'expiration ou un `AbortSignal`. Dérivez plutôt en ligne un client à usage unique à partir de votre client partagé :

```ts
const [err, created] = await createOrder(
  apiClient({ signal: AbortSignal.timeout(5_000) }),
  {
    customerName: "Ada Lovelace",
    totalCents: 4200,
    idempotencyKey: "idem-2026-101",
  },
);
```

### Enveloppe d'erreur partagée (`ApiError`)

Déclarez une seule fois l'enveloppe d'erreur standard de votre backend (`export const ApiError = struct.object(...)`) dans `src/api/schema/` et passez `error: ApiError` sur chaque `defineRequest` de `src/api/request/`. Lorsqu'une requête renvoie un statut autre que `2xx`, l'affinement de type `if (err.code === "HTTP_STATUS")` dans `if (err)` vous donne un accès fortement typé à `err.data.code`, `err.data.message` et `err.data.requestId`.
