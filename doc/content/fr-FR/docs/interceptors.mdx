# Intercepteurs

Les intercepteurs rattachent des politiques d'exécution transversales — en-têtes d'authentification, signature de requêtes, court-circuit de maintenance ou rejeu de lectures sûres — au `Client` de l'application sans modifier les définitions d'opérations du SDK.

La validation de l'entrée et la projection par le `builder` s'exécutent **avant** la chaîne d'intercepteurs ; l'aiguillage par statut HTTP et la validation des structs `output` / `error` s'exécutent **après** la chaîne.

### Règles du pipeline d'intercepteurs

- **Modèle en oignon** : Les intercepteurs s'exécutent dans l'ordre d'enregistrement à l'aller (`avant next(req)`) et dans l'ordre inverse au retour (`après await next(req)`). Placez les intercepteurs larges de journalisation/traçage à l'extérieur des intercepteurs plus spécialisés d'authentification ou de retry.
- **Convention de requête immuable** : Clonez toujours `req.headers` (`new Headers(req.headers)`) et passez un nouvel objet de requête (`{ ...req, headers }`) à `next(...)` afin que les retries externes voient des en-têtes intacts.
- **`content-type` et `bodyContentType`** : Defjs conserve son type de contenu inféré sur `req.bodyContentType` sans altérer `req.headers`. Les mécanismes de signature de requête doivent lire `req.headers.get("content-type") ?? req.bodyContentType`. Si un intercepteur remplace `req.body` par un nouveau format, spécifiez un en-tête `content-type` explicite.

`makeResponse` ne constitue **pas** un contournement de validation : la réponse synthétique reste soumise à la vérification du media type de l'opération, à la bifurcation selon le statut (`2xx` vs non-`2xx`) et à la validation des structs `output` / `error`.

## 3. Rejouer les lectures HTTP sûres

Defjs ne réessaie pas automatiquement les statuts HTTP applicatifs. Lorsque vous avez besoin d'un rejeu basé sur le statut (par exemple sur `429`, `502`, `503`, `504` pour des appels idempotents `GET` / `HEAD` / `OPTIONS`), implémentez une boucle bornée dans un intercepteur HTTP :

<include cwd lang="typescript">
  examples/interceptors/retry-safe-reads.ts#example
</include>

- **Gestion des rejets de transport** : `next(request)` rejette lorsqu'une erreur réseau survient (il n'existe aucune réponse de statut 0). Intercepter et relancer ce rejet préserve le code de fault `NET_*` initial.
- **Exceptions au sein d'un intercepteur** : Une exception non gérée (ou le renvoi d'une valeur inadéquate) résout le tuple de l'opération avec `EXT_INTERCEPTOR_FAILED` et renseigne `fault.cause`. Lever `ERR_ABORTED` ou `ERR_TIMEOUT` résout avec `NET_ABORTED` ou `NET_TIMEOUT`.

## 4. Envelopper des sessions WebSocket

Un intercepteur WebSocket ne peut appeler `next(req)` **qu'une seule fois au maximum**. Lorsque vous enveloppez le `WebSocketSessionLike` renvoyé, déléguez explicitement les accesseurs dynamiques (`state`, `connection`, `bufferedAmount`), `close`, `closed`, `receive` et `[Symbol.asyncDispose]()` plutôt que de copier un instantané figé avec la syntaxe de déploiement (spread) :

## 5. Fabriques et helpers intégrés

| Export                                         | Transport | Description                                                                                     |
| ---------------------------------------------- | --------- | ----------------------------------------------------------------------------------------------- |
| `createHttpInterceptor(fn)`                    | HTTP      | Enveloppe `(req, next) => Promise<HttpResponse<unknown>>`                                       |
| `createSSEInterceptor(fn)`                     | SSE       | Enveloppe `(req, next) => Promise<EventStreamHandle<unknown>>`                                  |
| `createWebSocketInterceptor(fn)`               | WebSocket | Enveloppe `(req, next) => Promise<WebSocketSessionLike>`                                        |
| `basicAuthHttpInterceptor(provider, options?)` | HTTP      | Injecte `Authorization: Basic ...` depuis un fournisseur d'identifiants synchrone ou asynchrone |
| `basicAuthSSEInterceptor(provider, options?)`  | SSE       | Injecte `Authorization: Basic ...` sur les handshakes SSE                                       |
