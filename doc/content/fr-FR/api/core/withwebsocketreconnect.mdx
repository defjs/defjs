```ts
function withWebSocketReconnect(options: ClientWebSocketOptions['reconnect']): ClientOption
```

Configure la reconnexion automatique quand le socket se ferme pour toute raison autre qu’un `session.close()` manuel. La reconnexion est opt-in : sans cette option, une fermeture met fin à la session. Passer `undefined` efface un réglage précédent. Le type de l’option est :

```ts
{
  attempts?: number
  delayMs?: number
  factor?: number
  jitter?: number
  maxDelayMs?: number
  shouldReconnect?: (context: { attempt: number; cause?: unknown; code?: number; reason?: string; wasClean?: boolean }) => boolean
}
```

- `attempts` est le budget de nouvelles tentatives de chaque coupure. Il vaut `3` par défaut, et `0` désactive la reconnexion. Un `open` réussi réinitialise le budget et l’exposant de backoff ; la coupure suivante repart au retry 1. L’omettre ne donne pas un nombre illimité de nouvelles tentatives au sein d’une même coupure. Un socket qui s’ouvre avec succès puis est immédiatement refermé par le serveur peut continuer à se reconnecter avec le délai de base (sous réserve du jitter et des plafonds), car chaque ouverture réinitialise le budget ; utilise `shouldReconnect` pour l’arrêter.
- `delayMs` vaut `1000` par défaut, `factor` `2`, `maxDelayMs` `30000`, et `jitter` (0 à 1) `0`. La nouvelle tentative _n_ commence par `delayMs * factor^(n-1)`, plafonné à `maxDelayMs` ; le jitter et l’arrondi suivent, puis le délai final est de nouveau plafonné à `maxDelayMs` et à `2_147_483_647` ms. Une base nulle reste nulle ; le dépassement d’un nombre valide sature à ces plafonds.
- `shouldReconnect` peut renvoyer `false` pour mettre fin à la session. Sans elle, chaque fermeture est retentée tant que le budget dure. Elle n’est pas appelée pour un `session.close()` manuel.
- Quand le retry est activé, `attempts` doit être un entier sûr positif ou nul ; `delayMs` et `maxDelayMs` doivent être finis et positifs ou nuls ; `factor` doit être fini et strictement positif ; `jitter` doit être fini et compris entre 0 et 1. Les valeurs invalides font échouer execute avec `REQ_OPTIONS_INVALID` avant la connexion. `attempts: 0` désactive immédiatement le retry et ignore les champs de reconnexion inutilisés.
- Un `reconnect` dans les options d’execute remplace celui-ci pour cet appel.
