<ApiReference identity="@defjs/core:createResolvedRequestUrl" />

```ts
function createResolvedRequestUrl(baseEndpoint: string, path: string, queryString?: string): URL
```

- **baseEndpoint** — Un endpoint client absolu valide. Sa query et son hash sont supprimés, et une barre oblique finale est ajoutée à son pathname afin de conserver le chemin de base : `https://api.example.com/v1` avec `/users` donne `https://api.example.com/v1/users`.
- **path** — Un chemin d’endpoint relatif. Une barre oblique initiale unique est retirée. Après résolution, l’URL doit conserver l’origine de base et rester sous son répertoire. Les chemins absolus ou relatifs au protocole, les caractères de contrôle C0 (dont tab, CR et LF), les barres obliques inverses, `?`, `#` et les traversées de répertoire sont rejetés. Les formes ressemblant à un schéma et celles relatives au protocole sont rejetées même avec des espaces initiaux ; un espace ordinaire à l’intérieur est autorisé et envoyé sous la forme `%20`.
- **queryString** — Query sans `?` initial. Quand elle n’est pas vide, elle est définie telle quelle comme search de l’URL.
- **Renvoie** l’`URL` résolue.

Lève `TypeError` quand l’endpoint de base ou le chemin est invalide. Pendant `client.execute`, une base absente, relative ou invalide, ou un chemin illégal, devient `REQ_BUILD_FAILED` avant tout intercepteur ou transport, y compris un intercepteur qui court-circuite, pour HTTP, SSE et WebSocket. Le `req.endpoint` final d’un intercepteur est aussi validé contre son `req.baseEndpoint` final ; remplacer délibérément la base par une autre URL absolue valide est autorisé. Les erreurs d’URL déterministes ne sont jamais retentées.
