```ts
function defineEventStream<
  const P extends string,
  const M extends string = 'GET',
  TInput extends AnyStruct | undefined = undefined,
  TEvents extends EventStructs = EventStructs,
  TError extends AnyStruct | undefined = undefined,
>(
  definition: Omit<EventStreamDefinitionBase<TEvents>, 'method' | 'path'> &
    EventStreamErrorField<TError> & {
      input?: TInput
      method?: M
      path: P
    } & BuilderField<NoInfer<TInput>, EventStreamRequestShape<NoInfer<P>, NoInfer<M>>>,
): EventStreamEndpoint<TInput, TEvents, TError>
```

- **definition** — `path`, une map `events`, et les limites obligatoires `maxBufferSize` et `maxQueueSize` (entiers sûrs positifs). `method` (défaut `'GET'`), `operation`, `input` et `error` sont optionnels. Un `input` déclaré exige toujours un `builder` explicite, même si l’entrée a déjà la forme de la requête. Seules les définitions sans `input` peuvent omettre `builder`.
- **Renvoie** un endpoint. Appelle-le avec l’entrée pour obtenir un `EventStreamCommand`.

`EventStreamDefinitionBase`, `EventStreamErrorField` et `BuilderField` sont des types utilitaires internes : `error` n’est obligatoire que lorsque `TError` est un struct, et `builder` vaut `(input: BuilderInput<TInput>) => EventStreamRequestShape` quand `input` est déclaré.
