<ApiReference identity="@defjs/opentelemetry-server:OpenTelemetryServerTransportOptions" />

```ts
interface OpenTelemetryServerTransportOptions<TResponse> {
  enabled?: boolean
  startSpanHook?: (request: HttpRequest) => Attributes
  requestHook?: (span: Span, req: HttpRequest) => Promise<void> | void
  responseHook?: (span: Span, res: TResponse, req: HttpRequest) => Promise<void> | void
}
```

`TResponse` est ce que reçoit `responseHook` : `HttpResponse<unknown>` pour HTTP, `EventStreamHandle<unknown>` pour SSE, `WebSocketSessionLike` pour WebSocket. Voir [OpenTelemetryServerHttpOptions](/fr-FR/api/opentelemetry-server/opentelemetryserverhttpoptions-type), [OpenTelemetryServerSSEOptions](/fr-FR/api/opentelemetry-server/opentelemetryserversseoptions-type) et [OpenTelemetryServerWebSocketOptions](/fr-FR/api/opentelemetry-server/opentelemetryserverwebsocketoptions-type).

`enabled` vaut `true` par défaut ; seul `enabled: false` désactive le transport. L’ancien interrupteur booléen (`http: false`) et les hooks de premier niveau ne sont refusés que par les types TypeScript. Il n’y a pas de vérification à l’exécution : `http: false` laisse donc le transport activé, et un hook de premier niveau est ignoré silencieusement.

Les span hooks ne s’exécutent que si un `tracer` est fourni. `startSpanHook` s’exécute synchroniquement avant la création du span, pour son propre transport. Ses attributs sont appliqués après les attributs intégrés, donc l’application peut remplacer `url.full` ou une autre valeur initiale. S’il lève une exception, Defjs crée le span avec les attributs intégrés, enregistre un événement `defjs.otel.hook.error` et poursuit la requête. `requestHook` s’exécute après la création du span et avant l’envoi de la requête ; `responseHook` s’exécute après le retour du résultat du transport. Les deux peuvent renvoyer une promise, mais aucun n’est attendu : une exception ou un rejet est enregistré de la même façon et ne bloque ni ne fait jamais échouer l’opération. `responseHook` reçoit la requête d’origine en troisième argument.

Par défaut, `url.full` ne résout que `request.endpoint` contre l’éventuel `request.baseEndpoint` ; un `request.queryString` indépendant n’est pas ajouté.
