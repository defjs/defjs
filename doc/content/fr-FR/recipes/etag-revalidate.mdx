# Revalider avec ETag et un 304

`ok` veut dire 2xx, donc un `304` arrive comme un fault `HTTP_STATUS`. Un statut de redirection n’est pas non plus un corps d’erreur, donc laisse `error` non déclaré : le corps n’est jamais lu, le fault porte le statut, et tu renvoies toi-même le produit en cache.

Voir [HTTP](/fr-FR/docs/http).

`throw error` après la branche 304 est la frontière de ce lecteur. La fonction renvoie toujours `Promise<Product>` ; un fault qui n’est pas un 304 n’est pas renvoyé comme tuple Defjs depuis cette frontière.

Ne réécris pas `304` en faux `200` à l’intérieur de Core. La propriété du cache reste dans le code applicatif, autour de l’appel d’opération.
