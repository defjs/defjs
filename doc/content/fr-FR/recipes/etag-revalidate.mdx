# Revalider avec ETag et un 304

Dans Defjs, seules les réponses `2xx` empruntent la branche de succès, par conséquent un code `304 Not Modified` arrive sous la forme d'un fault `HTTP_STATUS`. Laissez `error` non déclaré sur `defineRequest` afin que le corps vide du `304` ne soit jamais lu, et maintenez votre cache `Map` dans un wrapper applicatif entourant l'appel d'opération :

<Tabs items={["sdk/catalog.ts", "app/reader.ts", "etag-cache.ts"]}>
  <Tab value="sdk/catalog.ts">
```ts
import { defineRequest, struct, type Infer } from "@defjs/core";

export const Product = struct.object({
  sku: struct.string(),
  name: struct.string(),
  priceCents: struct.number(),
});

export type Product = Infer<typeof Product>;

export const readProduct = defineRequest({
  method: "GET",
  path: "/catalog/:sku",
  input: struct.object({
    sku: struct.string(),
    etag: struct.string().optional(),
  }),
  builder: (input) => ({
    path: { sku: input.sku },
    headers: { "If-None-Match": input.etag },
  }),
  output: Product,
});
```

  <Tab value="app/reader.ts">
```ts
import type { DerivableClient } from "@defjs/core";
import { readProduct, type Product } from "../sdk/catalog.ts";

export function createReader(client: DerivableClient) {
  const cache = new Map<string, { etag: string; product: Product }>();

return async (sku: string): Promise<Product> => {
const cached = cache.get(sku);
const [error, product, response] = await readProduct(client, {
sku,
etag: cached?.etag,
});

    if (error?.code === "HTTP_STATUS" && error.status === 304 && cached) {
      return cached.product;
    }
    if (error) throw error;

    const etag = response.headers.get("etag");
    if (!etag) throw new Error("missing ETag");
    cache.set(sku, { etag, product });
    return product;

};
}

````

- `if (error) throw error` après la vérification du code `304` constitue une frontière explicite pour `createReader`, qui renvoie une `Promise<Product>`.
- Ne réécrivez jamais un `304` en un faux `200` dans un intercepteur ; maintenez l'état du cache dans le code applicatif autour de l'appel d'opération. Consultez [Opérations HTTP](/fr-FR/docs/http).
