# Créer et publier un SDK [#publish-an-http-sdk-without-hiding-execute]

Un SDK Defjs organise des modèles `struct` partagés (`src/models/`) et des modules d'opérations métier (`src/services/`) au sein d'un paquet npm optimisé pour le _tree-shaking_, tout en déléguant `createClient(...)`, les endpoints, les identifiants et les intercepteurs à l'application consommatrice.

Contrairement aux générateurs OpenAPI historiques qui encapsulent les endpoints dans des classes `Service` à état (`ObjectsService.putObject(...)`), un SDK Defjs exporte **des fonctions d'opération pures et autonomes** (`putObject`, `getObject`, `listObjectsV2`) appelées directement avec le client de l'application.

---

## 1. Structurer et définir le paquet du SDK

En prenant pour exemple un SDK de stockage d'objets compatible Amazon S3 (`@company/s3-sdk`), découpez le paquet en deux couches :

- **`src/models/`** : Schémas `struct` partagés et types TypeScript `Infer<typeof ...>` (en utilisant des exports de valeur et de type portant le même nom afin que les consommateurs puissent importer un seul identifiant à la fois pour les schémas à l'exécution et pour les types statiques).
- **`src/services/`** : Modules métier regroupés par ressource (`buckets.ts`, `objects.ts`). Chaque module exporte des fonctions `defineRequest` autonomes dont le `builder` synchrone répartit une entrée d'appel à plat entre `path`, `query`, `headers` et le `body` binaire.

- **Des fonctions pures, jamais de classes `Service`** : Chaque opération (`listBuckets`, `listObjectsV2`, `getObject`, `putObject`, `deleteObject`) est exportée comme une valeur `defineRequest` indépendante. Ne les encapsulez pas dans une `class` ou un objet d'espace de noms : des fonctions autonomes conservent une convention d'appel identique à `@defjs/core` (`await putObject(client, input)`) et permettent aux bundlers de tree-shaker les endpoints inutilisés lorsque `"sideEffects": false` est défini.
- **Réponses vides, binaires ou structurées** : `listBuckets` et `listObjectsV2` décodent des structs JSON avec des correspondances réseau `.alias()` ; `getObject` décode un `Blob` binaire (`output: struct.blob()`) ; `putObject`, `headObject` et `deleteObject` omettent `output` pour les corps de réponse vides tout en continuant d'exposer `response.headers` (comme `etag`) dans le troisième élément du tuple.
- **Dépendance pair externe à l'exécution** : `@defjs/core` reste une `peerDependency` partagée avec l'application consommatrice.

---

## 2. Compiler et vérifier l'archive (tarball)

Empaquetez `dist/index.js` et `dist/index.d.ts` avec `tsdown`, puis inspectez le contenu du paquet avant publication :

```sh
bun install
bun run build
bun pm pack --dry-run
bun pm pack
```

Vérifiez que `dist/index.js` et `dist/index.d.ts` figurent bien dans la tarball.

---

## 3. Consommer le SDK dans une application

Installez votre SDK aux côtés de `@defjs/core` :

```sh
bun add @company/s3-sdk @defjs/core@^0.8.0
```

Comme le SDK ne lie aucun client, l'application consommatrice est propriétaire de l'endpoint (AWS S3, Cloudflare R2 ou MinIO), de l'intercepteur de signature et de la politique de réessai, et appelle directement chaque opération importée comme une fonction pure. Comme `syncReport` effectue trois appels, elle nomme chaque erreur d'après son étape (`putErr`, `listErr`, `getErr`) et renvoie un tuple error-first dont l'erreur enveloppe l'étape en échec, comme le `fmt.Errorf("put object: %w", err)` de Go. Seul `main` la journalise :


En production, remplacez l'import relatif `./src/index.ts` par `@company/s3-sdk` et supprimez `withHTTPHandle(...)` pour exploiter le `fetch` de la plateforme.

---

## 4. Tester et publier

Éprouvez vos définitions exportées avec des [tests en mémoire avec handle](/fr-FR/recipes/test-with-handle) couvrant la projection du chemin/de la requête/des en-têtes/du corps binaire, le décodage d'`output`, les en-têtes de réponse `ETag`, les erreurs `HTTP_STATUS` (`S3Error`) déclarées et l'annulation. Une fois les vérifications effectuées, publiez le paquet :

```sh
bun publish --access public
```

Consultez [Opérations HTTP](/fr-FR/docs/http), [Client](/fr-FR/docs/client), [Tests](/fr-FR/docs/testing) et [Architecture du cœur](/fr-FR/docs/design-decisions).
