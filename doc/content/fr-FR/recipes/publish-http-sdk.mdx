# Créer et publier un SDK [#publish-an-http-sdk-without-hiding-execute]

Un SDK Defjs exporte de pures définitions d'opérations et des schémas Struct sous forme de paquet npm, tout en déléguant `createClient(...)`, les endpoints, les identifiants et les intercepteurs à l'application consommatrice.

---

## 1. Définir le paquet du SDK

Conservez vos définitions d'opérations, les exports de point d'entrée, `package.json` et `tsconfig.json` dans un répertoire dédié au paquet avec `@defjs/core` déclaré comme `peerDependency` :

<include cwd meta='title="src/orders.ts"'>

  </Tab>
  <Tab value="src/index.ts">
```ts
export { getOrder } from "./orders";
```
  </Tab>
  <Tab value="package.json">
```json
{
  "name": "@company/orders-sdk",
  "version": "0.1.0",
  "type": "module",
  "sideEffects": false,
  "files": ["dist"],
  "exports": {
    ".": {
      "types": "./dist/index.d.ts",
      "default": "./dist/index.js"
    }
  },
  "scripts": {
    "build": "tsdown --platform neutral"
  },
  "peerDependencies": {
    "@defjs/core": "^0.6.0"
  },
  "devDependencies": {
    "@defjs/core": "^0.6.0",
    "tsdown": "^0.23.3",
    "typescript": "^7.0.2"
  }
}
```
  </Tab>
  <Tab value="tsconfig.json">
```json
{
  "compilerOptions": {
    "target": "ES2022",
    "module": "ESNext",
    "moduleResolution": "bundler",
    "lib": ["ES2022", "ESNext.Disposable", "DOM", "DOM.Iterable"],
    "strict": true,
    "noEmit": true
  },
  "include": ["src/**/*.ts"]
}
```
  </Tab>
</Tabs>

- `@defjs/core` reste une dépendance externe `peerDependency` partagée avec l'application consommatrice.
- `"sideEffects": false` permet aux bundlers de tree-shaker les endpoints non utilisés lorsqu'une application n'importe qu'un sous-ensemble d'opérations.

---

## 2. Compiler et vérifier l'archive (tarball)

Empaquetez `dist/index.js` et `dist/index.d.ts` avec `tsdown`, puis inspectez le contenu du paquet avant publication :

```sh
bun install
bun run build
bun pm pack --dry-run
bun pm pack
```

Vérifiez que `dist/index.js` et `dist/index.d.ts` figurent bien dans la tarball.

---

## 3. Consommer le SDK dans une application

Installez votre SDK aux côtés de `@defjs/core` :

```sh
bun add @company/orders-sdk @defjs/core@^0.6.0
```

L'application crée son propre `Client` et le transmet à l'opération importée :

<include cwd meta='title="app.ts"'>
  examples/recipes/publish-http-sdk/app.ts#example
</include>

```txt
paid
```

En production, remplacez l'import relatif `./orders-sdk` par `@company/orders-sdk` et supprimez `withHTTPHandle(...)` pour exploiter le `fetch` de la plateforme.

---

## 4. Tester et publier

Éprouvez vos définitions exportées avec des [tests en mémoire avec handle](/fr-FR/recipes/test-with-handle) couvrant la projection de requête, le décodage d'`output`, les erreurs `HTTP_STATUS` déclarées et l'annulation. Une fois les vérifications effectuées, publiez le paquet :

```sh
bun publish --access public
```

Consultez [Opérations HTTP](/fr-FR/docs/http), [Client](/fr-FR/docs/client), [Tests](/fr-FR/docs/testing) et [Architecture du cœur](/fr-FR/docs/design-decisions).
