# GET avec un 404 déclaré

Déclare les corps de succès et de 404. Branche sur `error.code` et `error.status` — tu obtiens un `error.data` typé pour l’absence déclarée.

Voir [HTTP](/fr-FR/docs/http) et [Gestion des erreurs](/fr-FR/docs/errors) pour les détails.

`api.example.com` est un placeholder. Avec un serveur qui répond à `GET /orders/7` par `200` et `{ "id": 7, "status": "paid" }`, le snippet affiche :

```txt
Loaded paid from 200
```

Un statut non-2xx est `HTTP_STATUS`. Déclarer `error` donne un type à son corps ; omettre `error` laisse `error.data` à `undefined` et le corps non lu. Si un corps `error` déclaré ne peut pas être lu (mauvais media type, JSON invalide, mauvaise forme), le résultat est un fault `RES_*` à la place. Un seul Struct `error` couvre chaque statut non-2xx, donc utilise `struct.or(...)` ou une union discriminée quand les formes diffèrent.
