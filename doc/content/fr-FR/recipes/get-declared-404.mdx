# GET avec un 404 déclaré

Déclare les corps de succès et de 404. Branche sur `error.code` et `error.status` — tu obtiens `error.data` typé pour le miss déclaré.

Voir [HTTP](/fr-FR/docs/http) et [Erreurs](/fr-FR/docs/errors) pour les détails.

`api.example.com` est un placeholder. Avec un serveur qui répond à `GET /users/7` par `200` et `{ "id": 7, "name": "Ada" }`, le snippet affiche :

```txt
Loaded Ada from 200
```

Un statut non-2xx est `HTTP_STATUS`. Déclarer `error` donne un type à son corps ; l’omettre laisse `error.data` à `undefined` et le corps non lu. Si un corps `error` déclaré ne peut pas être lu (mauvais media type, JSON invalide, mauvaise forme), le résultat est un fault `RES_*` à la place. Un seul Struct `error` couvre tous les statuts non-2xx : utilise donc `struct.or(...)` ou une union discriminée quand les formes diffèrent.
