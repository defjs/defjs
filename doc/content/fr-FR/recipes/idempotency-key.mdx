# Clés d'idempotence

Par défaut, `withRetry` ne réessaie que les méthodes HTTP idempotentes (`GET`, `HEAD`, `PUT`, `DELETE`, `OPTIONS`, `TRACE`). Lorsque vous activez les retries sur des endpoints `POST` ou `PATCH`, associez `withRetry` à `idempotencyKeyHttpInterceptor()` afin que chaque tentative de retry d'un même appel logique réutilise `req.correlationId` comme en-tête `Idempotency-Key`, tandis que les appels suivants reçoivent de nouvelles clés.
