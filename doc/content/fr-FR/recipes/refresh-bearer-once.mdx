# Renouveler un Bearer une fois sur 401

`next()` est le reste de **cet** oignon — pas un `axios(config)` redistribué depuis l’extérieur. Place l’attache, le refresh single-flight et un seul rejeu dans **un** intercepteur HTTP pour que les couches extérieures ne tournent pas deux fois.

Voir [Intercepteurs](/fr-FR/docs/interceptors).

<include cwd meta="refresh-bearer.ts">
  examples/recipes/refresh-bearer-once.ts#example
</include>

```txt
42
```

Appeler `next` à nouveau ne réentre que dans les intercepteurs **à l’intérieur** de cette couche (et le handler Fetch). Cela ne relance pas les wrappers extérieurs de timing ou d’auth — c’est pourquoi le traitement du 401 appartient à un seul intercepteur, pas à un second appel de l’opération.
