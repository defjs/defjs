# Renouveler un Bearer une fois sur 401

Dans Defjs, `next(request)` invoque la portion restante de la chaîne d'intercepteurs vers l'intérieur — sans jamais relancer le flux depuis l'intercepteur le plus externe. Regroupez l'injection du jeton, la déduplication du rafraîchissement (single-flight) et le rejeu unique suite à une réponse `401` dans **un seul** intercepteur HTTP afin que les intercepteurs externes de journalisation ou de mesure ne s'exécutent pas deux fois :

Un corps rejouable n’est pas une opération métier répétable. Cet intercepteur renvoie aussi un `POST` JSON après une réponse 401 correspondante : deux livraisons HTTP, d’abord rejetée puis acceptée. Ne l’utilisez pour les écritures que si l’authentification rejette la première livraison avant l’exécution du gestionnaire métier ; conservez une clé d’idempotence stable entre les deux livraisons et utilisez une déduplication côté serveur. Si ce contrat est indisponible, renvoyez la 401 au lieu de rejouer automatiquement l’écriture. L’exemple complet ne rejoue pas un corps de requête `ReadableStream`.

Consultez [Intercepteurs](/fr-FR/docs/interceptors) pour approfondir le modèle en oignon et les frontières de rejeu.
