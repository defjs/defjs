# Consommer un flux SSE

Chaque `EventStreamHandle` expose un unique itérateur asynchrone. Placez systématiquement `stream.close(...)` et `await stream.closed` dans un bloc `finally` afin qu'un `break` ou un `return` anticipé ne laisse pas fuiter le flux Fetch sous-jacent :

Avec un serveur dont le premier événement est `line` avec les données `{ "text": "build started" }`, le script affiche :

```txt
build started
```

- SSE ne se reconnecte pas automatiquement lors d'une déconnexion réseau ou d'une erreur de lecture sans avoir configuré [`withRetry(...)`](/fr-FR/api/core/withretry) sur le client.
- Lorsque `withSSEReconnect(...)` est configuré, `attempts` vaut `3` par défaut par coupure et se réinitialise après un handshake réussi (`attempts: 0` désactive la reconnexion). Sans callback personnalisé `shouldReconnect`, seules les requêtes `GET`, `HEAD`, `OPTIONS`, `PUT` et `DELETE` se reconnectent. Une requête dont le corps est un `ReadableStream` ne se reconnecte jamais. Consultez [Flux d'événements SSE](/fr-FR/docs/sse).
