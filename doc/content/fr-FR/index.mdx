# Defjs

**Conçu pour de meilleurs SDK.**

Defjs aide les équipes à transformer leurs API en SDK TypeScript réutilisables. `def` veut dire `define` : décris les opérations que ton service propose, exporte-les depuis un module ou un paquet npm, et laisse chaque application configurer son propre client pour les appeler.

## Définir le SDK, configurer l’application

| Auteur du SDK                                                                        | Consommateur du SDK                                                               |
| ------------------------------------------------------------------------------------ | --------------------------------------------------------------------------------- |
| Définir les opérations, l’entrée, le mapping de requête, les réponses et les erreurs | Choisir l’adresse du service, les identifiants, les intercepteurs et le transport |
| Exporter des endpoints HTTP, SSE et WebSocket typés                                  | Importer ces endpoints et les appeler avec un client Defjs                        |
| Maintenir et publier le contrat d’API                                                | Traiter les résultats et posséder l’annulation, les flux et les sessions          |

Une définition de SDK ne capture pas le client d’une application. Le même endpoint exporté peut servir une application navigateur, un serveur ou un test local avec des configurations de client différentes. Les deux côtés utilisent quand même le contrat d’exécution Defjs et des versions de Core compatibles.

Le SDK exporte une opération :

<include cwd meta="get-health.ts">
  examples/home/get-health.ts#example
</include>

L’application l’importe et possède l’exécution :

<include cwd meta="app.ts">
  examples/home/app.ts#example
</include>

Appeler `getHealth(client)` démarre la requête. Quand tu publies la définition, les consommateurs l’importent depuis ton paquet SDK au lieu du fichier local.

## Bonne pratique

Une définition reste indépendante du client. Passe le client de l’application en premier argument, comme dans `getHealth(client)`. L’application possède aussi l’adresse du service et les identifiants. Inspecte d’abord le tuple error-first. Quand `error` est présent, signale `error.code` et sors de la fonction avant de lire la valeur de succès.

## Construire ton SDK

1. [Définis et lance ta première opération](/fr-FR/docs/start) dans des fichiers SDK et application séparés.
2. Décris les [contrats de données](/fr-FR/docs/struct) et les [opérations HTTP](/fr-FR/docs/http) que ton SDK exporte.
3. [Teste et publie un paquet SDK](/fr-FR/recipes/publish-http-sdk) avec le JavaScript, les déclarations et une dépendance Core compatible.
4. Configure le [Client](/fr-FR/docs/client) de l’application consommatrice, puis ajoute une intégration de framework ou d’observabilité là où il le faut.

Les [décisions de conception](/fr-FR/docs/design-decisions) expliquent pourquoi les définitions d’API et l’exécution ont des propriétaires distincts. Tu peux utiliser la même structure dans une seule application avant de publier un paquet.

## Choisis un transport

| Ton besoin                        | Commence par                        | Résultat en succès                                                                 |
| --------------------------------- | ----------------------------------- | ---------------------------------------------------------------------------------- |
| Requête + réponse selon le statut | [HTTP](/fr-FR/docs/http)            | Données décodées + `DecodedResponse` (`HttpMeta` quand aucun output n’est déclaré) |
| Flux d’événements serveur durable | [SSE](/fr-FR/docs/sse)              | Un flux + instantané `open` au démarrage                                           |
| Session bidirectionnelle          | [WebSocket](/fr-FR/docs/web-socket) | Une session + instantané `connection` au démarrage                                 |

Les trois transports suivent la même séquence : définir une opération, puis l’appeler avec le client de l’application et l’entrée de l’appelant.

## Choisis un package

| Package                       | Quand                                                                                                           |
| ----------------------------- | --------------------------------------------------------------------------------------------------------------- |
| `@defjs/core`                 | Définir les opérations et contrats du SDK ; créer des clients et appeler des opérations HTTP, SSE et WebSocket  |
| `@defjs/react`                | `ClientProvider` / `useClient` — voir [React](/fr-FR/docs/integrations/react)                                   |
| `@defjs/vue`                  | Plugin + `injectClient` — voir [Vue](/fr-FR/docs/integrations/vue)                                              |
| `@defjs/opentelemetry-server` | Spans, métriques et logs sortants — voir [Serveur OpenTelemetry](/fr-FR/docs/integrations/opentelemetry-server) |

## Formes de résultat

Les trois transports renvoient un tuple de trois éléments, erreur en premier. Les positions correspondent ; les sens non :

- HTTP → `[error, data, response]`
- SSE → `[error, stream, open]`
- WebSocket → `[error, session, connection]`

En cas d’échec, le deuxième élément vaut `undefined`. Pour HTTP, le troisième vaut aussi `undefined`, car le fault porte les métadonnées de la réponse. Pour SSE et WebSocket, le troisième élément est l’instantané de démarrage s’il a été capturé avant l’échec. Voir [Gestion des erreurs](/fr-FR/docs/errors).

## Propriété en une phrase

Annule HTTP quand c’est périmé. Ferme SSE et `await stream.closed`. Ferme WebSocket et `await session.closed`. Sur un serveur, crée le client dans la frontière de la requête quand les options capturent cookies, auth ou données de tenant. Masque les URL, en-têtes et corps avant de les journaliser.

Defjs fournit les définitions, la validation et l’exécution. Les applications choisissent les politiques de cache et de nouvelle tentative ; la reconnexion des flux est opt-in. Les paquets SDK écrits à la main sont pris en charge aujourd’hui. L’outillage CLI et la génération OpenAPI/SDK restent prévus.
