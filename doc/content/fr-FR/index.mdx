# Defjs

**Conçu pour de meilleurs SDK.**

Defjs signifie **define js** : il facilite la conception, l’écriture et la publication de SDK d’API. L’auteur du SDK exporte des endpoints typés et réutilisables avec `defineRequest`, `defineEventStream` et `defineWebSocket`. L’application importe ces endpoints et les exécute avec son propre client Defjs.

| Auteur du SDK                                                               | Application                                                               |
| --------------------------------------------------------------------------- | ------------------------------------------------------------------------- |
| Définir les opérations, méthodes et chemins relatifs de l’API               | Configurer l’URL de base et le transport de l’environnement               |
| Décrire entrées, sorties, erreurs, événements et messages avec Struct       | Configurer l’authentification, les intercepteurs et la télémétrie         |
| Placer les entrées dans la requête avec `builder` et exporter les endpoints | Exécuter les commandes, traiter les résultats et gérer annulation et flux |

Le SDK exporte l’endpoint :

<include cwd meta="get-health.ts">
  examples/home/get-health.ts#example
</include>

L’application fournit le client et exécute la commande :

<include cwd meta="app.ts">
  examples/home/app.ts#example
</include>

Définition et exécution restent liées au contrat Defjs. Le client de l’application apporte la configuration d’exécution ; les endpoints conservent leurs méthodes, chemins et contrats de transport.

## Bonne pratique

Une définition reste indépendante du client. L’appeler crée seulement une commande. Donne-lui un nom, puis passe ce nom à `client.execute` sur le client que l’application possède. L’application possède aussi l’adresse du service et les identifiants. Inspecte d’abord le tuple error-first. Quand `error` est présent, signale `error.code` et sors de la fonction avant de lire la valeur de succès.

Commence par le [démarrage rapide](/fr-FR/docs/start), découvre [Struct](/fr-FR/docs/struct), les [commandes](/fr-FR/docs/commands) et le [client](/fr-FR/docs/client), puis [publie ton SDK](/fr-FR/recipes/publish-http-sdk). Les [décisions de conception](/fr-FR/docs/design-decisions) expliquent cette répartition.

Defjs ne met pas les résultats en cache et n’organise pas les tentatives à l’échelle de l’application. L’application décide de ces politiques, de l’annulation et du nettoyage.

## Choisis un transport

| Ton besoin                        | Commence par                        | Résultat en succès                                                                          |
| --------------------------------- | ----------------------------------- | ------------------------------------------------------------------------------------------- |
| Requête + réponse selon le statut | [HTTP](/fr-FR/docs/http)            | Données décodées + `DecodedResponse` (`HttpMeta` quand aucun struct `output` n’est déclaré) |
| Flux d’événements serveur durable | [SSE](/fr-FR/docs/sse)              | Un flux + instantané `open` au démarrage                                                    |
| Session bidirectionnelle          | [WebSocket](/fr-FR/docs/web-socket) | Une session + instantané `connection` au démarrage                                          |

## Choisis un package

| Package                       | Quand                                                                                                          |
| ----------------------------- | -------------------------------------------------------------------------------------------------------------- |
| `@defjs/core`                 | `defineRequest`, `defineEventStream`, `defineWebSocket`, `struct` et `createClient`                            |
| `@defjs/react`                | `ClientProvider` / `useClient` — voir [React](/fr-FR/docs/integrations/react)                                  |
| `@defjs/vue`                  | Plugin + `injectClient` — voir [Vue](/fr-FR/docs/integrations/vue)                                             |
| `@defjs/opentelemetry-server` | Spans, métriques et logs sortants — voir [OpenTelemetry Server](/fr-FR/docs/integrations/opentelemetry-server) |

## Formes de résultat

Les trois transports renvoient un tuple de trois éléments, erreur en premier. Les positions correspondent ; les sens non :

- HTTP → `[error, data, response]`
- SSE → `[error, stream, open]`
- WebSocket → `[error, session, connection]`

En cas d’échec, le deuxième élément vaut `undefined`. Pour HTTP, le troisième vaut aussi `undefined`, car le fault porte les métadonnées de la réponse. Pour SSE et WebSocket, le troisième élément est l’instantané de démarrage s’il a été capturé avant l’échec. Voir [Erreurs](/fr-FR/docs/errors).

## Propriété en une phrase

Annule HTTP quand c’est périmé. Ferme SSE et `await stream.closed`. Ferme WebSocket et `await session.closed`. Sur un serveur, crée le client dans la frontière de la requête quand les options capturent cookies, auth ou données de tenant. Masque les URL, en-têtes et corps avant de les journaliser.
