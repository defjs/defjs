```ts
function withWebSocketReconnect(options: ClientWebSocketOptions['reconnect']): ClientOption
```

Configura la reconexión automática cuando el socket se cierra por cualquier motivo distinto de un `session.close()` manual. La reconexión es opt-in: sin esta opción, un cierre termina la sesión. Pasar `undefined` borra un ajuste anterior. El tipo de la opción es:

```ts
{
  attempts?: number
  delayMs?: number
  factor?: number
  jitter?: number
  maxDelayMs?: number
  shouldReconnect?: (context: { attempt: number; cause?: unknown; code?: number; reason?: string; wasClean?: boolean }) => boolean
}
```

- `attempts` es el presupuesto de reintentos de cada interrupción. Vale `3` por defecto y `0` desactiva la reconexión. Un `open` correcto reinicia el presupuesto y el exponente de backoff; la siguiente interrupción empieza en el reintento 1. Omitirlo no da reintentos ilimitados dentro de una misma interrupción. Un socket que se abre correctamente y que el servidor vuelve a cerrar inmediatamente puede seguir reconectándose con el retraso base (sujeto al jitter y los topes), porque cada apertura reinicia el presupuesto; usa `shouldReconnect` para detenerlo.
- `delayMs` vale `1000` por defecto, `factor` `2`, `maxDelayMs` `30000` y `jitter` (de 0 a 1) `0`. El reintento _n_ empieza con `delayMs * factor^(n-1)`, limitado a `maxDelayMs`; después vienen el jitter y el redondeo, y el retraso final se vuelve a limitar a `maxDelayMs` y a `2_147_483_647` ms. Una base cero sigue siendo cero; el desbordamiento de números válidos se satura en esos topes.
- `shouldReconnect` puede devolver `false` para terminar la sesión en su lugar. Sin él, se reintenta cada cierre mientras dure el presupuesto. No se llama para un `session.close()` manual.
- Con el reintento habilitado, `attempts` debe ser un entero seguro no negativo; `delayMs` y `maxDelayMs` deben ser finitos y no negativos; `factor` debe ser finito y positivo; `jitter` debe ser finito y estar entre 0 y 1. Los valores no válidos hacen que execute falle con `REQ_OPTIONS_INVALID` antes de conectar. `attempts: 0` desactiva el reintento de inmediato e ignora los campos de reconexión que no se usan.
- Un `reconnect` en las opciones de execute sustituye a este para esa llamada.
