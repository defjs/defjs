<ApiReference identity="@defjs/core:createResolvedRequestUrl" />

```ts
function createResolvedRequestUrl(baseEndpoint: string, path: string, queryString?: string): URL
```

- **baseEndpoint** — Un endpoint de cliente absoluto y válido. Se descartan su query y su hash, y se añade una barra final a su pathname para conservar el path base: `https://api.example.com/v1` con `/users` da `https://api.example.com/v1/users`.
- **path** — Un path de endpoint relativo. Se elimina una única barra inicial. Tras la resolución, la URL debe conservar el origen base y permanecer bajo su directorio. Se rechazan los paths absolutos o relativos al protocolo, los caracteres de control C0 (incluidos tab, CR y LF), las barras invertidas, `?`, `#` y los escapes de directorio. Las formas similares a un esquema y las relativas al protocolo se rechazan incluso con espacios iniciales; se permite un espacio ordinario en el interior y se envía como `%20`.
- **queryString** — Query sin `?` inicial. Cuando no está vacía, se asigna tal cual como search de la URL.
- **Devuelve** la `URL` resuelta.

Lanza `TypeError` cuando el endpoint base o el path no son válidos. Durante `client.execute`, un base ausente, relativo o no válido, o un path ilegal, se convierte en `REQ_BUILD_FAILED` antes de que se ejecute cualquier interceptor o transporte, incluido un interceptor que cortocircuite, tanto en HTTP como en SSE y WebSocket. El `req.endpoint` final de un interceptor también se valida contra su `req.baseEndpoint` final; sustituir deliberadamente el base por otra URL absoluta válida está permitido. Los errores de URL deterministas nunca se reintentan.
