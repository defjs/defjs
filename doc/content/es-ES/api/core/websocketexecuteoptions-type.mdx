<ApiReference identity="@defjs/core:WebSocketExecuteOptions" />

```ts
type WebSocketExecuteOptions<TIncoming = unknown, TOutgoing = unknown> = UseWebSocketConfig<TIncoming, TOutgoing> & {
  signal?: AbortSignal
}
```

[`UseWebSocketConfig`](/es-ES/api/core/usewebsocketconfig-type) más `signal`. Expandido:

```ts
type WebSocketExecuteOptions<TIncoming = unknown, TOutgoing = unknown> = {
  beforeConnect?: (context: { attempt: number; signal: AbortSignal }) => void | Promise<void>
  heartbeat?: WebSocketHeartbeatConfig<TIncoming, TOutgoing>
  protocols?: readonly string[]
  reconnect?: ClientWebSocketOptions['reconnect']
  signal?: AbortSignal
} & ({ abort?: AbortSignal; timeout?: never } | { abort?: never; timeout?: number })
```

- `abort` y `timeout` son mutuamente excluyentes. El tipo rechaza pasar los dos y, en runtime, pasarlos falla con un fault `REQ_OPTIONS_INVALID`.
- `signal` se combina con cualquiera de los dos; no es un alias de `abort`.
- `timeout` debe ser un entero seguro positivo no mayor que `2_147_483_647`. Limita cuánto puede tardar la apertura de la sesión y no se vuelve a aplicar en un reconnect.
- `beforeConnect`, `heartbeat`, `protocols` y `reconnect` sustituyen las opciones del cliente para esta llamada.
- Cuando se define `reconnect`, `attempts` vale `3` por defecto; `0` lo desactiva. Omitir `attempts` no significa ilimitado.

Consulta [`WebSocketHeartbeatConfig`](/es-ES/api/core/websocketheartbeatconfig-type).
