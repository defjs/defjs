```ts
function withXSRF(options?: {
  cookieName?: string
  headerName?: string
  tokenProvider?: (context: { request: HttpRequest }) => string | null | undefined
}): ClientOption
```

Habilita el reenvío del token XSRF para las solicitudes **HTTP**. Las solicitudes SSE y WebSocket no reciben el header.

- `cookieName` vale `XSRF-TOKEN` por defecto y `headerName`, `X-XSRF-TOKEN`.
- El header se establece solo cuando se cumple todo lo siguiente: el método no es `GET`, `HEAD`, `OPTIONS` ni `TRACE`; la solicitud no tiene ya ese header; el cliente tiene un endpoint; y, en un navegador, la URL de la solicitud tiene el mismo origen que la página.
- Sin `tokenProvider`, el token se lee de `document.cookie` y se decodifica como URL. Fuera de un navegador no hay cookie, así que no se establece ningún header.
- Con `tokenProvider`, la cookie nunca se lee. El provider recibe la solicitud y su resultado es el token. Una cadena vacía, `null` o `undefined` significa que no hay header.

Consulta la [guía HTTP](/es-ES/docs/http) para el comportamiento a nivel de solicitud.
