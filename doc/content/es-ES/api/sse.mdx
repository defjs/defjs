# SSE

Declara un event stream, ejecútalo, itera los eventos y luego cierra.

## defineEventStream()

```ts
function defineEventStream(definition: EventStreamDefinition): EventStreamEndpoint
```

- **definition** — `path`, mapa `events` y los límites obligatorios, enteros positivos, `maxBufferSize` y `maxQueueSize`; opcionales: `method` (por defecto `'GET'`), `operation`, `input` y `error`. Declarar `input` siempre exige un `builder` explícito, aunque la entrada ya tenga la forma de la solicitud. Solo las definiciones sin `input` pueden omitir `builder`.
- **Devuelve** un endpoint. Llámalo con el input para obtener un `EventStreamCommand`.

## executeEventStreamCommand()

```ts
function executeEventStreamCommand(
  clientConfig: ClientConfig,
  command: EventStreamCommand,
  options?: EventStreamExecuteOptions,
): Promise<StreamAwaitResult>
```

Entrada de bajo nivel para `client.execute`. En el código de la aplicación prefiere el cliente.

- **Devuelve** `[null, stream, open]` o `[error, undefined, open?]`. Cuando se declara `error`, el fault es `Fault` de ese struct; si no, es `Fault<undefined>`.

## Opciones de execute

## EventStreamExecuteOptions

```ts
type EventStreamExecuteOptions = ({ abort?: AbortSignal; timeout?: never } | { abort?: never; timeout?: number }) & {
  signal?: AbortSignal
}
```

Las mismas reglas de cancelación que HTTP: `abort` o `timeout`, no ambos (el tipo rechaza los dos y pasarlos en runtime falla con `REQ_OPTIONS_INVALID`); `signal` se combina con cualquiera. `timeout` es un plazo de arranque: abarca el parseo del input, el builder, los interceptores y el handshake, y no aborta un stream ya abierto. `withTimeout` no se aplica a SSE.

## EventStreamHandle

```ts
interface EventStreamHandle<TEvent> extends AsyncIterable<TEvent>, AsyncDisposable {
  readonly open: EventStreamOpenInfo
  readonly closed: Promise<EventStreamCloseInfo>
  close(reason?: unknown): void
  [Symbol.asyncDispose](): PromiseLike<void>
}
```

El tercer hueco de la tupla es el snapshot de arranque de `open`; `stream.open` sigue la conexión más reciente tras un reconnect. Prefiere `await using stream = handle` para el cleanup del ámbito que posees. El disposer detiene la lectura y el trabajo de reconnect de Defjs y espera a que se libere el reader lock; no promete que termine una promise de `ReadableStream.cancel()` atascada y controlada por el proveedor. `close()` / `closed` manuales siguen disponibles.

```ts
async function consume(handle: EventStreamHandle<unknown>): Promise<void> {
  await using stream = handle
  for await (const event of stream) console.log(event)
}
```

Las implementaciones estructurales de `EventStreamHandle` ahora deben implementar `[Symbol.asyncDispose]()` y devolver el mismo camino de teardown que posee Defjs. Es un cambio breaking en tiempo de compilación para handles propios; el código que solo recibe handles devueltos por Defjs no tiene un requisito nuevo de llamada en runtime.

### EventStreamOpenInfo

```ts
interface EventStreamOpenInfo {
  response: HttpResponse<unknown>
  url: string
}
```

### EventStreamCloseInfo

```ts
type EventStreamCloseInfo =
  | { kind: 'eof'; reason?: string; cause?: unknown }
  | { kind: 'aborted'; reason?: string; cause?: unknown }
  | { kind: 'error'; code: EventStreamFaultCode; reason?: string; cause?: unknown }
```

`EventStreamFaultCode`: `'CAP_BUFFER_EXCEEDED' | 'CAP_QUEUE_OVERFLOW' | 'EXT_HOOK_FAILED' | 'EXT_OBSERVER_FAILED' | 'NET_TIMEOUT' | 'NET_UNREACHABLE' | 'RES_DECODE_FAILED' | 'RES_MEDIA_TYPE_INVALID'`.

## Mapa de eventos

## EventStructs

```ts
type EventStructs = { [eventName: string]: AnyStruct }
```

La clave es el nombre del evento SSE; un mensaje sin campo `event:` se llama `message`. Cuando ninguna clave coincide, se usa el struct `default`. Un struct de evento `string` conserva el texto crudo de `data`. Cualquier otro kind es texto JSON: `JSON.parse` y luego el struct. Un `struct.literal` suelto necesita por tanto texto JSON, no un token sin comillas. Los cuerpos `error` del handshake usan la misma regla de kind que HTTP: `string` es texto, `blob` / `file` son blobs, `arrayBuffer` son bytes y todo lo demás es JSON.

El reconnect vive en el cliente (`withSSEReconnect`). El `jitter` de SSE es un **factor multiplicativo 0–1**, igual que WebSocket.

Mira la [guía de SSE](/es-ES/docs/sse) y [Consumir un stream SSE](/es-ES/recipes/consume-sse).

## EventStreamDefinition

`path`, `events`, `maxBufferSize` y `maxQueueSize` obligatorios, y `method` / `operation` / `input` / `error` opcionales. La forma de la solicitud coincide con HTTP, incluido `body`. `GET` y `HEAD` no pueden devolver un body. Declarar `input` siempre exige un `builder` explícito, aunque la entrada ya tenga la forma de la solicitud. Solo las definiciones sin `input` pueden omitir `builder`.

## EventStreamEndpoint

Lo devuelve `defineEventStream`. Llámalo con input y sale un `EventStreamCommand`.

## EventStreamRequestShape

Los mismos campos que `HttpRequestShape` para el method y el path del stream.

## EventStreamCommand

Command SSE opaco. Pásaselo a `client.execute`.

## StreamAwaitResult

`[null, stream, open]` o `[error, undefined, open?]`.

## EventStreamData

Payload de evento parseado, inferido de un mapa `EventStructs`.
