# Defjs

**Diseñado para crear mejores SDK.**

Defjs significa **define js**: facilita el diseño, la escritura y la publicación de SDK de API. Quien desarrolla el SDK exporta endpoints tipados y reutilizables con `defineRequest`, `defineEventStream` y `defineWebSocket`. La aplicación los importa y los ejecuta con su propio cliente Defjs.

| Autor del SDK                                                                | Aplicación                                                             |
| ---------------------------------------------------------------------------- | ---------------------------------------------------------------------- |
| Definir operaciones, métodos y rutas relativas de la API                     | Configurar la URL base y el transporte del entorno                     |
| Describir entradas, salidas, errores, eventos y mensajes con Struct          | Configurar autenticación, interceptores y telemetría                   |
| Colocar las entradas en la solicitud mediante `builder` y exportar endpoints | Ejecutar comandos, tratar resultados y gestionar cancelación y streams |

El SDK exporta el endpoint:

<include cwd meta="get-health.ts">
  examples/home/get-health.ts#example
</include>

La aplicación proporciona el cliente y ejecuta el comando:

<include cwd meta="app.ts">
  examples/home/app.ts#example
</include>

Definición y ejecución siguen formando parte del contrato de Defjs. El cliente de la aplicación aporta la configuración de ejecución; los endpoints conservan métodos, rutas y contratos de transporte.

Empieza por el [inicio rápido](/es-ES/docs/start), aprende sobre [Struct](/es-ES/docs/struct), [comandos](/es-ES/docs/commands) y [cliente](/es-ES/docs/client) y después [publica tu SDK](/es-ES/recipes/publish-http-sdk). Las [decisiones de diseño](/es-ES/docs/design-decisions) explican este reparto.

Defjs no almacena resultados en caché ni organiza los reintentos de la aplicación. La aplicación decide esas políticas y gestiona la cancelación y la limpieza.

## Elige un transporte

| Necesitas                                      | Empieza por                         | Resultado correcto                                                                            |
| ---------------------------------------------- | ----------------------------------- | --------------------------------------------------------------------------------------------- |
| Solicitud + respuesta por estado               | [HTTP](/es-ES/docs/http)            | Datos decodificados + `DecodedResponse` (`HttpMeta` cuando no se declara un struct de salida) |
| Feed de eventos del servidor de larga duración | [SSE](/es-ES/docs/sse)              | Un stream + snapshot de arranque `open`                                                       |
| Sesión bidireccional                           | [WebSocket](/es-ES/docs/web-socket) | Una sesión + snapshot de arranque `connection`                                                |

## Elige un paquete

| Paquete                       | Cuándo                                                                                                       |
| ----------------------------- | ------------------------------------------------------------------------------------------------------------ |
| `@defjs/core`                 | `defineRequest`, `defineEventStream`, `defineWebSocket`, `struct` y `createClient`                           |
| `@defjs/react`                | `ClientProvider` / `useClient` — ver [React](/es-ES/docs/integrations/react)                                 |
| `@defjs/vue`                  | Plugin + `injectClient` — ver [Vue](/es-ES/docs/integrations/vue)                                            |
| `@defjs/opentelemetry-server` | Spans, métricas y logs salientes — ver [OpenTelemetry Server](/es-ES/docs/integrations/opentelemetry-server) |

## Formas del resultado

Los tres transportes devuelven una tupla de tres elementos con el error primero. Las posiciones coinciden; los significados no:

- HTTP → `[error, data, response]`
- SSE → `[error, stream, open]`
- WebSocket → `[error, session, connection]`

Si falla, el segundo elemento es `undefined`. En HTTP el tercero también es `undefined`, porque el fallo ya lleva los metadatos de la respuesta. En SSE y WebSocket el tercero es el snapshot de arranque cuando se capturó uno antes del fallo. Ver [Errores](/es-ES/docs/errors).

## Responsabilidad en una frase

Aborta HTTP cuando ya no sirve. Cierra SSE y `await stream.closed`. Cierra WebSocket y `await session.closed`. En un servidor, crea el cliente dentro del límite de la solicitud cuando las opciones capturan cookies, auth o datos de tenant. Redacta URL, cabeceras y cuerpos antes de registrarlos.
