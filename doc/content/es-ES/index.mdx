# Defjs

**Kit de SDK en TypeScript y cliente resiliente — Define el contrato de la API una sola vez. Configura la ejecución en cada aplicación.**

Defjs separa los dos lados de un SDK de TypeScript:

- **Definición del SDK (`@defjs/core`, `@defjs/cli`)** — Declara operaciones tipadas de HTTP, SSE y WebSocket junto con sus esquemas `struct` (escritos a mano o generados como ESM sin estado a partir de especificaciones OpenAPI 2.0/3.0/3.1/3.2). Una definición es solo dato puro: importarla no inicia ninguna llamada de red ni enlaza un cliente global.
- **Ejecución resiliente en la aplicación (`@defjs/core`)** — Las aplicaciones crean su propio `Client` (`createClient(withEndpoint(...))`), adjuntan credenciales e interceptores (`basicAuth*`, `idempotencyKeyHttpInterceptor`, `concurrencyLimitHttpInterceptor`), configuran el balanceo de carga P2C y `outlierDetection` (`halfOpen`, `maxEjectionPercent`), habilitan reintentos `429`/`Retry-After`, ejecutan llamadas en paralelo con `@defjs/core/concurrent` o conectan workers y extensiones mediante `@defjs/core/port`.

## ¿Por qué separar las definiciones de los clientes?

| Responsabilidad | Autor del SDK (Definición)                                                                                                           | Aplicación (Ejecución)                                                                                                 |
| --------------- | ------------------------------------------------------------------------------------------------------------------------------------ | ---------------------------------------------------------------------------------------------------------------------- |
| **Controla**    | Método, plantilla de ruta, esquemas de `input` / `output` / `error`, mapeo en `builder` y `meta` opcional definido por la aplicación | URLs base, credenciales, interceptores de autenticación, balanceo de carga, tiempos de espera y liberación de recursos |
| **Distribuye**  | Módulos ESM reutilizables y declaraciones `.d.ts`                                                                                    | Configuración para el runtime de navegador, servidor o entornos de prueba                                              |
| **Ventaja**     | Cero acoplamiento al entorno; funciona en navegador, SSR y tests                                                                     | Control total sobre reintentos, failover, telemetría y ciclo de vida                                                   |

## Transportes compatibles y tuplas de resultado

Cada operación devuelve una tupla de tres elementos con el error en la primera posición, adaptada al ciclo de vida de su transporte:

| Transporte                              | Punto de entrada    | Forma de la tupla            | Control del ciclo de vida                                                      |
| --------------------------------------- | ------------------- | ---------------------------- | ------------------------------------------------------------------------------ |
| **[HTTP](/es-ES/docs/http)**            | `defineRequest`     | `[err, data, response]`      | Cancela el trabajo en curso mediante `client({ signal })`                      |
| **[SSE](/es-ES/docs/sse)**              | `defineEventStream` | `[err, stream, open]`        | Libera recursos con `await using` o `stream.close()` + `await stream.closed`   |
| **[WebSocket](/es-ES/docs/web-socket)** | `defineWebSocket`   | `[err, session, connection]` | Libera recursos con `await using` o `session.close()` + `await session.closed` |

Si una petición HTTP falla, la tupla es `[err, undefined, undefined]` porque `err` ya incluye los metadatos de respuesta `HttpMeta`. Para SSE y WebSocket, la tercera posición contiene la instantánea de conexión siempre que se haya capturado una antes del fallo.
