# Defjs

**Define el contrato de la API una sola vez. Configura la ejecución en cada aplicación.**

Defjs separa los dos lados de un SDK de TypeScript:

- **Definición del SDK (`@defjs/core`)** — Quienes crean el SDK declaran operaciones tipadas de HTTP, SSE y WebSocket junto con sus esquemas `struct`. Una definición es solo dato puro: importarla no inicia ninguna petición de red ni la enlaza a un cliente global.
- **Ejecución en la aplicación** — Las aplicaciones consumidoras crean su propio `Client` (`createClient(withEndpoint(...))`), configuran credenciales, interceptores y balanceadores de carga, y pasan ese cliente al llamar a cada operación.

## ¿Por qué separar las definiciones de los clientes?

| Responsabilidad | Autor del SDK (Definición)                                                                                               | Aplicación (Ejecución)                                                                                                 |
| --------------- | ------------------------------------------------------------------------------------------------------------------------ | ---------------------------------------------------------------------------------------------------------------------- |
| **Controla**    | Método, plantilla de ruta, esquemas de `input` / `output` / `error`, mapeo en `builder` y nombre estático de `operation` | URLs base, credenciales, interceptores de autenticación, balanceo de carga, tiempos de espera y liberación de recursos |
| **Distribuye**  | Módulos ESM reutilizables y declaraciones `.d.ts`                                                                        | Configuración para el runtime de navegador, servidor o entornos de prueba                                              |
| **Ventaja**     | Cero acoplamiento al entorno; funciona en navegador, SSR y tests                                                         | Control total sobre reintentos, failover, telemetría y ciclo de vida                                                   |

## Transportes compatibles y tuplas de resultado

Cada operación devuelve una tupla de tres elementos con el error en la primera posición, adaptada al ciclo de vida de su transporte:

| Transporte                              | Punto de entrada    | Forma de la tupla              | Control del ciclo de vida                                                      |
| --------------------------------------- | ------------------- | ------------------------------ | ------------------------------------------------------------------------------ |
| **[HTTP](/es-ES/docs/http)**            | `defineRequest`     | `[error, data, response]`      | Cancela el trabajo en curso mediante `client({ signal })`                      |
| **[SSE](/es-ES/docs/sse)**              | `defineEventStream` | `[error, stream, open]`        | Libera recursos con `await using` o `stream.close()` + `await stream.closed`   |
| **[WebSocket](/es-ES/docs/web-socket)** | `defineWebSocket`   | `[error, session, connection]` | Libera recursos con `await using` o `session.close()` + `await session.closed` |

Si una petición HTTP falla, la tupla es `[error, undefined, undefined]` porque `error` ya incluye los metadatos de respuesta `HttpMeta`. Para SSE y WebSocket, la tercera posición contiene la instantánea de conexión siempre que se haya capturado una antes del fallo.
