# Capa de API de aplicación [#application-api-layer]

La mayoría de los proyectos utilizan Defjs directamente dentro del repositorio de una aplicación (`src/api/`) para sustituir envoltorios dispersos de `fetch` o `axios`. Incluso cuando no tienes previsto publicar un paquete npm externo, separar `src/api/schema/`, `src/api/request/` y `src/api/client.ts` mantiene tu capa de solicitudes fuertemente tipada, verificable en memoria y segura tanto en el navegador como en entornos SSR.

---

## 1. Estructura de directorios recomendada para `src/api/`

Organiza la capa de solicitudes de tu proyecto en tres partes bien definidas bajo `src/api/`:

```text
src/
├── api/
│   ├── schema/           # 1. Esquemas struct compartidos + tipos Infer<typeof ...>
│   │   └── order.ts      #    ApiError, OrderStatus, Order, OrderPage
│   ├── request/         # 2. Definiciones de operaciones puras agrupadas por dominio
│   │   └── orders.ts     #    getOrder, listOrders, createOrder
│   └── client.ts         # 3. Client propiedad de la app (endpoint, interceptor de auth, reintentos)
└── checkout.ts           # 4. Lógica de negocio / componentes de UI que invocan operaciones
```

`src/checkout.ts` es lógica de negocio, no la cima del programa, así que `placeAndLoadOrder` no registra nada. Devuelve una tupla con el error por delante, `Promise<[Error, undefined] | [null, Checkout]>`, y envuelve el fallo de cada paso con el paso que falló (`new Error("create order", { cause: createErr })`), como el `fmt.Errorf("create order: %w", err)` de Go. Quien llama, por ejemplo un manejador de eventos de la interfaz, comprueba `if (err)` y decide cómo mostrarlo.

## 3. Patrones clave para proyectos de aplicación

### Singleton en el navegador frente a cliente por solicitud en SSR

- **Navegador / SPA (`apiClient`)**: Exporta una única instancia `createClient(...)` con ámbito de módulo por cada origen de backend. Compartir esa instancia conserva el estado de salud del balanceador de carga y el presupuesto de reintentos HTTP a nivel de cliente entre las distintas interacciones de la página. En aplicaciones React o Vue, proporciona `apiClient` en la raíz mediante [`@defjs/react`](/es-ES/docs/integrations/react) (`ClientProvider` / `useClient`) o [`@defjs/vue`](/es-ES/docs/integrations/vue) (`createClientPlugin` / `injectClient`).
- **SSR / BFF (`createServerApiClient(accessToken)`)**: Siempre que las credenciales, las cookies o las cabeceras de inquilino varíen según la solicitud HTTP entrante, invoca una función factoría dentro del manejador de solicitudes del servidor para crear un `Client` aislado. Como `getOrder`, `listOrders` y `createOrder` son funciones puras, exactamente las mismas definiciones de `request/orders.ts` funcionan tanto con `apiClient` como con `createServerApiClient(token)`.

### Tiempos de espera y cancelación por llamada

Nunca crees un nuevo `Client` mediante `createClient(...)` solo para pasar un tiempo de espera o un `AbortSignal`. En su lugar, deriva en línea un cliente para una sola llamada a partir de tu cliente compartido:

```ts
const [err, created] = await createOrder(
  apiClient({ signal: AbortSignal.timeout(5_000) }),
  {
    customerName: "Ada Lovelace",
    totalCents: 4200,
    idempotencyKey: "idem-2026-101",
  },
);
```

### Envoltorio de error compartido (`ApiError`)

Declara una sola vez la estructura estándar de error de tu backend (`export const ApiError = struct.object(...)`) en `src/api/schema/` y pasa `error: ApiError` en cada `defineRequest` de `src/api/request/`. Cuando una solicitud devuelve un estado distinto de `2xx`, acotar con `if (err.code === "HTTP_STATUS")` dentro de `if (err)` te proporciona acceso fuertemente tipado a `err.data.code`, `err.data.message` y `err.data.requestId`.
