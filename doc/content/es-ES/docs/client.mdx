# Cliente

Un `Client` almacena la configuración de ejecución de la aplicación consumidora: URLs base, cabeceras predeterminadas, credenciales, interceptores, serialización de consultas y manejadores de transporte.

`createClient(...options)` devuelve un [`DerivableClient`](/es-ES/api/core/derivableclient-type):

- Pasa `client` directamente a una operación (`getOrder(client, { id: 1 })`) cuando no se requieran opciones de petición por llamada.
- Llama a `client(requestOptions)` para derivar un valor de `Client` de un solo uso (`getOrder(client({ signal }), { id: 1 })`). La derivación no ejecuta E/S y el valor resultante es un objeto plano (no invocable).

### Reglas de composición de opciones

- Las opciones se aplican de **izquierda a derecha**.
- Los configuradores de valor único (`withEndpoint`, `withHeaders`, `withQuerySerializer`, `withCredentials`, `withXSRF`) **reemplazan** los valores previos.
- `withInterceptors(...items)` **añade** elementos a la lista existente de interceptores y los filtra por transporte (`http`, `sse`, `web-socket`) cuando se ejecuta una operación.

> [!IMPORTANT]
> Dado que `createClient(...)` devuelve una función invocable (`DerivableClient`), **no** la pases directamente a un actualizador `setState(client)` de React ni como fuente de `watch(client)` / `computed(client)` en Vue, ya que estos frameworks interpretan las funciones como actualizadores de estado o _getters_.

### Referencia de `RequestOptions` por llamada

`RequestOptions` contiene siete campos planos. Cada transporte lee únicamente los campos que le corresponden e ignora el resto:

| Campo                | Usado por            | Comportamiento                                                                                                                              |
| -------------------- | -------------------- | ------------------------------------------------------------------------------------------------------------------------------------------- |
| `signal`             | HTTP, SSE, WebSocket | Aborta la llamada (`AbortSignal.timeout(ms)` → `NET_TIMEOUT`; abort manual → `NET_ABORTED`).                                                |
| `onUploadProgress`   | HTTP                 | Notifica el progreso de subida del cuerpo de la petición en streaming.                                                                      |
| `onDownloadProgress` | HTTP                 | Notifica el progreso de descarga del cuerpo declarado en la respuesta.                                                                      |
| `beforeConnect`      | WebSocket            | Reemplaza el hook `beforeConnect` definido a nivel de cliente para esta sesión.                                                             |
| `protocols`          | WebSocket            | Reemplaza la lista de subprotocolos definida a nivel de cliente para esta sesión.                                                           |
| `heartbeat`          | WebSocket            | Reemplaza la configuración de latidos (_heartbeat_) definida a nivel de cliente para esta sesión.                                           |
| `reconnect`          | WebSocket            | Reemplaza la política de reconexión WebSocket a nivel de cliente para esta sesión. (La reconexión SSE se configura con `withSSEReconnect`). |

## 3. Singleton en el navegador frente a ámbito por petición en servidor

- **Aplicaciones de navegador**: comparte un único `DerivableClient` a nivel de módulo cuando el endpoint, los interceptores y las credenciales sean globales en la aplicación.
- **Servidor y aplicaciones SSR**: crea un cliente nuevo **dentro del límite de cada petición entrante** siempre que las cabeceras, cookies, tokens de autenticación o datos del tenant sean específicos de la petición. Nunca guardes credenciales de usuario en un cliente global del proceso.

## 4. Múltiples endpoints y balanceo de carga [#multiple-endpoints]

`withEndpoint(...urls)` acepta una o más URLs base candidatas. Por defecto:

- Cada cliente utiliza [`pickFirstBalancer`](/es-ES/api/core/pickfirstbalancer), manteniéndose en la primera URL hasta que un fallo `NET_UNREACHABLE` o una respuesta no controlada `502`/`503`/`504` lo avance a la siguiente.
- Los métodos HTTP seguros (`GET`, `HEAD`, `OPTIONS`, `TRACE`) realizan automáticamente un **failover dentro de la misma llamada** hacia un endpoint de respaldo no probado en caso de fallo de conexión (`NET_UNREACHABLE`), regulado por un presupuesto de reintentos compartido estilo Finagle (`withEndpointFailover`).

### Filtrado por salud y P2C [#health-filtering-and-p2c]

Para réplicas equivalentes entre servidores, [`roundRobinBalancer`](/es-ES/api/core/roundrobinbalancer) y [`p2cBalancer`](/es-ES/api/core/p2cbalancer) (PeakEwma RTT × carga en vuelo) habilitan por defecto un disyuntor por fallos consecutivos estilo Linkerd (`outlierDetection`).

Consulta la guía específica de [Balanceo de carga y conmutación por error](/es-ES/docs/load-balancing) para conocer todos los detalles sobre presupuestos de reintento, sondas de salud activas/pasivas, estimación de carga P2C y balanceadores personalizados.

## 6. Referencia de configuradores de opciones de cliente

| Configurador                                                                                                  | Propósito                                                                                                     |
| ------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------- |
| `withEndpoint(...urls)`                                                                                       | Establece una o más URLs base candidatas (reemplaza la lista anterior).                                       |
| `withHeaders(HeadersInit)`                                                                                    | Establece cabeceras predeterminadas estáticas para HTTP y SSE (las cabeceras del builder prevalecen).         |
| `withInterceptors(...items)`                                                                                  | Añade interceptores HTTP, SSE y WebSocket en orden de capas concéntricas (cebolla).                           |
| `withQuerySerializer(fn)`                                                                                     | Serializa objetos de consulta con alias aplicados a una cadena query string.                                  |
| `withCredentials(boolean)`                                                                                    | Configura `credentials: "include"` en Fetch para HTTP y SSE cuando es `true`.                                 |
| `withXSRF(options?)`                                                                                          | Copia la cookie XSRF a una cabecera en peticiones HTTP mutantes de mismo origen.                              |
| `withEndpointBalancer(balancer)`                                                                              | Reemplaza la estrategia de selección de endpoints (`pickFirstBalancer`, `roundRobinBalancer`, `p2cBalancer`). |
| `withEndpointFailover(options?)`                                                                              | Configura el failover HTTP en la misma llamada y el presupuesto de reintentos del cliente.                    |
| `withSSEReconnect` / `withSSEOnInvalidEvent`                                                                  | Configura la reconexión de SSE y la observación de eventos no válidos.                                        |
| `withWebSocketReconnect` / `withWebSocketHeartbeat` / `withWebSocketProtocols` / `withWebSocketBeforeConnect` | Configura los valores predeterminados para sesiones WebSocket.                                                |
| `withHTTPHandle` / `withSSEHandle` / `withWebSocketHandle`                                                    | Inyecta implementaciones de transporte personalizadas o simuladas para pruebas.                               |
