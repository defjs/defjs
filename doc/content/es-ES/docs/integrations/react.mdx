# React

`@defjs/react` conecta un cliente `@defjs/core` propiedad de la aplicación en un árbol de componentes de React 18+ mediante React Context y `useClient()`. Tus definiciones de SDK se mantienen como módulos puros de `@defjs/core` con cero dependencias de React.

```sh
bun add @defjs/core @defjs/react react
```

## Lo que aporta `@defjs/react` frente a lo que controlas tú

- **Aportado por `@defjs/react`**: `ClientProvider` y `useClient(overrideClient?)`.
- **Bajo el control de tu aplicación**: crear el [`DerivableClient`](/es-ES/api/core/derivableclient-type), cancelar peticiones en curso al desmontar o ante cambios de dependencias (`AbortController`), cerrar handles de SSE/WebSocket e integrar cachés de consultas como TanStack Query.
- **Importante**: `useClient()` devuelve la función-objeto `DerivableClient`. Llama a `client({ signal })` donde se ejecuta la operación (`getOrder(client({ signal }), input)`). Nunca pases `client` directamente a `setState(client)` porque React trata cualquier argumento de función pasado a un setter de estado como una función de actualización.

## 2. Leer y sobrescribir el cliente con `useClient`

`useClient(overrideClient)` devuelve `overrideClient` cuando se proporciona, o lee el `ClientProvider` más cercano cuando se omite o es `undefined`. Solo lanza un `Error` si ninguna de las dos fuentes suministra un cliente.

<include cwd>examples/react/read-with-use-client.tsx#example</include>

- Llama siempre a `useClient(explicitClient)` de forma incondicional en el nivel superior de un componente o custom Hook. Nunca escribas `explicitClient ?? useClient()`, ya que viola las Reglas de los Hooks.

## 3. Integración con TanStack Query

`@defjs/react` se limita a la inyección de dependencias y **no** incluye un hook `useRequest`. Al utilizar una biblioteca de obtención de datos como TanStack Query, reenvía la señal `signal` de la función de consulta mediante `client({ signal })` y convierte la tupla con error por delante dentro del adaptador de la consulta:

En este caso, `throw err` constituye una frontera explícita de adaptación exigida por el contrato de rechazo de TanStack Query, no el estilo de llamada predeterminado de Defjs.

## 4. Gestionar el ciclo de vida de SSE y WebSocket en efectos

Los handles de SSE y WebSocket sobreviven a la llamada inicial a `openStream(...)` o `connectChat(...)`. Pasa la señal de un `AbortController` a la operación y abórtala en la limpieza: la señal cubre el arranque y la sesión abierta. Toma posesión de la sesión con `await using` y consume su iterador asíncrono único:

<include cwd>examples/react/own-realtime-work.tsx#example</include>

- Abortar la señal `signal` pasada a una operación WebSocket finaliza la sesión como `aborted` y rechaza `session.receive` con `AbortError`. Protege el bloque `catch` con `controller.signal.aborted` para que solo emerjan errores auténticos de tiempo de ejecución (como un tiempo de espera de latidos).
- Abortar un flujo SSE finaliza el bucle `for await (const msg of stream)` de forma limpia sin lanzar excepciones.

---

## 5. SSR y ámbito del proveedor

- **Navegador**: comparte un único cliente con ámbito de módulo cuando el endpoint y los interceptores sean independientes de la petición.
- **SSR**: crea un cliente nuevo dentro del límite de cada petición del servidor siempre que las cabeceras, cookies, datos de tenant o credenciales varíen por petición.
- Desmontar `<ClientProvider>` **no** cancela llamadas HTTP activas, no cierra conexiones SSE/WebSocket ni libera el cliente.
