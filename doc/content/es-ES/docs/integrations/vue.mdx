# Vue

`@defjs/vue` integra un cliente `@defjs/core` propiedad de la aplicación en una app de Vue 3.2+ mediante `createClientPlugin(client)`, `HTTP_CLIENT` e `injectClient()`. Tus definiciones de SDK se mantienen como módulos puros de `@defjs/core` sin dependencias de Vue.

```sh
bun add @defjs/core @defjs/vue vue
```

## Lo que aporta `@defjs/vue` frente a lo que controlas tú

- **Aportado por `@defjs/vue`**: `createClientPlugin(client)`, `HTTP_CLIENT` (`InjectionKey<DerivableClient>`) e `injectClient(key?)`.
- **Bajo el control de tu aplicación**: crear el [`DerivableClient`](/es-ES/api/core/derivableclient-type), abortar trabajo en curso en observadores (`onCleanup`) o composables (`onScopeDispose`), cerrar handles de SSE/WebSocket e integrar bibliotecas de consulta (como Vue Query).
- **Importante**: `injectClient()` devuelve la función-objeto `DerivableClient`. Llama a `client({ signal })` donde se ejecuta la operación (`getOrder(client({ signal }), input)`). Nunca pases `client` como primer argumento de `watch(client, ...)` o `computed(client)` porque Vue interpreta un argumento de función como un _getter_ reactivo.

## 2. Inyectar y sobreescribir en subárboles

`injectClient(key?)` busca el proveedor más cercano para la clave `key` (por defecto `HTTP_CLIENT`) y lanza un `Error` si se invoca fuera de un contexto de inyección activo de Vue (`setup()` o `app.runWithContext()`) o si no hay un cliente provisto para esa clave.

- Los componentes descendientes reciben `childClient`, mientras que los subárboles hermanos conservan el cliente raíz.
- Si una función auxiliar acepta un cliente explícito opcional (`explicitClient ?? injectClient()`), solo la rama alternativa requiere un contexto de inyección activo de Vue. Captura el cliente de forma sincrónica durante `setup()` antes de cualquier `await`.

## 3. Limpiar flujos SSE y WebSocket al desechar el ámbito (scope)

Para el trabajo iniciado dentro de un composable o componente fuera de un observador, combina `AbortController` con `onScopeDispose`. La señal cubre el inicio y el stream abierto, así que abortarla es toda la limpieza. Consume su iterador asíncrono único, luego cierra el handle y espera `.closed` en `finally`:

<include cwd>examples/vue/realtime-scope.vue#example</include>

- La rama de error de la tupla muestra los fallos del handshake inicial (incluido HTTP 503). El `catch` del iterador muestra los fallos posteriores al inicio; el bloque `finally` sigue cerrando el flujo y esperando su cierre.

- Detener el ámbito finaliza el bucle `for await` de SSE de forma normal.
- Abortar una sesión WebSocket la finaliza como `aborted` y rechaza `session.receive` con `AbortError`, por lo que debes proteger el bloque `catch` tras la liberación y cancelar las suscripciones a `onStateChange` / `onRuntimeError` en `finally`.

---

## 4. SSR y ámbito de la aplicación

- **Navegador**: comparte un único cliente por aplicación Vue cuando el endpoint y los interceptores no dependan de la petición.
- **SSR**: crea e instala un cliente nuevo para cada petición en SSR siempre que las cabeceras, cookies, datos de tenant o credenciales varíen.
- Desmontar la aplicación Vue o desechar el ámbito de un componente **no** aborta automáticamente peticiones HTTP, no cierra flujos SSE/WebSocket ni libera el cliente de Core.

## Exportaciones públicas y guías relacionadas

- `HTTP_CLIENT` — `InjectionKey<DerivableClient>` para `provide` / `inject` nativo.

- `injectClient(key?)` — resuelve el cliente más cercano para `key` (por defecto `HTTP_CLIENT`).
