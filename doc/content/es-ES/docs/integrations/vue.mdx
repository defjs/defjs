# Vue

Importa operaciones de tu SDK o de un módulo de definición compartido. La aplicación Vue configura y proporciona el cliente; el paquete del SDK puede seguir siendo independiente de Vue. Los componentes y los composables llaman a esas operaciones y son dueños del trabajo que arrancan. El cliente de `injectClient()` se pasa a la operación.

Estos plugins son ayudas opcionales para proporcionar y leer un `Client` existente. Importa un cliente fijo que posee la aplicación, pasa un `Client` de forma explícita a la lógica reutilizable, usa la inyección del framework para valores por defecto y sustituciones a nivel de árbol, o elige tu propia organización. Las definiciones del SDK no requieren estos plugins.

Conecta un cliente `@defjs/core` existente a Vue. Obtienes un plugin, una injection key y `injectClient()`. El paquete **no** crea clientes, no cachea resultados, no reintenta operaciones ni cierra recursos de transporte en el unmount. El valor inyectado es el [`DerivableClient`](/es-ES/api/core/derivableclient-type) que se proporcionó; llámalo con opciones de solicitud donde se ejecuta la operación para derivar un valor `Client`. No lo uses como fuente de `watch` o `computed`, porque esos llaman a una función. El plugin e `injectClient` no aceptan un valor `Client` derivado.

## Configuración básica

Instala `@defjs/core`, `@defjs/vue` y Vue 3.2+ (el plugin solo necesita `provide` / `inject`, pero los ejemplos usan `<script setup>` y `onScopeDispose`, que llegaron en la 3.2). ESM:

`bun add @defjs/core @defjs/vue vue`

## Inyectar y sobrescribir

`injectClient(key)` lee el provider más cercano para esa clave; sin argumento o con `undefined`, usa `HTTP_CLIENT`. Llámalo en un contexto de inyección válido de Vue: `setup()` síncrono o `app.runWithContext()` (Vue 3.3+). Este último solo ofrece contexto síncrono de aplicación, sin sustituciones de subárboles ni contexto a través de un `await` normal. Los contextos restaurados por el compilador tras un `await` de nivel superior en `<script setup>` siguen siendo válidos.

Para una `InjectionKey<Client>` personalizada, usa `app.provide(key, client)` o `provide(key, client)` en un componente ancestro. Ambos lados deben compartir el mismo objeto `Symbol`; descripciones iguales no hacen que las claves sean iguales. `createClientPlugin(client)` sigue aceptando solo el cliente y proporcionando únicamente `HTTP_CLIENT`.

Lanza un `Error` sin contexto de inyección activo o sin cliente para la clave elegida. Una clave personalizada ausente nunca recurre a `HTTP_CLIENT`; instalar el plugin no establece por sí solo un contexto de inyección.

Una función de la aplicación que solo obtiene un cliente puede usar `explicitClient ?? injectClient()`: solo la rama alternativa necesita contexto de inyección. Las demás API de ciclo de vida del mismo composable conservan sus requisitos de contexto. Lee el cliente en un contexto válido antes del trabajo async y reutiliza el objeto.

## Ser dueño del trabajo HTTP fuera de un watcher

Para trabajo arrancado por un composable o componente fuera de un watcher, usa `AbortController` + `onScopeDispose`. Aborta el arranque y el trabajo activo; comprueba el signal antes de asignar estado reactivo. Un plugin o un ámbito de inyección no infiere quién es dueño de una operación. Para páginas de listas, llama a la operación desde Vue Query (o similar): `@defjs/vue` se queda solo en DI y **no** incluye `useRequest`.

Cuando un ámbito es dueño de un cliente, mantenlo independiente de la solicitud para reutilizarlo en todo el navegador. Si captura cabeceras, cookies, usuarios, tenants o credenciales, créalo en el límite de solicitud de la app/SSR relevante y proporciona esa instancia allí.

## Limpiar el ámbito realtime

Cierra un stream o sesión aunque el ámbito desaparezca a mitad del connect. Aborta el arranque, cierra un handle que llega tarde, consume el único iterador, espera la promesa terminal:

<include cwd>examples/vue/realtime-scope.vue#example</include>

Los errores fatales del stream y el desbordamiento de cola rechazan el iterador, así que el bucle lleva un `catch`; si no, ese rechazo queda sin manejar. El ejemplo conserva solo los últimos 100 mensajes y usa un id como key de las filas, porque payloads idénticos darían keys duplicadas. Detener el ámbito termina la iteración con normalidad en SSE; una sesión WebSocket abortada, en cambio, rechaza `receive` con `AbortError`, así que protege el `catch` del mismo modo.

WebSocket: misma secuencia — aborta la prep, cierra una sesión tardía, consume `session.receive`, haz unsubscribe de `onStateChange` / `onRuntimeError`, cierra, await `session.closed`. Mantén la limpieza idempotente; la liberación y la finalización del iterador pueden coincidir.

## Ámbito SSR

`createClientPlugin(client)` proporciona una instancia a una app Vue. En el navegador, compártela cuando endpoint, interceptores y estado capturado sean seguros de compartir. Durante SSR, crea e instala un cliente separado por solicitud cuando cabeceras, cookies, usuarios, tenants o credenciales difieren.

El unmount de la app, la eliminación del plugin y la liberación del ámbito del componente **no** abortan HTTP, no cierran SSE/WebSocket, no hacen unsubscribe de listeners ni liberan (`dispose`) el cliente core. El dueño que arranca el trabajo debe terminarlo.
