# Sesiones WebSocket

`defineWebSocket` declara un contrato WebSocket bidireccional en tu SDK: la plantilla de ruta, `input` y `builder` opcionales (solo `path` y `query`), los structs de mensajes `incoming` y `outgoing`, límites de colas y subprotocolos estáticos. La aplicación consumidora configura los latidos (_heartbeat_), la reconexión y la limpieza del ciclo de vida en su cliente.

## 1. Definir el contrato y ejecutar una sesión

Modela múltiples tipos de tramas en `incoming` o `outgoing` con `struct.discriminatedUnion(...)`. Libera el `WebSocketSession` devuelto con `await using` o mediante `session.close()` explícito + `await session.closed`:

<Tabs items={["sdk/ticks-socket.ts", "app/session.ts", "Single-file quick look"]}>
<Tab value="sdk/ticks-socket.ts">

```ts
import { defineWebSocket, struct } from "@defjs/core";

export const TickFrame = struct.discriminatedUnion("type", [
  struct.object({
    type: struct.literal("tick"),
    symbol: struct.string(),
    price: struct.number(),
  }),
  struct.object({
    type: struct.literal("subscribed"),
    symbol: struct.string(),
  }),
]);

export const SubscribeCommand = struct.object({
  type: struct.literal("subscribe"),
  symbol: struct.string(),
});

export const openTicker = defineWebSocket({
  path: "/market/ws",
  operation: "market.ticker",
  incoming: TickFrame,
  outgoing: SubscribeCommand,
  maxIncomingQueueSize: 64,
});
```

</Tab>
<Tab value="app/session.ts">

```ts
import { createClient, withEndpoint } from "@defjs/core";
import { openTicker } from "../sdk/ticks-socket.ts";

const client = createClient(withEndpoint("https://api.example.com"));

async function main() {
  const [error, session] = await openTicker(client);
  if (error) {
    console.error(error.code);
    return;
  }

  await using active = session;
  active.send({ type: "subscribe", symbol: "ACME" });

  for await (const message of active.receive) {
    if (message.type === "tick") {
      console.log(message.symbol, message.price);
      break;
    }
  }
}

void main();
```

## 2. Validación de mensajes y reglas de dirección

- **Tramas entrantes (`session.receive`)**: las tramas de texto, `ArrayBuffer`, typed arrays y `Blob` se decodifican como UTF-8, se analizan como JSON y se validan contra el struct `incoming`. Si hay JSON malformado o discordancia de esquema, se notifican a `session.onRuntimeError` y se descartan sin cerrar la sesión. `session.receive` admite un único consumidor; solicitar un segundo iterador lanza un `TypeError`.
- **Tramas salientes (`session.send(payload)`)**: valida sincrónicamente contra `outgoing`, aplica `.alias()` y códecs, y serializa con `JSON.stringify`. Se envían inmediatamente cuando el estado es `open`, se encolan durante `reconnecting` (si `maxOutgoingQueueSize > 0`), y lanzan una excepción sincrónica si la carga no es válida, la cola está llena o deshabilitada, o la sesión está cerrada.

## 3. Estado de la sesión y observadores

| Miembro              | Descripción                                                                                           |
| -------------------- | ----------------------------------------------------------------------------------------------------- |
| `state`              | `'idle' \| 'connecting' \| 'open' \| 'reconnecting' \| 'closing' \| 'closed' \| 'aborted' \| 'error'` |
| `connection`         | Instantánea activa del socket físico más reciente (`generation`, `url`, `protocol`, `extensions`)     |
| `bufferedAmount`     | Recuento de bytes no enviados en el socket físico activo (`0` si está desconectado)                   |
| `receive`            | Iterable asíncrono de consumo único con los mensajes de `incoming` validados                          |
| `onStateChange(fn)`  | Se suscribe a transiciones de estado; devuelve una función `unsubscribe`                              |
| `onRuntimeError(fn)` | Se suscribe a errores de análisis o tramas posteriores al inicio; devuelve una función `unsubscribe`  |
| `closed`             | Promesa que resuelve al resultado terminal (`kind: 'closed' \| 'aborted' \| 'error'`)                 |

## 4. Reconexión, latidos y colas

Tanto la reconexión como los latidos (_heartbeat_) son opcionales mediante opciones de cliente (`withWebSocketReconnect`, `withWebSocketHeartbeat`) o derivadas por llamada (`client({ reconnect, heartbeat })`):

- **Reconexión**: cuando se habilita, los valores por defecto son `attempts: 3`, `delayMs: 1000`, `factor: 2`, `maxDelayMs: 30000`, `jitter: 0`. Cada evento físico `open` reinicia el presupuesto de fallos. El callback `beforeConnect({ attempt, signal })` se ejecuta antes de la conexión inicial y de cada intento de reconexión.
- **Tiempo límite del handshake (`connectTimeoutMs`)**: cuando se proporciona, debe ser finito, positivo y no mayor que 2147483647 (el límite del temporizador); si no, la operación devuelve `REQ_OPTIONS_INVALID`. Acota la construcción hasta `open` y se borra después del handshake.
- **Latidos (_heartbeat_)**: envía periódicamente `message()` a través del struct `outgoing` y espera hasta `timeoutMs` por una trama que coincida con `isAck(msg)`. Las tramas de confirmación coincidentes son consumidas por el monitor de latidos y no se transmiten a `session.receive`. Perder una confirmación resulta fatal para la sesión.
- **Límites de cola**:
  - `maxIncomingQueueSize` (entero positivo requerido): desbordar la cola termina la sesión con `CAP_QUEUE_OVERFLOW`. Mantén el consumo activo de `session.receive` mientras la sesión esté abierta.
  - `maxOutgoingQueueSize` (entero no negativo opcional, por defecto `0`): almacena llamadas de `session.send()` únicamente mientras `state === 'reconnecting'` y las vacía antes de emitir el siguiente `open`.

## 5. Subprotocolos y autenticación [#protocols-and-authentication]

Los WebSockets en el navegador no admiten cabeceras arbitrarias durante el handshake, por lo que las funciones `builder` de WebSocket devuelven únicamente `{ path?, query? }`.

- **Precedencia de subprotocolos**: `client({ protocols })` tiene prioridad sobre `withWebSocketProtocols(...)`, que a su vez prevalece sobre `defineWebSocket({ protocols })`.
- **Conversión de URLs**: Defjs convierte automáticamente `http:` → `ws:` y `https:` → `wss:` en el endpoint resuelto.
- **Credenciales**: `withCredentials(true)` aplica solo a Fetch (HTTP/SSE). Autentica las sesiones WebSocket mediante cookies o políticas de sesión, subprotocolos o tokens de conexión de corta duración; evita incluir credenciales de larga duración en la cadena de consulta (query string).

## 6. Cierre y propiedad de recursos
