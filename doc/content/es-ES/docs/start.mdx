# Primeros pasos: tu primera operación de SDK [#getting-started-one-http-request]

En esta guía crearás un módulo de SDK que define `GET /orders/:id` y lo llamarás desde dos módulos de aplicación distintos: uno con un transporte de prueba local sin conexión a internet y otro apuntando a una API real.

## 1. Instalar `@defjs/core`

`@defjs/core` es un paquete ESM sin dependencias que funciona en navegadores, Bun y Node.js (las versiones 22.18+ o 24+ ejecutan archivos `.ts` directamente). Asegúrate de tener `"type": "module"` en tu `package.json`.

```sh
bun add @defjs/core
```

### Cómo colaboran los tres archivos

1. **`src/define-request.ts` (Definición del SDK)**:
   - Declara `input`, `output` (para respuestas `2xx`) y `error` (para respuestas no `2xx`) usando `struct`.
   - Proporciona un `builder` síncrono y puro que mapea `input` a `{ path }`. Siempre que se declare `input`, es obligatorio incluir un `builder` explícito.
   - Exporta `getOrder` sin crear ni capturar ningún cliente.
2. **`src/execute-locally.ts` (Ejecución de prueba local)**:
   - Configura un cliente con `withHTTPHandle(...)` para ejecutar todo el flujo de Defjs (validación de entrada, resolución de URL, despacho por código de estado y análisis de structs en la respuesta) sin tocar la red.
3. **`src/real-api.ts` (Ejecución en producción)**:
   - Importa exactamente la misma operación `getOrder` y la invoca contra una URL base real configurada mediante `withEndpoint(...)`.

## 3. Ejecutar el ejemplo local

Ejecuta `src/execute-locally.ts` con Bun:

```sh
bun src/execute-locally.ts
```

```txt
Loaded paid from 200
```

Si cambias la entrada de `{ id: 7 }` a `{ id: 8 }`, el mock devuelve `404` y Defjs decodifica el struct `error` declarado en `error.data`:

```txt
Order not found
```

## 4. Comprender la tupla con error por delante

Cada llamada HTTP resuelve una tupla `[error, data, response]`:

- **En éxito `2xx`**: `error` es `null`, `data` es el valor de `output` validado (`Order`) y `response` es `DecodedResponse<Order>`.
- **En un estado no `2xx` declarado**: `error.code` es `'HTTP_STATUS'`, `error.status` es el código numérico (`404`) y `error.data` es el struct `error` validado (`NotFound`).
- **En fallos de entrada, decodificación o red**: `error.code` identifica la etapa exacta del fallo:
  - `REQ_INPUT_INVALID` / `REQ_BUILD_FAILED` — entrada no válida o una excepción lanzada en el `builder`.
  - `RES_MEDIA_TYPE_INVALID` — el cuerpo JSON declarado llegó con un `Content-Type` que no es JSON (se rechaza antes de leer el cuerpo).
  - `RES_DECODE_FAILED` / `RES_STRUCT_MISMATCH` — cuerpo ilegible o discordancia con el esquema.
  - `NET_UNREACHABLE` / `NET_ABORTED` / `NET_TIMEOUT` — fallo de transporte, cancelación manual o límite alcanzado con `AbortSignal.timeout(ms)`.

Pasa límites de tiempo o señales de cancelación por llamada derivando un valor de cliente de un solo uso: `getOrder(client({ signal: AbortSignal.timeout(5_000) }), { id: 7 })`.
