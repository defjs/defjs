# Claves de idempotencia

Por defecto, `withRetry` solo reintenta métodos HTTP idempotentes (`GET`, `HEAD`, `PUT`, `DELETE`, `OPTIONS`, `TRACE`). Cuando habilites reintentos en endpoints `POST` o `PATCH`, combina `withRetry` con `idempotencyKeyHttpInterceptor()` para que cada intento de reintento de la misma llamada lógica reutilice `req.correlationId` como cabecera `Idempotency-Key`, mientras que las llamadas posteriores reciban claves nuevas.
