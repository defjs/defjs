# Crear y publicar un SDK [#publish-an-http-sdk-without-hiding-execute]

Un SDK de Defjs organiza modelos `struct` compartidos (`src/models/`) y módulos de operaciones de dominio (`src/services/`) en un paquete npm compatible con _tree-shaking_, dejando `createClient(...)`, los endpoints, las credenciales y los interceptores en manos de la aplicación consumidora.

A diferencia de los generadores OpenAPI heredados que envuelven los endpoints en clases `Service` con estado (`ObjectsService.putObject(...)`), un SDK de Defjs exporta **funciones de operación puras e independientes** (`putObject`, `getObject`, `listObjectsV2`) que se invocan directamente con el cliente de la aplicación.

---

## 1. Estructurar y definir el paquete del SDK

Tomando como ejemplo un SDK de almacenamiento de objetos compatible con Amazon S3 (`@company/s3-sdk`), divide el paquete en dos capas:

- **`src/models/`**: Esquemas `struct` compartidos y tipos de TypeScript `Infer<typeof ...>` (utilizando exportaciones de valor y tipo con el mismo nombre para que los consumidores puedan importar un único identificador tanto para los esquemas en tiempo de ejecución como para los tipos estáticos).
- **`src/services/`**: Módulos de dominio agrupados por recurso (`buckets.ts`, `objects.ts`). Cada módulo exporta funciones `defineRequest` independientes cuyo `builder` síncrono enruta una entrada plana del llamador hacia `path`, `query`, `headers` y el `body` binario.

- **Funciones puras, nunca clases `Service`**: Cada operación (`listBuckets`, `listObjectsV2`, `getObject`, `putObject`, `deleteObject`) se exporta como un valor `defineRequest` independiente. No las envuelvas en una `class` ni en un objeto de espacio de nombres: las funciones independientes mantienen la convención de llamada idéntica a `@defjs/core` (`await putObject(client, input)`) y permiten a los empaquetadores eliminar endpoints no utilizados (_tree-shaking_) cuando se establece `"sideEffects": false`.
- **Respuestas vacías, binarias y estructuradas**: `listBuckets` y `listObjectsV2` decodifican structs JSON con mapeos de red `.alias()`; `getObject` decodifica un `Blob` binario (`output: struct.blob()`); `putObject`, `headObject` y `deleteObject` omiten `output` para cuerpos de respuesta vacíos mientras siguen exponiendo `response.headers` (como `etag`) en la tercera posición de la tupla.
- **Dependencia par externa en tiempo de ejecución**: `@defjs/core` se mantiene como una `peerDependency` compartida con la aplicación consumidora.

---

## 2. Construir y verificar el archivo tarball

Empaqueta `dist/index.js` y `dist/index.d.ts` con `tsdown`, e inspecciona el contenido del paquete antes de publicarlo:

```sh
bun install
bun run build
bun pm pack --dry-run
bun pm pack
```

Comprueba que `dist/index.js` y `dist/index.d.ts` estén incluidos en el tarball.

---

## 3. Consumir el SDK en una aplicación

Instala tu SDK junto a `@defjs/core`:

```sh
bun add @company/s3-sdk @defjs/core@^0.7.0
```

Dado que el SDK no vincula ningún cliente, la aplicación consumidora es propietaria del endpoint (AWS S3, Cloudflare R2 o MinIO), del interceptor de firma y de la política de reintentos, e invoca cada operación importada directamente como una función pura:

```txt

```

En código de producción, sustituye la importación relativa `./src/index.ts` por `@company/s3-sdk` y elimina `withHTTPHandle(...)` para utilizar el `fetch` nativo de la plataforma.

---

## 4. Probar y publicar

Ejercita tus definiciones exportadas con [pruebas en memoria con handles](/es-ES/recipes/test-with-handle) que cubran el mapeo de ruta/consulta/cabeceras/cuerpo binario, la decodificación de `output`, las cabeceras de respuesta `ETag`, errores declarados `HTTP_STATUS` (`S3Error`) y la cancelación. Una vez verificadas, publica el paquete:

```sh
bun publish --access public
```

Consulta [Operaciones HTTP](/es-ES/docs/http), [Cliente](/es-ES/docs/client), [Pruebas](/es-ES/docs/testing) y [Arquitectura central](/es-ES/docs/design-decisions).
