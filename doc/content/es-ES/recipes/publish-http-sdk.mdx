# Crear y publicar un SDK [#publish-an-http-sdk-without-hiding-execute]

Un SDK empaqueta la API que ofrece tu equipo. Con Defjs, exporta definiciones de endpoint y sus contratos de datos; las aplicaciones consumidoras aportan la configuración del cliente y deciden cuándo llamarlas. Esta receta usa HTTP, y el mismo límite de paquete vale para definiciones SSE y WebSocket.

## 1. Define las operaciones del SDK

Crea `src/users.ts` en tu proyecto de SDK. Deja aquí los paths, el mapeo de la entrada, las respuestas y los errores del servicio. No hace falta una instancia de cliente, una dirección de despliegue ni una credencial actual para definir esta operación.

<include cwd meta='title="src/users.ts"'>
  examples/recipes/publish-http-sdk/users-sdk.ts#example
</include>

Expónla desde `src/index.ts`:

```ts
export { getUser } from "./users";
```

Añade otros módulos de operación y reexporta sus endpoints a medida que crece el SDK.

## 2. Empaqueta JavaScript y declaraciones

El proyecto del SDK tiene su propio límite de paquete:

```txt
users-sdk/
  package.json
  tsconfig.json
  src/
    index.ts
    users.ts
```

Usa este `package.json`, sustituyendo el nombre de ejemplo por un scope de paquete que te pertenezca:

```json
{
  "name": "@company/users-sdk",
  "version": "0.1.0",
  "type": "module",
  "sideEffects": false,
  "files": ["dist"],
  "exports": {
    ".": {
      "types": "./dist/index.d.ts",
      "default": "./dist/index.js"
    }
  },
  "scripts": {
    "build": "tsdown --platform neutral"
  },
  "peerDependencies": {
    "@defjs/core": "^0.6.0"
  },
  "devDependencies": {
    "@defjs/core": "^0.6.0",
    "tsdown": "^0.23.3",
    "typescript": "^7.0.2"
  }
}
```

Core sigue siendo una dependencia de runtime externa, compartida con la aplicación. El rango peer indica qué versiones de Core admite tu SDK; la dependencia de desarrollo te deja construir y probar contra ese rango. Este ejemplo coincide con el contrato actual `0.4.x`. Elige y prueba el rango de tu SDK antes de publicar; las declaraciones y el comportamiento en runtime dependen de él.

Añade `tsconfig.json`:

```json
{
  "compilerOptions": {
    "target": "ES2022",
    "module": "ESNext",
    "moduleResolution": "bundler",
    "lib": ["ES2022", "ESNext.Disposable", "DOM", "DOM.Iterable"],
    "strict": true,
    "noEmit": true
  },
  "include": ["src/**/*.ts"]
}
```

Estas declaraciones de librería aportan tipos, no polyfills de runtime. La aplicación sigue necesitando las Web API que usan los transportes que elija.

`tsdown` empaqueta la entrada en `dist/index.js` y emite `dist/index.d.ts`.

Construye e inspecciona el paquete:

```sh
bun install
bun run build
bun pm pack --dry-run
bun pm pack
```

Comprueba que el tarball contenga `dist/index.js` y `dist/index.d.ts`. Instala ese tarball en una aplicación aparte y verifica tanto sus tipos como la ejecución antes de publicar. El README del SDK debe documentar la API del servicio, las versiones compatibles de Core, la autenticación esperada y cualquier valor por defecto opcional.

## 3. Llámalo desde la aplicación consumidora

El ejemplo local deja la definición en `users-sdk.ts` junto a `app.ts` para poder ejecutarse sin red. Su import no crea un cliente; la aplicación configura un handle Fetch local y llama a la operación importada:

<include cwd meta='title="app.ts"'>
  examples/recipes/publish-http-sdk/app.ts#example
</include>

```txt
Ada
```

Para el SDK empaquetado, instálalo junto con una versión compatible de Core:

```sh
bun add @company/users-sdk @defjs/core@^0.6.0
```

Sustituye el import relativo del ejemplo por:

```ts
import { getUser } from "@company/users-sdk";
```

Configura la dirección de tu servicio y la autenticación en el cliente de la aplicación. Conserva `withHTTPHandle(...)` para las pruebas locales; quítalo para usar la implementación Fetch de la plataforma. Una segunda aplicación puede importar el mismo endpoint y elegir ajustes de cliente distintos sin cambiar la definición del SDK.

## 4. Verifica y publica

Usa las [pruebas locales del cliente](/es-ES/recipes/test-with-handle) para ejercitar la definición exportada, el mapeo de la solicitud, la validación de la respuesta y los errores declarados. Verifica el mismo endpoint con dos clientes configurados para direcciones de servicio y credenciales distintas. Mantén disponible el manejo tipado de `HTTP_STATUS` en el punto de llamada, y prueba la cancelación y la limpieza de streams de los transportes que exporta tu SDK.

Cuando el paquete haya pasado tus comprobaciones, publícalo desde el directorio del SDK con tu cuenta de npm:

```sh
bun publish --access public
```

Este comando publica un paquete público. Usa el registro y la política de acceso de tu organización para un SDK privado. Defjs no genera ni publica el paquete por ti.

Las fábricas de cliente y los métodos de conveniencia son añadidos opcionales. Pueden aportar valores por defecto del servicio o comportamiento de dominio, aceptando la configuración de quien llama y conservando las exportaciones directas de endpoint. Documenta cualquier mapeo de errores o política de ciclo de vida que introduzcan. Ninguno de los dos es necesario para un SDK reutilizable.

Consulta [HTTP](/es-ES/docs/http), [Cliente](/es-ES/docs/client) y [Decisiones de diseño](/es-ES/docs/design-decisions) para los contratos de fondo.
