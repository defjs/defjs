# Renovar un token Bearer tras un 401

En Defjs, `next(request)` invoca el resto de la cadena de interceptores hacia adentro; no vuelve a despachar desde el interceptor más externo. Ubica la asignación del token, la desduplicación de renovaciones simultáneas (_single-flight_) y el reintento único tras `401` dentro de **un único** interceptor HTTP, de modo que los interceptores externos de registro o de medición de tiempos no se ejecuten dos veces:

Un cuerpo que puede reenviarse no equivale a una operación de negocio repetible. Este interceptor también reenvía un `POST` JSON tras un 401 coincidente: dos entregas HTTP, primero rechazada y después aceptada. Úsalo para escrituras solo cuando la autenticación rechace la primera entrega antes de ejecutar el gestor de negocio; conserva una clave de idempotencia estable entre ambas entregas y usa desduplicación en el servidor. Si ese contrato no está disponible, devuelve el 401 en lugar de repetir automáticamente la escritura. El ejemplo completo no repite un cuerpo de petición `ReadableStream`.

Consulta [Interceptores](/es-ES/docs/interceptors) para conocer el orden de capas y los límites de reintentos.
