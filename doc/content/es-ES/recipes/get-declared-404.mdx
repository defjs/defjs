# GET con un 404 declarado

Declara tanto `output` (para respuestas 2xx) como `error` (para respuestas no 2xx) en `defineRequest`. En el punto de llamada, comprueba `error?.code === "HTTP_STATUS" && error.status === 404` para leer la carga tipada en `error.data`.

<Tabs items={["sdk/orders.ts", "app/main.ts", "get-order.ts"]}>
  <Tab value="sdk/orders.ts">
```ts
import { defineRequest, struct } from "@defjs/core";

export const getOrder = defineRequest({
  method: "GET",
  path: "/orders/:id",
  input: struct.object({ id: struct.number() }),
  builder: (input) => ({ path: { id: input.id } }),
  output: struct.object({ id: struct.number(), status: struct.string() }),
  error: struct.object({ message: struct.string() }),
});
```
  </Tab>
  <Tab value="app/main.ts">
```ts
import { createClient, withEndpoint } from "@defjs/core";
import { getOrder } from "../sdk/orders.ts";

const client = createClient(withEndpoint("https://api.example.com"));

async function main() {
const [error, order, response] = await getOrder(client, { id: 7 });
if (error?.code === "HTTP_STATUS" && error.status === 404) {
console.log(error.data.message);
return;
}
if (error) {
console.error(error.code);
return;
}
console.log(`Loaded ${order.status} from ${response.status}`);
}

void main();

````

Con un servidor que responda a `GET /orders/7` con `200` y `{ "id": 7, "status": "paid" }`, el script imprime:

```txt
Loaded paid from 200
````

- Todo código de estado no 2xx produce `HTTP_STATUS`. Declarar `error` decodifica y valida el cuerpo del error en `error.data`; omitir `error` deja `error.data` como `undefined` sin leer el cuerpo.
- Si un cuerpo de `error` declarado llega con el tipo de medio incorrecto, JSON inválido o no supera la validación del Struct, la operación devuelve en su lugar un fallo `RES_*`. Puesto que un único Struct de `error` abarca todos los estados no 2xx, utiliza `struct.or(...)` cuando diferentes estados de error presenten formas distintas.

Consulta [Operaciones HTTP](/es-ES/docs/http) y [Tratamiento de errores](/es-ES/docs/errors).
