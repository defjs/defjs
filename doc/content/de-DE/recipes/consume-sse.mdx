# Einen SSE-Stream verarbeiten

Jedes `EventStreamHandle` stellt genau einen asynchronen Iterator bereit. Platziere `stream.close(...)` und `await stream.closed` immer in einem `finally`-Block, damit frühe `break`- oder `return`-Anweisungen den zugrundeliegenden Fetch-Stream niemals offen lassen:

Sendet der Server als erstes Ereignis `line` mit den Daten `{ "text": "build started" }`, gibt das Skript folgendes aus:

```txt
build started
```

- SSE verbindet sich bei Netzwerk- oder Lesefehlern nicht automatisch wieder, es sei denn, du konfigurierst [`withRetry(...)`](/de-DE/api/core/withretry) am Client.
- Ist `withRetry(...)` gesetzt, beträgt `maxRetries` standardmäßig `3` pro Ausfall und setzt sich bei einem erfolgreichen Handshake zurück (`maxRetries: 0` deaktiviert Retries). Ohne ein eigenes `shouldRetry` werden nur `GET`-, `HEAD`-, `OPTIONS`-, `TRACE`-, `PUT`- und `DELETE`-Anfragen wiederholt. Eine Anfrage mit einem `ReadableStream`-Body wird nie wiederholt. Siehe [SSE-Event-Streams](/de-DE/docs/sse).
