# Einen SSE-Stream verarbeiten

Jedes `EventStreamHandle` stellt genau einen asynchronen Iterator bereit. Platziere `stream.close(...)` und `await stream.closed` immer in einem `finally`-Block, damit frühe `break`- oder `return`-Anweisungen den zugrundeliegenden Fetch-Stream niemals leaken lassen:

<Tabs items={["sdk/deployments.ts", "app/main.ts", "deploy-events.ts"]}>
  <Tab value="sdk/deployments.ts">
```ts
import { defineEventStream, struct } from "@defjs/core";

export const deployEvents = defineEventStream({
  path: "/deployments/events",
  events: {
    line: struct.object({ text: struct.string() }),
  },
});
```
  </Tab>
  <Tab value="app/main.ts">
```ts
import { createClient, withEndpoint } from "@defjs/core";
import { deployEvents } from "../sdk/deployments.ts";

const client = createClient(withEndpoint("https://api.example.com"));

async function main() {
const [error, stream] = await deployEvents(client);
if (error) {
console.error(error.code);
return;
}
try {
for await (const event of stream) {
if (event.event === "line") {
console.log(event.data.text);
break;
}
}
} finally {
stream.close("consumer-finished");
await stream.closed;
}
}

void main();

````
  </Tab>

Sendet der Server als erstes Ereignis `line` mit den Daten `{ "text": "build started" }`, gibt das Skript folgendes aus:

```txt
build started
````

- SSE verbindet sich bei Netzwerk- oder Lesefehlern nicht automatisch wieder, es sei denn, du konfigurierst [`withSSEReconnect(...)`](/de-DE/api/core/withssereconnect) am Client.
- Ist `withSSEReconnect` mit einem Optionen-Objekt aktiviert, beträgt `attempts` standardmäßig `3` pro Ausfall und setzt sich bei einem erfolgreichen Handshake zurück (`attempts: 0` deaktiviert Reconnects). Ohne ein eigenes `shouldReconnect` verbinden sich nur `GET`-, `HEAD`-, `OPTIONS`-, `PUT`- und `DELETE`-Anfragen mit wiederholbaren Bodys erneut. Siehe [SSE-Ereignisströme](/de-DE/docs/sse).
