# SDK entwickeln und veröffentlichen [#publish-an-http-sdk-without-hiding-execute]

Ein SDK paketiert die API, die dein Team anbietet. Mit Defjs exportierst du Endpoint-Definitionen und ihre Datenverträge; konsumierende Anwendungen liefern die Client-Konfiguration und entscheiden, wann sie aufgerufen werden. Dieses Rezept nutzt HTTP, und dieselbe Paketgrenze gilt für SSE- und WebSocket-Definitionen.

## 1. Die Operationen des SDKs definieren

Lege `src/users.ts` in deinem SDK-Projekt an. Pfade, Input-Abbildung, Responses und Service-Fehler gehören hierher. Um diese Operation zu definieren, brauchst du keine Client-Instanz, keine Deployment-Adresse und kein aktuelles Credential.

<include cwd meta='title="src/users.ts"'>
  examples/recipes/publish-http-sdk/users-sdk.ts#example
</include>

Stelle sie aus `src/index.ts` bereit:

```ts
export { getUser } from "./users";
```

Füge weitere Operationsmodule hinzu und re-exportiere ihre Endpoints, wenn das SDK wächst.

## 2. JavaScript und Deklarationen paketieren

Das SDK-Projekt hat seine eigene Paketgrenze:

```txt
users-sdk/
  package.json
  tsconfig.json
  src/
    index.ts
    users.ts
```

Nutze diese `package.json` und ersetze den Beispielnamen durch einen Paket-Scope, den du besitzt:

```json
{
  "name": "@company/users-sdk",
  "version": "0.1.0",
  "type": "module",
  "sideEffects": false,
  "files": ["dist"],
  "exports": {
    ".": {
      "types": "./dist/index.d.ts",
      "default": "./dist/index.js"
    }
  },
  "scripts": {
    "build": "tsdown --platform neutral"
  },
  "peerDependencies": {
    "@defjs/core": "^0.4.0"
  },
  "devDependencies": {
    "@defjs/core": "^0.4.0",
    "tsdown": "^0.23.3",
    "typescript": "^7.0.2"
  }
}
```

Core bleibt eine externe Laufzeitabhängigkeit, die du mit der Anwendung teilst. Der Peer-Bereich sagt, welche Core-Releases dein SDK unterstützt; die Development-Abhängigkeit lässt dich gegen diesen Bereich bauen und testen. Dieses Beispiel entspricht dem aktuellen `0.4.x`-Vertrag. Wähle und teste den Bereich für dein SDK, bevor du veröffentlichst; Deklarationen und Laufzeitverhalten hängen beide davon ab.

Füge `tsconfig.json` hinzu:

```json
{
  "compilerOptions": {
    "target": "ES2022",
    "module": "ESNext",
    "moduleResolution": "bundler",
    "lib": ["ES2022", "ESNext.Disposable", "DOM", "DOM.Iterable"],
    "strict": true,
    "noEmit": true
  },
  "include": ["src/**/*.ts"]
}
```

Diese Library-Deklarationen liefern Typen, keine Laufzeit-Polyfills. Die Anwendung braucht weiterhin die Web-APIs der Transports, die sie wählt.

`tsdown` bündelt den Einstieg in `dist/index.js` und erzeugt `dist/index.d.ts`.

Baue das Paket und sieh es dir an:

```sh
bun install
bun run build
bun pm pack --dry-run
bun pm pack
```

Prüfe, dass das Tarball `dist/index.js` und `dist/index.d.ts` enthält. Installiere dieses Tarball in einer separaten Anwendung und prüfe Typen und Ausführung, bevor du veröffentlichst. Das README des SDKs sollte die Service-API, kompatible Core-Versionen, die erwartete Authentifizierung und optionale Defaults dokumentieren.

## 3. Aus der konsumierenden Anwendung aufrufen

Das lokale Beispiel hält die Definition in `users-sdk.ts` neben `app.ts`, damit es offline laufen kann. Sein Import erzeugt keinen Client; die Anwendung konfiguriert einen lokalen Fetch-Handler und ruft die importierte Operation auf:

<include cwd meta='title="app.ts"'>
  examples/recipes/publish-http-sdk/app.ts#example
</include>

```txt
Ada
```

Für das paketierte SDK installierst du es zusammen mit einem kompatiblen Core-Release:

```sh
bun add @company/users-sdk @defjs/core@^0.4.0
```

Ersetze den relativen Import des Beispiels durch:

```ts
import { getUser } from "@company/users-sdk";
```

Konfiguriere Service-Adresse und Authentifizierung am Anwendungsclient. Behalte `withHTTPHandle(...)` für lokale Tests; entferne es, um das Fetch der Plattform zu nutzen. Eine zweite Anwendung kann denselben Endpoint importieren und andere Client-Einstellungen wählen, ohne die SDK-Definition zu ändern.

## 4. Prüfen und veröffentlichen

Nutze [Tests mit lokalem Client](/de-DE/recipes/test-with-handle), um die exportierte Definition, die Request-Abbildung, die Response-Validierung und deklarierte Fehler auszuführen. Prüfe denselben Endpoint mit zwei Clients, die für unterschiedliche Service-Adressen und Zugangsdaten konfiguriert sind. Halte die typisierte `HTTP_STATUS`-Behandlung an der Aufrufstelle verfügbar und teste Abbruch sowie Stream-Cleanup für die Transports, die dein SDK exportiert.

Wenn das Paket deine Prüfungen bestanden hat, veröffentliche aus dem SDK-Verzeichnis mit deinem npm-Konto:

```sh
bun publish --access public
```

Dieser Befehl veröffentlicht ein öffentliches Paket. Nutze die Registry und die Zugriffsregeln deiner Organisation für ein privates SDK. Defjs erzeugt oder veröffentlicht das Paket nicht für dich.

Client-Factories und Komfortmethoden sind optionale Ergänzungen. Sie können Service-Defaults oder Domänenverhalten anbieten, Konfiguration des Aufrufers annehmen und die direkten Endpoint-Exporte erhalten. Dokumentiere jede Fehlerabbildung oder Lifecycle-Regel, die sie einführen. Für ein wiederverwendbares SDK ist keines von beiden erforderlich.

Siehe [HTTP](/de-DE/docs/http), [Client](/de-DE/docs/client) und [Entwurfsentscheidungen](/de-DE/docs/design-decisions) für die zugrunde liegenden Verträge.
