# SDK entwickeln und veröffentlichen [#publish-an-http-sdk-without-hiding-execute]

Ein Defjs-SDK exportiert reine Operationsdefinitionen und Struct-Schemas als npm-Paket, während `createClient(...)`, Endpunkte, Zugangsdaten und Interceptors vollständig in der konsumierenden Anwendung verbleiben.

---

## 1. Das SDK-Paket aufbauen

Halte deine Operationsdefinitionen, Barrel-Exporte, `package.json` und `tsconfig.json` in einem dedizierten Paketverzeichnis und deklariere `@defjs/core` als `peerDependency`:

  </Tab>
  <Tab value="package.json">
```json
{
  "name": "@company/orders-sdk",
  "version": "0.1.0",
  "type": "module",
  "sideEffects": false,
  "files": ["dist"],
  "exports": {
    ".": {
      "types": "./dist/index.d.ts",
      "default": "./dist/index.js"
    }
  },
  "scripts": {
    "build": "tsdown --platform neutral"
  },
  "peerDependencies": {
    "@defjs/core": "^0.6.0"
  },
  "devDependencies": {
    "@defjs/core": "^0.6.0",
    "tsdown": "^0.23.3",
    "typescript": "^7.0.2"
  }
}
```
  </Tab>
  <Tab value="tsconfig.json">
```json
{
  "compilerOptions": {
    "target": "ES2022",
    "module": "ESNext",
    "moduleResolution": "bundler",
    "lib": ["ES2022", "ESNext.Disposable", "DOM", "DOM.Iterable"],
    "strict": true,
    "noEmit": true
  },
  "include": ["src/**/*.ts"]
}
```
  </Tab>
</Tabs>

- `@defjs/core` bleibt eine externe Laufzeit-`peerDependency`, die mit der konsumierenden Anwendung geteilt wird.
- `"sideEffects": false` erlaubt es Bundlern, ungenutzte Operationen per Tree-Shaking zu entfernen, wenn eine Anwendung nur einen Teil davon importiert.

---

## 2. Bauen und den Tarball überprüfen

Bündle `dist/index.js` und `dist/index.d.ts` mit `tsdown` und prüfe die Paketinhalte vor der Veröffentlichung:

```sh
bun install
bun run build
bun pm pack --dry-run
bun pm pack
```

Überprüfe, dass `dist/index.js` und `dist/index.d.ts` im Tarball enthalten sind.

---

## 3. Das SDK in einer Anwendung konsumieren

Installiere dein SDK zusammen mit `@defjs/core`:

```sh
bun add @company/orders-sdk @defjs/core@^0.6.0
```

Die Anwendung erstellt ihren eigenen `Client` und übergibt ihn an die importierte Operation:

<include cwd meta='title="app.ts"'>
  examples/recipes/publish-http-sdk/app.ts#example
</include>

```txt
paid
```

Im Produktionscode ersetzt du den relativen Import `./src/orders.ts` durch `@company/orders-sdk` und entfernst `withHTTPHandle(...)`, um das plattformnative `fetch` zu verwenden.

---

## 4. Testen und veröffentlichen

Prüfe deine exportierten Definitionen mit [In-Memory-Handle-Tests](/de-DE/recipes/test-with-handle), die Request-Mapping, `output`-Dekodierung, deklarierte `HTTP_STATUS`-Faults und Abbruchszenarien abdecken. Nach erfolgreicher Verifikation veröffentlichst du das Paket:

```sh
bun publish --access public
```

Siehe [HTTP-Operationen](/de-DE/docs/http), [Client](/de-DE/docs/client), [Tests](/de-DE/docs/testing) und [Kernarchitektur](/de-DE/docs/design-decisions).
