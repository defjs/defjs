# SDK entwickeln und veröffentlichen [#ein-http-sdk-veröffentlichen-ohne-execute-zu-verstecken]

Ein Defjs-SDK veröffentlicht wiederverwendbare API-Endpoints. Der Autor definiert Eingaben, Request-Abbildung und Response-Verträge; die Anwendung importiert die Endpoints, konfiguriert ihren Client und behandelt die Ergebnisse. Dieses Rezept führt vom Endpoint-Modul über ein prüfbares npm-Archiv bis zum Import in einer Anwendung.

## 1. Den Endpoint exportieren

Lege ein Paketverzeichnis `users-sdk` an und speichere diese Definition als `src/users.ts`. Das Modul exportiert `getUser`; es erzeugt keinen vorkonfigurierten Anwendungsclient und startet keine Requests.

`output` beschreibt den 2xx-Body, `error` den Body aller anderen Statuscodes. Die Anwendung kann dadurch einen deklarierten `404` anhand von `error.code` und `error.status` behandeln und `error.data` typisiert lesen. Diese Informationen bleiben im Ergebnis von `client.execute(...)` erhalten.

## 2. Den Paketeinstieg und den Build definieren

Exportiere die öffentliche API in `src/index.ts`. Der `.js`-Suffix passt zur ESM-Ausgabe von TypeScript mit `NodeNext`; die Quelldatei heißt weiterhin `users.ts`.

```ts title="src/index.ts"
export { getUser } from "./users.js";
```

Lege die folgende `package.json` im Paketverzeichnis an. Ersetze `@company` vor einer Veröffentlichung durch deinen npm-Scope. `@defjs/core` ist eine Peer-Abhängigkeit, damit SDK und Anwendung dieselbe kompatible Laufzeit nutzen. Die Dev-Abhängigkeiten ermöglichen den lokalen Build und seine Typprüfung.

```json title="package.json"
{
  "name": "@company/users-sdk",
  "version": "0.1.0",
  "type": "module",
  "sideEffects": false,
  "files": ["dist"],
  "exports": {
    ".": {
      "types": "./dist/index.d.ts",
      "default": "./dist/index.js"
    }
  },
  "scripts": {
    "build": "tsc -p tsconfig.json"
  },
  "peerDependencies": {
    "@defjs/core": "^0.4.0"
  },
  "devDependencies": {
    "@defjs/core": "^0.4.0",
    "typescript": "^7.0.2"
  }
}
```

`files` beschränkt die Nutzdateien des Pakets auf `dist`; npm kann zusätzlich Paketmetadaten, README und Lizenz aufnehmen. `exports` veröffentlicht JavaScript und Typdeklarationen am selben Einstiegspunkt. `sideEffects: false` passt hier, weil das Modul ausschließlich Definitionen exportiert.

```json title="tsconfig.json"
{
  "compilerOptions": {
    "target": "ES2022",
    "module": "NodeNext",
    "moduleResolution": "NodeNext",
    "lib": ["ES2022", "ESNext.Disposable", "DOM", "DOM.Iterable"],
    "strict": true,
    "declaration": true,
    "rootDir": "src",
    "outDir": "dist"
  },
  "include": ["src/**/*.ts"]
}
```

Die DOM-Typen decken die öffentlichen Web-API-Typen von Defjs ab; `ESNext.Disposable` ergänzt die Typen für Ressourcenfreigabe. Diese `lib`-Einträge installieren keine Laufzeit-Polyfills.

## 3. Das Paket bauen und prüfen

Führe im Verzeichnis `users-sdk` aus:

```sh
npm install
npm run build
npm pack --dry-run
npm pack
```

Prüfe in der Vorschau insbesondere `dist/index.js`, `dist/index.d.ts`, `dist/users.js` und `dist/users.d.ts`. Der letzte Befehl erzeugt mit dem Beispielnamen `company-users-sdk-0.1.0.tgz`. So kannst du die tatsächlich paketierten Dateien in einer anderen Anwendung testen. Ein lokaler [Fetch-Handle-Test](/de-DE/recipes/test-with-handle) sollte Erfolgs- und Fehlervertrag prüfen, bevor du veröffentlichst.

Teste auch denselben exportierten Endpoint mit zwei Clients, die unterschiedliche Service-Adressen und Credentials verwenden. Prüfe im separaten Verbraucherprojekt sowohl Typen als auch Ausführung des Archivs. Berücksichtige Abbruch und bei Streaming-APIs das Schließen der Ressourcen. Dokumentiere im SDK-README die Service-API, kompatible Core-Versionen und erwartete Authentifizierung.

## 4. Das SDK aus einer Anwendung verwenden

Installiere das Archiv und die kompatible Defjs-Laufzeit in einer separaten ESM-Anwendung. Passe den relativen Pfad an deinen Verzeichnisaufbau an:

```sh
npm install ../users-sdk/company-users-sdk-0.1.0.tgz @defjs/core@^0.4.0
```

Die Anwendung importiert den veröffentlichten Einstiegspunkt:

```ts
import { getUser } from "@company/users-sdk";
```

Das folgende ausführbare Dokumentationsbeispiel importiert relativ aus `./users-sdk.ts`, weil beide Dateien im Beispielverzeichnis liegen. Für den Test des npm-Pakets ersetze nur diesen Import durch den Paketimport oben. Der Client und der lokale Fetch-Handler bleiben im Code der Anwendung.

</include>

```txt
Ada
```

Speichere die Anwendung als `app.ts` und führe sie mit `bun app.ts` oder einer im [Schnellstart](/de-DE/docs/start) beschriebenen Node.js-Version mit `node app.ts` aus. Der lokale Handler macht den Test unabhängig von einem laufenden Service. Für die echte API entfernt die Anwendung `withHTTPHandle(...)` und konfiguriert Base-Endpoint, Authentifizierung und Interceptors an ihrem Client. Sie behandelt Ergebnis-Tupel und Abbruch weiterhin selbst.

## 5. Auf npm veröffentlichen

Wenn Scope, Paketname, Version und Archiv geprüft sind und dein npm-Konto für den Scope veröffentlichen darf, führe im Paketverzeichnis aus:

```sh
npm publish --access public
```

Danach installieren Anwendungen das Paket mit `npm install @company/users-sdk @defjs/core@^0.4.0`. Versioniere Änderungen an Eingaben, Ausgaben, Fehlern und Request-Abbildung als Änderungen des SDK-Vertrags. Defjs-Endpoints werden weiterhin von einem Defjs-Client ausgeführt; der Paketexport ändert diesen Vertrag nicht.

Client-Factories und Komfortmethoden sind optionale Ergänzungen. Sie können Service-Defaults oder Domänenverhalten anbieten, Konfiguration des Aufrufers annehmen und die direkten Endpoint-Exporte beibehalten. Dokumentiere dabei die eingeführten Fehlerabbildungen und Regeln für den Ressourcenlebenszyklus. Für ein wiederverwendbares SDK ist keine Factory erforderlich.

Siehe [Commands](/de-DE/docs/commands), [Client](/de-DE/docs/client) und [Entwurfsentscheidungen](/de-DE/docs/design-decisions).
