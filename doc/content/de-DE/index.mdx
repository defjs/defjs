# Defjs

**Entwickelt für bessere SDKs.**

Defjs hilft Teams, ihre APIs in wiederverwendbare TypeScript-SDKs zu verwandeln. `def` steht für `define`: Beschreibe die Operationen, die dein Service anbietet, exportiere sie aus einem Modul oder npm-Paket, und lass jede Anwendung ihren eigenen Client konfigurieren, um sie aufzurufen.

## SDK definieren, Anwendung konfigurieren

| SDK-Autor                                                                | SDK-Nutzer                                                        |
| ------------------------------------------------------------------------ | ----------------------------------------------------------------- |
| Operationen, Eingabe, Request-Abbildung, Responses und Fehler definieren | Service-Adresse, Zugangsdaten, Interceptors und Transport wählen  |
| Typisierte HTTP-, SSE- und WebSocket-Endpoints exportieren               | Diese Endpoints importieren und mit einem Defjs-Client aufrufen   |
| Den API-Vertrag pflegen und veröffentlichen                              | Ergebnisse behandeln und Abbruch, Streams sowie Sessions besitzen |

Eine SDK-Definition bindet keinen Anwendungsclient. Derselbe exportierte Endpoint kann eine Browser-Anwendung, einen Server oder einen lokalen Test mit unterschiedlichen Client-Konfigurationen bedienen. Beide Seiten nutzen weiterhin den Defjs-Ausführungsvertrag und kompatible Core-Versionen.

Das SDK exportiert eine Operation:

<include cwd meta="get-health.ts">
  examples/home/get-health.ts#example
</include>

Die Anwendung importiert sie und besitzt die Ausführung:

<include cwd meta="app.ts">
  examples/home/app.ts#example
</include>

Der Aufruf `getHealth(client)` startet den Request. Veröffentlichst du die Definition, importieren Nutzer sie aus deinem SDK-Paket statt aus der lokalen Datei.

## Bewährte Praxis

Eine Definition bleibt vom Client unabhängig. Übergib den Client der Anwendung als erstes Argument, etwa `getHealth(client)`. Die Anwendung besitzt außerdem die Service-Adresse und die Zugangsdaten. Lies zuerst das Error-first-Tupel. Wenn `error` gesetzt ist, melde `error.code` und kehre aus der Funktion zurück, bevor du den Erfolgswert liest.

1. [Definiere deine erste Operation und führe sie aus](/de-DE/docs/start), in getrennten Dateien für SDK und Anwendung.
2. Beschreibe die [Datenverträge](/de-DE/docs/struct) und [HTTP-Operationen](/de-DE/docs/http), die dein SDK exportiert.

Die [Entwurfsentscheidungen](/de-DE/docs/design-decisions) erklären, warum API-Definitionen und Ausführung getrennte Eigentümer haben. Dieselbe Struktur kannst du in einer Anwendung nutzen, bevor du ein Paket veröffentlichst.

## Transport wählen

| Du brauchst                          | Starte mit                          | Erfolgreiches Ergebnis                                                             |
| ------------------------------------ | ----------------------------------- | ---------------------------------------------------------------------------------- |
| Request + statusspezifische Response | [HTTP](/de-DE/docs/http)            | Dekodierte Daten + `DecodedResponse` (`HttpMeta`, wenn kein Output deklariert ist) |
| Langlebiger Server-Event-Feed        | [SSE](/de-DE/docs/sse)              | Ein Stream + Startup-`open`-Snapshot                                               |
| Bidirektionale Session               | [WebSocket](/de-DE/docs/web-socket) | Eine Session + Startup-`connection`-Snapshot                                       |

Alle drei Transports folgen derselben Folge: eine Operation definieren, dann mit dem Client der Anwendung und der Eingabe des Aufrufers aufrufen.

## Paket wählen

| Paket                         | Wann                                                                                                             |
| ----------------------------- | ---------------------------------------------------------------------------------------------------------------- |
| `@defjs/core`                 | SDK-Operationen und Verträge definieren; Clients erzeugen und HTTP-, SSE- und WebSocket-Operationen aufrufen     |
| `@defjs/react`                | `ClientProvider` / `useClient` — siehe [React](/de-DE/docs/integrations/react)                                   |
| `@defjs/vue`                  | Plugin + `injectClient` — siehe [Vue](/de-DE/docs/integrations/vue)                                              |
| `@defjs/opentelemetry-server` | Ausgehende Spans, Metrics und Logs — siehe [OpenTelemetry Server](/de-DE/docs/integrations/opentelemetry-server) |

## Ergebnisformen

Alle drei Transports liefern ein Error-first-Tupel mit drei Einträgen. Positionen stimmen; Bedeutungen nicht:

- HTTP → `[error, data, response]`
- SSE → `[error, stream, open]`
- WebSocket → `[error, session, connection]`

Bei einem Fehler ist der zweite Eintrag `undefined`. Bei HTTP ist auch der dritte Eintrag `undefined`, weil der Fault die Response-Metadaten trägt. Bei SSE und WebSocket ist der dritte Eintrag der Startup-Snapshot, sofern vor dem Fehler einer erfasst wurde. Siehe [Fehler](/de-DE/docs/errors).

## Ownership in einem Atemzug

Brich HTTP ab, wenn sie veraltet ist. Schließe SSE und `await stream.closed`. Schließe WebSocket und `await session.closed`. Auf einem Server erzeuge den Client innerhalb der Request-Grenze, wenn Options Cookies, Auth oder Tenant-Daten erfassen. Schwärze URLs, Headers und Bodies, bevor du sie loggst.

Defjs liefert Definitionen, Validierung und Ausführung. Anwendungen wählen Caching- und Retry-Regeln; Stream-Reconnect ist opt-in. Handgeschriebene SDK-Pakete werden heute unterstützt. CLI-Werkzeuge und OpenAPI-/SDK-Generierung bleiben geplant.
