<ApiReference identity="@defjs/core:Fault" />

```ts
type Fault<TErr extends AnyStruct | undefined = undefined> = FaultOf<[TErr] extends [undefined] ? undefined : Infer<TErr>>
```

`TErr` ist das deklarierte `error`-Struct des Endpoints oder `undefined`, wenn er keines deklariert. `Fault<TErr>` ist [`FaultOf`](/de-DE/api/core/faultof-type), angewendet auf den dekodierten Body-Typ; es ist also die Union dreier Varianten: [`DecodeFault`](/de-DE/api/core/decodefault-type), [`HttpStatusFault<TErr>`](/de-DE/api/core/httpstatusfault-type) und [`PreflightFault`](/de-DE/api/core/preflightfault-type). Verzweige über `fault.code`.

Jede Variante ist ein nativer `Error` namens `DefjsFault`, daher liefert `String(fault)` `DefjsFault: <message>`. `code` und die Varianten-Metadaten — `status`, `response`, `data` — sind enumerable eigene Properties. Die native `cause`-Kette ist nicht enumerable.

Default-Struct-Messages sagen `received <kind>`, nie den empfangenen Wert. Ein JSON-`SyntaxError` hinter `RES_DECODE_FAILED` ergibt die Message `Response body could not be decoded`. Strukturelle Pfade behalten Record-Keys bei, die sensibel sein können. Rohes `StructIssue.received` und Parser-Causes bleiben sensibel; eigene `errorMap`- und Extension-Messages werden wörtlich verwendet und müssen vor dem Loggen geprüft werden.
