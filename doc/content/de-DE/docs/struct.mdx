# Struct & Schemas

`struct` deklariert den Wire-Datenvertrag zwischen einem SDK und seinen Konsumenten: Eingaben des Aufrufers, `2xx`-Ausgaben, deklarierte Service-Fehler, SSE-Events und WebSocket-Frames.

- **Statische Inferenz**: Leite TypeScript-Typen mit `Infer<typeof Schema>` ab.
- **Error-first-Validierung**: Validiere Werte zur Laufzeit mit `struct.parse(Schema, value)` — liefert `[null, data]` oder `[StructError, undefined]`, ohne Exceptions zu werfen.

Geparste Objekte behalten ausschließlich deklarierte Felder (unbekannte Properties werden entfernt) und besitzen einen `null`-Prototyp. Jeder fehlende Pflichtschlüssel, falsche Primitivtyp oder ungültige Zweig erzeugt einen `StructError` ohne partielle Ausgabe.

## 2. Pflichtfelder, optionale und nullbare Felder

Defjs unterscheidet strikt zwischen **Feld-Präsenz** (`undefined`) und **Nullbarkeit** (`null`). Jeder Struct-Konstruktor ist standardmäßig strikt erforderlich und nicht-nullbar:

| Deklaration                  | Fehlend / `undefined`                        | `null`      | Gültiger Wert         |
| ---------------------------- | -------------------------------------------- | ----------- | --------------------- |
| `struct.string()`            | Abweisen                                     | Abweisen    | Akzeptiert `string`   |
| `struct.string().optional()` | Akzeptieren (beim Serialisieren weggelassen) | Abweisen    | Akzeptiert `string`   |
| `struct.string().null()`     | Abweisen                                     | Akzeptieren | Akzeptiert `string`   |
| `struct.string().nullish()`  | Akzeptieren (beim Serialisieren weggelassen) | Akzeptieren | Akzeptiert `string`   |
| `struct.null()`              | Abweisen                                     | Akzeptieren | Weist Nicht-`null` ab |

<include cwd lang="typescript">

</include>

Auch `struct.any()` und `struct.unknown()` weisen `null` und `undefined` ab, es sei denn, sie werden mit `.null()`, `.optional()` oder `.nullish()` verkettet.

## 3. Bidirektionale Wire-Aliase (`.alias()`)

Verwende `.alias("wire_name")`, wenn das Backend `snake_case` oder Header-Namen verwendet, dein TypeScript-SDK aber `camelCase` nutzt. Du deklarierst das Alias einmalig am Feld, und es wirkt automatisch in beide Richtungen:

| Grenze                                                                             | Verwendeter Schlüssel                           |
| ---------------------------------------------------------------------------------- | ----------------------------------------------- |
| Operations-`input` und `struct.parse(Schema, value)`                               | Logischer Name (`customerName`)                 |
| Vom `builder` zurückgegebener typisierter Struct-Wert (`body`, `query`, `headers`) | Wire-Alias (`customer_name`)                    |
| Dekodierung von JSON-Responses / SSE-Events / WebSocket-Frames                     | Wire `customer_name` → logisches `customerName` |
| Anonymer Objektschlüssel direkt im `builder` notiert                               | Wörtlicher Schlüssel wie geschrieben            |

<include cwd lang="typescript">
  examples/struct/aliases.ts#example
</include>

Das Spreaden eines typisierten Objekts im `builder` (`{ ...input.order, extra: 1 }`) behält dessen Struct-Codierung und Aliase bei. Werden sowohl der logische Schlüssel als auch dessen Wire-Alias auf demselben Objekt notiert, schlägt der Aufruf mit `REQ_BUILD_FAILED` fehl.

## 4. Request-Platzierung und Form-Codecs

`input` definiert die Parameter; `builder` platziert sie in `{ path, query, headers, body }`. Für formularcodierte Bodys markieren `struct.urlencoded(shape)` und `struct.formData(shape)` das Wurzelobjekt, sodass der Transport es automatisch als `URLSearchParams` oder `FormData` serialisiert:

<include cwd lang="typescript">
  examples/struct/request-placement.ts#example
</include>

| Vom `builder` zurückgegebene Body-Wurzel                  | Wire-Format       | Standard-`Content-Type`                           |
| --------------------------------------------------------- | ----------------- | ------------------------------------------------- |
| Typisiertes Objekt, Array, endliche Zahl, Boolean, `null` | JSON-Text         | `application/json`                                |
| `string`-Struct oder roher `string`                       | UTF-8-Text        | `text/plain;charset=UTF-8`                        |
| `struct.urlencoded(shape)` an der Body-Wurzel             | `URLSearchParams` | `application/x-www-form-urlencoded;charset=UTF-8` |
| `struct.formData(shape)` an der Body-Wurzel               | `FormData`        | `multipart/form-data; boundary=...`               |
| `Blob` / `File` (`struct.file()`)                         | Binärer Blob      | `blob.type` oder `application/octet-stream`       |
| `ArrayBuffer` / View / `ReadableStream`                   | Rohe Bytes        | `application/octet-stream`                        |

## 5. `StructError` und Issues behandeln

`struct.parse(Schema, data, { aliases?, errorMap? })` gibt im Fehlerfall `[StructError, undefined]` zurück. `StructError` erweitert den nativen `Error` und bietet `issues`, `format()`, `flatten()` und `prettify()`:

<include cwd lang="typescript">
  examples/struct/parse-failures.ts#example
</include>

Jedes `StructIssue` enthält `code` (`invalid_type`, `missing_key`, `invalid_literal`, `invalid_enum`, `invalid_union`, `invalid_intersection` oder `custom`), `path`, `expected`, `received` und `message`. Standardmeldungen lassen den empfangenen Wert weg und nennen nur seinen _Typ_, aber Pfade behalten dynamische Record-Schlüssel, die sensible Werte enthalten können. `String(err)` und `err.prettify()` sind keine Grenze für die Schwärzung; verwende beim Loggen eine Allowlist sicherer Felder und behandle rohe `received`-Werte sowie eigene Meldungen als sensibel.

| Konstruktor                                                | Akzeptierte Eingabe                        | Inferierte Ausgabe                                                |
| ---------------------------------------------------------- | ------------------------------------------ | ----------------------------------------------------------------- |
| `struct.string()` / `struct.boolean()`                     | Passender Primitivtyp                      | `string` / `boolean`                                              |
| `struct.number()`                                          | Jede Zahl außer `NaN`                      | `number` (`NaN` abgewiesen; `±Infinity` in JSON-Bodys abgewiesen) |
| `struct.bigint()`                                          | `bigint` oder numerischer String           | `bigint`                                                          |
| `struct.date()`                                            | Gültiges `Date`, Timestamp oder ISO-String | `Date`                                                            |
| `struct.literal(value)`                                    | Exakter primitiver Literalwert             | Literal-Typ                                                       |
| `struct.enum(values)`                                      | Deklariertes String- oder Number-Element   | Union von Literalen                                               |
| `struct.array(item)` / `struct.tuple(items)`               | Array / Tupel fester Länge                 | `T[]` / `[...]`                                                   |
| `struct.object(shape)` / `struct.record(val)`              | Reines Objekt                              | Typisiertes Objekt / `Record<string, V>`                          |
| `struct.discriminatedUnion(key, options)`                  | Objekt mit literalem `key`-Diskriminator   | Union von Objekt-Zweigen                                          |
| `struct.or(branches)`                                      | Erster passender Zweig                     | Union der Zweig-Typen                                             |
| `struct.intersection(members)`                             | Wert, der alle Mitglieder erfüllt          | Tief zusammengeführte Schnittmenge (Intersection)                 |
| `struct.file()` / `struct.blob()` / `struct.arrayBuffer()` | `File` / `Blob` / `ArrayBuffer`            | Binäre Repräsentation                                             |

### Rekursive Structs

Ein selbstbezüglicher Typ liest sich über eine Getter-Eigenschaft der Shape selbst. Die Getter laufen einmal, wenn das Objekt-Struct zum ersten Mal verwendet wird, nicht beim Definieren der Konstante, daher kann die Konstante sich selbst nennen. Annotieren Sie die Konstante mit `Struct<T>`: TypeScript kann einen Typ, der auf sich selbst verweist, nicht ableiten.

### Was `struct` nicht tut

- `struct` deklariert nur Struktur. Stringlänge, Muster, Zahlenbereiche und Geschäftsregeln gehören nach dem Parsen in den Anwendungscode.
- Das Parsen stoppt beim ersten ungültigen Feld. Es füllt nie ein fehlendes Feld mit einem Nullwert und gibt nie eine Teilausgabe zurück.
