# Port-Transport (`@defjs/core/port`)

`@defjs/core/port` ermöglicht es einem isolierten Kontext (`SharedWorker`, Dedicated Worker, Sandbox-`iframe`, Electron-Renderer oder einem WebExtension-Popup / Side Panel / Content Script), reine `@defjs/core`-SDK-Definitionen über einen einzelnen gemultiplexten Port auszuführen, ohne Definitionen an den Proxy-Transport zu koppeln.

- Keine Laufzeitabhängigkeiten; wird als optionale Subpath-Exporte `@defjs/core/port` und `@defjs/core/port/webext` ohne Bundle-Overhead bei Nichtverwendung bereitgestellt
- Teilt einen Port gleichzeitig über HTTP (einschließlich `ReadableStream`-Uploads/-Downloads), SSE (`text/event-stream`) und WebSocket-Verbindungen hinweg
- **Standardmäßig Fail-Closed-Sicherheit**: `attachPortHost` lehnt jeglichen Datenverkehr ab, sofern der Host nicht `allowedOrigins`, `allowRequest` oder explizit `allowAnyOrigin: true` festlegt

```bash
bun add @defjs/core
```

## MV3-WebExtension-Proxy (`@defjs/core/port/webext`)

Ein WebExtension-`runtime.Port` kann `ArrayBuffer`-Objekte nicht direkt über Chromium-/Firefox-/Safari-Erweiterungsgrenzen hinweg transferieren und trennt die Verbindung, sobald ein Manifest-V3-Service-Worker pausiert. `@defjs/core/port/webext` liefert den abhängigkeitsfreien strukturellen Adapter `fromWebExtPort` (ohne dass `@types/chrome` benötigt wird), der `"json"`-gechunktes Base64-Framing nutzt und Lazy-Connector-Funktionen für automatisches Wiederverbinden nach dem Ruhezustand des Service-Workers unterstützt:
