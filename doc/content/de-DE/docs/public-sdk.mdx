# Design öffentlicher SDKs [#public-sdk-design]

Wenn dein Unternehmen oder Plattform-Team ein offizielles TypeScript-SDK für externe Entwickler veröffentlicht (zum Beispiel ein Objektspeicher-SDK, ein Payment-Gateway-SDK oder ein SaaS-Plattform-SDK), muss das SDK-Paket **den Wire-Vertrag definieren, ohne die Laufzeitumgebung vorzuschreiben**.

Anhand eines **zu Amazon S3 kompatiblen SDKs (`@company/s3-sdk`)** als konkretem Bauplan zeigt dieser Leitfaden, wie du ein mehrmoduliges öffentliches SDK mit `schema/` und reinen Funktionsmodulen in `request/` entwirfst.

---

## 1. Warum öffentliche SDKs von der Trennung in Defjs profitieren

Herkömmliche SDKs bündeln eine schwergewichtige Client-Klasse (`new S3Client({ region, credentials })`), die eng an Command-Klassen oder statische Service-Klassen gekoppelt ist. Die Entwicklung deines öffentlichen SDKs mit `@defjs/core` löst vier wiederkehrende Probleme für deine externen Nutzer:

1. **Flexibilität für mehrere Umgebungen und Sandboxen**: Da `@company/s3-sdk` weder einen Endpunkt noch einen Client bindet, kann ein Kunde exakt dieselben Operationsdefinitionen auf die Produktion (`https://s3.us-east-1.amazonaws.com`), eine Staging-Sandbox, Cloudflare R2 oder einen lokalen MinIO-Container während CI-Tests richten.
2. **100 % Bundler-Tree-Shaking**: Durch den Export eigenständiger reiner Funktionen (`listBuckets`, `listObjectsV2`, `getObject`, `putObject`, `deleteObject`) mit `"sideEffects": false` verwirft ein Browser-Bundle, das nur `getObject` und `putObject` aufruft, jeden anderen Endpunkt und jedes andere Schema.
3. **Laufzeitvalidierung + statische Typen aus einer einzigen Quelle**: Externe Konsumenten erhalten sowohl TypeScript-Typen zur Compile-Zeit (`Infer<typeof ...>`) als auch eine Laufzeitvalidierung für Antworten und Fehler (`struct`). Das schützt sie vor unerwarteten Wire-Payloads und wandelt `snake_case`-Felder oder ISO-Datumsstrings automatisch um.
4. **Volle Kontrolle über Authentifizierung, Retries und Telemetrie**: Kunden hängen ihre eigenen Interceptors zur Rotation von Zugangsdaten, `withRetry(...)`-Richtlinien, Multi-Region-Load-Balancer (`withBalancer(...)`) oder serverseitiges OpenTelemetry (`@defjs/opentelemetry-server`) an ihren eigenen `Client`.

## 2. Verzeichnisstruktur des Pakets

Teile das SDK-Paket in `src/schema/` (Datenstrukturen) und `src/request/` (nach Ressource gruppierte reine Operationsdefinitionen) mit einer flachen Barrel-Datei `src/index.ts` auf:

```text
@company/s3-sdk/
├── src/
│   ├── schema/                 # 1. Gemeinsame struct-Schemas + Infer<typeof ...>-Typen
│   │   ├── common.ts           #    StorageClass, S3Error
│   │   ├── bucket.ts           #    Bucket, ListBucketsOutput
│   │   └── object.ts           #    ObjectSummary, ListObjectsOutput
│   ├── request/               # 2. Reine defineRequest-Funktionen nach Ressourcendömäne
│   │   ├── buckets.ts          #    BucketInput, listBuckets, headBucket, deleteBucket
│   │   └── objects.ts          #    listObjectsV2, headObject, getObject, putObject, deleteObject
│   └── index.ts                # 3. Barrel-Exporte für Root- und Tree-Shaking-fähige Importe
├── package.json                # sideEffects: false, peerDependencies: { "@defjs/core": "^0.8.0" }
└── tsconfig.json
```

### Ergonomische Operationsverträge entwerfen

- **Aufrufer-Eingaben flach halten und im `builder` verteilen**: Bei `putObject` übergeben Aufrufer ein einziges ergonomisches Objekt (`{ bucket, key, body, contentType, storageClass }`). Der synchrone `builder` teilt diese Eingabe auf `path` (`:bucket/:key`), `headers` (`content-type`, `x-amz-storage-class`) und den binären `body` (`Blob`) auf. Bei `listObjectsV2` bildet `builder` die Felder `continuationToken` und `maxKeys` neben `list-type: 2` auf die S3-Query-Parameter `continuation-token` und `max-keys` ab.
- **`output` an den Wire-Payload anpassen**:
  - **Strukturiertes JSON (`listBuckets`, `listObjectsV2`)**: Deklariere ein `struct.object(...)` mit `.alias()`-Zuordnungen und `struct.date()`-Feldern.
  - **Binärer Payload (`getObject`)**: Deklariere `output: struct.blob()` (oder `struct.arrayBuffer()`).
  - **Leerer Body (`headBucket`, `headObject`, `putObject`, `deleteObject`)**: Lasse `output` weg, damit `HEAD`-, `200`- und `204`-Antworten mit null Bytes erfolgreich abgeschlossen werden, ohne eine JSON-Dekodierung zu versuchen, während Aufrufer weiterhin Antwort-Header (`response.headers.get("etag")`) aus dem dritten Tupel-Eintrag lesen können.

## 4. Wie externe Entwickler dein SDK nutzen

Externe Anwendungen installieren `@company/s3-sdk` zusammen mit `@defjs/core`, konfigurieren ihren eigenen `Client` mit Endpunkt und Signatur-Interceptor und rufen deine exportierten Operationen direkt als reine Funktionen auf. Das Beispiel folgt der Fehlerbehandlung im Go-Stil: `syncReport` macht drei Aufrufe, benennt deshalb jeden Fehler nach seinem Schritt (`putErr`, `listErr`, `getErr`), gibt ein Error-first-Tupel zurück und umhüllt den fehlgeschlagenen Schritt mit `new Error("put object", { cause: putErr })`, wie Gos `fmt.Errorf("put object: %w", err)`. Nur `main`, die Spitze des Programms, behandelt den Fehler, indem sie ihn protokolliert:
