# Übersicht der Integrationen

Eine Integration erweitert den `Client` der Anwendung an einem klar definierten Erweiterungspunkt, ohne `@defjs/core` zu verändern oder eine SDK-Definition an ein Framework oder einen Telemetrie-Stack zu koppeln. Deine SDK-Definitionen bleiben reine `@defjs/core`-Module; die konsumierende Anwendung entscheidet selbst, welche Integrationen installiert werden.

Jedes Defjs-Plugin folgt dem **Thin-Plugin-Vertrag**:

- **Kein verstecktes Caching oder State-Management**: Plugins speichern niemals Antworten zwischen, wiederholen Requests nicht eigenmächtig und verwalten keinen Query-Zustand.
- **Kein Austausch des Transports**: Plugins wrappen oder ersetzen niemals den zugrundeliegenden HTTP-, SSE- oder WebSocket-Transport.
- **Vollständige Lifecycle-Kontrolle beim Aufrufer**: Das Unmounten eines UI-Providers oder das Herunterfahren eines Telemetrie-SDKs bricht laufende Anfragen nicht automatisch ab und schließt keine aktiven Streams.

## Zwei Plugin-Architekturen

### 1. Framework-Plugins (`@defjs/react`, `@defjs/vue`)

Ein Framework-Plugin reicht einen bestehenden [`DerivableClient`](/de-DE/api/core/derivableclient-type) über native Dependency-Injection (React Context oder Vue `provide` / `inject`) im Komponentenbaum nach unten:

<Tabs items={["sdk/orders.ts", "app/main.tsx", "app/OrderCard.tsx"]}>
<Tab value="sdk/orders.ts">

```ts
import { defineRequest, struct } from "@defjs/core";

export const Order = struct.object({
  id: struct.number(),
  status: struct.string(),
});

export const getOrder = defineRequest({
  method: "GET",
  path: "/orders/:id",
  input: struct.object({ id: struct.number() }),
  builder: (input) => ({ path: { id: input.id } }),
  output: Order,
});
```

</Tab>
<Tab value="app/main.tsx">

```tsx
import { createClient, withEndpoint } from "@defjs/core";
import { ClientProvider } from "@defjs/react";
import { OrderCard } from "./OrderCard.tsx";

const client = createClient(withEndpoint("https://api.example.com"));

export function App() {
  return (
    <ClientProvider client={client}>
      <OrderCard id={42} />
    </ClientProvider>
  );
}
```

</Tab>
<Tab value="app/OrderCard.tsx">

```tsx
import { useClient } from "@defjs/react";
import { getOrder } from "../sdk/orders.ts";

export function OrderCard({ id }: { id: number }) {
  const client = useClient();
  // Übergib `client` oder `client({ signal })` innerhalb eines Effects oder Query-Hooks an `getOrder(...)`
  void id;
  void getOrder;
  void client;
  return null;
}
```

</Tab>
</Tabs>

### 2. Middleware-Plugins (`@defjs/opentelemetry-server`)

Ein Middleware-Plugin ist eine Factory, die eine [`ClientOption`](/de-DE/api/core/clientoption-type) zurückgibt. Wird diese an `createClient(...)` übergeben, hängt sie HTTP-, SSE- und/oder WebSocket-Interceptors über `withInterceptors` an:

<Tabs items={["plugins/request-id.ts", "app/client.ts"]}>
<Tab value="plugins/request-id.ts">

<include cwd lang="typescript">
  examples/integrations/request-id.ts#example
</include>

</Tab>
<Tab value="app/client.ts">

```ts
import { createClient, withEndpoint } from "@defjs/core";
import { withRequestIdHeader } from "../plugins/request-id.ts";

export const client = createClient(
  withEndpoint("https://api.example.com"),
  withRequestIdHeader(),
);
```

</Tab>
</Tabs>

Siehe [Interceptors](/de-DE/docs/interceptors) für Reihenfolgeregeln, Retry-Grenzen und Streaming-Lifecycle-Hooks.
