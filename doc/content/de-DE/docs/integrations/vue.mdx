# Vue

Die Vue-Anwendung importiert die Endpoints aus ihrem SDK und führt sie über einen injizierten Client aus. Das SDK bleibt unabhängig von Vue. Erzeuge und konfiguriere den Client an der passenden Anwendungs- oder Request-Grenze; das Framework-Plugin stellt ihn den Komponenten bereit.

Diese Plugins sind optionale Helfer, um einen bestehenden `Client` bereitzustellen und zu lesen. Du kannst einen festen anwendungseigenen Client importieren, wiederverwendbarer Logik einen Client explizit übergeben, Framework-Injection für Vorgaben im Baum und Subtree-Overrides nutzen oder deine eigene Struktur wählen. SDK-Definitionen setzen diese Plugins nicht voraus.

Verdrahte einen bestehenden `@defjs/core`-Client in Vue. Du bekommst ein Plugin, einen Injection-Key und `injectClient()`. Das Paket erzeugt **keine** Clients, legt keine Results im Cache ab, wiederholt keine Commands und schließt Transport-Resources bei Unmount nicht.

## Grundeinrichtung

Installiere `@defjs/core`, `@defjs/vue` und Vue 3.2+ (das Plugin braucht nur `provide` / `inject`, aber die Beispiele nutzen `<script setup>` und `onScopeDispose`, die mit 3.2 kamen). ESM:

`bun add @defjs/core @defjs/vue vue`

`createClientPlugin(client)` provides genau das Object, das du übergibst. Kein Clone, kein Disposal-Hook. Configure Core-Options und Interceptors, wenn du den Client erzeugst.

`onCleanup` läuft, bevor der Watcher neu läuft und wenn er stoppt. Registriere es, bevor Async-Arbeit startet. Das Error-first-Tupel bleibt Application-Data.

## Inject und Override

`injectClient(key)` liest den nächsten Provider für diesen Key; ohne Argument oder mit `undefined` wird `HTTP_CLIENT` verwendet. Ruf es in einem gültigen Vue-Injektionskontext auf: synchrones `setup()` oder `app.runWithContext()` (Vue 3.3+). Letzteres liefert nur synchronen App-Kontext, keine Subtree-Overrides und keinen Kontext über ein normales `await` hinweg. Vom Compiler nach Top-Level-`await` in `<script setup>` wiederhergestellte Kontexte bleiben gültig.

Nutze für einen eigenen `InjectionKey<Client>` `app.provide(key, client)` oder `provide(key, client)` in einer übergeordneten Komponente. Beide Seiten müssen dasselbe `Symbol`-Objekt teilen; gleiche Beschreibungen machen Keys nicht gleich. `createClientPlugin(client)` nimmt weiterhin nur den Client an und stellt nur `HTTP_CLIENT` bereit.

Wirft einen `Error`, wenn kein Injektionskontext aktiv ist oder für den gewählten Key kein Client vorliegt. Ein fehlender eigener Key fällt nie auf `HTTP_CLIENT` zurück; das installierte Plugin allein erzeugt keinen Injektionskontext.

Eine App-Funktion, die nur einen Client beschafft, kann `explicitClient ?? injectClient()` nutzen: Nur der Fallback-Zweig braucht einen Injektionskontext. Andere Lifecycle-APIs im selben Composable behalten ihre eigenen Kontextanforderungen. Lies den Client vor Async-Arbeit in einem gültigen Kontext und verwende das Objekt weiter.

## HTTP-Arbeit außerhalb eines Watchers besitzen

Für Arbeit, die ein Composable oder eine Komponente außerhalb eines Watchers startet, nutze `AbortController` + `onScopeDispose`. Brich Startup und aktive Arbeit ab; prüfe das Signal, bevor du reaktiven State zuweist. Ein Plugin oder Injection-Scope inferiert nicht, wer einen Command besitzt. Für List-Pages umhülle `execute` mit Vue Query (oder ähnlich) — `@defjs/vue` bleibt nur DI und liefert **kein** `useRequest`.

Wenn ein Scope einen Client besitzt, halte ihn request-independent für browser-weite Reuse. Wenn er Headers, Cookies, User, Tenants oder Credentials erfasst, erzeuge ihn in der relevanten App-/SSR-Request-Grenze und stelle diese Instanz dort per `provide` bereit.

## Realtime-Scope cleanupen

Schließe einen Stream oder eine Session auch, wenn der Scope mid-connect verschwindet. Brich Startup ab, schließe ein verspätet eintreffendes Handle, konsumiere den einzelnen Iterator, warte auf das Terminal-Promise:

<include cwd>examples/vue/realtime-scope.vue#example</include>

Fatale Stream-Errors und Queue-Overflow lehnen den Iterator ab, deshalb hat der Loop ein `catch`; sonst bliebe diese Ablehnung unbehandelt. Das Beispiel behält nur die letzten 100 Messages und keyt Zeilen über eine ID, weil identische Payloads doppelte Keys ergäben. Den Scope zu stoppen beendet die Iteration bei SSE normal; bei einer abgebrochenen WebSocket-Session lehnt dagegen `receive` mit `AbortError` ab, also schütze das `catch` genauso.

WebSocket: dieselbe Sequenz — Vorbereitung abbrechen, verspätete Session schließen, `session.receive` konsumieren, `onStateChange` / `onRuntimeError` abmelden, schließen, auf `session.closed` warten. Halte Cleanup idempotent; Disposal und Iterator-Completion können zusammentreffen.

## SSR-Scope

`createClientPlugin(client)` provides eine Instanz an eine Vue-App. Im Browser teile sie, wenn Endpoint, Interceptors und captured State safe zu teilen sind. Während SSR erzeuge und installiere einen separaten Client pro Request, wenn Headers, Cookies, User, Tenants oder Credentials differieren.

App-Unmount, Plugin-Removal und Component-Scope-Disposal brechen HTTP **nicht** ab, schließen SSE/WebSocket nicht, melden keine Listener ab und geben den Core-Client nicht frei. Der Owner, der die Arbeit startet, muss sie beenden.
