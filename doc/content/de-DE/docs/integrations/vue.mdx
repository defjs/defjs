# Vue

`@defjs/vue` bindet einen anwendungseigenen `@defjs/core`-Client über `createClientPlugin(client)`, `HTTP_CLIENT` und `injectClient()` in eine Vue 3.2+ Anwendung ein. Deine SDK-Definitionen bleiben dabei reine `@defjs/core`-Module ohne jegliche Vue-Abhängigkeiten.

```sh
bun add @defjs/core @defjs/vue vue
```

## Was `@defjs/vue` bereitstellt vs. was deine Anwendung verantwortet

- **Bereitgestellt von `@defjs/vue`**: `createClientPlugin(client)`, `HTTP_CLIENT` (`InjectionKey<DerivableClient>`) und `injectClient(key?)`.
- **Verantwortet von deiner Anwendung**: Erstellung des [`DerivableClient`](/de-DE/api/core/derivableclient-type), Abbruch laufender Vorgänge in Watchern (`onCleanup`) oder Composables (`onScopeDispose`), Schließen von SSE-/WebSocket-Handles und Integration von Query-Bibliotheken (wie Vue Query).
- **Wichtig**: `injectClient()` gibt das aufrufbare `DerivableClient`-Objekt zurück. Rufe `client({ signal })` dort auf, wo die Operation ausgeführt wird (`getOrder(client({ signal }), input)`). Übergib `client` niemals als erstes Argument an `watch(client, ...)` oder `computed(client)`, da Vue ein Funktionsargument als reaktiven Getter interpretiert.

## 2. Injizieren und in Teilbäumen überschreiben

`injectClient(key?)` sucht den nächstgelegenen Provider für `key` (standardmäßig `HTTP_CLIENT`) und wirft einen `Error`, wenn es außerhalb eines aktiven Vue-Injektionskontexts (`setup()` oder `app.runWithContext()`) aufgerufen wird oder kein Client für diesen Schlüssel bereitgestellt wurde.

Du kannst den Client für einen Teilbaum mit Vues nativem `provide(HTTP_CLIENT, childClient)` überschreiben:

- Kindkomponenten erhalten `childClient`, während Geschwister-Teilbäume den Root-Client behalten.
- Akzeptiert eine Hilfsfunktion einen optionalen expliziten Client (`explicitClient ?? injectClient()`), benötigt nur der Fallback-Zweig einen aktiven Vue-Injektionskontext. Sichere dir den Client synchron während `setup()` vor jedem `await`.

## 3. SSE- und WebSocket-Streams bei Scope-Disposal bereinigen

Für asynchrone Arbeiten innerhalb eines Composables oder einer Komponente außerhalb eines Watchers kombiniere `AbortController` mit `onScopeDispose`. Brich den Start ab, schließe Handles, die erst nach dem Disposal auflösen, konsumiere den einzelnen asynchronen Iterator und warte auf `.closed`:

<include cwd>examples/vue/realtime-scope.vue#example</include>

- Der Fehlerzweig des Tupels zeigt anfängliche Handshake-Fehler an (einschließlich HTTP 503). Das `catch` des Iterators zeigt Fehler nach dem Start an; der `finally`-Block schließt den Stream weiterhin und wartet auf seinen Abschluss.

- Das Stoppen des Scopes beendet eine SSE-`for await`-Schleife regulär.
- Das Abbrechen einer WebSocket-Sitzung beendet sie als `aborted` und lässt `session.receive` mit `AbortError` fehlschlagen; fange dies im `catch`-Block nach dem Disposal ab und melde `onStateChange`- / `onRuntimeError`-Listener im `finally`-Block ab.

---

## 4. SSR und Anwendungs-Scope

- **Browser**: Teile einen einzelnen Client pro Vue-App, wenn Endpunkt und Interceptors anfrageunabhängig sind.
- **SSR**: Erstelle und installiere einen frischen Client pro SSR-Request, sobald Header, Cookies, Mandanten oder Anmeldedaten variieren.
- Das Unmounten der Vue-App oder das Verwerfen eines Komponenten-Scopes bricht HTTP-Aufrufe **nicht** automatisch ab, schließt keine SSE-/WebSocket-Streams und entsorgt den Core-Client nicht.
