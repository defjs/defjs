# React

`@defjs/react` bindet einen anwendungseigenen `@defjs/core`-Client über React Context und `useClient()` in einen React 18+ Komponentenbaum ein. Deine SDK-Definitionen bleiben dabei reine `@defjs/core`-Module ohne jegliche React-Abhängigkeiten.

```sh
bun add @defjs/core @defjs/react react
```

## Was `@defjs/react` bereitstellt vs. was deine Anwendung verantwortet

- **Bereitgestellt von `@defjs/react`**: `ClientProvider` und `useClient(overrideClient?)`.
- **Verantwortet von deiner Anwendung**: Erstellung des [`DerivableClient`](/de-DE/api/core/derivableclient-type), Abbruch laufender Anfragen beim Unmounten oder bei Abhängigkeitswechseln (`AbortController`), Schließen von SSE-/WebSocket-Handles und Integration von Query-Caches wie TanStack Query.
- **Wichtig**: `useClient()` gibt das aufrufbare `DerivableClient`-Objekt zurück. Rufe `client({ signal })` dort auf, wo die Operation ausgeführt wird (`getOrder(client({ signal }), input)`). Übergib `client` niemals direkt an `setState(client)`, da React ein Funktionsargument im State-Setter als Updater-Funktion interpretiert.

- In der Entwicklung (`StrictMode`) mountet und bereinigt React Effects mehrfach. Die Prüfung auf `controller.signal.aborted` verhindert, dass eine veraltete Antwort den aktuellen Komponenten-State überschreibt.

## 2. Auslesen und Überschreiben mit `useClient`

`useClient(overrideClient)` liefert `overrideClient` zurück, sofern übergeben, oder liest den nächstgelegenen `ClientProvider` aus, wenn das Argument weggelassen wird oder `undefined` ist. Ein `Error` wird nur dann geworfen, wenn keine der beiden Quellen einen Client bereitstellt.

<include cwd>examples/react/read-with-use-client.tsx#example</include>

- Rufe `useClient(explicitClient)` immer bedingungslos auf oberster Ebene einer Komponente oder eines Custom-Hooks auf. Schreibe niemals `explicitClient ?? useClient()`, da dies die Rules of Hooks verletzt.

## 4. SSE- und WebSocket-Lebenszyklen in Effects verwalten

SSE- und WebSocket-Handles überdauern den ursprünglichen `openStream(...)`- oder `connectChat(...)`-Aufruf. Übergib der Operation das Signal eines `AbortController` und brich es im Cleanup ab: Das Signal deckt den Verbindungsaufbau und die offene Sitzung ab. Besitze die Sitzung mit `await using` und konsumiere ihren einzelnen asynchronen Iterator:

<include cwd>examples/react/own-realtime-work.tsx#example</include>

- Das Abbrechen des an eine WebSocket-Operation übergebenen `signal` beendet die Sitzung als `aborted` und lässt `session.receive` mit `AbortError` fehlschlagen. Schütze den `catch`-Block mit `controller.signal.aborted`, sodass nur echte Laufzeitfehler (wie ein Heartbeat-Timeout) sichtbar werden.
- Das Abbrechen eines SSE-Streams beendet `for await (const msg of stream)` sauber ohne Exception.

---

## 5. SSR und Provider-Scope

- **Browser**: Teile einen einzelnen modulweiten Client, wenn Endpunkt und Interceptors anfrageunabhängig sind.
- **SSR**: Erstelle innerhalb jeder Server-Request-Grenze einen neuen Client, wenn Header, Cookies, Mandanten oder Anmeldedaten pro Anfrage variieren.
- Das Unmounten von `<ClientProvider>` bricht aktive HTTP-Aufrufe **nicht** ab, schließt keine SSE-/WebSocket-Verbindungen und entsorgt den Client nicht.

## Öffentliche Exporte & verwandte Leitfäden

- `ClientProvider` — Stellt einen `DerivableClient` bereit (`ClientProviderProps: { client: DerivableClient; children?: ReactNode }`).
- `useClient(overrideClient?)` — Liest den expliziten Override oder den nächsten über Provider bereitgestellten Client aus.
