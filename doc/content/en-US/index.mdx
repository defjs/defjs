# Defjs

**TypeScript SDK & Resilient Client Kit — Define the API contract once. Configure execution per application.**

Defjs separates the two sides of a TypeScript SDK:

- **SDK Definition (`@defjs/core`, `@defjs/cli`)** — Declare typed HTTP, SSE, and WebSocket operations alongside their `struct` schemas (hand-written or generated as stateless ESM from OpenAPI 2.0/3.0/3.1/3.2 specs). A definition is pure data: importing it starts no network call and binds no global client.
- **Resilient Application Execution (`@defjs/core`)** — Applications create their own `Client` (`createClient(withEndpoint(...))`), attach credentials and interceptors (`basicAuth*`, `idempotencyKeyHttpInterceptor`, `concurrencyLimitHttpInterceptor`), configure P2C load balancing and `outlierDetection` (`halfOpen`, `maxEjectionPercent`), enable `429`/`Retry-After` retries, fan out via `@defjs/core/concurrent`, or bridge workers/extensions with `@defjs/core/port`.

## Why separate definitions from clients?

| Responsibility | SDK Author (Definition)                                                                                                 | Application (Execution)                                                                   |
| -------------- | ----------------------------------------------------------------------------------------------------------------------- | ----------------------------------------------------------------------------------------- |
| **Owns**       | Method, path template, `input` / `output` / `error` schemas, `builder` mapping, and optional application-defined `meta` | Base URLs, credentials, auth interceptors, load balancing, timeouts, and resource cleanup |
| **Ships**      | Reusable ESM modules and `.d.ts` declarations                                                                           | Browser, server, or test runtime configuration                                            |
| **Benefit**    | Zero environment coupling; works across browser, SSR, and tests                                                         | Full control over retries, failover, telemetry, and lifecycles                            |

## Supported transports and result tuples

Every operation returns a three-item error-first tuple tailored to its transport lifecycle:

| Transport                         | Entry point         | Tuple shape                  | Lifecycle ownership                                                      |
| --------------------------------- | ------------------- | ---------------------------- | ------------------------------------------------------------------------ |
| **[HTTP](/docs/http)**            | `defineRequest`     | `[err, data, response]`      | Cancel in-flight work via `client({ signal })`                           |
| **[SSE](/docs/sse)**              | `defineEventStream` | `[err, stream, open]`        | Release with `await using` or `stream.close()` + `await stream.closed`   |
| **[WebSocket](/docs/web-socket)** | `defineWebSocket`   | `[err, session, connection]` | Release with `await using` or `session.close()` + `await session.closed` |

On an HTTP failure, the tuple is `[err, undefined, undefined]` because `err` already carries any `HttpMeta` response metadata. For SSE and WebSocket, the third slot holds the startup snapshot whenever one was captured before failure.
