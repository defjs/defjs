# Defjs

**Define the API contract once. Configure execution per application.**

Defjs separates the two sides of a TypeScript SDK:

- **SDK Definition (`@defjs/core`)** — SDK authors declare typed HTTP, SSE, and WebSocket operations alongside their `struct` schemas. A definition is pure data: importing it starts no network call and binds no global client.
- **Application Execution** — Consuming applications create their own `Client` (`createClient(withEndpoint(...))`), attach credentials, interceptors, and load balancers, and pass that client when calling an operation.

## Why separate definitions from clients?

| Responsibility | SDK Author (Definition)                                                                                     | Application (Execution)                                                                   |
| -------------- | ----------------------------------------------------------------------------------------------------------- | ----------------------------------------------------------------------------------------- |
| **Owns**       | Method, path template, `input` / `output` / `error` schemas, `builder` mapping, and static `operation` name | Base URLs, credentials, auth interceptors, load balancing, timeouts, and resource cleanup |
| **Ships**      | Reusable ESM modules and `.d.ts` declarations                                                               | Browser, server, or test runtime configuration                                            |
| **Benefit**    | Zero environment coupling; works across browser, SSR, and tests                                             | Full control over retries, failover, telemetry, and lifecycles                            |

## Supported transports and result tuples

Every operation returns a three-item error-first tuple tailored to its transport lifecycle:

| Transport                         | Entry point         | Tuple shape                    | Lifecycle ownership                                                      |
| --------------------------------- | ------------------- | ------------------------------ | ------------------------------------------------------------------------ |
| **[HTTP](/docs/http)**            | `defineRequest`     | `[error, data, response]`      | Cancel in-flight work via `client({ signal })`                           |
| **[SSE](/docs/sse)**              | `defineEventStream` | `[error, stream, open]`        | Release with `await using` or `stream.close()` + `await stream.closed`   |
| **[WebSocket](/docs/web-socket)** | `defineWebSocket`   | `[error, session, connection]` | Release with `await using` or `session.close()` + `await session.closed` |

On an HTTP failure, the tuple is `[error, undefined, undefined]` because `error` already carries any `HttpMeta` response metadata. For SSE and WebSocket, the third slot holds the startup snapshot whenever one was captured before failure.
