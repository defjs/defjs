# SSE

Declare an event stream, call the operation with a client, iterate events, then close.

## defineEventStream()

<ApiSignature name="defineEventStream" />

- **definition** — `path` and `events` map; optional `method` (default `'GET'`), `operation`, `input`, `error`, and `maxBufferSize` (default `64 * 1024`). A declared `input` always requires an explicit `builder`. `input` only defines the parameters; the builder alone decides where each value goes. Only definitions without `input` may omit `builder`. These `definition` members are documented under [`EventStreamDefinition`](/api/core/eventstreamdefinition-type). `error` is required only when an error struct type is given, and `builder` is required exactly when `input` is declared.
- **Returns** an operation. The first argument is a [`Client`](/api/core/client-type). Further arguments are the input only. Calling it starts the stream.

<include cwd>examples/api/define-event-stream.ts#example</include>

The call returns `[null, stream, open]` or `[error, undefined, open?]`. When `error` is declared, the fault is `Fault` of that struct; otherwise it is `Fault<undefined>`. Pass `signal` by deriving a client from [`RequestOptions`](/api/core/requestoptions-type). SSE reads only `signal` and ignores progress and WebSocket fields.

## EventStreamExecuteOptions

<ApiSignature name="EventStreamExecuteOptions" />

`EventStreamExecuteOptions` is `{ signal? }`. There is no `timeout` or `abort` field and no progress callback. `signal` covers the whole stream, including after it opens. A deadline is `AbortSignal.timeout(ms)` and classifies as `NET_TIMEOUT`. A manual abort is `NET_ABORTED`. There is no startup-only deadline and no client-level default deadline. An application that wants a startup-only deadline creates its own `AbortController`, aborts it with `new DOMException("...", "TimeoutError")` from a timer, and clears the timer after the await returns.

## EventStreamHandle

<ApiSignature name="EventStreamHandle" />

The tuple's third slot is the startup snapshot of `open`; `stream.open` follows the latest connection after a reconnect. That third slot is the returned connection's first successful handshake snapshot only for a native Defjs handle or a wrapper forwarding the same live `open` object; custom handles and wrappers overriding `open` retain their current public `open` even after reconnect, so shared `closed` cannot bypass URL sanitization or header filtering, and Defjs does not reconstruct first-handshake metadata from arbitrary transformations. Prefer `await using stream = handle` for owned scope cleanup. The disposer stops Defjs reading and reconnect work and waits for its reader lock to be released; it does not promise that a provider-controlled, stuck `ReadableStream.cancel()` promise will finish. Manual `close()` / `closed` remains available.

### EventStreamCloseInfo

<ApiSignature name="EventStreamCloseInfo" />

`kind` is `eof`, `aborted`, or `error`. Every variant may carry `reason` and `cause`. Only `error` has `code`, one of [`EventStreamFaultCode`](/api/core/eventstreamfaultcode-type): `'CAP_BUFFER_EXCEEDED' | 'EXT_HOOK_FAILED' | 'EXT_OBSERVER_FAILED' | 'HTTP_STATUS' | 'NET_TIMEOUT' | 'NET_UNREACHABLE' | 'REQ_BUILD_FAILED' | 'REQ_OPTIONS_INVALID' | 'RES_DECODE_FAILED' | 'RES_MEDIA_TYPE_INVALID'`. `REQ_BUILD_FAILED` and `REQ_OPTIONS_INVALID` mean a reconnect pick failed after the stream opened. `HTTP_STATUS` means a reconnect handshake ended with a non-2xx status. A full queue is not an error: the library holds at most 1024 unread events and reading the response pauses until the consumer takes one. `close()`, disposal, and a caller `signal` abort discard the events nobody has read yet and end the iterator at once. After an `error` end, the events already queued are still delivered before the iterator rejects.

## EventStructs

<ApiSignature name="EventStructs" />

The key is the SSE event name; a message without an `event:` field is named `message`. When no key matches, the `default` struct is used. A `string` event struct keeps the raw `data` text. Every other kind is JSON text: `JSON.parse`, then the struct. A bare `struct.literal` therefore needs JSON text, not an unquoted token. Handshake `error` bodies use the same kind rule as HTTP: `string` is text, `blob` / `file` are blobs, `arrayBuffer` is bytes, and everything else is JSON.

Reconnect lives on the client (`withSSEReconnect`). SSE `jitter` is a **0–1 multiplicative factor**, same as WebSocket.

The retry budget and backoff exponent reset after every successful handshake; they apply per outage, so `attempts: 1` can still create many connections across a long session. Clean server EOF does not reconnect, and an incomplete event at EOF does not commit its id. A handshake answered with 502, 503, or 504 is retried like a refused connection under the same reconnect rules (method, `shouldReconnect`, `attempts`, `ReadableStream` body); other non-2xx handshakes are fatal. Exhausted retries and fatal reconnect handshakes end with `HTTP_STATUS`; inspect live `stream.open.response.status` for the status. Invalid numeric options return `REQ_OPTIONS_INVALID` before opening a stream, and `maxDelayMs` caps the final delay after jitter. See [`withSSEReconnect`](/api/core/withssereconnect) for validation rules, defaults, and UTF-8 `Last-Event-ID` handling.

The parser follows WHATWG SSE line and field rules and removes only one leading UTF-8 BOM at the start of each physical stream. U+FEFF in data or ID values is preserved; a later BOM-prefixed field name is ignored as unknown. Multi-line data joins with `\n`, a blank line dispatches a data-bearing event, and an unfinished event at EOF is discarded.

See [SSE guide](/docs/sse) and [Consume an SSE stream](/recipes/consume-sse).

## EventStreamDefinition

`path`, `events`, optional `method` / `operation` / `input` / `error` / `maxBufferSize`. The request shape matches HTTP, including `body`. `GET` and `HEAD` cannot carry a body. A declared `input` always requires an explicit `builder`. `input` only defines the parameters; the builder alone decides where each value goes. Only definitions without `input` may omit `builder`.

## EventStreamEndpoint

Returned by `defineEventStream`. The first argument is a client. Further arguments are the input only.

## EventStreamRequestShape

Same fields as `HttpRequestShape` for the stream's method and path.

## StreamAwaitResult

`[null, stream, open]` or `[error, undefined, open?]`.

## EventStreamData

Parsed event payload inferred from an `EventStructs` map.
