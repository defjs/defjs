# SSE

Declare an event stream, execute it, iterate events, then close.

## defineEventStream()

```ts
function defineEventStream(definition: EventStreamDefinition): EventStreamEndpoint
```

- **definition** — `path`, `events` map, and the required positive-integer limits `maxBufferSize` and `maxQueueSize`; optional `method` (default `'GET'`), `operation`, `input` and `error`. A declared `input` always requires an explicit `builder`, even when it already matches the request shape. Only definitions without `input` may omit `builder`.
- **Returns** an endpoint. Call with input to get an `EventStreamCommand`.

## executeEventStreamCommand()

```ts
function executeEventStreamCommand(
  clientConfig: ClientConfig,
  command: EventStreamCommand,
  options?: EventStreamExecuteOptions,
): Promise<StreamAwaitResult>
```

Low-level entry for `client.execute`. Prefer the client in application code.

- **Returns** `[null, stream, open]` or `[error, undefined, open?]`. When `error` is declared, the fault is `Fault` of that struct; otherwise it is `Fault<undefined>`.

## Execute options

## EventStreamExecuteOptions

```ts
type EventStreamExecuteOptions = ({ abort?: AbortSignal; timeout?: never } | { abort?: never; timeout?: number }) & {
  signal?: AbortSignal
}
```

Same cancellation rules as HTTP: `abort` or `timeout`, not both (the type rejects both, and passing both at runtime fails with `REQ_OPTIONS_INVALID`); `signal` combines with either. `timeout` is a startup deadline: it covers input parsing, the builder, interceptors and the handshake, and does not abort an open stream. `withTimeout` does not apply to SSE.

## EventStreamHandle

```ts
interface EventStreamHandle<TEvent> extends AsyncIterable<TEvent>, AsyncDisposable {
  readonly open: EventStreamOpenInfo
  readonly closed: Promise<EventStreamCloseInfo>
  close(reason?: unknown): void
  [Symbol.asyncDispose](): PromiseLike<void>
}
```

The tuple's third slot is the startup snapshot of `open`; `stream.open` follows the latest connection after a reconnect. Prefer `await using stream = handle` for owned scope cleanup. The disposer stops Defjs reading and reconnect work and waits for its reader lock to be released; it does not promise that a provider-controlled, stuck `ReadableStream.cancel()` promise will finish. Manual `close()` / `closed` remains available.

```ts
async function consume(handle: EventStreamHandle<unknown>): Promise<void> {
  await using stream = handle
  for await (const event of stream) console.log(event)
}
```

Structural implementations of `EventStreamHandle` must now implement `[Symbol.asyncDispose]()` and return the same owned teardown path. This is a compile-time breaking change for custom handles; code that only receives handles returned by Defjs has no new runtime call requirement.

### EventStreamOpenInfo

```ts
interface EventStreamOpenInfo {
  response: HttpResponse<unknown>
  url: string
}
```

### EventStreamCloseInfo

```ts
type EventStreamCloseInfo =
  | { kind: 'eof'; reason?: string; cause?: unknown }
  | { kind: 'aborted'; reason?: string; cause?: unknown }
  | { kind: 'error'; code: EventStreamFaultCode; reason?: string; cause?: unknown }
```

`EventStreamFaultCode`: `'CAP_BUFFER_EXCEEDED' | 'CAP_QUEUE_OVERFLOW' | 'EXT_HOOK_FAILED' | 'EXT_OBSERVER_FAILED' | 'NET_TIMEOUT' | 'NET_UNREACHABLE' | 'RES_DECODE_FAILED' | 'RES_MEDIA_TYPE_INVALID'`.

## Event map

## EventStructs

```ts
type EventStructs = { [eventName: string]: AnyStruct }
```

The key is the SSE event name; a message without an `event:` field is named `message`. When no key matches, the `default` struct is used. A `string` event struct keeps the raw `data` text. Every other kind is JSON text: `JSON.parse`, then the struct. A bare `struct.literal` therefore needs JSON text, not an unquoted token. Handshake `error` bodies use the same kind rule as HTTP: `string` is text, `blob` / `file` are blobs, `arrayBuffer` is bytes, and everything else is JSON.

Reconnect lives on the client (`withSSEReconnect`). SSE `jitter` is a **0–1 multiplicative factor**, same as WebSocket.

The retry budget and backoff exponent reset after a successful handshake; they apply per outage. Invalid numeric options return `REQ_OPTIONS_INVALID` before opening a stream, and `maxDelayMs` caps the final delay after jitter. See [`withSSEReconnect`](/api/core/withssereconnect) for validation rules, defaults, and UTF-8 `Last-Event-ID` handling.

The parser follows WHATWG SSE line and field rules and removes only one leading UTF-8 BOM at the start of each physical stream. U+FEFF in data or ID values is preserved; a later BOM-prefixed field name is ignored as unknown. Multi-line data joins with `\n`, a blank line dispatches a data-bearing event, and an unfinished event at EOF is discarded.

See [SSE guide](/docs/sse) and [Consume an SSE stream](/recipes/consume-sse).

## EventStreamDefinition

`path`, `events`, required `maxBufferSize` and `maxQueueSize`, optional `method` / `operation` / `input` / `error`. The request shape matches HTTP, including `body`. `GET` and `HEAD` cannot return a body. A declared `input` always requires an explicit `builder`, even when it already matches the request shape. Only definitions without `input` may omit `builder`.

## EventStreamEndpoint

Returned by `defineEventStream`. Call with input to get an `EventStreamCommand`.

## EventStreamRequestShape

Same fields as `HttpRequestShape` for the stream's method and path.

## EventStreamCommand

Opaque SSE command. Pass to `client.execute`.

## StreamAwaitResult

`[null, stream, open]` or `[error, undefined, open?]`.

## EventStreamData

Parsed event payload inferred from an `EventStructs` map.
