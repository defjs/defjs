# Client

`createClient(...)` returns a [`DerivableClient`](/api/core/derivableclient-type). Compose client options left to right, then call `client(options?)` to get a [`Client`](/api/core/client-type) value and pass it to an operation: `getOrder(client(options), input)`.

## createClient()

<ApiSignature name="createClient" />

Options apply in order. Prefer creating the client inside the request boundary when interceptors close over auth or tenants. The returned factory is a function. Calling it returns a `Client` value and performs no I/O. The factory itself is also a `Client` and carries no request options.

- **options** — Option helpers such as `withEndpoint`.
- **Returns** a callable factory. The base configuration is shared by every client value and is not frozen at runtime. It is fixed by convention: nothing in the library changes it, and applications should not either.

## Option helpers

All helpers return `ClientOption`. A later call replaces an earlier one for the same setting, except `withInterceptors`, which appends.

### withEndpoint()

<ApiSignature name="withEndpoint" />

Copies candidate base URLs in first-seen order and drops a later copy of the same string. A later `withEndpoint` replaces the list. It does not check URLs and does not replace the balancer. An empty list is legal and fails the call with `REQ_BUILD_FAILED`.

### withBalancer()

<ApiSignature name="withBalancer" />

Replaces the balancer used for later calls. The object is stored by reference. Without this option, each client gets its own `pickFirstBalancer()`.

### withInterceptors()

<ApiSignature name="withInterceptors" />

Appends interceptors in registration order. Mixed kinds are filtered per transport when the operation runs.

### withQuerySerializer()

<ApiSignature name="withQuerySerializer" />

Replaces query encoding for HTTP, SSE, and WebSocket. `serializer(query)` receives the **encoded wire object** (aliases applied, `Date` as ISO, `bigint` as string) and must return the query string without a leading `?`. It is not called when the request has no query. A builder that returns `URLSearchParams` skips it.

### withHeaders()

<ApiSignature name="withHeaders" />

Sets static default headers for HTTP and SSE requests. WebSocket requests do not use them. `headers` is copied when the option applies, so later changes to the object do not reach the client. A second `withHeaders` replaces the first; it does not merge.

Precedence for one request:

1. The defaults are the starting header set.
2. `headers` returned by the request builder replace a default of the same name. The first value for that name replaces the default; later values in the same array append only to that replacement. A scalar or a `Headers` instance also replaces. Other default names stay.
3. Interceptors receive the merged headers and may change them.
4. With `@defjs/core/xsrf`, the XSRF header is added last, only when still absent (see `withXSRF`).

Use an interceptor for values that change per request: a refreshed Bearer token, or an HMAC over the serialized body.

There is no client-level default deadline. Pass `signal: AbortSignal.timeout(ms)` on a derived client when one call needs one. A manual abort is `NET_ABORTED`. `AbortSignal.timeout` classifies as `NET_TIMEOUT`.

### withCredentials()

### withXSRF()

<ApiSignature name="withXSRF" />

Adds an XSRF token header to browser HTTP requests. Import it from `@defjs/core/xsrf`. `options` is an `XSRFOptions` value: `cookieName` (default `XSRF-TOKEN`) and `headerName` (default `X-XSRF-TOKEN`). Calling `withXSRF()` with no argument enables those defaults, and throws when `location` or `document` is missing, including in a Worker. Isomorphic code adds this option only in the browser. A token from another source is set with an interceptor. SSE and WebSocket requests are not affected.

The header is set only when all of these hold: the method is not `GET`, `HEAD`, `OPTIONS` or `TRACE`; the request does not already have that header; the resolved request origin equals the page origin; and `document.cookie` holds a non-empty token. A cross-origin request does not read the cookie. A throw while reading the cookie counts as no token. An empty token does not set the header.

The origin check covers the URL the library builds. Fetch follows redirects itself, and after a redirect to another origin it removes only `Authorization`, so the XSRF header goes along. The target receives the token when it allows the header in its CORS preflight. To refuse that, pass `withHTTPHandle` a function that calls `fetch(new Request(request, { mode: "same-origin" }))` for requests to the page origin that carry the header. Do not apply that mode to a cross-origin API whose header comes from an interceptor: Fetch rejects any request to another origin in that mode. Such a request fails with `NET_UNREACHABLE` when a redirect leaves the origin and still follows a same-origin redirect. With `Referrer-Policy: no-referrer`, Fetch sends `Origin: null` for a same-origin POST in that mode, where the default mode sends the serialized origin, so a server that checks `Origin` can reject it. Some engines implement this differently.

## Types

### DerivableClient

<ApiSignature name="DerivableClient" />

The root client returned by `createClient`, in two shapes. The factory is a function and is also a `Client` with no request options, so `getOrder(client, input)` works directly. Calling it with [`RequestOptions`](/api/core/requestoptions-type) returns a plain `Client` value for one call. That value is not callable, so `client()()` fails to compile and throws a `TypeError` at runtime. Derivation happens once, from the factory; there is no chain. Write the type as `DerivableClient` rather than `ReturnType<typeof createClient>`.

### Client

<ApiSignature name="Client" />

A `Client` is a value, not a function. Calling the [`DerivableClient`](/api/core/derivableclient-type) with [`RequestOptions`](/api/core/requestoptions-type) returns one. `client()` and `client(undefined)` store no request options. `client({})` keeps an empty snapshot. The call reads each top-level field once. A `protocols` array is copied. `heartbeat` and `reconnect` copy their known fields. Missing nested blocks stay missing. `signal`, `beforeConnect`, and callbacks keep their identity. A getter on a captured field runs during that call and, if it throws, escapes the call. Invalid numbers still fail later with `REQ_OPTIONS_INVALID`. Deriving performs no I/O. A client value is not callable, and calling one fails to compile and throws a `TypeError` at runtime. Create a client value per call. The same value can be passed to many operations, but reusing a value that carries `signal` shares that signal. `signal` is not combined; combine signals with `AbortSignal.any` in application code. The factory's base configuration stays shared and is not frozen. Standard `with*` helpers copy the fixed records they own when they are applied.

Do not pass the factory to a React state setter (`setState(factory)` would call it as an updater) or use it as a Vue `watch` or `computed` source (those call a function).

### RequestOptions

<ApiSignature name="RequestOptions" />

Seven flat fields. Each protocol reads the fields it understands and ignores the rest. Passing `heartbeat` to HTTP is ignored, not a fault. `client(options)` copies a `protocols` array and the known `heartbeat` and `reconnect` fields at that call. Missing nested blocks stay missing. `signal`, `beforeConnect`, and callbacks keep their identity. SSE reads only `signal` from request options. SSE reconnect comes from client configuration (`withSSEReconnect`), so `client({ reconnect })` affects WebSocket only. There is no compile-time protocol filter and no `timeout` or `abort` field.

| Field                | Protocol                 | Replacement                                                                                  |
| -------------------- | ------------------------ | -------------------------------------------------------------------------------------------- |
| `signal`             | HTTP, SSE, and WebSocket | Aborts the call. For SSE and WebSocket it covers the whole connection, including after open. |
| `onUploadProgress`   | HTTP                     | Ignored by other protocols.                                                                  |
| `onDownloadProgress` | HTTP                     | Ignored by other protocols.                                                                  |
| `beforeConnect`      | WebSocket                | Replaces the client setting for that call.                                                   |
| `protocols`          | WebSocket                | Replaces the client list.                                                                    |
| `heartbeat`          | WebSocket                | Replaced whole. `timeoutMs` is the acknowledgement wait, not a request deadline.             |
| `reconnect`          | WebSocket                | Replaced whole.                                                                              |

[`HttpExecuteOptions`](/api/core/httpexecuteoptions-type) is the HTTP slice (`signal` plus progress). [`EventStreamExecuteOptions`](/api/core/eventstreamexecuteoptions-type) is `{ signal? }`. [`WebSocketExecuteOptions`](/api/core/websocketexecuteoptions-type) is the WebSocket slice plus `signal`.

### FetchHandle

<ApiSignature name="FetchHandle" />

The call signature Defjs needs from a Fetch implementation. It is not `typeof fetch`, so a mock does not need host extras such as `preconnect`. The default HTTP/SSE handles resolve `globalThis.fetch` on each call. HTTP uses `(url, init)` only for untouched platform Fetch; replaced globals and custom handles receive a `Request`. SSE always passes a `Request`. Importing Core without Fetch is valid; a default execution reports `ENV_UNSUPPORTED` if Fetch is still missing, while custom handles remain usable.

### ClientSSEOptions

### ClientWebSocketOptions

<ApiSignature name="ClientSSEOptions, ClientWebSocketOptions" />

Reconnect is opt-in for both transports: without `withSSEReconnect` / `withWebSocketReconnect` there is no retry. Once `reconnect` is set, these defaults apply:

| Field        | SSE            | WebSocket      |
| ------------ | -------------- | -------------- |
| `attempts`   | `3` per outage | `3` per outage |
| `delayMs`    | `1000`         | `1000`         |
| `factor`     | `1`            | `2`            |
| `jitter`     | `0`            | `0`            |
| `maxDelayMs` | no cap         | `30000`        |

`connectTimeoutMs` is optional and must be finite, positive, and no greater than 2147483647 (the timer limit); otherwise the operation returns `REQ_OPTIONS_INVALID`. It bounds Fetch to response headers for SSE, and construction to `open` for WebSocket; it is cleared after the handshake. Expiry reports `NET_UNREACHABLE` to the balancer so a reconnect can pick the next endpoint. Exhausting retries ends with `NET_TIMEOUT`. It exists only inside the reconnect options, and `attempts` defaults to `3` whenever that object is present, so setting `connectTimeoutMs` alone also enables reconnect. For a handshake-only deadline, set `attempts: 0` as well.

For both transports, a successful handshake resets the per-outage retry budget, callback attempt, and backoff exponent. `attempts: 0` disables retry; omitting `attempts` does not give unlimited retries within one outage. `maxDelayMs` caps the final delay after jitter and rounding; the platform timer limit of `2_147_483_647` ms also applies, including when SSE has no configured cap. A zero base stays zero; valid-number overflow saturates at the caps.

Reconnect options are validated before transport: `attempts` must be a non-negative safe integer; `delayMs` must be finite and non-negative; `maxDelayMs` must be a non-negative finite number or positive `Infinity`, which removes the configured cap but not the platform limit of `2_147_483_647` ms; `factor` must be finite and positive; `jitter` must be finite and within 0–1. Invalid values return `REQ_OPTIONS_INVALID`. WebSocket `attempts: 0` disables subsequent retries, but all explicitly supplied reconnect fields are still validated before the initial connection, just as in SSE. Jitter scales the capped base in either direction before the final cap is applied.

For SSE, `delayMs` is only the starting base delay: a digits-only server `retry:` field replaces it for later attempts, including after recovery. `shouldReconnect` returning `false` stops retrying. The SSE callback also receives `lastEventId`, the request `method`, and the latest `open` info, and may be async. Without it, SSE reconnects only `GET`, `HEAD`, `OPTIONS`, `PUT`, and `DELETE` requests; with it, its result decides for every method. The latest event ID is sent as UTF-8 bytes in `Last-Event-ID`; an empty ID clears it and an ID containing NUL is ignored. The WebSocket callback receives the close `code`, `reason` and `wasClean` instead.

SSE `onInvalidEvent` handles an event with no matching struct, including no `default` (`missing-struct`), or whose data fails its struct (`validation-failed`). The event is always dropped; the handler's return value is ignored, and an error it throws does not close the stream.

For WebSocket, `beforeConnect`, `heartbeat`, `protocols` and `reconnect` can also be passed on a derived client; each replaces the corresponding client setting for that call as a whole. `heartbeat.message` builds each ping; nothing is sent when it is omitted or returns `undefined`. `heartbeat.timeoutMs` waits for an acknowledgement. It is not a request deadline.

### ClientOptions

<ApiSignature name="ClientOptions" />

The shown fields are `sse` and `webSocket`. The other six — `endpoints`, `headers`, `http`, `interceptors`, `querySerializer`, and `withCredentials` — are inherited from the non-exported HTTP base. `endpoints` is `readonly string[]`. The resolved default is `[]`. An empty array is a legal value and fails the call with `REQ_BUILD_FAILED`. There is no client-level `timeout`. `createClient` does not take this object; it takes option helpers.

### ClientConfig

The resolved snapshot that option helpers mutate and an operation reads: `ClientOptions` after defaults, with `http.handle`, `interceptors`, `sse` (a `ClientSSEConfig`), `webSocket`, and `balancer` always present. `http.retry` is optional and defaults to `undefined` (one attempt, no budget); `withRetry(options?)` configures it. `balancer` defaults to a new `pickFirstBalancer()` for that client. It is not a [`RequestOptions`](/api/core/requestoptions-type) field.

### ClientSSEConfig

<ApiSignature name="ClientSSEConfig" />

The resolved SSE config on `ClientConfig.sse`: `ClientSSEOptions` with a required `handle`.

### WebSocketHandle

The WebSocket instance surface the transport uses: `WebSocket` without `binaryType`, the ready-state constants, `dispatchEvent` and the `on*` handler properties, plus a read-only `readyState: number`.

### WebSocketHandleConstructor

<ApiSignature name="WebSocketHandleConstructor" />

The constructor passed to `withWebSocketHandle`. It must expose the `OPEN` ready-state constant.

## Balancers

### pickFirstBalancer()

### roundRobinBalancer()

<ApiSignature name="pickFirstBalancer, roundRobinBalancer" />

`pickFirstBalancer` advances on `NET_UNREACHABLE` or `NET_UNAVAILABLE` (HTTP 502, 503, or 504); an HTTP retry never moves its sticky endpoint, and order follows `members`, the client's whole endpoint list. Its optional positive finite `failbackMs` enables a single concurrent probe of the first endpoint after the interval; the probe is decided when the peer response begins (`end`), `done` decides one that never reached `end`. HTTP retries are a separate client policy configured with `withRetry`. `roundRobinBalancer` walks the list. `weights` is optional. See [Multiple endpoints](/docs/client#multiple-endpoints).

### p2cBalancer()

<ApiSignature name="p2cBalancer" />

Samples distinct candidates without replacement (unlike Envoy/gRPC A48), choosing tower PeakEwma or pending load. Linkerd defaults are RTT 30ms and decay 10s. Pending is reserved when `pick` selects the endpoint, and `end` releases it at headers or socket open and records the real RTT for every transport, including failures. A `done` without `end` releases pending without an RTT sample. There is no p2c failure classifier or penalty. `choiceCount` defaults to 2 and is capped at 10.

### outlierDetection()

<ApiSignature name="outlierDetection, OutlierDetectionOptions" />

Wraps a child with Linkerd-style consecutive-failure circuit breaking. Round robin and p2c enable it by default (as in Finagle); `false` disables it. Pick-first enables it with an object. The default classifier counts every coded outcome as a failure, including `NET_TIMEOUT` and `NET_BODY_INCOMPLETE`. After five failures, penalties start at 1000ms, double after failed probes, add positive jitter up to 0.5 times the base, and cap at 60000ms. Expiry admits a single probe decided at `end`, or at `done` if no `end` arrived. Success resets backoff; cancellation only releases the slot. There is no assumed-success timeout, quota, last-host protection, settlement grid, percentage criterion, or slow start. `isHealthy` reads application-owned cached state and never cancels a penalty. All hosts may break; Finagle-style list-local fail-open still sends requests. Unlike Envoy/gRPC A50 there is no ejection quota. See [Health filtering and p2c](/docs/client#health-filtering-and-p2c).

### withRetry()

<ApiSignature name="withRetry, RetryCondition, RetryOptions" />

Enables same-call HTTP retry independently of endpoint selection. Omitting `withRetry` means one attempt and no budget. `withRetry()` is equivalent to `withRetry({})` and defaults to `maxAttempts: 2` (including the original), `on: ["connect-failure"]`, and safe methods `GET`, `HEAD`, `OPTIONS`, `TRACE`. Methods are case-insensitive; `[]` disables retries. `maxAttempts` is a safe integer at least 1, and each endpoint is tried at most once. `"gateway-error"` includes `NET_UNAVAILABLE` (HTTP 502/503/504) and gateway bodies rejected by `RES_*` decoding; `"attempt-timeout"` uses `attemptTimeoutMs`. Streaming request bodies never retry.

Backoff defaults to `delayMs: 25`, `factor: 2`, `jitter: 0.2`, `maxDelayMs: 250`, with the same field semantics as SSE/WebSocket reconnect. `delayMs: 0` skips waiting. `attemptTimeoutMs` must be finite, positive, and no greater than 2147483647 (the timer limit); otherwise the operation returns `REQ_OPTIONS_INVALID`. It times each Fetch sent to the selected endpoint, from invocation until its response body has been read; interceptor work around the send and struct decoding are not timed and never count against the endpoint. The caller signal covers the whole call, including backoff waits. When a retry round cannot use any endpoint (the balancer's pick fails, or the next endpoint's URL does not resolve), the call returns the previous attempt's fault instead of `REQ_BUILD_FAILED`.

The client-owned Finagle budget defaults to 20% plus 10 retries/second of reserve over a 10s TTL. Credits and debits expire lazily in ten TTL/10 slices. `budget: false` removes the limit. Derived clients sharing a configuration share its budget; separate clients do not, even with one shared balancer. Invalid options return `REQ_OPTIONS_INVALID` with `Invalid retry options` when HTTP runs. The option captures owned fields, arrays, and the nested budget at application time. `withRetry()` and `withRetry(undefined)` behave like `withRetry({})`. A later `withRetry` replaces the policy; `withRetry({ maxAttempts: 1 })` turns retries off after they were enabled. Balancers and health wrappers have no retry settings. See [Load balancing & failover](/docs/load-balancing).

### Balancer

<ApiSignature name="Balancer, PickOutcome, PickInfo, PickResult, PickFaultCode, DoneInfo, ERR_NO_CANDIDATE, isNoCandidateCause" />

`pick` returns an error-first tuple. Optional `start` runs synchronously at most once immediately before the selected transport starts; optional `end` runs once after `start` when the peer response begins (or a pre-response failure occurs), and optional `done` runs once at completion. Fetch cannot expose Linkerd first-body-frame or Envoy stream boundaries. Throws from all hooks are contained and reported with `reportError` where the runtime defines it (an unhandled report can end a Bun or Deno process that has no error handler); thenable rejections are ignored. A selection outside the candidates fails with `REQ_BUILD_FAILED`, and its `done` is called with `{ attempted: false }`. `ERR_NO_CANDIDATE` is only a `cause` of `REQ_BUILD_FAILED`. It is not a `FaultCode`. [`isNoCandidateCause`](/api/core/isnocandidatecause) recognizes it across Core copies.

The balancer sees only neutral outcomes; each transport translates its own facts into `DoneInfo.code`. Default outlier detection counts every coded outcome as a failure, including `NET_TIMEOUT` and `NET_BODY_INCOMPLETE`. The raw `DoneInfo.status` is retained for custom balancers only and is never read by built-in strategies. `PickInfo` contains the candidate `endpoints` for one pick, `members` (the client's whole endpoint list, the same for every attempt), and optional `operation`, with no transport discriminator.

See [Client guide](/docs/client).
