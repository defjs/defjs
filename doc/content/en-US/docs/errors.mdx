# Error handling

In Defjs, request, transport, and decoding failures do not throw exceptions at the call site. Every operation returns an error-first tuple (`[error, ...]`) where `error` is either `null` or a typed `Fault` (a native `Error` instance discriminated by `error.code`).

Programming misuse is the exception. It typically rejects with `TypeError` instead of returning a `Fault`: a `signal` option that is not an `AbortSignal`, an HTTP operation whose `output` or `error` is not a `struct`, and calling an operation without a client.

### Why `error` carries the response metadata on HTTP failure

On an HTTP failure, the tuple is `[error, undefined, undefined]`. Whatever response metadata arrived (`status`, `statusText`, `headers`, `url`) is attached directly to `error.response` so you can pass `error` alone to a logger or error handler without losing context.

## 2. Fault classes and closed code set

The prefix before the first `_` names the fault class (`HTTP`, `REQ`, `NET`, `RES`, `EXT`, `CAP`, `ENV`), while the full `code` forms a closed union for exhaustive `switch` statements:

| Class  | Fault codes                                                            | Meaning & remediation                                                                                                                                                                                                                                                                                                                            |
| ------ | ---------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| `HTTP` | `HTTP_STATUS`                                                          | Server answered with a non-`2xx` status (`3xx`, `4xx`, `5xx`); any declared `error` struct decoded.                                                                                                                                                                                                                                              |
| `REQ`  | `REQ_INPUT_INVALID`, `REQ_OPTIONS_INVALID`, `REQ_BUILD_FAILED`         | Caller input failed validation, client options were out of range, the URL/path was invalid, `builder` threw, or the request could not be constructed (HTTP: body stream already used, invalid or forbidden method, GET/HEAD body, URL with credentials, invalid `Content-Type`; HTTP and SSE: a header value the platform rejects). Never retry. |
| `RES`  | `RES_MEDIA_TYPE_INVALID`, `RES_DECODE_FAILED`, `RES_STRUCT_MISMATCH`   | Server response broke the declared media type, representation, or `struct` contract.                                                                                                                                                                                                                                                             |
| `NET`  | `NET_ABORTED`, `NET_TIMEOUT`, `NET_UNREACHABLE`, `NET_BODY_INCOMPLETE` | Caller canceled (`NET_ABORTED`), deadline expired (`NET_TIMEOUT`), connection failed, or stream truncated.                                                                                                                                                                                                                                       |
| `EXT`  | `EXT_INTERCEPTOR_FAILED`, `EXT_HOOK_FAILED`, `EXT_OBSERVER_FAILED`     | An application interceptor, hook, or progress/state observer threw its own error or returned an invalid value, or an interceptor passed `next()` a `signal` that is not an `AbortSignal`.                                                                                                                                                        |
| `CAP`  | `CAP_BUFFER_EXCEEDED`, `CAP_QUEUE_OVERFLOW`                            | SSE frame buffer or WebSocket consumer queue exceeded its configured bound.                                                                                                                                                                                                                                                                      |
| `ENV`  | `ENV_UNSUPPORTED`                                                      | Host runtime lacks required Web APIs (e.g., streaming request body in Firefox).                                                                                                                                                                                                                                                                  |

The code names what failed, not who supplied the value. For HTTP, a request the platform cannot build is `REQ_BUILD_FAILED` whether the bad value came from the `builder`, the client configuration, or an interceptor. SSE applies the same rule to header values and to an invalid URL only. Other values the platform may refuse are not checked by the library on SSE and WebSocket (an invalid method or a URL with credentials on SSE; an invalid subprotocol or an unsupported scheme on WebSocket), so a refusal there is reported as `NET_UNREACHABLE` with the platform's error as `cause`, and a runtime that accepts the value (Bun, for the SSE cases) sends the request. `EXT_INTERCEPTOR_FAILED` covers the interceptor's own behavior: an error it throws, a result that is not a response or handle, or a `signal` that is not an `AbortSignal` (the cancellation channel, not request content).

### Fault properties by code

| Fault code    | `status` | `response`                                      | `data`                                 | `cause`                           |
| ------------- | -------- | ----------------------------------------------- | -------------------------------------- | --------------------------------- |
| `HTTP_STATUS` | `number` | `DecodedResponse<TErr>` or `HttpMeta`           | Decoded `error` struct, or `undefined` | Underlying cause if any           |
| `RES_*`       | `number` | `HttpMeta` (**no `body` field**)                | Absent                                 | `StructError` or parser error     |
| Other codes   | Absent   | `HttpMeta` if headers arrived, else `undefined` | Absent                                 | Underlying `Error` / abort reason |

## 4. Startup vs. post-open errors for SSE and WebSocket

For long-lived connections, the operation tuple reports **startup** failures (before the stream or socket opens). Once opened, runtime failures are delivered through the handle or session lifecycle:

| Transport     | Startup failure (returned in tuple)                                                                                                                                                                                    | Post-open failure (after tuple resolves)                                                                                                                                                                                                                                                                         |
| ------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| **HTTP**      | All failures settle the operation tuple once.                                                                                                                                                                          | N/A                                                                                                                                                                                                                                                                                                              |
| **SSE**       | Non-`2xx` (`HTTP_STATUS`, with `data: undefined` when the declared `error` body cannot be decoded), or a `2xx` handshake with a bad content type (`RES_MEDIA_TYPE_INVALID`) or no readable body (`RES_DECODE_FAILED`). | Async iterator rejects; `stream.closed` resolves with `{ kind: 'error', code }`.                                                                                                                                                                                                                                 |
| **WebSocket** | Pre-open close, constructor failure, or abort during handshake.                                                                                                                                                        | Non-fatal frame errors fire `session.onRuntimeError`; fatal errors reject `session.receive` and resolve `session.closed` with `{ kind: 'error', cause }`. Incoming queue overflow uses `cause.code === 'CAP_QUEUE_OVERFLOW'`; heartbeat timeout and exhausted reconnects retain ordinary runtime `Error` causes. |
