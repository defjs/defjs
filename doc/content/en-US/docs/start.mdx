# Getting started: your first SDK operation [#getting-started-one-http-request]

In this guide you will create an SDK module that defines `GET /orders/:id` and call it from two separate application modules: one using an offline mock transport and one pointing at a live API.

## 1. Install `@defjs/core`

`@defjs/core` is a zero-dependency ESM package that runs in browsers and Bun. Ensure `"type": "module"` is set in your `package.json`.

```sh
bun add @defjs/core
```

### How the three files work together

1. **`src/define-request.ts` (SDK definition)**:
   - Declares `input`, `output` (for `2xx` responses), and `error` (for non-`2xx` responses) using `struct`.
   - Supplies a synchronous, pure `builder` that maps `input` into `{ path }`. Whenever `input` is declared, an explicit `builder` is required.
   - Exports `getOrder` without creating or capturing a client.
2. **`src/execute-locally.ts` (Offline test execution)**:
   - Configures a client with `withHTTPHandle(...)` to run the full Defjs pipeline (input validation, URL resolution, status dispatch, and response struct parsing) without touching the network.
3. **`src/real-api.ts` (Production execution)**:
   - Imports the exact same `getOrder` operation and calls it against a live base URL configured via `withEndpoint(...)`.

## 3. Run the local example

Execute `src/execute-locally.ts` with Bun:

```sh
bun src/execute-locally.ts
```

```txt
Loaded paid from 200
```

If you change the input from `{ id: 7 }` to `{ id: 8 }`, the mock returns `404` and Defjs decodes the declared `error` struct into `error.data`:

```txt
Order not found
```

## 4. Understand the error-first tuple

Every HTTP call resolves `[error, data, response]`:

- **On `2xx` success**: `error` is `null`, `data` is the validated `output` value (`Order`), and `response` is `DecodedResponse<Order>`.
- **On a declared non-`2xx` status**: `error.code` is `'HTTP_STATUS'`, `error.status` is the status number (`404`), and `error.data` is the validated `error` struct (`NotFound`).
- **On input, decode, or network faults**: `error.code` identifies the exact failure stage:
  - `REQ_INPUT_INVALID` / `REQ_BUILD_FAILED` — invalid caller input or a throwing `builder`
  - `RES_MEDIA_TYPE_INVALID` — declared JSON body arrived with a non-JSON `Content-Type` (rejected before reading the body)
  - `RES_DECODE_FAILED` / `RES_STRUCT_MISMATCH` — unreadable body or schema mismatch
  - `NET_UNREACHABLE` / `NET_ABORTED` / `NET_TIMEOUT` — transport error, manual cancellation, or `AbortSignal.timeout(ms)` deadline

Pass per-call deadlines or cancellation signals by deriving a single-call client value: `getOrder(client({ signal: AbortSignal.timeout(5_000) }), { id: 7 })`.
