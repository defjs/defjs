# Application API layer [#application-api-layer]

Most projects use Defjs directly inside an application repository (`src/api/`) to replace scattered `fetch` or `axios` wrappers. Even when you have no plans to publish an external npm package, separating `src/api/models/`, `src/api/services/`, and `src/api/client.ts` keeps your request layer strongly typed, testable in memory, and safe across browser and SSR runtimes.

---

## 1. Recommended `src/api/` directory layout

Organize your project's request layer into three focused parts under `src/api/`:

```text
src/
├── api/
│   ├── models/           # 1. Shared struct schemas + Infer<typeof ...> types
│   │   └── order.ts      #    ApiError, OrderStatus, Order, OrderPage
│   ├── services/         # 2. Pure operation definitions grouped by domain
│   │   └── orders.ts     #    getOrder, listOrders, createOrder
│   └── client.ts         # 3. App-owned Client (endpoint, auth interceptor, retry)
└── checkout.ts           # 4. Business logic / UI components calling operations
```

## 3. Key patterns for application projects

### Browser singleton vs. SSR per-request client

- **Browser / SPA (`apiClient`)**: Export a single module-scoped `createClient(...)` instance per backend origin. Sharing that instance preserves load-balancer health state and the client-level HTTP retry budget across page interactions. In React or Vue apps, provide `apiClient` at the root via [`@defjs/react`](/docs/integrations/react) (`ClientProvider` / `useClient`) or [`@defjs/vue`](/docs/integrations/vue) (`createClientPlugin` / `injectClient`).
- **SSR / BFF (`createServerApiClient(accessToken)`)**: Whenever credentials, cookies, or tenant headers vary per incoming HTTP request, call a factory function inside your server request handler to create an isolated `Client`. Because `getOrder`, `listOrders`, and `createOrder` are pure functions, the exact same `services/orders.ts` definitions work with both `apiClient` and `createServerApiClient(token)`.

### Per-call timeouts and cancellation

Never create a new `Client` via `createClient(...)` just to pass a timeout or `AbortSignal`. Instead, derive a single-call client inline from your shared client:

```ts
const [error, created] = await createOrder(
  apiClient({ signal: AbortSignal.timeout(5_000) }),
  {
    customerName: "Ada Lovelace",
    totalCents: 4200,
    idempotencyKey: "idem-2026-101",
  },
);
```

### Shared error envelope (`ApiError`)

Declare your backend's standard error envelope once (`export const ApiError = struct.object(...)`) in `src/api/models/` and pass `error: ApiError` on every `defineRequest` in `src/api/services/`. When a request returns a non-`2xx` status, narrowing `if (error.code === "HTTP_STATUS")` gives you strongly typed access to `error.data.code`, `error.data.message`, and `error.data.requestId`.
