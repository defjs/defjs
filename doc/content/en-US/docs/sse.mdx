# Server-Sent Events

Open a stream, iterate it, then release the owned handle with `await using`. Manual `close()` and `closed` remain available; clients and plugins don’t dispose a returned stream for you.

## Define the stream

`defineEventStream(...)` needs `events`, positive safe-integer `maxBufferSize`, positive safe-integer `maxQueueSize`, and a relative `path`. Method defaults to `GET`.

The request shape matches HTTP: `builder` returning `path`, `query`, `headers`, and `body`. `GET` / `HEAD` cannot return a body. A declared `error` struct types the startup fault and decodes a non-2xx handshake body by struct kind (`string` text, `blob` / `file` blob, `arrayBuffer` bytes, otherwise JSON). Defjs sends `Accept: text/event-stream` when you didn’t already set `Accept`. A declared `input` always requires an explicit `builder`, even when it already matches the request shape. Only definitions without `input` may omit `builder`. A `ReadableStream` body follows the HTTP rules: on a runtime that cannot stream request bodies, such as Firefox, startup fails with `ENV_UNSUPPORTED` before anything is sent. In Chromium it needs HTTP/2 or later; over HTTP/1.1 startup fails with `NET_UNREACHABLE`. A stream body is sent once and never reconnected (see Reconnect).

One logical stream can span several physical Fetch attempts **when** you opt into reconnect. Without `withSSEReconnect`, transient network and stream-read failures end the logical stream. You still get one handle and one async iterator when the open succeeds.

## Open and inspect

`client.execute(...)` resolves only after status, content-type, and body checks pass:

</include>

Response must be successful, media type essence `text/event-stream`, and have a body. Non-2xx startup → `HTTP_STATUS`. When `error` is declared, that fault carries the decoded handshake body; a bad media type is `RES_MEDIA_TYPE_INVALID` and a body that cannot be read as the declared kind is `RES_DECODE_FAILED`. A response snapshot can still sit in the third tuple slot when validation fails after the response arrives.

A missing, relative, or invalid base endpoint or an illegal path fails with `REQ_BUILD_FAILED` during building, before any interceptor or transport runs, even if an interceptor would short-circuit. The resolved URL must keep the base origin and stay under its directory; C0 control characters (including tab, CR, and LF), backslashes, `?`, `#`, and directory escapes in the path are rejected. Scheme-like and protocol-relative forms are rejected even with leading spaces; a plain inner space is allowed and sent as `%20`. An interceptor's final `req.endpoint` is checked against its final `req.baseEndpoint` with the same rule; deliberately replacing the base with another valid absolute URL is allowed. Deterministic URL errors are never retried.

`startupOpen` is the initial snapshot for that execution; a new `execute` never reuses a previous execution's snapshot, even if it fails before a response arrives. `stream.open` is live and changes on later physical opens. Keep the tuple value when the first response matters. `startupOpen` is the returned connection's first successful handshake snapshot only for a native Defjs handle or a wrapper forwarding the same live `open` object; custom handles and wrappers overriding `open` retain their current public `open` even after reconnect, so shared `closed` cannot bypass URL sanitization or header filtering, and Defjs does not reconstruct first-handshake metadata from arbitrary transformations.

## Decode events

Wire event name → `events[eventName]`; else `events.default`. No matching Struct → event not delivered. Missing SSE `event` field → logical name `message`.

SSE `data` starts as text. A `string` struct keeps that text. Every other kind is JSON: parse the text, then decode with the struct. `struct.object`, `struct.number`, `struct.boolean`, `struct.any`, and `struct.unknown` are JSON, not trimmed text. A bare token such as `ping` does not satisfy `struct.literal('ping')`; the data has to be JSON. A server that sends the JSON string `"abc"` still satisfies `struct.string()`: the delivered value is that raw text, including the quotes, and is not JSON-decoded to `abc`.

Parsing follows the WHATWG SSE line and field rules: CR, LF, and CRLF end lines; a blank line dispatches a data-bearing event; multiple `data:` lines join with `\n`. Comments and unknown fields are ignored, and an unfinished event at EOF is not dispatched. Only one leading UTF-8 BOM at the start of each physical stream is removed. U+FEFF inside `data` or `id` values is preserved; a later BOM-prefixed field name such as `﻿data` is unknown and ignored.

Emitted value: `event`, decoded `data`, optional non-empty `id`. With `default`, unknown event names are `string` in the inferred union.

## Observe invalid events

Invalid/undeclared events are dropped, not queued. `withSSEOnInvalidEvent(...)` can observe raw ID, name, text data, plus `missing-struct` or `validation-failed` and an optional cause.

Observer runs at the transform boundary. Its failure is isolated unless the active attempt signal is aborted. Keep it short; don’t treat raw event data as trusted.

## Reconnect

**Behavior change:** SSE reconnect is opt-in. Without `withSSEReconnect(...)`, network and stream-read failures are **not** retried (same as `attempts: 0`). Pass `withSSEReconnect({ attempts: 3 })` (or another reviewed budget) to retry those failures. Normal EOF is not retried. Status/content-type validation, parser limits, message transform failures, queue overflow, and normal EOF stay terminal for the logical stream.

<include cwd>examples/sse/reconnect.ts#example</include>

`attempts` is the retry budget for each outage; it defaults to `3` when a reconnect object is set. A successful handshake resets the budget, callback attempt, and backoff exponent, so separate outages do not spend a lifetime budget. `attempts: 0` disables retry. Omitting `withSSEReconnect` also disables retry. `delayMs` is the initial interval (default `1000`); `factor` grows it (default `1`, a constant delay); `maxDelayMs` is a hard cap on the final delay, after jitter and rounding (default: no configured cap). SSE `jitter` is a **0–1 multiplicative factor**, same as WebSocket. The platform timer limit is `2_147_483_647` ms even without a configured cap. A zero base stays zero; overflow from otherwise valid numbers saturates at the caps. A digits-only stream `retry:` field updates the current base interval, including after recovery. Policy callback returning false / throwing / rejecting ends the logical stream. Repeated successful opens followed immediately by retryable stream failures can keep reconnecting at the current base delay (subject to jitter and caps), because each open resets the budget; use `shouldReconnect` to stop them. Normal EOF remains terminal.

Reconnect options are checked before interceptors or Fetch: `attempts` must be a non-negative safe integer; `delayMs` and an explicitly supplied `maxDelayMs` must be finite and non-negative; `factor` must be finite and positive; `jitter` must be finite and within 0–1. Invalid values return `REQ_OPTIONS_INVALID` without opening a stream.

Latest parsed event ID becomes `Last-Event-ID` on a later attempt, encoded as UTF-8 bytes on the wire, including non-ASCII IDs. An empty `id:` clears the header; an ID containing NUL is ignored. Apart from that header, a later attempt resends the request built for the first one: the builder and interceptors run once per `execute`, so method, URL, headers, and body stay the same. A header that must be fresh on every attempt, such as a short-lived token, belongs in the Fetch passed to `withSSEHandle`, which runs once per attempt. If a credential still expires, a non-2xx reconnect handshake after the stream has opened ends it with `RES_DECODE_FAILED`; inspect `stream.open.response.status` for the status. A non-2xx initial handshake instead returns a startup `HTTP_STATUS` fault when its declared error body decodes.

Reconnect resends a request only when that is safe:

- `GET`, `HEAD`, `OPTIONS`, `PUT`, and `DELETE` are idempotent (RFC 9110 §9.2.2) and reconnect within the budget.
- Any other method, such as `POST` or `PATCH`, reconnects only when `shouldReconnect` returns `true`. A failed connection cannot tell whether the server already acted: a `POST` that starts an LLM generation would run, and be billed, again, and its new events would follow the old ones in the same stream. Passing `shouldReconnect` replaces this default for every method, so check `method` in its context when one client serves both kinds of endpoint.
- A `ReadableStream` body is consumed by the first attempt. Any failure, before or after the stream opens, ends the stream with the original error; `shouldReconnect` is not called and no delay is spent. Use a string, bytes, `Blob`, form, or JSON body when the request must reconnect.

## Buffer and queue limits

Both must be positive safe integers. Overflow is fatal — no silent discard of older events.

| Limit           | Protects                                           | Terminal code         |
| --------------- | -------------------------------------------------- | --------------------- |
| `maxBufferSize` | Incomplete/oversized SSE line/event while parsing  | `CAP_BUFFER_EXCEEDED` |
| `maxQueueSize`  | Events produced faster than the one consumer reads | `CAP_QUEUE_OVERFLOW`  |

Fatal stream also clears buffered events, cancels the active body, rejects the iterator, and resolves `stream.closed` with `kind: 'error'`.

## Close and dispose

`EventStreamHandle`: one live opening snapshot, one terminal promise, one `close`, one async iterator, and one standard async disposer.

<include cwd lang="typescript">
  examples/sse/close-and-dispose.ts#example
</include>

Terminal kinds (`closed.kind`): `eof`, `aborted`, or `error`. An `error` result also carries `closed.code`, an `EventStreamFaultCode`: `CAP_BUFFER_EXCEEDED`, `CAP_QUEUE_OVERFLOW`, `EXT_HOOK_FAILED`, `EXT_OBSERVER_FAILED`, `NET_TIMEOUT`, `NET_UNREACHABLE`, `RES_DECODE_FAILED`, or `RES_MEDIA_TYPE_INVALID`.

`close(reason)` aborts the active attempt, closes the queue, settles as `aborted`, even when the reason is a `TimeoutError`. Aborting the `signal` or `abort` given to `execute` after the stream is open normally ends the iterator and reports `aborted`; if the abort reason is a `TimeoutError` or `ERR_TIMEOUT` (for example `AbortSignal.timeout(...)`), the iterator throws `ERR_TIMEOUT` and `closed` reports `kind: 'error'` with `code: 'NET_TIMEOUT'`. The execute `timeout` option is only a startup deadline and never ends an open stream. Loop `break` / `return` / throw invokes iterator return and closes with `iterator-return`. The code that executes the command owns closure.

`await using` calls the same owned close path and waits until Defjs reading/reconnect work has stopped and the active reader lock has been released. It is intentionally bounded around a provider-controlled `ReadableStream.cancel()` promise that never settles, so it does not guarantee that such a provider promise completed. Explicit `stream.close(reason)` plus `await stream.closed` is still valid when you need a reason or the terminal result.

Custom structural `EventStreamHandle` implementations must now provide `[Symbol.asyncDispose](): PromiseLike<void>` and connect it to the same lifecycle. That is a compile-time breaking change for implementers; consumers that only receive a Defjs handle do not need to invoke anything new at runtime.

The supported minimum lib set is `ES2022`, `ESNext.Disposable`, `DOM`, and `DOM.Iterable`. Repository declaration tooling uses TypeScript 7, but there is no automated packed-consumer or minimum-lib verification gate, and older compilers are not promised. This set supplies types, not runtime Web API polyfills. An ordinary HTTP client is not `AsyncDisposable`; manage each request with its timeout or `AbortSignal`.

Keep credentials, event data, event IDs, causes, and stream URLs out of routine logs. `withCredentials(true)` affects Fetch cookies for SSE; it does not configure WebSocket auth.
