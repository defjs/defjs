# SSE event streams

An SDK declares a Server-Sent Events endpoint with `defineEventStream`, specifying the path, optional input and builder, an `events` dictionary of structs, and buffer/queue limits. The consuming application configures authentication and opt-in reconnection on its client, opens the stream, iterates typed events, and owns closing the stream.

## 1. Define the event stream and consume it

Always release an opened `EventStreamHandle` with `await using` (or `stream.close()` + `await stream.closed` in a `finally` block):

<Tabs items={["sdk/orders-stream.ts", "app/watch-orders.ts", "Single-file quick look"]}>
<Tab value="sdk/orders-stream.ts">

```ts
import { defineEventStream, struct } from "@defjs/core";

export const watchOrders = defineEventStream({
  path: "/orders/events",
  operation: "orders.watch",
  events: {
    updated: struct.object({
      id: struct.number(),
      status: struct.string(),
    }),
  },
});
```

</Tab>
<Tab value="app/watch-orders.ts">

```ts
import { createClient, withEndpoint } from "@defjs/core";
import { watchOrders } from "../sdk/orders-stream.ts";

const client = createClient(withEndpoint("https://api.example.com"));

async function main() {
  const [error, stream] = await watchOrders(client);
  if (error) {
    console.error(error.code);
    return;
  }

  await using active = stream;
  for await (const event of active) {
    console.log(event.event, event.data.id, event.data.status);
    break;
  }
}

void main();
```

## 2. Opening handshake and tuple shape

Calling the operation resolves `[error, stream, startupOpen]` only after the initial HTTP response is `2xx`, has media type `text/event-stream`, and carries a readable body:

- **Non-`2xx` handshake**: Returns `HTTP_STATUS` (with decoded `error.data` when an `error` struct is declared on the definition). This is fatal for the current operation; `shouldReconnect` is not called. The next operation performs a fresh endpoint pick, so a balancer may choose another endpoint.
- **Wrong content type or unreadable body**: Returns `RES_MEDIA_TYPE_INVALID` or `RES_DECODE_FAILED`.
- **`startupOpen` vs. `stream.open`**: The tuple's third item (`startupOpen`) snapshots the first handshake response; `stream.open` updates live if the stream reconnects later. If a reconnect handshake returns `503`, the iterator rejects and `stream.closed` reports `RES_DECODE_FAILED`, while `stream.open.response.status` remains `503`; inspect `stream.open` for that live response status.

## 3. Event dispatch and decoding

When an SSE frame arrives (terminated by a blank line per WHATWG rules):

1. **Event routing**: The wire `event:` field selects `events[eventName]`, falling back to `events.default` if declared. An omitted `event:` field defaults to `"message"`. Undeclared events without `events.default` are dropped.
2. **Payload decoding**: A `struct.string()` schema receives the raw text `data:`. Every other struct kind parses `data:` as JSON first, then validates with the struct.
3. **Observing invalid events**: Invalid or undeclared events are dropped without killing the stream. Attach `withSSEOnInvalidEvent(...)` on the client for bounded diagnostics:

## 4. Reconnect and `Last-Event-ID` [#reconnect]

SSE reconnection is **opt-in**. Without `withSSEReconnect(...)`, any network drop or stream read error terminates the stream.

<include cwd>examples/sse/reconnect.ts#example</include>

- **Outage budget (`attempts`)**: Defaults to `3` when an options object is passed to `withSSEReconnect`. Every successful handshake resets the attempt counter and backoff exponent, so `attempts: 1` can still create many physical connections over a long-lived session when each one opens successfully. Normal server EOF is **not** a failure and does not trigger reconnect.
- **Cursor tracking (`Last-Event-ID`)**: Committed when an event's terminating blank line is parsed and automatically sent as `Last-Event-ID` on reconnect. A partial frame never commits its `id`, whether the connection ends cleanly or fails. Resume after a reconnectable read/network failure starts from the last committed id; the server must implement replay from that cursor.
- **Idempotency safety**: By default, only idempotent methods (`GET`, `HEAD`, `OPTIONS`, `PUT`, `DELETE`) reconnect automatically. Non-idempotent methods (`POST`, `PATCH`—such as LLM streaming requests) reconnect only when a custom `shouldReconnect` callback explicitly returns `true`. `ReadableStream` request bodies are consumed on the first attempt and never reconnect.
- **Handshake timeout (`connectTimeoutMs`)**: When provided, it must be finite, positive, and no greater than 2147483647 (the timer limit); otherwise the operation returns `REQ_OPTIONS_INVALID`. Bounds each handshake from Fetch invocation to response headers without limiting how long an established stream stays open.

## 5. Buffer and queue limits

The defaults are `maxBufferSize: 64 * 1024` bytes and `maxQueueSize: 1024` events. Both limits must be positive safe integers. There is no default handshake deadline: a pending Fetch waits for the platform, caller cancellation, or an explicitly configured `connectTimeoutMs`. Exceeding either capacity limit is fatal (`stream.closed` resolves with `kind: "error"` and the iterator rejects—events are never silently dropped):

| Definition option | What it bounds                                              | Terminal fault code   |
| ----------------- | ----------------------------------------------------------- | --------------------- |
| `maxBufferSize`   | Incomplete or oversized SSE frame bytes before a blank line | `CAP_BUFFER_EXCEEDED` |
| `maxQueueSize`    | Validated events waiting for the `for await` consumer       | `CAP_QUEUE_OVERFLOW`  |
