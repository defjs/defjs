# Client

A `Client` holds the consuming application's execution configuration: base URLs, default headers, credentials, interceptors, query serialization, and transport handles.

`createClient(...options)` returns a [`DerivableClient`](/api/core/derivableclient-type):

- Pass `client` directly to an operation (`getOrder(client, { id: 1 })`) when no per-call request options are needed.
- Call `client(requestOptions)` to derive a client value for one call (`getOrder(client({ signal }), { id: 1 })`). Deriving performs no I/O, and the derived value is a plain object (not callable).

### Option composition rules

- Options apply **left to right**.
- Single-value setters (`withEndpoint`, `withHeaders`, `withQuerySerializer`, `withCredentials`, `withXSRF`) **replace** earlier values.
- `withInterceptors(...items)` **appends** to the existing interceptor list and filters by transport (`http`, `sse`, `web-socket`) when an operation runs.

### Per-call `RequestOptions` reference

`RequestOptions` has seven flat fields. Each transport reads only the fields that apply to it and ignores the rest:

| Field                | Used by              | Behavior                                                                                                                                  |
| -------------------- | -------------------- | ----------------------------------------------------------------------------------------------------------------------------------------- |
| `signal`             | HTTP, SSE, WebSocket | Aborts the call (`AbortSignal.timeout(ms)` → `NET_TIMEOUT`; manual abort → `NET_ABORTED`).                                                |
| `onUploadProgress`   | HTTP                 | Reports streaming request-body upload progress.                                                                                           |
| `onDownloadProgress` | HTTP                 | Reports declared response-body download progress.                                                                                         |
| `beforeConnect`      | WebSocket            | Replaces the client-level `beforeConnect` hook for this session.                                                                          |
| `protocols`          | WebSocket            | Replaces the client-level subprotocol list for this session.                                                                              |
| `heartbeat`          | WebSocket            | Replaces the client-level heartbeat configuration for this session.                                                                       |
| `reconnect`          | WebSocket            | Replaces the client-level WebSocket reconnect policy for this session (SSE reconnect is configured on the client via `withSSEReconnect`). |

## 3. Browser singleton vs. server request scope

- **Browser applications**: Share a single module-scoped `DerivableClient` when the endpoint, interceptors, and credentials are browser-wide.
- **Server / SSR applications**: Create a fresh client **inside each inbound request boundary** whenever headers, cookies, auth tokens, or tenant context are request-specific. Never store per-user credentials on a process-wide client.

## 4. Multiple endpoints and load balancing [#multiple-endpoints]

`withEndpoint(...urls)` accepts one or more candidate base URLs. By default:

- Each client uses [`pickFirstBalancer`](/api/core/pickfirstbalancer), sticking to the first URL until it advances on `NET_UNREACHABLE` or `NET_UNAVAILABLE` (HTTP 502, 503, or 504). An HTTP retry does not move the sticky endpoint.
- **Same-call HTTP retry is off by default.** `withRetry()` is equivalent to `withRetry({})` and enables a second attempt on an untried endpoint for connection failures on safe methods (`GET`, `HEAD`, `OPTIONS`, `TRACE`), with backoff. A Finagle retry budget belongs to the client configuration and is shared by its derived clients, independently of balancer identity.

<include cwd lang="typescript">
  examples/client/multiple-endpoints.ts#example
</include>

With only one configured endpoint, `withRetry` does not replay the request because each retry excludes endpoints already tried. `attemptTimeoutMs` and `connectTimeoutMs`, when provided, must be finite, positive, and no greater than 2147483647 (the timer limit); otherwise the operation returns `REQ_OPTIONS_INVALID`. `connectTimeoutMs` exists only inside the SSE and WebSocket reconnect options. Those options default to `attempts: 3`, so setting it alone also enables reconnect; add `attempts: 0` for a handshake-only deadline.

### Health filtering and p2c [#health-filtering-and-p2c]

For peer server replicas, [`roundRobinBalancer`](/api/core/roundrobinbalancer) and [`p2cBalancer`](/api/core/p2cbalancer) (PeakEwma RTT × in-flight load) enable Linkerd-style consecutive-failure circuit breaking (`outlierDetection`) by default. Outlier detection counts every coded outcome as a failure (including `NET_TIMEOUT` and `NET_BODY_INCOMPLETE`); raw response `status` is only for custom balancers.

See the dedicated [Load balancing & failover](/docs/load-balancing) guide for full details on retry budgets, active/passive health checks, P2C load estimation, and custom balancers.

## 6. Client option helpers reference

| Helper                                                                                                        | Purpose                                                                                                |
| ------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------ |
| `withEndpoint(...urls)`                                                                                       | Sets one or more candidate base URLs (replaces earlier list).                                          |
| `withHeaders(HeadersInit)`                                                                                    | Sets static default headers for HTTP and SSE (builder headers override).                               |
| `withInterceptors(...items)`                                                                                  | Appends HTTP, SSE, and WebSocket interceptors in onion order.                                          |
| `withQuerySerializer(fn)`                                                                                     | Serializes already-aliased query objects into a query string.                                          |
| `withCredentials(boolean)`                                                                                    | Sets Fetch `credentials: "include"` for HTTP and SSE when `true`.                                      |
| `withXSRF(options?)`                                                                                          | Copies the XSRF cookie into a header on same-origin mutating HTTP requests.                            |
| `withBalancer(balancer)`                                                                                      | Replaces the endpoint selection strategy (`pickFirstBalancer`, `roundRobinBalancer`, `p2cBalancer`).   |
| `withRetry(options?)`                                                                                         | Configures opt-in HTTP retry conditions, methods, backoff, attempt timeout, and a client-owned budget. |
| `withSSEReconnect` / `withSSEOnInvalidEvent`                                                                  | Configures SSE reconnection and invalid-event observation.                                             |
| `withWebSocketReconnect` / `withWebSocketHeartbeat` / `withWebSocketProtocols` / `withWebSocketBeforeConnect` | Configures WebSocket session defaults.                                                                 |
| `withHTTPHandle` / `withSSEHandle` / `withWebSocketHandle`                                                    | Injects custom or mock transport implementations.                                                      |
