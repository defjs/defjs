# Client

A `Client` is the consuming application's execution configuration. `createClient(...)` returns a [`DerivableClient`](/api/core/derivableclient-type). Calling the factory with request options returns a `Client` value, and a `Client` value is what operations accept. It is not callable. Import operations from your SDK, choose the service address, credentials, interceptors, and transport, then call an operation with the client. `getOrder(client({ signal }), { id: 1 })` starts a call that declares input. `health(client)` starts one that does not. When the whole input struct is optional, both `search(client)` and `search(client, input)` are valid. There is no third options argument. Calling the operation starts it. `await` only waits for the error-first tuple.

The SDK's definitions do not bind this instance. A browser, a server request, and a local test can use the same exported operation with different clients. All still follow the same Defjs contract and compatible Core versions. Configure each client's service address for the operations you call through it.

The same client value can be passed to many operations. Applications choose caching and retry policies and own the work they start. HTTP is not retried automatically. Stream reconnection is opt-in.

The factory is a function and is also a `Client` with no request options. Do not pass the factory to a React state setter: `setState(factory)` would call it as an updater. Do not use it as a Vue `watch` or `computed` source: those call a function. A derived client value is a plain object.

## Derive a client

`client(options?)` returns a `Client` value for one call. `client()` and `client(undefined)` store no request options. `client({})` keeps an empty snapshot; Defjs does not drop it by inspecting keys. Calling `client(options)` reads each top-level request field once onto a new options object. A `protocols` array is copied. `heartbeat` copies `intervalMs`, `isAck`, `message`, and `timeoutMs`. `reconnect` copies `attempts`, `delayMs`, `factor`, `jitter`, `maxDelayMs`, and `shouldReconnect`. Missing nested blocks stay missing, so they do not turn heartbeat or retry on. `signal`, `beforeConnect`, and every callback keep their identity. The same option object can be passed again; each call captures its own containers. Deriving performs no I/O. A getter on these fixed fields runs during `client(options)`. If it throws, the exception escapes that call and leaves the factory usable. It is not turned into a fault. Out-of-range numbers are still checked when the operation runs and still return `REQ_OPTIONS_INVALID`. The client value is not callable; create one per call.

`signal` is not combined. Reusing a client value that carries `signal` shares that signal between calls, so create a client value per call. Combine signals with `AbortSignal.any` in application code.

The base configuration from `createClient` is shared by every client value and is not frozen at runtime. It is fixed by convention: nothing in the library changes it, and applications should not either. Standard helpers such as `withWebSocketHeartbeat`, `withWebSocketReconnect`, `withSSEReconnect`, and `withWebSocketProtocols` copy their fixed records when the helper is applied. A custom client option can still keep its own reference. `withInterceptors` appends a fresh `{ kind, fn }` record for each entry and keeps `fn` itself. A derived client carries a captured [`RequestOptions`](/api/core/requestoptions-type) object only when options were supplied. The factory, `client()`, and `client(undefined)` have none. Application code passes the client to an operation. It does not read that internal state.

## Request options

[`RequestOptions`](/api/core/requestoptions-type) has seven flat fields. Each protocol reads only the fields it knows and ignores the rest. Passing `heartbeat` to an HTTP operation is ignored, not a fault. SSE reads only `signal` from request options. SSE reconnect comes from client configuration (`withSSEReconnect`), so `client({ reconnect })` affects WebSocket only. There is no compile-time protocol filter.

| Field                | Used by              | Rule                                                                                                       |
| -------------------- | -------------------- | ---------------------------------------------------------------------------------------------------------- |
| `signal`             | HTTP, SSE, WebSocket | Aborts the call. A deadline is `AbortSignal.timeout(ms)` (`NET_TIMEOUT`). A manual abort is `NET_ABORTED`. |
| `onUploadProgress`   | HTTP                 | Ignored by SSE and WebSocket.                                                                              |
| `onDownloadProgress` | HTTP                 | Ignored by SSE and WebSocket.                                                                              |
| `beforeConnect`      | WebSocket            | Replaces the client setting for that call.                                                                 |
| `protocols`          | WebSocket            | Replaces the client list. It is not appended.                                                              |
| `heartbeat`          | WebSocket            | Replaced whole. `timeoutMs` is the heartbeat acknowledgement wait, not a request deadline.                 |
| `reconnect`          | WebSocket            | Replaced whole.                                                                                            |

There is no `timeout` field, no `abort` field, and no client-level default deadline. For SSE and WebSocket, `signal` covers the whole connection, including after it is open. There is no startup-only deadline. An application that wants one creates its own `AbortController`, aborts it with `new DOMException("...", "TimeoutError")` from a timer, and clears the timer after the await returns. See [SSE](/docs/sse#close-and-dispose).

`HttpExecuteOptions` is the HTTP slice: `signal` plus the progress callbacks. `EventStreamExecuteOptions` is `{ signal? }`. `WebSocketExecuteOptions` is the WebSocket slice plus `signal`.

## Results by transport

- HTTP → `[error, data, response]`
- SSE → `[error, stream, open]`. `open` is the returned connection's first successful handshake snapshot for native Defjs handles or wrappers forwarding the same live `open` object; custom handles or wrappers overriding `open` use their current public `open` even after reconnect, while `stream.open` stays live (see [SSE](/docs/sse)).
- WebSocket → `[error, session, connection]`

Return before using the success value when `error` is set.

You own cleanup: abort HTTP, close SSE + `await stream.closed`, close WebSocket + `await session.closed`.

## Scope on server vs browser

On a server, create the client inside the request boundary when options or interceptor closures capture auth, cookies, users, or tenants. Client identity isn’t a security boundary by itself.
