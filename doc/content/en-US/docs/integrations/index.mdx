# Integrations overview

An integration extends the application's own `Client` at a defined extension point without modifying `@defjs/core` or coupling an SDK definition to a framework or telemetry stack. Your SDK definitions remain pure `@defjs/core` modules; the consuming application chooses which integrations to install.

Every Defjs plugin obeys the **thin plugin contract**:

- **No hidden caching or state**: plugins never store responses, retry requests, or manage query state.
- **No transport replacement**: plugins never wrap or replace the underlying HTTP, SSE, or WebSocket transport.
- **Caller-owned lifecycle**: unmounting a UI provider or shutting down a telemetry SDK does not automatically cancel in-flight requests or close active streams.

## Published integrations & tools

| --------------------------------------------------------------- | --------------------------------- | ----------------- | ------------------------------------------------------------------------------------------------------------ | --------------------------------------------------------------------------------- |
| [React](/docs/integrations/react)                               | `@defjs/react`                    | Framework plugin  | `ClientProvider` and `useClient(overrideClient?)` for React 18+                                              | Client creation, `AbortController` cleanup, query caching (e.g., TanStack Query)  |
| [Vue](/docs/integrations/vue)                                   | `@defjs/vue`                      | Framework plugin  | `createClientPlugin`, `HTTP_CLIENT`, and `injectClient(key?)` for Vue 3.2+                                   | Client creation, `onCleanup` / `onScopeDispose` cancellation, query state         |
| [OpenTelemetry server](/docs/integrations/opentelemetry-server) | `@defjs/opentelemetry-server`     | Middleware plugin | `withOpenTelemetryServer(...)` `ClientOption` for outbound HTTP, SSE, and WebSocket spans, metrics, and logs | OpenTelemetry SDK initialization, exporters, sampling, redaction, and flush       |
| [AI Skill](/docs/ai) & [llms.txt](/docs/ai-api)                 | `defjs/defjs` skill & `/llms.txt` | AI tooling        | Agent skill (`SKILL.md`) and machine-readable Markdown documentation                                         | Verification against the project's installed `@defjs/core` version and test suite |

## Two plugin architectures

### 1. Framework plugins (`@defjs/react`, `@defjs/vue`)

### 2. Middleware plugins (`@defjs/opentelemetry-server`)

A middleware plugin is a factory that returns a [`ClientOption`](/api/core/clientoption-type). When passed to `createClient(...)`, it appends HTTP, SSE, and/or WebSocket interceptors through `withInterceptors`:
