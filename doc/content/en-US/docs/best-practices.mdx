# Engineering conventions [#engineering-conventions]

Whether you are hand-writing an HTTP request layer inside a frontend/backend application or publishing an official TypeScript SDK for your company's public API, Defjs projects follow the same modular architecture: **shared `struct` schemas (`schema/`) paired with pure operation definitions (`request/`)**.

---

## 1. Two ways to use Defjs

Most teams adopt Defjs in one of two scenarios. Both organize contracts into `schema/` and `request/`, differing only in where `createClient(...)` lives:

| Scenario                                                                               | Directory layout                                                 | Who owns `createClient(...)`?                                                                    | Guide                                          |
| :------------------------------------------------------------------------------------- | :--------------------------------------------------------------- | :----------------------------------------------------------------------------------------------- | :--------------------------------------------- |
| **[Application API layer](/docs/application-api)** (in-project HTTP/realtime requests) | `src/api/schema/` + `src/api/request/` + `src/api/client.ts`     | Your application (`src/api/client.ts` exports a browser singleton or an SSR per-request factory) | [Application API layer](/docs/application-api) |
| **[Public SDK design](/docs/public-sdk)** (external npm package for public APIs)       | `src/schema/` + `src/request/` + `src/index.ts` (`package.json`) | The external consumer's application (the published SDK never creates or captures a `Client`)     | [Public SDK design](/docs/public-sdk)          |

---

## 2. Four core engineering conventions

### Convention 1: Export pure operation functions, never `Service` classes

Legacy OpenAPI generators wrap endpoints in stateful or static `Service` classes (`OrdersService.getOrder(id)` or `new S3Client().send(...)`). In Defjs, every operation created with `defineRequest`, `defineEventStream`, or `defineWebSocket` is already a **standalone callable function**:

```ts
// Avoid: wrapping definitions in a class or namespace object
export class OrdersService {
  // Hides per-call client(options) derivation and blocks bundler tree-shaking
}

// Recommended: export standalone operation definitions from request/*.ts
export const getOrder = defineRequest({
  meta: { operation: "orders.get" },
  method: "GET",
  path: "/orders/:id",
  input: GetOrderInput,
  builder: (input) => ({ path: { id: input.id } }),
  output: Order,
  error: ApiError,
});
```

Calling the exported operation directly (`await getOrder(client, { id: 42 })` or `await getOrder(client({ signal }), { id: 42 })`) keeps the calling convention uniform across your entire codebase and allows bundlers to tree-shake unused operations when `"sideEffects": false` is set.

### Convention 2: Same-name `struct` + `Infer` exports in `schema/`

In `schema/*.ts`, export both the runtime `struct` schema and its inferred TypeScript type under the **same identifier**. TypeScript merges value and type declarations in the same scope, so callers import a single symbol for both runtime validation and static type annotations:

```ts
import { struct, type Infer } from "@defjs/core";

export const Order = struct.object({
  id: struct.number(),
  customerName: struct.string().alias("customer_name"),
  totalCents: struct.number().alias("total_cents"),
});
export type Order = Infer<typeof Order>;
```

### Convention 3: Keep `request/*.ts` free of client instances

Even when writing an [application API layer](/docs/application-api) inside a single repository (`src/api/`), do **not** import `apiClient` inside `src/api/request/*.ts` to wrap your definitions. Keeping `request/*.ts` as pure definitions gives you three immediate benefits:

1. **Deterministic offline tests**: Unit tests can pass a local `createClient(withEndpoint(...), withHTTPHandle(...))` directly into any operation without module mocking.
2. **SSR and multi-tenant safety**: Server loaders can pass a request-scoped `Client` carrying the current user's cookies or tenant token into the exact same operation definition used by browser components.
3. **Zero-cost graduation to a shared package**: If your team later moves `src/api/schema/` and `src/api/request/` into a monorepo workspace package or public npm SDK, no operation file needs to change.

### Convention 4: Separate `builder` placement from interceptor policy

Keep each concern in its designated layer:

| Concern                                                                              | Where it belongs                                                 | Why                                                                                                                        |
| :----------------------------------------------------------------------------------- | :--------------------------------------------------------------- | :------------------------------------------------------------------------------------------------------------------------- |
| Routing caller parameters into `path`, `query`, `headers`, and `body`                | Operation `builder` in `request/*.ts`                            | Synchronous pure function of the current `input`                                                                           |
| Application-defined context for interceptors (`{ operation: "orders.create" }`)      | Operation `meta` field in `request/*.ts`                         | `{ [key: string]: unknown }`; read-only and shared per definition; never sent with the request; reported as `defjs.meta.*` |
| Base URLs, auth headers (`Authorization`, signatures, XSRF), retries, load balancing | `createClient(...)` in `client.ts`                               | Environment- and session-specific execution policy                                                                         |
| Per-call deadlines, cancellation (`signal`), and transfer progress callbacks         | Inline `client({ signal, onDownloadProgress })` at the call site | Scoped to a single invocation without mutating the shared client                                                           |
