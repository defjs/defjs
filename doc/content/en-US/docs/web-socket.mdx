# WebSocket sessions

`defineWebSocket` declares a bidirectional WebSocket contract in your SDK: the path template, optional `input` and `builder` (`path` and `query` only), `incoming` and `outgoing` message structs, queue bounds, and static subprotocols. The consuming application configures heartbeat, reconnect, and lifecycle cleanup on its client.

## 2. Message validation and direction rules

- **Incoming frames (`session.receive`)**: Text, `ArrayBuffer`, typed arrays, and `Blob` frames are decoded as UTF-8, parsed as JSON, and validated against `incoming`. Malformed JSON or schema mismatches are reported to `session.onRuntimeError` and dropped without closing the session. `session.receive` is single-consumer; requesting a second iterator throws `TypeError`.
- **Outgoing frames (`session.send(payload)`)**: Synchronously validates against `outgoing`, applies `.alias()` and codecs, and serializes with `JSON.stringify`. Sends immediately in the `open` state, queues during `reconnecting` (if `maxOutgoingQueueSize > 0`), and throws synchronously if the payload is invalid, the queue is full/disabled, or the session is closed.

## 3. Session state and observers

| Member               | Description                                                                                           |
| -------------------- | ----------------------------------------------------------------------------------------------------- |
| `state`              | `'idle' \| 'connecting' \| 'open' \| 'reconnecting' \| 'closing' \| 'closed' \| 'aborted' \| 'error'` |
| `connection`         | Live snapshot of the latest physical socket (`generation`, `url`, `protocol`, `extensions`)           |
| `bufferedAmount`     | Unsent byte count on the active physical socket (`0` when disconnected)                               |
| `receive`            | Single-consumer async iterable of validated `incoming` messages                                       |
| `onStateChange(fn)`  | Subscribes to state transitions; returns an `unsubscribe` function                                    |
| `onRuntimeError(fn)` | Subscribes to non-startup frame/parse errors; returns an `unsubscribe` function                       |
| `closed`             | Promise resolving to the terminal outcome (`kind: 'closed' \| 'aborted' \| 'error'`)                  |

## 4. Reconnect, heartbeat, and queues

- **Reconnect**: When enabled, the defaults are `attempts: 3`, `delayMs: 1000`, `factor: 2`, `maxDelayMs: 30000`, `jitter: 0`. Each physical `open` resets the outage budget. `beforeConnect({ attempt, signal })` runs before the initial connect and every reconnect attempt. The balancer attribution of an opened socket depends on the close code only, whatever `wasClean` reports: `1006` or `1015` (no close frame arrived) is `NET_UNREACHABLE`, `1012` or `1013` is `NET_UNAVAILABLE`, and every other code is not a failure.
- **Handshake timeout (`connectTimeoutMs`)**: When provided, it must be finite, positive, and no greater than 2147483647 (the timer limit); otherwise the operation returns `REQ_OPTIONS_INVALID`. It bounds construction to `open` and is cleared after the handshake. The option exists only inside the `withWebSocketReconnect({...})` options object (or the `reconnect` request option). Passing that object enables automatic reconnect with the default `attempts: 3`, so `connectTimeoutMs` alone also reconnects; add `attempts: 0` for a handshake-only deadline.
- **Heartbeat**: Periodically sends `message()` through the `outgoing` struct and waits up to `timeoutMs` for a frame matching `isAck(msg)`. Matching ack frames are consumed by the heartbeat monitor and not forwarded to `session.receive`. A missed ack is fatal to the logical session: `closed.kind` is `"error"` and `closed.cause` is the ordinary `Error("WebSocket heartbeat timeout")`; it does not start reconnect. The missed ack is also reported to the balancer as `NET_UNREACHABLE` for the endpoint. Heartbeat serialization failures, or a throwing `message()`, follow the same fatal path with their original cause but are local and not attributed to the endpoint.
- **Queue bounds**:
  - `maxIncomingQueueSize` (required positive safe integer): Bounds both raw frames waiting to decode and decoded messages waiting for the consumer. Overflow terminates the session with a `CAP_QUEUE_OVERFLOW` Fault as `closed.cause`; the same cause is sent to `onRuntimeError` and rejects `session.receive`. Keep consuming `session.receive` while the session is open.
  - `maxOutgoingQueueSize` (optional non-negative safe integer, default `0`): Buffers `session.send()` calls only while `state === 'reconnecting'` and flushes them before publishing the next `open`.

`shouldReconnect` receives the native close code and `wasClean`. A server can complete a clean close handshake with application-error code `1011`, so `wasClean === true` does not mean the application succeeded. The example explicitly permits `1011`; choose application codes according to your protocol rather than relying on `!wasClean` alone.

## 5. Subprotocols and authentication [#protocols-and-authentication]

Browser WebSockets do not support arbitrary handshake headers, so WebSocket `builder` functions return only `{ path?, query? }`.

- **Subprotocol precedence**: `client({ protocols })` overrides `withWebSocketProtocols(...)`, which overrides `defineWebSocket({ protocols })`.
- **URL conversion**: Defjs automatically converts `http:` → `ws:` and `https:` → `wss:` on the resolved endpoint.
- **Credentials**: `withCredentials(true)` applies to Fetch (HTTP/SSE) only. Authenticate WebSockets using cookies/session policies, subprotocols, or short-lived connection tickets—avoid placing long-lived secrets in query strings.
- **`beforeConnect` is not a request mutator**: Input parsing, the synchronous pure `builder`, and the interceptor chain run once per operation. For a request whose base endpoint is not replaced by an interceptor, each reconnect re-picks an endpoint and reconstructs the URL with that endpoint but reuses the built path/query and the captured protocol list. The URL is fixed before that attempt's `beforeConnect` runs, both on the same endpoint and after failover. Changing a closure variable, input, or protocol array in the hook cannot supply a fresh ticket to the current handshake. Rotating a URL/subprotocol credential within one session is unsupported; obtain the new credential first, pass it as input or client configuration to a new operation, then own that replacement session's cleanup.

## 6. Closure and ownership

Call `session.close(code?, reason?)` (where `code` is `1000` or `3000..4999` and `reason` is ≤ 123 UTF-8 bytes) and `await session.closed`, or use `await using`:

When a reconnect outage exhausts its attempts, the session ends with `closed.kind: "error"` and the ordinary transport error as `closed.cause`, alongside the native close snapshot (often code `1006` for a failed upgrade); it does not expose a separate stable exhaustion code. Always unsubscribe `onStateChange` and `onRuntimeError` listeners when your component or worker finishes.
