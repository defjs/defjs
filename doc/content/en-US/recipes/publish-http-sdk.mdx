# Build and publish an SDK [#publish-an-http-sdk-without-hiding-execute]

A Defjs SDK organizes shared `struct` schemas (`src/schema/`) and domain operation modules (`src/request/`) into a tree-shakable npm package while leaving `createClient(...)`, endpoints, credentials, and interceptors in the consuming application.

Unlike legacy OpenAPI generators that wrap endpoints in stateful `Service` classes (`ObjectsService.putObject(...)`), a Defjs SDK exports **standalone pure operation functions** (`putObject`, `getObject`, `listObjectsV2`) that are called directly with the application's client.

---

## 1. Structure and define the SDK package

Using an Amazon S3-compatible object storage SDK (`@company/s3-sdk`) as an example, split the package into two layers:

- **`src/schema/`**: Shared `struct` schemas and `Infer<typeof ...>` TypeScript types (using same-name value + type exports so consumers can import a single identifier for both runtime schemas and static types).
- **`src/request/`**: Domain modules grouped by resource (`buckets.ts`, `objects.ts`). Each module exports standalone `defineRequest` functions whose synchronous `builder` routes a flat caller input across `path`, `query`, `headers`, and binary `body`.

- **Pure functions, never `Service` classes**: Every operation (`listBuckets`, `listObjectsV2`, `getObject`, `putObject`, `deleteObject`) is exported as an independent `defineRequest` value. Do not wrap them in a `class` or a namespace object—standalone functions keep the calling convention identical to `@defjs/core` (`await putObject(client, input)`) and let bundlers tree-shake unused endpoints when `"sideEffects": false` is set.
- **Empty vs binary vs structured responses**: `listBuckets` and `listObjectsV2` decode JSON structs with `.alias()` wire mappings; `getObject` decodes a binary `Blob` (`output: struct.blob()`); `putObject`, `headObject`, and `deleteObject` omit `output` for empty response bodies while still exposing `response.headers` (such as `etag`) in the third tuple slot.
- **External runtime peer**: `@defjs/core` stays a `peerDependency` shared with the consuming application.

## 2. Build and verify the tarball

Bundle `dist/index.js` and `dist/index.d.ts` with `tsdown`, then inspect the package contents before publishing:

```sh
bun install
bun run build
bun pm pack --dry-run
bun pm pack
```

Verify that `dist/index.js` and `dist/index.d.ts` are included in the tarball.

---

## 3. Consume the SDK in an application

Install your SDK alongside `@defjs/core`:

```sh
bun add @company/s3-sdk @defjs/core@^0.8.0
```

Because the SDK binds no client, the consuming application owns the endpoint (AWS S3, Cloudflare R2, or MinIO), signing interceptor, and retry policy, and calls each imported operation directly as a pure function. Because `syncReport` makes three calls, it names each error after its step (`putErr`, `listErr`, `getErr`) and returns an error-first tuple whose error wraps the step that failed, like Go's `fmt.Errorf("put object: %w", err)`. ## 4. Test and publish

Exercise your exported definitions with [in-memory handle tests](/recipes/test-with-handle) covering path/query/header/binary-body mapping, `output` decoding, `ETag` response headers, declared `HTTP_STATUS` (`S3Error`) faults, and cancellation. Once verified, publish the package:

```sh
bun publish --access public
```

See [HTTP operations](/docs/http), [Client](/docs/client), [Testing](/docs/testing), and [Core architecture](/docs/design-decisions).
