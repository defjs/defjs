# Consume an SSE stream

Each `EventStreamHandle` exposes a single async iterator. Always place `stream.close(...)` and `await stream.closed` inside a `finally` block so early `break` or `return` statements never leak the underlying Fetch stream:

<Tabs items={["sdk/deployments.ts", "app/main.ts", "deploy-events.ts"]}>
  <Tab value="sdk/deployments.ts">
```ts
import { defineEventStream, struct } from "@defjs/core";

export const deployEvents = defineEventStream({
  path: "/deployments/events",
  events: {
    line: struct.object({ text: struct.string() }),
  },
});
```
  </Tab>
  <Tab value="app/main.ts">
```ts
import { createClient, withEndpoint } from "@defjs/core";
import { deployEvents } from "../sdk/deployments.ts";

const client = createClient(withEndpoint("https://api.example.com"));

async function main() {
const [error, stream] = await deployEvents(client);
if (error) {
console.error(error.code);
return;
}
try {
for await (const event of stream) {
if (event.event === "line") {
console.log(event.data.text);
break;
}
}
} finally {
stream.close("consumer-finished");
await stream.closed;
}
}

void main();

````
  </Tab>

With a server whose first event is `line` with data `{ "text": "build started" }`, the script prints:

```txt
build started
````

- SSE does not automatically reconnect on network or read failures unless you configure [`withSSEReconnect(...)`](/api/core/withssereconnect) on the client.
- When `withSSEReconnect` is enabled with an options object, `attempts` defaults to `3` per outage and resets on a successful handshake (`attempts: 0` disables reconnect). Without a custom `shouldReconnect`, only `GET`, `HEAD`, `OPTIONS`, `PUT`, and `DELETE` requests with replayable bodies reconnect. See [SSE event streams](/docs/sse).
