# Consume an SSE stream

One async iterator per stream. Put `close` + `await stream.closed` in `finally` so early exits don’t leak the Fetch attempt.

See [SSE](/docs/sse) for details.

<include cwd meta="notifications.ts">

</include>

`api.example.com` is a placeholder. With a server whose first event is `message` with the data `{ "text": "hello from the server" }`, the snippet prints:

```txt
hello from the server
```

SSE does not retry network/read failures unless you enable `withSSEReconnect(...)`. With a reconnect object, `attempts` defaults to `3`; `attempts: 0` disables retry. Without `shouldReconnect`, only `GET`, `HEAD`, `OPTIONS`, `PUT`, and `DELETE` requests reconnect, and a `ReadableStream` request body never does.
