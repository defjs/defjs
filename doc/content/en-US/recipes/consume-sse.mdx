# Consume an SSE stream

Each `EventStreamHandle` exposes a single async iterator. Always place `stream.close(...)` and `await stream.closed` inside a `finally` block so early `break` or `return` statements never leak the underlying Fetch stream:

With a server whose first event is `line` with data `{ "text": "build started" }`, the script prints:

```txt
build started
```

- SSE does not automatically reconnect on network or read failures unless you configure [`withSSEReconnect(...)`](/api/core/withssereconnect) on the client.
- When `withSSEReconnect(...)` is set, `attempts` defaults to `3` per outage and resets on a successful handshake (`attempts: 0` disables reconnect). Without a custom `shouldReconnect`, only `GET`, `HEAD`, `OPTIONS`, `PUT`, and `DELETE` requests reconnect. A request with a `ReadableStream` body never reconnects. See [SSE event streams](/docs/sse).
