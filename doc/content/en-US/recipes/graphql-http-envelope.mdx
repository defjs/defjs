# Unwrap a GraphQL HTTP envelope

Defjs does not embed a GraphQL client or `errorPolicy`. Model GraphQL over HTTP as a standard `POST` operation whose `builder` sends `{ query, operationName, variables }`. Mark `data` as `.nullish()` on the envelope Struct so both omitted `data` and `data: null` pass structural validation, then unwrap `errors[]` in an application helper:

<Tabs items={["sdk/viewer.ts", "app/load-viewer.ts", "graphql-viewer.ts"]}>
  <Tab value="sdk/viewer.ts">
```ts
import { defineRequest, struct } from "@defjs/core";

const VIEWER_QUERY = "query Viewer { viewer { id login } }" as const;

export const runViewer = defineRequest({
  method: "POST",
  path: "/graphql",
  builder: () => ({
    body: { query: VIEWER_QUERY, operationName: "Viewer" },
  }),
  output: struct.object({
    data: struct
      .object({
        viewer: struct
          .object({ id: struct.string(), login: struct.string() })
          .null(),
      })
      .nullish(),
    errors: struct
      .array(struct.object({ message: struct.string() }))
      .optional(),
  }),
});
```
  </Tab>
  <Tab value="app/load-viewer.ts">
```ts
import type { Client } from "@defjs/core";
import { runViewer } from "../sdk/viewer.ts";

export async function loadViewer(client: Client) {
  const [error, result] = await runViewer(client);
  if (error) throw error;
  if (result.errors?.length) {
    throw new Error(result.errors.map((item) => item.message).join("; "));
  }
  if (!result.data) {
    throw new Error("GraphQL response contained neither data nor errors");
  }
  return result.data.viewer;
}
```

- An HTTP `200` only means the GraphQL envelope arrived intact. Domain errors inside `errors[]` (even when accompanied by `data: null`) are application-level results rather than `RES_STRUCT_MISMATCH` faults.
- See [Core architecture](/docs/design-decisions) for why protocol-specific envelopes stay in userland helpers.
