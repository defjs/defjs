# React

把既有的 `@defjs/core` client 提供給 React 樹。這個套件不會建立、快取或處置 client。它的入口標記了 `'use client'`，所以請從 client component 匯入。需要 React 18 或更新版本。

見 [React 指南](/zh-Hant-TW/docs/integrations/react)。

## ClientProvider

<ApiSignature name="ClientProvider" />

Context provider。傳入 `createClient` 回傳的 `DerivableClient`。巢狀的 `ClientProvider` 會覆蓋其子樹的 client；`useClient()` 讀最近的那一個。傳入不同的 `client`，會改變後代拿到的 context 值。

## useClient()

<ApiSignature name="useClient" />

`useClient(overrideClient)` 優先使用明確傳入的 client；省略參數或傳入 `undefined` 時，則讀取最近的 `ClientProvider`。只有兩種來源都沒有提供 client 時才會拋出 `Error`。不帶參數的 `useClient()` 呼叫依然有效。請把該 client 傳進操作。此 hook 回傳的是所提供的 [`DerivableClient`](/zh-Hant-TW/api/core/derivableclient-type)；在操作執行處以 request options 呼叫它，即可衍生出 `Client` 值。不要把它傳給 state setter，因為 `setState(client)` 會把它當成 updater 呼叫。衍生出的 `Client` 值不被 `ClientProvider` 或 `useClient` 接受。

即使傳入明確的 client，也一律在元件或自訂 Hook 的頂層呼叫 `useClient(explicitClient)`，不要在一般函式或事件回呼中呼叫。不要寫 `explicitClient ?? useClient()`，那會條件式呼叫 Hook。覆寫不會寫入 Context，也不會建立 provider；Hook 仍會訂閱 Context。

- **回傳** 明確傳入的 client，或最近一個 provider 提供的同一個 client。
- **拋出** 明確參數與 Context 都沒有提供 client 時，拋出 `Error`。

## ClientProviderProps

<ApiSignature name="ClientProviderProps" />

`client` 必填，且由應用程式擁有。`children` 為選用：它是可以呼叫 `useClient` 的樹。
