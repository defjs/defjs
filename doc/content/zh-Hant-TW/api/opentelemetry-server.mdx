# OpenTelemetry server

中介層外掛：以 core 攔截器為出站 HTTP／SSE／WebSocket 提供遙測。這個套件不會初始化 OpenTelemetry SDK，也不是入站的伺服器遙測。

見 [OpenTelemetry server 指南](/zh-Hant-TW/docs/integrations/opentelemetry-server)。

## withOpenTelemetryServer()

<ApiSignature name="withOpenTelemetryServer" />

為每個啟用的傳輸各附加一個攔截器，順序為 HTTP、SSE、WebSocket。請在 `createClient` 時套用。`options` 必填；傳入 `{}` 只會安裝帶有脈絡傳播的攔截器。

<include cwd>examples/api/with-opentelemetry-server.ts#example</include>

`tracer`、`meter` 與 `logger` 都是選用的。沒有 `propagator` 時 → W3C Trace Context + Baggage。

省略 `tracer` 時，外掛不建立本機 span、不呼叫 `trace.getTracer(...)`，並跳過 `startSpanHook`、`requestHook` 與 `responseHook`。傳入的 `meter` 與 `logger` 可獨立運作。脈絡傳播仍會轉發擷取到的父脈絡；WebSocket 的 `queryPropagation` 預設仍為 `false`。有 tracer 時，`requireParentSpan: true` 會在沒有進行中的父 span 時跳過所有遙測，包含日誌；沒有 tracer 時，它既不會阻擋 metrics，也不會阻擋日誌。

HTTP、SSE 與 WebSocket 預設全部啟用。對某個傳輸傳入 `{ enabled: false }` 就會跳過它。

## OpenTelemetryServerOptions

<ApiSignature name="OpenTelemetryServerOptions" />

| 欄位                | 預設值                      | 效果                                                                             |
| ------------------- | --------------------------- | -------------------------------------------------------------------------------- |
| `tracer`            | 無                          | 沒有它就沒有本地 span，也沒有 span hooks。                                       |
| `meter`             | 無                          | 沒有它就不記錄這個套件的 metrics。                                               |
| `logger`            | 無                          | 來自 `@opentelemetry/api-logs` 的 `Logger`。沒有它就不會發出診斷 LogRecord。     |
| `propagator`        | W3C Trace Context + Baggage | 擷取父 context，並注入外送的 context。                                           |
| `requireParentSpan` | `false`                     | 有 `tracer` 時，在沒有進行中父 span 的情況下跳過遙測。沒有 `tracer` 時會被忽略。 |
| `http`              | `{}`                        | HTTP 傳輸選項。                                                                  |
| `sse`               | `{}`                        | SSE 傳輸選項。                                                                   |
| `webSocket`         | `{}`                        | WebSocket 傳輸選項。                                                             |

`enabled` 預設為 `true`；只有 `enabled: false` 才會關閉某個傳輸。舊的布林開關（`http: false`）與頂層鉤子只會被 TypeScript 型別拒絕，沒有執行期檢查，所以執行時 `http: false` 會讓該傳輸維持啟用，頂層鉤子則會被悄悄忽略。

span 鉤子只有在傳入 `tracer` 時才會執行。`startSpanHook` 會在對應的 HTTP、SSE 或 WebSocket 傳輸建立 span 前同步執行。它回傳的 attributes 會在內建 attributes 之後套用，因此應用程式可以覆寫 `url.full` 或其他初始值。若它拋出例外，Defjs 會以內建 attributes 建立 span，並繼續請求；`requestHook` 與 `responseHook` 在 span 建立之後執行。兩者都不會被 await：拋出例外或 rejection 不會阻擋或導致操作失敗。

`span.isRecording()` 為 true 時，鉤子失敗會記錄 `defjs.otel.hook.error` 與 `exception` 事件。span 不再記錄（已結束或未取樣）時，失敗會透過 `diag.error` 交給 OpenTelemetry 診斷 logger。應用程式必須設定 `@opentelemetry/api` 的 `diag.setLogger(...)` 才能收到；預設不會自動輸出。本套件不初始化 SDK，這類診斷也不是獨立的 SDK `LogRecord`。

`responseHook` 收到的是傳輸層回傳的東西：HTTP 是 `HttpResponse`，SSE 是啟動成功後的串流 handle，WebSocket 是開啟後的工作階段。它的第三個參數是原始請求。

預設的 `url.full` 只會把 `request.endpoint` 對照選用的 `request.baseEndpoint` 解析，不會附加獨立的 `request.queryString`。這條界線不是遮蔽機制；套件沒有內建的遮蔽器或敏感鍵策略。請明確建構應用程式自有的 URL，並視需要自行遮蔽：

`webSocket.queryPropagation`（僅限 WebSocket）預設為 `false`。只有在你接受把 trace context 放進 WebSocket URL 時才開啟。

## Logger 診斷

頂層的 `logger?: Logger` 選項使用 `@opentelemetry/api-logs`，不是應用程式層級的 logger。它是選用的，也可以單獨使用。Defjs 不會取得全域 logger，也不擁有它的 provider。每個請求或邏輯連線最多發出一筆 `WARN` LogRecord（severity number 13），帶有固定訊息與下列 attributes：`server.address` 與 `server.port`（已知時）、`defjs.phase`、`exception.type`，HTTP 另外還有 `http.request.method`，SSE 串流以錯誤結束時有 `defjs.sse.fault.code`，WebSocket 的關閉資訊帶有數字 code 時則有 `websocket.close.code`：

| 結果                                                   | 事件                                                              | `defjs.phase` |
| ------------------------------------------------------ | ----------------------------------------------------------------- | ------------- |
| HTTP `next()` 拒絕，不含取消與對外公開的 `HTTP_STATUS` | `http.client.request.exception`                                   | `request`     |
| SSE 或 WebSocket 連線失敗                              | `defjs.client.sse.exception` / `defjs.client.websocket.exception` | `connect`     |
| SSE 或 WebSocket 以錯誤結束，包含 `closed` 被拒絕      | 同一個傳輸事件                                                    | `connection`  |

一般狀態的回應（包含已宣告 `error` 本文可以解碼的 4xx／5xx）、成功、正常關閉、EOF 與呼叫端取消，都不會產生 LogRecord。HTTP 期限中止只有在逾時拒絕到達 OTel 攔截器的 `next()`／傳輸邊界時才會記錄一次（中止原因為 `TimeoutError` 時，例如 `AbortSignal.timeout()`，算逾時而非取消）。如果只有操作呼叫在 input 剖析、建構、`next()` 之後的應用程式攔截器工作，或鏈之後的本文轉換期間觀察到期限，就不會發出 LogRecord；請改為觀察這次操作呼叫。在 HTTP 處理常式邊界內，已宣告的 `output`／`error` 本文讀取失敗會對每種表示法記錄；媒體型別與 `JSON.parse` 失敗只會對 JSON 表示法記錄，且不論 HTTP 狀態碼為何。非 JSON 的文字、blob 與位元組不會只因為媒體型別不是 JSON 就算失敗。沒有宣告的本文根本不會被讀取，因此也不會記錄。struct 驗證、已宣告但不存在的本文（例如 204），以及後續的 `HTTP_STATUS` 轉換都發生在攔截器之後，不會記錄。非 2xx 的 SSE 交握一律記錄一次；伺服器送來的 WebSocket 關閉訊框，無論 code 為何，都不會記錄。沒有關閉訊框的突發斷線（1006）則取決於執行環境：若平台 WebSocket 在 `close` 之前先觸發 `error`，工作階段會以錯誤結束並記錄一次；若不會（Bun），則視為正常關閉，不會記錄。

`exception.type` 是攔截器實際觀察到的東西的類別名稱，不是 Defjs 的錯誤碼：例如 `BodyFailure`（HTTP 本文）、`EventStreamFatalError`（SSE 交握因非 2xx 狀態以外的原因失敗，例如回應不是 `text/event-stream`）、`DefjsFault`（WebSocket 啟動，以及回傳非 2xx 狀態的 SSE 交握）、`TypeError`（網路失敗）或 `Error`（逾時）。過濾、exporter、flush 與 shutdown 由應用程式負責。

完整的日誌與第三方整合範例請見 [OpenTelemetry 指南](/zh-Hant-TW/docs/integrations/opentelemetry-server#logs-and-third-party-loggers)。
