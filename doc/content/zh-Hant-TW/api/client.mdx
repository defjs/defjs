# Client

`createClient(...)` 回傳 [`DerivableClient`](/zh-Hant-TW/api/core/derivableclient-type)。Options 由左到右組合，再呼叫 `client(options?)` 取得 [`Client`](/zh-Hant-TW/api/core/client-type) 值，並把它傳給操作：`getOrder(client(options), input)`。

## createClient()

<ApiSignature name="createClient" />

Options 依序套用。若 interceptors 會捕捉 auth 或 tenants，請在請求邊界內建立 client。回傳的 factory 是一個函式。呼叫它會回傳 `Client` 值，而且不會進行 I/O。factory 本身也是 `Client`，不帶任何 request options。

- **options** — 像 `withEndpoint` 這類 option helpers。
- **回傳** 可呼叫的 factory。基礎設定由每個 client 值共用，執行期不會凍結。它依慣例固定：函式庫不會改它，應用程式也不應該改。

## 選項 helpers

所有 helpers 都回傳 `ClientOption`。對同一項設定，後面的呼叫會取代前面的呼叫；唯一的例外是 `withInterceptors`，它是追加。

<ApiSignature name="withEndpoint" />

### withInterceptors()

<ApiSignature name="withInterceptors" />

依註冊順序追加 interceptors。混合的 kinds 在操作執行時依傳輸篩選。

### withQuerySerializer()

<ApiSignature name="withQuerySerializer" />

替換 HTTP、SSE、WebSocket 的 query 編碼。`serializer(query)` 收到的是**已編碼的 wire 物件**（已套用 aliases、`Date` 為 ISO、`bigint` 為字串），必須回傳不含開頭 `?` 的 query string。Request 沒有 query 時不會呼叫它。Builder 回傳 `URLSearchParams` 時會跳過它。

### withHeaders()

<ApiSignature name="withHeaders" />

為 HTTP 與 SSE request 設定靜態的預設 headers。WebSocket request 不使用它們。`headers` 會在 option 套用時複製，因此之後對該物件的修改不會影響 client。第二次呼叫 `withHeaders` 會取代第一次，不會合併。

單一 request 的優先順序：

1. 預設值是起始的 header 集合。
2. Request builder 回傳的 `headers` 會取代同名的預設值。該名稱的第一個值取代預設；同一個陣列裡後面的值只追加到這次取代之後的結果。scalar 或 `Headers` instance 也會取代。其他預設名稱保留。
3. Interceptors 收到的是合併後的 headers，並且可以修改它們。
4. 使用預設的 HTTP 傳輸時，XSRF header 最後才加入，而且只有在它仍不存在時才會加入（見 `withXSRF`）。

每個 request 都會變的值，請用 interceptor 處理，例如重新整理後的 Bearer token，或對序列化 body 計算的 HMAC。

沒有 client 層級的預設期限。某一次呼叫需要期限時，在衍生的 client 上傳 `signal: AbortSignal.timeout(ms)`。手動取消是 `NET_ABORTED`。`AbortSignal.timeout` 歸類為 `NET_TIMEOUT`。

### withCredentials()

<ApiSignature name="withCredentials" />

### withXSRF()

<ApiSignature name="withXSRF" />

在 HTTP request 加上 XSRF token header。`options` 就是 `xsrf` 設定，形狀與 [`ClientOptions`](/zh-Hant-TW/api/core/clientoptions-type) 上的 `xsrf` 相同：`cookieName`（預設 `XSRF-TOKEN`）、`headerName`（預設 `X-XSRF-TOKEN`）與 `tokenProvider({ request })`。不帶參數呼叫 `withXSRF()` 會啟用這些預設值。SSE 與 WebSocket request 不受影響。

預設的 HTTP 傳輸在下列條件全部成立時才會加上該 header：method 不是 `GET`、`HEAD`、`OPTIONS` 或 `TRACE`；request 尚未帶有該 header；request 是同源的；而且找得到非空的 token。只要 `location` 存在，包含 Worker，解析後的 request origin 就必須與 `location.origin` 相符；沒有它時，帶有 `baseEndpoint` 的 request 算作同源。跨來源的 request 不會呼叫 `tokenProvider`。有提供該 provider 時，token 來自它，否則來自 `document.cookie`，且只會在 `document` 存在時讀取。

## 型別

### DerivableClient

<ApiSignature name="DerivableClient" />

`createClient` 回傳的根 client，有兩種形態。factory 是一個函式，同時也是不帶 request options 的 `Client`，所以 `getOrder(client, input)` 可直接使用。帶著 [`RequestOptions`](/zh-Hant-TW/api/core/requestoptions-type) 呼叫它，會回傳供單次呼叫使用的一般 `Client` 值。該值不可呼叫，因此 `client()()` 無法編譯，執行期會拋出 `TypeError`。衍生只發生一次，從 factory 開始，沒有鏈式呼叫。請把型別寫成 `DerivableClient`，而不是 `ReturnType<typeof createClient>`。

### Client

<ApiSignature name="Client" />

`Client` 是一個值，不是函式。以 [`RequestOptions`](/zh-Hant-TW/api/core/requestoptions-type) 呼叫 [`DerivableClient`](/zh-Hant-TW/api/core/derivableclient-type) 會回傳一個。`client()` 與 `client(undefined)` 不存放 request options。`client({})` 保留一份空快照。這次呼叫把每個頂層欄位讀一次。`protocols` 陣列會被複製。`heartbeat` 與 `reconnect` 複製各自的已知欄位。缺失的巢狀區塊仍然缺失。`signal`、`beforeConnect` 與 callback 保持原身份。被捕獲欄位上的 getter 在這次呼叫期間執行；如果它拋錯，例外會離開這次呼叫。無效數字仍會稍後以 `REQ_OPTIONS_INVALID` 失敗。衍生不會進行 I/O。Client 值不可呼叫，呼叫它會在編譯時失敗，並在執行期拋出 `TypeError`。請為每次呼叫建立一個 client 值。同一個值可以傳給許多操作，但重複使用帶有 `signal` 的值會共用該 signal。`signal` 不會合併；在應用程式碼裡用 `AbortSignal.any` 組合 signals。Factory 的基礎設定仍然共用，也不會凍結。標準 `with*` helper 在套用時複製它們擁有的固定 record。

不要把 factory 傳給 React 的 state setter（`setState(factory)` 會把它當成 updater 呼叫），也不要把它當成 Vue 的 `watch` 或 `computed` 來源（那些會呼叫函式）。

### RequestOptions

<ApiSignature name="RequestOptions" />

七個扁平欄位。每種協定只讀自己看得懂的欄位，其餘忽略。把 `heartbeat` 傳給 HTTP 會被忽略，不是 fault。`client(options)` 在這次呼叫複製 `protocols` 陣列，以及 `heartbeat` 與 `reconnect` 的已知欄位。缺失的巢狀區塊仍然缺失。`signal`、`beforeConnect` 與 callback 保持原身份。SSE 只從請求 options 讀取 `signal`。SSE 重連來自 client 設定（`withSSEReconnect`），所以 `client({ reconnect })` 只影響 WebSocket。沒有編譯期的協定篩選，也沒有 `timeout` 或 `abort` 欄位。

| 欄位                 | 協定                   | 替換方式                                                          |
| -------------------- | ---------------------- | ----------------------------------------------------------------- |
| `signal`             | HTTP、SSE 與 WebSocket | 取消該次呼叫。對 SSE 與 WebSocket，它涵蓋整條連線，包含開啟之後。 |
| `onUploadProgress`   | HTTP                   | 其他協定會忽略。                                                  |
| `onDownloadProgress` | HTTP                   | 其他協定會忽略。                                                  |
| `beforeConnect`      | WebSocket              | 在該次呼叫取代 client 的設定。                                    |
| `protocols`          | WebSocket              | 取代 client 的清單。                                              |
| `heartbeat`          | WebSocket              | 整份替換。`timeoutMs` 是確認等待，不是請求期限。                  |
| `reconnect`          | WebSocket              | 整份替換。                                                        |

[`HttpExecuteOptions`](/zh-Hant-TW/api/core/httpexecuteoptions-type) 是 HTTP 切片（`signal` 加上進度）。[`EventStreamExecuteOptions`](/zh-Hant-TW/api/core/eventstreamexecuteoptions-type) 是 `{ signal? }`。[`WebSocketExecuteOptions`](/zh-Hant-TW/api/core/websocketexecuteoptions-type) 是 WebSocket 切片再加上 `signal`。

### FetchHandle

<ApiSignature name="FetchHandle" />

Defjs 對 Fetch 實作所需的呼叫簽章。它不是 `typeof fetch`，因此 mock 不需要 `preconnect` 這類宿主額外成員。預設的 HTTP／SSE handle 會在每次呼叫時解析 `globalThis.fetch`。HTTP 只對未被替換的平台 Fetch 使用 `(url, init)`；被替換的全域 Fetch 與自訂 handle 會收到 `Request`。SSE 一律傳入 `Request`。沒有 Fetch 也可以匯入 Core；若預設執行時 Fetch 仍然缺少，會回報 `ENV_UNSUPPORTED`，自訂 handle 則仍然可用。

### ClientSSEOptions

### ClientWebSocketOptions

<ApiSignature name="ClientSSEOptions, ClientWebSocketOptions" />

兩種傳輸的重新連線都需要主動啟用：沒有 `withSSEReconnect`／`withWebSocketReconnect` 就不會重試。一旦設定了 `reconnect`，就套用以下預設值：

| 欄位         | SSE            | WebSocket      |
| ------------ | -------------- | -------------- |
| `attempts`   | `3` 每一次中斷 | `3` 每一次中斷 |
| `delayMs`    | `1000`         | `1000`         |
| `factor`     | `1`            | `2`            |
| `jitter`     | `0`            | `0`            |
| `maxDelayMs` | 無上限         | `30000`        |

兩種傳輸在握手成功後，都會重設每一次中斷的重試額度、回呼的 attempt，以及 backoff 指數。`attempts: 0` 停用重試；省略 `attempts` 並不會在同一次中斷內給予無限次重試。`maxDelayMs` 會在 jitter 與捨入之後，為最終延遲加上上限；平台計時器上限 `2_147_483_647` ms 同樣適用，包含 SSE 沒有設定上限的情況。base 為零時維持零；有效數值溢位時會飽和在這些上限。

重新連線選項會在傳輸之前驗證：`attempts` 必須是非負安全整數；`delayMs` 必須是非負有限數；`maxDelayMs` 可以是非負有限數或正 `Infinity`，後者移除設定上限，但最終等待仍不超過 `2_147_483_647` ms；`factor` 必須有限且為正；`jitter` 必須有限且在 0–1 之內。無效值會回傳 `REQ_OPTIONS_INVALID`。WebSocket 的 `attempts: 0` 停用後續重試，但所有明確提供的重連欄位仍會在首次連線前驗證，與 SSE 一樣。Jitter 會在套用最終上限之前，把已加上限的 base 往正負兩個方向縮放。

對 SSE 而言，`delayMs` 只是起始的 base delay：只含數字的伺服器 `retry:` field 會取代它，用於之後的嘗試，包含恢復之後。`shouldReconnect` 回傳 `false` 就停止重試。SSE 的回呼另外會收到 `lastEventId`、請求的 `method` 與最新的 `open` 資訊，也可以採用非同步形式。未提供此回呼時，SSE 只會對 `GET`、`HEAD`、`OPTIONS`、`PUT` 與 `DELETE` 請求重新連線；提供後，所有請求方法是否重新連線都由它的回傳值決定。最新的事件 ID 會以 UTF-8 位元組放進 `Last-Event-ID` 送出；空的 ID 會清除它，含有 NUL 的 ID 則會被忽略。WebSocket 的回呼則會收到關閉時的 `code`、`reason` 與 `wasClean`。

SSE 的 `onInvalidEvent` 會處理兩種事件：沒有對應 struct 的事件，包括連 `default` 也沒有的情況（`missing-struct`），以及資料未通過其 struct 驗證的事件（`validation-failed`）。這類事件一律會被丟棄；handler 的回傳值會被忽略，它丟出的錯誤也不會關閉 stream。

對 WebSocket 來說，`beforeConnect`、`heartbeat`、`protocols` 與 `reconnect` 也可以在衍生的 client 上傳入；每一項都會在該次呼叫整份取代 client 的值。`heartbeat.message` 負責建立每一次 ping；省略它或它回傳 `undefined` 時，不會送出任何東西。`heartbeat.timeoutMs` 等待確認。它不是請求期限。

### ClientOptions

<ApiSignature name="ClientOptions" />

簽名裡出現的欄位是 `sse` 與 `webSocket`。另外七個——`endpoint`、`headers`、`http`、`interceptors`、`querySerializer`、`xsrf` 與 `withCredentials`——繼承自未匯出的 HTTP 基底型別，其中 `endpoint` 必填。沒有 client 層級的 `timeout`。`createClient` 不接收這個物件，而是接收 option helpers。

### ClientConfig

解析後的快照，由 option helpers 修改、由操作讀取：套用預設值之後的 `ClientOptions`，其中 `http.handle`、`interceptors`、`sse`（一個 `ClientSSEConfig`）與 `webSocket` 一定存在。

### ClientSSEConfig

<ApiSignature name="ClientSSEConfig" />

`ClientConfig.sse` 上解析好的 SSE config：`handle` 為必填的 `ClientSSEOptions`。

### WebSocketHandle

傳輸層使用的 WebSocket 實例面：不含 `binaryType`、ready-state 常數、`dispatchEvent` 與 `on*` handler 屬性的 `WebSocket`，並帶有唯讀的 `readyState: number`。
