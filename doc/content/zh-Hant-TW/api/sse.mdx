# SSE

宣告事件串流，帶著 client 呼叫操作，迭代事件，然後關閉。

## defineEventStream()

<ApiSignature name="defineEventStream" />

- **definition** — `path` 與 `events` 對照表；選用的 `method`（預設 `'GET'`）、`operation`、`input`、`error` 與 `maxBufferSize`（預設 `64 * 1024`）。只要宣告了 `input`，就必須提供明確的 `builder`。`input` 只宣告參數，每個值放在哪裡全由 builder 決定。只有未宣告 `input` 的定義可以省略 `builder`。這些 `definition` 成員的文件位於 [`EventStreamDefinition`](/zh-Hant-TW/api/core/eventstreamdefinition-type)。只有提供 error struct 型別時，`error` 才必填；`builder` 恰好在宣告 `input` 時必填。
- **回傳** 一個操作。第一個引數是 [`Client`](/zh-Hant-TW/api/core/client-type)。其餘引數只有 input。呼叫它就會啟動串流。

<include cwd>examples/api/define-event-stream.ts#example</include>

呼叫會回傳 `[null, stream, open]` 或 `[error, undefined, open?]`。有宣告 `error` 時，fault 是該 struct 的 `Fault`；否則為 `Fault<undefined>`。`signal` 請從 [`RequestOptions`](/zh-Hant-TW/api/core/requestoptions-type) 衍生 client 來傳。SSE 只讀 `signal` 與 `retry`，並忽略進度與 WebSocket 欄位。

## EventStreamExecuteOptions

<ApiSignature name="EventStreamExecuteOptions" />

`EventStreamExecuteOptions` 是 `{ signal?, retry? }`。沒有 `timeout` 或 `abort` 欄位，也沒有進度回呼。`signal` 涵蓋整條串流，包括開啟之後。期限是 `AbortSignal.timeout(ms)`，歸類為 `NET_TIMEOUT`。手動中止歸類為 `NET_ABORTED`。沒有 client 層級的預設期限。只限制交握的期限是 `withRetry({ maxRetries: 0, attemptTimeoutMs })`，單次呼叫則是 `retry: { maxRetries: 0, attemptTimeoutMs }`；它在回應標頭處結束。

## EventStreamHandle

<ApiSignature name="EventStreamHandle" />

tuple 第三項是 `open` 的啟動快照；重連之後，`stream.open` 會跟著最新的連線。只有原生 Defjs handle，或直接轉發同一個即時 `open` 物件的 wrapper，第三項才保證是該連線首次成功交握的快照；自訂 handle 或覆寫 `open` 的 wrapper 會保留它目前公開的 `open`，即使重連之後也一樣。因此共用的 `closed` 無法繞過 URL 清理或標頭過濾，Defjs 也不會從任意中繼資料轉換反推首次交握。自有作用域請優先用 `await using stream = handle` 清理。disposer 會停止 Defjs 的讀取與重連工作，並等待 reader lock 釋放；但它不保證由 provider 控制、卡住的 `ReadableStream.cancel()` promise 一定會完成。手動 `close()`／`closed` 仍可使用。

### EventStreamCloseInfo

<ApiSignature name="EventStreamCloseInfo" />

`kind` 是 `eof`、`aborted` 或 `error`。每個變體都可以帶 `reason` 與 `cause`。只有 `error` 有 `code`，取自 [`EventStreamFaultCode`](/zh-Hant-TW/api/core/eventstreamfaultcode-type)：`'CAP_BUFFER_EXCEEDED' | 'EXT_HOOK_FAILED' | 'EXT_OBSERVER_FAILED' | 'HTTP_STATUS' | 'NET_TIMEOUT' | 'NET_UNREACHABLE' | 'REQ_BUILD_FAILED' | 'RES_MEDIA_TYPE_INVALID'`。`REQ_BUILD_FAILED` 表示串流已開啟後，重連時的端點選取失敗。`EXT_HOOK_FAILED` 表示 `shouldRetry` 函式拋出例外，`cause` 包住拋出的值。`HTTP_STATUS` 表示重連交握以未重試的非 2xx 狀態結束，或重試已用盡。佇列滿了不是錯誤：函式庫最多保留 1024 個未讀事件，讀取回應會暫停，直到消費端取走一個。`close()`、釋放，以及呼叫端 `signal` 的中止，會丟棄還沒有人讀過的事件，並立刻結束迭代器，不論串流是否已經結束；以 `error` 結束之後，一旦沒有未讀事件，迭代器仍會以 `cause` 拒絕。沒有這種停止時，`error` 結束之後已經排入佇列的事件仍會先送出，然後迭代器才拒絕。

## EventStructs

<ApiSignature name="EventStructs" />

鍵是 SSE 事件名稱；沒有 `event:` 欄位的訊息，名稱是 `message`。沒有鍵相符時，會使用 `default` struct。`string` 事件 struct 會保留原始的 `data` 文字。其他種類都是 JSON 文字：先 `JSON.parse`，再交給 struct。因此單獨的 `struct.literal` 需要 JSON 文字，而不是未加引號的 token。交握 `error` 本文與 HTTP 採用同一套種類規則：`string` 是文字，`blob`／`file` 是 blob，`arrayBuffer` 是位元組，其餘都是 JSON。

重試設定在 client 上（`withRetry`），請求選項 `retry` 會為單次呼叫替換該策略。同一套策略也服務 HTTP 與 WebSocket。

每次交握成功後都會重設重試次數與 backoff 指數；它們以每次中斷為單位，因此即使設定 `maxRetries: 1`，長時間的工作階段仍可能建立多次連線。伺服器正常 EOF 不會重連，EOF 時未完成的事件也不會提交其 id。回傳 502、503 或 504 的交握會像連線被拒絕一樣，依相同規則（方法、`shouldRetry`、`maxRetries`、`ReadableStream` 請求本文）重試；其他任何非 2xx 交握會帶著 `retryable: false` 交給 `shouldRetry`，因此除非你的函式另有決定，否則會結束串流。重試用盡以及被拒絕的非 2xx 交握都以 `HTTP_STATUS` 結束；請查看即時的 `stream.open.response.status` 取得該狀態。預設值、決策順序與 UTF-8 的 `Last-Event-ID` 處理，見 [`withRetry`](/zh-Hant-TW/api/core/withretry)。

剖析器遵循 WHATWG 的 SSE 行與欄位規則，並且在每條實體串流開頭只移除一個前導 UTF-8 BOM。data 或 ID 值中的 U+FEFF 會保留；較晚出現、以 BOM 為前綴的欄位名稱會當成未知欄位忽略。多行 data 會以 `\n` 連接，空行會分派一個帶有 data 的事件，EOF 時未完成的事件則會被丟棄。

見 [SSE 指南](/zh-Hant-TW/docs/sse) 與 [消費 SSE 串流](/zh-Hant-TW/recipes/consume-sse)。

## EventStreamDefinition

`path`、`events`，以及選用的 `method`／`operation`／`input`／`error`／`maxBufferSize`。請求形狀與 HTTP 相同，包括 `body`。`GET` 與 `HEAD` 不能攜帶本文。只要宣告了 `input`，就必須提供明確的 `builder`。`input` 只宣告參數，每個值放在哪裡全由 builder 決定。只有未宣告 `input` 的定義可以省略 `builder`。

## EventStreamEndpoint

`defineEventStream` 的回傳值。第一個引數是 client。其餘引數只有 input。

## EventStreamRequestShape

欄位與該串流 method 及 path 的 `HttpRequestShape` 相同。

## StreamAwaitResult

`[null, stream, open]` 或 `[error, undefined, open?]`。

## EventStreamData

從 `EventStructs` 對照表推導出的解析後事件酬載。
