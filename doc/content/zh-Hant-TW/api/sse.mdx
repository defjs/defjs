# SSE

宣告事件串流，帶著 client 呼叫操作，迭代 events，然後 close。

## defineEventStream()

<ApiSignature name="defineEventStream" />

- **definition** — `path`、`events` map，以及必填的正整數上限 `maxBufferSize` 與 `maxQueueSize`；選填 `method`（預設 `'GET'`）、`operation`、`input` 與 `error`。只要宣告了 `input`，就必須明確提供 `builder`。`input` 只定義入參，每個值放在哪裡只由 builder 決定。只有沒有 `input` 的定義可以省略 `builder`。這些 `definition` 成員寫在 [`EventStreamDefinition`](/zh-Hant-TW/api/core/eventstreamdefinition-type)。只有給了 error struct 型別時 `error` 才必填，`builder` 恰好在宣告了 `input` 時才必填。
- **回傳** 操作。第一個引數是 [`Client`](/zh-Hant-TW/api/core/client-type)。其餘引數只有 input。呼叫它就會啟動串流。

<include cwd>examples/api/define-event-stream.ts#example</include>

呼叫回傳 `[null, stream, open]` 或 `[error, undefined, open?]`。宣告了 `error` 時，fault 是那個 struct 的 `Fault`；否則是 `Fault<undefined>`。`signal` 要從 [`RequestOptions`](/zh-Hant-TW/api/core/requestoptions-type) 衍生 client 來傳。SSE 只讀 `signal`，並忽略進度與 WebSocket 欄位。

## EventStreamExecuteOptions

<ApiSignature name="EventStreamExecuteOptions" />

`EventStreamExecuteOptions` 是 `{ signal? }`。沒有 `timeout` 或 `abort` 欄位，也沒有進度回呼。`signal` 涵蓋整條串流，包含開啟之後。期限是 `AbortSignal.timeout(ms)`，歸類為 `NET_TIMEOUT`。手動取消是 `NET_ABORTED`。沒有只涵蓋啟動期的期限，也沒有 client 層級的預設期限。應用程式若要只涵蓋啟動期的期限，就自己建立 `AbortController`，用計時器以 `new DOMException("...", "TimeoutError")` abort 它，並在 await 回傳後清掉計時器。

## EventStreamHandle

<ApiSignature name="EventStreamHandle" />

Tuple 第三項是 `open` 的啟動快照；重連後，`stream.open` 會跟著最新的連線。這一第三項僅對回傳的 Defjs 原生 handle 或直接傳遞同一 live `open` 物件的 wrapper 保證是所屬連線首次成功握手的快照；自訂 handle 或明確覆寫 `open` 的 wrapper 則保留其目前公開的 `open`，即使已發生重連也一樣，因此共用 `closed` 不能繞過 URL 淨化或標頭過濾，Defjs 也不從任意中繼資料轉換反推首次握手。自有作用域優先用 `await using stream = handle` 清理。Disposer 會停止 Defjs 的讀取與重連工作，並等待 reader lock 釋放；它不承諾由 provider 控制且卡住的 `ReadableStream.cancel()` promise 一定完成。手動 `close()`／`closed` 仍可使用。

```ts
async function consume(handle: EventStreamHandle<unknown>): Promise<void> {
  await using stream = handle;
  for await (const event of stream) console.log(event);
}
```

結構化實作 `EventStreamHandle` 的程式碼現在必須實作 `[Symbol.asyncDispose]()`，並回傳同一條自有 teardown 路徑。對自訂 handle 實作者而言，這是編譯期 breaking change；只接收 Defjs 回傳 handle 的程式碼不必新增執行期呼叫。

## EventStructs

<ApiSignature name="EventStructs" />

Key 是 SSE 事件名稱；沒有 `event:` 欄位的 message 名為 `message`。沒有 key 吻合時，使用 `default` struct。`string` 事件 struct 保留原始 `data` 文字。其餘 kind 都是 JSON 文字：先 `JSON.parse`，再走 struct。因此裸的 `struct.literal` 需要 JSON 文字，不是沒加引號的 token。握手 `error` body 跟 HTTP 用同一套 kind 規則：`string` 是文字，`blob`／`file` 是 blobs，`arrayBuffer` 是 bytes，其餘是 JSON。

重連放在 client 上（`withSSEReconnect`）。SSE 的 `jitter` 是 **0–1 乘性因子**，跟 WebSocket 一樣。

成功的握手會重設重試額度與 backoff 指數；它們適用於每一次中斷。無效的數值選項會在開啟 stream 之前回傳 `REQ_OPTIONS_INVALID`，而 `maxDelayMs` 會在 jitter 之後為最終延遲加上上限。驗證規則、預設值，以及 UTF-8 的 `Last-Event-ID` 處理，見 [`withSSEReconnect`](/zh-Hant-TW/api/core/withssereconnect)。

剖析器遵循 WHATWG SSE 的行與欄位規則，並且在每條實體 stream 開頭只移除一個前導 UTF-8 BOM。data 或 ID 值中的 U+FEFF 會保留；較晚出現、以 BOM 為前綴的欄位名稱會當作未知欄位而忽略。多行 data 以 `\n` 連接，空白行會派送一個帶有 data 的事件，EOF 時尚未完成的事件則會丟棄。

見 [SSE 指南](/zh-Hant-TW/docs/sse) 與 [消費 SSE 串流](/zh-Hant-TW/recipes/consume-sse)。

## EventStreamDefinition

`path`、`events`、必填的 `maxBufferSize` 與 `maxQueueSize`，可選 `method`／`operation`／`input`／`error`。Request 形狀跟 HTTP 一樣，包括 `body`。`GET` 與 `HEAD` 不能回傳 body。只要宣告了 `input`，就必須明確提供 `builder`。`input` 只定義入參，每個值放在哪裡只由 builder 決定。只有沒有 `input` 的定義可以省略 `builder`。

## EventStreamEndpoint

`defineEventStream` 的回傳值。第一個引數是 client。其餘引數只有 input。

## EventStreamRequestShape

欄位跟該串流 method 與 path 的 `HttpRequestShape` 一樣。

## StreamAwaitResult

`[null, stream, open]` 或 `[error, undefined, open?]`。

## EventStreamData

從 `EventStructs` map 推出的解析後事件載荷。
