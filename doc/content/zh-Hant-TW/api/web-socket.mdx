# WebSocket

宣告 socket，帶著 client 呼叫操作，收發具型別的訊息，然後關閉。

## defineWebSocket()

<ApiSignature name="defineWebSocket" />

- **definition** — `path`，以及一個 `incoming` struct；選用的 `outgoing` 與 `input` struct、`meta`、靜態 `protocols` 與 `maxOutgoingQueueSize`。只要宣告了 `input`，就必須提供明確的 `builder`。`input` 只宣告參數，每個值放在哪裡全由 builder 決定。只有未宣告 `input` 的定義可以省略 `builder`。這些 `definition` 成員的文件位於 [`WebSocketDefinition`](/zh-Hant-TW/api/core/websocketdefinition-type)。`builder` 恰好在宣告 `input` 時必填。
- **回傳** 一個操作。第一個引數是 [`Client`](/zh-Hant-TW/api/core/client-type)。其餘引數只有 input。呼叫它就會開啟工作階段。

<include cwd>examples/api/define-web-socket.ts#example</include>

呼叫會回傳 `[null, session, connection]` 或 `[err, undefined, connection?]`。單次呼叫的選項，請從 [`RequestOptions`](/zh-Hant-TW/api/core/requestoptions-type) 衍生 client 來傳。WebSocket 會讀 `signal`、`beforeConnect`、`heartbeat`、`protocols` 與 `retry`，並忽略 HTTP 進度欄位。

`beforeConnect`、`heartbeat`、`protocols` 與 `retry` 每一項都會在該次呼叫整份取代 client 的設定。子協定的優先順序是：衍生的 client、`withWebSocketProtocols`，最後才是定義上的 `protocols`。`heartbeat.timeoutMs` 是等待確認的時間，不是請求期限。

## WebSocketSession

<ApiSignature name="WebSocketSession" />

自有作用域請優先使用 `await using ownedSession = session` 清理。手動 `session.close()` 與 `await session.closed` 仍可使用。

`closed` 回報邏輯上的終止狀態。非同步 disposer 會要求原生關閉，並等待 Defjs 擁有的 teardown；但若關閉事件遲遲不來，最多只等一秒，並可能以名為 `TimeoutError` 的 `DOMException` 拒絕。它無法證明實體 TCP 連線真的關閉了。若 `session.close()` 執行時原生 `close()` 拋出，`session.close()` 會拋出該錯誤，工作階段以 `closed.kind: "error"` 與該原因結束。

### WebSocketState

`'idle' | 'connecting' | 'open' | 'closing' | 'closed' | 'reconnecting' | 'aborted' | 'error'`

### WebSocketConnectionInfo

`generation`（每次開啟時遞增），以及已知時的 `url`、`protocol` 與 `extensions`。

### WebSocketCloseInfo

<ApiSignature name="WebSocketCloseInfo" />

`kind` 是 `closed`、`aborted` 或 `error`。`cause` 在 `closed` 上不存在，在 `aborted` 上為選用，在 `error` 上必填。在 `error` 上，同一個 cause 會在已經排入佇列的訊息之後讓 `receive` 拒絕，並傳給 `onRuntimeError`。工作階段以 `aborted` 結束時，以及呼叫端以 `session.close()` 或釋放結束它時，未讀訊息會被丟棄。呼叫端的停止（`session.close()`、釋放，或中止 `signal`）在工作階段結束之後也會丟棄它們，且不會改變 `closed` 或 `receive` 的拒絕。心跳逾時與重試用盡則保留一般的執行時期 `Error` 作為 cause，沒有獨立而穩定的代碼。曾經開啟、隨後在沒有關閉訊框的情況下斷線的連線（代碼 `1006`）在每個執行環境都是 `error`。`code`、`reason` 與 `wasClean` 可能出現在每個變體上。手動 `session.close()` 會在關閉事件本身沒有這兩項時，為 `{ kind: "closed" }` 補上 `code` 與 `reason`。

## WebSocketExecuteOptions

<ApiSignature name="WebSocketExecuteOptions" />

`WebSocketExecuteOptions` 是 [`UseWebSocketConfig`](/zh-Hant-TW/api/core/usewebsocketconfig-type)：`beforeConnect`、`heartbeat`、`protocols`、`retry` 與 `signal`。`WebSocketHeartbeatConfig`：`intervalMs` 與 `message` 必填；`timeoutMs` 只允許與 `isAck` 一起出現。沒有 `timeout` 或 `abort` 欄位。

`signal` 涵蓋整個工作階段，包括開啟之後。期限是 `AbortSignal.timeout(ms)`，歸類為 `NET_TIMEOUT`。手動中止歸類為 `NET_ABORTED`。沒有 client 層級的預設期限。只限制建立連線階段的期限是 `retry: { maxRetries: 0, attemptTimeoutMs }`，它在 `open` 處結束。`signal` 是該次呼叫的 signal；請在應用程式碼中用 `AbortSignal.any` 組合。`heartbeat` 是整份替換；它的 `timeoutMs` 只是等待確認，不是請求期限。

builder 與攔截器鏈每次操作只執行一次。重連會重用已建構的 path/query 與擷取到的 protocols，並在 `beforeConnect` 之前建構 URL。若攔截器沒有取代請求的基礎端點，重連還會代入新選取的端點。這個 hook 無法在同一個工作階段內輪替 URL 或子協定的憑證；請用新的 input 或 client 設定發起新操作。

設定重試策略（`withRetry`）後，`maxRetries` 預設為每次中斷 3 次；`0` 會停用。`session.close()` 沒有要求的每一次關閉預設都會重試，包括從未開啟的連線與沒有得到回應的心跳，而 `shouldRetry` 可以推翻這個預設。建構子拋出（例如平台拒絕的子協定）是重試只會重複的本機失敗：它會結束呼叫，不會詢問 `shouldRetry`。成功的 `open` 會重設次數與 backoff 指數，所以每次新的中斷都從重試 1 開始。預設值與決策順序見 [Client](/zh-Hant-TW/api/client#withretry)。

## 訊息

`incoming` 是單一 struct。文字、`ArrayBuffer`、型別化陣列與 `Blob` 訊框都會以 UTF-8 讀取、剖析 JSON，再對這個 struct 檢查。JSON 剖析或 struct 驗證失敗的訊框會回報給 `session.onRuntimeError`，不會進入佇列。沒有用戶端層級的無效訊框選項。

`outgoing` 是單一 struct。`session.send` 接受該 struct 的 `StructInput`，編碼別名，再呼叫 `JSON.stringify`。編碼之後 JSON 無法忠實表示的值，會在送出或進入重連佇列之前拋出 `TypeError`，包括非有限數字、函式、symbol、`Map`、`Set`、串流，以及沒有 JSON 表示的類別實例。巢狀值沿用與 HTTP JSON 本文相同的檢查。心跳也適用這項檢查；心跳序列化失敗會結束工作階段。多種訊息型別請用 `struct.discriminatedUnion`。

## WebSocketDefinition

`path`、`incoming`，以及選用的 `outgoing`／`input`／`meta`／`protocols`／`maxOutgoingQueueSize`。builder 只能回傳 `path` 與 `query`。只要宣告了 `input`，就必須提供明確的 `builder`。`input` 只宣告參數，每個值放在哪裡全由 builder 決定。只有未宣告 `input` 的定義可以省略 `builder`。

## WebSocketEndpoint

`defineWebSocket` 的回傳值。第一個引數是 client。其餘引數只有 input。

## WebSocketRequestShape

只有 `path` 與 `query`。`headers` 與 `body` 是 `never`。

## UseWebSocketConfig

`beforeConnect`、`heartbeat`、`protocols`、`retry` 與 `signal`。`WebSocketExecuteOptions` 就是這個切片。沒有 `abort` 欄位。

## SocketAwaitResult

`[null, session, connection]` 或 `[err, undefined, connection?]`。

## ManualSocketCloseReason

透過 `session.close()` 關閉工作階段時所記錄的原因。

## WebSocketHeartbeatConfig

`intervalMs` 與 `message` 必填。`isAck` 用來辨認確認，`timeoutMs` 只允許與 `isAck` 一起出現；聯合型別會強制這點，執行時期則不會檢查。Defjs 沒有定義心跳格式：每一個值都來自你的函式。酬載會透過 `outgoing` struct 以 JSON 文字送出。沒有得到回應的心跳會關閉 socket，並進入 `withRetry` 的重試流程；沒有重試策略時，工作階段會以 `error` 結束。

## WebSocketIncomingData

解碼後的入站訊框：`incoming` struct 的 `Infer`。

## WebSocketOutgoingData

`session.send` 接受的值：`outgoing` struct 的 `StructInput`；未宣告時為 `never`。

## SocketLifecycleOutcome

單次連線嘗試的結果（`closeInfo`、`connection`、`cause`、`opened`），供重試邏輯使用。它不是工作階段的最終結果；最終結果請見 `WebSocketCloseInfo`。
