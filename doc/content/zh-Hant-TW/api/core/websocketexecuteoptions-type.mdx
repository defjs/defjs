<ApiReference identity="@defjs/core:WebSocketExecuteOptions" />

```ts
type WebSocketExecuteOptions<TIncoming = unknown, TOutgoing = unknown> = UseWebSocketConfig<TIncoming, TOutgoing> & {
  signal?: AbortSignal
}
```

[`UseWebSocketConfig`](/zh-Hant-TW/api/core/usewebsocketconfig-type) 加上 `signal`。展開後：

```ts
type WebSocketExecuteOptions<TIncoming = unknown, TOutgoing = unknown> = {
  beforeConnect?: (context: { attempt: number; signal: AbortSignal }) => void | Promise<void>
  heartbeat?: WebSocketHeartbeatConfig<TIncoming, TOutgoing>
  protocols?: readonly string[]
  reconnect?: ClientWebSocketOptions['reconnect']
  signal?: AbortSignal
} & ({ abort?: AbortSignal; timeout?: never } | { abort?: never; timeout?: number })
```

- `abort` 與 `timeout` 互斥。型別會拒絕兩者並存，執行時同時傳入則以 `REQ_OPTIONS_INVALID` fault 失敗。
- `signal` 可與其中任一組合；它不是 `abort` 的別名。
- `timeout` 必須是不大於 `2_147_483_647` 的正 safe integer。它限制開啟 session 最多可花多久，重連時不會再次套用。
- `beforeConnect`、`heartbeat`、`protocols` 與 `reconnect` 在這次呼叫中覆寫 client 層級的 options。
- 設定了 `reconnect` 時，`attempts` 預設是每次中斷 `3` 次；`0` 停用。成功的 `open` 會重設額度與 backoff 指數。省略 `attempts` 並不會在同一次中斷內給予無限次重試。驗證與最終延遲上限見 [`withWebSocketReconnect`](/zh-Hant-TW/api/core/withwebsocketreconnect)。

見 [`WebSocketHeartbeatConfig`](/zh-Hant-TW/api/core/websocketheartbeatconfig-type)。
