description: '用 struct 解析未知的值，並回傳 error-first tuple。'
---

<ApiReference identity="@defjs/core:struct.parse" />

```ts
function parse<S extends StructLike<unknown, unknown, boolean>>(
  struct: S,
  value: unknown,
  options?: { aliases?: boolean; errorMap?: ErrorMap },
): ParseResult<S['_struct']['output']>
```

- **struct** 是用來 parse 的 struct。不是 struct 的值會丟出 `TypeError`。
- **value** 是未知的輸入。
- **options.aliases** 預設為 `false`：物件 key 以**邏輯**名稱（`displayName`）讀取。設為 `true` 則以 wire 名稱（`display_name`）讀取，跟 HTTP／JSON codecs 一樣。輸出一律使用邏輯名稱。
- **options.errorMap** 是 [`ErrorMap`](/zh-Hant-TW/api/core/errormap-type)，只改這一次呼叫的 issue 文案，包含另一份 Core 複本所建立的 struct 在 bigint／date 轉換上的失敗。任何字串，包括 `''`，都會取代該文案；只有 `undefined` 會保留預設。自訂文字會原樣使用。
- **回傳** `[null, output]` 或 `[StructError, undefined]`。驗證失敗不會丟出例外。呼叫端提供的 getter 與 `errorMap` 回呼所丟出的例外會原樣傳播。
- 解析是 fail-fast：在第一個失敗就停止，所以 error 只含一個 issue。輸出會移除物件中的未知 key，輸入不會被修改。
- 沿一條路徑最多走訪 **256 層巢狀容器**（`object`、`array`、`record` 或 `tuple`），根容器算第一層。下一個容器會在其邏輯路徑以 `invalid_type` 失敗，並帶有 `expected: 'value nested at most 256 levels deep'`。在聯集中，後續候選仍可能成功；如果沒有候選符合，聯集會回報 `invalid_union`。經由已宣告的容器欄位形成的循環也會達到此上限；允許共用非循環的子節點。聯集與交集分支不會增加容器層數，而 `any`/`unknown` 的值會保持不透明，不會被遍歷。

```ts
const [error, user] = struct.parse(User, { id: 1, displayName: 'Ada' })
if (error) return console.error(error.prettify())
```

`any` 與 `unknown` 不會走訪其值，但交集可能會遞迴合併這些葉節點回傳的兩個不同物件或陣列值。這次合併與其外層邏輯路徑共用同一個 256 層容器預算。超出預算會在被拒絕容器的邏輯路徑產生 `invalid_intersection`。完全相同的參照會被保留而不走訪，即使共用的值含有循環也一樣。

見 [`ParseResult`](/zh-Hant-TW/api/core/parseresult-type) 與 [`StructError`](/zh-Hant-TW/api/core/structerror-type)。
