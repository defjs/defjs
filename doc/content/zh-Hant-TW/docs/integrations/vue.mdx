# Vue

`@defjs/vue` 透過 `createClientPlugin(client)`、`HTTP_CLIENT` 與 `injectClient()` 將應用程式專屬的 `@defjs/core` Client 注入 Vue 3 或更新版本的應用程式中。你的 SDK 定義維持純粹的 `@defjs/core` 模組，完全不依賴 Vue。外掛本身只需要 `provide` / `inject`；下方範例使用了 `<script setup>` 與 `onScopeDispose`，這兩者需要 Vue 3.2 或更新版本。

```sh
bun add @defjs/core @defjs/vue vue
```

## `@defjs/vue` 負責的項目 vs. 應用程式負責的項目

- **由 `@defjs/vue` 提供**：`createClientPlugin(client)`、`HTTP_CLIENT`（`InjectionKey<DerivableClient>`）與 `injectClient(key?)`。
- **由你的應用程式擁有**：建立 [`DerivableClient`](/zh-Hant-TW/api/core/derivableclient-type)、在 watcher（`onCleanup`）或 composable（`onScopeDispose`）中中止進行中的工作、關閉 SSE/WebSocket handle，以及整合 Vue Query 之類的 query 函式庫。
- **重要**：`injectClient()` 回傳的是 `DerivableClient` 函式物件。請在實際執行操作的地方呼叫 `client({ signal })`（`getOrder(client({ signal }), input)`）。切勿把 `client` 當成 `watch(client, ...)` 或 `computed(client)` 的第一個參數，因為 Vue 會把函式參數當成 reactive getter。

## 3. 在 Scope 銷毀時清理 SSE 與 WebSocket 串流

若工作是在 composable 內、或 watcher 以外的元件邏輯中啟動，請把 `AbortController` 與 `onScopeDispose` 搭配使用。這個 signal 涵蓋啟動階段與已開啟的串流，因此中止它就是全部的清理。消費它唯一的非同步迭代器，然後在 `finally` 中關閉 handle 並等待 `.closed`：

- tuple 的錯誤分支會顯示初始交握失敗（包含 HTTP 503）。迭代器的 `catch` 會顯示啟動後的失敗；`finally` 區塊仍會關閉串流並等待結束。
- 停止 scope 會讓 SSE 的 `for await` 迴圈正常結束。
- 中止 WebSocket 工作階段會讓它以 `aborted` 結束，並以 `AbortError` 拒絕 `session.receive`；因此處置後請在 `catch` 區塊加上防護，並在 `finally` 中取消訂閱 `onStateChange` / `onRuntimeError` 監聽器。

## 4. SSR 與應用程式範圍

- **瀏覽器**：當端點與攔截器不隨請求變更時，每個 Vue 應用程式可共用單一 client。
- **SSR**：只要標頭、Cookie、租戶或憑證會因請求而異，就為每個 SSR 請求建立並安裝新的 client。
- 卸載 Vue 應用程式或處置元件 scope **不會**自動中止 HTTP 請求、關閉 SSE/WebSocket 串流，也不會處置 core client。

## 公開匯出項目與相關指南

- `HTTP_CLIENT` — 供原生 `provide` / `inject` 使用的 `InjectionKey<DerivableClient>`。
- `createClientPlugin(client)` — 在 `HTTP_CLIENT` 下提供 `client` 的 Vue `Plugin`。
- `injectClient(key?)` — 解析 `key` 最近一層的 client（預設為 `HTTP_CLIENT`）。
