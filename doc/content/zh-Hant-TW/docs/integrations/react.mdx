# React

`@defjs/react` 透過 React Context 與 `useClient()` 將應用程式專屬的 `@defjs/core` Client 注入 React 18+ 元件樹中。你的 SDK 定義維持純粹的 `@defjs/core` 模組，完全不依賴 React。

```sh
bun add @defjs/core @defjs/react react
```

## `@defjs/react` 負責的項目 vs. 應用程式負責的項目

- **由 `@defjs/react` 提供**：`ClientProvider` 與 `useClient(overrideClient?)`。
- **由你的應用程式擁有**：建立 [`DerivableClient`](/zh-Hant-TW/api/core/derivableclient-type)、在卸載或相依性改變時取消進行中的請求（`AbortController`）、關閉 SSE/WebSocket handle，以及整合 TanStack Query 之類的 query 快取。
- **重要**：`useClient()` 回傳的是 `DerivableClient` 函式物件。請在實際執行操作的地方呼叫 `client({ signal })`（`getOrder(client({ signal }), input)`）。切勿把 `client` 直接傳給 `setState(client)`，因為 React 會把傳給 state setter 的函式參數當成 updater 函式。

## 2. 使用 `useClient` 讀取與覆寫

`useClient(overrideClient)` 在傳入 `overrideClient` 時會直接回傳該 Client，若省略或為 `undefined` 則會讀取最近層級的 `ClientProvider`。只有在兩者皆未提供 Client 時才會拋出 `Error`。

<include cwd>examples/react/read-with-use-client.tsx#example</include>

- 一律在元件或自訂 Hook 的頂層無條件呼叫 `useClient(explicitClient)`。切勿寫成 `explicitClient ?? useClient()`，那會違反 React Hooks 規則。

## 4. 在 Effect 中管理 SSE 與 WebSocket 生命週期

SSE 與 WebSocket handle 的生命週期會超過最初的 `openStream(...)` 或 `connectChat(...)` 呼叫。請把 `AbortController` 的 signal 傳入操作，並在清理時中止它：這個 signal 涵蓋啟動階段與已開啟的工作階段。以 `await using` 持有工作階段，並消費它唯一的非同步迭代器：

<include cwd>examples/react/own-realtime-work.tsx#example</include>

- 中止傳入 WebSocket 操作的 `signal`，會讓工作階段以 `aborted` 結束，並以 `AbortError` 拒絕 `session.receive`。請用 `controller.signal.aborted` 為 `catch` 區塊加上防護，只讓真正的執行時期錯誤（例如心跳逾時）浮現。
- 中止 SSE 串流會讓 `for await (const msg of stream)` 正常結束，不會拋出例外。

---

## 5. SSR 與 Provider 範圍

- **瀏覽器**：當端點與攔截器不隨請求變更時，共用單一模組層級的 client。
- **SSR**：只要標頭、Cookie、租戶或憑證會因請求而異，就在每個伺服器請求的邊界內建立新的 client。
- 卸載 `<ClientProvider>` **不會**中止進行中的 HTTP 呼叫、關閉 SSE/WebSocket 連線，也不會處置 client。
