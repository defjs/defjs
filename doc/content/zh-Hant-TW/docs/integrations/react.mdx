# React

`@defjs/react` 透過 React Context 與 `useClient()` 將應用程式專屬的 `@defjs/core` Client 注入 React 18+ 元件樹中。你的 SDK 定義維持純粹的 `@defjs/core` 模組，完全不依賴 React。

```sh
bun add @defjs/core @defjs/react react
```

## `@defjs/react` 負責的項目 vs. 應用程式負責的項目

- **由 `@defjs/react` 提供**：`ClientProvider` 與 `useClient(overrideClient?)`。
- **由你的應用程式掌控**：建立 [`DerivableClient`](/zh-Hant-TW/api/core/derivableclient-type)、在元件卸載或相依性改變時取消進行中的請求（`AbortController`）、關閉 SSE/WebSocket 控制代碼，以及整合如 TanStack Query 等資料快取函式庫。
- **重要提示**：`useClient()` 回傳的是 `DerivableClient` 函式物件。請在實際執行操作處呼叫 `client({ signal })`（如 `getOrder(client({ signal }), input)`）。切勿將 `client` 直接傳入 `setState(client)`，因為 React 會將狀態設定函式收到的函式參數視為 State Updater。

## 2. 使用 `useClient` 讀取與覆寫

`useClient(overrideClient)` 在傳入 `overrideClient` 時會直接回傳該 Client，若省略或為 `undefined` 則會讀取最近層級的 `ClientProvider`。只有在兩者皆未提供 Client 時才會拋出 `Error`。

<include cwd>examples/react/read-with-use-client.tsx#example</include>

- 請始終在元件或自訂 Hook 的頂層無條件呼叫 `useClient(explicitClient)`。切勿撰寫 `explicitClient ?? useClient()`，這樣做會違反 React Hooks 規範。

## 4. 在 Effect 中管理 SSE 與 WebSocket 生命週期

SSE 與 WebSocket 的生命週期會延續到初始的 `openStream(...)` 或 `connectChat(...)` 呼叫之後。請在 await 啟動前先註冊清理常式、在卸載後關閉成功解析的控制代碼、消費其唯一的非同步迭代器，並等待 `.closed`：

<include cwd>examples/react/own-realtime-work.tsx#example</include>

- 中斷傳入 WebSocket 操作的 `signal` 會將該工作階段終結為 `aborted`，並以 `AbortError` 拒絕 `session.receive`。在已處置的狀態下，請在 `catch` 區塊中進行防護，僅向上拋出真正的執行時期錯誤（如佇列溢位或心跳逾時）。
- 中斷 SSE 串流會讓 `for await (const msg of stream)` 乾淨終止，而不會拋出錯誤。

## 5. SSR 與 Provider 範圍

- **瀏覽器端**：當端點與攔截器不隨個別請求變更時，可在全域共用單一模組層級的 Client。
- **SSR 伺服器端**：當標頭、Cookie、租戶或憑證因請求而異時，請在每個伺服器請求邊界內建立全新的 Client。
- 卸載 `<ClientProvider>` **不會**自動中止進行中的 HTTP 呼叫、關閉 SSE/WebSocket 連線，也不會呼叫 `disposeClient`。
