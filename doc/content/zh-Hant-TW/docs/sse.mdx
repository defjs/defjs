# SSE 事件串流

SDK 開發者用 `defineEventStream` 宣告 Server-Sent Events（SSE）操作：指定路徑、選用的 `input` 與 `builder`、以 `events` 字典對應事件 struct，以及緩衝區與佇列上限。取用端應用程式則在自己的 Client 上設定身分驗證與需主動啟用的重連，開啟串流、迭代具型別的事件，並負責關閉串流。

只有在初始 HTTP 回應為 `2xx`、媒體型別為 `text/event-stream` 且帶有可讀取的本文時，呼叫該操作才會解析為 `[error, stream, startupOpen]`：

- **非 `2xx` 交握**：回傳 `HTTP_STATUS`（若定義上宣告了 `error` struct，則帶有解碼後的 `error.data`）。這對目前的操作是致命錯誤，不會呼叫 `shouldReconnect`。下一次操作會重新選取端點，因此平衡器可能選到另一個端點。
- **Content-Type 不符或本文無法讀取**：回傳 `RES_MEDIA_TYPE_INVALID` 或 `RES_DECODE_FAILED`。
- **`startupOpen` 與 `stream.open`**：tuple 的第三項（`startupOpen`）是首次交握回應的快照；`stream.open` 會在串流之後重連時即時更新。若重連交握回傳 `503`，迭代器會拒絕，`stream.closed` 回報 `RES_DECODE_FAILED`，而 `stream.open.response.status` 仍為 `503`；即時的回應狀態請看 `stream.open`。

## 3. 事件分派與解碼

當一個 SSE 訊框抵達時（依 WHATWG 規則以空行結尾）：

1. **事件路由**：線上的 `event:` 欄位會選出 `events[eventName]`；若沒有對應，則回退到已宣告的 `events.default`。省略 `event:` 欄位時，事件名稱預設為 `"message"`。未宣告且沒有 `events.default` 的事件會被丟棄。
2. **酬載解碼**：`struct.string()` schema 會直接收到原始的 `data:` 文字；其他所有 struct 種類都會先把 `data:` 剖析為 JSON，再以 struct 驗證。
3. **觀察無效事件**：無效或未宣告的事件會被丟棄，不會中斷串流。可在 Client 上設定 `withSSEOnInvalidEvent(...)`，取得有上限的診斷資訊：

## 4. 重新連線與 Last-Event-ID [#reconnect]

SSE 的重新連線是**需主動啟用（opt-in）**的功能。沒有設定 `withSSEReconnect(...)` 時，任何網路斷線或串流讀取錯誤都會直接終止串流。

<include cwd>examples/sse/reconnect.ts#example</include>

- **中斷額度（`attempts`）**：傳入設定物件給 `withSSEReconnect` 時，預設為 `3`。每次交握成功都會重設嘗試次數與退避指數，因此只要每次連線都成功開啟，即使設定 `attempts: 1`，長時間的工作階段仍可能建立多次實體連線。伺服器正常的 EOF **不算**失敗，不會觸發重連。
- **游標追蹤（`Last-Event-ID`）**：事件結尾的空行被剖析時，游標才會提交，並在重連時自動以 `Last-Event-ID` 送出。不完整的訊框不論連線是正常結束或失敗，都不會提交其 `id`。在可重連的讀取或網路失敗之後，會從最後提交的 id 續傳；伺服器必須支援從該游標重播。
- **冪等安全性**：預設只有冪等方法（`GET`、`HEAD`、`OPTIONS`、`PUT`、`DELETE`）會自動重連。非冪等方法（`POST`、`PATCH`——例如 LLM 串流請求）只有在自訂 `shouldReconnect` 明確回傳 `true` 時才會重連。帶有 `ReadableStream` 請求本文的請求會在第一次嘗試時用掉本文，因此永遠不會重連。
- **交握逾時（`connectTimeoutMs`）**：有提供時，必須是有限正數，且不得大於 2147483647（計時器上限）；否則該操作回傳 `REQ_OPTIONS_INVALID`。它限制每次交握從呼叫 Fetch 到收到回應標頭的時間，但不限制已建立串流的存活時間。

## 5. 緩衝區與佇列上限

預設為 `maxBufferSize: 64 * 1024` 位元組與 `maxQueueSize: 1024` 個事件。兩項上限都必須是正的安全整數。沒有預設的交握期限：未完成的 Fetch 會一直等待平台、呼叫端取消，或明確設定的 `connectTimeoutMs`。超過任一容量上限都是致命錯誤（`stream.closed` 以 `kind: "error"` 解析，迭代器拒絕——事件絕不會被悄悄丟棄）：

| 定義選項        | 限制範圍                                  | 終結錯誤碼            |
| --------------- | ----------------------------------------- | --------------------- |
| `maxBufferSize` | 遇到空行前未完成或過大的 SSE 訊框位元組數 | `CAP_BUFFER_EXCEEDED` |
| `maxQueueSize`  | 等待 `for await` 消費端處理的已驗證事件數 | `CAP_QUEUE_OVERFLOW`  |
