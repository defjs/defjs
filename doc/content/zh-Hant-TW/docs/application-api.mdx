# 應用程式 API 層 [#application-api-layer]

大多數專案直接在應用程式儲存庫內（`src/api/`）使用 Defjs，以取代散落在各處的 `fetch` 或 `axios` 封裝。即使沒有發布外部 npm 套件的計畫，將 `src/api/models/`、`src/api/services/` 與 `src/api/client.ts` 分離，依然能讓你的請求層保持強型別、支援記憶體內單元測試，並在瀏覽器與 SSR 執行環境間安全共用。

---

## 1. 建議的 `src/api/` 目錄結構

將專案的請求層在 `src/api/` 下劃分為三個職責明確的部分：

```text
src/
├── api/
│   ├── models/           # 1. 共用 struct schema 與 Infer<typeof ...> 型別
│   │   └── order.ts      #    ApiError, OrderStatus, Order, OrderPage
│   ├── services/         # 2. 按領域分組的純函式操作定義
│   │   └── orders.ts     #    getOrder, listOrders, createOrder
│   └── client.ts         # 3. 應用程式持有的 Client（端點、驗證攔截器、重試策略）
└── checkout.ts           # 4. 呼叫操作的商業邏輯／UI 元件
```

## 3. 應用程式專案的關鍵模式

### 瀏覽器單例 vs. SSR 單一請求 Client

- **瀏覽器／SPA（`apiClient`）**：針對每個後端來源匯出單一模組範圍的 `createClient(...)` 執行個體。共用該執行個體可在頁面互動期間保留負載平衡器的健康狀態與 Client 層級的 HTTP 重試預算。在 React 或 Vue 應用程式中，可透過 [`@defjs/react`](/zh-Hant-TW/docs/integrations/react)（`ClientProvider`／`useClient`）或 [`@defjs/vue`](/zh-Hant-TW/docs/integrations/vue)（`createClientPlugin`／`injectClient`）在根元件提供 `apiClient`。
- **SSR／BFF（`createServerApiClient(accessToken)`）**：只要憑證、Cookie 或租戶標頭會隨每個進入的 HTTP 請求而變動，請在伺服器端請求處理常式內呼叫工廠函式來建立隔離的 `Client`。由於 `getOrder`、`listOrders` 與 `createOrder` 皆為純函式，同一份 `services/orders.ts` 定義可同時搭配 `apiClient` 與 `createServerApiClient(token)` 運作。

### 單次呼叫的逾時與取消

切勿為了傳入逾時或 `AbortSignal` 而重新呼叫 `createClient(...)` 建立新 `Client`。請直接從共用的 Client 內聯衍生出單次呼叫專用的 Client：

```ts
const [error, created] = await createOrder(
  apiClient({ signal: AbortSignal.timeout(5_000) }),
  {
    customerName: "Ada Lovelace",
    totalCents: 4200,
    idempotencyKey: "idem-2026-101",
  },
);
```

### 共用錯誤外層結構（`ApiError`）

在 `src/api/models/` 中統一宣告後端的標準錯誤結構（`export const ApiError = struct.object(...)`），並在 `src/api/services/` 的每個 `defineRequest` 指定 `error: ApiError`。當請求回傳非 `2xx` 狀態碼時，只要透過 `if (error.code === "HTTP_STATUS")` 進行型別縮小，就能以強型別安全讀取 `error.data.code`、`error.data.message` 與 `error.data.requestId`。
