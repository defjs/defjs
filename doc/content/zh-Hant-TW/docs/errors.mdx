# 錯誤處理

在 Defjs 中，請求、傳輸層與解碼錯誤都不會在呼叫處拋出例外。每項操作都會回傳一個 error-first tuple（`[error, ...]`），其中 `error` 若非 `null`，就是一個具型別的 `Fault` 物件（由 `error.code` 鑑別的原生 `Error` 實例）。

### 為什麼 HTTP 失敗時 `error` 會包含回應中繼資料

在 HTTP 失敗時，回傳的 tuple 為 `[error, undefined, undefined]`。所有收到的回應中繼資料（`status`、`statusText`、`headers`、`url`）都會直接附加在 `error.response` 上，因此你可以單獨將 `error` 傳遞給日誌記錄器或錯誤處理常式，而不會遺失上下文資訊。

## 2. Fault 類別與封閉錯誤碼集合

錯誤碼第一個 `_` 前面的前綴代表錯誤類別（`HTTP`、`REQ`、`NET`、`RES`、`EXT`、`CAP`、`ENV`），而完整的 `code` 則構成一個封閉的 Union，適合使用窮舉式 `switch` 語句處理：

| 類別   | 錯誤碼                                                                 | 意義與處置建議                                                                                 |
| ------ | ---------------------------------------------------------------------- | ---------------------------------------------------------------------------------------------- |
| `HTTP` | `HTTP_STATUS`                                                          | 伺服器回傳非 `2xx` 狀態碼（`3xx`、`4xx`、`5xx`），且成功解碼已宣告的 `error` struct。          |
| `REQ`  | `REQ_INPUT_INVALID`、`REQ_OPTIONS_INVALID`、`REQ_BUILD_FAILED`         | 呼叫端傳入無效輸入、Client 選項超出合法範圍、URL/路徑不合法，或 `builder` 拋出例外。請勿重試。 |
| `RES`  | `RES_MEDIA_TYPE_INVALID`、`RES_DECODE_FAILED`、`RES_STRUCT_MISMATCH`   | 伺服器回應違反了宣告的媒體型別、資料表示法或 `struct` 契約。                                   |
| `NET`  | `NET_ABORTED`、`NET_TIMEOUT`、`NET_UNREACHABLE`、`NET_BODY_INCOMPLETE` | 呼叫端主動取消（`NET_ABORTED`）、逾時已過（`NET_TIMEOUT`）、連線失敗或回應本文串流中途截斷。   |
| `EXT`  | `EXT_INTERCEPTOR_FAILED`、`EXT_HOOK_FAILED`、`EXT_OBSERVER_FAILED`     | 應用程式攔截器、鉤子或進度/狀態觀察者拋出例外或回傳了無效值。                                  |
| `CAP`  | `CAP_BUFFER_EXCEEDED`、`CAP_QUEUE_OVERFLOW`                            | SSE 封包緩衝區或 SSE/WebSocket 消費端佇列超過了設定的上限。                                    |
| `ENV`  | `ENV_UNSUPPORTED`                                                      | 宿主執行環境缺乏必要的 Web API（例如在 Firefox 中嘗試串流上傳請求本文）。                      |

### Fault 屬性依錯誤碼對照

| 錯誤碼        | `status` | `response`                                        | `data`                                  | `cause`                  |
| ------------- | -------- | ------------------------------------------------- | --------------------------------------- | ------------------------ |
| `HTTP_STATUS` | `number` | `DecodedResponse<TErr>` 或 `HttpMeta`             | 解碼後的 `error` struct，或 `undefined` | 底層 cause（若有）       |
| `RES_*`       | `number` | `HttpMeta`（**不包含 `body` 欄位**）              | 無                                      | `StructError` 或剖析錯誤 |
| 其他錯誤碼    | 無       | 若已接收到標頭則為 `HttpMeta`，否則為 `undefined` | 無                                      | 底層 `Error` / 中斷原因  |

## 4. SSE 與 WebSocket 的啟動錯誤 vs. 連線後執行時期錯誤

對於長生命週期的連線，操作的 tuple 僅會回報**啟動時**的失敗（在串流或 Socket 成功開啟之前）。連線建立後，後續的執行時期錯誤會透過控制代碼或工作階段生命週期發布：

| 傳輸協定      | 啟動失敗（在回傳的 tuple 中反映）                                                                                             | 連線後執行時期失敗（tuple 解析之後）                                                                                                                                                                                                                           |
| ------------- | ----------------------------------------------------------------------------------------------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| **HTTP**      | 所有失敗皆在單次操作 tuple 中確定回傳。                                                                                       | 不適用                                                                                                                                                                                                                                                         |
| **SSE**       | 非 `2xx` 狀態碼（`HTTP_STATUS`）、無效的 Content-Type（`RES_MEDIA_TYPE_INVALID`）或交握本文缺失/無效（`RES_DECODE_FAILED`）。 | 非同步迭代器拋出拒絕；`stream.closed` 解析為 `{ kind: 'error', code }`。                                                                                                                                                                                       |
| **WebSocket** | 開啟前被關閉、建構子拋出例外或交握期間被中斷。                                                                                | 非致命封包錯誤會觸發 `session.onRuntimeError`；致命錯誤會拒絕 `session.receive` 並將 `session.closed` 解析為 `{ kind: 'error', cause }`。傳入佇列溢位使用 `cause.code === 'CAP_QUEUE_OVERFLOW'`；心跳逾時與重連次數耗盡仍使用一般執行時期 `Error` 作為 cause。 |
