# 公開 SDK 設計 [#public-sdk-design]

當你的公司或平台團隊為外部開發者發布官方 TypeScript SDK（例如物件儲存 SDK、金流閘道 SDK 或 SaaS 平台 SDK）時，SDK 套件的核心職責是**定義通訊契約，同時不強加執行環境與 Client 策略**。

本指南以**相容於 Amazon S3 的物件儲存 SDK（`@company/s3-sdk`）**為具體藍本，示範如何透過 `models/` 與純函式 `services/` 設計多模組的公開 SDK。

---

## 1. 為什麼公開 SDK 能受惠於 Defjs 的職責分離？

傳統 SDK 通常會把厚重的 Client 類別（如 `new S3Client({ region, credentials })`）與命令類別或靜態服務類別緊密耦合在一起。使用 `@defjs/core` 撰寫公開 SDK 能為外部使用者解決四個常見痛點：

1. **多環境與沙盒彈性切換**：因為 `@company/s3-sdk` 不綁定任何端點或 Client，客戶可以將完全相同的操作定義指向正式環境（`https://s3.us-east-1.amazonaws.com`）、測試沙盒、Cloudflare R2，或 CI 測試期間的本機 MinIO 容器。
2. **100% 打包工具 Tree-shaking**：匯出獨立的純函式（`listBuckets`、`listObjectsV2`、`getObject`、`putObject`、`deleteObject`）並設定 `"sideEffects": false`，能確保只呼叫 `getObject` 與 `putObject` 的瀏覽器打包產物自動剔除所有其他端點與資料模型。
3. **執行時期驗證與靜態型別同源**：外部取用端從單一來源即可同時獲得編譯期 TypeScript 型別（`Infer<typeof ...>`）與執行時期回應／錯誤驗證（`struct`），能防範非預期的網路酬載，並自動轉換 `snake_case` 欄位或 ISO 日期字串。
4. **完整掌控驗證、重試與遙測**：客戶可在自己的 `Client` 上自由掛載憑證輪替攔截器、`withRetry(...)` 策略、多區域負載平衡器（`withBalancer(...)`），或伺服器端 OpenTelemetry（`@defjs/opentelemetry-server`）。

## 2. 套件目錄結構

將 SDK 套件劃分為 `src/models/`（資料結構）與 `src/services/`（按資源領域分組的純函式操作定義），並透過扁平的入口檔案 `src/index.ts` 統一匯出：

```text
@company/s3-sdk/
├── src/
│   ├── models/                 # 1. 共用 struct schema 與 Infer<typeof ...> 型別
│   │   ├── common.ts           #    StorageClass, S3Error
│   │   ├── bucket.ts           #    Bucket, ListBucketsOutput
│   │   └── object.ts           #    ObjectSummary, ListObjectsOutput
│   ├── services/               # 2. 按資源領域劃分的純 defineRequest 函式
│   │   ├── buckets.ts          #    BucketInput, listBuckets, headBucket, deleteBucket
│   │   └── objects.ts          #    listObjectsV2, headObject, getObject, putObject, deleteObject
│   └── index.ts                # 3. 供根路徑匯入與 Tree-shaking 使用的匯出入口
├── package.json                # sideEffects: false, peerDependencies: { "@defjs/core": "^0.8.0" }
└── tsconfig.json
```

### 設計符合直覺的操作契約

- **扁平化呼叫端輸入，並在 `builder` 中進行路由**：在 `putObject` 中，呼叫端只需傳入單一且直覺的物件（`{ bucket, key, body, contentType, storageClass }`），再由同步的 `builder` 將該輸入拆分至 `path`（`:bucket/:key`）、`headers`（`content-type`、`x-amz-storage-class`）與二進位 `body`（`Blob`）。在 `listObjectsV2` 中，`builder` 會將 `continuationToken` 與 `maxKeys` 對應至 S3 的 `continuation-token` 與 `max-keys` 查詢參數，並自動帶上 `list-type: 2`。
- **讓 `output` 對齊實際的網路酬載**：
  - **結構化 JSON（`listBuckets`、`listObjectsV2`）**：宣告帶有 `.alias()` 對應與 `struct.date()` 欄位的 `struct.object(...)`。
  - **二進位酬載（`getObject`）**：宣告 `output: struct.blob()`（或 `struct.arrayBuffer()`）。
  - **空回應主體（`headBucket`、`headObject`、`putObject`、`deleteObject`）**：省略 `output`，讓零位元組的 `HEAD`、`200` 與 `204` 回應直接成功而不嘗試進行 JSON 解碼，同時呼叫端仍可從回傳元組的第三個位置讀取回應標頭（`response.headers.get("etag")`）。

## 4. 外部開發者如何使用你的 SDK

外部應用程式只需一併安裝 `@company/s3-sdk` 與 `@defjs/core`，以自己的端點與簽章攔截器設定 `Client`，即可直接將匯出的操作當作純函式呼叫：

