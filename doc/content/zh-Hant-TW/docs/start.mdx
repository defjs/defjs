# 開始使用：你的第一個 SDK 操作 [#getting-started-one-http-request]

你會寫兩個檔案：一個匯出 `GET /users/:id` 的 SDK 模組，以及一個匯入它並擁有 client 的應用程式。本機 Fetch handle 讓第一次執行保持離線。同一份 API 定義接著可以配上指向你服務的 client。

## 最佳實踐

定義與 client 彼此獨立。用應用程式的 client 呼叫操作，例如 `getUser(client, { id: 7 })`。沒有第三個 options 引數。呼叫操作就會啟動它；`await` 只是等待。服務位址與憑證也由應用程式持有。先檢查 error-first tuple。`error` 有值時，報告 `error.code`，從函式返回，然後再讀取成功值。

## Step 1 — 安裝

`@defjs/core` 是 ESM，可在 Node.js 或 Bun 上執行。Node.js 22.18+（或 24+）透過 type stripping 直接執行 `.ts` 檔；更舊的 22.x 版本需要 `--experimental-strip-types`。package.json 要保留 `"type": "module"`。瀏覽器環境仍要有 bundler 與 Fetch。

```sh
bun add @defjs/core
```

## Step 2 — 定義請求

建立 `src/define-request.ts`。這是 SDK 作者的模組：它匯出 `getUser`，不建立 client。Input struct 是呼叫端的值。`builder` 把那個值放到請求上。這裡整個 input 就是 path 物件，所以沒有 alias 的純量欄位會填入 `:id`。

<include cwd meta="define-request.ts">
  examples/start/define-request.ts#example
</include>

`output` 是 2xx body。`error` 是其餘每個狀態。各一個 struct。那些 body 形狀不同時，用 `struct.or(...)` 或判別聯集。

`defineRequest(...)` 回傳操作。呼叫 `getUser(client, input)` 就會啟動請求。上面的 `builder` 是放置 input 的函式，不是操作。宣告了 `input` 時，`builder` 必填、同步，而且是純函式。

## Step 3 — 在本機呼叫

在定義旁邊建立 `src/execute-locally.ts`。這是使用端的應用程式：它匯入 `getUser`，建立自己的 client，並提供本機 Fetch handle。Defjs 仍會驗證 input、建立 `Request`、依狀態分派，並剖析 body。

<include cwd meta="execute-locally.ts">
  examples/start/execute-locally.ts#example
</include>

執行：

```sh
bun src/execute-locally.ts
```

```txt
Loaded Ada from 200
```

試一個不存在的使用者 — 把 path id 改成 `8` 再跑一次：

```txt
User not found
```

成功時：`error` 是 `null`，`user` 是 `200` Struct 輸出，`response` 是 `DecodedResponse<User>`。已宣告的 `404`：`error.code` 是 `'HTTP_STATUS'`，`error.status` 是 `404`，`error.data` 是型別化的 `NotFound`。失敗時第二項是 `undefined`。

## Step 4 — 指向真實 API

在 `src/real-api.ts` 匯入同一個 `getUser`，並用服務的 base URL 建立 client。只有在把範例位址換成實作了 `GET /v1/users/:id`、且 body 符合那些契約的服務之後，才執行這個版本。

<include cwd>examples/start/real-api.ts#example</include>

API 定義留在 SDK 模組。服務位址、憑證、interceptors 與執行生命週期留在應用程式。兩個 client 使用同一份 Defjs 端點契約。

## 發佈定義

更多應用程式需要這份定義時，把它移進 SDK 套件。匯出 `getUser`，帶上它的 TypeScript 宣告，並宣告相容的 Core 版本。使用端接著從套件匯入，而不是從 `./define-request.ts` 匯入；client 設定仍是他們自己的。完整的套件設定見[建置並發佈 SDK](/zh-Hant-TW/recipes/publish-http-sdk)。

## 結果不一樣時

- 壞輸入 → `REQ_INPUT_INVALID`；失敗的 `builder` → `REQ_BUILD_FAILED`
- 非 2xx 狀態 → `HTTP_STATUS`；若宣告過 `error` 且它的 body 解碼成功，`error.data` 就有型別
- 已宣告的 JSON body 卻是另一種媒體類型 → `RES_MEDIA_TYPE_INVALID`，在讀 body 之前就回報
- 已宣告的 body（2xx 用 `output`，其餘用 `error`）解不出來 → `RES_DECODE_FAILED` 或 `RES_STRUCT_MISMATCH`，不論狀態碼是什麼
- Fetch 失敗／取消／期限 → `NET_UNREACHABLE`／`NET_ABORTED`／`NET_TIMEOUT`

期限是 `client({ abort: AbortSignal.timeout(ms) })`，歸類為 `NET_TIMEOUT`。手動取消是 `NET_ABORTED`。沒有 client 層級的預設期限。某一次呼叫需要自己的 `abort` 時，衍生一個 client；見 [Client](/zh-Hant-TW/docs/client)。取消只告訴你呼叫端看到什麼 — 不代表伺服器寫入有沒有提交。
