# 快速開始：你的第一個 SDK 操作 [#getting-started-one-http-request]

在本指南中，你將建立一個定義 `GET /orders/:id` 的 SDK 模組，並分別從兩個獨立的應用程式模組呼叫它：一個使用離線的模擬傳輸層，另一個則直接指向實際運作的 API。

## 1. 安裝 `@defjs/core`

`@defjs/core` 是一個零依賴的 ESM 套件，可在瀏覽器、Bun 以及 Node.js 目前 LTS 中執行。請確保你的 `package.json` 中已設定 `"type": "module"`。

```sh
bun add @defjs/core
```

## 2. 定義 SDK 並從應用程式呼叫

請將操作定義留在專屬的 SDK 模組中（`src/define-request.ts`），並在你的應用程式端建立 Client（`src/execute-locally.ts` 或 `src/real-api.ts`）：

### 這三個檔案如何協同運作

1. **`src/define-request.ts`（SDK 定義端）**：
   - 使用 `struct` 宣告 `input`、`output`（用於 `2xx` 回應）與 `error`（用於非 `2xx` 回應）。
   - 提供同步的純函式 `builder`，將 `input` 對應至 `{ path }`。凡是宣告了 `input`，就必須提供明確的 `builder`。
   - 匯出 `getOrder`，過程中不建立也不會捕捉任何 Client。
2. **`src/execute-locally.ts`（離線測試執行端）**：
   - 使用 `withHTTPHandle(...)` 設定 Client，在不觸及網路的情況下執行完整的 Defjs 管線（輸入驗證、URL 解析、狀態分派與回應 struct 解析）。
3. **`src/real-api.ts`（正式環境執行端）**：
   - 匯入完全相同的 `getOrder` 操作，並以 `withEndpoint(...)` 設定的線上基礎網址呼叫它。

## 3. 執行本機範例

使用 Bun 執行 `src/execute-locally.ts`：

```sh
bun src/execute-locally.ts
```

```txt
Loaded paid from 200
```

如果你將輸入從 `{ id: 7 }` 改為 `{ id: 8 }`，Mock 伺服器會回傳 `404`，而 Defjs 會將宣告的 `error` struct 解碼並填入 `error.data`：

```txt
Order not found
```

## 4. 理解 error-first tuple

每次 HTTP 呼叫都會解析為 `[error, data, response]`：

- **在 `2xx` 成功時**：`error` 為 `null`，`data` 為通過驗證的 `output` 值（`Order`），`response` 則為 `DecodedResponse<Order>`。
- **在已宣告的非 `2xx` 狀態碼時**：`error.code` 為 `'HTTP_STATUS'`，`error.status` 為狀態碼數值（`404`），`error.data` 則是通過驗證的 `error` struct（`NotFound`）。
- **在輸入無效、解碼失敗或網路錯誤時**：`error.code` 會精準識別失敗的階段：
  - `REQ_INPUT_INVALID` / `REQ_BUILD_FAILED` — 呼叫端傳入的輸入無效，或 `builder` 執行時拋出例外
  - `RES_MEDIA_TYPE_INVALID` — 宣告為 JSON 的回應本文收到了非 JSON 的 `Content-Type`（在讀取本文前即會直接拒絕）
  - `RES_DECODE_FAILED` / `RES_STRUCT_MISMATCH` — 回應本文無法讀取或結構不符合 schema
  - `NET_UNREACHABLE` / `NET_ABORTED` / `NET_TIMEOUT` — 傳輸層錯誤、手動取消請求，或 `AbortSignal.timeout(ms)` 逾時

若要傳入單次呼叫的逾時限制或取消訊號，請衍生出單次呼叫的 Client 值：`getOrder(client({ signal: AbortSignal.timeout(5_000) }), { id: 7 })`。
