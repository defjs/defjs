# 開始使用：一個 HTTP 請求

這次先以 SDK 作者的身分定義並匯出 `GET /users/:id`，再以應用程式開發者的身分匯入它、建立 Client 並執行。兩個檔案分別負責契約與呼叫，`200` 與已宣告的 `404` 都保留型別。本機 handle 讓第一次執行能夠離線完成；連接真實服務時繼續使用同一個定義。

## Step 1 — 安裝

`@defjs/core` 是 ESM，可在 Node.js 或 Bun 上執行。Node.js 22.18+（或 24+）透過 type stripping 直接執行 `.ts` 檔；更舊的 22.x 版本需要 `--experimental-strip-types`。package.json 要保留 `"type": "module"`。瀏覽器環境仍要有 bundler 與 Fetch。

## Step 2 — 定義請求

建立 `src/define-request.ts`，匯出 SDK 的 `getUser` 端點。Input Struct 描述呼叫端提供的值，`builder` 決定值在請求中的位置。這裡整個 input 就是 path 物件，沒有 alias 的純量欄位會填入 `:id`。定義檔案不建立 Client，也不發出請求。

<include cwd meta="define-request.ts">
  examples/start/define-request.ts#example
</include>

`output` 是 2xx body。`error` 是其餘每個狀態。各一個 struct。那些 body 形狀不同時，用 `struct.or(...)` 或判別聯集。

`defineRequest(...)` 回傳 endpoint。呼叫 `getUser(...)` 會建立要傳給 `client.execute(...)` 的不透明 command。上面的 `builder` 是放置 input 的函式，不是 endpoint。

## Step 3 — 本機執行

建立 `src/execute-locally.ts`，從 `./define-request.ts` 匯入 `getUser`。應用程式擁有 Client，並為它設定服務位址與本機 Fetch handle；不需網路也能完成輸入驗證、`Request` 建立、狀態分派與 body 解析。

## Step 4 — 指向真實 API

服務實作了 `GET /v1/users/:id` 且 body 符合契約時，在 `src/real-api.ts` 匯入同一個 `getUser`。應用程式只需建立指向真實 base URL 的 Client，省略本機的 `withHTTPHandle(...)`。請將範例位址替換為實際部署的服務。

SDK 定義保持不變。應用程式擁有服務位址、身分驗證與取消策略；定義中的 Struct、builder 與 HTTP 語意仍由 Defjs 執行。要將定義交給其他專案時，繼續閱讀[建置並發佈 SDK](/zh-Hant-TW/recipes/publish-http-sdk)。

## 結果不一樣時

- 壞輸入 → `REQ_INPUT_INVALID`；衝突的取消 options → `REQ_OPTIONS_INVALID`；失敗的 `builder` → `REQ_BUILD_FAILED`
- 非 2xx 狀態 → `HTTP_STATUS`；若宣告過 `error` 且它的 body 解碼成功，`error.data` 就有型別
- 已宣告的 JSON body 卻是另一種媒體類型 → `RES_MEDIA_TYPE_INVALID`，在讀 body 之前就回報
- 已宣告的 body（2xx 用 `output`，其餘用 `error`）解不出來 → `RES_DECODE_FAILED` 或 `RES_STRUCT_MISMATCH`，不論狀態碼是什麼
- Fetch 失敗／取消／逾時 → `NET_UNREACHABLE`／`NET_ABORTED`／`NET_TIMEOUT`

`timeout` 必須是 `1..2_147_483_647` 的正 safe integer。合法的取消形狀：`{ signal }`、`{ timeout }`、`{ abort }`，或 `{ signal, timeout }`／`{ signal, abort }`。`{ abort, timeout }` 一起傳是非法的。取消只告訴你呼叫端看到什麼 — 不代表伺服器寫入有沒有提交。
