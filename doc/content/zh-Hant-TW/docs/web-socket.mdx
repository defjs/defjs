# WebSocket 工作階段

`defineWebSocket` 用於在 SDK 中宣告雙向 WebSocket 契約：包含路徑模板、選用的 `input` 與 `builder`（僅限 `path` 與 `query`）、`incoming` 與 `outgoing` 訊息 struct、佇列大小邊界以及靜態子協定。取用端應用程式則在 Client 上設定心跳機制、斷線重連以及生命週期清理。

## 1. 定義契約並執行工作階段

在 `incoming` 或 `outgoing` 上使用 `struct.discriminatedUnion(...)` 為多種封包型別建立模型。釋放回傳的 `WebSocketSession` 時，可以使用 `await using` 或明確呼叫 `session.close()` + `await session.closed`：

<Tabs items={["sdk/ticks-socket.ts", "app/session.ts", "Single-file quick look"]}>
<Tab value="sdk/ticks-socket.ts">

```ts
import { defineWebSocket, struct } from "@defjs/core";

export const TickFrame = struct.discriminatedUnion("type", [
  struct.object({
    type: struct.literal("tick"),
    symbol: struct.string(),
    price: struct.number(),
  }),
  struct.object({
    type: struct.literal("subscribed"),
    symbol: struct.string(),
  }),
]);

export const SubscribeCommand = struct.object({
  type: struct.literal("subscribe"),
  symbol: struct.string(),
});

export const openTicker = defineWebSocket({
  path: "/market/ws",
  operation: "market.ticker",
  incoming: TickFrame,
  outgoing: SubscribeCommand,
  maxIncomingQueueSize: 64,
});
```

</Tab>
<Tab value="app/session.ts">

```ts
import { createClient, withEndpoint } from "@defjs/core";
import { openTicker } from "../sdk/ticks-socket.ts";

const client = createClient(withEndpoint("https://api.example.com"));

async function main() {
  const [error, session] = await openTicker(client);
  if (error) {
    console.error(error.code);
    return;
  }

  await using active = session;
  active.send({ type: "subscribe", symbol: "ACME" });

  for await (const message of active.receive) {
    if (message.type === "tick") {
      console.log(message.symbol, message.price);
      break;
    }
  }
}

void main();
```

## 2. 訊息驗證與方向性規範

- **接收封包（`session.receive`）**：文字、`ArrayBuffer`、型別化陣列以及 `Blob` 封包皆會被解碼為 UTF-8、剖析為 JSON，並對照 `incoming` 進行驗證。格式錯誤的 JSON 或結構不符會回報給 `session.onRuntimeError` 並直接丟棄，而不會中斷工作階段。`session.receive` 屬於單一消費者；重複請求第二個迭代器會拋出 `TypeError`。
- **發送封包（`session.send(payload)`）**：同步對照 `outgoing` 進行驗證，套用 `.alias()` 與編解碼器，並透過 `JSON.stringify` 序列化。在 `open` 狀態下會立即發送；在 `reconnecting` 重新連線期間會進入佇列緩衝（若 `maxOutgoingQueueSize > 0`）；若負載無效、佇列已滿/停用，或工作階段已關閉，則會同步拋出例外。

## 3. 工作階段狀態與觀察者

| 成員                 | 說明                                                                                                  |
| -------------------- | ----------------------------------------------------------------------------------------------------- |
| `state`              | `'idle' \| 'connecting' \| 'open' \| 'reconnecting' \| 'closing' \| 'closed' \| 'aborted' \| 'error'` |
| `connection`         | 最新實體 Socket 的即時快照（`generation`、`url`、`protocol`、`extensions`）                           |
| `bufferedAmount`     | 當前實體 Socket 上未傳送的位元組數（未連線時為 `0`）                                                  |
| `receive`            | 經由驗證的 `incoming` 訊息單一消費者非同步可迭代物件                                                  |
| `onStateChange(fn)`  | 訂閱狀態轉換事件；回傳 `unsubscribe` 取消訂閱函式                                                     |
| `onRuntimeError(fn)` | 訂閱連線建立後的封包/剖析錯誤；回傳 `unsubscribe` 取消訂閱函式                                        |
| `closed`             | 解析為最終終結結果的 Promise（`kind: 'closed' \| 'aborted' \| 'error'`）                              |

## 4. 重新連線、心跳檢測與佇列控制

重新連線與心跳檢測皆屬於選擇性啟用，可透過 Client 選項（`withWebSocketReconnect`、`withWebSocketHeartbeat`）或單次呼叫的衍生 Client 選項（`client({ reconnect, heartbeat })`）設定：

- **重新連線**：啟用時的預設值為 `attempts: 3`、`delayMs: 1000`、`factor: 2`、`maxDelayMs: 30000`、`jitter: 0`。每次實體連線 `open` 都會重設斷線重試預算。`beforeConnect({ attempt, signal })` 會在初始連線與每次重連嘗試之前執行。
- **心跳檢測**：定期透過 `outgoing` struct 發送 `message()`，並在 `timeoutMs` 內等待符合 `isAck(msg)` 的確認封包。相符的 ACK 封包會被心跳監控器消耗，不會轉發至 `session.receive`。遺漏 ACK 會終結該工作階段。
- **佇列邊界**：
  - `maxIncomingQueueSize`（必填正整數）：佇列溢位會以 `CAP_QUEUE_OVERFLOW` 終止工作階段。在工作階段開啟期間請持續消費 `session.receive`。
  - `maxOutgoingQueueSize`（選用非負整數，預設為 `0`）：僅在 `state === 'reconnecting'` 期間緩衝 `session.send()` 呼叫，並在發布下一次 `open` 之前將它們排空發出。

## 5. 子協定與身分驗證 [#protocols-and-authentication]

瀏覽器環境中的 WebSocket 不支援在交握期間自訂任意 HTTP 標頭，因此 WebSocket 的 `builder` 函式僅能回傳 `{ path?, query? }`。

- **子協定優先權順序**：`client({ protocols })` 覆蓋 `withWebSocketProtocols(...)`，後者再覆蓋 `defineWebSocket({ protocols })`。
- **URL 協定轉換**：Defjs 會自動將解析後的端點從 `http:` 轉為 `ws:`，或從 `https:` 轉為 `wss:`。
- **憑證**：`withCredentials(true)` 僅適用於 Fetch（HTTP/SSE）。請使用 Cookie / Session 機制、子協定或短期連線票證（Ticket）驗證 WebSocket——避免將長期密鑰放入 query string。

## 6. 關閉機制與擁有權

呼叫 `session.close(code?, reason?)`（其中 `code` 為 `1000` 或 `3000..4999`，`reason` 不超過 123 個 UTF-8 位元組）並等待 `await session.closed`，或者使用 `await using`：
