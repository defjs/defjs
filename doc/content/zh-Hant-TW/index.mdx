# Defjs

**為更友善的 SDK 設計而生。**

Defjs 幫助團隊把 API 做成可重用的 TypeScript SDK。`def` 代表 `define`：描述服務提供的操作，從模組或 npm 套件匯出，再讓每個應用程式設定自己的 client 去呼叫它們。

## 定義 SDK，設定應用程式

| SDK 作者                                 | SDK 使用端                               |
| ---------------------------------------- | ---------------------------------------- |
| 定義操作、input、請求對應、回應與錯誤    | 選擇服務位址、憑證、interceptors 與傳輸  |
| 匯出具型別的 HTTP、SSE 與 WebSocket 端點 | 匯入那些端點，並用 Defjs client 呼叫它們 |
| 維護並發佈 API 契約                      | 處理結果，並擁有取消、串流與 session     |

SDK 定義不會捕捉應用程式的 client。同一個匯出的端點可以用不同的 client 設定服務瀏覽器應用程式、伺服器或本機測試。兩邊仍使用 Defjs 的執行契約與相容的 Core 版本。

SDK 匯出一項操作：

<include cwd meta="get-health.ts">
  examples/home/get-health.ts#example
</include>

應用程式匯入它，並擁有執行：

<include cwd meta="app.ts">
  examples/home/app.ts#example
</include>

呼叫 `getHealth(client)` 就會啟動請求。發佈定義之後，使用端從你的 SDK 套件匯入，而不是從本機檔案匯入。

## 最佳實踐

定義與 client 彼此獨立。把應用程式的 client 當第一個引數傳入，例如 `getHealth(client)`。服務位址與憑證也由應用程式持有。先檢查 error-first tuple。`error` 有值時，報告 `error.code`，從函式返回，然後再讀取成功值。

## 建置你的 SDK

1. 在分開的 SDK 與應用程式檔案裡[定義並執行你的第一個操作](/zh-Hant-TW/docs/start)。
2. 描述 SDK 匯出的[資料契約](/zh-Hant-TW/docs/struct)與 [HTTP 操作](/zh-Hant-TW/docs/http)。
3. 用 JavaScript、宣告，以及相容的 Core 相依[測試並發佈 SDK 套件](/zh-Hant-TW/recipes/publish-http-sdk)。
4. 設定使用端應用程式的 [Client](/zh-Hant-TW/docs/client)，再依需要加上框架或可觀測性整合。

[設計決策](/zh-Hant-TW/docs/design-decisions)說明為什麼 API 定義與執行有各自的擁有者。發佈套件之前，也可以在同一個應用程式裡使用這套結構。

## 選傳輸方式

| 你要的                    | 從這裡開始                               | 成功時的結果                                                        |
| ------------------------- | ---------------------------------------- | ------------------------------------------------------------------- |
| 請求 + 依狀態碼區分的回應 | [HTTP](/zh-Hant-TW/docs/http)            | 解碼後的資料 + `DecodedResponse`（沒有宣告 output 時是 `HttpMeta`） |
| 長生命週期的伺服器事件流  | [SSE](/zh-Hant-TW/docs/sse)              | 一個串流 + 啟動時的 `open` 快照                                     |
| 雙向工作階段              | [WebSocket](/zh-Hant-TW/docs/web-socket) | 一個 session + 啟動時的 `connection` 快照                           |

三種傳輸都是同一套順序：定義操作，再帶著應用程式的 client 與呼叫端的 input 呼叫它。

## 選套件

| 套件                          | 何時用                                                                                                      |
| ----------------------------- | ----------------------------------------------------------------------------------------------------------- |
| `@defjs/core`                 | 定義 SDK 操作與契約；建立 client，並呼叫 HTTP、SSE 與 WebSocket 操作                                        |
| `@defjs/react`                | `ClientProvider` / `useClient` — 見 [React](/zh-Hant-TW/docs/integrations/react)                            |
| `@defjs/vue`                  | Plugin + `injectClient` — 見 [Vue](/zh-Hant-TW/docs/integrations/vue)                                       |
| `@defjs/opentelemetry-server` | 出站 spans、metrics 與 logs — 見 [OpenTelemetry Server](/zh-Hant-TW/docs/integrations/opentelemetry-server) |

## 結果形狀

三種傳輸都回傳 error-first 的三項 tuple。位置對齊，意義不一樣：

- HTTP → `[error, data, response]`
- SSE → `[error, stream, open]`
- WebSocket → `[error, session, connection]`

失敗時第二項是 `undefined`。HTTP 的第三項也是 `undefined`，因為 fault 已經帶著回應 metadata。SSE 與 WebSocket 的第三項，則是失敗之前若已捕捉到啟動快照，就是那份快照。詳見[錯誤](/zh-Hant-TW/docs/errors)。

## 擁有權一句話講完

HTTP 過期就 abort。SSE 要 close 並 `await stream.closed`。WebSocket 要 close 並 `await session.closed`。在伺服器上，若 options 會捕捉 cookies、auth 或 tenant 資料，請在請求邊界內建立 client。記錄前先遮罩 URL、headers、bodies。

Defjs 提供定義、驗證與執行。應用程式選擇快取與重試策略；串流重連需要明確啟用。手寫的 SDK 套件目前已支援。CLI 工具與 OpenAPI／SDK 產生仍在計畫中。
