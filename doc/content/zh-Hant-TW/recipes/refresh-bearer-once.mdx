# 401 後重新整理 Bearer token 一次

在 Defjs 中，`next(request)` 只會向內呼叫攔截器鏈剩下的部分——不會從最外層攔截器重新分派。請把 token 附加、single-flight 重新整理去重，以及一次性的 `401` 重試，全部放在**同一個** HTTP 攔截器裡，這樣外層的日誌或計時攔截器就不會執行兩次：

本文可以重播，不代表業務操作可以重複執行。遇到符合條件的 401 時，這個攔截器也會重送 JSON `POST`：兩次 HTTP 傳遞，第一次被拒，第二次被接受。只有在驗證先於業務處理常式拒絕第一次傳遞時，才能拿它來做寫入；兩次傳遞都要帶同一個穩定的 idempotency key，並由伺服器端去重。若沒有這項契約，請回傳 401，不要自動重播寫入。完整範例不會重播 `ReadableStream` 請求本文。

關於洋蔥式順序與重試邊界，請參閱[攔截器](/zh-Hant-TW/docs/interceptors)。
