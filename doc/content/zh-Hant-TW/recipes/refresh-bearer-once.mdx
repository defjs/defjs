# 401 後更新 Bearer Token 並重試一次

在 Defjs 中，`next(request)` 只會向內呼叫攔截器鏈的後續部分——不會從最外層攔截器重新發起分派。請將 Token 的附加、單飛（Single-flight）更新防重複請求，以及遭遇 `401` 時的一次性重試，全部放在**同一個** HTTP 攔截器中，這樣外層的日誌記錄或計時攔截器就不會被重複執行兩次：

export const getInvoice = defineRequest({
  method: "GET",
  path: "/v1/invoice",
  output: struct.object({ total: struct.number() }),
  error: struct.object({ code: struct.literal("expired_token") }),
});

```ts
import { createHttpInterceptor } from "@defjs/core";

export type Credential = { accessToken: string };

export function refreshingBearer(
  read: () => Credential,
  refresh: (stale: Credential) => Promise<Credential>,
) {
  let flight: Promise<Credential> | undefined;

return createHttpInterceptor(async (request, next) => {
const authorize = (credential: Credential) => {
const headers = new Headers(request.headers);
headers.set("authorization", `Bearer ${credential.accessToken}`);
return { ...request, headers };
};

    const used = read();
    const response = await next(authorize(used));
    const body = response.body;
    if (
      (typeof ReadableStream !== "undefined" &&
        request.body instanceof ReadableStream) ||
      response.status !== 401 ||
      typeof body !== "object" ||
      body === null ||
      !("code" in body) ||
      body.code !== "expired_token"
    ) {
      return response;
    }

    const current = read();
    if (current.accessToken !== used.accessToken) {
      return next(authorize(current));
    }

    flight ??= refresh(used).finally(() => {
      flight = undefined;
    });
    const refreshed = await flight;
    return next(authorize(refreshed));

});
}

````

請求 body 可以重播，不代表業務操作可以重複執行。符合條件的 401 之後，這個攔截器也會重新傳送 JSON `POST`：共兩次 HTTP 傳遞，第一次被拒絕，第二次被接受。只有當驗證在業務處理函式執行前拒絕第一次傳遞時，才能將它用於寫入；兩次傳遞之間必須保留同一個穩定的冪等鍵，並由伺服器端去除重複。如果沒有這項契約，就應回傳 401，而不是自動重播寫入操作。完整範例不會重播 `ReadableStream` 請求 body。

關於洋蔥模型執行順序與重試邊界規範，請參閱[中介層](/zh-Hant-TW/docs/interceptors)。
