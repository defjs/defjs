# 使用 SSE 事件串流

每個 `EventStreamHandle` 提供單一非同步迭代器。請始終將 `stream.close(...)` 與 `await stream.closed` 放在 `finally` 區塊中，避免提前執行的 `break` 或 `return` 導致底層 Fetch 串流發生資源外洩：

<Tabs items={["sdk/deployments.ts", "app/main.ts", "deploy-events.ts"]}>
  <Tab value="sdk/deployments.ts">
```ts
import { defineEventStream, struct } from "@defjs/core";

export const deployEvents = defineEventStream({
  path: "/deployments/events",
  events: {
    line: struct.object({ text: struct.string() }),
  },
});
```
  </Tab>
  <Tab value="app/main.ts">
```ts
import { createClient, withEndpoint } from "@defjs/core";
import { deployEvents } from "../sdk/deployments.ts";

const client = createClient(withEndpoint("https://api.example.com"));

async function main() {
const [error, stream] = await deployEvents(client);
if (error) {
console.error(error.code);
return;
}
try {
for await (const event of stream) {
if (event.event === "line") {
console.log(event.data.text);
break;
}
}
} finally {
stream.close("consumer-finished");
await stream.closed;
}
}

void main();

````
  </Tab>

  </Tab>

當伺服器的第一個事件為 `line` 且資料為 `{ "text": "build started" }` 時，該腳本會輸出：

```txt
build started
````

- 除非你在 Client 上設定了 [`withSSEReconnect(...)`](/zh-Hant-TW/api/core/withssereconnect)，否則 SSE 在發生網路或讀取失敗時預設不會自動重連。
- 當以選項物件啟用 `withSSEReconnect` 時，每次斷線的 `attempts` 預設為 `3` 次，並在交握成功後重設（`attempts: 0` 會停用重連）。若未提供自訂的 `shouldReconnect`，只有可重放本文的 `GET`、`HEAD`、`OPTIONS`、`PUT` 與 `DELETE` 請求才會重連。詳細資訊請參閱 [SSE 事件串流](/zh-Hant-TW/docs/sse)。
