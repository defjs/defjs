# 消費 SSE 串流

每個 `EventStreamHandle` 都只提供一個非同步迭代器。一律把 `stream.close(...)` 與 `await stream.closed` 放在 `finally` 區塊中，讓提早執行的 `break` 或 `return` 不會漏掉底層的 Fetch 串流：

當伺服器的第一個事件為 `line` 且資料為 `{ "text": "build started" }` 時，該腳本會輸出：

```txt
build started
```

- 除非在 client 上設定 [`withRetry(...)`](/zh-Hant-TW/api/core/withretry)，否則 SSE 不會在網路或讀取失敗時自動重連。
- 設定 `withRetry(...)` 後，每次中斷的 `maxRetries` 預設為 `3`，並在交握成功時重設（`maxRetries: 0` 會停用重試）。沒有自訂 `shouldRetry` 時，只有 `GET`、`HEAD`、`OPTIONS`、`TRACE`、`PUT` 與 `DELETE` 請求會重試。帶有 `ReadableStream` 本文的請求永遠不會重試。詳見 [SSE 事件串流](/zh-Hant-TW/docs/sse)。
