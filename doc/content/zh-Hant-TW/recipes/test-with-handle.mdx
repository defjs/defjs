# 使用本機 Fetch handle 進行測試

`withHTTPHandle(...)` 只會換掉單一測試 `Client` 底層的 `fetch`，你的請求定義、攔截器、狀態碼分派與 `struct` 解碼流程照常執行，而且全程不需真的建立網路連線：

### 撰寫測試時必知的三個細節

- **為什麼要在 Handle 裡包一層 `new Request(input, init)`**：`withHTTPHandle` 接收的參數跟標準 `fetch(input, init)` 相同，統一用 `new Request(input, init)` 包起來後，就能用統一介面讀取 `method`、`url`、`headers` 與 `await request.json()`。
- **為什麼要填 `withEndpoint("https://fixture.invalid")`**：`Client` 在進到 `withHTTPHandle` 前會先解析並驗證基礎 URL；`.invalid` 是 RFC 保留網域，即使寫漏也不會真的送出公網 DNS 查詢。
- **三種常見回傳如何模擬**：
  - `2xx` 成功：回傳 `Response.json(...)` -> 得到 `[null, data, response]`。
  - `4xx` / `5xx` 錯誤狀態：回傳 `Response.json(..., { status: 422 })` -> 得到 `err.code === "HTTP_STATUS"`。
  - 斷網／連線失敗：直接 `Promise.reject(new TypeError("fetch failed"))`（或直接拋出錯誤）-> 得到 `err.code === "NET_UNREACHABLE"`。注意**不要**回傳 `Response.error()`，只要回傳 `Response`（即使狀態碼是 `0`），Defjs 都會當成收到 HTTP 回應而歸類成 `HTTP_STATUS`。

在正式環境只要拿掉 `withHTTPHandle(...)`、改用指向真實服務的 `withEndpoint(...)`，就能呼叫完全相同的 `getOrder` 操作。想了解業務函式、重試／Token 刷新攔截器與元件測試，請參閱 [測試](/zh-Hant-TW/docs/testing) 與 [Client](/zh-Hant-TW/docs/client)。
