<ApiReference identity="@defjs/core:WebSocketExecuteOptions" />

```ts
type WebSocketExecuteOptions<TIncoming = unknown, TOutgoing = unknown> = UseWebSocketConfig<TIncoming, TOutgoing> & {
  signal?: AbortSignal
}
```

[`UseWebSocketConfig`](/ja-JP/api/core/usewebsocketconfig-type) に `signal` を足したものです。展開すると次のとおりです。

```ts
type WebSocketExecuteOptions<TIncoming = unknown, TOutgoing = unknown> = {
  beforeConnect?: (context: { attempt: number; signal: AbortSignal }) => void | Promise<void>
  heartbeat?: WebSocketHeartbeatConfig<TIncoming, TOutgoing>
  protocols?: readonly string[]
  reconnect?: ClientWebSocketOptions['reconnect']
  signal?: AbortSignal
} & ({ abort?: AbortSignal; timeout?: never } | { abort?: never; timeout?: number })
```

- `abort` と `timeout` は同時に使えません。型は両方の指定を拒否し、実行時に両方を渡すと `REQ_OPTIONS_INVALID` の fault で失敗します。
- `signal` はどちらとも組み合わせられます。`abort` の別名ではありません。
- `timeout` は `2_147_483_647` 以下の正の安全な整数でなければなりません。セッションを開くのにかけられる時間を制限するもので、再接続では再び適用されません。
- `beforeConnect`、`heartbeat`、`protocols`、`reconnect` は、この呼び出しに限ってクライアントレベルの options を上書きします。
- `reconnect` を設定すると、`attempts` のデフォルトは接続障害 1 回ごとに `3` です。`0` は再試行を無効にします。`open` が成功すると、再試行の残り回数が初期値に戻り、バックオフの指数もリセットされます。`attempts` を省略しても、1 回の接続障害に対する再試行が無制限になるわけではありません。検証規則と最終的な待ち時間の上限は [`withWebSocketReconnect`](/ja-JP/api/core/withwebsocketreconnect) を参照してください。

[`WebSocketHeartbeatConfig`](/ja-JP/api/core/websocketheartbeatconfig-type) を見てください。
