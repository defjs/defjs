# HTTP

型付きリクエストを宣言し、入力からコマンドを組み立てて実行します。

## defineRequest()

<ApiSignature name="defineRequest" />

- **definition** — `method`、`path`、任意の `input` struct、任意の `output` と `error` struct、任意の `operation`。`input` を宣言した定義では、明示的な `builder` が必須です。`input` は引数を定義するだけで、各値をどこに置くかは builder だけが決めます。`builder` を省略できるのは `input` がない定義だけです。これらの `definition` のメンバーは [`RequestDefinition`](/ja-JP/api/core/requestdefinition-type) にあります。`builder` が必須なのは `input` を宣言したときだけです。
- **戻り値** エンドポイントです。入力を渡して呼ぶと `HttpCommand` になります。

<include cwd>examples/api/define-request.ts#example</include>

`output` は 2xx ボディ用の struct 1 つ、`error` は 2xx 以外すべてのボディ用の struct 1 つです。どちらも status でキー分けされません。省いた側のボディは読まれません — [宣言は断言である](/ja-JP/docs/design-decisions#宣言は断言である) を参照してください。

## executeHttpCommand()

<ApiSignature name="executeHttpCommand" />

`client.execute` が使う低レベル入口です。アプリコードでは `client.execute(command, options)` を呼んでください。

- **戻り値** [`HttpAwaitResult`](/ja-JP/api/core/httpawaitresult-type) に書かれたタプル形式へ解決する promise。

2xx 以外の status は、`error` struct を宣言していないか、宣言した `error` ボディがデコードできる場合に `HTTP_STATUS` になります。fault の `data` は、`error` を宣言していればデコード済みのエラーボディ、していなければ `undefined` です。宣言した `error` ボディを読めない場合（メディアタイプが違う、JSON が不正）や struct に一致しない場合、fault は代わりに `RES_MEDIA_TYPE_INVALID`、`RES_DECODE_FAILED`、`RES_STRUCT_MISMATCH` のいずれかになり、レスポンスの status はそのメタデータに引き続き含まれます。失敗時のタプル第三要素は `undefined` で、レスポンスのメタデータは fault が持ちます。

## fetchHandler()

<ApiSignature name="fetchHandler" />

デフォルトの HTTP トランスポートです。`fetchImpl` のデフォルトは送信時に解決されるグローバルの `fetch` で、別のものは `withHTTPHandle` で与えます。差し替えられていないプラットフォームの Fetch には `(url, init)` を、差し替えたグローバルやカスタムハンドラーには `Request` を渡します。レスポンスがクライアントに届かなかったとき、または宣言されたボディの読み取りに失敗したときは、合成レスポンスで解決するのではなく reject します。

## makeResponse()

<ApiSignature name="makeResponse" />

ネットワークなしで `HttpResponse` を作ります（インターセプター、テスト）。デフォルトの status は `0` です。`ok` は 2xx のとき true です。返る値は、回線から来たレスポンスと同じメディアタイプ確認と同じ宣言 struct を通ります。信頼による短絡経路はありません。

## HttpExecuteOptions

<ApiSignature name="HttpExecuteOptions" />

`HttpExecuteOptions` は [`UseRequestConfig`](/ja-JP/api/core/userequestconfig-type) に `signal` を足したものです。`abort` と `timeout` は同時に指定できません。型は両方の指定を拒否し、実行時に両方を渡すと `REQ_OPTIONS_INVALID` で失敗します。`signal` はどちらかと組み合わせられ、`abort` の別名では**ありません**。有効な形は `{ signal }`、`{ timeout }`、`{ abort }`、`{ signal, timeout }`、`{ signal, abort }` です。`{ abort, timeout }` は無効です。`timeout` は `1..2_147_483_647` の正の安全な整数である必要があります。呼び出しで `timeout` を省くと、クライアントの `withTimeout` のデフォルトが適用されます（HTTP のみ）。`abort` と `signal` はそのデフォルトと組み合わさります。

## 型

### RequestDefinition

`method`、`path`、任意の `input`、`output`、`error`、`operation`、`builder` です。`responseType` はありません。宣言したボディの読み方は struct の kind が選びます。`input` を宣言した定義では、明示的な `builder` が必須です。`input` は引数を定義するだけで、各値をどこに置くかは builder だけが決めます。`builder` を省略できるのは `input` がない定義だけです。

### HttpAwaitResult

<ApiSignature name="HttpAwaitResult" />

成功時、第三要素が `body` を持つのは `output` を宣言していたときだけです。失敗時は `undefined` です — 存在したレスポンスのメタデータはすでに fault が抱えています。

### HttpRequest

正規化された送信リクエストです。`method`、`endpoint`、`headers`、`body`、`abort`、`operation`、`timeout`、`withCredentials`、`xsrf`、`downloadProgress` / `uploadProgress`、`baseEndpoint`、`queryString`、`queryParams` です。インターセプターが見る時点で `body` はすでに回線上の値（JSON なら JSON テキストの文字列）になっているので、HMAC やダイジェストの署名は struct の入力ではなくこの値に対して行ってください。インターセプターが見る `queryParams` は `new URLSearchParams(queryString)` です。ビルダーが `URLSearchParams` を返すと、そのインスタンスがそのまま渡されます。`responseType` と `errorResponseType` は readonly です。エンドポイントの `output` と `error` の struct kind から導出され、変更してはいけません。

### HttpMeta

<ApiSignature name="HttpMeta" />

レスポンスのメタデータで、レスポンスがクライアントに届いていれば使えます。`body` は**持ちません**。ボディは、宣言された struct がデコードしたあとにだけ存在します。

### DecodedResponse

<ApiSignature name="DecodedResponse" />

ボディが宣言された struct でデコードできたレスポンスです。この型を手にしていること自体がデコードが起きた証拠であり、だからデコード失敗は `HttpMeta` だけを報告します。

### HttpResponse

<ApiSignature name="HttpResponse" />

`body` は、レスポンスにボディがなかったときは `undefined` で、JSON の `null` は `null` のままです。この型はブランド付きなので、オブジェクトリテラルではなく `makeResponse` で作ってください。トランスポートが作り、インターセプターが見る回線上の形です。`body` はテキストか、すでにパースされた JSON で、デコード済みの値ではありません。JSON 表現では、文字列は JSON の文字列ルートであり、もう一度パースされません。バイトと blob は生のままで、一度だけパースされます。呼び出し側に届くのは `DecodedResponse` です。

### HttpProgressEvent

### HttpProgressFn

`loaded`、`total`、`lengthComputable` です。コールバックは非同期でも構いません。`onDownloadProgress` または `onUploadProgress` が例外を投げると、投げられた値を `cause` として呼び出しが `EXT_OBSERVER_FAILED` で失敗します。キャンセルと `timeout` は引き続き `NET_ABORTED` / `NET_TIMEOUT` を報告します。アップロードの進捗が報告されるのは、リクエストボディのストリーミングに対応するランタイムに限られます（Bun、Node）。ブラウザーでは、`Blob` / `File`、`ArrayBuffer`、`FormData` のボディはそのまま送られ、`onUploadProgress` は呼び出されません。

サーバーランタイムでは、FormData はボディ全体を Blob にバッファリングせず、シリアライズされたストリームを使い、実際の multipart boundary を保持します。有効な明示的 `Content-Length` がなければ総量は不明です。アップロード変換後も明示的な Content-Type は保持されますが、FormData はシリアライズ時の boundary を使う必要があります。`loaded` が数えるのはストリームのバイト数であり、サーバーの受信確認ではありません。`Content-Encoding` が identity 以外のダウンロードは `total: 0`、`lengthComputable: false` を報告します。そのストリームのバイト列はすでに展開されている場合があります。

[HTTP ガイド](/ja-JP/docs/http) と [Commands](/ja-JP/docs/commands) を見てください。

## RequestEndpoint

`defineRequest` の戻り値です。入力を渡して呼ぶと `HttpCommand` になります。

## BuilderInput

`builder` が見る、パース済みのエンドポイント入力です。オブジェクトノードは、その値を生成した struct の情報を保持するため、値に対応するエイリアス、`Date`、`bigint` のエンコードが適用されます。

## HttpRequestShape

<ApiSignature name="HttpRequestShape" />

4 つのフィールドはすべて任意です。`query` は `URLSearchParams` または record です。入れ子オブジェクトには実行時の `withQuerySerializer` が要ります。`headers` は `HeadersInit`、またはスカラーかスカラーの配列の record です。`path` は `:name` セグメントごとにスカラーを一つ渡します。

`GET` と `HEAD` の `body` は `never` です。それ以外では、ワイヤ値（`string`、`Blob`、`ArrayBuffer`、typed array または `DataView`、`FormData`、`URLSearchParams`、`ReadableStream<Uint8Array>`）か、JSON データ（`number`、`boolean`、`bigint`、`Date`、`null`、配列、文字列キーのオブジェクト）です。

## HttpCommand

リクエストのビルダーが出す不透明なコマンドです。`client.execute` に渡します。

## UseRequestConfig

任意の `onDownloadProgress` と `onUploadProgress` コールバックに、`abort` または `timeout`（両方は不可）が加わります。`HttpExecuteOptions` は `signal` を足します。

## RequestSuccessData

宣言された `output` struct から推論される成功ボディです。宣言がなければ `undefined` です。

## RequestErrorData

宣言された `error` struct から推論されるエラーボディです。宣言がなければ `undefined` です。

## HttpResponseType

`'arraybuffer' | 'blob' | 'json' | 'text'`

宣言した struct の kind から選ばれます（`string` → `text`、`blob` / `file` → `blob`、`arrayBuffer` → `arraybuffer`、それ以外 → `json`）。`defineRequest` のフィールドではありません。

## MakeResponseOptions

`makeResponse` 用のフィールドです。`status`、`statusText`、`url`、`headers`、`body`、`request`。
