# React

既存の `@defjs/core` クライアントを React ツリーに渡します。このパッケージはクライアントを作成せず、キャッシュせず、破棄しません。エントリポイントには `'use client'` が付いているので、クライアントコンポーネントから import してください。React 18 以降が必要です。

[React ガイド](/ja-JP/docs/integrations/react) を見てください。

## ClientProvider

<ApiSignature name="ClientProvider" />

Context プロバイダーです。`createClient` が返す `DerivableClient` を渡します。入れ子の `ClientProvider` はそのサブツリーのクライアントを上書きし、`useClient()` は最も近いものを読みます。別の `client` を渡すと、子孫から見える Context の値が変わります。

## useClient()

<ApiSignature name="useClient" />

`useClient(overrideClient)` は明示的なクライアントを優先して返します。省略または `undefined` なら最も近い `ClientProvider` を読み、どちらからもクライアントを取得できない場合にのみ `Error` を throw します。引数なしの `useClient()` も引き続き有効です。そのクライアントを操作に渡してください。フックは渡された [`DerivableClient`](/ja-JP/api/core/derivableclient-type) を返します。操作を実行する場所でリクエストオプションを付けて呼ぶと、`Client` 値が派生します。ステートセッターには渡さないでください。`setState(client)` はアップデーターとしてそれを呼びます。派生した `Client` 値は `ClientProvider` にも `useClient` にも渡せません。

明示的なクライアントがあっても、`useClient(explicitClient)` は必ずコンポーネントまたはカスタムフックのトップレベルで呼び、通常の関数やイベントコールバックでは呼ばないでください。`explicitClient ?? useClient()` はフックの条件付き呼び出しになるため無効です。明示的な値は Context に書き込まず、プロバイダーも作りません。フックは引き続き Context を購読します。

- **戻り値** 明示的に渡されたクライアント、または最も近いプロバイダーのクライアントそのものです。
- **例外** 明示的な引数と Context のどちらにもクライアントがない場合に `Error` を throw します。

## ClientProviderProps

<ApiSignature name="ClientProviderProps" />

`client` は必須で、アプリケーションが所有します。`children` は任意で、`useClient` を呼べるツリーです。
