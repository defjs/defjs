# SSE

イベントストリームを宣言し、実行し、イベントを反復してから閉じます。

## defineEventStream()

<ApiSignature name="defineEventStream" />

- **definition** — `path`、`events` マップ、必須で正の整数の上限 `maxBufferSize` と `maxQueueSize`、任意の `method`（デフォルト `'GET'`）、`operation`、`input`、`error` です。`input` を宣言した定義では、明示的な `builder` が必須です。`input` は引数を定義するだけで、各値をどこに置くかは builder だけが決めます。`builder` を省略できるのは `input` がない定義だけです。これらの `definition` のメンバーは [`EventStreamDefinition`](/ja-JP/api/core/eventstreamdefinition-type) にあります。`error` が必須なのは error struct の型を渡したときだけで、`builder` が必須なのは `input` を宣言したときだけです。
- **戻り値** エンドポイントです。入力を渡して呼ぶと `EventStreamCommand` になります。

## executeEventStreamCommand()

<ApiSignature name="executeEventStreamCommand" />

`client.execute` の低レベル入口です。アプリコードではクライアントを使ってください。

- **戻り値** `[null, stream, open]`、または `[error, undefined, open?]` です。`error` を宣言していれば fault はその struct の `Fault` で、していなければ `Fault<undefined>` です。

## 実行 options

## EventStreamExecuteOptions

<ApiSignature name="EventStreamExecuteOptions" />

`abort` か `timeout` の一方だけ（両方は不可）に加え、`signal` があります。進捗コールバックはありません。型は両方の指定を拒否し、実行時に両方を渡すと `REQ_OPTIONS_INVALID` で失敗します。`signal` はどちらとも組み合わせられます。`timeout` は開始の期限です。入力のパース、ビルダー、インターセプター、ハンドシェイクまでを含み、開いているストリームは中断しません。`withTimeout` は SSE には適用されません。

## EventStreamHandle

<ApiSignature name="EventStreamHandle" />

タプルの 3 番目の要素は `open` の起動時スナップショットです。再接続のあとは `stream.open` が最新の接続に追従します。その 3 番目の要素が返されたハンドルの接続の最初の成功したハンドシェイクのスナップショットになるのは、Defjs のネイティブハンドルか同じライブ `open` オブジェクトをそのまま渡すラッパーの場合だけであり、独自ハンドルや `open` を上書きするラッパーでは再接続後も現在公開している `open` が優先されるため、`closed` の共有によって URL のサニタイズやヘッダーのフィルタリングを迂回することはなく、Defjs は任意の変換から最初のハンドシェイクのメタデータを復元しません。 所有するスコープのクリーンアップには `await using stream = handle` を選んでください。disposer は Defjs の読み取りと再接続を止め、reader lock が解放されるのを待ちます。provider が制御する、止まった `ReadableStream.cancel()` の promise が終わることは約束しません。手動の `close()` / `closed` も残っています。

```ts
async function consume(handle: EventStreamHandle<unknown>): Promise<void> {
  await using stream = handle;
  for await (const event of stream) console.log(event);
}
```

`EventStreamHandle` の構造的実装は、今や `[Symbol.asyncDispose]()` を実装し、同じ所有 teardown 経路を返す必要があります。独自ハンドルにとってはコンパイル時の破壊的変更です。Defjs が返すハンドルを受け取るだけのコードには、新しい実行時呼び出しは要りません。

### EventStreamCloseInfo

<ApiSignature name="EventStreamCloseInfo" />

`kind` は `eof`、`aborted`、`error` のいずれかです。どのバリアントも `reason` と `cause` を持てます。`code` を持つのは `error` だけで、値は [`EventStreamFaultCode`](/ja-JP/api/core/eventstreamfaultcode-type) の一つで、`'CAP_BUFFER_EXCEEDED' | 'CAP_QUEUE_OVERFLOW' | 'EXT_HOOK_FAILED' | 'EXT_OBSERVER_FAILED' | 'NET_TIMEOUT' | 'NET_UNREACHABLE' | 'RES_DECODE_FAILED' | 'RES_MEDIA_TYPE_INVALID'` です。

## EventStructs

<ApiSignature name="EventStructs" />

キーは SSE のイベント名です。`event:` フィールドのないメッセージの名前は `message` です。どのキーにも一致しないときは `default` struct が使われます。`string` のイベント struct は生の `data` テキストを保ちます。それ以外の kind は JSON テキストです。`JSON.parse` してから struct です。だから裸の `struct.literal` には、引用のないトークンではなく JSON テキストが要ります。ハンドシェイクの `error` ボディは HTTP と同じ kind 規則です。`string` はテキスト、`blob` / `file` は blob、`arrayBuffer` はバイト列、それ以外は JSON です。

再接続はクライアントにあります（`withSSEReconnect`）。SSE の `jitter` は WebSocket と同じ、**0–1 の乗法因子**です。

リトライ予算とバックオフの指数は、ハンドシェイクの成功後にリセットされ、障害ごとに適用されます。不正な数値オプションは、ストリームを開く前に `REQ_OPTIONS_INVALID` を返します。`maxDelayMs` はジッター後の最終的な待ち時間に上限を設けます。検証規則、デフォルト、UTF-8 の `Last-Event-ID` の扱いについては、[`withSSEReconnect`](/ja-JP/api/core/withssereconnect) を参照してください。

パーサーは WHATWG SSE の行とフィールドの規則に従い、各物理ストリームの先頭にある UTF-8 BOM を 1 つだけ除去します。データや ID 値の U+FEFF は保持されます。ストリームの途中で BOM が付いたフィールド名は、未知のフィールドとして無視されます。複数行のデータは `\n` で結合され、空行でデータを持つイベントが配信されます。EOF 時点で未完了のイベントは破棄されます。

[SSE ガイド](/ja-JP/docs/sse) と [SSE ストリームを消費する](/ja-JP/recipes/consume-sse) を見てください。

## EventStreamDefinition

`path`、`events`、必須の `maxBufferSize` と `maxQueueSize`、任意の `method` / `operation` / `input` / `error` です。リクエストの形は HTTP と同じで、`body` も含みます。`GET` と `HEAD` はボディを返せません。`input` を宣言した定義では、明示的な `builder` が必須です。`input` は引数を定義するだけで、各値をどこに置くかは builder だけが決めます。`builder` を省略できるのは `input` がない定義だけです。

## EventStreamEndpoint

`defineEventStream` の戻り値です。入力を渡して呼ぶと `EventStreamCommand` になります。

## EventStreamRequestShape

ストリームの method と path に対する、`HttpRequestShape` と同じフィールドです。

## EventStreamCommand

不透明な SSE コマンドです。`client.execute` に渡します。

## StreamAwaitResult

`[null, stream, open]` または `[error, undefined, open?]` です。

## EventStreamData

`EventStructs` のマップから推論した、パース済みイベントペイロードです。
