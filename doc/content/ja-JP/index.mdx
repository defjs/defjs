# Defjs

**API 契約は一度だけ定義。実行制御はアプリケーションごとに構成。**

Defjs は、TypeScript SDK における 2 つの責務を明確に分離します。

- **SDK の定義 (`@defjs/core`)** — SDK 開発者は、`struct` スキーマとともに、型付けされた HTTP、SSE、WebSocket の各操作を宣言します。定義自体は純粋なデータであり、import してもネットワーク通信は開始されず、グローバルクライアントにもバインドされません。
- **アプリケーションでの実行** — 利用側アプリケーションは独自の `Client` を作成し（`createClient(withEndpoint(...))`）、認証情報、インターセプター、ロードバランサーを構成した上で、操作を呼び出す際にそのクライアントを渡します。

## なぜ定義とクライアントを分離するのか？

| 責務             | SDK 開発者（定義）                                                                                                  | アプリケーション（実行）                                                                     |
| ---------------- | ------------------------------------------------------------------------------------------------------------------- | -------------------------------------------------------------------------------------------- |
| **所有するもの** | HTTP メソッド、パステンプレート、`input` / `output` / `error` スキーマ、`builder` マッピング、静的な `operation` 名 | ベース URL、認証情報、認証インターセプター、ロードバランシング、タイムアウト、リソースの解放 |
| **配布するもの** | 再利用可能な ESM モジュールおよび `.d.ts` 型定義                                                                    | ブラウザ、サーバー、テスト環境それぞれの実行時設定                                           |
| **メリット**     | 実行環境への依存がゼロ。ブラウザ、SSR、テストのどこでも同じ定義が動作                                               | リトライ、フェイルオーバー、テレメトリ、ライフサイクル管理を完全に制御可能                   |

1. **[クイックスタート](/ja-JP/docs/start)** — 操作を定義し、ローカル Fetch ハンドルを使ってオフラインでテストした上で、実際のライブサービスに接続してみましょう。
2. **[コアアーキテクチャ](/ja-JP/docs/design-decisions)** — 6 つのレスポンスデコード規則、エラーファーストのタプル、リソース所有権の考え方を理解します。
3. **[SDK の定義](/ja-JP/docs/struct)** — [Struct](/ja-JP/docs/struct) で通信契約を宣言し、[HTTP](/ja-JP/docs/http)、[SSE](/ja-JP/docs/sse)、[WebSocket](/ja-JP/docs/web-socket) の各操作を export します。
4. **[クライアントと実行](/ja-JP/docs/client)** — [Client](/ja-JP/docs/client) の構成、型付けされた [エラーハンドリング](/ja-JP/docs/errors)、[インターセプター](/ja-JP/docs/interceptors) の追加、[ロードバランシングとフェイルオーバー](/ja-JP/docs/load-balancing) の設定、決定論的な [テスト](/ja-JP/docs/testing) の手法を学びます。

## サポートされているトランスポートと結果タプル

すべての操作は、各トランスポートのライフサイクルに合わせた 3 要素のエラーファーストタプルを返します。

| トランスポート                          | エントリポイント    | タプルの形状                   | ライフサイクルの管理責任                                               |
| --------------------------------------- | ------------------- | ------------------------------ | ---------------------------------------------------------------------- |
| **[HTTP](/ja-JP/docs/http)**            | `defineRequest`     | `[error, data, response]`      | 実行中のリクエストは `client({ signal })` 経由でキャンセル             |
| **[SSE](/ja-JP/docs/sse)**              | `defineEventStream` | `[error, stream, open]`        | `await using` または `stream.close()` + `await stream.closed` で解放   |
| **[WebSocket](/ja-JP/docs/web-socket)** | `defineWebSocket`   | `[error, session, connection]` | `await using` または `session.close()` + `await session.closed` で解放 |

HTTP の失敗時、タプルは `[error, undefined, undefined]` になります。これは、レスポンスのメタデータ（`HttpMeta`）を `error` 自身がすでに保持しているためです。SSE と WebSocket の場合、失敗前に起動時のスナップショットが取得できていれば、3 番目のスロットにそのスナップショットが格納されます。
