# Defjs

**よりよい SDK のために設計されています。**

Defjs は、チームが API を再利用できる TypeScript SDK にするのを助けます。`def` は `define` です。サービスが提供する操作を記述し、モジュールまたは npm パッケージから export し、各アプリケーションが自分のクライアントを構成してそれらを呼びます。

## SDK を定義し、アプリケーションを構成する

| SDK の作成者                                               | SDK の利用者                                                       |
| ---------------------------------------------------------- | ------------------------------------------------------------------ |
| 操作、入力、リクエストの配置、レスポンス、エラーを定義する | サービスアドレス、認証情報、インターセプター、トランスポートを選ぶ |
| 型付きの HTTP、SSE、WebSocket エンドポイントを export する | それらのエンドポイントを import し、Defjs のクライアントで呼び出す |
| API 契約を保守して公開する                                 | 結果を扱い、キャンセル、ストリーム、セッションを所有する           |

SDK の定義はアプリケーションのクライアントを捕まえません。同じ export されたエンドポイントが、異なるクライアント設定で、ブラウザーアプリケーション、サーバー、ローカルテストに使えます。どちらも Defjs の実行契約と互換性のある Core の版を使います。

SDK は操作を export します。

<include cwd meta="get-health.ts">
  examples/home/get-health.ts#example
</include>

アプリケーションはそれを import し、実行を所有します。

<include cwd meta="app.ts">
  examples/home/app.ts#example
</include>

`getHealth(client)` を呼ぶとリクエストが始まります。定義を公開すると、利用者はローカルファイルではなく SDK パッケージから import します。

## ベストプラクティス

定義は client から独立しています。アプリケーションの client を第一引数として渡します。たとえば `getHealth(client)` です。サービスアドレスと認証情報もアプリケーションのものです。先に error-first のタプルを確認します。`error` があるときは `error.code` を報告し、成功値を読む前に関数から return します。

## SDK を作る

1. [最初の操作を定義して動かす](/ja-JP/docs/start) を、SDK とアプリケーションの別ファイルで行います。
2. SDK が export する [データ契約](/ja-JP/docs/struct) と [HTTP 操作](/ja-JP/docs/http) を記述します。
3. JavaScript、型宣言、互換性のある Core 依存とともに [SDK パッケージをテストして公開します](/ja-JP/recipes/publish-http-sdk)。
4. 利用アプリケーションの [Client](/ja-JP/docs/client) を構成し、必要ならフレームワークや可観測性の連携を足します。

[設計上の判断](/ja-JP/docs/design-decisions) は、API 定義と実行の所有者が分かれている理由を説明します。パッケージを公開する前に、同じ構成を一つのアプリケーションの中で使うこともできます。

## トランスポートを選ぶ

| やりたいこと                         | ここから                            | 成功時の結果                                                                         |
| ------------------------------------ | ----------------------------------- | ------------------------------------------------------------------------------------ |
| リクエストと status ごとのレスポンス | [HTTP](/ja-JP/docs/http)            | デコード済みデータ + `DecodedResponse`（`output` を宣言していないときは `HttpMeta`） |
| 長寿命のサーバーイベントフィード     | [SSE](/ja-JP/docs/sse)              | 1 つのストリーム + 起動時の `open` スナップショット                                  |
| 双方向セッション                     | [WebSocket](/ja-JP/docs/web-socket) | 1 つのセッション + 起動時の `connection` スナップショット                            |

3 つのトランスポートは同じ順序です。操作を定義し、アプリケーションのクライアントと呼び出し側の入力を渡して呼びます。

## パッケージを選ぶ

| パッケージ                    | いつ                                                                                                                    |
| ----------------------------- | ----------------------------------------------------------------------------------------------------------------------- |
| `@defjs/core`                 | SDK の操作と契約を定義し、クライアントを作って HTTP、SSE、WebSocket の操作を呼びます                                    |
| `@defjs/react`                | `ClientProvider` / `useClient` — [React](/ja-JP/docs/integrations/react) を参照                                         |
| `@defjs/vue`                  | プラグイン + `injectClient` — [Vue](/ja-JP/docs/integrations/vue) を参照                                                |
| `@defjs/opentelemetry-server` | アウトバウンドのスパン・メトリクス・ログ — [OpenTelemetry Server](/ja-JP/docs/integrations/opentelemetry-server) を参照 |

## 結果の形

3 つのトランスポートとも、エラーファーストの 3 要素タプルを返します。位置は揃っていますが、意味は違います。

- HTTP → `[error, data, response]`
- SSE → `[error, stream, open]`
- WebSocket → `[error, session, connection]`

失敗したとき、2 番目は `undefined` です。HTTP では、フォールトがレスポンスのメタデータを持つため 3 番目も `undefined` です。SSE と WebSocket では、失敗より前にスナップショットが取れていれば、3 番目は起動時のスナップショットです。[Errors](/ja-JP/docs/errors) を見てください。

## 所有権をひと息で

古くなった HTTP は abort します。SSE は close して `await stream.closed`。WebSocket も close して `await session.closed`。サーバーでは、options が cookie・認証・テナントデータを掴むなら、クライアントをリクエスト境界の中で作ります。ログに出す前に URL・ヘッダー・ボディを redact してください。

Defjs が提供するのは定義、検証、実行です。キャッシュとリトライの方針はアプリケーションが選び、ストリームの再接続はオプトインです。手書きの SDK パッケージは現在サポートされています。CLI ツールと OpenAPI / SDK 生成は計画中のままです。
