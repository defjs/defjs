# インターセプター

インターセプターは、SDK の操作定義に手を加えることなく、認証ヘッダーの付与、リクエストの署名、メンテナンスモード時の短絡応答、安全な読み取り操作の再試行といった横断的な実行ポリシーをアプリケーション側の `Client` にアタッチします。

入力値の検証と `builder` による配置はインターセプターチェーンの実行 **前** に行われ、HTTP ステータスに応じた振り分けと `output` / `error` の struct バリデーションはチェーンの実行 **後** に行われます。

### インターセプターパイプラインのルール

- **オニオン（玉ねぎ）構造の実行順序**: インターセプターは、往路（`next(req)` の前）では登録された順序で実行され、復路（`await next(req)` の後）では逆順で実行されます。広範なロギングやトレーシングのインターセプターは、特定の認証やリトライのインターセプターよりも外側に配置してください。
- **不変（immutable）リクエストの原則**: 必ず `req.headers` を複製し（`new Headers(req.headers)`）、新しいリクエストオブジェクト（`{ ...req, headers }`）を `next(...)` に渡してください。これにより、外側のリトライ処理が常にクリーンな初期ヘッダーを参照できるようになります。
- **`content-type` と `bodyContentType`**: Defjs は推論されたボディの Content-Type を、`req.headers` を変更することなく `req.bodyContentType` に保持します。リクエスト署名処理では、`req.headers.get("content-type") ?? req.bodyContentType` を参照してください。インターセプターが `req.body` を別の形式に置き換える場合は、明示的に `content-type` ヘッダーを設定してください。

## 2. `makeResponse` によるリクエストの短絡（ショートサーキット）

HTTP インターセプターは、`next(req)` を呼び出さずに `makeResponse(...)` で生成した擬似レスポンスを返すことができます。

<include cwd lang="typescript">
  examples/interceptors/short-circuit.ts#example
</include>

`makeResponse` はバリデーションをバイパスするものでは **ありません**。生成されたレスポンスに対しても、操作で定義されたメディアタイプのチェック、ステータス分岐（`2xx` vs 非 `2xx`）、および `output` / `error` の struct バリデーションが通常どおり厳格に適用されます。

## 3. 安全な HTTP 読み取り操作のリトライ

Defjs は、アプリケーションレベルの HTTP ステータスに基づく自動リトライを行いません。ステータスに基づくリトライ（冪等な `GET` / `HEAD` / `OPTIONS` における `429`、`502`、`503`、`504` など）が必要な場合は、HTTP インターセプター内で回数制限を設けたループを実装します。

<include cwd lang="typescript">
  examples/interceptors/retry-safe-reads.ts#example
</include>

- **トランスポート例外のハンドリング**: ネットワークエラーが発生した場合、`next(request)` は reject されます（ステータス 0 のレスポンスは存在しません）。この reject を catch して再度 rethrow することで、元の `NET_*` Fault コードが保持されます。
- **インターセプター内での例外 throw**: ハンドルされていない例外が throw された場合（またはレスポンス以外の値が返された場合）、操作タプルは `EXT_INTERCEPTOR_FAILED` で解決され、`fault.cause` にその原因が設定されます。`ERR_ABORTED` または `ERR_TIMEOUT` を throw した場合は、それぞれ `NET_ABORTED` または `NET_TIMEOUT` で解決されます。

## 4. WebSocket セッションのラップ

WebSocket インターセプターが `next(req)` を呼び出せるのは **最大 1 回** です。返された `WebSocketSessionLike` をラップする際は、一過性のスナップショットをオブジェクトスプレッド展開するのではなく、動的ゲッター（`state`、`connection`、`bufferedAmount`）、`close`、`closed`、`receive`、`[Symbol.asyncDispose]()` を適切に委譲（delegate）してください。

## 5. 組み込みファクトリとヘルパー

| エクスポート                                   | トランスポート | 説明                                                                    |
| ---------------------------------------------- | -------------- | ----------------------------------------------------------------------- |
| `createHttpInterceptor(fn)`                    | HTTP           | `(req, next) => Promise<HttpResponse<unknown>>` をラップ                |
| `createSSEInterceptor(fn)`                     | SSE            | `(req, next) => Promise<EventStreamHandle<unknown>>` をラップ           |
| `createWebSocketInterceptor(fn)`               | WebSocket      | `(req, next) => Promise<WebSocketSessionLike>` をラップ                 |
| `basicAuthHttpInterceptor(provider, options?)` | HTTP           | 同期/非同期の認証情報プロバイダーから `Authorization: Basic ...` を注入 |
| `basicAuthSSEInterceptor(provider, options?)`  | SSE            | SSE ハンドシェイク時に `Authorization: Basic ...` を注入                |
