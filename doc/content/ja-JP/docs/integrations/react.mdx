# React

`@defjs/react` は、アプリケーションが所有する `@defjs/core` のクライアントを、React Context および `useClient()` を通じて React 18+ のコンポーネントツリーに注入します。SDK 定義は React に一切依存しない純粋な `@defjs/core` モジュールのまま保たれます。

```sh
bun add @defjs/core @defjs/react react
```

## `@defjs/react` が提供するもの vs 開発者が所有するもの

- **`@defjs/react` が提供するもの**: `ClientProvider` および `useClient(overrideClient?)`。
- **アプリケーション側が所有するもの**: [`DerivableClient`](/ja-JP/api/core/derivableclient-type) の生成、アンマウント時や依存配列変更時の通信キャンセル（`AbortController`）、SSE/WebSocket ハンドルのクローズ、TanStack Query 等のクエリキャッシュ連携。
- **重要**: `useClient()` は `DerivableClient` 関数オブジェクトを返します。操作を実行する箇所で `client({ signal })` を呼び出してください（`getOrder(client({ signal }), input)`）。React のステート更新関数は引数の関数をアップデーターとして解釈するため、`setState(client)` のように直接渡してはいけません。

## 1. クライアントの提供と Effect 内でのデータ取得

アプリケーションの境界でクライアントを作成し、ツリーを `<ClientProvider client={client}>` でラップします。Effect のクリーンアップ時には進行中の通信を中断（abort）します。

- `ClientProvider` は薄い React Context プロバイダーです。異なる `client` プロパティを渡すと、以前のクライアントを複製・破棄することなく、子孫コンポーネントが読み取るクライアントが更新されます。
- 開発環境（`StrictMode`）では、React は Effect のマウントとクリーンアップを複数回実行します。`controller.signal.aborted` をチェックすることで、古いレスポンスによって現在の最新ステートが上書きされるのを防ぎます。

## 2. `useClient` によるクライアントの取得とオーバーライド

`useClient(overrideClient)` は、引数が渡された場合はその `overrideClient` を返し、省略または `undefined` の場合は最も近い親の `ClientProvider` からクライアントを取得します。どちらからもクライアントを取得できない場合にのみ `Error` を throw します。

<include cwd>examples/react/read-with-use-client.tsx#example</include>

- `useClient(explicitClient)` は、コンポーネントやカスタムフックのトップレベルで常に無条件に呼び出してください。`explicitClient ?? useClient()` のように記述すると、React の Rules of Hooks に違反します。

## 3. TanStack Query との統合

`@defjs/react` は依存性注入のみを担当し、独自に `useRequest` フックなどを提供することは **ありません**。TanStack Query などのデータフェッチライブラリと組み合わせる場合は、クエリ関数の `signal` を `client({ signal })` 経由で渡し、クエリアダプターの内部でエラーファーストのタプルを変換します。

<include cwd>examples/react/own-query-work.tsx#example</include>

ここでの `throw error` は、TanStack Query のエラー捕捉要件を満たすために設けたアダプター境界の明示的な処理であり、Defjs 本来の標準的な呼び出しスタイルではありません。

## 4. Effect 内での SSE と WebSocket のライフサイクル管理

SSE や WebSocket のハンドルは、初回の `openStream(...)` や `connectChat(...)` 呼び出し完了後も長く存続します。ハンドシェイクの完了を待機する前にクリーンアップ処理を登録し、アンマウント後に解決されたハンドルも確実にクローズし、単一の非同期イテレーターを消費して `.closed` を await します。

<include cwd>examples/react/own-realtime-work.tsx#example</include>

- WebSocket 操作に渡した `signal` を abort すると、セッションは `aborted` として終了し、`session.receive` は `AbortError` で reject されます。クリーンアップ済みの場合は `catch` ブロックでエラーをガードし、キューのオーバーフローやハートビートタイムアウトなどの真の実行時エラーのみが通知されるようにします。
- SSE ストリームを abort した場合、例外を throw することなく `for await (const msg of stream)` が安全に終了します。

---

## 5. SSR とプロバイダースコープ

- **ブラウザ**: エンドポイントやインターセプターがリクエストに依存しない場合、モジュールスコープの単一クライアントを共有します。
- **SSR**: ヘッダー、Cookie、テナント、認証情報がリクエストごとに異なる場合、各サーバーリクエスト境界の中で新しいクライアントを生成します。
- `<ClientProvider>` のアンマウントによって、実行中の HTTP 通信が中止されたり、SSE/WebSocket 接続が切断されたり、`disposeClient` が呼ばれたりすることはありません。
