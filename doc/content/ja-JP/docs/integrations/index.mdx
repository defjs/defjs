# プラグイン統合の概要

プラグイン（インテグレーション）は、`@defjs/core` のコアコードを変更したり SDK 定義を特定のフレームワークやテレメトリ基盤と密結合させたりすることなく、定められた拡張ポイントを通じて利用側アプリケーションの `Client` を拡張します。作成した SDK 定義は純粋な `@defjs/core` モジュールのままであり、どのプラグインを導入するかは利用側アプリケーションが自由に選択します。

すべての Defjs プラグインは、**薄いプラグイン契約（Thin Plugin Contract）** に厳格に従います。

- **隠蔽されたキャッシュや状態を持たない**: プラグインがレスポンスを勝手にキャッシュしたり、リクエストを独自にリトライしたり、クエリ状態を管理したりすることはありません。
- **トランスポートを勝手に置き換えない**: プラグインが背後の HTTP、SSE、WebSocket トランスポートを勝手にラップしたり置き換えたりすることはありません。
- **呼び出し元が所有するライフサイクル**: UI プロバイダーのアンマウントやテレメトリ SDK の終了処理によって、通信中のリクエストやアクティブなストリームが勝手に暗黙キャンセルされることはありません。

## 2 つのプラグインアーキテクチャ

### 1. フレームワークプラグイン (`@defjs/react`, `@defjs/vue`)

フレームワークプラグインは、既存の [`DerivableClient`](/ja-JP/api/core/derivableclient-type) をネイティブの依存性注入機能（React Context または Vue の `provide` / `inject`）を通じてコンポーネントツリー下位へと渡します。

<Tabs items={["sdk/orders.ts", "app/main.tsx", "app/OrderCard.tsx"]}>
  <Tab value="sdk/orders.ts">
```ts
import { defineRequest, struct } from "@defjs/core";

export const Order = struct.object({
  id: struct.number(),
  status: struct.string(),
});

export const getOrder = defineRequest({
  method: "GET",
  path: "/orders/:id",
  input: struct.object({ id: struct.number() }),
  builder: (input) => ({ path: { id: input.id } }),
  output: Order,
});
```
  </Tab>
  <Tab value="app/main.tsx">
```tsx
import { createClient, withEndpoint } from "@defjs/core";
import { ClientProvider } from "@defjs/react";
import { OrderCard } from "./OrderCard.tsx";

const client = createClient(withEndpoint("https://api.example.com"));

export function App() {
  return (
    <ClientProvider client={client}>
      <OrderCard id={42} />
    </ClientProvider>
  );
}
```
  </Tab>
  <Tab value="app/OrderCard.tsx">
```tsx
import { useClient } from "@defjs/react";
import { getOrder } from "../sdk/orders.ts";

export function OrderCard({ id }: { id: number }) {
  const client = useClient();
  // エフェクトやクエリフック内で `client` または `client({ signal })` を `getOrder(...)` に渡します
  void id;
  void getOrder;
  void client;
  return null;
}
```
  </Tab>
</Tabs>

### 2. ミドルウェアプラグイン (`@defjs/opentelemetry-server`)

ミドルウェアプラグインは、[`ClientOption`](/ja-JP/api/core/clientoption-type) を返すファクトリ関数です。`createClient(...)` に渡されると、`withHttpInterceptors`、`withSSEInterceptors`、`withWebSocketInterceptors` を介して HTTP、SSE、WebSocket の各インターセプターをクライアントに追加します。

<Tabs items={["plugins/request-id.ts", "app/client.ts"]}>
  <Tab value="plugins/request-id.ts">
```ts
import type { ClientOption } from "@defjs/core";
import { createHttpInterceptor, withHttpInterceptors } from "@defjs/core";

export function withRequestIdHeader(headerName = "x-request-id"): ClientOption {
  const interceptor = createHttpInterceptor(async (request, next) => {
    const headers = new Headers(request.headers);
    if (!headers.has(headerName)) {
      headers.set(headerName, crypto.randomUUID());
    }
    return next({ ...request, headers });
  });

return withHttpInterceptors(interceptor);
}

````
  </Tab>
  <Tab value="app/client.ts">
```ts
import { createClient, withEndpoint } from "@defjs/core";
import { withRequestIdHeader } from "../plugins/request-id.ts";

export const client = createClient(
  withEndpoint("https://api.example.com"),
  withRequestIdHeader(),
);
````

  </Tab>
</Tabs>

実行順序のルール、リトライ境界、ストリーミングライフサイクルフックの詳細は [ミドルウェア](/ja-JP/docs/interceptors) を参照してください。
