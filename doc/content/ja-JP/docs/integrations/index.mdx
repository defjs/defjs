# プラグイン統合の概要

プラグイン（インテグレーション）は、`@defjs/core` のコアコードを変更したり SDK 定義を特定のフレームワークやテレメトリ基盤と密結合させたりすることなく、定められた拡張ポイントを通じて利用側アプリケーションの `Client` を拡張します。作成した SDK 定義は純粋な `@defjs/core` モジュールのままであり、どのプラグインを導入するかは利用側アプリケーションが自由に選択します。

すべての Defjs プラグインは、**薄いプラグイン契約（Thin Plugin Contract）** に厳格に従います。

- **隠れたキャッシュや状態を持たない**: プラグインがレスポンスを保存したり、リクエストをリトライしたり、クエリ状態を管理したりすることはありません。
- **トランスポートを置き換えない**: プラグインが背後の HTTP、SSE、WebSocket トランスポートをラップしたり置き換えたりすることはありません。
- **呼び出し元が所有するライフサイクル**: UI プロバイダーのアンマウントやテレメトリ SDK の終了処理によって、通信中のリクエストが自動的にキャンセルされたり、アクティブなストリームが閉じられたりすることはありません。

## 提供されているプラグインとツール

| 領域                                                                    | パッケージ / リソース              | カテゴリ                 | 提供される機能                                                                                                    | アプリケーション側に残る責務                                                                      |
| ----------------------------------------------------------------------- | ---------------------------------- | ------------------------ | ----------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------- |
| [React](/ja-JP/docs/integrations/react)                                 | `@defjs/react`                     | フレームワークプラグイン | React 18+ 向けの `ClientProvider` および `useClient(overrideClient?)`                                             | クライアントの生成、`AbortController` によるクリーンアップ、クエリキャッシュ（TanStack Query 等） |
| [Vue](/ja-JP/docs/integrations/vue)                                     | `@defjs/vue`                       | フレームワークプラグイン | Vue 3.2+ 向けの `createClientPlugin`、`HTTP_CLIENT`、`injectClient(key?)`                                         | クライアントの生成、`onCleanup` / `onScopeDispose` でのキャンセル、クエリ状態                     |
| [OpenTelemetry サーバー](/ja-JP/docs/integrations/opentelemetry-server) | `@defjs/opentelemetry-server`      | ミドルウェアプラグイン   | アウトバウンド HTTP、SSE、WebSocket のスパン・メトリクス・ログ用 `ClientOption`（`withOpenTelemetryServer(...)`） | OpenTelemetry SDK の初期化、エクスポーター、サンプリング、秘匿化、フラッシュ                      |
| [AI スキル](/ja-JP/docs/ai) & [llms.txt](/ja-JP/docs/ai-api)            | `defjs/defjs` スキル & `/llms.txt` | AI ツール                | エージェントスキル（`SKILL.md`）および機械可読な Markdown ドキュメント                                            | プロジェクトにインストールされた `@defjs/core` のバージョンおよびテストスイートによる検証         |

## 2 つのプラグインアーキテクチャ

### 1. フレームワークプラグイン (`@defjs/react`, `@defjs/vue`)

フレームワークプラグインは、既存の [`DerivableClient`](/ja-JP/api/core/derivableclient-type) をネイティブの依存性注入機能（React Context または Vue の `provide` / `inject`）を通じてコンポーネントツリーの下位へ渡します。

### 2. ミドルウェアプラグイン (`@defjs/opentelemetry-server`)

ミドルウェアプラグインは、[`ClientOption`](/ja-JP/api/core/clientoption-type) を返すファクトリ関数です。`createClient(...)` に渡されると、`withInterceptors` を介して HTTP、SSE、WebSocket のインターセプターを追加します。
