# HTTP 操作

SDK は、各 HTTP 操作を `defineRequest` を使って定義します。HTTP メソッド、パステンプレート、`input` スキーマ、同期的で純粋な `builder`、そしてレスポンスの `output` / `error` スキーマを宣言します。利用側アプリケーションはその操作を import し、設定済みの `Client` を渡して呼び出し、返される `[error, data, response]` タプルを処理します。

## 1. 操作の定義と呼び出し

SDK モジュール内で各操作ごとに個別の `defineRequest` を export し、`createClient` によるクライアント生成は利用側アプリケーションで行います。

### SDK 設計のベストプラクティス

- **1 定義につき 1 操作**: 各メソッド、パス、契約を独立した定義に保つことで、アプリケーション側で未使用の操作をツリーシェイクできます。
- **静的な `operation` 名を設定する**: `"orders.read"` のようなカーディナリティの低い識別子を使用します。テレメトリプラグイン（`@defjs/opentelemetry-server`）やロギングインターセプターが、URL やユーザー ID を漏らすことなく操作を識別できるようにするためです。
- **SDK 内にクライアントを埋め込まない**: export するのは操作定義、`struct` スキーマ、型定義のみに限定します。

## 2. URL 解決とパスパラメータ

`withEndpoint(...)` には有効な絶対 URL を渡す必要があります。指定した URL のパス部分がベースディレクトリとして機能します（ベースエンドポイントに含まれるクエリ文字列やハッシュフラグメントは破棄されます）。

<include cwd>examples/http/resolve-url.ts#example</include>

- **パステンプレートのプレースホルダー (`:name`)**: 単一のパスセグメントとして正確に 1 回だけ URL エンコードされます。スラッシュ、`?`、`#`、`%`、空白、Unicode はそのセグメント内に収まります。値を事前にエンコードしないでください。空文字列、`.`、`..` は `REQ_BUILD_FAILED` で失敗します。
- **オリジンとディレクトリの制限**: 定義側のパスに絶対 URL、プロトコル相対 URL（`//...`）、C0 制御文字、バックスラッシュ、`?`、`#` を含めたり、ベースエンドポイントのディレクトリ階層を遡る指定（`../`）を行うことはできません。違反した場合は、インターセプターやトランスポートが実行される前に `REQ_BUILD_FAILED` で即座に失敗します。

## 3. `builder` による入力値の配置

操作で `input` を宣言した場合、`{ path?, query?, headers?, body? }` を返す同期的で純粋な関数 `builder` が**必須**となります。`builder` を省略できるのは、`input` を持たない操作のみです。

<include cwd lang="typescript">
  examples/http/place-input.ts#example
</include>

### `builder` がフィールドエイリアスをエンコードする仕組み

| `builder` の戻り値の式                         | 通信時の出力                                                                          |
| ---------------------------------------------- | ------------------------------------------------------------------------------------- |
| `body: input.profile`                          | 型付けされた struct: `.alias()` および `Date` / `bigint` コーデックが適用されます     |
| `body: { profile: input.profile }`             | 外側の `profile` キーはリテラル。内側のオブジェクトは struct のエイリアスを維持します |
| `body: { ...input.profile, role: "admin" }`    | スプレッド展開は struct エイリアスを維持。`role` はリテラルキーとなります             |
| `body: { name: input.profile.customerName }`   | 匿名オブジェクト: 記述されたキー名がリテラルキーとなります                            |
| `query: input.filter` / `headers: input.trace` | フラットな型付きオブジェクト: 各フィールドの `.alias()` が通信用キーになります        |

### クエリパラメータのカスタムシリアライズ

デフォルトでは、スカラー値およびスカラーの配列（同一キーの繰り返し）が直接エンコードされますが、ネストしたオブジェクトを渡すと `REQ_BUILD_FAILED` で失敗します。バックエンドがネストされたクエリ構文（`filter[status]=paid` など）を要求する場合は、クライアントに `withQuerySerializer` を設定してください。

### リクエストボディの形式

`GET` と `HEAD` ではリクエストボディを送信できません。その他のメソッドでは、`builder` が返した値に応じてボディの形式が選ばれます。

| `body` の値                                                              | 送信時の形式                                         | デフォルトの `Content-Type`                   |
| ------------------------------------------------------------------------ | ---------------------------------------------------- | --------------------------------------------- |
| `undefined` / 省略                                                       | ボディなし                                           | —                                             |
| `urlencoded` / `formData` コーデックを持つルート struct                  | `URLSearchParams` / `FormData`（エイリアス適用済み） | フォーム形式 / multipart boundary             |
| ネイティブの `FormData` または `URLSearchParams`                         | そのまま通過                                         | multipart boundary / urlencoded               |
| `Blob` / `File`                                                          | そのまま通過                                         | `blob.type` または `application/octet-stream` |
| `ArrayBuffer`、typed array、`DataView`、`ReadableStream`                 | 生のバイト列 / ストリーム                            | `application/octet-stream`                    |
| `string`                                                                 | UTF-8 テキスト                                       | `text/plain;charset=UTF-8`                    |
| プレーンオブジェクト、配列、有限の数値、真偽値、`null`、`Date`、`bigint` | struct エンコードされた JSON                         | `application/json`                            |

<include cwd lang="typescript">
  examples/http/body.ts#example
</include>

JSON で表現できない値（`NaN`、`±Infinity`、`Map`、`Set`、関数、`toJSON()` を持たないクラスインスタンス、生のイテラブルなど）が含まれている場合、暗黙的に `{}` や `null` にシリアライズされるのではなく、即座に `REQ_BUILD_FAILED` で失敗します。

## 4. レスポンスのデコード処理

`output` は `2xx` レスポンスを検証し、`error` は `2xx` 以外のレスポンス（`3xx`、`4xx`、`5xx`）を検証します。struct の種別によって、レスポンスストリームの読み取り方法が決まります（`struct.string()` → テキスト、`struct.blob()` / `struct.file()` → `Blob`、`struct.arrayBuffer()` → `ArrayBuffer`、それ以外 → JSON）。

1. **`ok` (`200..299`) による分岐**: `2xx` は `output`、非 `2xx` は `error` を使用します。
2. **省略時の明示的スキップ**: その側に宣言された struct がない場合、レスポンスボディは一切読み取られません（`2xx` では `data: undefined` + `HttpMeta` が返り、非 `2xx` では `data: undefined` の `HTTP_STATUS` が返ります）。
3. **JSON メディアタイプの先行検証**: JSON struct の場合、ボディストリームを読み取る前に、非 JSON の `Content-Type` が返されていないか検証し、不一致なら即座に `RES_MEDIA_TYPE_INVALID` を返します。
4. **ストリームの読み取りとパース**: 読み取り不可のストリームや壊れた JSON は `RES_DECODE_FAILED`（ストリーム途中切断の場合は `NET_BODY_INCOMPLETE`）で失敗します。
5. **`struct` による検証**: スキーマと一致しないデータは `RES_STRUCT_MISMATCH` で失敗します。

## 5. 処理のキャンセルと期限の設定 [#cancel-the-work]

呼び出しごとに派生させたクライアント値 `client({ signal })` に `signal` を渡します。

- **期限 (`NET_TIMEOUT`)**: `AbortSignal.timeout(ms)` を使用します。
- **手動キャンセル (`NET_ABORTED`)**: `AbortController` を使用します。
- **シグナルの結合**: `AbortSignal.any([controller.signal, AbortSignal.timeout(ms)])` を使用します。

## 6. クレデンシャル、XSRF、転送進捗

- **`withCredentials(true)`**: HTTP および SSE リクエストの Fetch 設定に `credentials: "include"` を適用します。
- **`withXSRF(options?)`**: 同一オリジンに対するデータ変更 HTTP メソッド（`POST`、`PUT`、`PATCH`、`DELETE`）において、XSRF クッキー（デフォルトは `XSRF-TOKEN`）を読み取り、対応するヘッダー（`X-XSRF-TOKEN`）を自動注入します。
- **`onDownloadProgress` / `onUploadProgress`**: `client({ onDownloadProgress, onUploadProgress })` に渡します。ダウンロード進捗は、正の `Content-Length` が存在し `Content-Encoding` が未指定または `identity` の場合にのみ `lengthComputable: true` を報告します。アップロード進捗は、サーバーランタイム（Bun、Node.js）でボディをストリーミングします。進捗コールバック内で例外が throw された場合、呼び出しは `EXT_OBSERVER_FAILED` で失敗します。
