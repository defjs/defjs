# はじめに: 最初の SDK 操作 [#getting-started-one-http-request]

書くファイルは二つです。`GET /users/:id` を export する SDK モジュールと、それを import してクライアントを所有するアプリケーションです。ローカル Fetch ハンドルが最初の実行をオフラインに保ちます。同じ API 定義は、そのあとサービスを向いたクライアントでも動きます。

## ベストプラクティス

定義は client から独立しています。アプリケーションの client を渡して操作を呼びます。たとえば `getUser(client, { id: 7 })` です。第 3 の options 引数はありません。操作を呼ぶと処理が始まり、`await` は待つだけです。サービスアドレスと認証情報もアプリケーションのものです。先に error-first のタプルを確認します。`error` があるときは `error.code` を報告し、成功値を読む前に関数から return します。

## Step 1 — インストール

`@defjs/core` は ESM で、Node.js、Bun で動きます。Node.js 22.18+（または 24+）は type stripping により `.ts` をそのまま実行します。それより古い 22.x では `--experimental-strip-types` が要ります。package.json に `"type": "module"` を書いてください。ブラウザーでもバンドラーと Fetch は要ります。

```sh
bun add @defjs/core
```

## Step 2 — リクエストを定義する

`src/define-request.ts` を作ります。これは SDK 作成者のモジュールです。クライアントを作らずに `getUser` を export します。入力 struct は呼び出し側の値です。`builder` はその値をリクエストに配置します。ここでは入力全体が path オブジェクトなので、エイリアスのないスカラーフィールドが `:id` を埋めます。

<include cwd meta="define-request.ts">
  examples/start/define-request.ts#example
</include>

`output` は 2xx のボディです。`error` はそれ以外のすべての status です。それぞれ struct は 1 つです。ボディの形が違うときは `struct.or(...)` か判別可能な union を使います。

`defineRequest(...)` は操作を返します。`getUser(client, input)` を呼ぶとリクエストが始まります。上の `builder` は入力を配置する関数であり、操作そのものではありません。`input` を宣言したところでは、`builder` は必須で、同期的な純粋関数です。

## Step 3 — ローカルで呼び出す

定義の隣に `src/execute-locally.ts` を作ります。これは利用アプリケーションです。`getUser` を import し、自分のクライアントを作り、ローカル Fetch ハンドルを渡します。Defjs はそれでも入力を検証し、`Request` を組み立て、status で振り分け、ボディをパースします。

<include cwd meta="execute-locally.ts">
  examples/start/execute-locally.ts#example
</include>

実行します。

```sh
bun src/execute-locally.ts
```

```txt
Loaded Ada from 200
```

いないユーザーも試してみましょう — path の id を `8` にしてもう一度実行します。

```txt
User not found
```

成功時は `error` が `null`、`user` が `200` の Struct 出力、`response` が `DecodedResponse<User>` です。宣言済み `404` では `error.code` が `'HTTP_STATUS'`、`error.status` が `404`、`error.data` は型付きの `NotFound` です。失敗時、タプルの 2 番目は `undefined` です。

## Step 4 — 実 API に向ける

`src/real-api.ts` で同じ `getUser` を import し、サービスのベース URL でクライアントを作ります。例のアドレスを、それらのボディで `GET /v1/users/:id` を実装しているサービスに置き換えてから、この版を実行してください。

<include cwd>examples/start/real-api.ts#example</include>

API 定義は SDK モジュールに残ります。サービスアドレス、認証情報、インターセプター、実行の寿命はアプリケーションに残ります。どちらのクライアントも同じ Defjs のエンドポイント契約を使います。

## 定義を公開する

より多くのアプリケーションが必要になったら、定義を SDK パッケージへ移します。`getUser` を export し、その TypeScript 宣言を含め、互換性のある Core の版を宣言します。利用者はそのとき `./define-request.ts` ではなくパッケージから import します。クライアント設定は利用者自身のものです。パッケージ構成の全体は [SDK の作成と公開](/ja-JP/recipes/publish-http-sdk) に従ってください。

## 結果が違うとき

- 悪い入力 → `REQ_INPUT_INVALID`。失敗する `builder` → `REQ_BUILD_FAILED`
- non-2xx の status → `HTTP_STATUS`。`error` を宣言していてそのボディがデコードできれば、`error.data` に型が付きます
- 宣言された JSON ボディのメディアタイプ違い → `RES_MEDIA_TYPE_INVALID`。ボディを読む前に報告されます
- 宣言済みボディ（2xx なら `output`、それ以外は `error`）がデコードできない → `RES_DECODE_FAILED` または `RES_STRUCT_MISMATCH`。status は問いません
- Fetch 失敗 / キャンセル / 期限 → `NET_UNREACHABLE` / `NET_ABORTED` / `NET_TIMEOUT`

期限は `client({ signal: AbortSignal.timeout(ms) })` で、`NET_TIMEOUT` に分類されます。手動の abort は `NET_ABORTED` です。クライアント単位の既定の期限はありません。1 回の呼び出しに独自の `signal` が要るときはクライアントを派生させてください。[Client](/ja-JP/docs/client) を参照してください。キャンセルは呼び出し側が見たことを伝えます — サーバー側の書き込みがコミットしたかどうかではありません。
