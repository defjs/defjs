# はじめに: SDK の定義とアプリケーションの実行 [#はじめに-1-つの-http-リクエスト]

この例では、SDK 作成者として `GET /users/:id` の型付き定義を export し、利用アプリケーションとして別ファイルで Defjs Client を作ります。最初はローカル Fetch ハンドルで `200` と宣言済みの `404` を確認します。実 API への切り替えではアプリケーションの Client 設定を変え、同じ定義を使います。

## ベストプラクティス

定義は client から独立しています。定義を呼ぶと command ができるだけで、送信は始まりません。その command に名前を付け、アプリケーションが所有する client の `client.execute` に渡します。サービスアドレスと認証情報もアプリケーションのものです。先に error-first のタプルを確認します。`error` があるときは `error.code` を報告し、成功値を読む前に関数から return します。

## Step 1 — インストール

`@defjs/core` は ESM で、Node.js、Bun で動きます。Node.js 22.18+（または 24+）は type stripping により `.ts` をそのまま実行します。それより古い 22.x では `--experimental-strip-types` が要ります。package.json に `"type": "module"` を書いてください。ブラウザーでもバンドラーと Fetch は要ります。

```sh
bun add @defjs/core
```

## Step 2 — SDK の定義を export する [#step-2--リクエストを定義する]

`src/define-request.ts` を作ります。SDK はここで `getUser` を export します。入力 Struct は呼び出し側が渡す値を宣言し、`builder` はその値の配置先を決めます。ここでは入力全体を path オブジェクトとして渡すため、エイリアスのないスカラーフィールドが `:id` を埋めます。定義には環境固有の URL や認証情報を含めません。

<include cwd meta="src/define-request.ts">
  examples/start/define-request.ts#example
</include>

`output` は 2xx のボディです。`error` はそれ以外のすべての status です。それぞれ struct は 1 つです。ボディの形が違うときは `struct.or(...)` か判別可能な union を使います。

`defineRequest(...)` はエンドポイントを返します。`getUser(...)` を呼ぶと、`client.execute(...)` に渡す不透明なコマンドができます。上の `builder` は入力を配置する関数であり、エンドポイントそのものではありません。

## Step 3 — アプリケーションの Client で実行する [#step-3--ローカルで実行する]

同じディレクトリに `src/execute-locally.ts` を作り、`./define-request.ts` から定義を import します。アプリケーションは Client の endpoint、認証、インターセプター、トランスポートを選びます。この例ではローカル Fetch ハンドルを設定し、ネットワークなしで入力検証、`Request` の組み立て、status による振り分け、ボディのパースを実行します。

<include cwd meta="src/execute-locally.ts">
  examples/start/execute-locally.ts#example
</include>

実行します。

```sh
bun src/execute-locally.ts
```

```txt
Loaded Ada from 200
```

いないユーザーも試してみましょう — path の id を `8` にしてもう一度実行します。

```txt
User not found
```

成功時は `error` が `null`、`user` が `200` の Struct 出力、`response` が `DecodedResponse<User>` です。宣言済み `404` では `error.code` が `'HTTP_STATUS'`、`error.status` が `404`、`error.data` は型付きの `NotFound` です。失敗時、タプルの 2 番目は `undefined` です。

## Step 4 — 実 API に向ける

サービスが `GET /v1/users/:id` と同じレスポンス契約を実装しているなら、アプリケーション側で `withHTTPHandle(...)` を外し、実際のベース URL を設定します。次の例を `src/real-api.ts` に保存すると、同じ `./define-request.ts` の定義を使えます。例の URL は利用するサービスに置き換えてください。

SDK の API 定義はそのままで、アプリケーションの実行設定だけが変わります。アプリケーションは引き続き結果とキャンセルを管理します。定義を配布する手順は [SDK の作成と公開](/ja-JP/recipes/publish-http-sdk) に進んでください。

## 結果が違うとき

- 悪い入力 → `REQ_INPUT_INVALID`。衝突するキャンセル options → `REQ_OPTIONS_INVALID`。失敗する `builder` → `REQ_BUILD_FAILED`
- non-2xx の status → `HTTP_STATUS`。`error` を宣言していてそのボディがデコードできれば、`error.data` に型が付きます
- 宣言された JSON ボディのメディアタイプ違い → `RES_MEDIA_TYPE_INVALID`。ボディを読む前に報告されます
- 宣言済みボディ（2xx なら `output`、それ以外は `error`）がデコードできない → `RES_DECODE_FAILED` または `RES_STRUCT_MISMATCH`。status は問いません
- Fetch 失敗 / キャンセル / タイムアウト → `NET_UNREACHABLE` / `NET_ABORTED` / `NET_TIMEOUT`

`timeout` は `1..2_147_483_647` の正の安全な整数である必要があります。有効なキャンセルの形は `{ signal }`、`{ timeout }`、`{ abort }`、または `{ signal, timeout }` / `{ signal, abort }` です。`{ abort, timeout }` を同時に渡すのは無効です。キャンセルは呼び出し側が見たことを伝えます — サーバー側の書き込みがコミットしたかどうかではありません。
