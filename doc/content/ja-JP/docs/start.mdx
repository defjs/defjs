# はじめに: 最初の SDK 操作 [#getting-started-one-http-request]

このガイドでは、`GET /orders/:id` を定義する SDK モジュールを作成し、それを 2 つの異なるアプリケーションモジュールから呼び出します。1 つはオフラインのモックトランスポートを使用し、もう 1 つは実際のライブ API にリクエストを送信します。

## 1. `@defjs/core` のインストール

`@defjs/core` は依存関係ゼロの ESM パッケージであり、ブラウザ、Bun、Node.js 現行 LTS で動作します。`package.json` に `"type": "module"` が設定されていることを確認してください。

```sh
bun add @defjs/core
```

## 2. SDK の定義とアプリケーションからの呼び出し

操作の定義は独自の SDK モジュール（`src/define-request.ts`）に記述し、クライアントの作成はアプリケーションモジュール（`src/execute-locally.ts` や `src/real-api.ts`）で行います。

### 3 つのファイルが連携する仕組み

1. **`src/define-request.ts`（SDK の定義）**:
   - `struct` を使用して `input`、`output`（`2xx` レスポンス用）、`error`（`2xx` 以外のレスポンス用）を宣言します。
   - `input` を `{ path }` にマッピングする同期的で純粋な関数 `builder` を指定します。`input` を宣言した場合は、明示的な `builder` が必須です。
   - クライアントを作成したりキャプチャしたりすることなく、`getOrder` を export します。
2. **`src/execute-locally.ts`（オフラインテストでの実行）**:
   - `withHTTPHandle(...)` を使用してクライアントを構成し、ネットワーク通信を行わずに Defjs のパイプライン全体（入力検証、URL 解決、ステータスに応じたディスパッチ、レスポンス struct のパース）を実行します。
3. **`src/real-api.ts`（本番環境での実行）**:
   - まったく同じ `getOrder` 操作を import し、`withEndpoint(...)` で設定した実際のベース URL に対して呼び出します。

## 3. ローカルサンプルの実行

Bun で `src/execute-locally.ts` を実行します。

```sh
bun src/execute-locally.ts
```

```txt
Loaded paid from 200
```

入力を `{ id: 7 }` から `{ id: 8 }` に変更すると、モックは `404` を返し、Defjs は宣言された `error` struct をデコードして `error.data` に格納します。

```txt
Order not found
```

## 4. エラーファーストタプルの理解

すべての HTTP 呼び出しは `[error, data, response]` を返します。

- **`2xx` の成功時**: `error` は `null`、`data` は検証済みの `output` 値（`Order`）、`response` は `DecodedResponse<Order>` になります。
- **宣言された非 `2xx` ステータス時**: `error.code` は `'HTTP_STATUS'`、`error.status` はステータスコード数値（`404`）、`error.data` は検証済みの `error` struct（`NotFound`）になります。
- **入力値エラー、デコード失敗、ネットワーク障害時**: `error.code` が失敗した正確なステージを特定します。
  - `REQ_INPUT_INVALID` / `REQ_BUILD_FAILED` — 呼び出し元入力値の不正、または `builder` 内での例外発生
  - `RES_MEDIA_TYPE_INVALID` — 宣言された JSON ボディに対して非 JSON の `Content-Type` が返された場合（ボディの読み取り前に即座に拒否）
  - `RES_DECODE_FAILED` / `RES_STRUCT_MISMATCH` — ボディの読み取り不可またはスキーマの不一致
  - `NET_UNREACHABLE` / `NET_ABORTED` / `NET_TIMEOUT` — トランスポートエラー、手動キャンセル、または `AbortSignal.timeout(ms)` によるタイムアウト

呼び出しごとの期限やキャンセルシグナルは、単一呼び出し用のクライアント値を派生させて渡します: `getOrder(client({ signal: AbortSignal.timeout(5_000) }), { id: 7 })`。
