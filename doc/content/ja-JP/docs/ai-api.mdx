アプリケーションから AI サービスを呼ぶことと、助手に Defjs を書かせることは別の作業です。[AI を活用した開発](/ja-JP/docs/ai) が助手の手順です。API と SSE のイベント形式は提供者ごとに異なります。このページのストリームは架空のバックエンドであり、特定の提供者のプロトコルではありません。

## アプリケーションから AI API を呼ぶ [#call-an-api]

いつもの HTTP または SSE の契約で呼び出しを定義し、アプリケーションが所有する client で操作を呼びます。出発点は [HTTP リクエスト](/ja-JP/docs/http) と [SSE イベントストリーム](/ja-JP/docs/sse) です。[JSON の送信](/ja-JP/recipes/post-json) は JSON ボディの例です。[SSE イベントの受信](/ja-JP/recipes/consume-sse) はストリームの読み取りと終了の例ですが、最初のイベントで終了します。その例は完全な AI の回答ではありません。AI の回答をすべて得るには、提供者の完了シグナルまたは EOF まで読み続け、読み取りエラーを処理してストリームを閉じてください。イベント名とデータの構造も提供者の形式に合わせます。[キャンセルとタイムアウト](/ja-JP/recipes/cancel-http) は HTTP 呼び出しを止める方法です。

提供者の秘密は、それを使って費用を発生させてよいサーバーに置きます。ブラウザのバンドル、公開されるビルド変数、ブラウザへ配送する client には入れないでください。資格情報はアプリケーションのものです。サーバー上の client に設定するか、そのサーバー境界の中だけで動くインターセプターで付けます。置き場所は[クライアント設定](/ja-JP/docs/client)と[インターセプター](/ja-JP/docs/interceptors)です。`withCredentials` は Fetch の cookie モードを選ぶだけで、提供者の秘密は持ちません。

操作が戻ったあと、ストリームの所有者はアプリケーションです。SSE ではイベントを読み、ハンドルを閉じ、閉じ終わるまで待ちます。HTTP では、答えが不要になったら呼び出しを中止します。中止しても、サービスが受け取った作業を取り消したことにはなりません。

失敗したという理由だけでストリーミング POST を再送しないでください。Defjs は HTTP を自分では再試行しません。SSE の再接続は、アプリケーションが明示するまでオフです。明示したあとも、POST のようなメソッドは、その方針が明確に許さない限り再送されません。失敗した試行でも、サービス側で課金される作業が始まっていることがあります。同じ POST を再度送ると、その作業がもう一度始まることがあります。再試行を足す前に、[HTTP リクエスト](/ja-JP/docs/http) の再送規則と [SSE イベントストリーム](/ja-JP/docs/sse) の再接続規則を読んでください。

## 架空のオフラインストリーム [#fictional-stream]

次のワイヤ形式は架空です。特定の提供者のイベント形式ではありません。`withSSEHandle` が応答を渡すため、この例にネットワークも本物の資格情報も要りません。本文は二つの `delta` イベントと、その後の完了イベントです。ループは両方のテキストを残し、最初のイベントでは止まりません。

<include cwd lang="typescript">
  examples/ai/fictional-completion.ts#example
</include>

`@defjs/core` をインストールしたプロジェクトで、例を `fictional-completion.ts` として保存し、実行します。

```sh
bun fictional-completion.ts
```

期待される出力：

```txt
Hello there
```
