# 公開 SDK 設計 [#public-sdk-design]

企業やプラットフォームチームが外部の開発者向けに公式 TypeScript SDK（オブジェクトストレージ SDK、決済ゲートウェイ SDK、SaaS プラットフォーム SDK など）を公開する場合、SDK パッケージは**実行環境を縛ることなく通信契約（wire contract）を定義する**必要があります。

このガイドでは、**Amazon S3 互換の SDK（`@company/s3-sdk`）**を具体例として、`models/` と純粋関数の `services/` を用いたマルチモジュール公開 SDK の設計方法を解説します。

---

## 1. 公開 SDK が Defjs の分離設計から得られるメリット

従来の SDK は、重厚なクライアントクラス（`new S3Client({ region, credentials })`）をコマンドクラスや静的なサービスクラスと密結合してバンドルしていました。`@defjs/core` で公開 SDK を作成すると、外部ユーザーにとって繰り返し発生する 4 つの課題を解決できます。

1. **マルチ環境およびサンドボックスへの柔軟な対応**：`@company/s3-sdk` はエンドポイントやクライアントを束縛しないため、利用者は本番環境（`https://s3.us-east-1.amazonaws.com`）、ステージングのサンドボックス、Cloudflare R2、あるいは CI テスト中のローカル MinIO コンテナに対して、まったく同じ操作定義を向けることができます。
2. **バンドラーによる 100% の tree-shaking**：独立した純粋関数（`listBuckets`、`listObjectsV2`、`getObject`、`putObject`、`deleteObject`）を export し、`"sideEffects": false` を指定することで、`getObject` と `putObject` しか呼び出さないブラウザバンドルから他のすべてのエンドポイントとモデルが自動的に除去されます。
3. **単一ソースからの実行時バリデーションと静的型**：外部の利用者は、コンパイル時の TypeScript 型（`Infer<typeof ...>`）と実行時のレスポンス／エラー検証（`struct`）の両方を同時に得られます。予期しないワイヤーペイロードからアプリケーションを保護し、ワイヤー上の `snake_case` フィールドや ISO 日付文字列も自動的に変換されます。
4. **認証、リトライ、テレメトリの完全な制御**：利用者は自身の `Client` に対して、認証情報ローテーション用のインターセプター、`withRetry(...)` ポリシー、マルチリージョンのロードバランサー（`withBalancer(...)`）、またはサーバーサイド OpenTelemetry（`@defjs/opentelemetry-server`）を自由に組み込めます。

## 2. パッケージのディレクトリ構成

SDK パッケージを `src/models/`（データ構造）と `src/services/`（リソース領域ごとに整理された純粋な操作定義）に分割し、フラットなバレルファイル `src/index.ts` から再 export します。

```text
@company/s3-sdk/
├── src/
│   ├── models/                 # 1. 共有される struct スキーマと Infer<typeof ...> 型
│   │   ├── common.ts           #    StorageClass, S3Error
│   │   ├── bucket.ts           #    Bucket, ListBucketsOutput
│   │   └── object.ts           #    ObjectSummary, ListObjectsOutput
│   ├── services/               # 2. リソース領域ごとの純粋な defineRequest 関数
│   │   ├── buckets.ts          #    BucketInput, listBuckets, headBucket, deleteBucket
│   │   └── objects.ts          #    listObjectsV2, headObject, getObject, putObject, deleteObject
│   └── index.ts                # 3. ルート import と tree-shaking のためのバレル export
├── package.json                # sideEffects: false, peerDependencies: { "@defjs/core": "^0.8.0" }
└── tsconfig.json
```

### 使いやすい操作契約の設計ポイント

- **呼び出し元の入力をフラットにし、`builder` で振り分ける**：`putObject` では、呼び出し元は直感的な 1 つのオブジェクト（`{ bucket, key, body, contentType, storageClass }`）を渡すだけでよく、同期的な `builder` がその入力を `path`（`:bucket/:key`）、`headers`（`content-type`、`x-amz-storage-class`）、バイナリの `body`（`Blob`）へと分割します。`listObjectsV2` では、`builder` が `continuationToken` と `maxKeys` を S3 のクエリパラメータ `continuation-token` と `max-keys` にマッピングし、`list-type: 2` を自動的に付与します。
- **ワイヤーペイロードに合わせて `output` を宣言する**：
  - **構造化 JSON（`listBuckets`、`listObjectsV2`）**：`.alias()` マッピングや `struct.date()` フィールドを備えた `struct.object(...)` を宣言します。
  - **バイナリペイロード（`getObject`）**：`output: struct.blob()`（または `struct.arrayBuffer()`）を宣言します。
  - **空ボディ（`headBucket`、`headObject`、`putObject`、`deleteObject`）**：`output` を省略することで、ゼロバイトの `HEAD`、`200`、`204` レスポンスが JSON デコードを試みることなく成功し、呼び出し元はタプルの 3 番目の要素からレスポンスヘッダー（`response.headers.get("etag")`）を読み取れます。

## 4. 外部の開発者が SDK を利用する方法

外部のアプリケーションは、`@company/s3-sdk` と `@defjs/core` をインストールし、自身のエンドポイントと署名インターセプターで `Client` を構成するだけで、export された操作を純粋関数として直接呼び出せます。
