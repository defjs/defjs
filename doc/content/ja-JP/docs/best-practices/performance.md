## 大きなボディをストリーミングする [#streaming]

バッファすべきでないボディには `ReadableStream` を送り、消費者がチャンクを処理できるなら大きなレスポンスはストリームとして読みます。JSON ボディは送る前に完全に実体化する必要がありますが、大きなアップロードはそうする必要はありません。

`onUploadProgress` と `onDownloadProgress` は、Fetch の境界を越えるバイトを観測します。サーバーがボディを受け入れたり処理したりしたことの約束ではありません。フロー制御ではなく、ユーザーへのフィードバックに使ってください。

## 増え得るものに上限を設ける [#bounds]

WebSocket セッションには `maxIncomingQueueSize`、SSE には `maxBufferSize` / `maxQueueSize` を設定します。上限はアプリケーションのバックプレッシャー方針の一部です。遅い消費者を早く失敗させるか、生産者に圧力をかけるかを決めます。オーバーフローの経路は、本番と同じ上限でテストしてください。

## フェイルオーバーを意図的に選ぶ [#failover]

`withEndpointFailover` は、設定した方針のもとでのみ失敗した試行をリトライします。試行の予算とリトライの予算は小さく保ち、サービスが再送できない非冪等なリクエストを繰り返すためにフェイルオーバーを使わないでください。ヘルスチェックやペナルティは、実際に使うトランスポートを反映すべきです。

## チューニングの前に計測する [#measure]

操作、トランスポート、消費者を別々に計測してください。短すぎるタイムアウトはネットワーク失敗のように見え、小さすぎるキューはバーストをフォールトに変えます。バッファ、タイムアウト、リトライ回数を変える前に、既存のテレメトリーフックと、負荷を再現するフィクスチャを使ってください。
