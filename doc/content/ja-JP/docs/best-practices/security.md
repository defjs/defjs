## 秘密を SDK とブラウザーの外に置く [#secrets]

SDK の定義にはエンドポイント、トークン、認証情報を含めません。アプリケーションは、使用が許可された場所で動くクライアントに認証情報を置きます。サーバープロセス、ワーカー、信頼できるテストです。プロバイダーの秘密を、ブラウザーバンドル、公開ビルド変数、ブラウザーに配布するクライアントに入れないでください。

```ts
const client = createClient(
  withEndpoint("https://api.example.com"),
  withInterceptors(serverAuth),
);
```

## 認証にはインターセプターを使う [#auth]

アプリケーションの境界で動くインターセプターでトークンを付けます。`builder` は純粋な配置関数のままでなければなりません。トークンストアを読んだり、別の呼び出しが使うヘッダーを変更したりしてはいけません。

## クライアントで XSRF を設定する [#xsrf]

サービスが cookie からヘッダーへ載せるトークンを使う場合は、アプリケーションのクライアントで `withXsrf` を設定してください。`withCredentials` は Fetch の cookie モードを選ぶだけで、トークンを作成も検証もしません。トークンの発行と検証は引き続きサーバーが行う必要があります。

## アプリケーションが制御するものを検証する [#urls]

Defjs は、トランスポートが動く前に、不正なリクエスト path、ディレクトリ外への移動、バックスラッシュ、`?`、`#`、制御文字を拒否します。アプリケーションがどのホストを信頼するかは知りません。エンドポイントのリストを明示的に保ち、ユーザーが提供する値は `builder` に届く前に検証し、信頼できない入力からベース URL を組み立てないでください。

## ログやトレーシングの前に秘匿化する [#redaction]

URL、query 文字列、headers、body には秘密や個人データが含まれることがあります。OpenTelemetry プラグインは既定でボディや完全なヘッダーを取得しません。そのままにしてください。`startSpanHook` かアプリケーションのエクスポーターで秘匿化し、生のリクエスト値を独自のテレメトリーにコピーしないでください。

## abort はローカルなものとして扱う [#abort]

キャンセルはローカルの作業を止めます。サービスがすでに受け入れた作業を止めた証明にはならず、サーバー側の効果をロールバックもしません。非冪等な操作では、abort をサービス自身のキャンセル契約と組み合わせてください。
