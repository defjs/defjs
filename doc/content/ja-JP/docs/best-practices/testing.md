## トランスポートを注入する [#inject]

`withHTTPHandle`、`withSSEHandle`、`withWebSocketHandle` を使って、プラットフォームのトランスポートを置き換えます。操作はそれでもリクエストを組み立て、インターセプターを実行し、レスポンスをデコードするので、テストは実際の契約の境界を通過します。

```ts
const client = createClient(
  withEndpoint("https://fixture.invalid"),
  withHTTPHandle(async () => Response.json({ id: 7, status: "paid" })),
);
const [error, order] = await getOrder(client, { id: 7 });
expect(error).toBeNull();
expect(order?.status).toBe("paid");
```

## 内部ではなくタプルを検証する [#tuple]

フォールトのコードとデコードされた値を検証してください。プライベートなヘルパーの呼び出しやトランスポートの実装詳細を検証するテストは、契約が変わらないまま実装が変わると壊れます。フォールトでは `code`、関連するフィールド、そして cause が契約の一部なら `cause` の同一性を検証します。

## 契約のフィクスチャは実物を保つ [#fixtures]

変更がリクエストの組み立て、デコード、ストリームの破棄に触れるときは、トランスポートごとに実際のサーバーに対する統合テストを 1 つ実行してください。2 つ目のモックプロトコルではなく、リポジトリにすでにあるフィクスチャサーバーを使ってください。ブラウザーだけの振る舞いはブラウザープロジェクトに、サーバーだけの振る舞いはサーバープロジェクトに置きます。

## 時間を明示的に制御する [#time]

タイムアウト、バックオフ、再接続の遅延、ハートビートには fake timers を使ってください。テスト対象のイベントが起きたあとに時間を進め、実行されるべきコード経路を検証します。経過した実時間を検証してはいけません。実際のソケットでは、`open`、`closed`、最初のフレームといった具体的なイベントを待ちます。

## SDK を利用者としてテストする [#consumer]

SDK のテストは、アプリケーションが import する定義を import し、テスト用トランスポートでクライアントを作成し、操作を呼ぶべきです。リクエストを手で作り直してはいけません。それは SDK ではなくテストをテストすることになります。
