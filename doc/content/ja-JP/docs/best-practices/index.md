title: "概要"
description: "SDK の作成者、アプリケーション、ランタイムの間で SDK を予測可能に保つ契約と境界。"
---

これらの実践は Defjs の動作に必須ではありません。定義、アプリケーション、トランスポートを複数の人が所有するときに、SDK を予測可能に保つためのものです。各ページは 1 つのルールから始まり、推奨する形と避ける形を示し、その背景にある境界を説明します。

## 定義と実行を分離する [#definition-execution]

定義はデータです。method、path、入力、出力、エラーの契約を宣言します。クライアントを作成せず、認証情報を読み取らず、I/O も開始しません。アプリケーションがクライアントを作成し、操作を呼び出します。リクエストを実行するのは、操作を呼び出すことです。

この分離により、SDK パッケージはエンドポイントも認証情報も持たずに出荷でき、1 つの定義をブラウザー、サーバー、テストで異なるエンドポイントに対して実行できます。

## 入力を宣言し、明示的に配置する [#input-builder]

`input` は呼び出し側が提供する値を記述します。`builder` が各値の行き先を決めます。path、query、headers、body です。配置がフィールド名や path テンプレートから推論されることはありません。

`builder` は同期的な純粋関数です。実行時に動作します。throw は `REQ_BUILD_FAILED` になります。

## まずエラーの位置を読む [#error-first]

すべての操作は error-first タプルを返します。最初の要素はフォールトか `null` です。リクエスト、レスポンス、トランスポートの失敗は、呼び出し地点で throw されません。

成功値を使う前に、フォールトを読んでください。`code` で絞り込み、そのフォールトに属するフィールドを読みます。

## クライアントはアプリケーションが所有する [#client-ownership]

アプリケーションは、エンドポイント、認証情報、インターセプター、トランスポート、そしてストリームとセッションのライフサイクルを所有します。SDK は契約を所有します。プラグインはアプリケーションのクライアントをフレームワークのツリーに渡すことはありますが、作成したりキャッシュしたりはしません。
