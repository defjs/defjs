# Client

`Client` は、利用側アプリケーションの実行時設定（ベース URL、デフォルトヘッダー、認証情報、インターセプター、クエリシリアライズ、トランスポートハンドル）を保持します。

`createClient(...options)` は [`DerivableClient`](/ja-JP/api/core/derivableclient-type) を返します。

- 呼び出しごとの個別オプションが不要な場合は、`client` をそのまま操作に渡します（`getOrder(client, { id: 1 })`）。
- 呼び出しごとのオプションが必要な場合は、`client(requestOptions)` を呼び出して単一呼び出し用の派生 `Client` 値を生成して渡します（`getOrder(client({ signal }), { id: 1 })`）。派生処理自体は I/O を行わず、返される値はプレーンなオブジェクト（関数ではない）です。

### オプション合成のルール

- オプションは **左から右へ** 順番に適用されます。
- 単一値を設定するヘルパー（`withEndpoint`、`withHeaders`、`withQuerySerializer`、`withCredentials`、`@defjs/core/xsrf` の `withXSRF`）は、先行する同種の設定を **置き換え** ます。
- `withInterceptors(...items)` は既存のインターセプターリストの **末尾に追加** され、操作の実行時にトランスポート（`http`、`sse`、`web-socket`）ごとにフィルタリングされます。

## 2. 呼び出しごとのクライアント派生 (`client(options)`)

独自の `signal`、進捗コールバック、または WebSocket セッション固有の上書きが必要な呼び出しごとに、新しい派生クライアント値を生成します。

> [!IMPORTANT]
> `createClient(...)` は呼び出し可能な関数（`DerivableClient`）を返すため、React の `setState(client)` アップデーターや Vue の `watch(client)` / `computed(client)` ソースに直接渡さないでください。フレームワークが関数をアップデーターやゲッターとして解釈してしまうためです。

### 呼び出しごとの `RequestOptions` リファレンス

`RequestOptions` には 7 つのフラットなフィールドがあります。各トランスポートは自身に関係するフィールドのみを読み取り、それ以外は無視します。

| フィールド           | 対象トランスポート   | 動作                                                                                                                |
| -------------------- | -------------------- | ------------------------------------------------------------------------------------------------------------------- |
| `signal`             | HTTP, SSE, WebSocket | 呼び出しを中断（`AbortSignal.timeout(ms)` → `NET_TIMEOUT`、手動中止 → `NET_ABORTED`）                               |
| `onUploadProgress`   | HTTP                 | ストリーミングリクエストボディのアップロード進捗を報告                                                              |
| `onDownloadProgress` | HTTP                 | 宣言されたレスポンスボディのダウンロード進捗を報告                                                                  |
| `beforeConnect`      | WebSocket            | このセッションに限り、クライアントレベルの `beforeConnect` フックを置き換え                                         |
| `protocols`          | WebSocket            | このセッションに限り、クライアントレベルのサブプロトコル一覧を置き換え                                              |
| `heartbeat`          | WebSocket            | このセッションに限り、クライアントレベルのハートビート設定を置き換え                                                |
| `retry`              | HTTP, SSE, WebSocket | この呼び出しに限り、クライアントレベルのリトライポリシーを置き換えます。HTTP の `budget` はクライアントに残ります。 |

## 3. ブラウザのシングルトン vs サーバーのリクエストスコープ

- **ブラウザアプリケーション**: エンドポイント、インターセプター、認証情報がブラウザ全体で共通である場合、モジュールスコープの単一の `DerivableClient` を共有します。
- **サーバー / SSR アプリケーション**: ヘッダー、Cookie、認証トークン、テナントコンテキストがリクエスト固有である場合、**各インバウンドリクエストの境界内で新しいクライアントを生成** します。プロセス共通のクライアントにユーザー固有の認証情報を保持させてはいけません。

## 4. 複数エンドポイントとロードバランシング [#multiple-endpoints]

`withEndpoint(...urls)` は 1 つ以上の候補ベース URL を受け取ります。デフォルトでは以下の動作になります。

- 各クライアントは [`pickFirstBalancer`](/ja-JP/api/core/pickfirstbalancer) を使い、`NET_UNREACHABLE` または `NET_UNAVAILABLE`（HTTP 502、503、504）まで最初の URL に留まります。
- **リトライはデフォルトでオフです。** 呼び出しの試行は 1 回です。`withRetry()` は `withRetry({})` と同等で、HTTP、SSE、WebSocket のいずれも、バックオフ付きで最大 3 回リトライします。失敗のたびにバランサーはすべてのエンドポイントから選び直すため、pick-first では接続拒否のあとのリトライが次のエンドポイントに達し、単一のエンドポイントは遅延のあとにもう一度試されます。HTTP の Finagle リトライバジェットはクライアント構成に属し、バランサーの同一性とは無関係に、その派生クライアント間で共有されます。

<include cwd lang="typescript">
  examples/client/multiple-endpoints.ts#example
</include>

`attemptTimeoutMs` は 1 回の試行を区切ります。HTTP はレスポンスボディの終わりまで、SSE はレスポンスヘッダーまで、WebSocket は `open` まで数えます。リトライなしの時間制限は `withRetry({ maxRetries: 0, attemptTimeoutMs })` と書いてください。リトライのオプションは実行時には検証されません。判断の順序と、`withSSEReconnect` および `withWebSocketReconnect` からの移行は、[ロードバランシングとフェイルオーバー](/ja-JP/docs/load-balancing#retries) を参照してください。

### ヘルスフィルタリングと P2C [#health-filtering-and-p2c]

ピアサーバーのレプリカ群に対しては、[`roundRobinBalancer`](/ja-JP/api/core/roundrobinbalancer) や [`p2cBalancer`](/ja-JP/api/core/p2cbalancer)（PeakEwma RTT × 処理中負荷）が `outlierDetection` オプションを取れます。オブジェクトを渡さない限りオフです（デフォルトにするには `{}` です）。失敗を数えてエンドポイントをしばらく隔離し、独自の `isHealthy` 関数が拒否するエンドポイントをスキップします。何が健全かを決めるのは Defjs ではありません。デフォルトでは、コードを持つ結果をすべて失敗としてカウントし（`NET_TIMEOUT` と `NET_BODY_INCOMPLETE` を含む）、その規則は `isFailure` で置き換えられます。生のレスポンス `status` はカスタムバランサー専用です。

リトライバジェット、失敗による隔離と独自のヘルス関数、P2C 負荷推定、カスタムバランサーの詳細は、専用の [ロードバランシングとフェイルオーバー](/ja-JP/docs/load-balancing) ガイドを参照してください。

## 6. クライアントオプションヘルパーリファレンス

| ヘルパー                                                                           | 役割                                                                                                                                                                                                                                                                                                                                                               |
| ---------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| `withEndpoint(...urls)`                                                            | 1 つ以上の候補ベース URL を設定（以前のリストを上書き）                                                                                                                                                                                                                                                                                                            |
| `withHeaders(HeadersInit)`                                                         | HTTP および SSE 向けの静的デフォルトヘッダーを設定（ビルダーのヘッダーが優先）                                                                                                                                                                                                                                                                                     |
| `withInterceptors(...items)`                                                       | HTTP、SSE、WebSocket のインターセプターをオニオン順で末尾に追加                                                                                                                                                                                                                                                                                                    |
| `withQuerySerializer(fn)`                                                          | エイリアス適用済みのクエリオブジェクトをクエリ文字列にシリアライズ                                                                                                                                                                                                                                                                                                 |
| `withCredentials(boolean)`                                                         | `true` の場合、HTTP および SSE の Fetch に `credentials: "include"` を設定                                                                                                                                                                                                                                                                                         |
| `withXSRF(options?)`                                                               | `@defjs/core/xsrf` から。ブラウザでは、同一オリジンに対するデータ変更 HTTP リクエストで XSRF クッキーをヘッダーにコピーします。`location` または `document` がない実行環境（Worker を含む）では、`withXSRF()` が例外を投げます。ブラウザとサーバーで共有するコードは、このオプションをブラウザだけで追加します。別の出所のトークンはインターセプターで設定します。 |
| `withBalancer(balancer)`                                                           | エンドポイント選択戦略を置き換え（`pickFirstBalancer`、`roundRobinBalancer`、`p2cBalancer`）                                                                                                                                                                                                                                                                       |
| `withRetry(options?)`                                                              | HTTP、SSE、WebSocket のオプトインのリトライを設定します。リトライ回数、バックオフ、メソッド、試行タイムアウト、`shouldRetry` 関数、HTTP のクライアント所有バジェットです。                                                                                                                                                                                         |
| `withSSEOnInvalidEvent`                                                            | struct がない、または検証に失敗した SSE イベントを観測します。                                                                                                                                                                                                                                                                                                     |
| `withWebSocketHeartbeat` / `withWebSocketProtocols` / `withWebSocketBeforeConnect` | WebSocket セッションのデフォルト設定を構成                                                                                                                                                                                                                                                                                                                         |
| `withHTTPHandle` / `withSSEHandle` / `withWebSocketHandle`                         | カスタムまたはモックのトランスポート実装を注入                                                                                                                                                                                                                                                                                                                     |
