# SSE ストリームを受信する

各 `EventStreamHandle` は、単一の非同期イテレーターを提供します。途中の `break` や `return` で基盤の Fetch ストリームがリークしないよう、`finally` ブロック内で必ず `stream.close(...)` と `await stream.closed` を実行してください。

サーバーが最初のイベントとして `{ "text": "build started" }` を持つ `line` を送信した場合、スクリプトの出力は以下のようになります。

```txt
build started
```

- クライアント側で [`withSSEReconnect(...)`](/ja-JP/api/core/withssereconnect) を設定しない限り、ネットワークエラーや読み取り障害時に SSE が自動再接続されることはありません。
- `withSSEReconnect` にオプションオブジェクトを指定して有効化した場合、障害ごとの試行回数 `attempts` はデフォルトで `3` 回となり、ハンドシェイクが成功するたびにリセットされます（`attempts: 0` で再接続を無効化できます）。カスタムの `shouldReconnect` を指定しない限り、再接続されるのは `GET`、`HEAD`、`OPTIONS`、`PUT`、`DELETE` リクエストだけです。`ReadableStream` ボディを持つリクエストは再接続されません。詳細は [SSE イベントストリーム](/ja-JP/docs/sse) を参照してください。
