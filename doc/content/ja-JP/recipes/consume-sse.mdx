# SSE イベントの受信 (Consume an SSE stream)

各 `EventStreamHandle` は、単一の非同期イテレーターを提供します。途中の `break` や `return` で基盤の Fetch ストリームがリークしないよう、`finally` ブロック内で必ず `stream.close(...)` と `await stream.closed` を実行してください。

<Tabs items={["sdk/deployments.ts", "app/main.ts", "deploy-events.ts"]}>
  <Tab value="sdk/deployments.ts">
```ts
import { defineEventStream, struct } from "@defjs/core";

export const deployEvents = defineEventStream({
  path: "/deployments/events",
  events: {
    line: struct.object({ text: struct.string() }),
  },
});
```
  </Tab>
  <Tab value="app/main.ts">
```ts
import { createClient, withEndpoint } from "@defjs/core";
import { deployEvents } from "../sdk/deployments.ts";

const client = createClient(withEndpoint("https://api.example.com"));

async function main() {
const [error, stream] = await deployEvents(client);
if (error) {
console.error(error.code);
return;
}
try {
for await (const event of stream) {
if (event.event === "line") {
console.log(event.data.text);
break;
}
}
} finally {
stream.close("consumer-finished");
await stream.closed;
}
}

void main();

````

サーバーが最初のイベントとして `{ "text": "build started" }` を持つ `line` を送信した場合、スクリプトの出力は以下のようになります。

```txt
build started
````

- クライアント側で [`withSSEReconnect(...)`](/ja-JP/api/core/withssereconnect) を明示的に設定しない限り、ネットワークエラーや読み取り障害時に SSE が自動再接続されることはありません。
- `withSSEReconnect` にオプションオブジェクトを指定して有効化した場合、障害ごとの試行回数上限 `attempts` はデフォルトで `3` 回となり、ハンドシェイクが成功するたびにリセットされます（`attempts: 0` で再接続を無効化できます）。カスタムの `shouldReconnect` を指定しない限り、再実行可能なボディを持つ `GET`、`HEAD`、`OPTIONS`、`PUT`、`DELETE` リクエストのみが再接続されます。詳細は [SSE イベントストリーム](/ja-JP/docs/sse) を参照してください。
