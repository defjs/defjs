# SSE ストリームを消費する

ストリームあたり非同期イテレータは 1 つです。早めの exit で Fetch 試行を漏らさないよう、`finally` で `close` + `await stream.closed` を置きます。

詳細は [SSE](/ja-JP/docs/sse) を見てください。

<include cwd meta="notifications.ts">
  examples/recipes/consume-sse.ts#example
</include>

`api.example.com` はプレースホルダーです。最初のイベントが `message` で、データが `{ "text": "hello from the server" }` のサーバーに対して、このスニペットは次のように出力します。

```txt
hello from the server
```

SSE は `withSSEReconnect(...)` を有効にしない限り、ネットワーク/読み取りの失敗をリトライしません。再接続オブジェクトを指定すると、`attempts` のデフォルトは障害ごとに `3` です。ハンドシェイクに成功すると、予算とバックオフの指数がリセットされます。`attempts: 0` はリトライを無効にします。不正な数値の再接続オプションは、リクエスト前に `REQ_OPTIONS_INVALID` で失敗します。[検証規則](/ja-JP/api/core/withssereconnect) を参照してください。`shouldReconnect` がなければ、再接続するのは `GET`、`HEAD`、`OPTIONS`、`PUT`、`DELETE` のリクエストだけです。`ReadableStream` をボディに持つリクエストは再接続しません。
