# SSE ストリームを受信する

各 `EventStreamHandle` は、単一の非同期イテレーターを提供します。途中の `break` や `return` で基盤の Fetch ストリームがリークしないよう、`finally` ブロック内で必ず `stream.close(...)` と `await stream.closed` を実行してください。

サーバーが最初のイベントとして `{ "text": "build started" }` を持つ `line` を送信した場合、スクリプトの出力は以下のようになります。

```txt
build started
```

- クライアント側で [`withRetry(...)`](/ja-JP/api/core/withretry) を設定しない限り、ネットワークエラーや読み取り障害時に SSE が自動再接続されることはありません。
- `withRetry(...)` を設定した場合、障害ごとの `maxRetries` はデフォルトで `3` となり、ハンドシェイクが成功するたびにリセットされます（`maxRetries: 0` でリトライを無効化できます）。カスタムの `shouldRetry` を指定しない限り、リトライされるのは `GET`、`HEAD`、`OPTIONS`、`TRACE`、`PUT`、`DELETE` リクエストだけです。`ReadableStream` ボディを持つリクエストはリトライされません。詳細は [SSE イベントストリーム](/ja-JP/docs/sse) を参照してください。
