# SDK の作成と公開 [#publish-an-http-sdk-without-hiding-execute]

Defjs の SDK は、共有の `struct` モデル（`src/models/`）とドメインごとの操作定義モジュール（`src/services/`）をツリーシェイク可能な npm パッケージとして構成し、`createClient(...)`、エンドポイント、認証情報、インターセプターの設定は利用側アプリケーションに委ねます。

エンドポイントを状態を持つ `Service` クラス（`ObjectsService.putObject(...)` など）でラップする従来の OpenAPI ジェネレーターとは異なり、Defjs の SDK は**独立した純粋関数の操作定義**（`putObject`、`getObject`、`listObjectsV2`）を直接 export し、アプリケーション側のクライアントを渡して呼び出します。

---

## 1. SDK パッケージの構成と定義

Amazon S3 互換のオブジェクトストレージ SDK（`@company/s3-sdk`）を例に、パッケージを 2 つのレイヤーに分割します。

- **`src/models/`**：複数の操作で共有する `struct` スキーマと `Infer<typeof ...>` による TypeScript 型（値と型を同じ識別子で export することで、利用側は 1 つの import でランタイムスキーマと静的型の両方として利用できます）。
- **`src/services/`**：リソース領域ごとに分割した操作モジュール（`buckets.ts`、`objects.ts`）。各モジュールは独立した `defineRequest` 純粋関数を export し、同期純粋関数 `builder` によってフラットな入力を `path`、`query`、`headers`、およびバイナリ `body` に振り分けます。

- **`Service` クラスを使わず純粋関数を export する**：すべての操作（`listBuckets`、`listObjectsV2`、`getObject`、`putObject`、`deleteObject`）は、独立した `defineRequest` の値として export します。`class` や名前空間オブジェクトでラップしないでください。単体の関数として公開することで、`@defjs/core` と同じ呼び出し規約（`await putObject(client, input)`）を保ちつつ、`"sideEffects": false` によって未使用のエンドポイントをバンドラーで確実にツリーシェイクできます。
- **空レスポンス・バイナリ・構造化 JSON の使い分け**：`listBuckets` と `listObjectsV2` は `.alias()` のワイヤマッピングを用いて JSON 構造体をデコードします。`getObject` はバイナリの `Blob`（`output: struct.blob()`）をデコードします。`putObject`、`headObject`、`deleteObject` は空のレスポンスボディに対して `output` を省略しつつ、返却タプルの第 3 要素にある `response.headers` から `etag` などのレスポンスヘッダーを参照できます。
- **外部ランタイムのピア依存関係**：`@defjs/core` は利用側アプリケーションと共有される `peerDependency` として維持します。

## 2. ビルドと tarball の検証

`tsdown` を使用して `dist/index.js` と `dist/index.d.ts` をバンドルし、公開前にパッケージの内容を確認します。

```sh
bun install
bun run build
bun pm pack --dry-run
bun pm pack
```

tarball に `dist/index.js` と `dist/index.d.ts` が正しく含まれていることを確認してください。

---

## 3. アプリケーションでの SDK の利用

作成した SDK を `@defjs/core` と共にインストールします。

```sh
bun add @company/s3-sdk @defjs/core@^0.7.0
```

SDK はクライアントを束縛しないため、エンドポイント（AWS S3、Cloudflare R2、MinIO など）、署名インターセプター、リトライポリシーは利用側アプリケーションが所有し、import した各操作を純粋関数として直接呼び出します。

## 4. テストとパッケージの公開

パス・クエリ・ヘッダー・バイナリボディのマッピング、`output` のデコード、`ETag` レスポンスヘッダー、宣言された `HTTP_STATUS`（`S3Error`）Fault、およびキャンセル処理を網羅した [インメモリのハンドルテスト](/ja-JP/recipes/test-with-handle) を通じて、export された定義を検証します。検証完了後、パッケージを npm に公開します。

```sh
bun publish --access public
```

詳細は [HTTP 操作](/ja-JP/docs/http)、[Client](/ja-JP/docs/client)、[テスト](/ja-JP/docs/testing)、および [コアアーキテクチャ](/ja-JP/docs/design-decisions) を参照してください。
