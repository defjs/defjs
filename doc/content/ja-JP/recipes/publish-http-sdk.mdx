# SDK の作成と公開 [#publish-an-http-sdk-without-hiding-execute]

Defjs の SDK は、純粋な操作定義と Struct スキーマを npm パッケージとして export します。一方、`createClient(...)`、ベース URL、認証情報、インターセプターの設定は利用側アプリケーションに委ねます。

---

## 1. SDK パッケージの定義

操作定義、バレル export（エントリポイント）、`package.json`、`tsconfig.json` を専用のパッケージディレクトリ内に配置し、`@defjs/core` を `peerDependency` として宣言します。

```ts

```
  </Tab>
  <Tab value="package.json">
```json
{
  "name": "@company/orders-sdk",
  "version": "0.1.0",
  "type": "module",
  "sideEffects": false,
  "files": ["dist"],
  "exports": {
    ".": {
      "types": "./dist/index.d.ts",
      "default": "./dist/index.js"
    }
  },
  "scripts": {
    "build": "tsdown --platform neutral"
  },
  "peerDependencies": {
    "@defjs/core": "^0.6.0"
  },
  "devDependencies": {
    "@defjs/core": "^0.6.0",
    "tsdown": "^0.23.3",
    "typescript": "^7.0.2"
  }
}
```
  </Tab>
  <Tab value="tsconfig.json">
```json
{
  "compilerOptions": {
    "target": "ES2022",
    "module": "ESNext",
    "moduleResolution": "bundler",
    "lib": ["ES2022", "ESNext.Disposable", "DOM", "DOM.Iterable"],
    "strict": true,
    "noEmit": true

}
```
  </Tab>
</Tabs>

- `@defjs/core` は利用側アプリケーションと共有される外部ランタイム `peerDependency` として維持します。
- `"sideEffects": false` を設定することで、アプリケーションが一部の操作のみを import した場合に、バンドラーが未使用のエンドポイントを安全にツリーシェイク（不要コード削除）できるようにします。

---

## 2. ビルドと tarball の検証

`tsdown` を使用して `dist/index.js` と `dist/index.d.ts` をバンドルし、公開前にパッケージの内容を確認します。

```sh
bun install
bun run build
bun pm pack --dry-run
bun pm pack
```

tarball に `dist/index.js` と `dist/index.d.ts` が正しく含まれていることを確認してください。

---

## 3. アプリケーションでの SDK の利用

作成した SDK を `@defjs/core` と共にインストールします。

```sh
bun add @company/orders-sdk @defjs/core@^0.6.0
```

アプリケーション側で独自の `Client` を作成し、import した操作に渡して実行します。

<include cwd meta='title="app.ts"'>
  examples/recipes/publish-http-sdk/app.ts#example
</include>

```txt
paid
```

本番コードでは、相対パス `./orders-sdk` を公開されたパッケージ名 `@company/orders-sdk` に置き換え、`withHTTPHandle(...)` を削除してプラットフォーム標準の `fetch` を使用します。

---

## 4. テストとパッケージの公開

リクエストマッピング、`output` のデコード、宣言された `HTTP_STATUS` エラー、キャンセル処理を網羅した [インメモリのハンドルテスト](/ja-JP/recipes/test-with-handle) を通じて、export された定義を検証します。検証完了後、パッケージを npm に公開します。

```sh
bun publish --access public
```

詳細は [HTTP 操作](/ja-JP/docs/http)、[Client](/ja-JP/docs/client)、[テスト](/ja-JP/docs/testing)、および [コアアーキテクチャ](/ja-JP/docs/design-decisions) を参照してください。
