# 宣言済み 404 付きの GET

成功と 404 のボディの両方を宣言します。`error.code` と `error.status` で分岐すると、宣言済みの miss に対して型付きの `error.data` が得られます。

詳細は [HTTP](/ja-JP/docs/http) と [Errors](/ja-JP/docs/errors) を見てください。

<include cwd meta="get-user.ts">
  examples/recipes/get-declared-404.ts#example
</include>

`api.example.com` はプレースホルダーです。`GET /users/7` に `200` と `{ "id": 7, "name": "Ada" }` で応答するサーバーに対して、このスニペットは次のように出力します。

```txt
Loaded Ada from 200
```

2xx 以外の status は `HTTP_STATUS` です。`error` を宣言すればそのボディに型が付き、`error` を省けば `error.data` は `undefined` のまま、ボディは読まれません。宣言した `error` のボディを読み取れない場合（media type の不一致、不正な JSON、形の不一致）は、代わりに `RES_*` フォールトになります。ひとつの `error` Struct が 2xx 以外のすべての status を受け持つので、形が異なるときは `struct.or(...)` か判別可能な union を使ってください。
