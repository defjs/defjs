### テストを書くときに押さえたい 3 点

- **`new Request(input, init)` で包む理由**：`withHTTPHandle` は標準の `fetch(input, init)` と同じ引数を受け取るため、`new Request(input, init)` にまとめることで `method`・`url`・`headers`・`await request.json()` を一貫して検証できます。
- **`withEndpoint("https://fixture.invalid")` が必要な理由**：`createClient` は `withHTTPHandle` に届く前にベース URL の解決と検証を行います。`.invalid` は RFC 予約ドメインなので誤設定しても実 DNS に飛びません。
- **3 パターンの HTTP 結果を再現する方法**：
  - `2xx` 成功：`Response.json(...)` を返す -> `[null, data, response]`
  - `4xx` / `5xx` エラー：`Response.json(..., { status: 422 })` を返す -> `err.code === "HTTP_STATUS"`
  - ネットワーク障害：`Promise.reject(new TypeError("fetch failed"))`（または `throw`）を使う -> `err.code === "NET_UNREACHABLE"`。`Response.error()` はステータス `0` の `Response` として `HTTP_STATUS` 扱いになるため使わないでください。

本番環境では `withEndpoint(...)` を設定したクライアントで同じ `getOrder` 操作を呼び出すだけです。業務ロジックやリトライ、UI テストの詳細は [テスト](/ja-JP/docs/testing) および [Client](/ja-JP/docs/client) を参照してください。
