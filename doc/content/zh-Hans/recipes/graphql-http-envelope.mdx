# 解包 GraphQL HTTP 信封

Defjs 不内嵌 GraphQL 客户端或 `errorPolicy`。把基于 HTTP 的 GraphQL 建模为普通 `POST` 操作，其 `builder` 发送 `{ query, operationName, variables }`。在信封 struct 上把 `data` 标为 `.nullish()`，让省略的 `data` 和 `data: null` 都能通过结构校验，然后在应用辅助函数中解包 `errors[]`：

运行输出：

```txt

```

- HTTP `200` 只表示 GraphQL 信封完整到达。`errors[]` 中的领域错误（即使伴随 `data: null`）是应用层结果，而不是 `RES_STRUCT_MISMATCH` Fault。
- 协议专用信封为何留在应用辅助函数中，见[核心架构设计](/zh-Hans/docs/design-decisions)。
