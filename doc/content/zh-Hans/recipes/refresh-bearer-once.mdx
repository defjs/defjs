# 401 后刷新一次 Bearer 令牌

在 Defjs 中，`next(request)` 调用拦截器链内部剩余的部分——不会从最外层拦截器重新分发。把令牌附加、单飞刷新去重和一次性 `401` 重放都放在**同一个** HTTP 拦截器中，这样外层日志或计时拦截器不会运行两次：


请求体可重放，不代表业务操作可以重复执行。匹配到 401 后，这个拦截器也会重新发送 JSON `POST`：共两次 HTTP 投递，第一次被拒绝，第二次被接受。只有当认证在业务处理函数运行前拒绝第一次投递时，才能把它用于写操作；两次投递之间必须保留稳定的幂等键，并由服务端去重。如果无法满足该契约，应返回 401，而不是自动重放写操作。完整示例不会重放 `ReadableStream` 请求体。

关于洋葱顺序和重试边界，见[拦截器](/zh-Hans/docs/interceptors)。
