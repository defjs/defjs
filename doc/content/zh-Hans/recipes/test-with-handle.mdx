### 写测试时用得上的三个细节

- **为什么在句柄里包一层 `new Request(input, init)`**：`withHTTPHandle` 拿到的签名和标准 `fetch(input, init)` 一样，可能是 URL 字符串加配置对象，也可能是 `Request` 实例；统一包成 `new Request(input, init)` 后，就能直接读 `method`、`url`、`headers` 和 `await request.json()`。
- **为什么要配 `withEndpoint("https://fixture.invalid")`**：客户端在把请求交给 `withHTTPHandle` 之前会先做 URL 拼接与校验；`.invalid` 是 RFC 保留域名，就算线上误用也不会发出真实 DNS 查询。
- **三种常见返回怎么造**：
  - `2xx` 成功：`Response.json(...)` -> 得到 `[null, data, response]`。
  - `4xx` / `5xx` 接口报错：`Response.json(..., { status: 422 })` -> 得到 `err.code === "HTTP_STATUS"`。
  - 断网 / 连接失败：直接 `Promise.reject(new TypeError("fetch failed"))`（或抛出异常）-> 得到 `err.code === "NET_UNREACHABLE"`。注意**不要**用 `Response.error()`，Defjs 会把返回的 `Response`（哪怕 `status` 是 `0`）当作收到 HTTP 响应来处理。

上线时把 `withHTTPHandle(...)` 去掉，只保留指向真实接口的 `withEndpoint(...)`，`getOrder` 等操作代码一行都不用改。更多项目测试写法（业务函数、自定义拦截器、React/Vue 组件、假定时器）请看 [测试指南](/zh-Hans/docs/testing) 与 [Client 配置](/zh-Hans/docs/client)。
