# 消费 SSE 服务端推送流

每个 `EventStreamHandle` 句柄仅暴露单一消费者的异步迭代器。请务必将 `stream.close(...)` 与 `await stream.closed` 放置在 `finally` 代码块中，确保即使遇到中途 `break` 提前跳出或 `return` 返回时，底层的 Fetch 数据流也能得到绝对可靠的释放：

<Tabs items={["sdk/deployments.ts", "app/main.ts", "deploy-events.ts"]}>
<Tab value="sdk/deployments.ts">

```ts
import { defineEventStream, struct } from "@defjs/core";

export const deployEvents = defineEventStream({
  path: "/deployments/events",
  events: {
    line: struct.object({ text: struct.string() }),
  },
});
```

</Tab>
<Tab value="app/main.ts">

```ts
import { createClient, withEndpoint } from "@defjs/core";
import { deployEvents } from "../sdk/deployments.ts";

const client = createClient(withEndpoint("https://api.example.com"));

async function main() {
  const [error, stream] = await deployEvents(client);
  if (error) {
    console.error(error.code);
    return;
  }
  try {
    for await (const event of stream) {
      if (event.event === "line") {
        console.log(event.data.text);
        break;
      }
    }
  } finally {
    stream.close("consumer-finished");
    await stream.closed;
  }
}

void main();
```

若服务端的第一个推送事件为 `line` 且数据载荷为 `{ "text": "build started" }`，该脚本将打印：

```txt
build started
```

- 除非在 Client 上显式配置了 [`withSSEReconnect(...)`](/zh-Hans/api/core/withssereconnect)，否则 SSE 在遇到网络抖动或流读取故障时默认不会自动重连。
- 当传入配置对象开启 `withSSEReconnect` 时，单次断线的重试预算 `attempts` 默认为 `3` 次，并在握手成功后重置（设置 `attempts: 0` 则关闭重试）。在未提供自定义 `shouldReconnect` 的情况下，仅有携带可重放请求体的 `GET`、`HEAD`、`OPTIONS`、`PUT` 和 `DELETE` 请求支持自动重连。更多细节请参阅 [SSE 事件流](/zh-Hans/docs/sse)。
