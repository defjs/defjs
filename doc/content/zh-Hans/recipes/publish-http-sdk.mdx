# 构建并发布 SDK [#publish-an-http-sdk-without-hiding-execute]

Defjs SDK 把纯操作定义和 struct schema 作为 npm 包导出，而把 `createClient(...)`、端点、凭据和拦截器留在消费方应用中。

---

## 1. 定义 SDK 包

把操作定义、统一导出入口、`package.json` 和 `tsconfig.json` 放在独立的包目录中，并把 `@defjs/core` 声明为 `peerDependency`：

  </Tab>
  <Tab value="package.json">
```json
{
  "name": "@company/orders-sdk",
  "version": "0.1.0",
  "type": "module",
  "sideEffects": false,
  "files": ["dist"],
  "exports": {
    ".": {
      "types": "./dist/index.d.ts",
      "default": "./dist/index.js"
    }
  },
  "scripts": {
    "build": "tsdown --platform neutral"
  },
  "peerDependencies": {
    "@defjs/core": "^0.6.0"
  },
  "devDependencies": {
    "@defjs/core": "^0.6.0",
    "tsdown": "^0.23.3",
    "typescript": "^7.0.2"
  }
}
```
  </Tab>
  <Tab value="tsconfig.json">
```json
{
  "compilerOptions": {
    "target": "ES2022",
    "module": "ESNext",
    "moduleResolution": "bundler",
    "lib": ["ES2022", "ESNext.Disposable", "DOM", "DOM.Iterable"],
    "strict": true,
    "noEmit": true
  },
  "include": ["src/**/*.ts"]
}
```
  </Tab>
</Tabs>

- `@defjs/core` 保持为外部运行时 `peerDependency`，与消费方应用共享。
- `"sideEffects": false` 让打包器在应用只导入部分操作时 tree-shake 掉未使用的操作。

---

## 2. 构建并验证 tarball

用 `tsdown` 打包 `dist/index.js` 和 `dist/index.d.ts`，发布前检查包内容：

```sh
bun install
bun run build
bun pm pack --dry-run
bun pm pack
```

确认 tarball 中包含 `dist/index.js` 和 `dist/index.d.ts`。

---

## 3. 在应用中使用 SDK

把 SDK 与 `@defjs/core` 一起安装：

```sh
bun add @company/orders-sdk @defjs/core@^0.6.0
```

应用创建自己的 `Client`，并传入导入的操作：

<include cwd meta='title="app.ts"'>
  examples/recipes/publish-http-sdk/app.ts#example
</include>

```txt
paid
```

在生产代码中，把相对导入 `./src/orders.ts` 替换为 `@company/orders-sdk`，并移除 `withHTTPHandle(...)` 以使用平台 `fetch`。

---

## 4. 测试并发布

用[内存句柄测试](/zh-Hans/recipes/test-with-handle)覆盖导出的定义：请求映射、`output` 解码、声明的 `HTTP_STATUS` Fault 和取消。验证通过后发布包：

```sh
bun publish --access public
```

见 [HTTP 请求](/zh-Hans/docs/http)、[Client](/zh-Hans/docs/client)、[测试](/zh-Hans/docs/testing) 与 [核心架构设计](/zh-Hans/docs/design-decisions)。
