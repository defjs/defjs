# 构建并发布 SDK [#publish-an-http-sdk-without-hiding-execute]

基于 Defjs 架构的 SDK 仅向外导出纯粹的接口操作定义与 Struct 结构体契约作为 npm 依赖包，而将 `createClient(...)`、服务基地址、认证凭据与拦截器留给具体的消费方应用进行配置。

---

## 1. 声明并定义 SDK 软件包

将你的接口操作定义、统一导出入口、`package.json` 与 `tsconfig.json` 放置在专属的 SDK 项目目录中，并将 `@defjs/core` 声明为外部共享的 `peerDependency`：

<Tab value="src/orders.ts">

<include cwd meta='title="src/orders.ts"'>

</include>

</Tab>
<Tab value="src/index.ts">

```ts
export { getOrder } from "./orders";
```

</Tab>
<Tab value="package.json">

```json
{
  "name": "@company/orders-sdk",
  "version": "0.1.0",
  "type": "module",
  "sideEffects": false,
  "files": ["dist"],
  "exports": {
    ".": {
      "types": "./dist/index.d.ts",
      "default": "./dist/index.js"
    }
  },
  "scripts": {
    "build": "tsdown --platform neutral"
  },
  "peerDependencies": {
    "@defjs/core": "^0.6.0"
  },
  "devDependencies": {
    "@defjs/core": "^0.6.0",
    "tsdown": "^0.23.3",
    "typescript": "^7.0.2"
  }
}
```

</Tab>
<Tab value="tsconfig.json">

```json
{
  "compilerOptions": {
    "target": "ES2022",
    "module": "ESNext",
    "moduleResolution": "bundler",
    "lib": ["ES2022", "ESNext.Disposable", "DOM", "DOM.Iterable"],
    "strict": true,
    "noEmit": true
  },
  "include": ["src/**/*.ts"]
}
```

</Tab>
</Tabs>

- `@defjs/core` 保持为外部运行时的 `peerDependency`，与调用方应用共享同一个 Core 实例。
- 配置 `"sideEffects": false` 允许现代打包工具进行精确的 Tree-shaking 摇树优化，当应用仅导入部分操作时自动剔除无用代码。

---

## 2. 构建产物并验证打包文件

使用 `tsdown` 将入口文件编译为 `dist/index.js` 与 `dist/index.d.ts`，并在正式发布前审查 tarball 打包内容：

```sh
bun install
bun run build
bun pm pack --dry-run
bun pm pack
```

确保 `dist/index.js` 和 `dist/index.d.ts` 正确包含在最终生成的压缩包内。

---

## 3. 在消费方应用程序中接入 SDK

将发布后的 SDK 与 `@defjs/core` 一同安装至消费方项目中：

```sh
bun add @company/orders-sdk @defjs/core@^0.6.0
```

消费方应用程序创建属于自己的 `Client`，并将其传入导入的接口操作中执行：

<include cwd meta='title="app.ts"'>
  examples/recipes/publish-http-sdk/app.ts#example
</include>

```txt
paid
```

在真实的生产代码中，将相对路径导入 `./orders-sdk` 替换为 npm 包名 `@company/orders-sdk`，并移除离线专用的 `withHTTPHandle(...)` 即可直接使用宿主平台的原生 `fetch`。

---

## 4. 离线自动化测试与发布

在发布前，通过[本地 HTTP 测试](/zh-Hans/recipes/test-with-handle)对导出的接口定义进行完整的在内存测试，覆盖请求参数映射、`output` 解码、声明的 `HTTP_STATUS` 错误以及取消逻辑。全部验证通过后，即可一键发布软件包：

```sh
bun publish --access public
```

更多细节请参阅 [HTTP 请求](/zh-Hans/docs/http)、[Client](/zh-Hans/docs/client)、[测试](/zh-Hans/docs/testing) 与 [核心架构设计](/zh-Hans/docs/design-decisions)。
