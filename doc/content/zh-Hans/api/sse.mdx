# SSE

声明一条事件流，带着 client 调用该操作，迭代事件，再 close。

## defineEventStream()

<ApiSignature name="defineEventStream" />

- **definition** — `path` 和 `events` map；可选 `method`（默认 `'GET'`）、`operation`、`input`、`error`、`maxBufferSize`（默认 `64 * 1024`）和 `maxQueueSize`（默认 `1024`）。只要声明了 `input`，就必须显式提供 `builder`。`input` 只定义入参，每个值放在哪里只由 builder 决定。只有没有 `input` 的定义可以省略 `builder`。这些 `definition` 成员写在 [`EventStreamDefinition`](/zh-Hans/api/core/eventstreamdefinition-type)。只有给出了 error struct 类型时 `error` 才必填，`builder` 恰好在声明了 `input` 时才必填。
- **返回** 一个操作。第一个参数是 [`Client`](/zh-Hans/api/core/client-type)。其余参数只是 input。调用它即开始这条流。

<include cwd>examples/api/define-event-stream.ts#example</include>

调用返回 `[null, stream, open]` 或 `[error, undefined, open?]`。声明了 `error` 时，fault 是那个 struct 的 `Fault`；否则是 `Fault<undefined>`。通过从 [`RequestOptions`](/zh-Hans/api/core/requestoptions-type) 派生 client 来传入 `signal`。SSE 只读取 `signal`，忽略进度和 WebSocket 字段。

## EventStreamExecuteOptions

<ApiSignature name="EventStreamExecuteOptions" />

`EventStreamExecuteOptions` 是 `{ signal? }`。没有 `timeout` 或 `abort` 字段，也没有进度回调。`signal` 覆盖整条流，包括打开之后。期限是 `AbortSignal.timeout(ms)`，归类为 `NET_TIMEOUT`。手动中止是 `NET_ABORTED`。没有仅限启动期的期限，也没有 client 级的默认期限。应用若需要仅限启动期的期限，就自己建一个 `AbortController`，用定时器以 `new DOMException("...", "TimeoutError")` 中止它，并在 await 返回后清掉定时器。

## EventStreamHandle

<ApiSignature name="EventStreamHandle" />

tuple 第三项是 `open` 的启动快照；重连之后，`stream.open` 跟随最新的连接。这一第三项仅对返回的 Defjs 原生 handle 或透传同一 live `open` 对象的 wrapper 保证是所属连接首次成功握手的快照；自定义 handle 或显式覆盖 `open` 的 wrapper 则保留其当前公开 `open`，即使已发生重连也一样，因此共享 `closed` 不能绕过 URL 净化或响应头过滤，Defjs 也不从任意元数据变换反推首次握手。自有作用域优先用 `await using stream = handle` 清理。disposer 会停止 Defjs 的读取和重连任务，并等待 reader lock 释放；它不承诺由 provider 控制且卡住的 `ReadableStream.cancel()` promise 一定完成。手动 `close()` / `closed` 仍可使用。

```ts
async function consume(handle: EventStreamHandle<unknown>): Promise<void> {
  await using stream = handle;
  for await (const event of stream) console.log(event);
}
```

结构化实现 `EventStreamHandle` 的代码必须实现 `[Symbol.asyncDispose]()`，并返回同一条自有 teardown 路径。

### EventStreamCloseInfo

<ApiSignature name="EventStreamCloseInfo" />

`kind` 是 `eof`、`aborted` 或 `error`。每个变体都可以带 `reason` 和 `cause`。只有 `error` 有 `code`，取自 [`EventStreamFaultCode`](/zh-Hans/api/core/eventstreamfaultcode-type)：`'CAP_BUFFER_EXCEEDED' | 'CAP_QUEUE_OVERFLOW' | 'EXT_HOOK_FAILED' | 'EXT_OBSERVER_FAILED' | 'NET_TIMEOUT' | 'NET_UNREACHABLE' | 'REQ_BUILD_FAILED' | 'REQ_OPTIONS_INVALID' | 'RES_DECODE_FAILED' | 'RES_MEDIA_TYPE_INVALID'`。`REQ_BUILD_FAILED` 和 `REQ_OPTIONS_INVALID` 表示流已经打开之后，重连时挑选端点失败。

## EventStructs

<ApiSignature name="EventStructs" />

key 是 SSE 事件名；没有 `event:` 字段的消息名为 `message`。没有任何 key 匹配时，使用 `default` struct。`string` 事件 struct 保留原始 `data` 文本。其余 kind 都是 JSON 文本：`JSON.parse`，再交给 struct。所以裸的 `struct.literal` 需要 JSON 文本，不是没加引号的 token。握手 `error` body 用和 HTTP 一样的 kind 规则：`string` 是文本，`blob` / `file` 是 blob，`arrayBuffer` 是字节，其余是 JSON。

重连在 client 上（`withSSEReconnect`）。SSE `jitter` 是 **0–1 的乘性因子**，和 WebSocket 一样。

成功握手后会重置重试预算和退避指数；它们按每次连接中断计算。无效的数字选项会在打开流之前返回 `REQ_OPTIONS_INVALID`，`maxDelayMs` 限制抖动后的最终延迟。校验规则、默认值和 UTF-8 `Last-Event-ID` 的处理方式见 [`withSSEReconnect`](/zh-Hans/api/core/withssereconnect)。

解析器遵循 WHATWG SSE 的行和字段规则，只移除每条物理流开头的一个 UTF-8 BOM。data 或 ID 值中的 U+FEFF 会被保留；后续带 BOM 前缀的字段名会按未知字段忽略。多行 data 用 `\n` 连接，空行触发携带 data 的事件分发，EOF 时尚未完成的事件会被丢弃。

见 [SSE 指南](/zh-Hans/docs/sse) 和[消费 SSE 流](/zh-Hans/recipes/consume-sse)。

## EventStreamDefinition

`path`、`events`，可选 `method` / `operation` / `input` / `error` / `maxBufferSize` / `maxQueueSize`。请求形状和 HTTP 一样，包括 `body`。`GET` 和 `HEAD` 的 builder 不能返回请求体。只要声明了 `input`，就必须显式提供 `builder`。`input` 只定义入参，每个值放在哪里只由 builder 决定。只有没有 `input` 的定义可以省略 `builder`。

## EventStreamEndpoint

`defineEventStream` 的返回值。第一个参数是 client。其余参数只是 input。

## EventStreamRequestShape

和这条流的 method、path 对应的 `HttpRequestShape` 字段相同。

## StreamAwaitResult

`[null, stream, open]` 或 `[error, undefined, open?]`。

## EventStreamData

从 `EventStructs` map 推出来的解析后事件载荷。
