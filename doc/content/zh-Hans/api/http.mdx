# HTTP

声明一次类型化请求，用 input 打出 command，再 execute。

## defineRequest()

```ts
function defineRequest(definition: RequestDefinition): RequestEndpoint
```

- **definition** — `method`、`path`，可选 `input` struct，可选 `output` 和 `error` struct，可选 `operation`。只要声明了 `input`，就必须显式提供 `builder`，即使输入已经是请求形状也一样。只有没有 `input` 的定义可以省略 `builder`。
- **返回** 一个 endpoint。传入 input 调用，得到 `HttpCommand`。

<include cwd>examples/api/define-request.ts#example</include>

`output` 是 2xx body 的单一 struct；`error` 是每个非 2xx body 的单一 struct。两者都不按状态码分键。省略哪个，那个 body 就根本不会被读——见 [声明即断言](/zh-Hans/docs/design-decisions#声明即断言)。

## executeHttpCommand()

```ts
function executeHttpCommand(clientConfig: ClientConfig, command: HttpCommand, options?: HttpExecuteOptions): Promise<HttpAwaitResult>
```

`client.execute` 走的底层入口。业务代码调 `client.execute(command, options)`。

- **返回** `[null, data, response]` 或 `[fault, undefined, undefined]`。

没有声明 `error` struct，或所声明的 `error` body 能成功解码时，非 2xx 状态才是 `HTTP_STATUS`。声明过 `error` 时它的 `data` 是解码后的错误 body，否则是 `undefined`。如果所声明的 `error` body 无法读取（媒体类型错误、JSON 无效）或与其 struct 不匹配，则 fault 改为 `RES_MEDIA_TYPE_INVALID`、`RES_DECODE_FAILED` 或 `RES_STRUCT_MISMATCH`，响应状态仍会记在它的元数据里。失败时 tuple 第三项是 `undefined`；响应元数据由 fault 携带。

## fetchHandler()

```ts
function fetchHandler(httpRequest: HttpRequest, fetchImpl?: FetchHandle): Promise<HttpResponse<unknown>>
```

默认 HTTP 传输。`fetchImpl` 默认是在发送时解析的全局 `fetch`；`withHTTPHandle` 可换成别的实现。未被替换的平台 Fetch 收到 `(url, init)`，被替换的全局实现或自定义 handle 则收到 `Request`。没有响应到达 client，或读取已声明的 body 失败时，它会 reject，而不是 resolve 一个合成响应。

## makeResponse()

```ts
function makeResponse<R>(options?: MakeResponseOptions<R>): HttpResponse<R>
```

不走网络造一个 `HttpResponse`（interceptor、测试）。默认 status 是 `0`。2xx 时 `ok` 为 true。它返回的值会走和网络响应完全一样的媒体类型检查和声明 struct；不存在受信任的短路。

## 执行选项

## HttpExecuteOptions

```ts
type HttpExecuteOptions = {
  onDownloadProgress?: HttpProgressFn
  onUploadProgress?: HttpProgressFn
} & ({ abort?: AbortSignal; timeout?: never } | { abort?: never; timeout?: number }) & { signal?: AbortSignal }
```

取消是 `abort` **或** `timeout`，不能两个一起：类型层面会拒绝同时传两者，运行时同时传入则以 `REQ_OPTIONS_INVALID` 失败。`signal` 可与其中任一组合，**不是** `abort` 的别名。合法形状：`{ timeout }`、`{ abort }`、`{ signal, timeout }`、`{ signal, abort }`。`{ abort, timeout }` 非法。`timeout` 必须是 `1..2_147_483_647` 的正安全整数。调用省略 `timeout` 时，使用 client 的 `withTimeout` 默认值（仅 HTTP）；`abort` 和 `signal` 会与该默认值组合。

## 类型

### RequestDefinition

`method`、`path`，可选 `input`、`output`、`error`、`operation` 和 `builder`。没有 `responseType`：声明 body 怎么读，由 struct kind 决定。只要声明了 `input`，就必须显式提供 `builder`，即使输入已经是请求形状也一样。只有没有 `input` 的定义可以省略 `builder`。

### HttpAwaitResult

```ts
type HttpAwaitResult<TData = undefined, TErrorData = undefined> =
  | [error: null, result: TData, response: [TData] extends [undefined] ? HttpMeta : DecodedResponse<TData>]
  | [error: FaultOf<TErrorData>, result: undefined, response: undefined]
```

成功时第三项只有在声明过 `output` 时才带 `body`。失败时它是 `undefined`——fault 已经握着当时存在的响应元数据。

### HttpRequest

规范化后的出站请求：`method`、`endpoint`、`headers`、`body`、`abort`、`operation`、`timeout`、`withCredentials`、`xsrf`、`downloadProgress` / `uploadProgress`、`baseEndpoint`、`queryString`、`queryParams`。Interceptor 看到它时，`body` 已经是传输值——JSON 时是 JSON 文本字符串——所以 HMAC 和摘要要针对它来签，而不是针对 struct 输入。Interceptor 看到的 `queryParams` 是 `new URLSearchParams(queryString)`。builder 返回 `URLSearchParams` 时，传过去的就是那个实例。`responseType` 和 `errorResponseType` 是只读的：它们由端点的 `output` 与 `error` struct kind 推导而来，不能修改。

### HttpMeta

```ts
type HttpMeta = {
  readonly headers: Headers
  readonly ok: boolean
  readonly status: number
  readonly statusText: string
  readonly url: string
}
```

响应元数据，只要有响应到达 client 就有。它**不**带 `body`：body 只有在声明过的 struct 解出来之后才存在。

### DecodedResponse

```ts
type DecodedResponse<TBody> = HttpMeta & { readonly body: TBody }
```

body 已按声明的 struct 解码成功的响应。拿到这个类型就是解码确实发生过的证明——这也正是解码失败时只报 `HttpMeta` 的原因。

### HttpResponse

```ts
type HttpResponse<R> = {
  readonly url: string
  readonly status: number
  readonly statusText: string
  readonly headers: Headers
  readonly body: R | null | undefined
  readonly ok: boolean
}
```

响应没有 body 时，`body` 缺省（`undefined`）；JSON `null` 仍是 `null`。该类型带类型标记，所以请用 `makeResponse` 构造，不要用对象字面量。这是传输产出、interceptor 看到的传输形状：`body` 是文本或已解析的 JSON，不是解码后的值。对于 JSON 表示，字符串是 JSON 字符串根，不会再次解析；字节和 blob 仍是原始数据，只解析一次。到达调用方的是 `DecodedResponse`。

### HttpProgressEvent

### HttpProgressFn

`loaded`、`total`、`lengthComputable`。回调可以异步执行。`onDownloadProgress` 或 `onUploadProgress` 抛出异常时，调用会以 `EXT_OBSERVER_FAILED` 失败，抛出的值作为 `cause`；取消和 `timeout` 仍分别报告 `NET_ABORTED` / `NET_TIMEOUT`。只有支持流式发送请求体的运行时（Bun、Node、Deno）才会报告上传进度；在浏览器中，`Blob` / `File`、`ArrayBuffer` 和 `FormData` 请求体会原样发送，不会调用 `onUploadProgress`。

在服务端运行时，FormData 使用序列化后的流，不会先把整个请求体缓冲成 Blob，并且保留实际的 multipart 边界。除非显式提供有效的 `Content-Length`，否则总长度未知。上传转换会保留显式设置的内容类型，但 FormData 必须使用其序列化产生的边界。`loaded` 统计流中的字节，不代表服务器已经确认收到的字节。带非 identity `Content-Encoding` 的下载报告 `total: 0` 和 `lengthComputable: false`；它们的流字节可能已经解压。

见 [HTTP 指南](/zh-Hans/docs/http) 和 [Commands](/zh-Hans/docs/commands)。

## RequestEndpoint

`defineRequest` 的返回值。拿 input 调一下就得到 `HttpCommand`。

## BuilderInput

`builder` 看到的、已经 parse 过的 endpoint input。对象节点带着产出它的 struct，所以 alias、`Date`、`bigint` 编码跟着这个值走。

## HttpRequestShape

```ts
type HttpRequestShape<P extends string, M extends string> = {
  path?: PathValue<P>
  query?: URLSearchParams | QueryRecord
  headers?: HeadersInit | FlatRecord
  body?: Uppercase<M> extends 'GET' | 'HEAD' ? never : BodyValue
}
```

`GET` 和 `HEAD` 的 builder 不能返回请求体。`path` 和 `headers` 必须是扁平标量；`query` 可以嵌套，嵌套对象在运行时需要 `withQuerySerializer`。

`BodyValue` 接受的传输值和 JSON 值见 [`HttpRequestShape`](/zh-Hans/api/core/httprequestshape-type)。

## HttpCommand

请求 builder 返回的不透明 command。传给 `client.execute`。

## UseRequestConfig

进度、取消。`HttpExecuteOptions` 再加一个 `signal`。

## RequestSuccessData

从声明的 `output` struct 推出来的成功 body；没声明时是 `undefined`。

## RequestErrorData

从声明的 `error` struct 推出来的错误 body；没声明时是 `undefined`。

## HttpResponseType

`'arraybuffer' | 'blob' | 'json' | 'text'`

由声明的 struct kind 选出（`string` → `text`，`blob` / `file` → `blob`，`arrayBuffer` → `arraybuffer`，其余 → `json`）。不是 `defineRequest` 上的字段。

## MakeResponseOptions

给 `makeResponse` 的字段：`status`、`statusText`、`url`、`headers`、`body`、`request`。
