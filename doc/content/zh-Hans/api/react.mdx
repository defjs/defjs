# React

把已有的 `@defjs/core` Client 接到 React 树。这个包**不会**创建、缓存或释放这个 Client。它的入口标有 `'use client'`，所以请在客户端组件中导入。需要 React 18 或更高版本。

见 [React 指南](/zh-Hans/docs/integrations/react)。

## ClientProvider

<ApiSignature name="ClientProvider" />

Context Provider。传入 `createClient` 返回的 `DerivableClient`。嵌套的 `ClientProvider` 会覆盖其子树的 Client；`useClient()` 读取最近的一个。传入不同的 `client` 会改变后代读取的 Context 值。

## useClient()

<ApiSignature name="useClient" />

`useClient(overrideClient)` 优先返回显式 Client；省略或传入 `undefined` 时读取最近的 `ClientProvider`。只有两种来源都没有 Client 时才抛出 `Error`，零参数的 `useClient()` 调用仍然有效。把该 Client 传进操作。Hook 返回传入的 [`DerivableClient`](/zh-Hans/api/core/derivableclient-type)；在操作运行处用请求选项调用它可派生一个 `Client` 值。不要把它传给状态设置函数，因为 `setState(client)` 会把它当作更新函数调用。派生出的 `Client` 值不被 `ClientProvider` 或 `useClient` 接受。

始终在组件或自定义 Hook 顶层调用 `useClient(explicitClient)`，即使传了显式 Client，也不要在普通函数或事件回调中调用。不要写 `explicitClient ?? useClient()`，它会条件调用 Hook。覆盖值不写入 Context，也不创建 Provider；Hook 仍然订阅 Context。

- **返回** 显式传入的 Client，或最近 Provider 提供的同一个 Client。
- **抛出** 显式参数与 Context 都未提供 Client 时抛出 `Error`。

## ClientProviderProps

<ApiSignature name="ClientProviderProps" />

`client` 必填，由应用持有。`children` 可选：它是可以调用 `useClient` 的子树。
