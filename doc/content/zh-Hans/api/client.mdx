# Client

`createClient(...)` 返回一个 [`DerivableClient`](/zh-Hans/api/core/derivableclient-type)。从左到右组合 Client 选项，再调用 `client(options?)` 得到一个 [`Client`](/zh-Hans/api/core/client-type) 值并传给操作：`getOrder(client(options), input)`。

## createClient()

<ApiSignature name="createClient" />

选项按顺序生效。当拦截器闭包捕获认证信息或租户信息时，优先在请求边界内创建 Client。返回的工厂是一个函数。调用它会返回 `Client` 值，不执行 I/O。工厂本身也是 `Client`，不带任何请求选项。

- **options** — `withEndpoint` 之类的选项辅助函数。
- **返回** 一个可调用的工厂。基础配置由每个 Client 值共享，运行时不会被冻结。它按约定固定：库不会修改它，应用也不应修改。

## 选项辅助函数

每个辅助函数都返回 `ClientOption`。对同一项设置，后一次调用会替换前一次；`withInterceptors` 例外，它是追加。

### withEndpoint()

<ApiSignature name="withEndpoint" />

按首次出现顺序复制候选基地址 URL，并去除同一字符串的后续副本。后一次 `withEndpoint` 会替换整份列表。它不检查 URL，也不替换均衡器。空列表是合法值，调用会以 `REQ_BUILD_FAILED` 失败。

### withBalancer()

<ApiSignature name="withBalancer" />

替换此后调用使用的均衡器。对象按引用保存。没有这个选项时，每个 Client 各自获得一个 `pickFirstBalancer()`。

### withInterceptors()

<ApiSignature name="withInterceptors" />

按注册顺序追加拦截器。混合类型会在操作运行时按传输过滤。

### withQuerySerializer()

<ApiSignature name="withQuerySerializer" />

替换 HTTP、SSE 和 WebSocket 的查询编码。`serializer(query)` 接收**已编码的网络对象**（别名已应用，`Date` 为 ISO，`bigint` 为字符串），必须返回不带前导 `?` 的查询字符串。请求没有 query 时不会调用它。`builder` 返回 `URLSearchParams` 时会跳过序列化器。

### withHeaders()

<ApiSignature name="withHeaders" />

为 HTTP 和 SSE 请求设置静态默认请求头。WebSocket 请求不使用它们。`headers` 在选项生效时被复制，因此之后修改该对象不会影响 Client。第二次 `withHeaders` 会替换第一次，不会合并。

单个请求的优先级：

1. 默认请求头是起始集合。
2. 请求 `builder` 返回的 `headers` 会替换同名默认值。该名称的第一个值替换默认值；同一数组中的后续值只追加到这次替换上。标量或 `Headers` 实例也会整体替换。其他默认名称保留。
3. 拦截器收到合并后的请求头，并可以修改它们。
4. 使用默认 HTTP 传输时，XSRF 请求头最后添加，且仅在仍然缺失时添加（见 `withXSRF`）。

随请求变化的值（例如刷新后的 Bearer 令牌，或对序列化 body 计算的 HMAC）请用拦截器处理。

没有 Client 级默认期限。某次调用需要期限时，在派生出的 Client 上传入 `signal: AbortSignal.timeout(ms)`。手动中止是 `NET_ABORTED`，`AbortSignal.timeout` 归类为 `NET_TIMEOUT`。

### withXSRF()

<ApiSignature name="withXSRF" />

为 HTTP 请求添加 XSRF 令牌请求头。`options` 就是 `xsrf` 设置，形状与 [`ClientOptions`](/zh-Hans/api/core/clientoptions-type) 上的 `xsrf` 相同：`cookieName`（默认 `XSRF-TOKEN`）、`headerName`（默认 `X-XSRF-TOKEN`）和 `tokenProvider({ request })`。不带参数调用 `withXSRF()` 会启用这些默认值。SSE 和 WebSocket 请求不受影响。

默认 HTTP 传输在以下条件全部成立时添加该请求头：方法不是 `GET`、`HEAD`、`OPTIONS` 或 `TRACE`；请求尚未带有该请求头；请求同源；并且找到了非空令牌。只要存在 `location`（包括 Worker 中），解析后的请求源就必须匹配 `location.origin`；不存在 `location` 时，带 `baseEndpoint` 的请求视为同源。跨源请求不会调用 `tokenProvider`。提供了 provider 时，令牌取自它，否则取自 `document.cookie`；只有存在 `document` 时才读取 cookie。

## 类型

### DerivableClient

<ApiSignature name="DerivableClient" />

`createClient` 返回的根 Client，有两种形态。工厂是一个函数，同时也是不带请求选项的 `Client`，所以 `getOrder(client, input)` 可以直接使用。用 [`RequestOptions`](/zh-Hans/api/core/requestoptions-type) 调用它，会返回仅供单次调用的普通 `Client` 值。该值不可调用，因此 `client()()` 无法通过编译，运行时会抛出 `TypeError`。派生只从工厂发生一次，没有链式调用。类型请写成 `DerivableClient`，不要写 `ReturnType<typeof createClient>`。

### Client

<ApiSignature name="Client" />

`Client` 是一个值，不是函数。调用 [`DerivableClient`](/zh-Hans/api/core/derivableclient-type) 并传入 [`RequestOptions`](/zh-Hans/api/core/requestoptions-type) 会得到一个。`client()` 和 `client(undefined)` 不保存请求选项。`client({})` 保留空快照。该调用会把每个顶层字段读取一次。`protocols` 数组会被复制。`heartbeat` 和 `reconnect` 复制各自的已知字段。缺失的嵌套块保持缺失。`signal`、`beforeConnect` 和回调保持自身身份。被捕获字段上的 getter 会在该调用期间运行；如果它抛出异常，异常会离开该调用。无效数字仍会在之后以 `REQ_OPTIONS_INVALID` 失败。派生不执行 I/O。Client 值不可调用，调用它无法通过编译，运行时会抛出 `TypeError`。每次调用创建一个 Client 值。同一个值可以传给多个操作，但复用携带 `signal` 的值会共享该 signal。`signal` 不会自动组合；要组合 signal，请在应用代码中使用 `AbortSignal.any`。工厂的基础配置仍然共享，不会被冻结。标准 `with*` 辅助函数被应用时会复制它们拥有的固定记录。

不要把工厂传给 React 状态设置函数（`setState(factory)` 会把它当作更新函数调用），也不要把它用作 Vue `watch` 或 `computed` 的来源（那些 API 会调用函数）。

### RequestOptions

<ApiSignature name="RequestOptions" />

七个扁平字段。每种协议只读取自己理解的字段，忽略其余字段。把 `heartbeat` 传给 HTTP 会被忽略，这不是 `Fault`。`client(options)` 在该次调用中复制 `protocols` 数组，以及 `heartbeat` 和 `reconnect` 的已知字段。缺失的嵌套块保持缺失。`signal`、`beforeConnect` 和回调保持自身身份。SSE 从请求选项中只读取 `signal`。SSE 重连来自 Client 配置（`withSSEReconnect`），所以 `client({ reconnect })` 只影响 WebSocket。没有编译期协议过滤，也没有 `timeout` 或 `abort` 字段。

| 字段                 | 协议                   | 替换方式                                                          |
| -------------------- | ---------------------- | ----------------------------------------------------------------- |
| `signal`             | HTTP、SSE 和 WebSocket | 中止该次调用。对 SSE 和 WebSocket，它覆盖整条连接，包括打开之后。 |
| `onUploadProgress`   | HTTP                   | 其他协议忽略。                                                    |
| `onDownloadProgress` | HTTP                   | 其他协议忽略。                                                    |
| `beforeConnect`      | WebSocket              | 替换该次调用的 client 设置。                                      |
| `protocols`          | WebSocket              | 替换 client 上的列表。                                            |
| `heartbeat`          | WebSocket              | 整体替换。`timeoutMs` 是等待确认的时间，不是请求期限。            |
| `reconnect`          | WebSocket              | 整体替换。                                                        |

[`HttpExecuteOptions`](/zh-Hans/api/core/httpexecuteoptions-type) 是 HTTP 切片（`signal` 加上进度）。[`EventStreamExecuteOptions`](/zh-Hans/api/core/eventstreamexecuteoptions-type) 是 `{ signal? }`。[`WebSocketExecuteOptions`](/zh-Hans/api/core/websocketexecuteoptions-type) 是 WebSocket 切片再加上 `signal`。

### FetchHandle

<ApiSignature name="FetchHandle" />

Defjs 对 Fetch 实现所需的调用签名。它不是 `typeof fetch`，所以 mock 不需要提供 `preconnect` 之类的宿主额外成员。默认 HTTP/SSE 句柄在每次调用时解析 `globalThis.fetch`。HTTP 只有在平台 Fetch 未被替换时才使用 `(url, init)`；被替换的全局实现和自定义句柄收到 `Request`。SSE 始终传入 `Request`。没有 Fetch 也可以导入 Core；如果默认执行时 Fetch 仍然缺失，会报告 `ENV_UNSUPPORTED`，自定义句柄仍可使用。

### ClientSSEOptions

### ClientWebSocketOptions

<ApiSignature name="ClientSSEOptions, ClientWebSocketOptions" />

两种传输的重连都是可选开启：没有 `withSSEReconnect` / `withWebSocketReconnect` 就不会重试。一旦设置了 `reconnect`，以下默认值生效：

| 字段         | SSE             | WebSocket       |
| ------------ | --------------- | --------------- |
| `attempts`   | 每次中断 `3` 次 | 每次中断 `3` 次 |
| `delayMs`    | `1000`          | `1000`          |
| `factor`     | `1`             | `2`             |
| `jitter`     | `0`             | `0`             |
| `maxDelayMs` | 无上限          | `30000`         |

`connectTimeoutMs` 可选，且必须是有限正数，并且不得大于 2147483647（计时器上限）；否则该操作返回 `REQ_OPTIONS_INVALID`。对 SSE，它把从 Fetch 到响应头的时间加上限；对 WebSocket，它把从构造到 `open` 的时间加上限；握手之后会被清掉。到期会向均衡器报告 `NET_UNREACHABLE`，这样重连可以选择下一个端点。重试耗尽后以 `NET_TIMEOUT` 结束。它只存在于重连选项内；只要该对象存在，`attempts` 就默认为 `3`，因此单独设置 `connectTimeoutMs` 也会启用重连。只想限制握手时，请同时设置 `attempts: 0`。

两种传输在成功握手后，都会重置每次连接中断的重试预算、回调中的尝试次数和退避指数。`attempts: 0` 禁用重试；省略 `attempts` 并不表示单次中断期间可以无限重试。`maxDelayMs` 限制抖动和取整后的最终延迟；平台计时器上限 `2_147_483_647` 毫秒也始终生效，包括 SSE 未配置上限时。基础延迟为零时始终为零；有效数字溢出时会饱和到这些上限。

重连选项在传输层运行前校验：`attempts` 必须是非负安全整数；`delayMs` 必须是非负有限数；`maxDelayMs` 必须是非负有限数或正 `Infinity`，后者移除配置上限，但最终等待仍不超过 `2_147_483_647` ms；`factor` 必须是正的有限数；`jitter` 必须是 0–1 范围内的有限数。无效值返回 `REQ_OPTIONS_INVALID`。WebSocket 的 `attempts: 0` 禁用后续重试，但所有显式提供的重连字段仍会在首次连接前校验，与 SSE 一样。抖动会在最终上限应用前，让已经受限的基础延迟向任一方向按比例浮动。

对 SSE，`delayMs` 只是起始基础延迟：服务器的 `retry:` 字段若只含数字，会为之后的尝试替换它，恢复连接后也继续生效。`shouldReconnect` 返回 `false` 会停止重试。SSE 回调还会收到 `lastEventId`、请求的 `method` 和最新的 `open` 信息，并且可以是异步的。没有该回调时，SSE 只重连 `GET`、`HEAD`、`OPTIONS`、`PUT` 和 `DELETE` 请求；提供后，其返回值决定每个方法是否重连。最新事件 ID 会以 UTF-8 字节写入 `Last-Event-ID`；空 ID 会清除它，包含 NUL 的 ID 会被忽略。WebSocket 回调则接收关闭的 `code`、`reason` 和 `wasClean`。

SSE 的 `onInvalidEvent` 处理没有匹配 struct 的事件（包括没有 `default`，即 `missing-struct`），或数据未通过其 struct 校验的事件（`validation-failed`）。事件一律被丢弃；处理函数的返回值被忽略，它抛出的错误也不会关闭流。

对 WebSocket，`beforeConnect`、`heartbeat`、`protocols` 和 `reconnect` 也可以在派生 Client 上传入；每一项都整体替换该次调用的 Client 设置。`heartbeat.message` 构造每次 ping；省略它或它返回 `undefined` 时不发送任何内容。`heartbeat.timeoutMs` 等待确认。它不是请求期限。

### ClientOptions

<ApiSignature name="ClientOptions" />

显示的字段是 `sse` 和 `webSocket`。另外七个——`endpoints`、`headers`、`http`、`interceptors`、`querySerializer`、`xsrf` 和 `withCredentials`——继承自未导出的 HTTP 基础类型。`endpoints` 是 `readonly string[]`。解析后的默认值是 `[]`。空数组是合法值，调用会以 `REQ_BUILD_FAILED` 失败。没有 Client 级 `timeout`。`createClient` 不接收这个对象，它接收选项辅助函数。

### ClientConfig

选项辅助函数修改、操作读取的解析后快照：应用默认值后的 `ClientOptions`，其中 `http.handle`、`interceptors`、`sse`（一个 `ClientSSEConfig`）、`webSocket` 和 `balancer` 始终存在。`http.retry` 可选，默认为 `undefined`（一次尝试，无预算）；`withRetry(options?)` 配置它。`balancer` 默认为该 Client 新建的 `pickFirstBalancer()`。它不是 [`RequestOptions`](/zh-Hans/api/core/requestoptions-type) 字段。

<ApiSignature name="ClientSSEConfig" />

### roundRobinBalancer()

<ApiSignature name="pickFirstBalancer, roundRobinBalancer" />

`pickFirstBalancer` 会在 `NET_UNREACHABLE` 或 `NET_UNAVAILABLE`（HTTP 502、503 或 504）上前进；HTTP 重试从不移动其粘滞端点，顺序遵循 client 的完整端点列表 `members`。可选的有限正数 `failbackMs` 在这段间隔之后，对第一个端点做至多一个同时进行的探测；探测在对端响应开始（`end`）时判定，从未到达 `end` 的探测由 `done` 判定。HTTP 重试是用 `withRetry` 配置的另一份 client 策略。`roundRobinBalancer` 沿列表走。`weights` 可选。见 [多个端点](/zh-Hans/docs/client#multiple-endpoints)。

### p2cBalancer()

<ApiSignature name="p2cBalancer" />

不放回地抽取不同候选（与 Envoy/gRPC A48 不同），选择 tower 的 PeakEwma 或 pending 负载。Linkerd 默认值是 RTT 30 ms、衰减 10 秒。pending 在 `pick` 选中端点时预留，`end` 在响应头或 socket 打开时释放它，并为每种传输记录真实 RTT，包括失败。没有 `end` 的 `done` 只释放 pending，不产生 RTT 样本。p2c 没有失败分类器，也没有惩罚。`choiceCount` 默认为 2，上限为 10。

### outlierDetection()

<ApiSignature name="outlierDetection, OutlierDetectionOptions" />

用 Linkerd 风格的连续失败熔断包装子均衡器。Round robin 和 p2c 默认启用（与 Finagle 相同）；`false` 关闭。Pick-first 传入对象时启用。默认分类器把每个带 code 的结果都计为失败，包括 `NET_TIMEOUT` 和 `NET_BODY_INCOMPLETE`。连续五次失败后，惩罚从 1000 ms 起，探测失败后翻倍，加上不超过基数 0.5 倍的正抖动，上限为 60000 ms。到期后接纳一次探测，在 `end` 时判定；若没有 `end`，则在 `done` 时判定。成功会重置退避；取消只释放名额。没有假定成功的超时、配额、最后一台主机保护、结算网格、百分比判据或慢启动。`isHealthy` 读取应用持有的缓存状态，从不取消惩罚。所有主机都可以熔断；Finagle 式的列表内失败时放行仍会发出请求。与 Envoy/gRPC A50 不同，没有驱逐配额。见 [健康过滤与 p2c](/zh-Hans/docs/client#health-filtering-and-p2c)。

### withRetry()

<ApiSignature name="withRetry, RetryCondition, RetryOptions" />

独立于端点选择，启用同一次调用内的 HTTP 重试。省略 `withRetry` 表示一次尝试且没有预算。`withRetry()` 与 `withRetry({})` 等价，默认值为 `maxAttempts: 2`（含首次）、`on: ["connect-failure"]`，以及安全方法 `GET`、`HEAD`、`OPTIONS`、`TRACE`。方法名不区分大小写；`[]` 关闭重试。`maxAttempts` 是至少为 1 的安全整数，且每个端点最多尝试一次。`"gateway-error"` 包括 `NET_UNAVAILABLE`（HTTP 502/503/504）以及被 `RES_*` 解码拒绝的网关 body；`"attempt-timeout"` 使用 `attemptTimeoutMs`。流式请求 body 从不重试。

退避默认值为 `delayMs: 25`、`factor: 2`、`jitter: 0.2`、`maxDelayMs: 250`，字段语义与 SSE/WebSocket 重连相同。`delayMs: 0` 跳过等待。`attemptTimeoutMs` 必须是有限正数，且不大于 2147483647（计时器上限）；否则操作返回 `REQ_OPTIONS_INVALID`。它为发往所选端点的每次 Fetch 计时，从发起一直到其响应 body 读取完成；发送前后的拦截器工作以及 struct 解码都不计时，也绝不会算到端点头上。调用方 signal 覆盖整次调用，包括退避等待。当某一轮重试无法使用任何端点（均衡器 pick 失败，或下一个端点的 URL 无法解析）时，调用返回上一次尝试的错误，而不是 `REQ_BUILD_FAILED`。

归 Client 所有的 Finagle 预算默认为 20%，外加 10 秒 TTL 内每秒 10 次重试的储备。存入与取出在十个 TTL/10 切片上惰性过期。`budget: false` 移除该限制。共享同一配置的派生 Client 共享其预算；独立 Client 不共享，即使共用一个均衡器。无效选项会在 HTTP 运行时返回 `REQ_OPTIONS_INVALID`，消息为 `Invalid retry options`。该选项在应用时捕获自己拥有的字段、数组和嵌套 budget。`withRetry()` 与 `withRetry(undefined)` 的行为与 `withRetry({})` 相同。后一次 `withRetry` 会替换策略；`withRetry({ maxAttempts: 1 })` 会在启用后关闭重试。均衡器和健康包装器没有重试设置。见 [负载均衡与故障转移](/zh-Hans/docs/load-balancing)。

### Balancer

<ApiSignature name="Balancer, PickOutcome, PickInfo, PickResult, PickFaultCode, DoneInfo, ERR_NO_CANDIDATE, isNoCandidateCause" />

`pick` 返回错误优先元组。可选的 `start` 在所选传输开始前至多同步运行一次；可选的 `end` 在 `start` 之后、对端响应开始（或响应前发生失败）时运行一次；可选的 `done` 在完成时运行一次。Fetch 暴露不了 Linkerd 的首个 body 帧，也暴露不了 Envoy 的流边界。所有 Hook 的抛出和 thenable rejection 都会被接住。选中候选集之外的值会以 `REQ_BUILD_FAILED` 失败，其 `done` 以 `{ attempted: false }` 调用。`ERR_NO_CANDIDATE` 只作为 `REQ_BUILD_FAILED` 的 `cause`。它不是 `FaultCode`。[`isNoCandidateCause`](/zh-Hans/api/core/isnocandidatecause) 能跨 Core 副本识别它。

均衡器只看到中立结果；每种传输把自己的事实转换成 `DoneInfo.code`。默认离群检测（`outlierDetection`）把每个带 code 的结果都计为失败，包括 `NET_TIMEOUT` 和 `NET_BODY_INCOMPLETE`。原始 `DoneInfo.status` 只保留给自定义均衡器，内置策略从不读取。`PickInfo` 包含一次 pick 的候选 `endpoints`、`members`（client 的完整端点列表，每次尝试都相同）和可选的 `operation`，没有传输类型判别字段。

见 [Client 指南](/zh-Hans/docs/client)。
