# Client

建一个 client，options 从左到右叠，然后 `execute` HTTP / SSE / WebSocket command。

## createClient()

```ts
function createClient(...options: ClientOption[]): Client
```

Options 按顺序生效。interceptor 闭包会捕获鉴权或租户时，把 client 建在请求边界里。

- **options** — 像 `withEndpoint` 这种 option helper。
- **返回** 一个 client，`execute` 按传输重载。

## 选项 helpers

每个 helper 都返回 `ClientOption`。对同一项设置，后一次调用会替换前一次，`withInterceptors` 例外，它是追加。

### withEndpoint()

```ts
function withEndpoint(endpoint: string): ClientOption
```

设置拼在相对路径前面的 base URL。

### withInterceptors()

```ts
function withInterceptors(...interceptors: Interceptor[]): ClientOption
```

按注册顺序追加 interceptor。混着的 kind 在 execute 时按传输过滤。

### withQuerySerializer()

```ts
function withQuerySerializer(serializer: QuerySerializer): ClientOption
```

换掉 HTTP、SSE、WebSocket 的 query 编码。`serializer(query)` 收到的是**已经编码的线上对象**（alias 已应用，`Date` 为 ISO，`bigint` 为 string），必须返回 query string，不要带前导 `?`。请求没有 query 时不会调用。builder 返回 `URLSearchParams` 时会跳过它。

### withHeaders()

```ts
function withHeaders(headers: HeadersInit): ClientOption
```

为 HTTP 和 SSE 请求设置静态默认 header，WebSocket 请求不使用它们。init 在 option 生效时被复制，所以之后对该对象的修改不会影响 client。第二次调用 `withHeaders` 会替换第一次，不会合并。

单个请求的优先级：

1. 默认 header 是起始的 header 集合。
2. request builder 返回的 `headers`，当值是标量或 `Headers` 实例时，会替换同名的默认值。数组值（例如 `{ 'x-a': ['one', 'two'] }` 这样的 record 条目，或 tuple 数组形式的 `HeadersInit`）则是追加到默认值上，不替换。
3. interceptor 收到的是合并后的 header，并且可以修改它们。
4. 使用默认 HTTP transport 时，XSRF header 最后才加，且仅在仍然缺失时添加（见 `withXSRF`）。

随请求变化的值（刷新后的 Bearer token，或对序列化 body 计算的 HMAC）请用 interceptor。

### withTimeout()

```ts
function withTimeout(ms: number): ClientOption
```

为**仅 HTTP** 的 `execute` 设置默认超时，单位毫秒。SSE 和 WebSocket 忽略它；它们 execute 的 `timeout` 是另一个按调用计的启动期限。`ms` 必须是不超过 `2_147_483_647` 的正 safe integer，否则调用 `withTimeout` 时会抛出 `RangeError`。第二次调用 `withTimeout` 会替换第一次。

该期限涵盖输入解析、builder、interceptor、transport，以及读取已声明的 body。它会与每次调用的 execute options 组合：

| Execute options             | 效果                                                                             |
| --------------------------- | -------------------------------------------------------------------------------- |
| 无                          | 使用 client 默认值；到期为 `NET_TIMEOUT`。                                       |
| `{ timeout }`               | 本次调用替换 client 默认值。                                                     |
| `{ abort }` 或 `{ signal }` | 与默认值组合：调用方的 signal 触发为 `NET_ABORTED`，计时器触发为 `NET_TIMEOUT`。 |
| `{ abort, timeout }`        | 仍然无效：`REQ_OPTIONS_INVALID`。client 默认值从不算作冲突。                     |

### withCredentials()

```ts
function withCredentials(value: boolean): ClientOption
```

为 `true` 时，HTTP 和 SSE 的 Fetch 用 `credentials: 'include'`。默认关闭。WebSocket 连接不受影响。

### withXSRF()

```ts
function withXSRF(options?: {
  cookieName?: string
  headerName?: string
  tokenProvider?: (context: { request: HttpRequest }) => string | null | undefined
}): ClientOption
```

给 HTTP 请求加上 XSRF token header。默认 cookie `XSRF-TOKEN`，header `X-XSRF-TOKEN`。SSE 和 WebSocket 请求不受影响。

默认 HTTP transport 在以下条件全部满足时添加该 header：方法不是 `GET`、`HEAD`、`OPTIONS` 或 `TRACE`；请求尚未带有该 header；请求同源（在浏览器之外，任何带 `baseEndpoint` 的请求都算同源）；并且找到了非空 token。token 优先取自 `tokenProvider`，否则取自 cookie，而 cookie 只在浏览器中读取。

## 类型

### Client

```ts
type Client = {
  execute(command: EventStreamCommand, options?: EventStreamExecuteOptions): Promise<StreamAwaitResult>
  execute(command: WebSocketCommand, options?: WebSocketExecuteOptions): Promise<SocketAwaitResult>
  execute(command: HttpCommand, options?: HttpExecuteOptions): Promise<HttpAwaitResult>
}
```

这里省略了类型参数；每个重载都会根据 command 推断结果。

### ClientOption

```ts
type ClientOption = (config: ClientConfig) => void
```

修改 `createClient` 构建的 `ClientConfig`。没有合适的 `with*` helper 时，自己写一个。

### QuerySerializer

```ts
type QuerySerializer = (query: { [key: string]: unknown }) => string
```

### FetchHandle

```ts
type FetchHandle = (input: RequestInfo | URL, init?: RequestInit) => Promise<Response>
```

Defjs 对 Fetch 实现所要求的调用签名。它不是 `typeof fetch`，所以 mock 不需要提供 `preconnect` 之类的宿主额外成员。

### ClientSSEOptions

### ClientWebSocketOptions

```ts
interface ClientSSEOptions {
  handle?: FetchHandle
  onInvalidEvent?: (context: {
    reason: 'missing-struct' | 'validation-failed'
    message: { id: string; event: string; data: string }
    cause?: unknown
    signal: AbortSignal
  }) => unknown
  reconnect?: {
    attempts?: number
    delayMs?: number
    factor?: number
    jitter?: number
    maxDelayMs?: number
    shouldReconnect?: (context: {
      attempt: number
      cause?: unknown
      lastEventId: string
      method: string
      open?: { response: { status: number; statusText: string; url: string }; url: string }
    }) => boolean | Promise<boolean>
  }
}

interface ClientWebSocketOptions {
  handle?: WebSocketHandleConstructor
  beforeConnect?: (context: { attempt: number; signal: AbortSignal }) => void | Promise<void>
  heartbeat?: {
    intervalMs: number
    isAck?: (message: unknown) => boolean
    message?: <T = unknown>() => T | unknown
    timeoutMs?: number
  }
  protocols?: readonly string[]
  reconnect?: {
    attempts?: number
    delayMs?: number
    factor?: number
    jitter?: number
    maxDelayMs?: number
    shouldReconnect?: (context: { attempt: number; cause?: unknown; code?: number; reason?: string; wasClean?: boolean }) => boolean
  }
}
```

两种传输的重连都是可选开启：没有 `withSSEReconnect` / `withWebSocketReconnect` 就不会重试。一旦设置了 `reconnect`，以下默认值生效：

| 字段         | SSE    | WebSocket |
| ------------ | ------ | --------- |
| `attempts`   | `3`    | `3`       |
| `delayMs`    | `1000` | `1000`    |
| `factor`     | `1`    | `2`       |
| `jitter`     | `0`    | `0`       |
| `maxDelayMs` | 无上限 | `30000`   |

对 SSE，`delayMs` 只是起始的基础延迟：服务器发来的 `retry:` 字段会在之后的尝试中取代它。`attempts: 0` 禁用重试；省略 `attempts` 不是无限次。`jitter` 必须在 0–1 之间：每次延迟会向任一方向随机浮动，幅度最多为该比例。`shouldReconnect` 返回 `false` 即停止重试。SSE 的回调还会收到 `lastEventId`、请求的 `method` 和最近一次的 `open` 信息，并且可以是异步的。未提供该回调时，SSE 只对 `GET`、`HEAD`、`OPTIONS`、`PUT` 和 `DELETE` 请求进行重连；提供后，所有请求方法是否重连都由回调的返回结果决定。WebSocket 的回调则收到 close 的 `code`、`reason` 和 `wasClean`。

SSE 的 `onInvalidEvent` 处理没有匹配 struct 的事件（包括没有 `default`，即 `missing-struct`），或数据未通过其 struct 校验的事件（`validation-failed`）。该事件一律被丢弃；handler 的返回值会被忽略，它抛出的错误也不会关闭 stream。

对 WebSocket，`beforeConnect`、`heartbeat`、`protocols` 和 `reconnect` 也可以在每次调用 `execute` 时传入；execute 传入的值在本次调用中替换 client 上的值。`heartbeat.message` 负责构造每次 ping；省略它或它返回 `undefined` 时不发送任何内容。

### ClientOptions

```ts
interface ClientOptions extends HttpClientOptions {
  sse?: ClientSSEOptions
  webSocket?: ClientWebSocketOptions
}
```

client 的输入形态描述：`endpoint`、`headers`、`http`、`interceptors`、`querySerializer`、`timeout`、`xsrf`、`withCredentials`、`sse` 和 `webSocket`。`createClient` 不接收它，它接收的是 option helpers。

### ClientConfig

option helpers 修改、`execute` 读取的解析后快照：应用默认值之后的 `ClientOptions`，其中 `http.handle`、`interceptors`、`sse`（一个 `ClientSSEConfig`）和 `webSocket` 始终存在。

### ClientSSEConfig

```ts
interface ClientSSEConfig extends ClientSSEOptions {
  handle: FetchHandle
}
```

`ClientConfig.sse` 上解析好的 SSE config：`handle` 为必填的 `ClientSSEOptions`。

### WebSocketHandle

传输层用到的 WebSocket 实例面：去掉 `binaryType`、ready-state 常量、`dispatchEvent` 和 `on*` handler 属性的 `WebSocket`，再加上只读的 `readyState: number`。

### WebSocketHandleConstructor

```ts
type WebSocketHandleConstructor = { readonly OPEN: number } & (new (...args: never[]) => WebSocketHandle)
```

传给 `withWebSocketHandle` 的构造函数。它必须暴露 `OPEN` ready-state 常量。
