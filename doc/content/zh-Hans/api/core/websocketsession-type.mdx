<ApiReference identity="@defjs/core:WebSocketSession" />

```ts
interface WebSocketSession<TIncoming = unknown, TOutgoing = never> extends AsyncDisposable {
  readonly bufferedAmount: number
  readonly connection: WebSocketConnectionInfo
  readonly closed: Promise<WebSocketCloseInfo>
  readonly receive: AsyncIterable<TIncoming>
  readonly state: WebSocketState
  close(code?: number, reason?: string): void
  [Symbol.asyncDispose](): PromiseLike<void>
  send(message: TOutgoing): void
  onRuntimeError(listener: (error: unknown) => void): () => void
  onStateChange(listener: (state: WebSocketState) => void): () => void
}
```

- `state` 是逻辑上的 [`WebSocketState`](/zh-Hans/api/core/websocketstate-type)；`connection` 是最新的 [`WebSocketConnectionInfo`](/zh-Hans/api/core/websocketconnectioninfo-type)。`bufferedAmount` 是原生尚未发出的字节数；没有物理 socket 时为 `0`。
- `receive` 产出已经按 `incoming` struct 解析好的入站消息。它只能有一个消费者：请求第二个迭代器会抛出 `TypeError`。无法解析的 frame 会报告给 `onRuntimeError` 的监听器并被跳过。
- `send(message)` 用 `outgoing` struct 校验并编码消息，然后发送 JSON 文本。`open` 时立即发送；`reconnecting` 时，若 `maxOutgoingQueueSize` 允许就入队；session 不可写时，抛出名为 `InvalidStateError` 的 `DOMException`。在没有声明 `outgoing` struct、消息未通过 struct 校验，或队列被禁用或已满时同样会抛错。
- `close(code?, reason?)` 请求关闭并停止心跳。`code` 必须是 `1000` 或落在 `3000..4999`，`reason` 最多 123 个 UTF-8 字节；参数无效时，在状态改变之前就会抛错。
- `closed` 以逻辑上的终态 [`WebSocketCloseInfo`](/zh-Hans/api/core/websocketcloseinfo-type) resolve。
- `onStateChange` 和 `onRuntimeError` 返回一个取消订阅函数。

自有作用域优先用 `await using ownedSession = session` 清理。手动 `session.close()` 和 `await session.closed` 仍可使用。

```ts
async function consume(session: WebSocketSession<unknown, never>): Promise<void> {
  await using ownedSession = session
  for await (const message of ownedSession.receive) console.log(message)
}
```

Async disposer 会请求原生 close 并等待 Defjs 自有 teardown，但若一直没有 close event，则以 1 秒为界，并可能用名为 `TimeoutError` 的 `DOMException` reject。它无法证明物理 TCP 连接已经关闭。
