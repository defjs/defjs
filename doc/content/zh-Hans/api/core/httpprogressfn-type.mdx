title: 'HttpProgressFn'
description: '上传和下载进度的回调类型。'
---

<ApiReference identity="@defjs/core:HttpProgressFn" />

```ts
type HttpProgressFn = (event: HttpProgressEvent) => Promise<void> | void
```

作为 `HttpExecuteOptions` 中的 `onDownloadProgress` 或 `onUploadProgress` 传入。回调可以异步执行；处理下一个数据块之前，会等待回调完成。无论上传还是下载，回调抛出异常或返回的 Promise 被拒绝时，调用都会以 `EXT_OBSERVER_FAILED` 失败，抛出的值作为 `cause`。调用方取消和 `timeout` 仍优先处理，分别报告 `NET_ABORTED` 和 `NET_TIMEOUT`。只有支持流式发送请求体的运行时（Bun、Node、Deno）才会报告上传进度。在浏览器中，`Blob` / `File`、`ArrayBuffer` 或 `FormData` 请求体会原样发送，不会调用 `onUploadProgress`；`onDownloadProgress` 不受影响。

见 [`HttpProgressEvent`](/zh-Hans/api/core/httpprogressevent-type)、[HTTP 指南](/zh-Hans/docs/http) 和 [Commands](/zh-Hans/docs/commands)。

在服务端运行时，带 `onUploadProgress` 的 FormData 直接读取序列化后的流，保留其 multipart boundary，并且发送时不带库生成的 `Content-Length`（在 HTTP/1.1 上分块传输），因此进度、超时和中止都能工作，而不必缓冲整个 body。除非显式设置的有效 `Content-Length` 提供了总量，否则总量未知。对于要求 `Content-Length` 的端点（例如某些预签名上传目标），请省略 `onUploadProgress`；此时平台 Fetch 会带上 FormData 的长度发送。使用非 `identity` 编码的下载也会报告 `total: 0` 和 `lengthComputable: false`，因为 `loaded` 统计的是解码后流的字节数。取消会释放包装后的上传流。
