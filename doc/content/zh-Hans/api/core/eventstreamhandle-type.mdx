description: '已打开的 SSE 流：迭代事件、读取 open 元数据，以及提前关闭。'
---

<ApiReference identity="@defjs/core:EventStreamHandle" />

```ts
interface EventStreamHandle<TEvent = EventStreamMessage> extends AsyncIterable<TEvent>, AsyncDisposable {
  readonly open: EventStreamOpenInfo
  readonly closed: Promise<EventStreamCloseInfo>
  close(reason?: unknown): void
  [Symbol.asyncDispose](): PromiseLike<void>
}
```

`EventStreamMessage` 是原始的 `{ id: string; event: string; data: string }` 消息。`client.execute` 返回的 handle 带的是解析后的 [`EventStreamData`](/zh-Hans/api/core/eventstreamdata-type)。

`open` 是启动时的快照（[`EventStreamOpenInfo`](/zh-Hans/api/core/eventstreamopeninfo-type)）；重连之后它可能变化，所以请重新读取 `stream.open`。流结束时，`closed` 会以 [`EventStreamCloseInfo`](/zh-Hans/api/core/eventstreamcloseinfo-type) resolve。

推荐用 `await using stream = handle` 在所属作用域内清理。dispose 会停止 Defjs 的读取与重连工作，并等待它的 reader lock 被释放；但它不保证由运行时提供方控制、卡住的 `ReadableStream.cancel()` promise 一定会完成。仍然可以手动使用 `close()` / `closed`。

```ts
async function consume(handle: EventStreamHandle<unknown>): Promise<void> {
  await using stream = handle
  for await (const event of stream) console.log(event)
}
```

`EventStreamHandle` 的结构化实现必须实现 `[Symbol.asyncDispose]()`，并返回同一条所属清理路径。这是对自定义 handle 的编译期要求；只接收 Defjs 返回的 handle 的代码，没有额外的运行时调用要求。
