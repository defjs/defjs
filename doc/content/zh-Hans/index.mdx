# Defjs

**为更友好的 SDK 设计而生。**

Defjs 帮助团队把 API 做成可复用的 TypeScript SDK。`def` 代表 `define`：描述服务提供的操作，从模块或 npm 包导出它们，再让每个应用配置自己的 client 来调用它们。

## 定义 SDK，配置应用

| SDK 作者                                 | SDK 消费方                               |
| ---------------------------------------- | ---------------------------------------- |
| 定义操作、输入、请求映射、响应和错误     | 选择服务地址、凭证、拦截器和传输         |
| 导出带类型的 HTTP、SSE 和 WebSocket 端点 | 导入这些端点，并用 Defjs client 调用它们 |
| 维护并发布 API 契约                      | 处理结果，并拥有取消、流和会话           |

SDK 定义不会捕获应用的 client。同一个导出的端点可以用不同的 client 配置服务浏览器应用、服务端或本地测试。两边仍使用 Defjs 的执行契约和兼容的 Core 版本。

SDK 导出一个操作：

<include cwd meta="get-health.ts">
  examples/home/get-health.ts#example
</include>

应用导入它，并拥有执行：

<include cwd meta="app.ts">
  examples/home/app.ts#example
</include>

调用 `getHealth(client)` 即开始请求。发布定义之后，消费方从你的 SDK 包导入它，而不是从本地文件导入。

## 最佳实践

定义与 client 彼此独立。把应用的 client 作为第一个参数传入，例如 `getHealth(client)`。服务地址和凭证也归应用所有。先检查 error-first tuple。`error` 有值时，报告 `error.code`，从函数返回，然后再读取成功值。

## 构建你的 SDK

1. 在分开的 SDK 文件和应用文件里[定义并运行你的第一个操作](/zh-Hans/docs/start)。
2. 描述 SDK 导出的[数据契约](/zh-Hans/docs/struct)和 [HTTP 操作](/zh-Hans/docs/http)。
3. 用 JavaScript、声明文件和兼容的 Core 依赖[测试并发布一个 SDK 包](/zh-Hans/recipes/publish-http-sdk)。
4. 配置消费方应用的 [Client](/zh-Hans/docs/client)，再按需要加上框架或可观测性集成。

[设计决策](/zh-Hans/docs/design-decisions)解释为什么 API 定义和执行有各自的所有者。发布成包之前，也可以在同一个应用里使用这套结构。

## 选传输

| 你要做的事              | 从这里看                              | 成功时拿到什么                                                      |
| ----------------------- | ------------------------------------- | ------------------------------------------------------------------- |
| 请求 + 按状态区分的响应 | [HTTP](/zh-Hans/docs/http)            | 解码后的数据 + `DecodedResponse`（没有声明 output 时是 `HttpMeta`） |
| 长连接的服务端事件流    | [SSE](/zh-Hans/docs/sse)              | 一条 stream + 启动时的 `open` 快照                                  |
| 双向会话                | [WebSocket](/zh-Hans/docs/web-socket) | 一个 session + 启动时的 `connection` 快照                           |

三种传输走同一条顺序：定义一个操作，再带着应用的 client 和调用方的 input 调用它。

## 选包

| 包                            | 什么时候用                                                                                              |
| ----------------------------- | ------------------------------------------------------------------------------------------------------- |
| `@defjs/core`                 | 定义 SDK 操作和契约；创建 client，并调用 HTTP、SSE 和 WebSocket 操作                                    |
| `@defjs/react`                | `ClientProvider` / `useClient` — 见 [React](/zh-Hans/docs/integrations/react)                           |
| `@defjs/vue`                  | Plugin + `injectClient` — 见 [Vue](/zh-Hans/docs/integrations/vue)                                      |
| `@defjs/opentelemetry-server` | 出站 span、metrics 和 logs — 见 [OpenTelemetry Server](/zh-Hans/docs/integrations/opentelemetry-server) |

## 结果长什么样

三种传输都返回错误优先的三项 tuple。位置对齐，含义不一样：

- HTTP → `[error, data, response]`
- SSE → `[error, stream, open]`
- WebSocket → `[error, session, connection]`

失败时第二项是 `undefined`。HTTP 的第三项同样是 `undefined`，因为 fault 已经带着响应元数据。SSE 和 WebSocket 的第三项，是失败前已捕获到的启动快照（如果有）。细节见[错误](/zh-Hans/docs/errors)。

## 所有权一句话

HTTP 过期了就 abort。SSE 要 `close` 再 `await stream.closed`。WebSocket 要 `close` 再 `await session.closed`。服务端如果 options 会捕获 cookie、鉴权或租户，把 Client 建在请求边界里。打日志前先把 URL、headers、body 脱敏。

Defjs 提供定义、校验和执行。应用选择缓存和重试策略；流的重连需要显式启用。今天支持手写的 SDK 包。CLI 工具和 OpenAPI/SDK 生成仍在计划中。
