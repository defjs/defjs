# Defjs

先定义端点，再构建一个不透明命令，最后执行它。HTTP、SSE、WebSocket 都是同一套路。

<include cwd meta="get-health.ts">

Defjs 不会帮你缓存结果、自动重试，也不会在你忘了关流时替你收尾。取消和清理都归你管。

## 选传输

| 你要做的事              | 从这里看                              | 成功时拿到什么                            |
| ----------------------- | ------------------------------------- | ----------------------------------------- |
| 请求 + 按状态区分的响应 | [HTTP](/zh-Hans/docs/http)            | 解码后的数据 + `HttpResponse`             |
| 长连接的服务端事件流    | [SSE](/zh-Hans/docs/sse)              | 一条 stream + 启动时的 `open` 快照        |
| 双向会话                | [WebSocket](/zh-Hans/docs/web-socket) | 一个 session + 启动时的 `connection` 快照 |

## 结果长什么样

三种传输都返回错误优先的三项 tuple。位置对齐，含义不一样：

- HTTP → `[error, data, response]`
- SSE → `[error, stream, open]`
- WebSocket → `[error, session, connection]`

失败时第二项是 `undefined`。HTTP 的第三项同样是 `undefined`，因为 fault 已经带着响应元数据。SSE 和 WebSocket 的第三项，是失败前已捕获到的启动快照（如果有）。细节见[错误](/zh-Hans/docs/errors)。

## 所有权一句话

HTTP 过期了就 abort。SSE 要 `close` 再 `await stream.closed`。WebSocket 要 `close` 再 `await session.closed`。服务端如果 options 会捕获 cookie、鉴权或租户，把 Client 建在请求边界里。打日志前先把 URL、headers、body 脱敏。
