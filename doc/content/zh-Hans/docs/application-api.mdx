# 应用接口层 [#application-api-layer]

大多数前端和全栈项目并不是要发一个对外公开的 npm 包，而是在自己的业务仓库（`src/api/`）里管理 HTTP 请求，用来替代散落各处的 `fetch` 或 `axios` 二次封装。就算不发布独立包，只要在项目里把 `src/api/schema/`、`src/api/request/` 和 `src/api/client.ts` 拆清楚，一样能拿到完整的运行时结构校验、零 Mock 内存单测体验，以及浏览器和 SSR 双端复用能力。

---

## 1. 推荐的 `src/api/` 目录结构

在业务仓库的 `src/api/` 下分成三个职责清晰的模块层：

```text
src/
├── api/
│   ├── schema/           # 1. 共享 schema 与通用错误结构（struct + Infer 同名导出）
│   │   └── order.ts      #    ApiError, OrderStatus, Order, OrderPage
│   ├── request/          # 2. 按业务域划分的纯函数接口定义
│   │   └── orders.ts     #    getOrder, listOrders, createOrder
│   └── client.ts         # 3. Client 实例配置（基地址、鉴权/XSRF 拦截器、重试策略）
└── checkout.ts           # 4. 页面、组件或业务函数里调用这些接口
```

`src/checkout.ts` 属于业务编排函数，不是程序最顶层，所以 `placeAndLoadOrder` 里不记日志，而是继续向上返回错误优先元组 `Promise<[Error, undefined] | [null, Checkout]>`，并用 `new Error("create order", { cause: createErr })` 给每一步补上失败上下文（类似 Go 里的 `fmt.Errorf("create order: %w", err)`）。到了最外层调用方（比如 UI 事件处理器）检查 `if (err)`，再决定怎么报错或提示用户。

## 3. 业务项目中的几个关键做法

### 浏览器模块单例 vs. SSR 每次请求独立建 Client

- **浏览器 / SPA 单页应用（`apiClient`）**：每个后端域名建一个模块级 `createClient(...)` 实例全局复用，这样页面切换时能保留负载均衡的健康状态和客户端重试预算。在 React 或 Vue 项目里，可以通过 [`@defjs/react`](/zh-Hans/docs/integrations/react)（`ClientProvider` / `useClient`）或 [`@defjs/vue`](/zh-Hans/docs/integrations/vue)（`createClientPlugin` / `injectClient`）往下注给组件树。
- **服务端渲染（SSR）与多租户服务（`createServerApiClient(accessToken)`）**：只要 Token、Cookie 或租户信息会随每个入站请求变化，就在服务端处理函数里调工厂函数为当次请求新建一个隔离 `Client`。因为 `getOrder`、`listOrders`、`createOrder` 全是纯函数，同一套 `request/orders.ts` 可以同时服务于浏览器单例 `apiClient` 和 SSR 请求级 `Client`。

### 单次调用的超时和取消直接派生

只给某一次请求加超时或 `AbortSignal` 时，不需要新建 `createClient(...)`，对共享 `apiClient` 做一次内联派生就行：

```ts
const [err, created] = await createOrder(
  apiClient({ signal: AbortSignal.timeout(5_000) }),
  {
    customerName: "Ada Lovelace",
    totalCents: 4200,
    idempotencyKey: "idem-2026-101",
  },
);
```

### 复用统一的业务错误结构（`ApiError`）

在 `src/api/schema/` 里统一声明后端的错误响应结构（`export const ApiError = struct.object(...)`），并在业务接口的 `defineRequest` 上配置 `error: ApiError`。接口返回非 `2xx` 状态码时，只要在 `if (err)` 里判断 `if (err.code === "HTTP_STATUS")`，就能直接拿到带完整类型推导的 `err.data.code`、`err.data.message` 和 `err.data.requestId`。
