# WebSocket 会话

在 SDK 中，`defineWebSocket` 声明双向 WebSocket 契约：路径模板、可选的 `input` 与 `builder`（仅限 `path` 和 `query`）、`incoming` 与 `outgoing` 消息 struct、队列上限，以及静态子协议。消费方应用在自己的 Client 上配置心跳、重连和生命周期清理。

## 2. 消息校验与双向通信规则

- **入站帧（`session.receive`）**：文本、`ArrayBuffer`、类型化数组和 `Blob` 帧都按 UTF-8 解码，解析为 JSON，再用 `incoming` 校验。畸形 JSON 或 schema 不匹配会上报给 `session.onRuntimeError` 并被丢弃，不会关闭会话。`session.receive` 是单消费者；请求第二个迭代器会抛出 `TypeError`。
- **出站帧（`session.send(payload)`）**：同步用 `outgoing` 校验，应用 `.alias()` 和编解码器，再用 `JSON.stringify` 序列化。`open` 状态下立即发送；`reconnecting` 期间若队列可用（`maxOutgoingQueueSize > 0`）则排队；载荷无效、队列已满/被禁用或会话已关闭时同步抛出异常。

## 3. 会话状态与观察者机制

| 成员                 | 说明                                                                                                                |
| -------------------- | ------------------------------------------------------------------------------------------------------------------- |
| `state`              | 当前连接状态：`'idle' \| 'connecting' \| 'open' \| 'reconnecting' \| 'closing' \| 'closed' \| 'aborted' \| 'error'` |
| `connection`         | 底层最新物理 Socket 的实时快照（包含 `generation`、`url`、协商的 `protocol` 以及 `extensions`）                     |
| `bufferedAmount`     | 当前活跃物理 Socket 上未发送完成的缓冲字节数（未连接时为 `0`）                                                      |
| `receive`            | 单消费者的异步可迭代对象，提供经过强类型校验的 `incoming` 入站消息流                                                |
| `onStateChange(fn)`  | 订阅连接状态流转事件；返回一个用于取消订阅的 `unsubscribe` 函数                                                     |
| `onRuntimeError(fn)` | 订阅连接建立后的非启动期数据帧/解析异常；返回一个 `unsubscribe` 函数                                                |
| `closed`             | 一个返回最终终态结果（`kind: 'closed' \| 'aborted' \| 'error'`）的 Promise                                          |

## 4. 重连策略、心跳保活与队列管理

重连与心跳都需显式开启（opt-in），可通过 Client 选项（`withWebSocketReconnect`、`withWebSocketHeartbeat`）或单次调用的派生 Client 选项（`client({ reconnect, heartbeat })`）配置：

- **重连**：启用时的默认值为 `attempts: 3`、`delayMs: 1000`、`factor: 2`、`maxDelayMs: 30000`、`jitter: 0`。每次物理连接 `open` 都会重置中断预算。`beforeConnect({ attempt, signal })` 在首次连接和每次重连尝试之前运行。
- **握手超时（`connectTimeoutMs`）**：提供时必须是有限正数，且不大于 2147483647（计时器上限）；否则操作返回 `REQ_OPTIONS_INVALID`。它限制从构造到 `open` 的时间，握手后清除。
- **心跳**：定期通过 `outgoing` struct 发送 `message()`，并在至多 `timeoutMs` 内等待匹配 `isAck(msg)` 的帧。匹配的 ack 帧由心跳监视器消费，不转发给 `session.receive`。漏掉 ack 对逻辑会话是致命的：`closed.kind` 为 `"error"`，`closed.cause` 是普通 `Error("WebSocket heartbeat timeout")`；这不会启动重连。心跳序列化失败也沿同一致命路径结束，并保留原始 cause。
- **队列上限**：
  - `maxIncomingQueueSize`（必填正的安全整数）：同时限制等待解码的原始帧和等待消费者的解码后消息。溢出会以 `CAP_QUEUE_OVERFLOW` Fault 作为 `closed.cause` 终止会话；同一个 cause 会传给 `onRuntimeError` 并使 `session.receive` reject。会话打开期间请持续消费 `session.receive`。
  - `maxOutgoingQueueSize`（可选非负安全整数，默认 `0`）：仅在 `state === 'reconnecting'` 时缓冲 `session.send()` 调用，并在下一次 `open` 发布前全部刷出。

`shouldReconnect` 接收原生关闭码和 `wasClean`。服务端可能以应用错误码 `1011` 完成正常的关闭握手，因此 `wasClean === true` 不代表应用处理成功。示例显式允许 `1011`；请根据自己的协议选择应用关闭码，而不要只依赖 `!wasClean`。

## 5. 子协议与身份认证 [#protocols-and-authentication]

浏览器 WebSocket 不支持任意握手请求头，因此 WebSocket 的 `builder` 只返回 `{ path?, query? }`。

- **子协议优先级**：`client({ protocols })` 覆盖 `withWebSocketProtocols(...)`，后者覆盖 `defineWebSocket({ protocols })`。
- **URL 转换**：Defjs 会在解析出的端点上自动把 `http:` 转为 `ws:`，把 `https:` 转为 `wss:`。
- **凭据**：`withCredentials(true)` 只适用于 Fetch（HTTP/SSE）。WebSocket 请通过 cookie/会话策略、子协议或短期连接 ticket 认证——避免在 query 字符串中放长期密钥。
- **`beforeConnect` 不是请求修改器**：输入解析、同步纯 `builder` 和拦截器链每次操作只运行一次。如果请求的基础端点未被拦截器替换，每次重连都会重新选择端点并用它重建 URL，但会复用已构建的 path/query 和捕获的协议列表。不论仍使用原端点还是发生故障转移，URL 都会在该次尝试的 `beforeConnect` 运行之前确定。在 hook 中修改闭包变量、input 或协议数组，不能为当前握手提供新的 ticket。同一个会话内不支持轮换 URL/子协议凭据；请先获取新凭据，再通过 input 或 client 配置发起新操作，并负责替代会话的清理。

## 6. 连接关闭与资源回收

调用 `session.close(code?, reason?)`（其中 `code` 必须为 `1000` 或 `3000..4999`，`reason` 长度不超过 123 个 UTF-8 字节）并等待 `await session.closed`，或者直接使用 `await using`：

重连中断耗尽尝试后，会话以 `closed.kind: "error"` 结束，`closed.cause` 是普通传输错误，并带有原生关闭快照（升级失败时通常为代码 `1006`）；没有单独的稳定耗尽代码。组件或 worker 结束工作时，始终注销 `onStateChange` 和 `onRuntimeError` 监听器。
