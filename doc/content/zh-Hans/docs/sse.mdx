# SSE 事件流

在 SDK 中，用 `defineEventStream` 声明 Server-Sent Events（SSE）操作，指定路径、可选的 `input` 与 `builder`、由 struct 组成的 `events` 字典，以及缓冲区与队列上限。消费方应用在自己的 Client 上配置认证与可选的重连策略，打开流，迭代带类型的事件，并负责关闭流。

- **非 `2xx` 握手**：返回 `HTTP_STATUS`（定义声明了 `error` struct 时，`error.data` 是解码后的错误体）。这对当前操作是致命的；不会调用 `shouldReconnect`。下一次操作会重新选择端点，因此均衡器可能选中另一个端点。
- **媒体类型错误或 body 不可读**：返回 `RES_MEDIA_TYPE_INVALID` 或 `RES_DECODE_FAILED`。
- **`startupOpen` 与 `stream.open`**：元组第三项（`startupOpen`）是首次握手响应的快照；`stream.open` 会在之后重连时实时更新。如果重连握手返回 `503`，迭代器会 reject，`stream.closed` 报告 `RES_DECODE_FAILED`，而 `stream.open.response.status` 仍为 `503`；请检查 `stream.open` 获取这个实时状态。

## 3. 事件分发与解码

收到 SSE 帧时（按 WHATWG 规则以空行结束）：

1. **事件路由**：网络上的 `event:` 字段选择 `events[eventName]`；没有该字段时默认为 `"message"`。没有匹配项时，若声明了 `events.default` 就用它；未声明且无 `events.default` 的事件会被丢弃。
2. **载荷解码**：`struct.string()` schema 接收原始文本 `data:`。其他 struct 类型会先把 `data:` 解析为 JSON，再用 struct 校验。
3. **观察无效事件**：无效或未声明的事件会被丢弃，不会终止流。需要在 Client 上配置 `withSSEOnInvalidEvent(...)` 进行有界诊断：

## 4. 自动重连与 `Last-Event-ID` [#reconnect]

SSE 重连是**显式开启（opt-in）**的。没有 `withSSEReconnect(...)` 时，任何网络中断或流读取错误都会终止流。

<include cwd>examples/sse/reconnect.ts#example</include>

- **中断预算（`attempts`）**：向 `withSSEReconnect` 传入选项对象时默认为 `3`。每次成功握手都会重置尝试计数器和退避指数，因此只要每次都能成功打开，`attempts: 1` 也能在长会话中建立许多物理连接。服务器的正常 EOF **不是**失败，不会触发重连。
- **游标追踪（`Last-Event-ID`）**：解析到事件末尾的空行时才提交游标，并在重连时自动作为 `Last-Event-ID` 发送。无论连接正常结束还是失败，不完整帧都不会提交其 `id`。重连后从最后一个已提交的 id 恢复；服务器必须实现从该游标重放。
- **幂等性安全**：默认只有幂等方法（`GET`、`HEAD`、`OPTIONS`、`PUT`、`DELETE`）会自动重连。非幂等方法（`POST`、`PATCH`，例如 LLM 流式请求）只有在自定义 `shouldReconnect` 回调显式返回 `true` 时才重连。`ReadableStream` 请求体在首次尝试时被消耗，永远不会重连。
- **握手超时（`connectTimeoutMs`）**：提供时必须是有限正数，且不大于 2147483647（计时器上限）；否则操作返回 `REQ_OPTIONS_INVALID`。它限制每次握手从 Fetch 调用到响应头的时间，不限制已打开的流存活多久。

## 5. 缓冲区与队列上限

默认值是 `maxBufferSize: 64 * 1024` 字节和 `maxQueueSize: 1024` 个事件。两个上限都必须是正的安全整数。没有默认握手期限：挂起的 Fetch 会等待平台、调用方取消或显式配置的 `connectTimeoutMs`。超出任一容量上限都是致命的（`stream.closed` 以 `kind: "error"` 解析，迭代器 reject——事件绝不会被静默丢弃）：

| 定义选项        | 约束内容                                                        | 终态 Fault 代码       |
| --------------- | --------------------------------------------------------------- | --------------------- |
| `maxBufferSize` | 单个 SSE 帧在遇到空行之前所允许的最大不完整或过长字节数         | `CAP_BUFFER_EXCEEDED` |
| `maxQueueSize`  | 已解码但尚未被 `for await` 消费的事件在内存队列中的最大积压数量 | `CAP_QUEUE_OVERFLOW`  |
