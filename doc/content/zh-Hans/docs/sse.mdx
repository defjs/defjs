# Server-Sent Events

打开流、迭代它，再用 `await using` 释放自有 handle。手动 `close()` 和 `closed` 仍可使用；Client 和插件不会替你释放返回的流。

## 定义流

`defineEventStream(...)` 要 `events`、正 safe integer 的 `maxBufferSize`、正 safe integer 的 `maxQueueSize`，以及相对 `path`。Method 默认 `GET`。

请求形状和 HTTP 一样：`builder`，返回 `path`、`query`、`headers`、`body`。`GET` / `HEAD` 不能返回 body。声明了 `error` struct 时，启动 fault 带类型，非 2xx 握手 body 按 struct kind 解码（`string` 是文本，`blob` / `file` 是 blob，`arrayBuffer` 是字节，其余是 JSON）。你没设 `Accept` 时，Defjs 会发 `Accept: text/event-stream`。只要声明了 `input`，就必须显式提供 `builder`，即使输入已经是请求形状也一样。只有没有 `input` 的定义可以省略 `builder`。`ReadableStream` 请求体遵循 HTTP 的规则：在不支持流式发送请求体的运行时（例如 Firefox）中，启动会在发送任何内容之前以 `ENV_UNSUPPORTED` 失败。在 Chromium 中，发送这种请求体需要 HTTP/2 或更高版本；使用 HTTP/1.1 时，启动会以 `NET_UNREACHABLE` 失败。流式请求体只发送一次，使用这种请求体的请求不会重连（见「重连」）。

**当你**选择重连时，一条逻辑流可以跨多次物理 Fetch。没有 `withSSEReconnect`，瞬时网络和流读取失败会结束逻辑流。打开成功时你仍拿到一个 handle、一个 async iterator。

## 解码事件

线上事件名 → `events[eventName]`；否则 `events.default`。没有匹配 Struct → 事件不投递。缺 SSE `event` 字段 → 逻辑名是 `message`。

SSE `data` 一开始是文本。`string` struct 保留这段文本。其余 kind 都是 JSON：先 parse 文本，再用 struct 解码。`struct.object`、`struct.number`、`struct.boolean`、`struct.any`、`struct.unknown` 都是 JSON，不是 trim 过的文本。`ping` 这种裸 token 满足不了 `struct.literal('ping')`；data 必须是 JSON。服务端发 JSON 字符串 `"abc"` 时仍然满足 `struct.string()`：交付的值就是这段原始文本，引号也在，不会 JSON 解码成 `abc`。

发出的值：`event`、解码后的 `data`、可选非空 `id`。有 `default` 时，未知事件名在推断 union 里是 `string`。

## 观察无效事件

无效/未声明事件会被丢掉，不进队列。`withSSEOnInvalidEvent(...)` 可以观察原始 ID、名字、文本 data，以及 `missing-struct` 或 `validation-failed` 和可选 cause。

## 重连

**行为变化：** SSE 重连是 opt-in。没有 `withSSEReconnect(...)` 时，网络和流读取失败**不会**重试（等同 `attempts: 0`）。传 `withSSEReconnect({ attempts: 3 })`（或另一份审过的预算）才会重试这些失败。正常 EOF 不重试。状态/content-type 校验、parser 上限、消息 transform 失败、队列溢出、正常 EOF 对逻辑流仍是终止性的。

<include cwd>examples/sse/reconnect.ts#example</include>

`attempts` 计的是初次尝试之后的重试次数；设了 reconnect 对象时默认 `3`。`attempts: 0` 禁用重试。不写 `withSSEReconnect` 同样禁用重试。`delayMs` 是初始间隔（默认 `1000`）；`factor` 放大（默认 `1`，即恒定间隔）；`maxDelayMs` 封顶基数（默认不封顶）。SSE 的 `jitter` 是与 WebSocket 相同的 **0–1 乘性因子**。流上的 `retry:` 字段会更新当前间隔。策略回调返回 false / 抛错 / reject 会结束逻辑流。

最近解析到的事件 ID 会通过后续尝试的 `Last-Event-ID` 请求头发送。除了这个请求头，后续尝试会重发首次尝试时构建的请求：`builder` 和拦截器在每次 `execute` 中只运行一次，因此请求方法、URL、请求头和请求体都保持不变。如果某个请求头需要在每次尝试时更新，例如有效期较短的令牌，就应在传给 `withSSEHandle` 的 Fetch 实现中设置；该实现会在每次尝试时运行一次。如果凭证仍然过期，下一次握手会收到非 2xx 响应，并以 `HTTP_STATUS` 结束这条流。

重连只在安全时重发请求：

- `GET`、`HEAD`、`OPTIONS`、`PUT` 和 `DELETE` 是幂等的（RFC 9110 §9.2.2），会在预算内重连。
- 其他请求方法（例如 `POST` 或 `PATCH`）只有在 `shouldReconnect` 返回 `true` 时才会重连。连接失败并不能说明服务端是否已经执行了请求：重发用于启动大语言模型生成的 `POST` 请求，会再次执行生成并再次计费，新事件也会在同一条流中接在旧事件后面。传入 `shouldReconnect` 会替换所有请求方法的默认重连策略，因此，当同一个客户端同时用于这两类端点时，应检查回调上下文中的 `method`。
- `ReadableStream` 请求体会在首次尝试时被消耗。无论失败发生在流打开之前还是之后，都会以原始错误结束这条流；不会调用 `shouldReconnect`，也不会等待重连延迟。请求需要重连时，请使用字符串、字节、`Blob`、表单或 JSON 请求体。

## 缓冲区与队列上限

两者都必须是正 safe integer。溢出是致命的——不会悄悄丢掉旧事件。

| 上限            | 保护什么                        | 终止 code             |
| --------------- | ------------------------------- | --------------------- |
| `maxBufferSize` | 解析时不完整/过大的 SSE 行/事件 | `CAP_BUFFER_EXCEEDED` |
| `maxQueueSize`  | 生产快于唯一消费者读取的事件    | `CAP_QUEUE_OVERFLOW`  |

致命流还会清空缓冲事件、取消活动 body、reject iterator，并以 `kind: 'error'` resolve `stream.closed`。

## 关闭与释放

`EventStreamHandle`：一个实时的打开快照、一个终止 promise、一个 `close`、一个 async iterator 和一个标准 async disposer。

<include cwd lang="typescript">
  examples/sse/close-and-dispose.ts#example
</include>

终止 kind（`closed.kind`）：`eof`、`aborted` 或 `error`。`error` 结果还会带 `closed.code`，即一个 `EventStreamFaultCode`：`CAP_BUFFER_EXCEEDED`、`CAP_QUEUE_OVERFLOW`、`EXT_HOOK_FAILED`、`EXT_OBSERVER_FAILED`、`NET_TIMEOUT`、`NET_UNREACHABLE`、`RES_DECODE_FAILED` 或 `RES_MEDIA_TYPE_INVALID`。

`close(reason)` 中止当前尝试、关闭队列，以 `aborted` settle。stream 打开之后中止传给 `execute` 的 `signal` 或 `abort` 也一样：iterator 正常结束，`closed` 报告 `aborted`。`timeout` 只是启动期限，绝不会结束一条已打开的 stream。循环 `break` / `return` / throw 会触发 iterator return，并以 `iterator-return` 关闭。执行 command 的代码拥有关闭权。

`await using` 调用同一条自有 close 路径，并等待 Defjs 读取/重连任务停止及当前 reader lock 释放。若 provider 控制的 `ReadableStream.cancel()` promise 永久卡住，它并不保证该 promise 完成。需要 reason 或终止结果时，仍可显式调用 `stream.close(reason)`，再 `await stream.closed`。

结构化实现 `EventStreamHandle` 的代码现在必须提供 `[Symbol.asyncDispose](): PromiseLike<void>`，并把它连到同一 lifecycle。对实现者而言，这是编译期 breaking change；只接收 Defjs handle 的消费者无需新增运行时调用。

仓库验证并支持的最低 lib 契约是固定 TypeScript 7 加 `ES2022`、`ESNext.Disposable`、`DOM`、`DOM.Iterable`。这四项组合是一个 baseline；不表示每份 declaration 都分别强制全部四项，也不承诺未经测试的旧 compiler。普通 HTTP Client 不是 `AsyncDisposable`，其请求应使用 timeout 或 `AbortSignal` 管理。

日常日志别带 credentials、事件 data、事件 ID、cause、流 URL。`withCredentials(true)` 影响 SSE 的 Fetch cookie；不配置 WebSocket 鉴权。
