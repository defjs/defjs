# React

`@defjs/react` 通过 React Context 和 `useClient()`，把应用自己的 `@defjs/core` Client 传进 React 18+ 组件树。SDK 本身仍然是纯 `@defjs/core` 模块，不依赖 React。

```sh
bun add @defjs/core @defjs/react react
```

## `@defjs/react` 管什么，应用管什么

- **`@defjs/react` 提供**：`ClientProvider` 和 `useClient(overrideClient?)`。
- **应用自己负责**：创建 [`DerivableClient`](/zh-Hans/api/core/derivableclient-type)、在组件卸载或依赖变化时用 `AbortController` 取消还没结束的请求、关闭 SSE / WebSocket 句柄，以及对接 TanStack Query 这类查询缓存。
- **注意避坑**：`useClient()` 返回的 `DerivableClient` 本身是个可调用对象（带函数签名），发请求时调用 `client({ signal })` 就好（比如 `getOrder(client({ signal }), input)`）。**千万别**把 `client` 直接传给 `setState(client)`，因为 React 会把函数当成状态更新回调直接执行。

- `ClientProvider` 只是个很薄的 React Context Provider。换一个 `client` prop 只会让下层拿到的值变掉，不会自动克隆或销毁上一个 Client。
- 开发模式（`StrictMode`）下，React 会反复挂载和清理 Effect。写之前记得检查 `controller.signal.aborted`，防止过期请求回来把新状态覆盖掉。

## 2. 使用 `useClient` 读取与覆盖 Client

`useClient(overrideClient)` 会优先返回 `overrideClient`；没传或传 `undefined` 时，就读取最近一层 `ClientProvider` 给的值。两边都没提供 Client 时才会抛出 `Error`。

<include cwd>examples/react/read-with-use-client.tsx#example</include>

- 在组件或自定义 Hook 顶层无条件调用 `useClient(explicitClient)` 就好。千万别写 `explicitClient ?? useClient()`，这会违反 React 的 Hook 规则（Rules of Hooks）。

## 4. 在 Effect 中管理 SSE 与 WebSocket 生命周期

SSE 和 WebSocket 句柄在 `openStream(...)` 或 `connectChat(...)` 返回之后还会长期保持连接。把 `AbortController` 的 `signal` 传进去并在清理函数里 `abort()`，就能同时覆盖建连阶段和已打开的会话。用 `await using` 拿住会话对象，消费它唯一的异步迭代器即可：

<include cwd>examples/react/own-realtime-work.tsx#example</include>

- 取消传给 WebSocket 的 `signal` 会让会话按 `aborted` 结束，并使 `session.receive` 抛出 `AbortError`。记得在 `catch` 里用 `controller.signal.aborted` 过滤掉主动取消，只让真正的运行时错误（比如心跳超时）浮出来。
- 取消 SSE 流会让 `for await (const msg of stream)` 直接正常退出循环，不会抛出异常。

---

## 5. SSR 与 Provider 作用域

- **浏览器**：如果域名和拦截器不随单个请求变化，共享一个模块级 Client 就够了。
- **SSR**：只要请求头、Cookie、租户或凭据会随每个服务端请求变化，就在每个入站请求边界内新建一个 Client。
- 卸载 `<ClientProvider>` **不会**自动中止没跑完的 HTTP 调用、关掉 SSE/WebSocket 连接，也不会销毁 Client。
