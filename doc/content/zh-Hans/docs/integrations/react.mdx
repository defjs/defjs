# React

从 SDK 或共享定义模块导入操作。React 应用拥有 client，并通过这个框架插件提供它；SDK 包可以不依赖 React，并被其他应用复用。

这些插件只是设置和获取已有 `Client` 的可选便利。可以直接导入应用固定的 Client、给可复用逻辑传入显式 Client、用框架注入提供组件树默认值与子树覆盖，或采用应用自己的组织方式；SDK 定义不要求通过插件执行。

这个包**不会**创建 Client、加缓存、重试操作或释放传输资源。启动工作的组件、effect 或数据请求库负责取消、关闭及其他生命周期处理。`useClient()` 拿到的 client 要传进操作。该 Hook 返回传入的那个 [`DerivableClient`](/zh-Hans/api/core/derivableclient-type)。需要 `abort` 等按次选项时，在操作运行的地方调用它：`getUser(client({ abort }), input)`。不要把它传给 state setter，因为 `setState(client)` 会把它当成 updater 来调用。派生出的 `Client` 值不被 `ClientProvider` 或 `useClient` 接受。

## 用 `useClient` 读

`useClient(overrideClient)` 优先返回显式 Client；省略参数或传入 `undefined` 时读取最近的 `ClientProvider`。两种来源都没有 Client 时才抛出 `Error`，原来的 `useClient()` 调用仍然有效。

始终在组件或自定义 Hook 顶层调用 `useClient(explicitClient)`，即使传了显式 Client，也不能在普通函数或事件回调里调用。不要写 `explicitClient ?? useClient()`，它会条件调用 Hook。显式值不写入 Context，也不建立 Provider；Hook 仍然订阅 Context。

Hook 只提供 Client。它不启动工作、不订阅传输，也不把错误优先 tuple 变成异常。

传给操作的 `abort` signal 会一直管着已打开的 session。在清理函数里 abort 它，session 会以 `aborted` 结束，`receive` 以 `AbortError` reject，所以上面的 `catch` 在 effect 被释放之后忽略错误，只报告真正的失败（队列溢出、心跳确认超时）。被 abort 的 SSE stream 则是 iterator 正常结束。没有这个 `catch`，循环的 reject 就是未处理的 promise rejection。

`EventStreamHandle` 同理：在 `finally` 里 close，await `stream.closed`。WebSocket 消费者还要退订状态/运行时错误监听，并持续读 `session.receive`——有界队列不读会溢出。

## SSR 与 Client 作用域

包入口是 Client Component 边界。浏览器应用在 endpoint、interceptor、捕获的状态对浏览器安全且请求无关时，可以共享模块作用域 Client。SSR 时若 headers、cookie、用户、租户、凭证不同，在每个请求边界里单独创建 Client。

Provider 卸载**不会** abort HTTP、关 SSE/WebSocket、退订监听，也不会调 `dispose`。`@defjs/react` 没有这套生命周期 API。启动每次操作的代码必须收尾或取消。

## 参考

`@defjs/react` 的公开导出：

- `ClientProvider` — 接收 `ClientProviderProps`，提供传入的 Client
- `useClient` — 显式 Client 优先，否则读最近提供的 Client；两者都没有就抛错
- `ClientProviderProps` — `{ client: Client; children?: ReactNode }`

Client 和 options 在 `@defjs/core` 里创建。见 [Client](/zh-Hans/docs/client)、[Errors](/zh-Hans/docs/errors)、[SSE](/zh-Hans/docs/sse)、[WebSocket](/zh-Hans/docs/web-socket)。
