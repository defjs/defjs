# React

`@defjs/react` 通过 React Context 与 `useClient()`，把应用自有的 `@defjs/core` Client 接入 React 18+ 组件树。SDK 定义保持为纯 `@defjs/core` 模块，不依赖 React。

```sh
bun add @defjs/core @defjs/react react
```

## `@defjs/react` 负责什么，应用负责什么

- **由 `@defjs/react` 提供**：`ClientProvider` 与 `useClient(overrideClient?)`。
- **由应用负责**：创建 [`DerivableClient`](/zh-Hans/api/core/derivableclient-type)，在卸载或依赖变化时用 `AbortController` 取消在途请求，关闭 SSE/WebSocket 句柄，以及接入 TanStack Query 等查询缓存。
- **重要**：`useClient()` 返回 `DerivableClient` 函数对象。在操作运行处调用 `client({ signal })`（例如 `getOrder(client({ signal }), input)`）。不要把 `client` 直接传给 `setState(client)`，因为 React 会把传给状态设置函数的函数参数当作更新函数。

## 2. 使用 `useClient` 读取与覆盖 Client

`useClient(overrideClient)` 优先返回 `overrideClient`；省略或传入 `undefined` 时读取最近的 `ClientProvider`。两种来源都没有提供 Client 时才抛出 `Error`。

<include cwd>examples/react/read-with-use-client.tsx#example</include>

- 请始终在组件或自定义 Hook 的顶层无条件调用 `useClient(explicitClient)`。切勿书写 `explicitClient ?? useClient()`，这违反了 React 的 Hook 规则（Rules of Hooks）。

## 4. 在 Effect 中管理 SSE 与 WebSocket 生命周期

SSE 与 WebSocket 句柄的存活时间长于最初的 `openStream(...)` 或 `connectChat(...)` 调用。把 `AbortController` 的 signal 传入操作，并在清理逻辑中中止它：该 signal 覆盖启动阶段和已打开的会话。用 `await using` 持有会话，并消费其唯一的异步迭代器：

<include cwd>examples/react/own-realtime-work.tsx#example</include>

- 中止传入 WebSocket 操作的 `signal` 会让会话以 `aborted` 结束，并使 `session.receive` 以 `AbortError` reject。用 `controller.signal.aborted` 保护 `catch` 块，只让真正的运行时错误（例如心跳超时）暴露出来。
- 中止 SSE 流会让 `for await (const msg of stream)` 正常结束，不抛出异常。

---

## 5. SSR 与 Provider 作用域

- **浏览器**：当端点与拦截器与具体请求无关时，共享一个模块作用域的 Client。
- **SSR**：当请求头、cookie、租户或凭据因请求而异时，在每个服务端请求边界内创建新 Client。
- 卸载 `<ClientProvider>` **不会**中止活跃的 HTTP 调用、关闭 SSE/WebSocket 连接或销毁 Client。
