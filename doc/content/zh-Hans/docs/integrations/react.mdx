# React

`@defjs/react` 通过 React Context 与 `useClient()` Hook，将消费方应用自有的 `@defjs/core` Client 注入到 React 18+ 组件树中。你的 SDK 定义始终保持为纯净的 `@defjs/core` 模块，对 React 实现完全零依赖。

```sh
bun add @defjs/core @defjs/react react
```

## `@defjs/react` 负责什么 vs. 你负责什么

- **由 `@defjs/react` 提供**：`ClientProvider` 组件与 `useClient(overrideClient?)` Hook。
- **由你的应用全权管理**：创建 [`DerivableClient`](/zh-Hans/api/core/derivableclient-type)、在组件卸载或依赖项变更时通过 `AbortController` 取消在途请求、关闭 SSE/WebSocket 句柄，以及接入诸如 TanStack Query 等数据缓存管理库。
- **重要须知**：`useClient()` 返回的是可调用的 `DerivableClient` 函数对象。在执行操作的地方调用 `client({ signal })`（如 `getOrder(client({ signal }), input)`）。切勿将 `client` 直接传递给 `setState(client)`，因为 React 会将传递给 state setter 的函数参数当成状态更新函数（updater function）来执行。

- `ClientProvider` 是一个轻量的 React Context Provider。传递不同的 `client` prop 会更新后代组件读取到的值，而不会克隆或销毁原有的 Client。
- 在开发模式（`StrictMode`）下，React 会多次挂载并清理 Effect。通过判断 `controller.signal.aborted`，可以有效防止因请求过时返回而覆盖当前最新渲染状态。

## 2. 使用 `useClient` 读取与覆盖 Client

`useClient(overrideClient)` 若传入了 `overrideClient` 参数则优先直接返回它；若省略或传入 `undefined`，则读取组件树向上最近的 `ClientProvider`。只有当两种来源均未提供 Client 时，才会抛出 `Error` 异常。

<include cwd>examples/react/read-with-use-client.tsx#example</include>

- 请始终在组件或自定义 Hook 的顶层无条件调用 `useClient(explicitClient)`。切勿书写 `explicitClient ?? useClient()`，这违反了 React 的 Hook 规则（Rules of Hooks）。

## 4. 在 Effect 中管理 SSE 与 WebSocket 的长连接生命周期

SSE 与 WebSocket 长连接的存活时间往往远长于初次调用 `openStream(...)` 或 `connectChat(...)` 的时刻。在 await 异步握手前先行注册清理逻辑，关闭在卸载后才成功建立的句柄，消费其唯一的异步迭代器，并等待 `.closed`：

<include cwd>examples/react/own-realtime-work.tsx#example</include>

- 取消传递给 WebSocket 操作的 `signal` 会使会话以 `aborted` 状态终结，并使 `session.receive` 以 `AbortError` 报错。在清理阶段注意捕获该错误，确保只向外界暴露真正的运行时异常（如队列溢出或心跳确认超时）。
- 取消 SSE 事件流时，`for await (const msg of stream)` 循环会优雅退出结束，不会抛出异常。

## 5. SSR 与 Provider 作用域

- **浏览器环境**：当服务地址与拦截器对所有请求通用安全时，可直接共享模块作用域的 Client 单例。
- **服务端渲染（SSR）**：当请求头、Cookie、租户或认证凭据因每个入站请求而异时，务必在每个服务端请求边界内部单独创建全新的 Client 实例。
- 卸载 `<ClientProvider>` **不会**自动中断活跃的 HTTP 请求，不会关闭 SSE/WebSocket 长连接，也不会调用 `disposeClient`。
