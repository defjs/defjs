# 快速开始：你的第一个 SDK 操作 [#getting-started-one-http-request]

这次先以 SDK 作者的身份定义并导出 `GET /orders/:id`，再以应用开发者的身份导入它、创建 Client 并执行。两个文件分别承担契约与调用，`200` 和声明的 `404` 都保留类型。本地 handle 让第一次执行可以离线完成；连接真实服务时继续使用同一个定义。

## 最佳实践

定义与 client 彼此独立。用应用的 client 调用操作，例如 `getOrder(client, { id: 7 })`。没有第三个 options 参数。调用操作即开始它；`await` 只是等待。服务地址和凭证也归应用所有。先检查 error-first tuple。`error` 有值时，报告 `error.code`，从函数返回，然后再读取成功值。

## 第 1 步 — 安装

`@defjs/core` 是 ESM，可运行在 Node.js 或 Bun 上。Node.js 22.18+（或 24+）通过类型擦除直接运行 `.ts`；更早的 22.x 需要 `--experimental-strip-types`。package.json 里保留 `"type": "module"`。浏览器里照样需要 bundler 和 Fetch。

```sh
bun add @defjs/core
```

## 第 2 步 — 定义请求

创建 `src/define-request.ts`，导出 SDK 的 `getOrder` 端点。Input Struct 描述调用方提供的值，`builder` 决定值在请求中的位置。这里整个 input 就是 path 对象，没有 alias 的标量字段会填入 `:id`。定义文件不创建 Client，也不发起请求。

<include cwd meta="define-request.ts">
  examples/start/define-request.ts#example
</include>

`output` 是 2xx body。`error` 是其余每个状态。各一个 struct。这些 body 形状不同时，用 `struct.or(...)` 或判别联合。

`defineRequest(...)` 返回一个操作。调用 `getOrder(client, input)` 即开始请求。上面的 `builder` 是摆放 input 的函数，它不是操作。声明了 `input` 时，`builder` 必填、同步且纯。

## 第 3 步 — 本地调用

创建 `src/execute-locally.ts`，从 `./define-request.ts` 导入 `getOrder`。应用拥有 Client，并为它配置服务地址和本地 Fetch handle；不用联网也能完成输入校验、`Request` 构造、状态分派和 body 解析。

<include cwd meta="execute-locally.ts">
  examples/start/execute-locally.ts#example
</include>

跑起来：

```sh
bun src/execute-locally.ts
```

```txt
Loaded paid from 200
```

试试找不到的订单——把 path id 改成 `8` 再跑：

```txt
Order not found
```

成功时：`error` 是 `null`，`order` 是 `200` Struct 输出，`response` 是 `DecodedResponse`。声明过的 `404`：`error.code` 是 `'HTTP_STATUS'`，`error.status` 是 `404`，`error.data` 类型是 `NotFound`。失败时第二项是 `undefined`。

## 第 4 步 — 指向真实 API

在 `src/real-api.ts` 里导入同一个 `getOrder`，并用你的服务 base URL 创建一个 client。先把示例地址换成实现了 `GET /v1/orders/:id`、且 body 与这些契约一致的服务，再运行这一版。

<include cwd>examples/start/real-api.ts#example</include>

API 定义留在 SDK 模块里。服务地址、凭证、拦截器和执行寿命留在应用里。两个 client 使用同一份 Defjs 端点契约。

## 发布定义

更多应用需要这份定义时，把它移进一个 SDK 包。导出 `getOrder`，带上它的 TypeScript 声明，并声明兼容的 Core 版本。消费方改为从包导入，而不是从 `./define-request.ts` 导入；他们的 client 配置仍是他们自己的。完整的包设置见[构建并发布 SDK](/zh-Hans/recipes/publish-http-sdk)。

## 结果对不上时

- 坏输入 → `REQ_INPUT_INVALID`；`builder` 失败 → `REQ_BUILD_FAILED`
- 非 2xx 状态 → `HTTP_STATUS`；声明过 `error` 且其 body 解码成功时，`error.data` 带类型
- 声明过的 JSON body 媒体类型不对 → `RES_MEDIA_TYPE_INVALID`，在读 body 之前就报
- 声明过的 body（2xx 是 `output`，其余是 `error`）解不出来 → `RES_DECODE_FAILED` 或 `RES_STRUCT_MISMATCH`，与状态无关
- Fetch 失败 / 取消 / 期限 → `NET_UNREACHABLE` / `NET_ABORTED` / `NET_TIMEOUT`

期限是 `client({ signal: AbortSignal.timeout(ms) })`，归类为 `NET_TIMEOUT`。手动中止是 `NET_ABORTED`。没有 client 级的默认期限。某一次调用需要自己的 `signal` 时，派生一个 client；见 [Client](/zh-Hans/docs/client)。取消只说明调用方看到了什么——无法说明服务端写入是否已经提交。
