# 快速开始：一次 HTTP 请求

这次先以 SDK 作者的身份定义并导出 `GET /users/:id`，再以应用开发者的身份导入它、创建 Client 并执行。两个文件分别承担契约与调用，`200` 和声明的 `404` 都保留类型。本地 handle 让第一次执行可以离线完成；连接真实服务时继续使用同一个定义。

## 最佳实践

定义与 client 彼此独立。调用定义只会创建 command。先给这个 command 起名，再把这个名字交给应用自己的 client 去 `client.execute`。服务地址和凭证也归应用所有。先检查 error-first 元组。`error` 有值时，报告 `error.code`，从函数返回，然后再读取成功值。

## 第 1 步 — 安装

`@defjs/core` 是 ESM，可运行在 Node.js 或 Bun 上。Node.js 22.18+（或 24+）通过类型擦除直接运行 `.ts`；更早的 22.x 需要 `--experimental-strip-types`。package.json 里保留 `"type": "module"`。浏览器里照样需要 bundler 和 Fetch。

```sh
bun add @defjs/core
```

## 第 2 步 — 定义请求

创建 `src/define-request.ts`，导出 SDK 的 `getUser` 端点。Input Struct 描述调用方提供的值，`builder` 决定值在请求中的位置。这里整个 input 就是 path 对象，没有 alias 的标量字段会填入 `:id`。定义文件不创建 Client，也不发起请求。

<include cwd meta="define-request.ts">
  examples/start/define-request.ts#example
</include>

`output` 是 2xx body。`error` 是其余每个状态。各一个 struct。这些 body 形状不同时，用 `struct.or(...)` 或判别联合。

`defineRequest(...)` 返回 endpoint。调用 `getUser(...)` 创建不透明命令，再交给 `client.execute(...)`。上面的 `builder` 是摆放 input 的函数，它不是 endpoint。

## 第 3 步 — 本地执行

创建 `src/execute-locally.ts`，从 `./define-request.ts` 导入 `getUser`。应用拥有 Client，并为它配置服务地址和本地 Fetch handle；不用联网也能完成输入校验、`Request` 构造、状态分派和 body 解析。

<include cwd meta="execute-locally.ts">
  examples/start/execute-locally.ts#example
</include>

跑起来：

```sh
bun src/execute-locally.ts
```

```txt
Loaded Ada from 200
```

试试找不到的用户——把 path id 改成 `8` 再跑：

```txt
User not found
```

成功时：`error` 是 `null`，`user` 是 `200` Struct 输出，`response` 是 `DecodedResponse`。声明过的 `404`：`error.code` 是 `'HTTP_STATUS'`，`error.status` 是 `404`，`error.data` 类型是 `NotFound`。失败时第二项是 `undefined`。

## 第 4 步 — 指向真实 API

服务实现了 `GET /v1/users/:id` 且 body 符合契约时，在 `src/real-api.ts` 中导入同一个 `getUser`。应用只需创建指向真实 base URL 的 Client，省略本地 `withHTTPHandle(...)`。将示例地址替换为你实际部署的服务。

<include cwd meta="real-api.ts">

</include>

SDK 定义保持不变。应用拥有服务地址、鉴权和取消策略；定义中的 Struct、builder 和 HTTP 语义仍由 Defjs 执行。需要把定义交给其他项目时，继续阅读[构建并发布 SDK](/zh-Hans/recipes/publish-http-sdk)。

## 结果对不上时

- 坏输入 → `REQ_INPUT_INVALID`；冲突的取消 options → `REQ_OPTIONS_INVALID`；`builder` 失败 → `REQ_BUILD_FAILED`
- 非 2xx 状态 → `HTTP_STATUS`；声明过 `error` 且其 body 解码成功时，`error.data` 带类型
- 声明过的 JSON body 媒体类型不对 → `RES_MEDIA_TYPE_INVALID`，在读 body 之前就报
- 声明过的 body（2xx 是 `output`，其余是 `error`）解不出来 → `RES_DECODE_FAILED` 或 `RES_STRUCT_MISMATCH`，与状态无关
- Fetch 失败 / 取消 / 超时 → `NET_UNREACHABLE` / `NET_ABORTED` / `NET_TIMEOUT`

`timeout` 必须是 `1..2_147_483_647` 的正安全整数。合法取消形状：`{ signal }`、`{ timeout }`、`{ abort }`，或 `{ signal, timeout }` / `{ signal, abort }`。`{ abort, timeout }` 一起传是非法的。取消只说明调用方看到了什么——无法说明服务端写入是否已经提交。
