# Client

`Client` 负责把所有和运行环境相关的执行配置收拢到一起：服务域名、公共请求头、认证凭据、拦截器、查询序列化以及单元测试传输句柄。

调用 `createClient(...options)` 会返回一个 [`DerivableClient`](/zh-Hans/api/core/derivableclient-type)：

- **日常直接调用**：不需要为单次请求单独覆写参数时，直接传 `client` 给操作就行：`getOrder(client, { id: 1 })`。
- **单次派生配置**：需要给这一次请求加 `signal` 或进度监听时，调用 `client(requestOptions)` 派生一个一次性 `Client` 值：`getOrder(client({ signal }), { id: 1 })`。注意：派生这一步**不会**发网络请求，返回的新对象是一次性的普通 `Client`（不能再当函数二次调用）。

### 配置项叠加顺序

- 配置按参数**从左到右**依次生效。
- 覆盖型选项（`withEndpoint`、`withHeaders`、`withQuerySerializer`、`withCredentials` 以及 `@defjs/core/xsrf` 的 `withXSRF`）会用后面的配置**直接替换**前面的同款选项。
- `withInterceptors(...items)` 会不断**追加**到拦截器队列里。调用时，`operation` 拦截器包住整次调用，里面只跑当前传输协议对应的拦截器（`http`、`sse` 或 `web-socket`）。

> [!IMPORTANT]
> 因为 `createClient(...)` 返回的是一个**可调用的函数对象**（`DerivableClient`），写前端代码时**千万别**把它直接传进 React 的 `setState(client)` 或 Vue 的 `watch(client)` / `computed(client)`，否则框架会把它当成状态更新回调或 getter 直接执行！

### 单次 `RequestOptions` 支持哪些字段

`RequestOptions` 一共 7 个扁平字段，各协议只读取跟自己有关的那几个，无关字段自动忽略：

| 字段名称             | 适用协议             | 效果说明                                                                                        |
| -------------------- | -------------------- | ----------------------------------------------------------------------------------------------- |
| `signal`             | HTTP、SSE、WebSocket | 中断当前调用（`AbortSignal.timeout(ms)` 对应 `NET_TIMEOUT`；手动 `abort()` 对应 `NET_ABORTED`） |
| `onUploadProgress`   | HTTP                 | 监听 `ReadableStream` 请求体的上传进度                                                          |
| `onDownloadProgress` | HTTP                 | 监听响应体的下载进度                                                                            |
| `beforeConnect`      | WebSocket            | 仅本次连接覆盖 Client 默认的 `beforeConnect` 钩子                                               |
| `protocols`          | WebSocket            | 仅本次连接覆盖 Client 默认的子协议列表                                                          |
| `heartbeat`          | WebSocket            | 仅本次连接覆盖 Client 默认的心跳保活策略                                                        |
| `retry`              | HTTP、SSE、WebSocket | 仅本次调用替换重试策略（注意 HTTP 的全局重试预算 `budget` 仍留在原 Client 上共享）              |

## 3. 浏览器全局用 vs. SSR 按请求隔离

- **浏览器 SPA**：接口域名、拦截器和认证方式在整页生命周期内都一致时，在模块顶层导出一份共享 `DerivableClient` 即可。
- **Node 服务端 / SSR**：如果不同请求会带不同的用户 Cookie、Token 或租户信息，**务必在每次请求处理内部单独 `createClient(...)`**。千万别把带某个用户登录态的拦截器写进全进程共享的 Client 里，否则会导致串号！

## 4. 多节点与重试策略 [#multiple-endpoints]

`withEndpoint(...urls)` 可以传多个候选服务地址，默认规则很克制：

- **默认用 [`pickFirstBalancer`](/zh-Hans/api/core/pickfirstbalancer)**：一直盯着第一个可用地址发，只有遇到连不上（`NET_UNREACHABLE`）或 `502`/`503`/`504`（`NET_UNAVAILABLE`）时才会尝试往后面的备选节点切。
- **默认完全不重试**：不传 `withRetry` 时每次操作只试一次。如果传 `withRetry()` 或 `withRetry({})`，HTTP、SSE 和 WebSocket 都会开启最多 3 次带退避的重试。每次重试都会重新过一遍均衡器挑节点（单节点则在等完退避后重打同一个节点）；HTTP 的 Finagle 重试预算挂在原 `Client` 上，所有派生出的 `client(options)` 共用同一份预算。

<include cwd lang="typescript">
  examples/client/multiple-endpoints.ts#example
</include>

**只要单次超时、不想要重试**怎么办？配置 `withRetry({ maxRetries: 0, attemptTimeoutMs })`！其中 `attemptTimeoutMs` 管单次尝试期限：HTTP 计到响应体读完，SSE 计到拿到响应头，WebSocket 计到触发 `open`。详细的优先级和旧选项迁移说明见 [负载均衡与故障转移](/zh-Hans/docs/load-balancing#retries)。

### 异常节点摘除与 P2C 负载均衡 [#health-filtering-and-p2c]

如果有多个对等后端实例，可以用 [`roundRobinBalancer`](/zh-Hans/api/core/roundrobinbalancer) 或 [`p2cBalancer`](/zh-Hans/api/core/p2cbalancer)（基于 PeakEwma 衰减耗时 × 当前并发负载选路）：

- **默认不开启摘除**：除非在配置里显式传入 `outlierDetection`（用默认阈值只需写 `outlierDetection: {}`），否则节点不会因为失败被暂时踢出候选池。
- **什么是“失败”**：开启摘除后，默认所有带错误码的结果（包括 `NET_TIMEOUT` 和 `NET_BODY_INCOMPLETE`）都会计入失败统计，你也可以传自定义 `isFailure` 函数调整判定规则（只有自己实现自定义均衡器时能看到原始响应 `status`）。
- **搭配主动健康检查**：还可以同时传 `isHealthy` 钩子接入自己的健康状态判断，Defjs 不会代替你规定“什么叫健康”。

关于重试预算、摘除冷却时长和自定义均衡器，继续看 [负载均衡与故障转移](/zh-Hans/docs/load-balancing)。

## 6. 常用 `with*` 配置项速查表

| 配置项                                                                             | 一句话说明                                                                                                                          |
| ---------------------------------------------------------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------- |
| `withEndpoint(...urls)`                                                            | 设置一个或多个服务基础地址（覆盖之前的值）                                                                                          |
| `withHeaders(HeadersInit)`                                                         | 为 HTTP 和 SSE 设置默认请求头（会被操作里的 `builder` 覆盖）                                                                        |
| `withInterceptors(...items)`                                                       | 按洋葱模型追加 HTTP、SSE、WebSocket 或操作拦截器                                                                                    |
| `withQuerySerializer(fn)`                                                          | 自定义 Query 序列化格式（例如支持嵌套方括号写法）                                                                                   |
| `withCredentials(boolean)`                                                         | 为 `true` 时给 HTTP 和 SSE 开启 `credentials: "include"`                                                                            |
| `withXSRF(options?)`                                                               | 来自 `@defjs/core/xsrf`。浏览器内自动将 XSRF Cookie 带到同源变更请求头里；在 Node/Bun/Worker 里会抛错，同构项目注意判断环境后再挂载 |
| `withBalancer(balancer)`                                                           | 切换节点选择策略（`pickFirstBalancer`、`roundRobinBalancer`、`p2cBalancer`）                                                        |
| `withRetry(options?)`                                                              | 配置 HTTP / SSE / WebSocket 的重试次数、退避、方法白名单、单次尝试超时与重试预算                                                    |
| `withSSEOnInvalidEvent`                                                            | 监听 SSE 推过来但未过 `struct` 校验的异常事件                                                                                       |
| `withWebSocketHeartbeat` / `withWebSocketProtocols` / `withWebSocketBeforeConnect` | 设置 WebSocket 默认心跳、子协议和建连前钩子                                                                                         |
| `withHTTPHandle` / `withSSEHandle` / `withWebSocketHandle`                         | 在测试环境替换底层传输实现                                                                                                          |
