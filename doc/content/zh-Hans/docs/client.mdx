# Client

`Client` 承载消费方应用的执行配置：基地址、默认请求头、认证凭据、拦截器、查询序列化器和传输层句柄。

`createClient(...options)` 返回一个 [`DerivableClient`](/zh-Hans/api/core/derivableclient-type)：

- 当无需传递单次调用的特定请求选项时，直接将 `client` 传给操作函数（如 `getOrder(client, { id: 1 })`）。
- 调用 `client(requestOptions)` 可派生出一个仅供单次调用生效的 `Client` 值（如 `getOrder(client({ signal }), { id: 1 })`）。派生过程不执行任何网络 I/O，且派生出的值是一个普通对象（不再具备可调用特性）。

### 选项组合规则

- 选项生效顺序为**从左向右**。
- 单值覆盖型配置项（`withEndpoint`、`withHeaders`、`withQuerySerializer`、`withCredentials`，以及来自 `@defjs/core/xsrf` 的 `withXSRF`）会直接**替换**之前配置的值。
- `withInterceptors(...items)` 会**追加**到现有拦截器列表中，并在操作实际执行时按对应的传输协议类型（`http`、`sse`、`web-socket`）自动过滤执行。

> [!IMPORTANT]
> 由于 `createClient(...)` 返回的是一个可调用的函数对象（`DerivableClient`），请**切勿**将其直接传入 React 的 `setState(client)` 或 Vue 的 `watch(client)` / `computed(client)` 中，否则会被框架错误识别为状态更新函数或计算属性 Getter。

### 单次调用 `RequestOptions` 参数速查

`RequestOptions` 包含七个扁平属性字段。每种传输协议在运行时只读取与自身相关的字段，其余字段会被自动安全忽略：

| 属性字段             | 适用协议             | 行为表现                                                                                                   |
| -------------------- | -------------------- | ---------------------------------------------------------------------------------------------------------- |
| `signal`             | HTTP、SSE、WebSocket | 取消/中断当前调用（`AbortSignal.timeout(ms)` 映射为 `NET_TIMEOUT`；手动调用 abort 映射为 `NET_ABORTED`）。 |
| `onUploadProgress`   | HTTP                 | 监听流式请求体上传进度。                                                                                   |
| `onDownloadProgress` | HTTP                 | 监听声明过的响应体下载进度。                                                                               |
| `beforeConnect`      | WebSocket            | 覆盖当前会话在 Client 级别配置的 `beforeConnect` 钩子。                                                    |
| `protocols`          | WebSocket            | 覆盖当前会话在 Client 级别配置的子协议列表。                                                               |
| `heartbeat`          | WebSocket            | 覆盖当前会话在 Client 级别配置的心跳检测策略。                                                             |
| `retry`              | HTTP、SSE、WebSocket | 为这次调用替换 Client 级的重试策略。HTTP 的 `budget` 仍留在 Client 上。                                    |

## 3. 浏览器单例模式 vs. 服务端请求作用域

- **浏览器应用程序**：当服务地址、拦截器和认证凭据在整个浏览器上下文内全局共享时，可直接在模块作用域导出一个单例 `DerivableClient`。
- **服务端 / SSR 应用程序**：当请求头、Cookie、身份 Token 或租户信息与单个入站请求强绑定时，**务必在每个请求边界内部**创建独立的 Client 实例。切勿在整个进程共用的 Client 上存储单个用户的鉴权信息。

## 4. 多服务节点与负载均衡 [#multiple-endpoints]

`withEndpoint(...urls)` 支持传入一个或多个候选服务基地址。在默认配置下：

- 每个 Client 默认使用 [`pickFirstBalancer`](/zh-Hans/api/core/pickfirstbalancer)，持续停在首个 URL，直到遇到 `NET_UNREACHABLE` 或 `NET_UNAVAILABLE`（HTTP 502、503 或 504）时才前进。
- **重试默认关闭。** 一次调用只做一次尝试。`withRetry()` 与 `withRetry({})` 等价：HTTP、SSE 和 WebSocket 都最多重试三次，并带退避。每次失败后，均衡器会从全部端点中再次选择，因此在 pick-first 下，连接被拒绝之后的重试会到达下一个端点，而只有一个端点时，延迟之后会再次尝试它。HTTP 的 Finagle 重试预算属于 Client 配置，由其派生出的 Client 共享，与均衡器的身份无关。

<include cwd lang="typescript">
  examples/client/multiple-endpoints.ts#example
</include>

`attemptTimeoutMs` 限制单次尝试：HTTP 计到响应 body 结束，SSE 计到响应头，WebSocket 计到 `open`。只要时间限制、不要重试时，写成 `withRetry({ maxRetries: 0, attemptTimeoutMs })`。重试选项在运行时不会校验。决策顺序，以及从 `withSSEReconnect` 和 `withWebSocketReconnect` 迁移的说明，见 [负载均衡与故障转移](/zh-Hans/docs/load-balancing#retries)。

### 被动健康检测与 P2C 算法 [#health-filtering-and-p2c]

对于多个对等的服务端副本，[`roundRobinBalancer`](/zh-Hans/api/core/roundrobinbalancer) 与 [`p2cBalancer`](/zh-Hans/api/core/p2cbalancer)（基于 PeakEwma 衰减 RTT × 在途负载）可以接收 `outlierDetection` 选项；除非传入对象（默认值用 `{}`），否则它是关闭的。它统计失败并把端点逐出一段时间，也会跳过你自己的 `isHealthy` 函数拒绝的端点；Defjs 不决定什么叫健康。默认情况下，每个带错误码的结果都计为失败（包括 `NET_TIMEOUT` 和 `NET_BODY_INCOMPLETE`），你可以用 `isFailure` 替换这条规则；原始响应 `status` 只供自定义均衡器使用。

关于重试预算、失败逐出和你自己的健康函数、P2C 负载估算及编写自定义均衡器的详细内容，请参阅专门的[负载均衡与故障转移](/zh-Hans/docs/load-balancing)指南。

## 6. Client 配置辅助函数速查

| 辅助函数                                                                           | 作用说明                                                                                                                                                                                                                                                         |
| ---------------------------------------------------------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `withEndpoint(...urls)`                                                            | 设置一个或多个候选服务基地址（直接替换原有列表）。                                                                                                                                                                                                               |
| `withHeaders(HeadersInit)`                                                         | 为 HTTP 和 SSE 配置静态默认请求头（会被 builder 返回的 headers 覆盖）。                                                                                                                                                                                          |
| `withInterceptors(...items)`                                                       | 按洋葱模型追加 HTTP、SSE 及 WebSocket 拦截器。                                                                                                                                                                                                                   |
| `withQuerySerializer(fn)`                                                          | 自定义将带有别名的 Query 对象序列化为查询字符串的算法。                                                                                                                                                                                                          |
| `withCredentials(boolean)`                                                         | 当为 `true` 时，为 HTTP 和 SSE 请求开启 Fetch `credentials: "include"`。                                                                                                                                                                                         |
| `withXSRF(options?)`                                                               | 来自 `@defjs/core/xsrf`。在浏览器中，于同源且产生数据变更的 HTTP 请求上，自动将 XSRF Cookie 拷贝注入至对应请求头中。调用 `withXSRF()` 时，若缺少 `location` 或 `document`（包括 Worker）会抛错。同构代码只在浏览器里添加这个选项。令牌来自别处时，用拦截器设置。 |
| `withBalancer(balancer)`                                                           | 替换服务节点选择策略（如 `pickFirstBalancer`、`roundRobinBalancer`、`p2cBalancer`）。                                                                                                                                                                            |
| `withRetry(options?)`                                                              | 为 HTTP、SSE 和 WebSocket 配置可选开启的重试：重试次数、退避、方法、单次尝试超时、`shouldRetry` 函数，以及归 HTTP Client 所有的预算。                                                                                                                            |
| `withSSEOnInvalidEvent`                                                            | 观察没有 struct 或校验失败的 SSE 事件。                                                                                                                                                                                                                          |
| `withWebSocketHeartbeat` / `withWebSocketProtocols` / `withWebSocketBeforeConnect` | 配置 WebSocket 会话的默认行为。                                                                                                                                                                                                                                  |
| `withHTTPHandle` / `withSSEHandle` / `withWebSocketHandle`                         | 注入自定义或 Mock 的传输层实现，用于离线单测。                                                                                                                                                                                                                   |
