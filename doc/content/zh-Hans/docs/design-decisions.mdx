# 核心架构设计

Defjs 构建在一条根本边界之上：**SDK 定义网络契约，消费方应用负责执行。** `@defjs/core` 的每条设计规则都源自这条边界。

## 1. 定义与执行

SDK 包导出操作（用 `defineRequest`、`defineEventStream`、`defineWebSocket` 创建）和数据契约（`struct`）。它绝不调用 `createClient`、不保存单例 Client，也不读取环境变量。

因为 `getOrder` 不捕获任何 Client 状态：

- 浏览器 UI、后台任务、SSR 请求处理器和单元测试，都可以用不同的 `Client` 配置调用同一个 `getOrder` 操作。
- 框架插件（`@defjs/react`、`@defjs/vue`）和可观测性中间件插件（`@defjs/opentelemetry-server`）挂载在应用的 `Client` 上，从而让发布的 SDK 包保持 100% 零依赖。

## 2. 显式放置输入与双向别名

在 Defjs 中，`input` 声明调用方传入的值，`struct` 控制值如何编码与解码，`builder` 把每个值放到请求上（`path`、`query`、`headers`、`body`）。

- **没有隐式推断**：操作声明了 `input`，就必须提供显式、同步、纯的 `builder`。字段放置绝不根据参数名猜测。
- **双向 `.alias(wireName)`**：在 struct 字段上声明 `.alias("customer_name")`，TypeScript 中保持 `customerName`，网络上自动与 `"customer_name"` 双向映射。

## 3. 声明即断言 [#declaration-is-an-assertion]

Defjs 在读取 HTTP 响应时严格遵循以下六大规则：

### 规则 1：声明什么就断言什么

`output` 断言 `2xx` body 的结构。`error` 断言非 `2xx` body 的结构。声明是运行时保证，不是尽力而为的提示。

### 规则 2：`ok`（`200..299`）是唯一分流点

`2xx` 响应只用 `output` 解码。其他所有状态码（`3xx`、`4xx`、`5xx`）只用 `error` 解码。Defjs 绝不从一侧回退到另一侧。

### 规则 3：任何偏离声明都是明确的 Fault

Defjs 用 `response.ok` 选择响应的一侧：`2xx` 用 `output`，非 `2xx` 用 `error`。只有该侧声明了 JSON struct 才会触发解码，并可能产生 `RES_MEDIA_TYPE_INVALID` 或 `RES_DECODE_FAILED`；它的 `Content-Type` 会在读取 body 字节**之前**校验。非 `2xx` 的 HTML 网关页只有在声明了 JSON `error` struct 时才会产生 `RES_MEDIA_TYPE_INVALID`。当前响应一侧没有声明时，不会读取 body；非 `2xx` 响应返回未解码的 `HTTP_STATUS`。

| 读取响应时出现的失败                               | 返回的 `Fault` 代码                                            |
| -------------------------------------------------- | -------------------------------------------------------------- |
| 媒体类型与所声明的 JSON 格式不匹配                 | `RES_MEDIA_TYPE_INVALID`（根本不会读取 body 字节流）           |
| 底层字节流无法按所声明的格式解码                   | `RES_DECODE_FAILED`                                            |
| 解码后的数据未能通过 `struct` 模式校验             | `RES_STRUCT_MISMATCH`（HTTP）/ `RES_DECODE_FAILED`（SSE 握手） |
| 非 `2xx` 状态码，且成功解码了声明的 `error` struct | `HTTP_STATUS`（附带强类型的 `error.data`）                     |
| 非 `2xx` 状态码，但未声明 `error`                  | `HTTP_STATUS`（此时 `error.data` 为 `undefined`）              |

### 规则 4：解码失败则无 Body 数据

只有通过解码与校验之后才存在 body。解码失败时，`Fault` 的 `response` 类型是 `HttpMeta`（没有 `body` 属性），解析或校验错误挂在 `fault.cause` 上。

### 规则 5：省略声明即代表主动放弃读取

省略 `output` 意味着 `2xx` body 从不读取。省略 `error` 意味着非 `2xx` body 从不读取——即使服务端在 `500` 上返回了非法 JSON。

### 规则 6：`3xx` 不属于成功状态区间

`ok` 意味着 `200 <= status < 300`。`304 Not Modified` 不是 `2xx`：保持 `error` 未声明并处理 `HTTP_STATUS`（或在 ETag 拦截器中拦截 `304`），或者在期望空文本 body 时声明 `struct.string()`。

## 4. 传输专属的返回结果元组

三种传输都返回三项错误优先元组，而不是在调用处抛出异常：

- **HTTP** → `[error, data, response]` —— 解码后的载荷 + `DecodedResponse<T>`（未声明 `output` 时为 `HttpMeta`）。
- **SSE** → `[error, stream, open]` —— `EventStreamHandle` + 初始握手快照。
- **WebSocket** → `[error, session, connection]` —— `WebSocketSession` + 初始连接快照。

Client 承载配置，不承载活跃连接。发起 HTTP 请求、SSE 流或 WebSocket 会话的调用方负责取消或关闭它（HTTP 用 `AbortSignal`；SSE 和 WebSocket 用 `await using` 或 `.close()` + `await .closed`）。
