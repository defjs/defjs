# 核心架构设计

Defjs 所有设计都围绕着一条核心边界：**接口定义只声明网络契约，具体怎么发请求由应用在运行时决定。** `@defjs/core` 里的每条约束都源于这一原则。

## 1. 定义与执行分开

操作定义模块只导出操作（`defineRequest`、`defineEventStream`、`defineWebSocket`）和数据结构（`struct`）。它从不调用 `createClient`，不保留全局单例，也不读取 `process.env`。

正因为 `getOrder` 自身不绑定任何 `Client` 状态：

- 浏览器组件、定时任务、SSR 服务端接口处理器和离线单元测试，都能拿着各自配置好的 `Client` 去调用同一个 `getOrder`。
- 框架插件（`@defjs/react`、`@defjs/vue`）与服务端可观测性工具（`@defjs/opentelemetry-server`）只需挂到应用侧的 `Client` 上，定义模块本身可以保持 100% 零运行时依赖。

## 2. 参数怎么放置由 `builder` 显式决定，字段名靠 `.alias()` 双向映射

在 Defjs 里，`input` 只负责声明业务入参类型，`struct` 负责编码解码格式，而参数具体放到 URL、请求头还是请求体，全由 `builder` 明确写出（`path`、`query`、`headers`、`body`）。

- **绝不猜字段名**：只要声明了 `input`，就必须写一个显式、同步、无副作用的纯函数 `builder`，Defjs 不会按字段名自动推断放在 path 还是 query 里。
- **`.alias(wireName)` 双向自动转换**：在 `struct` 字段上写一次 `.alias("customer_name")`，TypeScript 代码里始终使用驼峰 `customerName`，发出和收到的网络报文自动按 `"customer_name"` 转换。

当 `builder` 直接把带类型声明的 `struct` 对象传给 `body`、`query` 或 `headers` 时，字段别名和 `Date` / `bigint` 编码会自动生效；如果你自己手写了一层外包对象（比如上面例子里的 `account_id` 或 `x-api-version`），手写的这几个键名会按字面量原样发出去。

## 3. 声明即断言 [#declaration-is-an-assertion]

Defjs 解析 HTTP 响应时严格遵循六条铁律：

### 规则 1：声明了结构就会在运行时校验

`output` 校验 `2xx` 响应体，`error` 校验非 `2xx` 响应体。这不只是 TypeScript 类型提示，而是真正在运行时执行的契约断言。

### 规则 2：`ok`（`200..299`）是唯一分流点

`2xx` 响应只会用 `output` 解码，其余所有状态码（`3xx`、`4xx`、`5xx`）只会用 `error` 解码，两条路绝不互相降级回退。

### 规则 3：只要偏离声明就明确报 Fault

Defjs 先看 `response.ok` 决定走 `output`（`2xx`）还是 `error`（非 `2xx`），随后按下面的规则执行：

- **声明了 JSON `struct` 时先查 `Content-Type`**：在读取 body 字节之前就检查媒体类型。即使是没有响应体的响应（`HEAD`、`204`、`205`、`304`）也同样检查：声明了 JSON 但缺少 JSON `Content-Type` 会报 `RES_MEDIA_TYPE_INVALID`；若带有 JSON `Content-Type`，再去读空字节则会报 `RES_DECODE_FAILED`。
- **非 `2xx` HTML 错误网关页的行为**：只有当你给非 `2xx` 侧声明了 JSON `error` struct，网关返回的 HTML 错误页才会触发 `RES_MEDIA_TYPE_INVALID`；如果没有声明 `error`，Defjs 根本不会去读响应体，而是直接返回不带 `data` 的 `HTTP_STATUS`。
- **SSE 非 `2xx` 握手的行为**：如果 SSE 握手返回了非 `2xx`，且声明了 `error` struct 但解码失败，那么启动调用直接返回对应的解码 Fault（状态码保留在它的响应元数据里）；而拦截器、重连逻辑以及单次重连的 `closed` 看到的仍然是 `HTTP_STATUS`。

| 读取响应时遇到的情况                   | 最终返回的 Fault                                                    |
| -------------------------------------- | ------------------------------------------------------------------- |
| 媒体类型与所声明的 JSON 格式不匹配     | `RES_MEDIA_TYPE_INVALID`（最先检查；绝不读 body，有没有内容都一样） |
| 响应流读取失败，或字节解析成 JSON 失败 | `RES_DECODE_FAILED`（包括返回空内容却按 JSON 解析的场景）           |
| 解出来的值不符合 `struct` 规则         | `RES_STRUCT_MISMATCH`                                               |
| 非 `2xx` 且成功解码了 `error` struct   | `HTTP_STATUS`，`err.data` 带完整强类型错误信息                      |
| 非 `2xx` 且未声明 `error` struct       | `HTTP_STATUS`，`err.data` 为 `undefined`                            |

### 规则 4：解码失败就没有 `body` 数据

只有通过解析与 `struct` 校验的响应才会有解码后的 body。一旦解码失败，Fault 上的 `response` 类型只是响应元信息 `HttpMeta`（没有 `body` 属性），真正的底层错误原因放在 `err.cause` 上。

### 规则 5：不声明就完全不读取

省略 `output` 意味着收到 `2xx` 时根本不会去读响应体；省略 `error` 意味着哪怕服务端 `500` 返回了一段坏 JSON，Defjs 也直接跳过响应体读取，干净返回 `HTTP_STATUS`。

### 规则 6：`3xx` 不算成功响应

`ok` 严格指 `200 <= status < 300`。像 `304 Not Modified` 属于非 `2xx` 分支：平时只要不写 `error` schema，然后捕获 `HTTP_STATUS` 即可（见 [ETag 条件请求](/zh-Hans/recipes/etag-revalidate)）；如果确实希望接收空文本 body，可以把 `error` 设为 `struct.string()`。

## 4. 不同协议各自返回什么结果元组

三种传输协议都不在调用处抛异常，而是各自返回一套贴合自身生命周期的三元素元组：

- **HTTP** → `[err, data, response]` —— 解码后的数据 + `DecodedResponse<T>`（未声明 `output` 时是 `HttpMeta`）。
- **SSE** → `[err, stream, open]` —— 流控制句柄 `EventStreamHandle` + 首次握手快照。
- **WebSocket** → `[err, session, connection]` —— 会话对象 `WebSocketSession` + 建立连接时的快照。

`Client` 只存放静态配置，不持有活跃连接。发起请求的业务代码自己负责清理资源：HTTP 用 `AbortSignal` 取消，SSE 与 WebSocket 用 `await using` 或 `.close()` 配 `await .closed` 释放连接。

## 5. Defjs 刻意不提供哪些能力（及替代写法）

下面这些在其他客户端里常见的模式，Defjs 都刻意去掉了，对应的替代做法也很直接：

| 刻意不提供                                      | 在 Defjs 里该怎么写                                                    |
| ----------------------------------------------- | ---------------------------------------------------------------------- |
| 全局 Client 单例                                | 由应用自己用 `createClient(...)` 创建，调用时传给操作                  |
| 把操作挂在 Client 方法上（`client.getOrder()`） | 直接调用函数：`getOrder(client, input)`                                |
| Client 级全局超时或 `timeout` / `abort` 配置项  | 传 `client({ signal: AbortSignal.timeout(ms) })` 或 `AbortController`  |
| `defineRequest` 上的 `responseType` 选项        | 通过 `output` 的 struct 类型决定（`string`/`blob`/`arrayBuffer`/JSON） |
| struct 实例上的 `.parse()` 或 `struct.encode`   | 统一使用 `struct.parse(schema, value)` 和 `builder` 映射               |
| 自定义 WebSocket 握手请求头                     | 走 Cookie、短期查询参数票据或 `protocols`                              |
| WebSocket 消息自动包装或路由信封                | 使用 `struct.discriminatedUnion` 配合 `session.onRuntimeError`         |
| OpenAPI 代码生成器                              | 把 OpenAPI 当外部接口规范文档，在边界处用 `struct` 做契约校验          |
