# 公共 SDK 设计 [#public-sdk-design]

当企业或平台团队需要为对外开放的公共 API 发布官方 TypeScript SDK（例如云存储 SDK、支付网关 SDK 或开放平台 SDK）时，SDK 包的核心职责是**完整声明接口契约，同时不预设消费方的运行环境与客户端策略**。

本指南以**兼容 Amazon S3 协议的对象存储 SDK（`@company/s3-sdk`）**为完整手写蓝本，展示如何通过 `models/` 与纯函数 `services/` 构建企业级公共 SDK。

---

## 1. 为什么用 Defjs 构建对外公共 SDK？

传统公共 SDK 往往在包内封装厚重的客户端类（如 `new S3Client({ region, credentials })`）或静态 `Service` 类。使用 `@defjs/core` 编写对外 SDK 能为你的外部客户解决四个核心痛点：

1. **多环境与多云/沙箱无缝切换**：由于 `@company/s3-sdk` 不绑定任何 Endpoint 或 Client，外部开发者可以用同一套操作定义自由连接生产环境（`https://s3.us-east-1.amazonaws.com`）、沙箱测试环境、Cloudflare R2，或本地 CI 中的 MinIO 容器。
2. **100% 按需 Tree-shaking**：每个接口（`listBuckets`、`listObjectsV2`、`getObject`、`putObject`、`deleteObject`）都作为独立纯函数导出，配合 `"sideEffects": false`，只用到上传和下载的前端应用在打包时会自动剔除所有未引用的接口与模型。
3. **运行时结构校验与静态类型合一**：消费方导入一个符号即可同时获得 TypeScript 静态类型（`Infer<typeof ...>`）与运行时数据校验（`struct`），自动完成下划线字段映射（`.alias()`）与日期解析（`struct.date()`）。
4. **消费方完全掌控鉴权、重试与可观测性**：外部客户可以在自己的 `Client` 上自由挂载请求签名拦截器、`withRetry(...)` 重试策略、多区域 `withBalancer(...)` 容灾，或服务端 OpenTelemetry 追踪（`@defjs/opentelemetry-server`）。

## 2. 公共 SDK 目录结构

将 SDK 包划分为 `src/models/`（共享数据模型）与 `src/services/`（按资源域划分的纯函数操作定义），并通过顶层 `src/index.ts` 统一重导出：

```text
@company/s3-sdk/
├── src/
│   ├── models/                 # 1. 共享数据模型（struct + Infer 同名导出）
│   │   ├── common.ts           #    StorageClass, S3Error
│   │   ├── bucket.ts           #    Bucket, ListBucketsOutput
│   │   └── object.ts           #    ObjectSummary, ListObjectsOutput
│   ├── services/               # 2. 按资源域划分的 defineRequest 纯函数
│   │   ├── buckets.ts          #    BucketInput, listBuckets, headBucket, deleteBucket
│   │   └── objects.ts          #    listObjectsV2, headObject, getObject, putObject, deleteObject
│   └── index.ts                # 3. 顶层按需重导出入口
├── package.json                # sideEffects: false, peerDependencies: { "@defjs/core": "^0.8.0" }
└── tsconfig.json
```

### 公共 SDK 接口契约设计要点

- **入参扁平化，由 `builder` 完成多位置分发**：在 `putObject` 中，调用方只需传入扁平的语义化对象（`{ bucket, key, body, contentType, storageClass }`），由同步纯函数 `builder` 将其拆分为 `path`（`:bucket/:key`）、`headers`（`content-type`、`x-amz-storage-class`）与二进制 `body`（`Blob`）；在 `listObjectsV2` 中，`builder` 将驼峰字段 `continuationToken` 和 `maxKeys` 映射为 S3 协议要求的 `continuation-token`、`max-keys` 查询参数，并自动附带 `list-type: 2`。
- **按响应载荷类型精准声明 `output`**：
  - **结构化 JSON（`listBuckets`、`listObjectsV2`）**：声明 `struct.object(...)` 并配合 `.alias()` 和 `struct.date()`。
  - **二进制流/文件（`getObject`）**：声明 `output: struct.blob()`（或 `struct.arrayBuffer()`）。
  - **空响应体（`headBucket`、`headObject`、`putObject`、`deleteObject`）**：直接省略 `output`，避免对 `HEAD`、`200` 或 `204` 的零字节响应体执行 JSON 解析，同时调用方依然可以从返回元组的第 3 项 `response.headers.get("etag")` 中读取响应头元数据。

## 4. 外部开发者如何接入你的公共 SDK

外部应用只需安装 `@company/s3-sdk` 与 `@defjs/core`，使用自己的服务端点和签名拦截器创建 `Client`，即可直接以纯函数方式调用 SDK 导出的操作。该示例采用 Go 风格的错误处理：`syncReport` 发起三次调用，因此按步骤给每个错误命名（`putErr`、`listErr`、`getErr`），返回错误优先元组，并用 `new Error("put object", { cause: putErr })` 包装失败的那一步，就像 Go 的 `fmt.Errorf("put object: %w", err)`。只有程序顶层的 `main` 通过记录日志来处理错误：
