# 公共 SDK 设计 [#public-sdk-design]

当企业或平台团队需要为开放 API 发布官方 TypeScript SDK（比如云存储 SDK、支付网关 SDK 或开放平台 SDK）时，SDK 包最核心的原则是**把接口契约声明清楚，但不替接入方决定运行环境和 Client 策略**。

本指南以**兼容 Amazon S3 协议的对象存储 SDK（`@company/s3-sdk`）**为蓝本，演示怎么用 `schema/` 搭配纯函数 `request/` 写出可直接发布的企业级公共 SDK。

---

## 1. 为什么用 Defjs 写对外公共 SDK？

传统公共 SDK 经常在包里塞进很重的客户端类（比如 `new S3Client({ region, credentials })`）或静态 `Service` 类。用 `@defjs/core` 写对外 SDK 能帮接入方直接省掉四个大麻烦：

1. **多环境与沙箱无缝切换**：因为 `@company/s3-sdk` 不绑定任何 Endpoint 或 Client，使用方可以用完全同一套接口定义连生产环境（`https://s3.us-east-1.amazonaws.com`）、沙箱环境、Cloudflare R2，或者本地 CI 里的 MinIO 容器。
2. **100% 按需 Tree-shaking**：每个接口（`listBuckets`、`listObjectsV2`、`getObject`、`putObject`、`deleteObject`）都是独立导出的纯函数，配合 `"sideEffects": false`，前端只用了上传和下载就不会把其他未引用的接口和 schema 打进产物里。
3. **运行时校验与静态类型合一**：接入方只导入一个名字就能同时拿到 TypeScript 类型（`Infer<typeof ...>`）和运行时校验（`struct`），自动处理下划线转驼峰（`.alias()`）和日期转换（`struct.date()`）。
4. **把鉴权、重试和可观测性还给接入方**：使用 SDK 的团队可以在自己的 `Client` 上按需挂载签名拦截器、`withRetry(...)` 重试、多区域 `withBalancer(...)` 容灾，以及服务端 OpenTelemetry 追踪（`@defjs/opentelemetry-server`）。

## 2. 公共 SDK 目录结构

把 SDK 包拆成 `src/schema/`（共享 schema）和 `src/request/`（按资源域拆分的纯函数接口定义），再通过顶层 `src/index.ts` 统一重导出：

```text
@company/s3-sdk/
├── src/
│   ├── schema/                 # 1. 共享 schema（struct + Infer 同名导出）
│   │   ├── common.ts           #    StorageClass, S3Error
│   │   ├── bucket.ts           #    Bucket, ListBucketsOutput
│   │   └── object.ts           #    ObjectSummary, ListObjectsOutput
│   ├── request/                # 2. 按资源域划分的 defineRequest 纯函数
│   │   ├── buckets.ts          #    BucketInput, listBuckets, headBucket, deleteBucket
│   │   └── objects.ts          #    listObjectsV2, headObject, getObject, putObject, deleteObject
│   └── index.ts                # 3. 顶层按需重导出入口
├── package.json                # sideEffects: false, peerDependencies: { "@defjs/core": "^0.9.0" }
└── tsconfig.json
```

### 公共 SDK 接口契约设计要点

- **入参铺平，由 `builder` 拆到对应位置**：在 `putObject` 里，调用方只要传一个扁平对象（`{ bucket, key, body, contentType, storageClass }`），同步纯函数 `builder` 会把它拆成 `path`（`:bucket/:key`）、`headers`（`content-type`、`x-amz-storage-class`）和二进制 `body`（`Blob`）；而在 `listObjectsV2` 里，`builder` 会把驼峰字段 `continuationToken` 和 `maxKeys` 映射成 S3 协议要求的 `continuation-token`、`max-keys` 查询参数，并自动补上 `list-type: 2`。
- **按响应体类型选对 `output`**：
  - **结构化 JSON（`listBuckets`、`listObjectsV2`）**：声明 `struct.object(...)`，配合 `.alias()` 和 `struct.date()`。
  - **二进制流 / 文件（`getObject`）**：声明 `output: struct.blob()`（或 `struct.arrayBuffer()`）。
  - **空响应体（`headBucket`、`headObject`、`putObject`、`deleteObject`）**：直接不写 `output`，避免对 `HEAD` 或空响应做 JSON 解析；需要读元数据的话，可以直接从返回元组的第 3 项里拿 `response.headers.get("etag")`。

## 4. 接入方怎么用你的公共 SDK

接入方只需要装上 `@company/s3-sdk` 和 `@defjs/core`，用自己的域名和签名拦截器创建 `Client`，就能直接按纯函数的方式调用 SDK。下面的 `syncReport` 连续发了三次请求，采用 Go 风格的错误处理：给每一步的错误按动作命名（`putErr`、`listErr`、`getErr`），返回错误优先元组，并用 `new Error("put object", { cause: putErr })` 给失败步骤包上上下文（就像 Go 里的 `fmt.Errorf("put object: %w", err)`），只在程序最外层的 `main` 里打日志：
