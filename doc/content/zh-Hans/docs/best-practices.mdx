# 工程规范 [#engineering-conventions]

无论是业务项目内部手写的 HTTP 请求层，还是给公司对外 API 发布的官方 TypeScript SDK，Defjs 项目都推荐同一套模块化分层：**共享的 schema 层（`schema/`）搭配纯函数接口定义层（`request/`）**。

---

## 1. 两大核心使用场景

实际开发里，团队主要会在下面两种场景用上 Defjs。两者的 `schema/` 和 `request/` 组织方式完全一样，唯一区别在于 `createClient(...)` 放在谁手里：

| 使用场景                                                                          | 推荐目录结构                                                         | 谁来创建并持有 `createClient(...)`？                                       | 专题指南                                    |
| :-------------------------------------------------------------------------------- | :------------------------------------------------------------------- | :------------------------------------------------------------------------- | :------------------------------------------ |
| **[应用接口层](/zh-Hans/docs/application-api)**（业务项目内手写 HTTP / 实时请求） | `src/api/schema/` + `src/api/request/` + `src/api/client.ts`         | 当前业务项目自己（由 `src/api/client.ts` 导出浏览器单例或 SSR 请求级工厂） | [应用接口层](/zh-Hans/docs/application-api) |
| **[公共 SDK 设计](/zh-Hans/docs/public-sdk)**（公司对外发布的公共 API npm 包）    | `src/schema/` + `src/request/` + `src/index.ts`（含 `package.json`） | 接入方自己的业务应用（发布的 SDK 包里绝不创建或绑定任何 `Client`）         | [公共 SDK 设计](/zh-Hans/docs/public-sdk)   |

---

## 2. 四条核心工程规范

### 规范一：直接导出纯函数接口，不用 `Service` 类

传统的 OpenAPI 生成器习惯把接口包进带状态或静态方法的 `Service` 类（比如 `OrdersService.getOrder(id)` 或 `new S3Client().send(...)`）。但在 Defjs 里，用 `defineRequest`、`defineEventStream` 或 `defineWebSocket` 定义出来的每一个操作，本身就是**可以直接调用的独立纯函数**：

```ts
// 反模式：把接口定义塞进 class 或命名空间对象里
export class OrdersService {
  // 会遮住 client(options) 的单次派生能力，也让打包器没法按接口粒度 tree-shake
}

// 最佳实践：在 request/*.ts 中直接导出独立的纯函数接口定义
export const getOrder = defineRequest({
  meta: { operation: "orders.get" },
  method: "GET",
  path: "/orders/:id",
  input: GetOrderInput,
  builder: (input) => ({ path: { id: input.id } }),
  output: Order,
  error: ApiError,
});
```

全项目统一直接调用导出的纯函数（`await getOrder(client, { id: 42 })` 或 `await getOrder(client({ signal }), { id: 42 })`），不仅写法干净一致，只要 `package.json` 配了 `"sideEffects": false`，打包器还能按接口粒度把没用到的定义 100% tree-shake 掉。

### 规范二：在 `schema/` 中同名导出 `struct` 与 `Infer`

在 `schema/*.ts` 里，用**同一个名字**同时导出运行时的 `struct` schema 和 `Infer<typeof ...>` 静态类型。TypeScript 会自动把同一作用域里的值声明和类型声明合并到一起，业务代码只需要 `import { Order }` 一次，运行时校验解析和类型标注就全有了：

```ts
import { struct, type Infer } from "@defjs/core";

export const Order = struct.object({
  id: struct.number(),
  customerName: struct.string().alias("customer_name"),
  totalCents: struct.number().alias("total_cents"),
});
export type Order = Infer<typeof Order>;
```

### 规范三：保持 `request/*.ts` 与 Client 实例解耦

哪怕只是在一个业务仓库里写[应用接口层](/zh-Hans/docs/application-api)（`src/api/`），也**不要**在 `src/api/request/*.ts` 里导入 `apiClient` 再二次封装。让 `request/*.ts` 保持纯粹的接口定义有三个实打实的好处：

1. **零 Mock 内存单测**：写单元测试时可以直接给任意接口传入 `createClient(withEndpoint(...), withHTTPHandle(...))`，不用靠 `vi.mock` 劫持模块或给全局打补丁。
2. **天然兼容 SSR 与多租户**：服务端渲染（SSR）或 BFF 接口可以在每次收到请求时，新建一个只带当前用户 Cookie/Token 的隔离 `Client`，和前端组件共用完全同一份接口定义。
3. **随时无痛抽成共享包**：以后需要把 `src/api/schema/` 和 `src/api/request/` 拆成 Monorepo 子包或对外公共 SDK 时，定义层一行代码都不用改。

### 规范四：严格区分 `builder` 参数映射与拦截器策略

把不同维度的逻辑放回各自该在的位置：

| 职责维度                                                        | 归属位置                                                  | 原因                                                                                       |
| :-------------------------------------------------------------- | :-------------------------------------------------------- | :----------------------------------------------------------------------------------------- |
| 把调用入参分配到 `path`、`query`、`headers`、`body`             | `request/*.ts` 中的 `builder`                             | 只依赖当前 `input` 的同步纯函数                                                            |
| 给拦截器透传的业务上下文（如 `{ operation: "orders.create" }`） | `request/*.ts` 中的 `meta` 字段                           | `{ [key: string]: unknown }`；只读且按定义共享；不会发到服务端；会作为 `defjs.meta.*` 上报 |
| 基地址、鉴权请求头（Bearer Token、签名、XSRF）、重试、负载均衡  | `client.ts` 中的 `createClient(...)`                      | 跟运行环境、会话状态绑定的通用执行策略                                                     |
| 单次调用超时、手动取消（`signal`）以及上传/下载进度回调         | 调用处的内联派生 `client({ signal, onDownloadProgress })` | 只影响这一次请求，不会污染共享 Client                                                      |
