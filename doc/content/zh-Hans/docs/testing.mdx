# 测试

由于 Defjs 将接口操作定义与 Client 执行完全解耦，你可以直接在本地单测中对真实的 SDK 定义及应用层拦截器进行离线测试，而无需启动真实的 HTTP 服务器，更无需侵入式 Mock 库的内部函数。

## 1. 注入本地传输句柄

在调用 `createClient(...)` 时，通过 `withHTTPHandle`、`withSSEHandle` 或 `withWebSocketHandle` 替换底层的平台原生网络传输。Defjs 依然会严格跑通整个操作的完整处理流水线：入参 `struct` 校验、`builder` 参数映射、URL 目录安全检查、中间件拦截器链、HTTP 状态码分流，以及最终的响应 `struct` 解码。

## 2. 测试最佳实践

### 断言错误优先元组，而非内部实现细节

始终使用测试专用的 Client 调用导出的 SDK 操作函数，并对返回的 `[error, data, response]` 元组进行严格断言：

- 对于 `2xx` 成功场景，断言 `expect(error).toBeNull()`，并检查解码后的 `data` 属性（包括 `.alias()` 从网络下划线到逻辑小驼峰的映射是否正确）。
- 对于异常失败场景，根据契约要求断言 `error?.code`、`error?.status`、`error?.data` 以及 `error?.cause`。

### 校验出站请求的原始网络字节

在你的 `withHTTPHandle(async (input, init) => ...)` 函数内部，构造 `const request = new Request(input, init)` 并审查 `request.url`、`request.method`、`request.headers` 以及 `await request.text()`（或 `await request.json()`），以此验证你的 `builder` 和 struct 别名是否精确序列化为后端接口所期望的网络格式。

### 使用虚拟时钟实现确定性的时间测试

拦截器重试退避、SSE/WebSocket 重连延迟或 WebSocket 心跳，在 Vitest 里用 `vi.useFakeTimers({ toFake: ["setTimeout", "clearTimeout", "Date"] })`。这些假定时钟不会推动原生的 `AbortSignal.timeout`。要在 Vitest 里得到确定的请求截止时间，请用受控的 `setTimeout` 以 `TimeoutError` 为原因中止一个 `AbortController`：

在 Bun test 里用 `jest.useFakeTimers()` 和 `jest.advanceTimersByTime()`；Bun 的假定时钟也会控制 `AbortSignal.timeout`。不要假定两种运行器控制同一套原生时钟。只在被等待的阶段已经开始之后再推进时钟，断言状态变化或尝试次数，而不是墙上时间，并在每个测试之后恢复真实时钟。
