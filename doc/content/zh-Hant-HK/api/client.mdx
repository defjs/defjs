# Client

`createClient(...)` 回傳一個 [`DerivableClient`](/zh-Hant-HK/api/core/derivableclient-type)。Client 選項由左至右組合，之後呼叫 `client(options?)` 取得 [`Client`](/zh-Hant-HK/api/core/client-type) 值，再傳俾操作：`getOrder(client(options), input)`。

## createClient()

<ApiSignature name="createClient" />

選項按次序套用。如果攔截器會捕獲 auth 或者 tenant 資料，建議喺 request boundary 入面建立 client。回傳嘅 factory 係一個函式。呼叫佢會回傳一個 `Client` 值，而且唔會做 I/O。factory 本身亦係一個 `Client`，唔帶任何 request options。

- **options** — 選項輔助函式，例如 `withEndpoint`。
- **Returns** 一個可呼叫嘅 factory。Base 設定由每個 client 值共用，runtime 唔會 freeze。佢按慣例固定：library 唔會改佢，應用程式亦唔應該改。

## 選項輔助函式

所有輔助函式都回傳 `ClientOption`。同一個設定，後面嗰次呼叫會取代前面嗰次，只有 `withInterceptors` 例外，佢會追加。

<ApiSignature name="withEndpoint" />

### withInterceptors()

<ApiSignature name="withInterceptors" />

### withQuerySerializer()

<ApiSignature name="withQuerySerializer" />

取代 HTTP、SSE 同 WebSocket 嘅 query 編碼。`serializer(query)` 收到嘅係**已經編碼嘅 wire object**（aliases 已套用，`Date` 係 ISO，`bigint` 係 string），一定要回傳 query string，而且唔可以有開頭嘅 `?`。request 冇 query 嘅時候唔會呼叫。builder 回傳 `URLSearchParams` 就會跳過佢。

### withHeaders()

<ApiSignature name="withHeaders" />

為 HTTP 同 SSE request 設定靜態預設 headers。WebSocket request 唔會用。`headers` 會喺選項套用嗰刻複製，所以之後改嗰個 object 唔會影響 client。第二次 `withHeaders` 會取代第一次，唔會合併。

單一 request 嘅優先次序：

1. 預設值係起始嘅 header 集合。
2. request builder 回傳嘅 `headers` 會取代同名嘅預設值。嗰個名嘅第一個值取代預設；同一個 array 入面之後嘅值只會追加落呢個取代結果。scalar 或者 `Headers` 實例亦會取代。其他預設名保留。
3. 攔截器收到合併後嘅 headers，可以修改。
4. 用 `@defjs/core/xsrf` 嘅話，XSRF header 最後先加，而且只喺仍然未有嘅時候先加（見 `withXSRF`）。

每個 request 都會變嘅值，例如刷新後嘅 Bearer token，或者對序列化 body 計算嘅 HMAC，請用攔截器。

冇 client 層級嘅預設 deadline。某次呼叫需要 deadline 時，喺派生 client 上傳 `signal: AbortSignal.timeout(ms)`。手動 abort 係 `NET_ABORTED`。`AbortSignal.timeout` 分類為 `NET_TIMEOUT`。

## 型別

### DerivableClient

<ApiSignature name="DerivableClient" />

`createClient` 回傳嘅根 client，有兩種形態。factory 係一個函式，同時亦係一個冇 request options 嘅 `Client`，所以 `getOrder(client, input)` 可以直接用。用 [`RequestOptions`](/zh-Hant-HK/api/core/requestoptions-type) 呼叫佢，會回傳一個只供單次呼叫用嘅普通 `Client` 值。嗰個值唔可以呼叫，所以 `client()()` 無法編譯，runtime 亦會 throw `TypeError`。派生只喺 factory 做一次，冇鏈式。寫型別時用 `DerivableClient`，唔好寫 `ReturnType<typeof createClient>`。

### Client

<ApiSignature name="Client" />

`Client` 係一個值，唔係函式。用 [`DerivableClient`](/zh-Hant-HK/api/core/derivableclient-type) 配 [`RequestOptions`](/zh-Hant-HK/api/core/requestoptions-type) 呼叫，就會得到一個。`client()` 同 `client(undefined)` 唔會保存 request options。`client({})` 保留一份空 snapshot。呢次呼叫每個頂層欄位只讀一次。`protocols` array 會被複製。`heartbeat` 同 `reconnect` 會複製各自嘅已知欄位。缺失嘅巢狀區塊仍然缺失。`signal`、`beforeConnect` 同 callback 保持原來嘅 identity。被捕獲欄位上面嘅 getter 喺呢次呼叫期間執行；如果 throw，異常會離開呢次呼叫。無效數字仍然會之後以 `REQ_OPTIONS_INVALID` 失敗。派生唔會做 I/O。Client 值唔可以呼叫，呼叫佢無法編譯，runtime 亦會 throw `TypeError`。每次呼叫建立一個 client 值。同一個值可以傳俾好多操作，但重用帶有 `signal` 嘅值會共用嗰個 signal。`signal` 唔會合併；喺應用程式程式碼用 `AbortSignal.any` 合併 signal。factory 嘅 base 設定仍然共用，亦唔會 freeze。標準 `with*` 輔助函式喺套用時複製佢哋擁有嘅固定 record。

唔好將 factory 傳俾 React state setter（`setState(factory)` 會將佢當 updater 嚟呼叫），亦唔好將佢做 Vue `watch` 或者 `computed` 嘅 source（嗰啲會呼叫函式）。

### RequestOptions

<ApiSignature name="RequestOptions" />

七個扁平欄位。每種協議只會讀自己明白嘅欄位，其餘忽略。將 `heartbeat` 傳俾 HTTP 會被忽略，唔係 fault。`client(options)` 喺呢次呼叫複製 `protocols` array，以及 `heartbeat` 同 `reconnect` 嘅已知欄位。缺失嘅巢狀區塊仍然缺失。`signal`、`beforeConnect` 同 callback 保持原來嘅 identity。SSE 只會由 request options 讀 `signal`。SSE 重連來自 client 設定（`withSSEReconnect`），所以 `client({ reconnect })` 只影響 WebSocket。冇 compile-time 嘅協議過濾，亦冇 `timeout` 或 `abort` 欄位。

| Field                | 協議                   | 取代方式                                                      |
| -------------------- | ---------------------- | ------------------------------------------------------------- |
| `signal`             | HTTP、SSE 同 WebSocket | 中止該次呼叫。SSE 同 WebSocket 覆蓋成條連線，包括 open 之後。 |
| `onUploadProgress`   | HTTP                   | 其他協議會忽略。                                              |
| `onDownloadProgress` | HTTP                   | 其他協議會忽略。                                              |
| `beforeConnect`      | WebSocket              | 喺該次呼叫取代 client 設定。                                  |
| `protocols`          | WebSocket              | 取代 client 嘅清單。                                          |
| `heartbeat`          | WebSocket              | 成個換走。`timeoutMs` 係等確認嘅時間，唔係請求 deadline。     |
| `reconnect`          | WebSocket              | 成個換走。                                                    |

[`HttpExecuteOptions`](/zh-Hant-HK/api/core/httpexecuteoptions-type) 係 HTTP 嗰部分（`signal` 加上 progress）。[`EventStreamExecuteOptions`](/zh-Hant-HK/api/core/eventstreamexecuteoptions-type) 係 `{ signal? }`。[`WebSocketExecuteOptions`](/zh-Hant-HK/api/core/websocketexecuteoptions-type) 係 WebSocket 嗰部分再加 `signal`。

### ClientSSEOptions

### ClientWebSocketOptions

<ApiSignature name="ClientSSEOptions, ClientWebSocketOptions" />

兩種傳輸層嘅重連都係 opt-in：冇 `withSSEReconnect` / `withWebSocketReconnect` 就唔會重試。一旦設咗 `reconnect`，就會套用以下預設值：

| 欄位         | SSE             | WebSocket       |
| ------------ | --------------- | --------------- |
| `attempts`   | 每次斷線 `3` 次 | 每次斷線 `3` 次 |
| `delayMs`    | `1000`          | `1000`          |
| `factor`     | `1`             | `2`             |
| `jitter`     | `0`             | `0`             |
| `maxDelayMs` | 冇上限          | `30000`         |

`connectTimeoutMs` 可選，而且必須係有限正數，並且唔可以大過 2147483647（timer 上限）；否則該操作回傳 `REQ_OPTIONS_INVALID`。對 SSE，佢限制由 Fetch 到 response headers；對 WebSocket，佢限制由建立連線到 `open`；handshake 之後會被清走。到期會向 balancer 報告 `NET_UNREACHABLE`，等重連可以 pick 下一個端點。重試用盡就以 `NET_TIMEOUT` 結束。佢只存在於重連選項入面；只要該物件存在，`attempts` 就預設係 `3`，所以淨係設定 `connectTimeoutMs` 都會啟用重連。只想限制 handshake 嘅話，請同時設定 `attempts: 0`。

兩種傳輸層每次成功握手，都會重設該次斷線嘅重試預算、callback 嘅嘗試次數同退避指數。`attempts: 0` 停用重試；省略 `attempts` 唔代表同一次斷線可以無限重試。`maxDelayMs` 限制套用 jitter 同四捨五入之後嘅最終延遲；平台 timer 上限 `2_147_483_647` ms 亦適用，包括 SSE 冇設定上限嘅情況。Base 係零就會維持零；有效數值運算溢位時，會限制喺上限。

重連選項會喺傳輸層執行之前驗證：`attempts` 必須係非負安全整數；`delayMs` 必須係有限非負數；`maxDelayMs` 必須係有限非負數或者正 `Infinity`，後者會移除設定上限，但最終等待仍然唔會超過 `2_147_483_647` ms；`factor` 必須係有限正數；`jitter` 必須係有限數，而且喺 0–1 之內。無效值會回傳 `REQ_OPTIONS_INVALID`。WebSocket `attempts: 0` 會停用之後嘅重試，但所有明確提供嘅重連欄位仍然會喺首次連線之前驗證，同 SSE 一樣。jitter 會向兩個方向縮放已設上限嘅 base，之後再套用最終上限。

對 SSE 嚟講，`delayMs` 只係起始嘅 base delay：server 傳嚟、只包含數字嘅 `retry:` 欄位會取代佢，用喺之後嘅嘗試，恢復連線之後亦一樣。`shouldReconnect` 回傳 `false` 就會停止重試。SSE 嘅 callback 另外會收到 `lastEventId`、request 嘅 `method` 同最新嘅 `open` 資料，亦可以係 async。冇呢個 callback 嘅時候，SSE 只會重連 `GET`、`HEAD`、`OPTIONS`、`PUT` 同 `DELETE` request；有呢個 callback 嘅話，每種 method 會唔會重連都由佢嘅結果決定。最新 event ID 會以 UTF-8 bytes 放喺 `Last-Event-ID` 送出；空 ID 會清除佢，包含 NUL 嘅 ID 會被忽略。WebSocket 嘅 callback 則會收到 close 嘅 `code`、`reason` 同 `wasClean`。

SSE 嘅 `onInvalidEvent` 處理冇對應 struct（包括冇 `default`）嘅 event（`missing-struct`），或者 data 通唔過 struct 驗證嘅 event（`validation-failed`）。呢類 event 一定會被丟棄；handler 嘅回傳值會被忽略，佢 throw 出嚟嘅 error 亦唔會關閉 stream。

對 WebSocket 嚟講，`beforeConnect`、`heartbeat`、`protocols` 同 `reconnect` 亦可以喺派生 client 上傳；每個都會喺該次呼叫成個取代 client 嘅值。`heartbeat.message` 建立每個 ping；省略或者回傳 `undefined` 就唔會傳送任何嘢。`heartbeat.timeoutMs` 等確認。佢唔係請求 deadline。

`pickFirstBalancer` 會喺 `NET_UNREACHABLE` 或 `NET_UNAVAILABLE`（HTTP 502、503 或 504）上前進；HTTP 重試永遠唔會移動佢黏住嘅端點，次序跟隨 `members`，即 client 嘅完整端點清單。可選嘅有限正數 `failbackMs` 喺呢段間隔之後，對第一個端點做至多一個同時進行嘅 probe；probe 喺對端 response 開始（`end`）時判定，未去到 `end` 嘅 probe 由 `done` 判定。HTTP 重試係用 `withRetry` 設定嘅另一份 client 策略。`roundRobinBalancer` 順住份清單行。`weights` 可選。睇[多個端點](/zh-Hant-HK/docs/client#multiple-endpoints)。

### p2cBalancer()

<ApiSignature name="p2cBalancer" />

唔放回咁抽樣唔同嘅候選端點（同 Envoy/gRPC A48 唔同），揀 tower 嘅 PeakEwma 或者 pending load。Linkerd 預設係 RTT 30 ms、decay 10 秒。pending 喺 `pick` 揀中端點時預留，`end` 喺 headers 或者 socket open 釋放佢，並對每種傳輸層記錄真實 RTT，包括 failure。冇 `end` 嘅 `done` 只釋放 pending，唔產生 RTT sample。冇 p2c failure classifier，亦冇 penalty。`choiceCount` 預設係 2，上限係 10。

### outlierDetection()

<ApiSignature name="outlierDetection, OutlierDetectionOptions" />

用 Linkerd 式嘅連續失敗熔斷包住 child。Round robin 同 p2c 預設開啟（同 Finagle 一樣）；`false` 關掉佢。Pick-first 要傳入 object 先至開啟。預設分類器將每個帶錯誤碼嘅結果都計為失敗，包括 `NET_TIMEOUT` 同 `NET_BODY_INCOMPLETE`。五次失敗之後，penalty 由 1000 ms 起，probe 失敗就加倍，並加上唔超過 base 0.5 倍嘅正 jitter，上限 60000 ms。到期接納一次 probe，喺 `end` 判定；如果冇 `end` 到達，就喺 `done` 判定。成功會重置 backoff；取消只釋放 slot。冇假定成功嘅 timeout、quota、last-host protection、settlement grid、percentage criterion 或者 slow start。`isHealthy` 讀應用程式自己持有嘅 cached state，永遠唔會取消 penalty。所有 host 都可以熔斷；Finagle 式、只限目前清單嘅 fail-open 仍然會送 request。同 Envoy/gRPC A50 唔同，冇 ejection quota。睇[健康過濾同 p2c](/zh-Hant-HK/docs/client#health-filtering-and-p2c)。

### withRetry()

<ApiSignature name="withRetry, RetryOptions, RetryContext, HttpRetryContext, SSERetryContext, WebSocketRetryContext" />

獨立於端點選擇，啟用同一次呼叫入面嘅 HTTP 重試。省略 `withRetry` 代表一次 attempt，亦冇預算。`withRetry()` 等同 `withRetry({})`，預設係 `maxAttempts: 2`（包括最初嗰次）、`on: ["connect-failure"]`，以及安全 method `GET`、`HEAD`、`OPTIONS`、`TRACE`。method 名唔分大小寫；`[]` 停用重試。`maxAttempts` 係至少為 1 嘅安全整數，而且每個端點最多試一次。`"gateway-error"` 包括 `NET_UNAVAILABLE`（HTTP 502/503/504），以及被 `RES_*` 解碼拒絕嘅 gateway body；`"attempt-timeout"` 用 `attemptTimeoutMs`。streaming request body 永遠唔會重試。

Backoff 預設係 `delayMs: 25`、`factor: 2`、`jitter: 0.2`、`maxDelayMs: 250`，欄位語義同 SSE/WebSocket 重連一樣。`delayMs: 0` 跳過等待。`attemptTimeoutMs` 必須係有限正數，並且唔可以大過 2147483647（timer 上限）；否則該操作回傳 `REQ_OPTIONS_INVALID`。佢會為每個發送去所選端點嘅 Fetch 計時，由發起直到讀完 response body；發送前後嘅攔截器工作同 struct 解碼唔會計時，亦唔會算落端點頭上。caller 嘅 signal 覆蓋成次呼叫，包括 backoff 等待。當某一輪重試用唔到任何端點（balancer 嘅 pick 失敗，或者下一個端點嘅 URL 解析唔到），該次呼叫會回傳上一次 attempt 嘅 fault，而唔係 `REQ_BUILD_FAILED`。

歸 client 所有嘅 Finagle 重試預算預設係 20%，再加 10 秒 TTL 上面每秒 10 次嘅 reserve。credit 同 debit 都喺十個 TTL/10 slice 上 lazy 過期。`budget: false` 拎走呢個限制。共享同一份配置嘅派生 client 共享佢嘅預算；各自獨立嘅 client 唔共享，即使共用一個 balancer 都係。無效選項喺 HTTP 執行時回傳 `REQ_OPTIONS_INVALID`，訊息係 `Invalid retry options`。呢個選項喺套用時捕獲自己擁有嘅欄位、array 同巢狀嘅預算。`withRetry()` 同 `withRetry(undefined)` 嘅行為同 `withRetry({})` 一樣。後一次 `withRetry` 會替換呢份策略；`withRetry({ maxAttempts: 1 })` 會喺啟用之後關閉重試。balancer 同 health wrapper 冇重試設定。睇[負載平衡與故障轉移](/zh-Hant-HK/docs/load-balancing)。

### Balancer

<ApiSignature name="Balancer, PickOutcome, PickInfo, PickResult, PickFaultCode, DoneInfo, ERR_NO_CANDIDATE, isNoCandidateCause" />

`pick` 回傳一個 error-first tuple。可選嘅 `start` 喺所選傳輸層開始之前至多同步執行一次；可選嘅 `end` 喺 `start` 之後執行一次，時機係對端 response 開始（或者 response 之前發生失敗）；可選嘅 `done` 喺完成時執行一次。Fetch 暴露唔到 Linkerd 嘅 first body frame，亦暴露唔到 Envoy 嘅 stream boundary。所有 hook 嘅 throw，同 thenable 嘅 rejection，都會被接住。揀咗候選以外嘅值會以 `REQ_BUILD_FAILED` 失敗，而佢嘅 `done` 會以 `{ attempted: false }` 呼叫。`ERR_NO_CANDIDATE` 只係 `REQ_BUILD_FAILED` 嘅 `cause`。佢唔係 `FaultCode`。[`isNoCandidateCause`](/zh-Hant-HK/api/core/isnocandidatecause) 亦可以識別另一份 Core 副本入面嘅佢。

balancer 只見到中立結果；每種傳輸層會將自己嘅事實翻譯成 `DoneInfo.code`。預設嘅 outlier detection 將每個帶 code 嘅結果都計為失敗，包括 `NET_TIMEOUT` 同 `NET_BODY_INCOMPLETE`。原始嘅 `DoneInfo.status` 只留給自訂 balancer，內建策略從不讀取佢。`PickInfo` 包含單次 pick 嘅候選 `endpoints`、`members`（client 嘅完整端點清單，每次嘗試都一樣）同可選嘅 `operation`，冇 transport 判別欄位。
