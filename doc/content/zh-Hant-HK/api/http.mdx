# HTTP

Declare 一個 typed request，用 input build command，之後 execute。

## defineRequest()

```ts
function defineRequest(definition: RequestDefinition): RequestEndpoint
```

- **definition** — `method`、`path`，可選 `input` struct、`output` 同 `error` structs，以及 `operation`。只要聲明咗 `input`，就必須明確提供 `builder`，即使 input 已經係 request shape 都一樣。只有冇 `input` 嘅定義先可以省略 `builder`。
- **Returns** 一個 endpoint。用 input call 佢，就會得到 `HttpCommand`。

`output` 係 2xx body 嘅單一 struct；`error` 係每個非 2xx body 嘅單一 struct。兩者都唔會按 status code 分 key。唔寫邊個，嗰個 body 就根本唔會被讀——睇
[聲明即斷言](/zh-Hant-HK/docs/design-decisions#聲明即斷言)。

## executeHttpCommand()

```ts
function executeHttpCommand(clientConfig: ClientConfig, command: HttpCommand, options?: HttpExecuteOptions): Promise<HttpAwaitResult>
```

Low-level entry，`client.execute` 用呢個。Application code 應該 call `client.execute(command, options)`。

- **Returns** `[null, data, response]` 或 `[fault, undefined, undefined]`。

非 2xx status 喺冇聲明 `error` struct，或者已聲明嘅 `error` body 解碼成功嘅時候，就係 `HTTP_STATUS`。聲明過 `error` 嘅時候佢個 `data` 係解碼之後嘅 error body，否則就係 `undefined`。如果已聲明嘅 `error` body 讀唔到（media type 錯、JSON 無效），或者同佢嘅 struct 唔匹配，fault 就會改為 `RES_MEDIA_TYPE_INVALID`、`RES_DECODE_FAILED` 或 `RES_STRUCT_MISMATCH`，而 response status 仍然會記喺 metadata 入面。失敗時 tuple 第三項係 `undefined`；response metadata 由 fault 帶住。

## fetchHandler()

```ts
function fetchHandler(httpRequest: HttpRequest, fetchImpl?: FetchHandle): Promise<HttpResponse<unknown>>
```

Default HTTP transport。`fetchImpl` 預設係全域 `fetch`；`withHTTPHandle` 可以提供另一個。冇 response 到達 client，或者讀取已聲明嘅 body 失敗嘅時候，佢會 reject，而唔係 resolve 一個合成 response。

## makeResponse()

```ts
function makeResponse<R>(options?: MakeResponseOptions<R>): HttpResponse<R>
```

唔打 network 都 build 到 `HttpResponse`（interceptors、tests）。Default status 係 `0`。2xx 嘅時候 `ok` 係 true。佢回嘅值會走同線上 response 一模一樣嘅 media-type 檢查同聲明 struct；唔存在受信任嘅短路。

## HttpExecuteOptions

```ts
type HttpExecuteOptions = {
  onDownloadProgress?: HttpProgressFn
  onUploadProgress?: HttpProgressFn
} & ({ abort?: AbortSignal; timeout?: never } | { abort?: never; timeout?: number }) & { signal?: AbortSignal }
```

Cancellation 係 `abort` **或者** `timeout`，唔可以兩個一齊：type 會拒絕兩者並存，runtime 時兩者都傳會以 `REQ_OPTIONS_INVALID` 失敗。`signal` 可以同其中一個一齊用，**唔係** `abort` 嘅 alias。合法形狀：`{ timeout }`、`{ abort }`、`{ signal, timeout }`、`{ signal, abort }`。`{ abort, timeout }` 唔得。`timeout` 一定要係 `1..2_147_483_647` 入面嘅 positive safe integer。某次 call 冇寫 `timeout` 嘅時候，會套用 client 嘅 `withTimeout` 預設值（只限 HTTP）；`abort` 同 `signal` 會同嗰個預設值合併。

## 類型

### RequestDefinition

`method`、`path`，可選 `input`、`output`、`error`、`operation` 同 `builder`。冇 `responseType`：struct kind 決定一個已聲明 body 點讀。只要聲明咗 `input`，就必須明確提供 `builder`，即使 input 已經係 request shape 都一樣。只有冇 `input` 嘅定義先可以省略 `builder`。

### HttpAwaitResult

```ts
type HttpAwaitResult<TData = undefined, TErrorData = undefined> =
  | [error: null, result: TData, response: [TData] extends [undefined] ? HttpMeta : DecodedResponse<TData>]
  | [error: FaultOf<TErrorData>, result: undefined, response: undefined]
```

成功時第三項只有聲明過 `output` 才會帶 `body`。失敗時佢係 `undefined`——fault 已經揸住當時存在嘅 response metadata。

### HttpRequest

Normalized outgoing request：`method`、`endpoint`、`headers`、`body`、`abort`、`operation`、`timeout`、`withCredentials`、`xsrf`、`downloadProgress` / `uploadProgress`、`baseEndpoint`、`queryString` 同 `queryParams`。Interceptors 見到佢嗰陣，`body` 已經係 wire value——JSON 嘅話就係 JSON 文字字串——所以簽 HMAC 同 digest 要對住嗰個，唔好對住 struct input。Interceptors 見到嘅 `queryParams` 係 `new URLSearchParams(queryString)`。Builder return `URLSearchParams` 就會將嗰個 instance 直接傳落去。`responseType` 同 `errorResponseType` 係唯讀：佢哋由端點嘅 `output` 同 `error` struct kind 推導出嚟，唔可以改。

### HttpMeta

```ts
type HttpMeta = {
  readonly headers: Headers
  readonly ok: boolean
  readonly status: number
  readonly statusText: string
  readonly url: string
}
```

Response metadata，只要有 response 到達 client 就有。佢**唔會**帶 `body`：body 要等聲明過嘅 struct 解出嚟之後才存在。

### DecodedResponse

```ts
type DecodedResponse<TBody> = HttpMeta & { readonly body: TBody }
```

Body 已經按聲明嘅 struct 解碼成功嘅 response。拿到呢個 type 就係解碼真係發生過嘅證明——呢個亦正係解碼失敗時只報 `HttpMeta` 嘅原因。

### HttpResponse

```ts
type HttpResponse<R> = {
  readonly url: string
  readonly status: number
  readonly statusText: string
  readonly headers: Headers
  readonly body: R | null | undefined
  readonly ok: boolean
}
```

Response 冇 body 嘅時候，`body` 係 `undefined`；JSON `null` 就保持係 `null`。呢個 type 帶 brand，所以要用 `makeResponse` 建立，唔好用 object literal。Transport 產出、interceptor 見到嘅線上形狀：`body` 係文字或者已經 parse 咗嘅 JSON，唔係解碼之後嘅值。對於 JSON 表示，字串係 JSON 字串根，唔會再 parse 一次；bytes 同 blob 仍然係原始資料，只會 parse 一次。到達 caller 嘅係 `DecodedResponse`。

### HttpProgressEvent

### HttpProgressFn

`loaded`、`total`、`lengthComputable`。Callbacks 可以係 async。如果 `onDownloadProgress` 或者 `onUploadProgress` 拋出錯誤，該次 call 就會以 `EXT_OBSERVER_FAILED` 失敗，並以拋出嘅值作為 `cause`；取消操作同 `timeout` 仍然會報 `NET_ABORTED` / `NET_TIMEOUT`。只有 runtime 支援以 stream 方式送出 request body，先會回報 upload progress（Bun、Node、Deno）；喺 browser，`Blob` / `File`、`ArrayBuffer` 同 `FormData` body 會原樣送出，而且唔會 call `onUploadProgress`。

睇 [HTTP guide](/zh-Hant-HK/docs/http) 同 [Commands](/zh-Hant-HK/docs/commands)。

## RequestEndpoint

`defineRequest` 嘅回傳。用 input call 一次就攞到 `HttpCommand`。

## BuilderInput

`builder` 見到嘅、已經 parse 嘅 endpoint input。Object nodes 帶住產生佢哋嘅 struct，所以 alias、`Date` 同 `bigint` encoding 跟住個 value 走。

## HttpRequestShape

```ts
type HttpRequestShape<P extends string, M extends string> = {
  path?: PathValue<P>
  query?: URLSearchParams | QueryRecord
  headers?: HeadersInit | FlatRecord
  body?: Uppercase<M> extends 'GET' | 'HEAD' ? never : unknown
}
```

`GET` 同 `HEAD` 唔可以 return body。`path` 同 `headers` 一定要係 flat scalars；`query` 可以 nest，nested object 喺 runtime 要有 `withQuerySerializer`。

## HttpCommand

Request builder 吐出嚟嘅 opaque command。交畀 `client.execute`。

## UseRequestConfig

Progress 同 cancellation fields。`HttpExecuteOptions` 再加 `signal`。

## RequestSuccessData

由聲明嘅 `output` struct 推出嚟嘅成功 body；冇聲明就係 `undefined`。

## RequestErrorData

由聲明嘅 `error` struct 推出嚟嘅錯誤 body；冇聲明就係 `undefined`。

## HttpResponseType

`'arraybuffer' | 'blob' | 'json' | 'text'`

由聲明嘅 struct kind 揀出嚟（`string` → `text`，`blob` / `file` → `blob`，`arrayBuffer` → `arraybuffer`，其他 → `json`）。唔係 `defineRequest` 上面嘅 field。

## MakeResponseOptions

`makeResponse` 用嘅 fields：`status`、`statusText`、`url`、`headers`、`body`、`request`。
