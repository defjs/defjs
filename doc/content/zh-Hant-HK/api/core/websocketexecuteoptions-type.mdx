title: 'WebSocketExecuteOptions'
description: '執行 WebSocket command 時，每次 call 嘅 options。'
---

<ApiReference identity="@defjs/core:WebSocketExecuteOptions" />

```ts
type WebSocketExecuteOptions<TIncoming = unknown, TOutgoing = unknown> = UseWebSocketConfig<TIncoming, TOutgoing> & {
  signal?: AbortSignal
}
```

即係 [`UseWebSocketConfig`](/zh-Hant-HK/api/core/usewebsocketconfig-type) 加上 `signal`。展開之後：

```ts
type WebSocketExecuteOptions<TIncoming = unknown, TOutgoing = unknown> = {
  beforeConnect?: (context: { attempt: number; signal: AbortSignal }) => void | Promise<void>
  heartbeat?: WebSocketHeartbeatConfig<TIncoming, TOutgoing>
  protocols?: readonly string[]
  reconnect?: ClientWebSocketOptions['reconnect']
  signal?: AbortSignal
} & ({ abort?: AbortSignal; timeout?: never } | { abort?: never; timeout?: number })
```

- `abort` 同 `timeout` 互斥。Type 會拒絕兩者並存；runtime 時如果兩者都傳，會失敗並返回 `REQ_OPTIONS_INVALID` fault。
- `signal` 可以同兩者任何一個合併使用；佢唔係 `abort` 嘅別名。
- `timeout` 必須係正安全整數，而且唔可以大過 `2_147_483_647`。佢限制開啟 session 最多可以用幾耐，reconnect 時唔會再套用。
- `beforeConnect`、`heartbeat`、`protocols` 同 `reconnect` 會喺今次 call 覆蓋 client 層級嘅 options。
- 設定 `reconnect` 時，`attempts` 預設係 `3`；`0` 就停用。唔寫 `attempts` 唔代表無限。

參閱 [`WebSocketHeartbeatConfig`](/zh-Hant-HK/api/core/websocketheartbeatconfig-type)。
