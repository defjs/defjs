<ApiReference identity="@defjs/core:ClientSSEOptions" />

```ts
interface ClientSSEOptions {
  handle?: FetchHandle
  onInvalidEvent?: (context: {
    reason: 'missing-struct' | 'validation-failed'
    message: { id: string; event: string; data: string }
    cause?: unknown
    signal: AbortSignal
  }) => unknown
  reconnect?: {
    attempts?: number
    delayMs?: number
    factor?: number
    jitter?: number
    maxDelayMs?: number
    shouldReconnect?: (context: {
      attempt: number
      cause?: unknown
      lastEventId: string
      method: string
      open?: { response: { status: number; statusText: string; url: string }; url: string }
    }) => boolean | Promise<boolean>
  }
}
```

- **handle** — 開啟 stream 嘅 Fetch implementation。預設 handle 每次嘗試都會解析 `globalThis.fetch`，包括 import 之後安裝嘅替代實作。每個 SSE handle 都會收到 `Request`。缺少 global Fetch 時，預設執行會以 `ENV_UNSUPPORTED` 失敗；自訂 handle 仍然可用。
- **onInvalidEvent** — Event 冇對應 struct 又冇 `default` struct（`'missing-struct'`），或者 data 驗證失敗（`'validation-failed'`）時會 call。該 event 會被跳過。Hook throw 咗 error 並唔會令 stream 關閉。
- **reconnect** — Opt-in。唔設定嘅話，stream 永遠唔會重連。`attempts` 預設係每次斷線 **3** 次；`attempts: 0` 停用重試。成功握手會重設預算、callback 嘅 `attempt` 同退避指數。`delayMs` 係第一次嘅 base delay，預設 1000，server 發送嘅 `retry:` 值會取代佢。`factor` 預設係 1。`jitter` 係 0–1 嘅乘數，預設係 0。`maxDelayMs` 限制套用 jitter 同四捨五入之後嘅最終延遲；冇設定上限時，平台上限 `2_147_483_647` ms 仍然適用。Base 係零就會維持零；有效數值運算溢位時，會限制喺上限。冇 `shouldReconnect` 嘅時候，只有 `GET`、`HEAD`、`OPTIONS`、`PUT` 同 `DELETE` 會重連；有佢嘅話，每種 method 會唔會重連都由佢嘅結果決定，佢嘅 context 亦會帶住 `method`。用 `ReadableStream` 做 request body 嘅 request 永遠唔會重連。重連會將最新 ID 以 UTF-8 bytes 放喺 `Last-Event-ID` 送出；空 ID 會清除佢，包含 NUL 嘅 ID 會被忽略。

重連選項會喺 interceptors 或 Fetch 執行之前驗證：`attempts` 係非負安全整數；`delayMs` 同明確設定嘅 `maxDelayMs` 係有限非負數；`factor` 係有限正數；`jitter` 係有限數，而且喺 0–1 之內。無效值會喺 execute 時回傳 `REQ_OPTIONS_INVALID`。

用 `withSSEHandle`、`withSSEOnInvalidEvent` 同 `withSSEReconnect` 設定呢啲選項。唔用 `withSSEReconnect` 就等於停用 retry。
