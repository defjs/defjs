```ts
function createResolvedRequestUrl(baseEndpoint: string, path: string, queryString?: string): URL
```

- **baseEndpoint** — 有效嘅絕對 client endpoint。佢嘅 query 同 hash 會被丟棄，pathname 會補上尾部 slash，令 base path 得以保留：`https://api.example.com/v1` 配 `/users` 得出 `https://api.example.com/v1/users`。
- **path** — 相對 endpoint path。開頭單一個 slash 會被移除。解析後嘅 URL 必須保持 base origin，並留喺佢嘅目錄之下。絕對或 protocol-relative paths、C0 控制字元（包括 tab、CR 同 LF）、反斜線、`?`、`#`，以及逃出目錄嘅路徑都會被拒絕。形似 scheme 同 protocol-relative 嘅形式，就算前面有空格都會被拒絕；路徑入面嘅普通空格允許，並會以 `%20` 送出。
- **queryString** — 冇開頭 `?` 嘅 query。非空時會原樣設為 URL 嘅 search。
- **Returns** 解析後嘅 `URL`。

Base endpoint 或 path 無效時會 throw `TypeError`。執行 `client.execute` 時，缺少、相對或無效嘅 base，以及非法 path，都會喺任何 interceptor 或 transport 執行之前變成 `REQ_BUILD_FAILED`，包括會 short-circuit 嘅 interceptor；HTTP、SSE 同 WebSocket 都一樣。Interceptor 最終嘅 `req.endpoint` 亦會按最終嘅 `req.baseEndpoint` 驗證；容許刻意將 base 換成另一個有效嘅絕對 URL。確定嘅 URL 錯誤永遠唔會重試。
