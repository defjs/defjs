# Errors

Execute 會將一個可判別嘅 `Fault` 放喺 tuple 第一項——聲明過嘅失敗唔會拋 exception。

## FaultCode

<ApiSignature name="FaultCode" />

一個封閉集合。第一個 `_` 之前嗰段就係類別；冇獨立嘅 `kind` field。集合保持封閉，`switch (fault.code)` 才可以窮盡——extension 報自己嘅細節走 `cause`，唔係加新 code。

## FaultClass

<ApiSignature name="FaultClass" />

`FaultClass<FaultCode>` 係 `'CAP' | 'ENV' | 'EXT' | 'HTTP' | 'NET' | 'REQ' | 'RES'`。

## Fault

<ApiSignature name="Fault" />

對 `fault.code` 做 switch。

### FaultOf

<ApiSignature name="FaultOf, Fault" />

`FaultOf` 係用解碼後嘅 error-body type（而唔係產生佢嘅 struct）嚟表達嘅 `Fault`。`HttpAwaitResult` 同各個 fault factories 都係以解碼後嘅值運作，所以用呢個形式。

每個變體都係名為 `DefjsFault` 嘅原生 `Error`，所以 `String(fault)` 俾出 `DefjsFault: <message>`。`code` 同各變體 metadata——`status`、`response`、`data`——都係可枚舉嘅自有屬性。原生 `cause` chain 唔可枚舉。

預設 Struct 訊息會寫 `received <kind>`，永遠唔會包含收到嘅值，例如 `Expected number at email, received string`。`RES_DECODE_FAILED` 背後嘅 JSON `SyntaxError` 會產生 `Response body could not be decoded` 訊息。Issue path 係結構性嘅，會保留 record 嘅 key：`struct.record(...)` 可以產生 `Expected number at alice@example.com, received string`，所以 key 喺預設訊息、`prettify()` 同 `String(fault)` 入面仍然可能敏感。原始 `StructIssue.received` 同 parser causes 仍然可能包含敏感資料；自訂 `errorMap` 同 extension 訊息會原樣使用，寫 log 前需要檢查。

一定要先將 `fault.cause` 窄化到 `StructError`，之後才可以 call `format()`、`flatten()` 或者 `prettify()`；呢啲 helper 唔會被複製到 fault 上面。

### HttpStatusFault

<ApiSignature name="HttpStatusFaultOf, HttpStatusFault" />

任何非 2xx status。Endpoint 聲明過 `error` 而 body 又解碼成功嘅時候，`data` 就係嗰個 body，`response` 亦帶住佢。冇寫 `error` 嘅時候 body 根本唔會被讀，於是 `data` 係 `undefined`，`response` 只有 metadata。

### DecodeFault

<ApiSignature name="DecodeFaultCode, DecodeFault" />

Response 到咗，但冇辦法按聲明讀出嚟。`response` 只有 metadata：body 就係解碼之後嘅值，而解碼本身失敗咗，所以冇 `body` field 可以拿。出錯細節喺 `cause` 上面——struct 唔匹配就係 `StructError`，representation 讀唔出就係 parser 嘅失敗。

### PreflightFault

<ApiSignature name="PreflightFaultCode, PreflightFault" />

所有可能喺 response 存在之前就失敗嘅情況：`REQ_*`、`NET_*`、`EXT_*`、`CAP_*`、`ENV_UNSUPPORTED`。只有 transport 當時真係有 metadata 可以報嘅時候才帶 `response`，例如下載中途截斷咗嘅 body。

### AnyFault

<ApiSignature name="AnyFault" />

任何 fault，唔理佢解碼後嘅 error body 係咩 type。寫嗰啲只做分類、唔理係邊個 endpoint 產出嘅 handler 就用佢；body type 緊要嘅地方優先用 `Fault<typeof yourErrorStruct>`。

## createPreflightFault()

<ApiSignature name="createHttpStatusFault, createUndecodedHttpStatusFault, createDecodeFault, createNetworkFault, createPreflightFault" />

`createHttpStatusFault` 收一個已經帶住解碼後 body 嘅 response；`createUndecodedHttpStatusFault` 只收 metadata，俾嗰啲冇聲明 `error` 嘅 endpoint 用。

`createNetworkFault` 用 [`isAbortCause`](/zh-Hant-HK/api/core/isabortcause) 揀 `NET_ABORTED`，用 [`isTimeoutCause`](/zh-Hant-HK/api/core/istimeoutcause) 揀 `NET_TIMEOUT`：兩者會識別任何 Core 副本帶 brand 嘅 sentinel，前者亦識別名為 `AbortError` 嘅 `DOMException`，後者亦識別名為 `TimeoutError` 嘅 `DOMException` 或 `Error`。其餘一律映射去 `NET_UNREACHABLE`。`createPreflightFault` 直接收 code；唔俾 `cause` 嘅時候，code 就變成 message。

所有工廠都 return 帶住上述結構化 field 嘅原生 `Error` instance；佢哋唔會造普通 object error，`String(fault)` 亦唔需要 adapter。

## 哨兵

## ERR_ABORTED

## ERR_TIMEOUT

<ApiSignature name="ERR_ABORTED, ERR_TIMEOUT" />

Abort 同 timeout 共享嘅 `Error` sentinel，用作 `cause`。喺 HTTP interceptor 入面 throw 其中一個，該次 call 就會 resolve 成 `NET_ABORTED` 或者 `NET_TIMEOUT`。SSE 同 WebSocket interceptors 會將任何 throw（包括呢兩個）都回報為 `EXT_INTERCEPTOR_FAILED`。

Sentinels 帶有不可枚舉嘅 `Symbol.for('defjs.cause.aborted')` 同 `Symbol.for('defjs.cause.timeout')` brands。分類唔依賴 sentinel 嘅 object identity，亦唔受之前無關嘅執行影響。

## Cause 檢查

<ApiSignature name="isAbortCause, isTimeoutCause" />

[`isAbortCause`](/zh-Hant-HK/api/core/isabortcause) 識別帶 abort brand 嘅 `Error`，或者名為 `AbortError` 嘅 `DOMException`。[`isTimeoutCause`](/zh-Hant-HK/api/core/istimeoutcause) 識別帶 timeout brand 嘅 `Error`，或者名為 `TimeoutError` 嘅 `DOMException` / `Error`。請傳入 `fault.cause` 去分類底層值；呢啲函數唔會解開 fault。佢哋亦適用於另一份 Core 嘅 sentinels。
