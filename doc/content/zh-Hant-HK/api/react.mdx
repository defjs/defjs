# React

將現有嘅 `@defjs/core` client 提供俾 React 元件樹。呢個 package 唔會建立、快取或者銷毀 client。佢嘅入口標記咗 `'use client'`，所以要喺 client component 入面 import。需要 React 18 或以上。

見 [React 指南](/zh-Hant-HK/docs/integrations/react)。

## ClientProvider

<ApiSignature name="ClientProvider" />

Context provider。傳入 `createClient` 回傳嘅 `DerivableClient`。巢狀嘅 `ClientProvider` 會喺自己嘅子樹覆蓋 client；`useClient()` 讀取最近嗰個。傳入唔同嘅 `client`，會改變後代元件讀到嘅 context 值。

## useClient()

<ApiSignature name="useClient" />

`useClient(overrideClient)` 優先回傳明確傳入嘅 client；省略參數或者傳入 `undefined` 就讀最近嘅 `ClientProvider`。兩個來源都冇 client 先會 throw `Error`，原本嘅零參數 `useClient()` 呼叫仍然有效。將嗰個 client 傳入操作。Hook 回傳嘅就係提供入去嗰個 [`DerivableClient`](/zh-Hant-HK/api/core/derivableclient-type)；喺操作執行嗰度用 request options 呼叫佢，就會派生一個 `Client` 值。唔好傳俾 state setter，因為 `setState(client)` 會將佢當 updater 嚟呼叫。派生出嚟嘅 `Client` 值唔會被 `ClientProvider` 或者 `useClient` 接受。

無論有冇明確傳入 client，都要喺元件或者自訂 Hook 頂層呼叫 `useClient(explicitClient)`，唔可以喺普通函式或者 event callback 入面呼叫。唔好寫 `explicitClient ?? useClient()`，因為佢會有條件咁呼叫 Hook。明確值唔會寫入 Context，亦唔會建立 provider；Hook 仍然會訂閱 Context。

- **Returns** 明確傳入或者最近 provider 提供嘅同一個 client。
- **Throws** 明確參數同 Context 都冇提供 client 時會 throw `Error`。

## ClientProviderProps

<ApiSignature name="ClientProviderProps" />

`client` 必填，由應用程式擁有。`children` 可選：佢係可以呼叫 `useClient` 嘅元件樹。
