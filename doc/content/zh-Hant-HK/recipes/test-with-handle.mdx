### 寫測試時要留意嘅三個細節

- **點解要包一層 `new Request(input, init)`**：`withHTTPHandle` 收到嘅參數同標準 `fetch(input, init)` 一樣，用 `new Request(input, init)` 包好之後，就可以一致咁讀取 `method`、`url`、`headers` 同 `await request.json()`。
- **點解要填 `withEndpoint("https://fixture.invalid")`**：`Client` 喺入到 `withHTTPHandle` 前會先解析同檢查基礎 URL；`.invalid` 係 RFC 保留網域，唔會意外打去真實 DNS。
- **三種常見回傳點樣造**：
  - `2xx` 成功：返 `Response.json(...)` -> 得到 `[null, data, response]`。
  - `4xx` / `5xx` 錯誤狀態：返 `Response.json(..., { status: 422 })` -> 得到 `err.code === "HTTP_STATUS"`。
  - 斷網／連線失敗：直接 `Promise.reject(new TypeError("fetch failed"))`（或直接拋錯）-> 得到 `err.code === "NET_UNREACHABLE"`。**千祈唔好**返 `Response.error()`，只要返咗 `Response`（就算狀態碼係 `0`），Defjs 都會當成收到 HTTP 回應而出 `HTTP_STATUS`。

上線只要移除 `withHTTPHandle(...)`、保留設定咗真實 API 位址嘅 `withEndpoint(...)`，同一份 `getOrder` 操作程式碼一啲都唔使改。想睇業務函式、重試／Token 刷新攔截器同元件測試，請睇 [測試](/zh-Hant-HK/docs/testing) 同 [Client](/zh-Hant-HK/docs/client)。
