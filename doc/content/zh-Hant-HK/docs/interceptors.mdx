# 中介層（Interceptors）

中介層可以將橫切關注點（cross-cutting execution policies）——例如認證 headers、請求簽名、維護模式快速阻斷（short-circuiting），或者安全讀取嘅重試機制——掛載到應用程式嘅 `Client`，完全唔使改動 SDK 嘅操作定義。

呼叫流程中，Input 驗證同 `builder` 映射會喺中介層鏈**之前**執行；而 HTTP 狀態碼分發以及 `output` / `error` struct 驗證則會喺中介層鏈**之後**執行。

### 中介層管線規則

- **洋蔥模型順序**：中介層喺傳出請求時會按註冊順序執行（`before next(req)`）；喺回應返回時則會按相反順序執行（`after await next(req)`）。請將廣泛嘅日誌／追蹤中介層放喺最外層，而將較具體嘅認證或重試中介層放喺內層。
- **不可變 Request 慣例**：記得一定要複製 `req.headers`（`new Headers(req.headers)`），並將全新嘅 request 物件（`{ ...req, headers }`）傳畀 `next(...)`，等外層嘅重試邏輯可以見到乾淨嘅原始 headers。
- **`content-type` 與 `bodyContentType`**：Defjs 會將推斷出嚟嘅 body content type 存喺 `req.bodyContentType`，唔會直接修改 `req.headers`。請求簽名邏輯應讀取 `req.headers.get("content-type") ?? req.bodyContentType`。如果中介層將 `req.body` 替換成全新格式，請明確設定 `content-type` header。

## 3. 重試安全嘅 HTTP 讀取

Defjs 唔會自動重試業務 HTTP 狀態碼。當你需要針對特定狀態碼進行重試（例如喺冪等嘅 `GET` / `HEAD` / `OPTIONS` 呼叫上遇到 `429`、`502`、`503`、`504`），可以在 HTTP 中介層入面實作有次數限制嘅重試迴圈：

<include cwd lang="typescript">
  examples/interceptors/retry-safe-reads.ts#example
</include>

- **處理傳輸層 Reject**：當發生網絡錯誤時，`next(request)` 會直接 reject（絕唔存在狀態碼為 0 嘅 response 物件）。Catch 之後再重新 throw 該 rejection，可以完整保留原始嘅 `NET_*` fault code。
- **喺中介層入面拋出例外**：未處理嘅 throw（或回傳非 response 值）會令操作 tuple 以 `EXT_INTERCEPTOR_FAILED` 失敗，並將原因記錄喺 `fault.cause`。若拋出 `ERR_ABORTED` 或 `ERR_TIMEOUT`，則會分別結算為 `NET_ABORTED` 或 `NET_TIMEOUT`。

## 4. 包裝 WebSocket 會話

WebSocket 中介層**最多只可以呼叫 `next(req)` 一次**。當包裝回傳嘅 `WebSocketSessionLike` 時，請務必代理即時嘅 getter（`state`、`connection`、`bufferedAmount`）、`close`、`closed`、`receive` 同埋 `[Symbol.asyncDispose]()`，而唔好貪方便用物件展開（spread）走去複製一次性嘅快照：

## 5. 內建工廠函式與輔助工具

| 匯出名稱                                       | 傳輸協議  | 描述                                                      |
| ---------------------------------------------- | --------- | --------------------------------------------------------- |
| `createHttpInterceptor(fn)`                    | HTTP      | 包裝 `(req, next) => Promise<HttpResponse<unknown>>`      |
| `createSSEInterceptor(fn)`                     | SSE       | 包裝 `(req, next) => Promise<EventStreamHandle<unknown>>` |
| `createWebSocketInterceptor(fn)`               | WebSocket | 包裝 `(req, next) => Promise<WebSocketSessionLike>`       |
| `basicAuthHttpInterceptor(provider, options?)` | HTTP      | 從同步／非同步憑證提供者注入 `Authorization: Basic ...`   |
| `basicAuthSSEInterceptor(provider, options?)`  | SSE       | 喺 SSE 握手請求中注入 `Authorization: Basic ...`          |
