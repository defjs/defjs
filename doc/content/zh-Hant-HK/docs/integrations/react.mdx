# React

`@defjs/react` 透過 React Context 同 `useClient()`，將應用程式自設嘅 `@defjs/core` client 接駁到 React 18+ 元件樹入面。你嘅 SDK 定義依然保持純粹嘅 `@defjs/core` 模組，完全零 React 依賴。

```sh
bun add @defjs/core @defjs/react react
```

## `@defjs/react` 負責乜嘢 vs. 你負責乜嘢

- **`@defjs/react` 提供**：`ClientProvider` 與 `useClient(overrideClient?)`。
- **由你嘅應用程式負責**：建立 [`DerivableClient`](/zh-Hant-HK/api/core/derivableclient-type)、喺元件卸載或者依賴項改變時取消進行中嘅請求（`AbortController`）、關閉 SSE/WebSocket handle，以及整合 TanStack Query 等非同步狀態快取庫。
- **重要提醒**：`useClient()` 回傳嘅係一個可呼叫嘅 `DerivableClient` 函式物件。請喺呼叫具體操作嘅地方使用 `client({ signal })`（例如 `getOrder(client({ signal }), input)`）。切忌直接將 `client` 傳入 `setState(client)`，因為 React 會將傳入 state setter 嘅函式當成 updater 執行。

## 2. 用 `useClient` 讀取與覆寫

`useClient(overrideClient)` 喺傳入 `overrideClient` 時會直接回傳佢；省略或為 `undefined` 時則會讀取距離最近嘅 `ClientProvider`。只有喺兩者都冇提供 client 嗰陣先會拋出 `Error`。

<include cwd>examples/react/read-with-use-client.tsx#example</include>

- 請務必喺元件或自訂 Hook 嘅最頂層無條件呼叫 `useClient(explicitClient)`。切勿寫成 `explicitClient ?? useClient()`，否則會違反 React Hook 嘅使用規則。

## 4. 喺 effect 入面管理 SSE 與 WebSocket 生命週期

SSE 同 WebSocket handle 嘅生命週期遠長於最初嗰次 `openStream(...)` 或 `connectChat(...)` 呼叫。請喺 await 啟動之前註冊好清理邏輯、關閉喺卸載之後先 resolve 出嚟嘅 handle、消費佢唯一嘅 async iterator，並等待 `.closed`：

<include cwd>examples/react/own-realtime-work.tsx#example</include>

- 中斷傳入 WebSocket 操作嘅 `signal` 會將會話狀態置為 `aborted`，並以 `AbortError` reject `session.receive`。喺元件已清理嘅情況下，請喺 `catch` 區塊加以保護，確保淨係向上拋出真正嘅執行時嚴重錯誤（例如佇列溢出或心跳逾時）。
- 中斷 SSE 串流則會令 `for await (const msg of stream)` 乾淨優雅地退出，唔會拋出例外。

## 5. SSR 與 Provider 作用域

- **瀏覽器端**：當端點同攔截器與請求無關時，喺模組作用域共用單一 client 實例。
- **SSR 伺服器端**：只要 headers、cookies、租戶或身分憑證隨請求變動，就一定要喺每個伺服器請求邊界內建立全新嘅 client。
- 卸載 `<ClientProvider>` **唔會**自動中斷進行中嘅 HTTP 請求、唔會關閉 SSE/WebSocket 連線，亦唔會銷毀個 client。
