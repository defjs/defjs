# WebSocket 會話

`defineWebSocket` 用嚟喺你嘅 SDK 入面宣告雙向 WebSocket 契約：包括路徑模板、可選嘅 `input` 同 `builder`（僅限 `path` 同 `query`）、`incoming` 同 `outgoing` 訊息 struct、佇列大小上限，以及靜態子協議（subprotocols）。使用方應用程式則喺自己嘅 client 設定心跳偵測（heartbeat）、自動重連同生命週期釋放。

## 1. 定義契約並運行會話

利用 `struct.discriminatedUnion(...)` 為 `incoming` 或 `outgoing` 建立多種 frame 訊息型別模型。記得隨時用 `await using` 或手動 `session.close()` + `await session.closed` 嚟釋放回傳嘅 `WebSocketSession`：

<Tabs items={["sdk/ticks-socket.ts", "app/session.ts", "Single-file quick look"]}>
<Tab value="sdk/ticks-socket.ts">

```ts
import { defineWebSocket, struct } from "@defjs/core";

export const TickFrame = struct.discriminatedUnion("type", [
  struct.object({
    type: struct.literal("tick"),
    symbol: struct.string(),
    price: struct.number(),
  }),
  struct.object({
    type: struct.literal("subscribed"),
    symbol: struct.string(),
  }),
]);

export const SubscribeCommand = struct.object({
  type: struct.literal("subscribe"),
  symbol: struct.string(),
});

export const openTicker = defineWebSocket({
  path: "/market/ws",
  operation: "market.ticker",
  incoming: TickFrame,
  outgoing: SubscribeCommand,
  maxIncomingQueueSize: 64,
});
```

</Tab>
<Tab value="app/session.ts">

```ts
import { createClient, withEndpoint } from "@defjs/core";
import { openTicker } from "../sdk/ticks-socket.ts";

const client = createClient(withEndpoint("https://api.example.com"));

async function main() {
  const [error, session] = await openTicker(client);
  if (error) {
    console.error(error.code);
    return;
  }

  await using active = session;
  active.send({ type: "subscribe", symbol: "ACME" });

  for await (const message of active.receive) {
    if (message.type === "tick") {
      console.log(message.symbol, message.price);
      break;
    }
  }
}

void main();
```

## 2. 訊息驗證與方向規則

- **傳入 Frames（`session.receive`）**：文字、`ArrayBuffer`、TypedArray 同 `Blob` frame 都會解碼成 UTF-8，解析為 JSON，並以 `incoming` struct 進行驗證。損壞嘅 JSON 或 schema 結構唔吻合會被回報到 `session.onRuntimeError` 並丟棄，唔會中斷會話。`session.receive` 係單一消費者模式；請求第二個 iterator 會拋出 `TypeError`。
- **傳出 Frames（`session.send(payload)`）**：會同步通過 `outgoing` 驗證、套用 `.alias()` 同編解碼器，然後以 `JSON.stringify` 序列化。喺 `open` 狀態下會即時發送；喺 `reconnecting` 狀態下會排入佇列（若 `maxOutgoingQueueSize > 0`）；如果 payload 無效、佇列已滿／關閉，或會話已終止，則會同步拋出例外。

## 3. 會話狀態與監聽器

| 成員                 | 描述                                                                                                  |
| -------------------- | ----------------------------------------------------------------------------------------------------- |
| `state`              | `'idle' \| 'connecting' \| 'open' \| 'reconnecting' \| 'closing' \| 'closed' \| 'aborted' \| 'error'` |
| `connection`         | 最新實體 socket 嘅即時快照（`generation`、`url`、`protocol`、`extensions`）                           |
| `bufferedAmount`     | 當前活躍實體 socket 上未送出嘅位元組數（斷線時為 `0`）                                                |
| `receive`            | 單一消費者模式嘅非同步迭代器，輸出通過驗證嘅 `incoming` 訊息                                          |
| `onStateChange(fn)`  | 訂閱狀態轉換；回傳 `unsubscribe` 函式                                                                 |
| `onRuntimeError(fn)` | 訂閱非啟動階段嘅 frame／解析錯誤；回傳 `unsubscribe` 函式                                             |
| `closed`             | Promise 解析出最終終止狀態（`kind: 'closed' \| 'aborted' \| 'error'`）                                |

## 4. 重連、心跳與佇列

重連同心跳機制都係 opt-in 嘅，可透過 client 選項（`withWebSocketReconnect`、`withWebSocketHeartbeat`）或單次衍生 client 選項（`client({ reconnect, heartbeat })`）配置：

- **重新連線**：啟用時嘅預設值係 `attempts: 3`、`delayMs: 1000`、`factor: 2`、`maxDelayMs: 30000`、`jitter: 0`。每次實體連線成功變成 `open` 都會重設重試預算。`beforeConnect({ attempt, signal })` 會喺初始連線同每次重連嘗試前執行。
- **心跳偵測**：定時透過 `outgoing` struct 發送 `message()`，並等待最多 `timeoutMs` 嚟接收吻合 `isAck(msg)` 嘅 frame。吻合嘅 ack frame 會由心跳監控器消費，唔會轉發畀 `session.receive`。錯過 ack 會被判定為會話致命錯誤。
- **佇列邊界**：
  - `maxIncomingQueueSize`（必填正整數）：超出上限會以 `CAP_QUEUE_OVERFLOW` 終止會話。喺會話開啟期間請保持消費 `session.receive`。
  - `maxOutgoingQueueSize`（可選非負整數，預設 `0`）：淨係會喺 `state === 'reconnecting'` 期間緩衝 `session.send()` 呼叫，並喺下次發佈 `open` 狀態前將佢哋一次過 flush 送出。

## 5. 子協議與身分認證 [#protocols-and-authentication]

瀏覽器環境嘅 WebSocket 唔支援自訂握手 headers，因此 WebSocket 嘅 `builder` 函式只可以回傳 `{ path?, query? }`。

- **子協議優先級**：`client({ protocols })` 優於 `withWebSocketProtocols(...)`，而後者又優於 `defineWebSocket({ protocols })`。
- **URL 自動轉換**：Defjs 會自動將已解析端點嘅 `http:` 轉為 `ws:`，`https:` 轉為 `wss:`。
- **憑證傳遞**：`withCredentials(true)` 僅適用於 Fetch（HTTP/SSE）。WebSocket 認證應透過 Cookie/Session 策略、子協議或短期 connection ticket 完成——避免將長期敏感密鑰放入 query string。

## 6. 關閉與生命週期管理

呼叫 `session.close(code?, reason?)`（其中 `code` 須為 `1000` 或 `3000..4999`，`reason` 唔超過 123 個 UTF-8 位元組）並等待 `await session.closed`，或者直接用 `await using`：
