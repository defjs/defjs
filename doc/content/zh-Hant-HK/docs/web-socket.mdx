# WebSocket 會話

`defineWebSocket` 用嚟喺你嘅 SDK 入面宣告雙向 WebSocket 契約：包括路徑模板、可選嘅 `input` 同 `builder`（僅限 `path` 同 `query`）、`incoming` 同 `outgoing` 訊息 struct、佇列上限，以及靜態子協議（subprotocols）。使用方應用程式則喺自己嘅 client 設定心跳偵測（heartbeat）、自動重連同生命週期釋放。

## 2. 訊息驗證與方向規則

- **傳入 frame（`session.receive`）**：文字、`ArrayBuffer`、typed array 同 `Blob` frame 都會解碼成 UTF-8，解析為 JSON，並用 `incoming` struct 驗證。損壞嘅 JSON 或 schema 結構唔吻合會被回報到 `session.onRuntimeError` 並丟棄，唔會中斷會話。`session.receive` 係單一消費者模式；請求第二個 iterator 會拋出 `TypeError`。
- **傳出 frame（`session.send(payload)`）**：會同步通過 `outgoing` 驗證、套用 `.alias()` 同 codec，然後以 `JSON.stringify` 序列化。喺 `open` 狀態下會即時發送；喺 `reconnecting` 狀態下會排入佇列（若 `maxOutgoingQueueSize > 0`）；如果 payload 無效、佇列已滿／關閉，或會話已終止，則會同步拋出例外。

## 3. 會話狀態與監聽器

| 成員                 | 描述                                                                                                  |
| -------------------- | ----------------------------------------------------------------------------------------------------- |
| `state`              | `'idle' \| 'connecting' \| 'open' \| 'reconnecting' \| 'closing' \| 'closed' \| 'aborted' \| 'error'` |
| `connection`         | 最新實體 socket 嘅即時快照（`generation`、`url`、`protocol`、`extensions`）                           |
| `bufferedAmount`     | 當前活躍實體 socket 上未送出嘅位元組數（斷線時為 `0`）                                                |
| `receive`            | 單一消費者模式嘅非同步迭代器，輸出通過驗證嘅 `incoming` 訊息                                          |
| `onStateChange(fn)`  | 訂閱狀態轉換；回傳 `unsubscribe` 函式                                                                 |
| `onRuntimeError(fn)` | 訂閱非啟動階段嘅 frame／解析錯誤；回傳 `unsubscribe` 函式                                             |
| `closed`             | Promise 解析出最終終止狀態（`kind: 'closed' \| 'aborted' \| 'error'`）                                |

## 4. 重連、心跳與佇列

重連同心跳機制都係 opt-in 嘅，可透過 client 選項（`withWebSocketReconnect`、`withWebSocketHeartbeat`）或單次衍生 client 選項（`client({ reconnect, heartbeat })`）配置：

- **重新連線**：啟用時嘅預設值係 `attempts: 3`、`delayMs: 1000`、`factor: 2`、`maxDelayMs: 30000`、`jitter: 0`。每次實體連線成功變成 `open` 都會重設重試預算。`beforeConnect({ attempt, signal })` 會喺初始連線同每次重連嘗試前執行。已開啟嘅 socket 報畀 balancer 嘅結果只取決於關閉代碼，同 `wasClean` 無關：`1006` 或 `1015`（冇收到 close frame）係 `NET_UNREACHABLE`，`1012` 或 `1013` 係 `NET_UNAVAILABLE`，其他代碼都唔算失敗。
- **握手逾時（`connectTimeoutMs`）**：如果提供咗，佢必須係有限正數，而且唔可以大過 2147483647（timer 上限）；否則該操作回傳 `REQ_OPTIONS_INVALID`。佢限制由建立連線到 `open` 嘅時間，handshake 之後會被清走。呢個選項只存在於 `withWebSocketReconnect({...})` 嘅選項物件（或者 `reconnect` 請求選項）入面；只要傳入呢個物件，就會用預設嘅 `attempts: 3` 啟用自動重連，所以淨係設定 `connectTimeoutMs` 都會開啟重連。如果只想限制 handshake，請同時設定 `attempts: 0`。
- **心跳偵測**：定時透過 `outgoing` struct 發送 `message()`，並等待最多 `timeoutMs` 嚟接收吻合 `isAck(msg)` 嘅 frame。吻合嘅 ack frame 會由心跳監控器消費，唔會轉發畀 `session.receive`。收唔到 ack 對邏輯會話係致命錯誤：`closed.kind` 係 `"error"`，`closed.cause` 係一般嘅 `Error("WebSocket heartbeat timeout")`；呢個唔會啟動重連。錯過嘅 ack 亦會以 `NET_UNREACHABLE` 報畀 balancer，歸於該端點。心跳序列化失敗，或者 `message()` throw，亦會行同一條致命路徑並保留原始 cause，但屬於本地事件，唔會歸於端點。
- **佇列上限**：
  - `maxIncomingQueueSize`（必填正整數）：同時限制等待解碼嘅原始 frames 同等待消費者嘅已解碼訊息。溢出會用 `CAP_QUEUE_OVERFLOW` Fault 做 `closed.cause` 終止會話；同一個 cause 會傳俾 `onRuntimeError` 並 reject `session.receive`。喺會話開啟期間請保持消費 `session.receive`。
  - `maxOutgoingQueueSize`（可選非負整數，預設 `0`）：淨係會喺 `state === 'reconnecting'` 期間緩衝 `session.send()` 呼叫，並喺下次發佈 `open` 狀態前將佢哋一次過 flush 送出。

`shouldReconnect` 會收到原生關閉代碼同 `wasClean`。伺服器可以用應用程式錯誤碼 `1011` 完成正常嘅關閉握手，所以 `wasClean === true` 唔代表應用程式處理成功。範例明確允許 `1011`；請根據自己嘅協議揀選應用程式代碼，唔好淨係依賴 `!wasClean`。

## 5. 子協議與身分認證 [#protocols-and-authentication]

瀏覽器環境嘅 WebSocket 唔支援自訂握手 headers，因此 WebSocket 嘅 `builder` 函式只可以回傳 `{ path?, query? }`。

- **子協議優先級**：`client({ protocols })` 優於 `withWebSocketProtocols(...)`，而後者又優於 `defineWebSocket({ protocols })`。
- **URL 自動轉換**：Defjs 會自動將已解析端點嘅 `http:` 轉為 `ws:`，`https:` 轉為 `wss:`。
- **憑證傳遞**：`withCredentials(true)` 僅適用於 Fetch（HTTP/SSE）。WebSocket 認證應透過 Cookie／會話策略、子協議或短期 connection ticket 完成——避免將長期敏感密鑰放入 query string。
- **`beforeConnect` 唔係 request mutator**：input 解析、同步純函式 `builder` 同攔截器鏈每次操作只執行一次。如果 request 嘅 base endpoint 冇俾攔截器取代，每次重連都會重新揀選端點並用嗰個端點重建 URL，但會重用已建構嘅 path/query 同擷取嘅協議清單。無論仍然用同一端點定已經故障轉移，URL 都會喺嗰次嘗試嘅 `beforeConnect` 執行之前確定。喺 hook 入面改閉包變數、input 或協議陣列，唔可以為目前握手提供新 ticket。同一個會話內唔支援輪換 URL/子協議憑證；請先取得新憑證，再透過 input 或 client 設定開始新操作，並負責替代會話嘅清理。

## 6. 關閉與生命週期管理

呼叫 `session.close(code?, reason?)`（其中 `code` 須為 `1000` 或 `3000..4999`，`reason` 唔超過 123 個 UTF-8 位元組）並等待 `await session.closed`，或者直接用 `await using`：

一次斷線嘅重連嘗試用盡之後，會話會以 `closed.kind: "error"` 結束，保留原生關閉 snapshot（升級失敗時通常係代碼 `1006`），並用一般傳輸層錯誤做 `closed.cause`；唔會提供獨立而穩定嘅用盡錯誤碼。當元件或背景 worker 結束工作時，記得取消訂閱 `onStateChange` 同 `onRuntimeError` 監聽器。
