# Client

`Client` 係使用方應用程式嘅執行設定，而且佢係一個 function。`createClient(...)` return 嗰個 function。由 SDK 匯入操作，揀服務地址、認證、攔截器同傳輸，再用 client 呼叫操作。`getUser(client({ abort }), { id: 1 })` 開始一次有聲明 input 嘅呼叫。`health(client)` 開始一次冇 input 嘅呼叫。成個 input struct 可選嗰陣，`search(client)` 同 `search(client, input)` 都合法。冇第三個 options 參數。呼叫操作就開始佢。`await` 只係等 error-first tuple。

SDK 嘅定義唔綁死呢個 instance。瀏覽器、伺服器請求同本地測試可以用同一個匯出操作，配唔同 client。全部仍然跟同一份 Defjs 契約同兼容嘅 Core 版本。你經一個 client 呼叫嘅操作，就要為嗰個 client 設定服務地址。

同一個 client 值可以傳俾好多操作。應用程式自己揀快取同重試策略，並擁有自己開始嘅工作。HTTP 唔會自動重試。串流重連係 opt-in。

因為 `Client` 係 function，唔好將佢傳俾 React state setter：`setState(client)` 會將佢當 updater 嚟 call。亦唔好將佢做 Vue `watch` 或者 `computed` 嘅 source：嗰啲會 call function。

## 派生一個 client

`client(options?)` return 一個新 client。呼叫 `client(options)` 時，七個已知 field 從參數物件複製出嚟：頂層快照落一個新 options 物件，再疊上而家嘅 options。後到嘅 field 贏。field 嘅值係 `undefined` 時，當冇提供，保留上一層嘅值。派生出嚟嘅 client 唔可以掉低上一層已有嘅設定；想返到冇呢項設定，要由當初冇佢嗰個 client 再派生一次（留住根 client）。巢狀嘅 `heartbeat`、`protocols` 同 `reconnect` 嘅值按 reference 留住，唔會 clone，並且成個值換走上一層嘅值，唔會合併。WebSocket 喺操作行嗰陣先讀佢哋（嗰陣會複製 heartbeat 嘅 field 同 protocols 列表），所以派生之後再改呢啲物件，仍然可以影響之後嘅呼叫。應用程式傳入之後應該當佢哋係 immutable。派生唔做 I/O。原本嗰個 client 永遠唔會被改。`client()`、`client(undefined)` 同 `client({})` 複製而家嘅 options。

`abort` 唔會合併。後到嘅 `abort` 取代之前嘅 signal。喺應用程式程式碼用 `AbortSignal.any` 合併 signal。

`createClient` 嘅 base 設定每個派生 client 共用，runtime 唔會 freeze。佢按慣例固定：個 library 唔會改佢，應用程式亦唔應該改。嗰個 client 上面嘅 [`RequestOptions`](/zh-Hant-HK/api/core/requestoptions-type) 就係嗰份頂層快照。應用程式程式碼呼叫 client，再將佢傳俾操作。佢唔讀呢個內部狀態。

## Request options

[`RequestOptions`](/zh-Hant-HK/api/core/requestoptions-type) 有七個扁平 field。每種協定只讀自己識嘅 field，其餘忽略。傳 `heartbeat` 俾 HTTP 操作會被忽略，唔係 fault。SSE 只會由 request options 讀 `abort`。SSE reconnect 來自 client 設定（`withSSEReconnect`），所以 `client({ reconnect })` 只影響 WebSocket。冇 compile-time 嘅協定過濾。

| Field                | 邊個用               | 規則                                                                                                     |
| -------------------- | -------------------- | -------------------------------------------------------------------------------------------------------- |
| `abort`              | HTTP、SSE、WebSocket | 取代之前嘅 signal。Deadline 係 `AbortSignal.timeout(ms)`（`NET_TIMEOUT`）。手動 abort 係 `NET_ABORTED`。 |
| `onUploadProgress`   | HTTP                 | SSE 同 WebSocket 會忽略。                                                                                |
| `onDownloadProgress` | HTTP                 | SSE 同 WebSocket 會忽略。                                                                                |
| `beforeConnect`      | WebSocket            | 喺該次呼叫取代 client 設定。                                                                             |
| `protocols`          | WebSocket            | 取代 client 嘅 list。唔會 append。                                                                       |
| `heartbeat`          | WebSocket            | 成個換走。`timeoutMs` 係 heartbeat 等確認嘅時間，唔係請求 deadline。                                     |
| `reconnect`          | WebSocket            | 成個換走。                                                                                               |

冇 `timeout` field，冇 `signal` field，亦冇 client 層級嘅預設 deadline。SSE 同 WebSocket 嘅 `abort` 覆蓋成條連線，包括 open 之後。冇只限啟動嘅 deadline。應用程式想要一個，就自己建立 `AbortController`，用 timer 以 `new DOMException("...", "TimeoutError")` abort，並喺 await 返回之後清走 timer。睇 [SSE](/zh-Hant-HK/docs/sse#close-and-dispose)。

`HttpExecuteOptions` 係 HTTP 嗰片：`abort` 加 progress callbacks。`EventStreamExecuteOptions` 係 `{ abort? }`。`WebSocketExecuteOptions` 係 WebSocket 嗰片再加 `abort`。

## 按 transport 嘅結果

- HTTP → `[error, data, response]`
- SSE → `[error, stream, open]`。`open` 對 Defjs 原生 handle 或透傳同一 live `open` 物件嘅 wrapper，係返回連線首次成功 handshake 嘅 snapshot；custom handle 或覆寫 `open` 嘅 wrapper 就算已經 reconnect，都以自己目前公開嘅 `open` 為準，`stream.open` 仍然係 live（見 [SSE](/zh-Hant-HK/docs/sse)）。
- WebSocket → `[error, session, connection]`

`error` 有值時，先 return，先至用成功值。

Cleanup 係你 own：abort HTTP，close SSE + `await stream.closed`，close WebSocket + `await session.closed`。

## Server vs browser 嘅 scope

喺 server 上面，當 options 或者 interceptor closures capture auth、cookies、users 或者 tenants 時，喺 request boundary 入面 create client。Client identity 本身唔係 security boundary。

## 遷移

| 舊                                        | 新                                             |
| ----------------------------------------- | ---------------------------------------------- |
| `client.execute(getUser(input), options)` | `getUser(client(options), input)`              |
| `execute(cmd, { timeout: 5000 })`         | `client({ abort: AbortSignal.timeout(5000) })` |
| `execute(cmd, { signal })`                | `client({ abort: signal })`                    |
| `createClient(withTimeout(5000), ...)`    | 喺呼叫嗰陣傳入 `abort`，或者包一層應用程式函數 |

| `withSSEReconnect` / `withSSEOnInvalidEvent`                                                                  | SSE knobs                                                       |
