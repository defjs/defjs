# Client

`Client` 負責持有使用方應用程式嘅執行設定：包括 base URL、預設 headers、認證憑證、中介層（interceptor）、query 序列化函式同埋傳輸 handle。

呼叫 `createClient(...options)` 會回傳一個 [`DerivableClient`](/zh-Hant-HK/api/core/derivableclient-type)：

- 如果唔需要單次呼叫自訂選項，可以直接將 `client` 傳入操作（例如 `getOrder(client, { id: 1 })`）。
- 呼叫 `client(requestOptions)` 可以衍生出單次呼叫嘅 `Client` 物件（例如 `getOrder(client({ signal }), { id: 1 })`）。衍生過程唔會進行任何 I/O 操作，而衍生出嚟嘅值係一個普通純物件（唔可以再作為函式呼叫）。

### 選項組合規則

- 所有選項按**由左至右**嘅順序套用。
- 單值設定函式（`withEndpoint`、`withHeaders`、`withQuerySerializer`、`withCredentials`、`withXSRF`）會**覆寫**前面設定嘅舊值。
- `withInterceptors(...items)` 會將新項目**追加**到現有嘅中介層清單尾部，並喺執行具體操作時自動按傳輸類型（`http`、`sse`、`web-socket`）過濾。

### 單次呼叫 `RequestOptions` 參考

`RequestOptions` 包含七個扁平欄位。每種傳輸只會讀取適用於自己嘅欄位，並自動忽略其餘部分：

| 欄位                 | 適用傳輸             | 行為描述                                                                                                    |
| -------------------- | -------------------- | ----------------------------------------------------------------------------------------------------------- |
| `signal`             | HTTP、SSE、WebSocket | 中斷當前呼叫（`AbortSignal.timeout(ms)` → `NET_TIMEOUT`；手動中斷 → `NET_ABORTED`）。                       |
| `onUploadProgress`   | HTTP                 | 回報串流 request body 嘅上傳進度。                                                                          |
| `onDownloadProgress` | HTTP                 | 回報宣告過嘅 response body 嘅下載進度。                                                                     |
| `beforeConnect`      | WebSocket            | 喺呢次會話入面替換 client 層級嘅 `beforeConnect` hook。                                                     |
| `protocols`          | WebSocket            | 喺呢次會話入面替換 client 層級嘅子協議清單。                                                                |
| `heartbeat`          | WebSocket            | 喺呢次會話入面替換 client 層級嘅心跳偵測設定。                                                              |
| `reconnect`          | WebSocket            | 喺呢次會話入面替換 client 層級嘅 WebSocket 重連策略（SSE 重連則係透過 client 嘅 `withSSEReconnect` 設定）。 |

## 3. 瀏覽器單例 vs. 伺服器請求作用域

- **瀏覽器應用程式**：當 endpoint、中介層同憑證屬於整個前端共用嗰陣，喺模組頂層共用一個 `DerivableClient` 單例即可。
- **伺服器 / SSR 應用程式**：只要 headers、cookies、認證 token 或租戶 context 係隨請求變動，就一定要**喺每個傳入請求嘅處理範圍內**建立獨立嘅 client。絕唔好喺整個 process 共用嘅全域 client 上面存放個別用戶嘅身分憑證。

## 4. 多端點與負載平衡 [#multiple-endpoints]

`withEndpoint(...urls)` 接受傳入一個或多個候選 base URL。預設情況下：

- 每個 client 預設使用 [`pickFirstBalancer`](/zh-Hant-HK/api/core/pickfirstbalancer)，停喺第一個 URL，直至遇到 `NET_UNREACHABLE` 或 `NET_UNAVAILABLE`（HTTP 502、503 或 504）先至前進。
- **同一次呼叫內嘅 HTTP 重試預設關閉。** `withRetry()` 等同 `withRetry({})`，會喺安全方法（`GET`、`HEAD`、`OPTIONS`、`TRACE`）嘅連線失敗上，帶住 backoff，對一個未試過嘅端點再試一次。Finagle 重試預算屬於 client 配置，由佢派生出嚟嘅 client 共享，同 balancer 嘅 identity 無關。

<include cwd lang="typescript">
  examples/client/multiple-endpoints.ts#example
</include>

只設定咗一個端點嗰陣，`withRetry` 唔會重放請求，因為每一次重試都會排除已經試過嘅端點。如果提供咗 `attemptTimeoutMs` 同 `connectTimeoutMs`，佢哋必須係有限正數，而且唔可以大過 2147483647（timer 上限）；否則該操作 return `REQ_OPTIONS_INVALID`。

### 健康檢查過濾與 P2C [#health-filtering-and-p2c]

對於對等伺服器節點，[`roundRobinBalancer`](/zh-Hant-HK/api/core/roundrobinbalancer) 同 [`p2cBalancer`](/zh-Hant-HK/api/core/p2cbalancer)（結合 PeakEwma RTT 與進行中請求負載）預設開啟 Linkerd 風格嘅連續失敗熔斷斷路器（`outlierDetection`）。佢計入 `NET_UNREACHABLE`、`NET_UNAVAILABLE` 同 `NET_SERVER_ERROR`；原始 response `status` 只供自訂 balancer 使用。

關於重試預算、主動／被動健康檢查、P2C 負載估算以及自訂負載平衡器嘅完整細節，請參閱 [負載平衡與故障轉移](/zh-Hant-HK/docs/load-balancing) 指南。

## 6. Client 選項輔助函式參考

| 輔助函式                                                                                                      | 用途                                                                                              |
| ------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------- |
| `withEndpoint(...urls)`                                                                                       | 設定一個或多個候選 base URL（會覆寫先前嘅清單）。                                                 |
| `withHeaders(HeadersInit)`                                                                                    | 為 HTTP 同 SSE 設定靜態預設 headers（會被 builder headers 覆寫）。                                |
| `withInterceptors(...items)`                                                                                  | 以洋蔥模型順序追加 HTTP、SSE 同 WebSocket 中介層。                                                |
| `withQuerySerializer(fn)`                                                                                     | 將已套用別名嘅 query 物件序列化成 query string。                                                  |
| `withCredentials(boolean)`                                                                                    | 設為 `true` 時，為 HTTP 同 SSE 請求設定 Fetch 嘅 `credentials: "include"`。                       |
| `withXSRF(options?)`                                                                                          | 喺同源嘅變更類 HTTP 請求中，自動將 XSRF cookie 複製到 header。                                    |
| `withBalancer(balancer)`                                                                                      | 替換端點選取策略（`pickFirstBalancer`、`roundRobinBalancer`、`p2cBalancer`）。                    |
| `withRetry(options?)`                                                                                         | 設定要自己開嘅 HTTP 重試條件、方法、backoff、單次 attempt 逾時，以及一份歸 client 所有嘅 budget。 |
| `withSSEReconnect` / `withSSEOnInvalidEvent`                                                                  | 設定 SSE 重新連線機制同無效事件監聽。                                                             |
| `withWebSocketReconnect` / `withWebSocketHeartbeat` / `withWebSocketProtocols` / `withWebSocketBeforeConnect` | 設定 WebSocket 會話嘅各項預設參數。                                                               |
| `withHTTPHandle` / `withSSEHandle` / `withWebSocketHandle`                                                    | 注入自訂或 mock 傳輸實作。                                                                        |
