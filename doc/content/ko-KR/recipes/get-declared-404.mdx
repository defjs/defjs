# 선언된 404가 있는 GET

성공 body와 404 body를 둘 다 선언해요. `error.code`와 `error.status`로 분기하면, 선언된 miss의 타입이 있는 `error.data`를 받아요.

자세한 내용은 [HTTP](/ko-KR/docs/http)와 [오류](/ko-KR/docs/errors)를 보세요.

<include cwd meta="get-user.ts">
  examples/recipes/get-declared-404.ts#example
</include>

`api.example.com`은 placeholder예요. `GET /users/7`에 `200`과 `{ "id": 7, "name": "Ada" }`로 응답하는 서버에서는 이 스니펫이 다음을 출력해요.

```txt
Loaded Ada from 200
```

2xx가 아닌 status는 `HTTP_STATUS`예요. `error`를 선언하면 그 body에 타입이 생기고, `error`를 빼면 `error.data`는 `undefined`이고 body는 읽히지 않아요. 선언한 `error` body를 읽을 수 없으면 (잘못된 미디어 타입, 잘못된 JSON, 잘못된 모양) 대신 `RES_*` fault가 돼요. `error` Struct 하나가 모든 non-2xx status를 덮으니, 모양이 달라지면 `struct.or(...)`나 discriminated union을 쓰세요.
