# SDK 작성과 배포 [#publish-an-http-sdk-without-hiding-execute]

Defjs SDK는 공유 `struct` 모델(`src/models/`)과 도메인별 작업 모듈(`src/services/`)을 트리쉐이킹 가능한 npm 패키지로 구성하며, `createClient(...)`, 엔드포인트, 자격 증명, 인터셉터 설정은 사용하는 애플리케이션에 온전히 맡깁니다.

엔드포인트를 상태를 가진 `Service` 클래스(`ObjectsService.putObject(...)`)로 감싸는 레거시 OpenAPI 생성기와 달리, Defjs SDK는 애플리케이션의 클라이언트로 직접 호출할 수 있는 **독립적인 순수 작업 함수**(`putObject`, `getObject`, `listObjectsV2`)를 export합니다.

---

## 1. SDK 패키지 구조화 및 정의하기

Amazon S3 호환 오브젝트 스토리지 SDK(`@company/s3-sdk`)를 예로 들어 패키지를 두 계층으로 나눕니다:

- **`src/models/`**: 공유 `struct` 스키마 및 `Infer<typeof ...>` TypeScript 타입(런타임 스키마와 정적 타입 모두에 동일한 이름의 값 + 타입 export를 사용하여 사용하는 쪽에서 단일 식별자로 import할 수 있도록 구성).
- **`src/services/`**: 리소스별로 그룹화된 도메인 모듈(`buckets.ts`, `objects.ts`). 각 모듈은 동기 `builder`를 통해 호출자의 평탄한 입력을 `path`, `query`, `headers`, 바이너리 `body`로 분배하는 독립형 `defineRequest` 함수를 export합니다.

- **`Service` 클래스가 아닌 순수 함수**: 모든 작업(`listBuckets`, `listObjectsV2`, `getObject`, `putObject`, `deleteObject`)은 독립적인 `defineRequest` 값으로 export됩니다. 이를 `class`나 네임스페이스 객체로 감싸지 마세요. 독립형 함수를 사용하면 호출 규약이 `@defjs/core`(`await putObject(client, input)`)와 동일하게 유지되며, `"sideEffects": false`가 설정된 경우 번들러가 사용하지 않는 엔드포인트를 트리쉐이킹할 수 있습니다.
- **빈 응답, 바이너리 응답, 구조화된 응답**: `listBuckets`와 `listObjectsV2`는 `.alias()` 와이어 매핑이 적용된 JSON struct를 디코딩하고, `getObject`는 바이너리 `Blob`(`output: struct.blob()`)을 디코딩합니다. `putObject`, `headObject`, `deleteObject`는 빈 응답 본문에 대해 `output`을 생략하면서도 세 번째 튜플 슬롯을 통해 `response.headers`(예: `etag`)를 그대로 노출합니다.
- **외부 런타임 peer 의존성**: `@defjs/core`는 사용하는 애플리케이션과 공유되는 `peerDependency`로 유지됩니다.

## 2. 빌드 및 Tarball 검증

`tsdown`을 사용해 `dist/index.js`와 `dist/index.d.ts`를 번들링한 뒤 배포 전에 패키지 내용을 점검하세요:

```sh
bun install
bun run build
bun pm pack --dry-run
bun pm pack
```

Tarball 내에 `dist/index.js`와 `dist/index.d.ts`가 정상적으로 포함되어 있는지 확인합니다.

---

## 3. 애플리케이션에서 SDK 사용하기

애플리케이션에 작성한 SDK와 `@defjs/core`를 함께 설치합니다:

```sh
bun add @company/s3-sdk @defjs/core@^0.8.0
```

SDK는 클라이언트를 바인딩하지 않으므로 사용하는 애플리케이션이 엔드포인트(AWS S3, Cloudflare R2 또는 MinIO), 서명 인터셉터, 재시도 정책의 소유권을 가지며, import한 각 작업을 순수 함수로 직접 호출합니다:

## 4. 테스트 및 배포

경로/쿼리/헤더/바이너리 본문 매핑, `output` 디코딩, `ETag` 응답 헤더, 선언된 `HTTP_STATUS`(`S3Error`) 결함, 취소 동작을 포괄하는 [인메모리 핸들 테스트](/ko-KR/recipes/test-with-handle)로 export된 정의들을 철저히 검증하세요. 검증이 완료되면 패키지를 배포합니다:

```sh
bun publish --access public
```

자세한 내용은 [HTTP 작업](/ko-KR/docs/http), [Client](/ko-KR/docs/client), [테스트](/ko-KR/docs/testing), [핵심 아키텍처](/ko-KR/docs/design-decisions) 문서를 참조하세요.
