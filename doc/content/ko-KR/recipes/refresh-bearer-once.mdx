# 401 발생 시 Bearer 토큰 1회 갱신

Defjs에서 `next(request)`는 인터셉터 체인의 남은 안쪽 단계들을 호출하며, 가장 바깥쪽 인터셉터부터 전체 체인을 다시 디스패치하지 않습니다. 토큰 첨부, 동시 갱신의 단일 실행(single-flight deduplication), 그리고 `401` 수신 시 1회 재요청 처리를 **단일** HTTP 인터셉터 내부에 배치하세요. 이렇게 하면 바깥쪽의 로깅이나 타이밍 인터셉터가 중복으로 두 번 실행되는 문제를 방지할 수 있습니다:

본문을 재전송할 수 있다고 해서 비즈니스 작업도 반복해도 되는 것은 아닙니다. 이 인터셉터는 조건에 맞는 401 뒤에 JSON `POST`도 재전송합니다. HTTP 전달은 두 번이며, 처음에는 거부되고 다음에는 수락됩니다. 인증이 비즈니스 핸들러 실행 전에 첫 번째 전달을 거부하는 경우에만 쓰기 작업에 사용하세요. 두 전달에 동일하고 안정적인 멱등성 키를 유지하고 서버 측 중복 제거를 사용해야 합니다. 이 계약을 보장할 수 없다면 쓰기를 자동 재전송하지 말고 401을 반환하세요. 전체 예제는 `ReadableStream` 요청 본문을 재전송하지 않습니다.

인터셉터의 양파 껍질 실행 순서와 재시도 경계에 대한 자세한 내용은 [인터셉터](/ko-KR/docs/interceptors) 문서를 참조하세요.
