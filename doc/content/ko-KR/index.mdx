# 더 나은 SDK를 위해 [#defjs]

**Defjs = define js.** API를 JavaScript / TypeScript 정의로 표현해 SDK를 더 쉽게 설계하고 작성하고 배포할 수 있게 합니다.

SDK 작성자는 `defineRequest`, `defineEventStream`, `defineWebSocket`으로 재사용 가능한 타입이 있는 API를 제공합니다. Struct는 입력, 출력, 오류 등의 데이터 계약을 선언하고, `builder`는 입력을 요청에 배치합니다. 사용하는 앱은 정의를 import하고 자신이 구성한 Defjs Client로 실행합니다.

| 책임        | SDK 작성자                                        | 사용하는 앱                                               |
| ----------- | ------------------------------------------------- | --------------------------------------------------------- |
| API 계약    | method, 상대 path, Struct, `builder`를 정의합니다 | 공개된 정의로 명령을 만듭니다                             |
| 실행 환경   | 재사용할 정의를 export합니다                      | endpoint, 인증, 인터셉터, 플랫폼 전송 수단을 구성합니다   |
| 결과와 수명 | 타입이 있는 성공, 오류, 이벤트를 선언합니다       | `execute` 결과를 처리하고 취소와 스트림 종료를 관리합니다 |
| 배포        | 정의와 타입 선언을 패키지로 배포합니다            | SDK와 호환되는 `@defjs/core`를 설치합니다                 |

## 정의를 배포하고 앱에서 실행하기

SDK의 `get-health.ts`는 접속 주소나 인증 정보를 갖지 않는 정의를 export합니다.

<include cwd meta="get-health.ts">
  examples/home/get-health.ts#example
</include>

앱의 `app.ts`는 이 정의를 import하고 실행 환경에 맞게 클라이언트를 만듭니다.

<include cwd meta="app.ts">
  examples/home/app.ts#example
</include>

두 파일을 같은 디렉터리에 저장합니다. SDK를 패키지로 배포한 뒤에는 앱의 상대 import를 패키지 이름으로 바꿉니다. 재사용의 경계는 Defjs의 정의와 실행 계약입니다. 앱마다 Client 설정을 바꾸면서 같은 API 정의를 사용할 수 있습니다.

## 모범 사례

정의는 client와 독립입니다. 정의를 호출하면 command만 만들어집니다. 그 command에 이름을 붙인 다음, 애플리케이션이 소유한 client의 `client.execute`에 넘깁니다. 서비스 주소와 자격 증명도 애플리케이션의 것입니다. error-first 튜플을 먼저 확인합니다. `error`가 있으면 `error.code`를 보고하고, 성공 값을 읽기 전에 함수에서 return 합니다.

[빠른 시작](/ko-KR/docs/start)에서 두 파일의 흐름을 실행하고, [SDK 작성과 배포](/ko-KR/recipes/publish-http-sdk)에서 패키지 구성과 배포 방법을 확인하세요. 설계 배경은 [설계 결정](/ko-KR/docs/design-decisions)에 설명되어 있습니다.

Defjs는 결과 캐시나 자동 재시도를 추가하지 않으며, 앱이 소유한 스트림을 자동으로 닫지 않습니다.

## 전송 방식 고르기

| 필요한 것                      | 여기서 시작                         | 성공 시 결과                                                                   |
| ------------------------------ | ----------------------------------- | ------------------------------------------------------------------------------ |
| 요청 + status별 응답           | [HTTP](/ko-KR/docs/http)            | 디코딩된 data + `DecodedResponse` (output struct를 선언하지 않으면 `HttpMeta`) |
| 오래 유지되는 서버 이벤트 피드 | [SSE](/ko-KR/docs/sse)              | 스트림 하나 + 시작 시점 `open` 스냅샷                                          |
| 양방향 세션                    | [WebSocket](/ko-KR/docs/web-socket) | 세션 하나 + 시작 시점 `connection` 스냅샷                                      |

## 패키지 고르기

| 패키지                        | 언제                                                                                                 |
| ----------------------------- | ---------------------------------------------------------------------------------------------------- |
| `@defjs/core`                 | API 정의, Struct, `createClient` (HTTP + SSE + WebSocket)                                            |
| `@defjs/react`                | `ClientProvider` / `useClient` — [React](/ko-KR/docs/integrations/react)                             |
| `@defjs/vue`                  | 플러그인 + `injectClient` — [Vue](/ko-KR/docs/integrations/vue)                                      |
| `@defjs/opentelemetry-server` | 아웃바운드 span, metric, log — [OpenTelemetry Server](/ko-KR/docs/integrations/opentelemetry-server) |

## 결과 형태

세 전송 모두 error-first 세 항목 튜플을 돌려줘요. 위치는 같고, 의미는 달라요.

- HTTP → `[error, data, response]`
- SSE → `[error, stream, open]`
- WebSocket → `[error, session, connection]`

실패하면 두 번째 항목은 `undefined`예요. HTTP는 세 번째 항목도 `undefined`인데, fault가 응답 메타데이터를 가지고 있기 때문이에요. SSE와 WebSocket은 실패 전에 잡힌 시작 스냅샷이 있으면 세 번째 항목이 그 스냅샷이에요. [오류](/ko-KR/docs/errors)를 보세요.

## 소유권을 한 호흡으로

HTTP는 낡았을 때 abort 해요. SSE는 닫고 `await stream.closed` 해요. WebSocket은 닫고 `await session.closed` 해요. 서버에서는 옵션이 쿠키, 인증, 테넌트 데이터를 담을 때 요청 경계 안에서 클라이언트를 만들어요. 로그하기 전에 URL, 헤더, body를 마스킹해요.
