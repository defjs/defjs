# Defjs

**API 계약은 한 번만 정의하고, 실행 환경은 애플리케이션마다 구성하세요.**

Defjs는 TypeScript SDK를 두 가지 영역으로 명확히 분리합니다:

- **SDK 정의 (`@defjs/core`)** — SDK 작성자는 `struct` 스키마와 함께 타입이 부여된 HTTP, SSE, WebSocket 작업을 선언합니다. 정의는 순수한 데이터입니다. 정의를 import한다고 해서 네트워크 호출이 시작되거나 전역 클라이언트가 바인딩되지 않습니다.
- **애플리케이션 실행** — SDK를 사용하는 애플리케이션은 자체 `Client`를 직접 생성하고(`createClient(withEndpoint(...))`), 자격 증명, 인터셉터, 로드 밸런서를 연결한 뒤, 작업을 호출할 때 이 클라이언트를 전달합니다.

## 정의와 클라이언트를 분리하는 이유

| 책임 구분     | SDK 작성자 (정의)                                                                               | 애플리케이션 (실행)                                                    |
| ------------- | ----------------------------------------------------------------------------------------------- | ---------------------------------------------------------------------- |
| **소유 항목** | 메서드, 경로 템플릿, `input` / `output` / `error` 스키마, `builder` 매핑, 고정 `operation` 이름 | 기본 URL, 자격 증명, 인증 인터셉터, 로드 밸런싱, 타임아웃, 리소스 정리 |
| **배포 단위** | 재사용 가능한 ESM 모듈 및 `.d.ts` 타입 선언                                                     | 브라우저, 서버, 테스트 런타임별 실행 환경 설정                         |
| **얻는 이점** | 특정 환경에 종속되지 않음; 브라우저, SSR, 테스트 어디서나 동작                                  | 재시도, 장애 복구, 원격 측정, 수명 주기에 대한 완전한 제어권           |

## 시작 가이드 선택

1. **[빠른 시작](/ko-KR/docs/start)** — 작업을 정의하고, 로컬 Fetch 핸들로 오프라인 테스트를 진행한 뒤, 실제 서비스에 연결해 봅니다.
2. **[핵심 아키텍처](/ko-KR/docs/design-decisions)** — 6가지 응답 디코딩 규칙, error-first 튜플, 리소스 소유권 모델을 이해합니다.
3. **[SDK 정의하기](/ko-KR/docs/struct)** — [Struct](/ko-KR/docs/struct)로 통신 계약을 선언하고 [HTTP](/ko-KR/docs/http), [SSE](/ko-KR/docs/sse), [WebSocket](/ko-KR/docs/web-socket) 작업을 export합니다.
4. **[클라이언트 및 실행](/ko-KR/docs/client)** — [Client](/ko-KR/docs/client)를 구성하고, 타입화된 [오류](/ko-KR/docs/errors)를 처리하며, [인터셉터](/ko-KR/docs/interceptors)를 연결하고, [로드 밸런싱 및 장애 조치](/ko-KR/docs/load-balancing)와 결정론적 [테스트](/ko-KR/docs/testing)를 설정합니다.

## 지원되는 전송 방식 및 결과 튜플

모든 작업은 각 전송 수단의 수명 주기에 최적화된 3개 항목의 error-first 튜플을 반환합니다:

| 전송 방식                               | 진입 함수           | 튜플 형태                      | 수명 주기 소유권                                                     |
| --------------------------------------- | ------------------- | ------------------------------ | -------------------------------------------------------------------- |
| **[HTTP](/ko-KR/docs/http)**            | `defineRequest`     | `[error, data, response]`      | `client({ signal })`을 통해 진행 중인 요청 취소                      |
| **[SSE](/ko-KR/docs/sse)**              | `defineEventStream` | `[error, stream, open]`        | `await using` 또는 `stream.close()` + `await stream.closed`로 해제   |
| **[WebSocket](/ko-KR/docs/web-socket)** | `defineWebSocket`   | `[error, session, connection]` | `await using` 또는 `session.close()` + `await session.closed`로 해제 |

HTTP 요청 실패 시 튜플은 `[error, undefined, undefined]`가 됩니다. `error` 자체가 이미 `HttpMeta` 응답 메타데이터를 담고 있기 때문입니다. SSE와 WebSocket의 경우, 실패 전 초기 스냅샷이 수집되었다면 세 번째 자리에 해당 스냅샷이 반환됩니다.

## 공식 패키지

| 패키지                        | 역할                                                                  | 가이드                                                                |
| ----------------------------- | --------------------------------------------------------------------- | --------------------------------------------------------------------- |
| `@defjs/core`                 | 런타임 의존성이 없는 SDK 정의, `struct`, 클라이언트, 인터셉터         | [빠른 시작](/ko-KR/docs/start)                                        |
| `@defjs/react`                | React 18+를 위한 `ClientProvider` 및 `useClient()` 컨텍스트 주입      | [React 통합](/ko-KR/docs/integrations/react)                          |
| `@defjs/vue`                  | Vue 3.2+를 위한 `createClientPlugin`, `HTTP_CLIENT`, `injectClient()` | [Vue 통합](/ko-KR/docs/integrations/vue)                              |
| `@defjs/opentelemetry-server` | 서버 사이드 아웃바운드 span, 메트릭, 진단 로그 수집                   | [OpenTelemetry Server](/ko-KR/docs/integrations/opentelemetry-server) |
