# OpenTelemetry server

미들웨어 플러그인이에요. 모든 작업 호출과 그 HTTP / SSE / WebSocket 전송에 대한 아웃바운드 계측을 Core 인터셉터로 붙여요. 이 패키지는 OpenTelemetry SDK를 초기화하지 않고, 인바운드 서버 계측도 아니에요.

[OpenTelemetry server 가이드](/ko-KR/docs/integrations/opentelemetry-server)를 보세요.

## withOpenTelemetryServer()

<ApiSignature name="withOpenTelemetryServer" />

`tracer`, `meter`, `logger` 중 하나라도 전달하면 작업 인터셉터를 추가하고, 이어서 활성화된 전송마다 인터셉터 하나를 HTTP, SSE, WebSocket 순서로 추가해요. `createClient` 때 클라이언트마다 한 번 적용하세요. `options`는 필수예요. 전파만 하는 전송 인터셉터를 설치하려면 `{}`를 넘기세요.

<include cwd>examples/api/with-opentelemetry-server.ts#example</include>

`tracer`, `meter`, `logger`는 각각 선택 사항이에요. `propagator`가 없으면 W3C Trace Context + Baggage예요.

모든 작업 호출은 호출부터 튜플까지 관찰돼요. `defjs.operation.name`(예: `GET /orders/:id`)이라는 이름의 `INTERNAL` 작업 span(실패하면 `error.type`에 결함 코드가 설정돼요), `defjs.client.operation.duration` 샘플 하나, 실패 시 `WARN` 로그 하나가 생겨요. 각 HTTP 시도와 각 SSE 또는 WebSocket 연결은 그 아래에 `CLIENT` 전송 span을 가져요. 활성 부모 span 없이 시작한 호출은 자체 trace를 시작하고, 무엇을 남길지는 SDK의 샘플러가 정해요.

`tracer`를 생략하면 플러그인은 로컬 span을 만들지 않고, `trace.getTracer(...)`를 호출하지 않으며, `startSpanHook`, `requestHook`, `responseHook`을 건너뛰어요. 전달한 `meter`와 `logger`는 독립적으로 동작해요. 추출한 부모 컨텍스트는 계속 전파하고, WebSocket의 `queryPropagation` 기본값은 `false`로 유지돼요.

HTTP, SSE, WebSocket은 기본으로 켜져 있어요. 전송에 `{ enabled: false }`를 주면 건너뛰어요.

## OpenTelemetryServerOptions

<ApiSignature name="OpenTelemetryServerOptions" />

| 필드                      | 기본값                      | 효과                                                                               |
| ------------------------- | --------------------------- | ---------------------------------------------------------------------------------- |
| `tracer`                  | 없음                        | 없으면 로컬 span도 span 훅도 없어요.                                               |
| `meter`                   | 없음                        | 없으면 패키지 메트릭을 기록하지 않아요.                                            |
| `logger`                  | 없음                        | `@opentelemetry/api-logs`의 `Logger`예요. 없으면 진단 LogRecord를 내보내지 않아요. |
| `propagator`              | W3C Trace Context + Baggage | 부모 컨텍스트를 추출하고 아웃바운드 컨텍스트를 주입해요.                           |
| `includeErrorDiagnostics` | `false`                     | 실패한 span, `exception` 이벤트, 실패 로그에 오류 메시지와 스택을 내보내요.        |
| `http`                    | `{}`                        | HTTP 전송 옵션이에요.                                                              |
| `sse`                     | `{}`                        | SSE 전송 옵션이에요.                                                               |
| `webSocket`               | `{}`                        | WebSocket 전송 옵션이에요.                                                         |

`enabled`의 기본값은 `true`이고, `enabled: false`일 때만 전송이 꺼지며, 그 전송 호출의 작업 텔레메트리도 함께 꺼져요.

span 훅은 `tracer`를 전달했을 때만 실행돼요. `startSpanHook`은 해당 HTTP, SSE, WebSocket 전송의 span을 만들기 전에 동기적으로 실행돼요. 반환한 속성은 내장 속성 뒤에 적용되므로 애플리케이션이 `url.full`이나 다른 초기 값을 덮어쓸 수 있어요. 훅이 throw해도 Defjs는 내장 속성으로 span을 만들고 요청을 계속해요. `requestHook`과 `responseHook`은 span을 만든 뒤 실행돼요. 둘 다 await하지 않아요. throw나 reject는 작업을 막거나 실패시키지 않아요.

훅은 전송 span을 다루고, 작업 span에는 훅이 없어요. `span.isRecording()`이 true인 동안 훅 실패는 `defjs.otel.hook.error`와 `exception` 이벤트로 기록돼요. `exception` 이벤트는 `exception.type`(클래스 이름이며 Defjs 결함 코드가 아님)만 담고, `includeErrorDiagnostics`를 켜지 않으면 `exception.message`나 `exception.stacktrace`는 담지 않아요. 런타임 오류 텍스트에 전체 요청 URL이나 응답 본문 조각이 들어갈 수 있기 때문이에요. 전송이 실패할 때 기록되는 `exception` 이벤트에도 같은 규칙이 적용돼요. 기록하지 않는 span(종료됐거나 샘플링되지 않은 경우)의 실패는 `diag.error`를 통해 OpenTelemetry 진단 로거로 전달돼요. 이를 받으려면 애플리케이션에서 `@opentelemetry/api`의 `diag.setLogger(...)`를 설정해야 해요. 기본적으로 자동 출력되지 않아요. 패키지는 SDK를 초기화하지 않으며 이 진단은 별도의 SDK `LogRecord`가 아니에요.

`responseHook`은 전송이 돌려준 값을 받아요. HTTP는 `HttpResponse`, SSE는 시작에 성공한 뒤의 스트림 핸들, WebSocket은 열린 뒤의 세션이에요. 세 번째 인자는 원래의 요청이에요.

기본적으로 `url.full`은 `request.endpoint`만 선택적인 `request.baseEndpoint`에 대해 해석해요. `request.query`는 덧붙이지 않아요. 이 경계는 쿼리 민감 정보 제거가 아니에요. OpenTelemetry 시맨틱 컨벤션이 요구하듯, 엔드포인트 userinfo의 자격 증명은 `REDACTED:REDACTED`로 바뀌고, 기본 민감 쿼리 키(`sig`, `Signature`, `AWSAccessKeyId`, `X-Amz-Signature`, `X-Amz-Credential`, `X-Amz-Security-Token`, `X-Goog-Signature`)의 값은 `REDACTED`로 바뀌지만, 패키지에는 그 밖의 내장 제거기나 민감 키 정책이 없어요. `startSpanHook`이 돌려준 `url.full`도 같은 방식으로 제거되지만, 애플리케이션이 `requestHook`이나 `responseHook`에서 `Span` 객체로 쓰는 URL은 가로채지 않으므로, 직접 만들고 필요하면 명시적으로 민감 정보를 제거하세요.

## 로거 진단

최상위 `logger?: Logger` 옵션은 애플리케이션 로거가 아니라 `@opentelemetry/api-logs`를 써요. 선택 사항이고 단독으로 쓸 수 있어요. Defjs는 전역 로거를 얻지도, 프로바이더를 소유하지도 않아요. 실패한 작업 호출마다, 그리고 열린 뒤에 실패한 SSE 스트림이나 WebSocket 세션마다 `WARN` LogRecord(심각도 13)를 하나씩 내보내요. 메시지는 각각 고정이에요.

| 결과                                                                  | 이벤트                                                            | 속성                                                                                                                  |
| --------------------------------------------------------------------- | ----------------------------------------------------------------- | --------------------------------------------------------------------------------------------------------------------- |
| 작업 호출이 `NET_ABORTED`가 아닌 결함으로 resolve됨                   | `defjs.client.operation.exception`                                | `defjs.operation.name`, `error.type`(결함 코드), `exception.type`, `defjs.meta.*`                                     |
| SSE 스트림 또는 WebSocket 세션이 오류로 끝남 (reject된 `closed` 포함) | `defjs.client.sse.exception` / `defjs.client.websocket.exception` | `server.address`, `server.port`, `exception.type`, `defjs.meta.*`, `defjs.sse.fault.code` 또는 `websocket.close.code` |

성공, 이후 시도가 복구한 재시도 시도, 정상 종료, EOF, 코드와 관계없이 서버가 보낸 WebSocket close 프레임, 호출자의 취소는 LogRecord를 만들지 않아요. close 프레임 없이 갑자기 끊기는 WebSocket(1006)은 세션이 오류로 끝나고 모든 런타임에서 한 번 기록해요. 작업 레코드는 작업 span의 컨텍스트와 함께 내보내요.

`includeErrorDiagnostics: true`이면 모든 레코드에 `exception.message`와 `exception.stacktrace`도 담겨요. 작업 호출에서는 결함의 `message`와 `stack`이에요. 원인 체인과 오류의 열거 가능한 필드는 내보내지 않지만, 메시지는 걸러지지 않아요. 결함의 메시지는 흔히 그 원인의 메시지이고, 플랫폼 오류 텍스트는 요청 URL을 인용할 수 있어요. 필터, 익스포터, flush, shutdown은 애플리케이션이 관리해요.

로그와 서드파티 로거 연동의 전체 예제는 [OpenTelemetry 가이드](/ko-KR/docs/integrations/opentelemetry-server#logs-and-third-party-loggers)를 보세요.
