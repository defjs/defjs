---

<ApiReference identity="@defjs/core:ClientConfig" />

```ts
interface ClientConfig {
  endpoint: string
  headers?: Headers
  http: { handle: FetchHandle }
  interceptors: Interceptor[]
  querySerializer?: QuerySerializer
  timeout?: number
  withCredentials?: boolean
  xsrf?: {
    cookieName: string
    headerName: string
    tokenProvider?: (context: { request: HttpRequest }) => string | null | undefined
  }
  sse: ClientSSEConfig
  webSocket: ClientWebSocketOptions
}
```

`createClient`가 만들고 모든 option 헬퍼가 변경하는, 해석된 스냅샷이에요. HTTP 멤버는 export되지 않는 `HttpClientConfig` 기반 타입에서 오며 여기서는 인라인으로 보여줘요.

option이 하나도 적용되기 전에는 `endpoint`가 `''`, `interceptors`가 빈 배열이고, `http.handle`과 `sse.handle`은 호출마다 `globalThis.fetch`를 해석하는 기본 래퍼를 공유해요. import 뒤에 Fetch를 바꿔도 두 기본값에 모두 반영돼요. Fetch 없이도 Core를 import할 수 있어요. 그래도 Fetch가 없으면 기본 HTTP/SSE 실행은 `ENV_UNSUPPORTED`로 실패해요. 사용자 지정 handle은 전역 Fetch가 없어도 쓸 수 있어요. `webSocket.handle`은 `globalThis.WebSocket`이고 나머지 `webSocket` 설정은 비어 있어요. `withXSRF`는 생략된 `xsrf.cookieName`을 `XSRF-TOKEN`으로, `xsrf.headerName`을 `X-XSRF-TOKEN`으로 채워요.
