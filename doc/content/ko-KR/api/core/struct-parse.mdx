description: 'unknown 값을 struct로 파싱하고 error-first 튜플을 돌려줘요.'
---

<ApiReference identity="@defjs/core:struct.parse" />

```ts
function parse<S extends StructLike<unknown, unknown, boolean>>(
  struct: S,
  value: unknown,
  options?: { aliases?: boolean; errorMap?: ErrorMap },
): ParseResult<S['_struct']['output']>
```

- **struct**는 파싱에 쓸 struct예요. struct가 아닌 값은 `TypeError`를 던져요.
- **value**는 unknown 입력이에요.
- **options.aliases**의 기본값은 `false`예요. 객체 키를 **논리** 이름(`displayName`)으로 읽어요. `true`이면 HTTP/JSON 코덱처럼 와이어 이름(`display_name`)으로 읽어요. 출력은 항상 논리 이름을 써요.
- **options.errorMap**은 이번 호출에 한해 issue 메시지를 다시 쓰는 [`ErrorMap`](/ko-KR/api/core/errormap-type)이에요. 다른 Core 사본이 만든 struct의 bigint/date 변환 실패도 포함해요. `''`를 포함한 어떤 문자열이든 message를 대체하고, `undefined`만 기본값을 유지해요. 사용자 텍스트는 그대로 쓰여요.
- **반환값**은 `[null, output]` 또는 `[StructError, undefined]`예요. 검증 실패는 예외를 던지지 않아요. 호출자가 제공한 getter와 `errorMap` 콜백의 예외는 그대로 전파돼요.
- 파싱은 fail-fast예요. 처음 실패에서 멈추므로 error에는 issue가 하나만 들어 있어요. 알 수 없는 객체 키는 출력에서 제거되고, 입력은 수정하지 않아요.
- 한 경로를 따라 최대 **256개의 중첩 컨테이너**(`object`, `array`, `record`, `tuple`)를 방문하며, 루트 컨테이너를 첫 번째로 세어요. 그다음 컨테이너는 해당 논리 경로에서 `invalid_type`으로 실패하고 `expected: 'value nested at most 256 levels deep'`를 가져요. 유니온에서는 뒤의 후보가 여전히 성공할 수 있고, 아무 후보도 일치하지 않으면 유니온이 `invalid_union`을 보고해요. 선언된 컨테이너 필드를 거치는 순환도 이 한도에 도달하지만, 순환하지 않는 자식 노드를 공유하는 것은 허용돼요. 유니온과 교차의 분기는 컨테이너 깊이를 늘리지 않으며, `any`/`unknown` 값은 불투명한 값으로 취급해 순회하지 않아요.

```ts
const [error, user] = struct.parse(User, { id: 1, displayName: 'Ada' })
if (error) return console.error(error.prettify())
```

`any`와 `unknown`은 자신의 값을 순회하지 않지만, 교차에서는 이런 리프 노드가 반환한 서로 다른 두 객체 또는 배열 값을 재귀적으로 병합할 수 있어요. 이 병합은 바깥쪽 논리 경로와 동일한 256개 컨테이너 한도를 공유해요. 한도를 초과하면 거부된 컨테이너의 논리 경로에서 `invalid_intersection`이 발생해요. 동일한 참조는 순회하지 않고 유지하며, 공유된 값이 순환을 포함해도 마찬가지예요.
