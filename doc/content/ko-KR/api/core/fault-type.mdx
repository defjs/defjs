<ApiReference identity="@defjs/core:Fault" />

```ts
type Fault<TErr extends AnyStruct | undefined = undefined> = FaultOf<[TErr] extends [undefined] ? undefined : Infer<TErr>>
```

`TErr`는 엔드포인트가 선언한 `error` struct이고, 선언하지 않았다면 `undefined`예요. `Fault<TErr>`는 디코딩된 body 타입에 [`FaultOf`](/ko-KR/api/core/faultof-type)를 적용한 것이라서, 세 변형의 유니온이에요. [`DecodeFault`](/ko-KR/api/core/decodefault-type), [`HttpStatusFault<TErr>`](/ko-KR/api/core/httpstatusfault-type), [`PreflightFault`](/ko-KR/api/core/preflightfault-type)예요. `fault.code`로 switch 하세요.

모든 변형은 `DefjsFault`라는 이름의 네이티브 `Error`라서, `String(fault)`가 `DefjsFault: <message>`를 줘요. `code`와 각 변형의 메타데이터 — `status`, `response`, `data` — 는 열거 가능한 자체 속성이에요. 네이티브 `cause` 체인은 열거되지 않아요.

기본 Struct message는 받은 값이 아니라 `received <kind>`라고 말해요. `RES_DECODE_FAILED` 뒤에 JSON `SyntaxError`가 있으면 fault message는 `Response body could not be decoded`예요. 구조를 나타내는 path에는 record 키가 남으며, 이 키는 민감 정보일 수 있어요. 원본 `StructIssue.received`와 파서 cause는 민감하게 남아요. 사용자 `errorMap`과 extension message는 그대로 쓰이므로 로깅 전에 검토가 필요해요.
