<ApiReference identity="@defjs/core:EventStreamHandle" />

```ts
interface EventStreamHandle<TEvent = EventStreamMessage> extends AsyncIterable<TEvent>, AsyncDisposable {
  readonly open: EventStreamOpenInfo
  readonly closed: Promise<EventStreamCloseInfo>
  close(reason?: unknown): void
  [Symbol.asyncDispose](): PromiseLike<void>
}
```

`EventStreamMessage`는 원시 `{ id: string; event: string; data: string }` 메시지예요. `client.execute`가 반환하는 handle은 파싱된 [`EventStreamData`](/ko-KR/api/core/eventstreamdata-type)를 지녀요.

`open`은 시작 스냅샷([`EventStreamOpenInfo`](/ko-KR/api/core/eventstreamopeninfo-type))이에요. 재연결 뒤에는 바뀔 수 있으니 `stream.open`을 다시 읽으세요. `closed`는 스트림이 끝나면 [`EventStreamCloseInfo`](/ko-KR/api/core/eventstreamcloseinfo-type)로 resolve돼요.

소유한 범위를 정리할 때는 `await using stream = handle`을 권장해요. disposer는 Defjs의 읽기와 재연결 작업을 멈추고 reader lock이 풀릴 때까지 기다려요. provider가 제어하는, 멈춰 버린 `ReadableStream.cancel()` promise가 끝난다고 약속하지는 않아요. 수동 `close()` / `closed`도 그대로 쓸 수 있어요.

```ts
async function consume(handle: EventStreamHandle<unknown>): Promise<void> {
  await using stream = handle
  for await (const event of stream) console.log(event)
}
```

`EventStreamHandle`의 구조적인 구현은 `[Symbol.asyncDispose]()`를 구현하고 같은 소유 teardown 경로를 반환해야 해요. 이는 사용자 지정 handle에 대한 컴파일 타임 요구 사항이에요. Defjs가 반환한 handle만 받는 코드는 런타임에 새로 호출할 것이 없어요.
