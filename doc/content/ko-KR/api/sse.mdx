# SSE

이벤트 스트림을 선언하고, 실행하고, 이벤트를 순회한 뒤 닫아요.

## defineEventStream()

```ts
function defineEventStream(definition: EventStreamDefinition): EventStreamEndpoint
```

- **definition** — `path`, `events` map, 필수인 양의 정수 한도 `maxBufferSize`와 `maxQueueSize`, 선택 `method`(기본 `'GET'`), `operation`, `input`, `error`예요. `input`을 선언하면 입력이 이미 요청 모양이어도 명시적인 `builder`가 반드시 필요해요. `input`이 없는 정의만 `builder`를 생략할 수 있어요.
- **반환** 엔드포인트예요. 입력을 넣어 호출하면 `EventStreamCommand`가 나와요.

## executeEventStreamCommand()

```ts
function executeEventStreamCommand(
  clientConfig: ClientConfig,
  command: EventStreamCommand,
  options?: EventStreamExecuteOptions,
): Promise<StreamAwaitResult>
```

`client.execute`의 저수준 진입점이에요. 애플리케이션 코드에서는 클라이언트를 쓰는 편이 좋아요.

- **반환** `[null, stream, open]` 또는 `[error, undefined, open?]`예요. `error`를 선언하면 fault는 그 struct의 `Fault`이고, 아니면 `Fault<undefined>`예요.

## 실행 options

## EventStreamExecuteOptions

```ts
type EventStreamExecuteOptions = ({ abort?: AbortSignal; timeout?: never } | { abort?: never; timeout?: number }) & {
  signal?: AbortSignal
}
```

취소 규칙은 HTTP와 같아요. `abort` 또는 `timeout`이지, 둘 다가 아니에요 (타입이 둘 다 주는 것을 막고, 런타임에 둘 다 넘기면 `REQ_OPTIONS_INVALID`로 실패해요). `signal`은 어느 쪽과도 합쳐져요. `timeout`은 시작 데드라인이에요. 입력 파싱, builder, interceptor, 핸드셰이크를 포함하고, 이미 열린 스트림을 abort하지는 않아요. `withTimeout`은 SSE에 적용되지 않아요.

## EventStreamHandle

```ts
interface EventStreamHandle<TEvent> extends AsyncIterable<TEvent>, AsyncDisposable {
  readonly open: EventStreamOpenInfo
  readonly closed: Promise<EventStreamCloseInfo>
  close(reason?: unknown): void
  [Symbol.asyncDispose](): PromiseLike<void>
}
```

튜플의 세 번째 자리는 `open`의 시작 스냅샷이고, `stream.open`은 재연결 뒤 최신 연결을 따라가요. `startupOpen`이 반환된 handle의 연결에서 처음 성공한 핸드셰이크의 스냅샷인 것은 Defjs 네이티브 handle이나 동일한 live `open` 객체를 그대로 전달하는 래퍼일 때뿐이며, 커스텀 handle이나 `open`을 재정의하는 래퍼는 재연결 뒤에도 현재 공개한 `open`을 유지하므로 `closed` 공유로 URL 정제나 헤더 필터링을 우회할 수 없고 Defjs는 임의의 변환으로부터 최초 핸드셰이크 메타데이터를 복원하지 않아요. 소유한 범위를 정리할 때는 `await using stream = handle`을 선호해요. disposer는 Defjs의 읽기와 재연결 작업을 멈추고 reader lock이 풀릴 때까지 기다려요. provider가 붙잡고 끝나지 않는 `ReadableStream.cancel()` promise가 끝난다고 약속하지는 않아요. 수동 `close()` / `closed`도 그대로 쓸 수 있어요.

```ts
async function consume(handle: EventStreamHandle<unknown>): Promise<void> {
  await using stream = handle
  for await (const event of stream) console.log(event)
}
```

`EventStreamHandle`의 구조적 구현은 이제 `[Symbol.asyncDispose]()`를 구현하고 같은 소유 teardown 경로를 돌려줘야 해요. 커스텀 handle에는 컴파일 타임 breaking change예요. Defjs가 돌려준 handle만 받는 코드는 런타임에 새 호출이 필요 없어요.

### EventStreamOpenInfo

```ts
interface EventStreamOpenInfo {
  response: HttpResponse<unknown>
  url: string
}
```

### EventStreamCloseInfo

```ts
type EventStreamCloseInfo =
  | { kind: 'eof'; reason?: string; cause?: unknown }
  | { kind: 'aborted'; reason?: string; cause?: unknown }
  | { kind: 'error'; code: EventStreamFaultCode; reason?: string; cause?: unknown }
```

`EventStreamFaultCode`: `'CAP_BUFFER_EXCEEDED' | 'CAP_QUEUE_OVERFLOW' | 'EXT_HOOK_FAILED' | 'EXT_OBSERVER_FAILED' | 'NET_TIMEOUT' | 'NET_UNREACHABLE' | 'RES_DECODE_FAILED' | 'RES_MEDIA_TYPE_INVALID'`.

## 이벤트 map

## EventStructs

```ts
type EventStructs = { [eventName: string]: AnyStruct }
```

키는 SSE 이벤트 이름이에요. `event:` 필드가 없는 메시지의 이름은 `message`예요. 일치하는 키가 없으면 `default` struct를 써요. `string` 이벤트 struct는 raw `data` 텍스트를 유지해요. 그 밖의 kind는 JSON 텍스트예요. `JSON.parse`한 뒤 struct를 적용해요. 그래서 bare `struct.literal`에는 따옴표 없는 토큰이 아니라 JSON 텍스트가 필요해요. 핸드셰이크 `error` body는 HTTP와 같은 kind 규칙을 써요. `string`은 텍스트, `blob` / `file`은 blob, `arrayBuffer`는 바이트, 그 밖은 JSON이에요.

재연결은 클라이언트에 있어요 (`withSSEReconnect`). SSE `jitter`는 WebSocket과 같은 **0–1 곱셈 계수**예요.

재시도 예산과 백오프 지수는 핸드셰이크가 성공한 뒤 초기화되고, 단절마다 적용돼요. 잘못된 숫자 옵션은 스트림을 열기 전에 `REQ_OPTIONS_INVALID`를 반환하고, `maxDelayMs`는 jitter 뒤의 최종 지연을 제한해요. 검증 규칙, 기본값, UTF-8 `Last-Event-ID` 처리는 [`withSSEReconnect`](/ko-KR/api/core/withssereconnect)를 보세요.

파서는 WHATWG SSE 줄과 필드 규칙을 따르고, 각 물리 스트림의 시작에서 선행 UTF-8 BOM 하나만 제거해요. data나 ID 값 안의 U+FEFF는 유지되고, 뒤에 나오는 BOM이 붙은 필드 이름은 알 수 없는 필드로 무시돼요. 여러 줄 data는 `\n`으로 이어지고, 빈 줄은 data가 있는 이벤트를 내며, EOF의 미완성 이벤트는 버려져요.

[SSE 가이드](/ko-KR/docs/sse)와 [SSE 스트림 소비하기](/ko-KR/recipes/consume-sse)를 보세요.

## EventStreamDefinition

`path`, `events`, 필수 `maxBufferSize`와 `maxQueueSize`, 선택 `method` / `operation` / `input` / `error`예요. 요청 모양은 `body`를 포함해 HTTP와 같아요. `GET`과 `HEAD`는 body를 돌려줄 수 없어요. `input`을 선언하면 입력이 이미 요청 모양이어도 명시적인 `builder`가 반드시 필요해요. `input`이 없는 정의만 `builder`를 생략할 수 있어요.

## EventStreamEndpoint

`defineEventStream`이 돌려줘요. 입력을 넣어 호출하면 `EventStreamCommand`가 나와요.

## EventStreamRequestShape

스트림의 method와 path에 대한 `HttpRequestShape`와 같은 필드예요.

## EventStreamCommand

opaque SSE 명령이에요. `client.execute`에 넘기세요.

## StreamAwaitResult

`[null, stream, open]` 또는 `[error, undefined, open?]`예요.

## EventStreamData
