# HTTP

타입이 있는 요청을 선언한 다음, 클라이언트와 입력으로 작업을 호출해요.

## defineRequest()

<ApiSignature name="defineRequest" />

- **definition** — `method`, `path`, 선택 `input` struct, 선택 `output`과 `error` struct, 선택 `operation`이에요. `input`을 선언하면 명시적인 `builder`가 반드시 필요해요. `input`은 인자만 정의하고, 각 값을 어디에 둘지는 `builder`만 정해요. `input`이 없는 정의만 `builder`를 생략할 수 있어요. 이 `definition` 멤버는 [`RequestDefinition`](/ko-KR/api/core/requestdefinition-type)에 적혀 있어요. `builder`는 `input`을 선언했을 때만 필요해요.
- **반환** 작업이에요. 입력이 없으면 `health(client)`처럼, 있으면 `getOrder(client, input)`처럼 호출해요. 입력 struct 전체가 선택이면 입력 인자를 생략할 수 있어요. 호출하면 요청이 시작돼요. 세 번째 옵션 인자는 없어요.

<include cwd>examples/api/define-request.ts#example</include>

`output`은 2xx 본문을 위한 struct 하나이고, `error`는 모든 비2xx 본문을 위한 struct 하나예요. 둘 다 상태 코드로 키를 나누지 않아요. 하나를 빼면 그 본문은 읽히지 않아요 — [선언은 단언이에요](/ko-KR/docs/design-decisions#declaration-is-an-assertion)를 보세요.

작업을 호출하면 [`HttpAwaitResult`](/ko-KR/api/core/httpawaitresult-type)에 적힌 튜플을 담은 Promise가 돌아와요. 호출별 옵션은 [`RequestOptions`](/ko-KR/api/core/requestoptions-type)로 클라이언트를 파생해서 넘기세요. HTTP는 `signal`과 진행률 콜백만 읽고 나머지 필드는 무시해요.

비2xx 상태 코드는 `error` struct를 선언하지 않았거나 선언한 `error` 본문이 디코딩되면 `HTTP_STATUS`예요. 결함의 `data`는 선언됐을 때 디코딩된 `error` 본문이고, 아니면 `undefined`예요. 선언한 `error` 본문을 읽을 수 없거나(미디어 타입 불일치, 잘못된 JSON) struct와 맞지 않으면 결함은 대신 `RES_MEDIA_TYPE_INVALID`, `RES_DECODE_FAILED`, `RES_STRUCT_MISMATCH` 중 하나이고, 응답 상태 코드는 그 메타데이터에 그대로 담겨요. 실패하면 튜플의 세 번째 자리는 `undefined`이고, 결함이 응답 메타데이터를 가져요.

## fetchHandler()

<ApiSignature name="fetchHandler" />

기본 HTTP 전송이에요. `fetchImpl`의 기본값은 보내는 시점에 해석되는 전역 `fetch`이고, `withHTTPHandle`로 다른 것을 줄 수 있어요. 손대지 않은 플랫폼 Fetch는 `(url, init)`을 받고, 교체된 전역이나 사용자 지정 핸들은 `Request`를 받아요. 응답이 클라이언트에 닿지 않았거나 선언된 본문을 읽는 데 실패하면 합성 응답으로 resolve하지 않고 reject해요.

## makeResponse()

<ApiSignature name="makeResponse" />

네트워크 호출 없이 `HttpResponse`를 만들어요 (인터셉터, 테스트). 기본 상태 코드는 `0`이에요. `ok`는 2xx일 때 true예요. 반환값은 와이어에서 온 응답과 같은 미디어 타입 검사와 같은 선언된 struct를 거쳐요. 신뢰할 수 있는 단락(short-circuit)은 없어요.

## HttpExecuteOptions

<ApiSignature name="HttpExecuteOptions" />

`HttpExecuteOptions`는 [`RequestOptions`](/ko-KR/api/core/requestoptions-type)의 HTTP 조각인 [`UseRequestConfig`](/ko-KR/api/core/userequestconfig-type)예요. `signal`과 `onDownloadProgress`, `onUploadProgress`, `retry`예요. `timeout`이나 `abort` 필드는 없어요. 데드라인은 `signal: AbortSignal.timeout(ms)`이고 `NET_TIMEOUT`으로 분류돼요. 수동 취소는 `NET_ABORTED`예요. `signal`은 그 호출의 신호예요. 신호는 애플리케이션 코드에서 `AbortSignal.any`로 합치세요. 클라이언트 기본 데드라인은 없어요. `heartbeat` 같은 다른 요청 필드는 무시돼요.

## 타입

### RequestDefinition

`method`, `path`, 선택 `input`, `output`, `error`, `operation`, `builder`예요. struct kind가 선언된 본문을 어떻게 읽을지 골라요. `input`을 선언하면 명시적인 `builder`가 반드시 필요해요. `input`은 인자만 정의하고, 각 값을 어디에 둘지는 `builder`만 정해요. `input`이 없는 정의만 `builder`를 생략할 수 있어요.

### HttpAwaitResult

<ApiSignature name="HttpAwaitResult" />

성공하면 세 번째 자리는 `output`을 선언했을 때만 `body`를 가져요. 실패하면 `undefined`예요 — 결함이 이미 있던 응답 메타데이터를 들고 있어요.

### HttpRequest

정규화된 나가는 요청이에요. `method`, `endpoint`, `headers`, `body`, `signal`, `operation`, `withCredentials`, `finalizeHeaders`, `downloadProgress` / `uploadProgress`, `baseEndpoint`, `query`예요. 인터셉터가 볼 시점에 `body`는 이미 와이어 값이에요. JSON이면 JSON 텍스트 문자열이므로, HMAC이나 다이제스트는 struct 입력이 아니라 이 값을 기준으로 서명하세요. `query`는 요청이 보내는 유일한 쿼리이고 `URLSearchParams`예요. 인터셉터는 이를 그 자리에서 바꾸거나 대체 값을 `next()`에 넘겨요. `builder`가 `URLSearchParams`를 돌려주면 그 인스턴스는 복사되고, `withQuerySerializer` 함수가 돌려준 문자열은 그 안으로 파싱돼요. 와이어 형태는 `query.toString()`, 즉 URL Standard의 application/x-www-form-urlencoded 직렬화라서 공백은 `+`이고, 비어 있는 `query`는 `?`를 붙이지 않아요. `responseType`과 `errorResponseType`은 readonly예요. 선언된 `output`과 `error` struct kind에서 유도되며, 바꾸면 안 돼요.

### HttpMeta

<ApiSignature name="HttpMeta" />

응답이 클라이언트에 닿을 때마다 있는 응답 메타데이터예요. **`body`는 없어요**. 본문은 선언된 struct가 하나를 디코딩한 뒤에만 존재해요.

### DecodedResponse

<ApiSignature name="DecodedResponse" />

선언된 struct에 대해 본문이 디코딩된 응답이에요. 이 타입을 들고 있다는 것은 디코딩이 일어났다는 증거라서, 디코딩 실패는 `HttpMeta`만 보고해요.

### HttpResponse

<ApiSignature name="HttpResponse" />

`body`는 응답에 본문이 없으면 값이 `undefined`, JSON `null`은 `null` 그대로예요. 이 타입에는 브랜드가 붙어 있으므로 객체 리터럴 대신 `makeResponse`로 만드세요. 전송이 만들고 인터셉터가 보는 와이어 모양이에요. `body`는 텍스트이거나 이미 파싱된 JSON이지, 디코딩된 값이 아니에요. JSON 표현에서 문자열은 JSON 문자열 루트라서 다시 파싱하지 않아요. 바이트와 Blob은 원시 값이라 한 번만 파싱해요. 호출자에게 닿는 것은 `DecodedResponse`예요.

### HttpProgressEvent

### HttpProgressFn

`loaded`, `total`, `lengthComputable`이에요. 콜백은 비동기 함수일 수 있어요. `onDownloadProgress`나 `onUploadProgress`에서 예외를 던지면 던진 값을 `cause`로 담아 호출이 `EXT_OBSERVER_FAILED`로 실패해요. 취소는 여전히 `NET_ABORTED`를 보고하고, abort 이유가 타임아웃이면 `NET_TIMEOUT`을 보고해요. 업로드 진행률은 요청 본문이 직접 넘긴 `ReadableStream`일 때만 보고돼요. 그 밖의 본문(`Blob`, `File`, `ArrayBuffer`, `FormData`, 문자열, `URLSearchParams`)은 만든 그대로 보내지고, 모든 런타임에서 `onUploadProgress`는 호출되지 않아요. 라이브러리는 본문을 스트림으로 바꾸지 않아요. `ReadableStream` 본문은 `onUploadProgress` 유무와 관계없이 스트리밍 요청 본문의 Fetch 규칙을 따라요. Chromium과 WebKit은 HTTP/2 이상에서만 받아들이고, HTTP/1.1에서는 `NET_UNREACHABLE`이에요(WebKit은 27.2에서만 수동으로 확인했어요. Node.js와 Bun은 HTTP/1.1을 받아들여요). Firefox는 요청 본문을 스트리밍할 수 없어 `ENV_UNSUPPORTED`예요. 브라우저에서 교차 출처 요청은 캐시된 preflight 결과가 없으면 CORS preflight가 필요하므로 서버가 `OPTIONS`에 응답해야 해요. 301, 302, 307, 308 리다이렉트는 본문을 한 번 보낸 뒤 실패하고, 303은 GET이 되어 성공해요. 브라우저는 `Content-Length`를 보내지 않아요. `fetch`는 이런 실패와, `fetch`가 읽는 동안 throw하는 원본 `ReadableStream`을 도달할 수 없는 엔드포인트와 같은 네트워크 오류로 보고하므로, 로드 밸런서는 이것들에 `{ attempted: false }`를 받아요. throw하는 진행률 콜백(`EXT_OBSERVER_FAILED`)도 같아요. 따라서 스트리밍 업로드만으로는 다운된 엔드포인트를 감지할 수 없고, 거절된 스트리밍 업로드는 재시도되지 않아요. `ReadableStream` 본문은 `shouldRetry`에 묻기 전에 재시도 흐름을 끝내요.

스트리밍 본문은 길이를 알 수 없어요. 유효한 명시적 `Content-Length` 헤더가 지정하지 않으면 보고되는 total은 알 수 없고, 브라우저는 그 헤더를 보내지 않아요. `loaded`는 서버 확인이 아니라 스트림 바이트를 세요. identity가 아닌 `Content-Encoding`의 다운로드는 `total: 0`과 `lengthComputable: false`를 보고하고, 스트림 바이트는 이미 압축이 풀려 있을 수 있어요.

[HTTP 가이드](/ko-KR/docs/http)와 [Client](/ko-KR/docs/client)를 보세요.

## RequestEndpoint

`defineRequest`가 돌려줘요. 첫 인자는 [`Client`](/ko-KR/api/core/client-type)예요. 그 뒤 인자는 입력뿐이에요.

## BuilderInput

`builder`가 보는, 파싱된 작업 입력이에요. 객체 노드는 자신을 만든 struct를 지니므로 별칭, `Date`, `bigint` 인코딩이 그 값을 따라가요.

## HttpRequestShape

<ApiSignature name="HttpRequestShape" />

네 필드는 모두 선택이에요. `query`는 `URLSearchParams` 또는 레코드예요. 중첩 객체는 런타임에 `withQuerySerializer`가 필요해요. `headers`는 `HeadersInit`이거나, 스칼라 또는 스칼라 배열의 레코드예요. `path`는 `:name` 구간마다 스칼라 하나를 넣어요.

`GET`과 `HEAD`의 `body`는 `never`예요. 그 외에는 와이어 값(`string`, `Blob`, `ArrayBuffer`, typed array 또는 `DataView`, `FormData`, `URLSearchParams`, `ReadableStream<Uint8Array>`)이거나 JSON 데이터(`number`, `boolean`, `bigint`, `Date`, `null`, 배열, 문자열 키를 가진 객체)예요.

## UseRequestConfig

`signal`과 선택 `onDownloadProgress`, `onUploadProgress`, `retry`예요. `HttpExecuteOptions`가 이 조각이에요. `timeout`이나 `abort` 필드는 없어요.

## RequestSuccessData

선언된 `output` struct에서 추론한 성공 본문이에요. 선언이 없으면 `undefined`예요.

## RequestErrorData

선언된 `error` struct에서 추론한 오류 본문이에요. 선언이 없으면 `undefined`예요.

## HttpResponseType

`'arraybuffer' | 'blob' | 'json' | 'text'`

선언된 struct kind에서 골라요 (`string` → `text`, `blob` / `file` → `blob`, `arrayBuffer` → `arraybuffer`, 그 밖은 `json`). `defineRequest`의 필드가 아니에요.

## MakeResponseOptions

`makeResponse`의 필드예요. `status`, `statusText`, `url`, `headers`, `body`, `request`.
