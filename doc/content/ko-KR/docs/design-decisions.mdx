# 핵심 아키텍처

Defjs는 하나의 근본적인 경계를 중심으로 구축되었습니다: **SDK는 통신 계약(wire contract)을 정의하고, 사용하는 애플리케이션이 실행 환경을 소유합니다.** `@defjs/core`의 모든 설계 원칙은 바로 이 분리에서 시작됩니다.

## 1. 정의 vs. 실행

SDK 패키지는 작업(`defineRequest`, `defineEventStream`, `defineWebSocket`)과 데이터 계약(`struct`)을 export합니다. SDK 모듈 안에서 `createClient`를 호출하거나 싱글톤 클라이언트를 보관하거나 환경 변수를 읽는 일은 절대 없습니다.

`getOrder`는 어떤 클라이언트 상태도 캡처하지 않기 때문에:

- 브라우저 UI, 백그라운드 작업, SSR 요청 핸들러, 단위 테스트 모두 동일한 `getOrder` 작업을 각기 다른 `Client` 설정으로 호출할 수 있습니다.
- 프레임워크 플러그인(`@defjs/react`, `@defjs/vue`)과 관측성 미들웨어 플러그인(`@defjs/opentelemetry-server`)은 애플리케이션의 `Client`에 연결되므로, 배포된 SDK 패키지는 의존성이 전혀 없는(100% dependency-free) 상태를 유지합니다.

## 2. 명시적인 입력 배치와 양방향 별칭(alias)

Defjs에서 `input`은 호출자가 전달하는 값을 선언하고, `struct`는 값이 인코딩/디코딩되는 방식을 제어하며, `builder`는 각 값을 요청(`path`, `query`, `headers`, `body`)의 어느 위치에 둘지 배치합니다.

- **마법 같은 추론은 없다**: 작업에 `input`을 선언했다면 반드시 동기 순수 함수인 `builder`를 명시적으로 제공해야 합니다. 매개변수 이름을 바탕으로 요청 위치를 임의로 추측하지 않습니다.
- **양방향 `.alias(wireName)` 지원**: struct 필드에 `.alias("customer_name")`을 선언하면 TypeScript 코드에서는 카멜케이스인 `customerName`을 유지하면서, 통신 시에는 `"customer_name"`으로 자동 인코딩되고 응답으로부터 다시 디코딩됩니다.

## 3. 선언은 곧 단언이다 [#declaration-is-an-assertion]

Defjs가 HTTP 응답을 읽는 방식에는 6가지 엄격한 규칙이 적용됩니다:

### 규칙 1: 선언한 것이 곧 단언(assertion)이다

`output`은 `2xx` 응답 본문의 형태를 단언합니다. `error`는 `2xx`가 아닌 응답 본문의 형태를 단언합니다. 이러한 선언은 단순한 힌트가 아니라 런타임 보장입니다.

### 규칙 2: `ok` (`200..299`)만이 유일한 분기 기준이다

`2xx` 응답은 오직 `output`으로만 디코딩됩니다. 그 외의 모든 상태 코드(`3xx`, `4xx`, `5xx`)는 오직 `error`로만 디코딩됩니다. Defjs는 둘 사이에서 대체 동작(fallback)을 절대 시도하지 않습니다.

### 규칙 3: 단언에서 벗어난 모든 경우는 명확한 결함으로 처리된다

Defjs는 `response.ok`로 응답 쪽을 고릅니다. `2xx`는 `output`, `2xx`가 아니면 `error`입니다. 그 쪽에 선언된 JSON struct만 디코딩을 일으키고 `RES_MEDIA_TYPE_INVALID` 또는 `RES_DECODE_FAILED`를 낼 수 있으며, 그 `Content-Type`은 본문을 읽거나 찾기 **전에** 먼저 검증합니다. 내용이 없는 응답(`HEAD`, `204`, `205`, `304`)도 같은 검사를 받습니다. 선언된 JSON 표현에 JSON `Content-Type`이 없으면 `RES_MEDIA_TYPE_INVALID`로 실패하고, 있으면 빈 바이트를 파싱해 `RES_DECODE_FAILED`로 실패합니다. `2xx`가 아닌 HTML 게이트웨이 페이지는 JSON `error` struct가 선언된 경우에만 `RES_MEDIA_TYPE_INVALID`를 냅니다. 활성 쪽에 선언이 없으면 본문을 읽지 않으며, `2xx`가 아닌 응답은 디코딩되지 않은 `HTTP_STATUS`를 반환합니다. SSE 핸드셰이크도 같은 규칙을 따릅니다. 선언된 `error` 본문을 디코딩할 수 없는 비`2xx` 핸드셰이크는 시작 시 그 디코딩 결함을 반환하고 메타데이터에 상태를 담으며, 인터셉터, 재연결 정책, 재연결의 `closed`는 여전히 `HTTP_STATUS`를 봅니다.

| 응답을 읽는 도중 실패한 원인                       | 반환되는 결함                                                                            |
| -------------------------------------------------- | ---------------------------------------------------------------------------------------- |
| 미디어 타입이 선언된 JSON 표현과 일치하지 않음     | `RES_MEDIA_TYPE_INVALID` (먼저 검사함. 본문은 읽지 않으며, 내용이 있든 없든 차이가 없음) |
| 바이트를 선언된 표현 형식으로 디코딩할 수 없음     | `RES_DECODE_FAILED` (빈 JSON 바이트 포함)                                                |
| 디코딩된 값이 `struct` 스키마 검증을 통과하지 못함 | `RES_STRUCT_MISMATCH`                                                                    |
| 디코딩된 `error` struct를 포함한 비`2xx` 상태 코드 | 타입화된 `error.data`를 포함하는 `HTTP_STATUS`                                           |
| `error`가 선언되지 않은 비`2xx` 상태 코드          | `error.data: undefined`인 `HTTP_STATUS`                                                  |

### 규칙 4: 디코딩에 실패하면 본문도 존재하지 않는다

본문은 디코딩과 검증을 통과한 후에만 존재합니다. 디코딩이 실패하면 결함 객체의 `response`는 `HttpMeta` 타입(`body` 프로퍼티가 없음)이 되며, 파서/유효성 검증 오류는 `fault.cause`에 첨부됩니다.

### 규칙 5: 한쪽을 생략하는 것은 해당 본문을 읽지 않겠다는 선택이다

`output`을 생략하면 `2xx` 본문을 아예 읽지 않습니다. `error`를 생략하면 서버가 `500`에서 잘못된 JSON을 보내더라도 비`2xx` 본문을 전혀 읽지 않습니다.

### 규칙 6: `3xx`는 성공 상태 코드가 아니다

`ok`는 오직 `200 <= status < 300`만을 의미합니다. `304 Not Modified`는 비`2xx`입니다. `error`를 선언하지 않고 `HTTP_STATUS`를 직접 처리하거나([ETag 조건부 요청](/ko-KR/recipes/etag-revalidate) 참고), 빈 텍스트 본문을 기대한다면 `struct.string()`을 선언하세요.

## 4. 전송 방식별 결과 튜플

세 가지 전송 방식 모두 호출 지점에서 예외(throw)를 던지는 대신 3개 항목의 error-first 튜플을 반환합니다:

- **HTTP** → `[error, data, response]` — 디코딩된 페이로드 + `DecodedResponse<T>` (`output` 생략 시 `HttpMeta`).
- **SSE** → `[error, stream, open]` — `EventStreamHandle` + 초기 핸드셰이크 스냅샷.
- **WebSocket** → `[error, session, connection]` — `WebSocketSession` + 초기 연결 스냅샷.

클라이언트는 활성 연결이 아닌 설정 정보를 보관합니다. HTTP 요청, SSE 스트림, WebSocket 세션을 시작한 호출자가 직접 취소하거나 닫는 책임을 갖습니다(HTTP는 `AbortSignal`, SSE와 WebSocket은 `await using` 또는 `.close()` + `await .closed`).
