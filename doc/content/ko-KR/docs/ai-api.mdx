애플리케이션에서 AI 서비스를 호출하는 일과 도우미에게 Defjs를 맡기는 일은 서로 다릅니다. [AI 지원 개발](/ko-KR/docs/ai)이 도우미 작업 흐름입니다. API와 SSE 이벤트 형식은 제공자마다 다릅니다. 이 페이지의 스트림은 가상 백엔드이며, 특정 제공자의 프로토콜이 아닙니다.

## 애플리케이션에서 AI API 호출하기 [#call-an-api]

이미 쓰는 HTTP 또는 SSE 계약으로 호출을 정의한 뒤, 애플리케이션이 소유한 client로 작업을 호출합니다. 출발점은 [HTTP 요청](/ko-KR/docs/http)과 [SSE 이벤트 스트림](/ko-KR/docs/sse)입니다. [JSON 보내기](/ko-KR/recipes/post-json)는 JSON 본문 예제입니다. [SSE 이벤트 소비](/ko-KR/recipes/consume-sse)는 스트림을 읽고 닫는 예제지만 첫 이벤트에서 멈춥니다. 그 예제는 완전한 AI 응답이 아닙니다. 전체 AI 응답을 얻으려면 제공자의 완료 신호나 EOF까지 계속 읽고, 읽기 오류를 처리하며 스트림을 닫으세요. 이벤트 이름과 데이터 스키마도 제공자의 형식에 맞게 조정하세요. [취소와 시간 제한](/ko-KR/recipes/cancel-http)은 HTTP 호출을 멈추는 방법입니다.

제공자 비밀은 그 비용이 발생해도 되는 서버에 둡니다. 브라우저 번들, 공개 빌드 변수, 브라우저로 전달되는 client에는 넣지 마세요. 자격 증명은 애플리케이션의 것입니다. 서버의 client에 두거나, 그 서버 경계 안에서만 실행되는 인터셉터로 붙입니다. 자리는 [클라이언트 설정](/ko-KR/docs/client)과 [인터셉터](/ko-KR/docs/interceptors)입니다. `withCredentials`는 Fetch의 cookie 모드만 고르며, 제공자 비밀을 보관하지 않습니다.

작업이 반환된 뒤 스트림의 주인은 애플리케이션입니다. SSE는 이벤트를 읽고, 핸들을 닫고, 닫힐 때까지 기다립니다. HTTP는 답이 더 필요 없으면 호출을 중단합니다. 중단이 서비스가 이미 받은 작업을 되돌렸다는 증거는 아닙니다.

스트리밍 POST가 실패했다는 이유만으로 다시 보내지 마세요. Defjs는 HTTP를 스스로 재시도하지 않습니다. SSE 재연결은 애플리케이션이 켤 때까지 꺼져 있고, 켠 뒤에도 POST 같은 메서드는 그 정책이 분명히 허용하지 않으면 다시 보내지지 않습니다. 실패한 시도에서도 서비스가 과금하는 작업이 이미 시작됐을 수 있습니다. 같은 POST를 다시 보내면 그 작업이 한 번 더 시작될 수 있습니다. 재시도를 넣기 전에 [HTTP 요청](/ko-KR/docs/http)의 재생 규칙과 [SSE 이벤트 스트림](/ko-KR/docs/sse)의 재연결 규칙을 읽으세요.

## 가상의 오프라인 스트림 [#fictional-stream]
