# 데이터 구조 / Struct

`struct`는 SDK와 사용자 간에 공유되는 통신 데이터 계약(호출자 입력, `2xx` 출력, 선언된 서비스 오류, SSE 이벤트, WebSocket 프레임)을 선언합니다.

- **정적 타입 추론**: `Infer<typeof Schema>`를 통해 TypeScript 타입을 도출합니다.
- **error-first 유효성 검증**: `struct.parse(Schema, value)`를 사용하여 런타임에 값을 검증하며, 예외(throw) 없이 `[null, data]` 또는 `[StructError, undefined]`를 반환합니다.

## 1. SDK에서 스키마를 정의하고, 애플리케이션에서 검증하기

<Tabs items={["sdk/schema.ts", "app/validate.ts"]}>
<Tab value="sdk/schema.ts">

```ts
import { struct, type Infer } from "@defjs/core";

export const Order = struct.object({
  id: struct.number(),
  status: struct.enum(["pending", "paid", "shipped"] as const),
  customerName: struct.string().alias("customer_name"),
  notes: struct.string().optional(),
});

export type Order = Infer<typeof Order>;
```

파싱된 객체는 선언된 필드만 유지하며(알 수 없는 프로퍼티는 제거됨), 프로토타입은 `null`이 됩니다. 필수 키 누락, 원시 타입 불일치, 유효하지 않은 브랜치 등의 문제가 발생하면 부분 결과 없이 `StructError`가 반환됩니다.

## 2. 필수, 선택, Null 허용 필드

Defjs는 **필드 존재 여부**(`undefined`)와 **null 허용 여부**(`null`)를 명확히 구분합니다. 모든 struct 생성자는 기본적으로 엄격한 필수(required)이며 non-null입니다:

| 선언 방식                    | 누락 / `undefined`           | `null` | 유효한 값        |
| ---------------------------- | ---------------------------- | ------ | ---------------- |
| `struct.string()`            | 거부                         | 거부   | `string` 허용    |
| `struct.string().optional()` | 허용 (객체 직렬화 시 생략됨) | 거부   | `string` 허용    |
| `struct.string().null()`     | 거부                         | 허용   | `string` 허용    |
| `struct.string().nullish()`  | 허용 (객체 직렬화 시 생략됨) | 허용   | `string` 허용    |
| `struct.null()`              | 거부                         | 허용   | `null` 이외 거부 |

<include cwd lang="typescript">
  examples/struct/required-optional-null.ts#example
</include>

`struct.any()`와 `struct.unknown()` 역시 `.null()`, `.optional()`, `.nullish()`를 연결하지 않는 한 `null`과 `undefined`를 거부합니다.

## 3. 양방향 통신 별칭 (`.alias()`)

백엔드 API가 `snake_case`나 헤더 이름을 사용하지만 TypeScript SDK에서는 `camelCase`를 사용하고 싶을 때 `.alias("wire_name")`을 사용하세요. 필드에 별칭을 한 번만 선언해 두면 양방향으로 자동 적용됩니다:

| 적용 경계                                                          | 사용되는 키                                            |
| ------------------------------------------------------------------ | ------------------------------------------------------ |
| 작업 `input` 및 `struct.parse(Schema, value)`                      | 논리적 이름 (`customerName`)                           |
| `builder`가 반환한 타입화된 struct 값 (`body`, `query`, `headers`) | 통신 별칭 (`customer_name`)                            |
| JSON 응답 / SSE 이벤트 / WebSocket 프레임 디코딩                   | 통신 별칭 `customer_name` → 논리적 이름 `customerName` |
| `builder`에 직접 작성한 익명 객체 키                               | 코드에 작성된 리터럴 키 그대로 유지                    |

<include cwd lang="typescript">
  examples/struct/aliases.ts#example
</include>

`builder` 내부에서 타입화된 객체를 전개(`{ ...input.order, extra: 1 }`)하더라도 struct 인코딩과 별칭 설정이 유지됩니다. 동일한 객체에 논리적 키와 통신 별칭을 동시에 작성하면 `REQ_BUILD_FAILED` 오류가 발생합니다.

## 4. 요청 배치 및 폼 코덱

`input`은 매개변수를 선언하고, `builder`는 이를 `{ path, query, headers, body }`로 배치합니다. 폼 인코딩 본문의 경우, `struct.urlencoded(shape)`와 `struct.formData(shape)`가 루트 객체에 태그를 지정하여 전송 계층이 자동으로 `URLSearchParams`나 `FormData`로 직렬화하도록 합니다:

<include cwd lang="typescript">
  examples/struct/request-placement.ts#example
</include>

| `builder`가 반환한 body 루트                        | 전송 형식         | 기본 `Content-Type`                               |
| --------------------------------------------------- | ----------------- | ------------------------------------------------- |
| 타입화된 객체, 배열, 유한수(number), 불리언, `null` | JSON 텍스트       | `application/json`                                |
| `string` struct 또는 원시 `string`                  | UTF-8 텍스트      | `text/plain;charset=UTF-8`                        |
| body 루트에 지정된 `struct.urlencoded(shape)`       | `URLSearchParams` | `application/x-www-form-urlencoded;charset=UTF-8` |
| body 루트에 지정된 `struct.formData(shape)`         | `FormData`        | `multipart/form-data; boundary=...`               |
| `Blob` / `File` (`struct.file()`)                   | 바이너리 블롭     | `blob.type` 또는 `application/octet-stream`       |
| `ArrayBuffer` / typed view / `ReadableStream`       | 원시 바이트       | `application/octet-stream`                        |

## 5. `StructError` 및 이슈 처리

`struct.parse(Schema, data, { aliases?, errorMap? })`는 유효성 검증 실패 시 `[StructError, undefined]`를 반환합니다. `StructError`는 표준 `Error`를 상속하며 `issues`, `format()`, `flatten()`, `prettify()` 메서드를 제공합니다:

<include cwd lang="typescript">
  examples/struct/parse-failures.ts#example
</include>

각 `StructIssue`에는 `code`(`invalid_type`, `missing_key`, `invalid_literal`, `invalid_enum`, `invalid_union`, `invalid_intersection`, 또는 `custom`), `path`, `expected`, `received`, `message`가 포함됩니다. 기본 메시지는 수신된 값을 생략하고 그 *타입*만 보고하지만, path에는 동적 record 키가 남아 민감한 값이 들어갈 수 있습니다. `String(error)`와 `error.prettify()`는 삭제 경계가 아닙니다. 로그에는 안전한 필드의 허용 목록을 쓰고, 원시 `received` 값과 커스텀 메시지는 민감한 것으로 다루세요.

## 6. 생성자 레퍼런스

<include cwd lang="typescript">
  examples/struct/any.ts#example
</include>

| 생성자                                                     | 입력 가능한 값                             | 추론되는 출력 타입                                    |
| ---------------------------------------------------------- | ------------------------------------------ | ----------------------------------------------------- |
| `struct.string()` / `struct.boolean()`                     | 일치하는 원시 타입                         | `string` / `boolean`                                  |
| `struct.number()`                                          | `NaN`을 제외한 모든 `number`               | `number` (`NaN` 거부; JSON 본문에서 `±Infinity` 거부) |
| `struct.bigint()`                                          | `bigint` 또는 숫자 문자열                  | `bigint`                                              |
| `struct.date()`                                            | 유효한 `Date`, 타임스탬프, 또는 ISO 문자열 | `Date`                                                |
| `struct.literal(value)`                                    | 정확히 일치하는 원시 리터럴                | 리터럴 타입                                           |
| `struct.enum(values)`                                      | 선언된 문자열 또는 숫자 멤버               | 리터럴의 유니온                                       |
| `struct.array(item)` / `struct.tuple(items)`               | 배열 / 고정 길이 튜플                      | `T[]` / `[...]`                                       |
| `struct.object(shape)` / `struct.record(val)`              | 순수 객체(Plain object)                    | 타입화된 객체 / `Record<string, V>`                   |
| `struct.discriminatedUnion(key, options)`                  | 리터럴 `key` 판별자를 가진 객체            | 객체 브랜치들의 유니온                                |
| `struct.or(branches)`                                      | 첫 번째로 일치하는 브랜치                  | 브랜치 타입들의 유니온                                |
| `struct.intersection(members)`                             | 모든 멤버 조건을 만족하는 값               | 딥 머지된 교차 타입                                   |
| `struct.file()` / `struct.blob()` / `struct.arrayBuffer()` | `File` / `Blob` / `ArrayBuffer`            | 바이너리 표현                                         |
