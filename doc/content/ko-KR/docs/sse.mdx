# SSE 이벤트 스트림

SDK는 `defineEventStream`을 사용하여 Server-Sent Events 엔드포인트를 선언합니다. 경로, 선택적 입력 및 builder, struct로 구성된 `events` 딕셔너리, 버퍼/큐 제한을 지정합니다. SDK를 사용하는 애플리케이션은 클라이언트에서 인증 및 재연결 옵션을 구성하고, 스트림을 열어 타입화된 이벤트를 순회하며, 스트림 종료 책임을 소유합니다.

## 1. 이벤트 스트림 정의 및 소비하기

열린 `EventStreamHandle`은 항상 `await using`(또는 `finally` 블록의 `stream.close()` + `await stream.closed`)을 통해 해제해야 합니다:

<Tabs items={["sdk/orders-stream.ts", "app/watch-orders.ts", "Single-file quick look"]}>
<Tab value="sdk/orders-stream.ts">

```ts
import { defineEventStream, struct } from "@defjs/core";

export const watchOrders = defineEventStream({
  path: "/orders/events",
  operation: "orders.watch",
  events: {
    updated: struct.object({
      id: struct.number(),
      status: struct.string(),
    }),
  },
});
```

</Tab>
<Tab value="app/watch-orders.ts">

```ts
import { createClient, withEndpoint } from "@defjs/core";
import { watchOrders } from "../sdk/orders-stream.ts";

const client = createClient(withEndpoint("https://api.example.com"));

async function main() {
  const [error, stream] = await watchOrders(client);
  if (error) {
    console.error(error.code);
    return;
  }

  await using active = stream;
  for await (const event of active) {
    console.log(event.event, event.data.id, event.data.status);
    break;
  }
}

void main();
```

## 2. 핸드셰이크 열기 및 튜플 형태

초기 HTTP 응답이 `2xx`이고 미디어 타입이 `text/event-stream`이며 읽을 수 있는 본문이 포함되어 있을 때 비로소 `[error, stream, startupOpen]` 튜플이 반환됩니다:

- **비`2xx` 핸드셰이크**: `HTTP_STATUS`를 반환합니다(정의에 `error` struct가 선언되어 있다면 디코딩된 `error.data` 포함).
- **잘못된 Content-Type 또는 읽을 수 없는 본문**: `RES_MEDIA_TYPE_INVALID` 또는 `RES_DECODE_FAILED`를 반환합니다.
- **`startupOpen` vs. `stream.open`**: 튜플의 세 번째 항목(`startupOpen`)은 첫 번째 핸드셰이크 응답의 스냅샷입니다. 반면 `stream.open`은 스트림이 나중에 재연결될 때마다 실시간으로 갱신됩니다.

## 3. 이벤트 디스패치 및 디코딩

SSE 프레임이 도착하면(WHATWG 규칙에 따라 빈 줄로 구분):

1. **이벤트 라우팅**: 통신상의 `event:` 필드가 `events[eventName]`을 선택하며, 선언되어 있다면 `events.default`로 폴백합니다. `event:` 필드가 생략된 경우 기본값은 `"message"`입니다. `events.default` 없이 선언되지 않은 이벤트가 오면 무시되고 폐기됩니다.
2. **페이로드 디코딩**: `struct.string()` 스키마는 원시 텍스트 `data:`를 그대로 수신합니다. 그 외의 모든 struct 종류는 `data:`를 먼저 JSON으로 파싱한 후 struct 스키마로 검증합니다.
3. **유효하지 않은 이벤트 관측**: 유효하지 않거나 선언되지 않은 이벤트는 스트림을 강제 종료하지 않고 조용히 폐기됩니다. 클라이언트에 `withSSEOnInvalidEvent(...)`를 연결하여 진단 정보를 제한적으로 수집할 수 있습니다:

## 4. 재연결 및 `Last-Event-ID` [#reconnect]

SSE 재연결은 **선택 사항(opt-in)**입니다. `withSSEReconnect(...)`를 설정하지 않으면 네트워크 단절이나 스트림 읽기 오류 발생 시 스트림이 즉시 종료됩니다.

<include cwd>examples/sse/reconnect.ts#example</include>

- **재연결 시도 한도 (`attempts`)**: `withSSEReconnect`에 옵션 객체를 전달할 경우 기본값은 `3`입니다. 핸드셰이크가 성공하면 시도 횟수 카운터와 백오프 지수가 초기화됩니다. 정상적인 서버의 EOF(스트림 종료)는 실패가 아니므로 재연결을 트리거하지 않습니다.
- **커서 추적 (`Last-Event-ID`)**: 이벤트의 끝을 알리는 빈 줄이 파싱될 때 커서가 확정(commit)되며, 재연결 시 자동으로 `Last-Event-ID` 헤더로 전송됩니다.
- **멱등성(Idempotency) 안전장치**: 기본적으로 멱등한 메서드(`GET`, `HEAD`, `OPTIONS`, `PUT`, `DELETE`)만 자동 재연결됩니다. 비멱등한 메서드(`POST`, `PATCH`—예: LLM 스트리밍 요청 등)는 커스텀 `shouldReconnect` 콜백이 명시적으로 `true`를 반환할 때만 재연결됩니다. `ReadableStream` 요청 본문은 첫 번째 시도에서 완전히 소비되므로 재연결되지 않습니다.
- **핸드셰이크 타임아웃 (`connectTimeoutMs`)**: 제공할 경우 유한한 양수여야 하고 2147483647(타이머 상한)을 넘지 않아야 합니다. 그렇지 않으면 작업은 `REQ_OPTIONS_INVALID`를 반환합니다. Fetch 호출부터 응답 헤더 수신까지의 각 핸드셰이크 시간을 제한하며, 이미 수립된 스트림의 유지 시간은 제한하지 않습니다.

## 5. 버퍼 및 큐 제한

두 제한값 모두 안전한 양의 정수여야 합니다. 둘 중 하나의 한도를 초과하면 치명적 오류로 처리됩니다(`stream.closed`가 `kind: "error"`로 확정되고 이터레이터가 예외를 발생시키며, 이벤트가 조용히 유실되지 않습니다):

| 정의 옵션       | 제한 대상                                                        | 종료 결함 코드        |
| --------------- | ---------------------------------------------------------------- | --------------------- |
| `maxBufferSize` | 빈 줄이 오기 전까지 미완성되거나 크기가 초과된 SSE 프레임 바이트 | `CAP_BUFFER_EXCEEDED` |
| `maxQueueSize`  | `for await` 소비자를 기다리며 큐에 대기 중인 검증 완료 이벤트 수 | `CAP_QUEUE_OVERFLOW`  |

## 6. 스트림 종료 및 리소스 해제 [#close-and-dispose]
