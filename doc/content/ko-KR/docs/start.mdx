# 시작하기: HTTP 요청 하나

`GET /users/:id`를 정의하고, 명시적인 클라이언트로 실행한 뒤 `200`과 선언된 `404`를 모두 디코딩해요. 로컬 핸들러로 첫 실행은 오프라인으로 두고, 실제 서비스로 바꿔도 명령은 그대로예요.

## Step 1 — 설치

`@defjs/core`는 ESM이고 Node.js, Bun, Deno에서 돌아요. Node.js 22.18+ (또는 24+)는 type stripping으로 `.ts` 파일을 그대로 실행하고, 그보다 낮은 22.x는 `--experimental-strip-types`가 필요해요. package.json에 `"type": "module"`을 두세요. 브라우저에서는 여전히 번들러와 Fetch가 필요해요.

## Step 2 — 요청 정의하기

`src/get-user.ts`를 만들어요. input struct는 호출자가 주는 값이에요. `builder`가 그 값을 요청에 배치해요. 여기서는 입력 전체가 path 객체라서, alias가 없는 스칼라 필드가 `:id`를 채워요.

<include cwd meta="get-user.ts">
  examples/start/define-request.ts#example
</include>

`output`은 2xx body예요. `error`는 그 밖의 모든 status예요. 각각 struct 하나예요. body가 달라지면 `struct.or(...)`나 discriminated union을 쓰세요.

`defineRequest(...)`는 엔드포인트를 돌려줘요. `getUser(...)`를 호출하면 `client.execute(...)`에 넘길 opaque 명령이 만들어져요. 위의 `builder`는 입력을 배치하는 함수이지, 엔드포인트가 아니에요.

## 결과가 달라질 때

- 잘못된 입력 → `REQ_INPUT_INVALID`. 충돌하는 취소 옵션 → `REQ_OPTIONS_INVALID`. 실패하는 `builder` → `REQ_BUILD_FAILED`
- non-2xx status → `HTTP_STATUS`. `error`를 선언했고 그 body가 디코딩되면 타입이 있는 `error.data`
- 선언된 JSON body인데 다른 미디어 타입 → `RES_MEDIA_TYPE_INVALID`. body를 읽기 전에 보고돼요
- 선언된 body (2xx는 `output`, 그 밖은 `error`)가 디코딩되지 않음 → status와 관계없이 `RES_DECODE_FAILED` 또는 `RES_STRUCT_MISMATCH`
- Fetch 실패 / 취소 / 타임아웃 → `NET_UNREACHABLE` / `NET_ABORTED` / `NET_TIMEOUT`

`timeout`은 `1..2_147_483_647` 범위의 양의 안전 정수여야 해요. 유효한 취소 모양은 `{ timeout }`, `{ abort }`, 또는 `{ signal, timeout }` / `{ signal, abort }`예요. `{ abort, timeout }`을 함께 주는 건 유효하지 않아요. 취소는 호출자가 본 것을 알려 줄 뿐, 서버 쓰기가 커밋됐는지는 알려 주지 않아요.
