# 미들웨어

인터셉터(미들웨어)는 SDK 작업 정의를 수정하지 않고도 애플리케이션의 `Client`에 인증 헤더 추가, 요청 서명, 유지보수 모드 단락(short-circuit), 안전한 조회 재시도 등 횡단 관심사 실행 정책을 연결할 수 있게 해줍니다.

입력값 검증 및 `builder` 매핑은 인터셉터 체인이 실행되기 **전에** 수행되며, HTTP 상태 코드 분기 및 `output` / `error` struct 유효성 검증은 인터셉터 체인이 실행된 **후에** 수행됩니다.

### 인터셉터 파이프라인 규칙

- **양파 껍질 순서**: 요청이 나갈 때는 등록된 순서대로 실행되고(`next(req)` 이전), 응답이 돌아올 때는 등록 역순으로 실행됩니다(`await next(req)` 이후). 전역 로깅이나 추적 인터셉터는 인증이나 재시도 같은 구체적인 인터셉터의 바깥쪽에 배치하세요.
- **불변 요청 객체 규칙**: 외부 재시도 로직이 깨끗한 헤더 상태를 참조할 수 있도록, 항상 `req.headers`를 복제(`new Headers(req.headers)`)하여 새로운 요청 객체(`{ ...req, headers }`)를 `next(...)`에 전달하세요.
- **`content-type`과 `bodyContentType`**: Defjs는 추론된 본문 컨텐츠 타입을 `req.headers`를 직접 변경하지 않고 `req.bodyContentType`에 저장합니다. 요청 서명 모듈은 `req.headers.get("content-type") ?? req.bodyContentType`을 읽어야 합니다. 인터셉터가 `req.body`를 새로운 형식으로 교체하는 경우 명시적인 `content-type` 헤더를 설정하세요.

## 2. `makeResponse`를 통한 요청 단락(Short-circuit)

HTTP 인터셉터는 `makeResponse(...)`를 사용하여 합성 응답을 만들어 `next(req)`를 호출하지 않고 즉시 반환할 수 있습니다:

<include cwd lang="typescript">
  examples/interceptors/short-circuit.ts#example
</include>

`makeResponse`는 검증 과정을 우회(bypass)하는 것이 **아닙니다**. 합성된 응답 역시 해당 작업의 미디어 타입 확인, 상태 코드 분기(`2xx` vs 비`2xx`), `output` / `error` struct 유효성 검증을 거칩니다.

## 3. 안전한 HTTP 조회 요청 재시도

Defjs는 애플리케이션 레벨의 HTTP 상태 코드를 자동으로 재시도하지 않습니다. 멱등한 `GET` / `HEAD` / `OPTIONS` 호출에서 `429`, `502`, `503`, `504` 등 상태 코드 기반의 재시도가 필요하다면 HTTP 인터셉터 내부에서 제어 루프를 직접 구현하세요:

<include cwd lang="typescript">
  examples/interceptors/retry-safe-reads.ts#example
</include>

- **전송 계층 거부(rejection) 처리**: 네트워크 오류가 발생하면 `next(request)`는 상태 코드 0 응답 대신 reject됩니다. 이 거부를 잡아서 다시 throw하면 원래의 `NET_*` 결함 코드가 보존됩니다.
- **인터셉터 내부 예외 발생 시**: 처리되지 않은 예외가 발생하거나(또는 응답 객체가 아닌 값을 반환하면) 작업 튜플은 `EXT_INTERCEPTOR_FAILED`와 함께 원인이 `fault.cause`에 담겨 해결됩니다. `ERR_ABORTED`나 `ERR_TIMEOUT`을 던지면 `NET_ABORTED`나 `NET_TIMEOUT`으로 해결됩니다.

## 4. WebSocket 세션 래핑

WebSocket 인터셉터는 `next(req)`를 **최대 1회만** 호출할 수 있습니다. 반환된 `WebSocketSessionLike`를 래핑할 때는 1회성 스냅샷 객체를 전개하기보다는 실시간 getter 프로퍼티(`state`, `connection`, `bufferedAmount`), `close`, `closed`, `receive`, `[Symbol.asyncDispose]()`를 명시적으로 위임하세요:

## 5. 내장 팩토리 및 헬퍼

| Export                                         | 전송 방식 | 설명                                                               |
| ---------------------------------------------- | --------- | ------------------------------------------------------------------ |
| `createHttpInterceptor(fn)`                    | HTTP      | `(req, next) => Promise<HttpResponse<unknown>>` 래핑               |
| `createSSEInterceptor(fn)`                     | SSE       | `(req, next) => Promise<EventStreamHandle<unknown>>` 래핑          |
| `createWebSocketInterceptor(fn)`               | WebSocket | `(req, next) => Promise<WebSocketSessionLike>` 래핑                |
| `basicAuthHttpInterceptor(provider, options?)` | HTTP      | 동기/비동기 자격 증명 제공자로부터 `Authorization: Basic ...` 주입 |
| `basicAuthSSEInterceptor(provider, options?)`  | SSE       | SSE 핸드셰이크 시 `Authorization: Basic ...` 주입                  |
