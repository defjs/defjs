# Vue

Vue 앱은 SDK에서 API 정의를 import하고 자신이 구성한 Defjs Client를 제공합니다. SDK 정의는 Vue에 의존하지 않으며, 컴포넌트나 데이터 계층이 실행 결과와 취소를 관리합니다.

이 플러그인은 기존 `Client`를 제공하고 읽기 위한 선택적 도구예요. 앱이 소유한 고정 클라이언트를 직접 import하거나, 재사용 로직에 Client를 명시적으로 넘기거나, 트리 기본값과 하위 트리 덮어쓰기에 프레임워크 주입을 쓰거나, 앱만의 구성을 선택해도 돼요. SDK 정의에 이 플러그인이 필수는 아니에요.

기존 `@defjs/core` 클라이언트를 Vue에 연결해요. 플러그인, injection key, `injectClient()`를 받아요. 패키지는 클라이언트를 **만들지 않고**, 결과를 캐시하지 않으며, 명령을 재시도하지 않고, unmount 때 전송 리소스를 닫지도 않아요.

## 기본 사용법

`@defjs/core`, `@defjs/vue`, Vue 3.2+를 설치하세요 (플러그인은 `provide` / `inject`만 필요하지만, 예제는 3.2에서 도입된 `<script setup>`과 `onScopeDispose`를 써요). ESM이에요.

`bun add @defjs/core @defjs/vue vue`

클라이언트를 만들고 플러그인을 설치한 뒤, 변경 시 abort로 fetch 해요.

  examples/vue/main.ts#example
</include>

<include cwd>examples/vue/basic-setup.vue#example</include>

`createClientPlugin(client)`는 넘긴 객체를 그대로 제공해요. 복제나 dispose 훅은 없어요. core 옵션과 인터셉터는 클라이언트를 만들 때 설정하세요.

`onCleanup`은 watcher가 다시 돌기 전에 실행되고, watcher가 멈출 때도 실행돼요. 비동기 작업을 시작하기 전에 등록하세요. error-first 튜플은 애플리케이션 data로 남아요.

## inject와 덮어쓰기

`injectClient(key)`는 해당 키의 가장 가까운 provider를 읽고, 생략하거나 `undefined`를 넘기면 `HTTP_CLIENT`를 써요. 동기 `setup()`이나 `app.runWithContext()`(Vue 3.3+)처럼 유효한 Vue 주입 컨텍스트에서 호출하세요. 후자는 동기 앱 수준 컨텍스트만 제공하며, 하위 트리 덮어쓰기를 가져오거나 일반 `await`를 넘어 컨텍스트를 유지하지 않아요. `<script setup>`의 최상위 `await` 이후 컴파일러가 복원한 컨텍스트는 여전히 유효해요.

사용자 지정 `InjectionKey<Client>`는 `app.provide(key, client)` 또는 상위 컴포넌트의 `provide(key, client)`로 설정하세요. 제공하는 쪽과 읽는 쪽은 동일한 `Symbol` 객체를 공유해야 해요. 설명이 같아도 같은 키가 아니에요. `createClientPlugin(client)`는 여전히 클라이언트만 받고 `HTTP_CLIENT`만 제공해요.

활성 주입 컨텍스트가 없거나 선택한 키에 클라이언트가 없으면 `Error`를 던져요. 사용자 지정 키가 없어도 `HTTP_CLIENT`로 대체하지 않아요. 플러그인 설치만으로 주입 컨텍스트가 생기지는 않아요.

클라이언트 조회만 감싼 앱 함수는 `explicitClient ?? injectClient()`를 써도 돼요. 대체 분기만 주입 컨텍스트가 필요해요. 같은 컴포저블 안의 다른 수명 주기 API는 각자의 컨텍스트 요구 사항을 유지해요. 비동기 작업 전에 유효한 컨텍스트에서 클라이언트를 읽고 해당 객체를 재사용하세요.

하위 트리는 Vue의 `provide(HTTP_CLIENT, childClient)`로 덮어써요.

<include cwd>examples/vue/inject-and-override.vue#example</include>

가장 가까운 provider가 이겨요. 자손은 `childClient`를 받고, 하위 트리 밖 형제들은 앱 수준 클라이언트를 유지해요. provide를 실행한 컴포넌트 자신은 여전히 상위 컴포넌트에서 읽어요.

## watcher 밖에서 HTTP 작업 소유하기

watcher 밖에서 composable이나 컴포넌트가 시작한 작업은 `AbortController` + `onScopeDispose`를 쓰세요. 시작과 활성 작업을 abort하고, 반응형 상태를 할당하기 전에 signal을 확인하세요. 플러그인이나 injection 범위는 명령 소유자를 추론하지 않아요. 목록 페이지에서는 `execute`를 Vue Query(또는 비슷한 것)로 감싸세요. `@defjs/vue`는 DI만 하고 `useRequest`를 제공하지 **않아요**.

범위가 클라이언트를 소유하면 브라우저 전역 재사용을 위해 요청에 독립적으로 두세요. 헤더, 쿠키, 사용자, 테넌트, 자격 증명을 담으면 관련 앱/SSR 요청 경계에서 만들고 그 인스턴스를 거기서 제공하세요.

## 실시간 범위 정리하기

범위가 연결 중간에 사라져도 스트림이나 세션을 닫으세요. 시작을 abort하고, 늦게 도착한 핸들을 닫고, 단일 iterator를 소비하고, 종료 프로미스를 await 하세요.

<include cwd>examples/vue/realtime-scope.vue#example</include>

치명적인 스트림 오류와 큐 오버플로는 이터레이터를 reject하므로 루프에 `catch`가 있어요. 없으면 그 rejection이 처리되지 않아요. 예제는 마지막 100개 메시지만 유지하고 행을 id로 키 지정해요. 같은 payload가 오면 키가 중복되기 때문이에요. 범위를 멈추면 SSE는 정상적으로 순회가 끝나지만, abort된 WebSocket 세션은 `receive`를 `AbortError`로 reject하므로 `catch`도 같은 방식으로 가드하세요.

WebSocket도 같은 순서예요 — 준비를 abort하고, 늦은 세션을 닫고, `session.receive`를 소비하고, `onStateChange` / `onRuntimeError`를 구독 해제하고, 닫고, `session.closed`를 await 하세요. 정리는 멱등하게 두세요. dispose와 iterator 완료가 만날 수 있어요.

## SSR 범위

`createClientPlugin(client)`는 Vue 앱 하나에 인스턴스 하나를 제공해요. 브라우저에서는 엔드포인트, 인터셉터, 담은 상태를 공유해도 안전할 때 공유하세요. SSR에서는 헤더, 쿠키, 사용자, 테넌트, 자격 증명이 다르면 요청마다 별도 클라이언트를 만들고 설치하세요.

앱 unmount, 플러그인 제거, 컴포넌트 범위 dispose는 HTTP를 abort하거나, SSE/WebSocket을 닫거나, 리스너를 구독 해제하거나, core 클라이언트를 dispose하지 **않아요**. 작업을 시작한 소유자가 끝내야 해요.
