# 통합 개요

통합(Integration)은 `@defjs/core`를 직접 수정하거나 SDK 정의를 특정 프레임워크나 텔레메트리 스택에 종속시키지 않고도, 정해진 확장 지점에서 애플리케이션 자체의 `Client`를 확장할 수 있도록 지원합니다. 여러분이 작성한 SDK 정의는 순수한 `@defjs/core` 모듈로 유지되며, 어떤 통합 플러그인을 설치하고 사용할지는 사용하는 애플리케이션이 직접 선택합니다.

모든 Defjs 플러그인은 **가벼운 플러그인 계약(thin plugin contract)**을 엄격히 준수합니다:

- **숨겨진 캐싱이나 상태 관리 없음**: 플러그인은 절대 응답을 임의로 저장하거나, 요청을 제멋대로 재시도하거나, 쿼리 상태를 관리하지 않습니다.
- **전송 계층 교체 금지**: 플러그인은 기저의 HTTP, SSE, WebSocket 전송 계층을 임의로 감싸거나 대체하지 않습니다.
- **호출자 소유의 수명 주기**: UI 프로바이더의 언마운트나 텔레메트리 SDK의 종료가 진행 중인 요청의 자동 취소나 활성 스트림의 자동 종료를 유발하지 않습니다.

## 두 가지 플러그인 아키텍처

### 1. 프레임워크 플러그인 (`@defjs/react`, `@defjs/vue`)

프레임워크 플러그인은 네이티브 의존성 주입(React Context 또는 Vue `provide` / `inject`)을 통해 기존의 [`DerivableClient`](/ko-KR/api/core/derivableclient-type)를 컴포넌트 트리의 하위로 전달합니다:

<Tabs items={["sdk/orders.ts", "app/main.tsx", "app/OrderCard.tsx"]}>
  <Tab value="sdk/orders.ts">
```ts
import { defineRequest, struct } from "@defjs/core";

export const Order = struct.object({
  id: struct.number(),
  status: struct.string(),
});

export const getOrder = defineRequest({
  method: "GET",
  path: "/orders/:id",
  input: struct.object({ id: struct.number() }),
  builder: (input) => ({ path: { id: input.id } }),
  output: Order,
});
```
  </Tab>
  <Tab value="app/main.tsx">
```tsx
import { createClient, withEndpoint } from "@defjs/core";
import { ClientProvider } from "@defjs/react";
import { OrderCard } from "./OrderCard.tsx";

const client = createClient(withEndpoint("https://api.example.com"));

export function App() {
  return (
    <ClientProvider client={client}>
      <OrderCard id={42} />
    </ClientProvider>
  );
}
```
  </Tab>
  <Tab value="app/OrderCard.tsx">
```tsx
import { useClient } from "@defjs/react";
import { getOrder } from "../sdk/orders.ts";

export function OrderCard({ id }: { id: number }) {
  const client = useClient();
  // effect 또는 쿼리 훅 내부에서 `client` 또는 `client({ signal })`을 `getOrder(...)`에 전달합니다
  void id;
  void getOrder;
  void client;
  return null;
}
```
  </Tab>
</Tabs>

### 2. 미들웨어 플러그인 (`@defjs/opentelemetry-server`)

미들웨어 플러그인은 [`ClientOption`](/ko-KR/api/core/clientoption-type)을 반환하는 팩토리 함수입니다. `createClient(...)`에 전달되면 `withHttpInterceptors`, `withSSEInterceptors`, `withWebSocketInterceptors`를 통해 HTTP, SSE, WebSocket 인터셉터를 추가합니다:

<Tabs items={["plugins/request-id.ts", "app/client.ts"]}>
  <Tab value="plugins/request-id.ts">
```ts
import type { ClientOption } from "@defjs/core";
import { createHttpInterceptor, withHttpInterceptors } from "@defjs/core";

export function withRequestIdHeader(headerName = "x-request-id"): ClientOption {
  const interceptor = createHttpInterceptor(async (request, next) => {
    const headers = new Headers(request.headers);
    if (!headers.has(headerName)) {
      headers.set(headerName, crypto.randomUUID());
    }
    return next({ ...request, headers });
  });

return withHttpInterceptors(interceptor);
}

````
  </Tab>
  <Tab value="app/client.ts">
```ts
import { createClient, withEndpoint } from "@defjs/core";
import { withRequestIdHeader } from "../plugins/request-id.ts";

export const client = createClient(
  withEndpoint("https://api.example.com"),
  withRequestIdHeader(),
);
````

  </Tab>
</Tabs>

인터셉터 실행 순서 규칙, 재시도 경계, 스트리밍 수명 주기 훅에 대한 자세한 내용은 [미들웨어](/ko-KR/docs/interceptors) 문서를 참조하세요.
