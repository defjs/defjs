# React

React 앱은 SDK에서 API 정의를 import하고 자신이 구성한 Defjs Client를 이 프레임워크 플러그인으로 트리에 제공합니다. SDK 정의는 React에 의존하지 않으며, 컴포넌트나 데이터 계층이 같은 정의를 실행해 결과와 취소를 관리합니다.

이 플러그인은 기존 `Client`를 제공하고 읽기 위한 선택적 도구예요. 앱이 소유한 고정 클라이언트를 직접 import하거나, 재사용 로직에 Client를 명시적으로 넘기거나, 트리 기본값과 하위 트리 덮어쓰기에 프레임워크 주입을 쓰거나, 앱만의 구성을 선택해도 돼요. SDK 정의에 이 플러그인이 필수는 아니에요.

기존 `@defjs/core` 클라이언트를 React 트리에 연결해요. Context와 `useClient()`를 받아요. 패키지는 클라이언트를 **만들지 않고**, 캐시를 더하지 않으며, 명령을 재시도하지 않고, 전송 리소스를 dispose하지도 않아요. 작업을 시작한 컴포넌트, effect, 또는 데이터 라이브러리가 소유해요.

## 기본 사용법

`@defjs/core`, `@defjs/react`, React 18+를 설치하세요. ESM이에요.

`bun add @defjs/core @defjs/react react`

클라이언트를 제공한 뒤, 사용자를 fetch하고 변경 시 abort 해요.

<include cwd>examples/react/client-provider.tsx#example</include>

<include cwd>examples/react/basic-setup.tsx#example</include>

`ClientProvider`는 일반 Context provider예요. 다른 `client` prop은 자손이 보는 값을 바꿔요 — 복제, 교체, dispose는 없어요. 중첩 provider는 명시적 경계를 만들어요.

개발 모드에서 React는 effect를 두 번 이상 설정·정리할 수 있어요. signal 검사는 낡은 프로미스가 현재 렌더에 쓰지 못하게 해요. 튜플 오류는 여전히 data예요.

## `useClient`로 읽기

`useClient(overrideClient)`는 명시적 클라이언트를 우선해 돌려줘요. 생략하거나 `undefined`를 넘기면 가장 가까운 `ClientProvider`를 읽고, 두 곳 모두 클라이언트가 없을 때만 `Error`를 던져요. 인자 없는 `useClient()`도 계속 유효해요.

명시적 클라이언트가 있어도 `useClient(explicitClient)`는 항상 컴포넌트나 커스텀 훅의 최상위에서 호출하세요. 일반 함수나 이벤트 콜백에서 호출하면 안 돼요. `explicitClient ?? useClient()`는 훅을 조건부로 호출하므로 유효하지 않아요. 명시적 값은 Context에 쓰거나 provider를 만들지 않으며, 훅은 여전히 Context를 구독해요.

<include cwd>examples/react/read-with-use-client.tsx#example</include>

훅은 클라이언트만 공급해요. 작업을 시작하거나, 전송을 구독하거나, error-first 튜플을 예외로 바꾸지 않아요.

## 쿼리 작업 소유하기

쿼리 라이브러리가 캐싱, 재시도, 낡은 결과 억제, 취소를 소유할 수 있어요. 라이브러리가 주는 signal을 넘기세요. 목록 페이지에서는 `client.execute(...)`를 TanStack Query(또는 비슷한 것)로 감싸세요. `@defjs/react`는 DI만 하고 `useRequest`를 제공하지 **않아요**.

<include cwd>examples/react/own-query-work.tsx#example</include>

같은 명령을 두 번째 effect로 감싸지 마세요 — 소유자가 둘이면 취소와 낡은 결과 처리가 모호해져요.

## 실시간 작업 소유하기

SSE와 WebSocket 핸들은 `client.execute(...)`보다 오래 살아요. 시작을 await하기 전에 정리를 등록하고, dispose 뒤에 도착한 핸들을 닫고, 단일 iterator를 소비하고, 종료 프로미스를 await 하세요.

<include cwd>examples/react/own-realtime-work.tsx#example</include>

`execute`에 넘긴 `signal`은 열린 세션에도 계속 적용돼요. cleanup에서 abort하면 세션이 `aborted`로 끝나고 `receive`가 `AbortError`로 reject되므로, 위의 `catch`는 effect가 dispose된 뒤의 오류를 무시하고 진짜 실패(큐 오버플로, heartbeat 타임아웃)만 보고해요. abort된 SSE 스트림은 대신 이터레이터가 정상적으로 끝나요. `catch`가 없으면 루프의 reject가 처리되지 않은 프로미스 rejection이 돼요.

`EventStreamHandle`도 같은 규칙이에요. `finally`에서 닫고 `stream.closed`를 await 하세요. WebSocket 소비자는 상태/런타임 오류 리스너도 구독 해제하고 `session.receive`를 계속 읽어야 해요 — 읽지 않은 한정 큐는 오버플로할 수 있어요.

## SSR과 클라이언트 범위

패키지 진입점은 Client Component 경계예요. 브라우저 앱은 엔드포인트, 인터셉터, 담은 상태가 브라우저에 안전하고 요청에 독립적일 때 모듈 범위 클라이언트를 공유할 수 있어요. SSR에서는 헤더, 쿠키, 사용자, 테넌트, 자격 증명이 다르면 요청 경계마다 별도 클라이언트를 만들어요.

provider unmount는 HTTP를 abort하거나, SSE/WebSocket을 닫거나, 리스너를 구독 해제하거나, `dispose`를 호출하지 **않아요**. `@defjs/react`에는 그런 수명 API가 없어요. 각 작업을 시작한 코드가 끝내거나 취소해야 해요.

## 참고

`@defjs/react`의 공개 export:

- `ClientProvider` — `ClientProviderProps`를 받고 넘긴 클라이언트를 제공
- `useClient` — 명시적 클라이언트 우선, 없으면 가장 가까운 provider의 클라이언트, 둘 다 없으면 throw
- `ClientProviderProps` — `{ client: Client; children?: ReactNode }`

클라이언트와 옵션은 `@defjs/core`에서 만들어요. [클라이언트](/ko-KR/docs/client), [오류](/ko-KR/docs/errors), [SSE](/ko-KR/docs/sse), [WebSocket](/ko-KR/docs/web-socket)을 보세요.
