# 클라이언트

`Client`는 사용하는 앱의 실행 설정이고, 함수예요. `createClient(...)`가 그 함수를 돌려줘요. SDK에서 작업을 import하고, 서비스 주소, 자격 증명, 인터셉터, 전송 수단을 고른 다음, 클라이언트로 작업을 호출해요. `getUser(client({ abort }), { id: 1 })`는 입력을 선언한 호출을 시작해요. `health(client)`는 입력이 없는 호출을 시작해요. 입력 struct 전체가 선택이면 `search(client)`와 `search(client, input)`이 모두 유효해요. 세 번째 옵션 인자는 없어요. 작업을 호출하면 시작되고, `await`는 error-first 튜플만 기다려요.

SDK 정의는 이 인스턴스에 묶이지 않아요. 브라우저, 서버 요청, 로컬 테스트가 서로 다른 클라이언트로 같은 export된 작업을 쓸 수 있어요. 모두 같은 Defjs 계약과 호환되는 Core 버전을 따라요. 그 클라이언트로 호출하는 작업에 맞게 각 클라이언트의 서비스 주소를 구성해요.

같은 클라이언트 값을 여러 작업에 넘길 수 있어요. 앱이 캐시와 재시도 정책을 고르고, 시작한 작업을 소유해요. HTTP는 자동으로 재시도하지 않아요. 스트림 재연결은 opt-in이에요.

`Client`는 함수라서 React state setter에 넘기지 마세요. `setState(client)`는 updater로 호출해요. Vue `watch`나 `computed`의 소스로 쓰지 마세요. 그 API는 함수를 호출해요.

## 클라이언트 파생하기

`client(options?)`는 새 클라이언트를 돌려줘요. `client(options)`를 호출할 때 알려진 필드 일곱 개는 인자 객체에서 복사돼요. 현재 옵션 위에 덮는 새 options 객체로의 최상위 스냅샷이에요. 나중 필드가 이겨요. 필드 값이 `undefined`이면 제공되지 않은 것으로 보고, 부모의 값을 유지해요. 파생된 클라이언트는 부모가 가진 설정을 없앨 수 없어요. 설정이 없는 상태로 돌아가려면, 그 설정이 없던 클라이언트에서 다시 파생하세요 (루트 클라이언트는 남겨 두세요). 중첩된 `heartbeat`, `protocols`, `reconnect` 값은 참조로 유지되고, 복제되지 않으며, 병합하지 않고 부모 값 전체를 바꿔요. WebSocket은 작업이 실행될 때 그것들을 읽어요 (그때 heartbeat 필드와 protocols 목록을 복사해요). 그래서 파생한 뒤에 그 객체를 바꾸면 이후 호출에 여전히 영향을 줄 수 있어요. 넘긴 뒤에는 불변으로 다루세요. 파생은 I/O를 하지 않아요. 원래 클라이언트는 절대 바뀌지 않아요. `client()`, `client(undefined)`, `client({})`는 현재 옵션을 복사해요.

`abort`는 합쳐지지 않아요. 나중 `abort`가 이전 신호를 바꿔요. 신호는 앱 코드에서 `AbortSignal.any`로 합치세요.

`createClient`의 기본 설정은 파생된 클라이언트마다 공유되고, 런타임에 얼려지지 않아요. 관례로 고정돼요. 라이브러리는 그것을 바꾸지 않고, 애플리케이션도 바꾸면 안 돼요. 그 클라이언트의 [`RequestOptions`](/ko-KR/api/core/requestoptions-type)는 그 최상위 스냅샷이에요. 앱 코드는 클라이언트를 호출해 작업에 넘길 뿐, 그 내부 상태를 읽지 않아요.

## 요청 옵션

[`RequestOptions`](/ko-KR/api/core/requestoptions-type)는 평평한 필드 일곱 개예요. 각 프로토콜은 아는 필드만 읽고 나머지는 무시해요. HTTP 작업에 `heartbeat`를 넘겨도 무시될 뿐, 오류가 아니에요. SSE는 요청 옵션에서 `abort`만 읽어요. SSE 재연결은 클라이언트 설정(`withSSEReconnect`)에서 오므로, `client({ reconnect })`는 WebSocket에만 영향을 줘요. 컴파일 타임 프로토콜 필터는 없어요.

| 필드                 | 쓰는 쪽              | 규칙                                                                                                        |
| -------------------- | -------------------- | ----------------------------------------------------------------------------------------------------------- |
| `abort`              | HTTP, SSE, WebSocket | 이전 신호를 바꿔요. 데드라인은 `AbortSignal.timeout(ms)`(`NET_TIMEOUT`)예요. 수동 취소는 `NET_ABORTED`예요. |
| `onUploadProgress`   | HTTP                 | SSE와 WebSocket은 무시해요.                                                                                 |
| `onDownloadProgress` | HTTP                 | SSE와 WebSocket은 무시해요.                                                                                 |
| `beforeConnect`      | WebSocket            | 그 호출에 한해 클라이언트 설정을 바꿔요.                                                                    |
| `protocols`          | WebSocket            | 클라이언트 목록을 바꿔요. 추가되지 않아요.                                                                  |
| `heartbeat`          | WebSocket            | 통째로 바뀌어요. `timeoutMs`는 heartbeat 확인 대기이지, 요청 데드라인이 아니에요.                           |
| `reconnect`          | WebSocket            | 통째로 바뀌어요.                                                                                            |

`timeout` 필드도, `signal` 필드도, 클라이언트 기본 데드라인도 없어요. SSE와 WebSocket에서 `abort`는 열린 뒤를 포함해 연결 전체를 덮어요. 시작 전용 데드라인은 없어요. 그게 필요하면 앱이 `AbortController`를 만들고, 타이머에서 `new DOMException("...", "TimeoutError")`로 abort한 뒤, await가 돌아온 다음 타이머를 지워요. [SSE](/ko-KR/docs/sse#close-and-dispose)를 보세요.

`HttpExecuteOptions`는 HTTP 조각이에요. `abort`와 진행률 콜백이에요. `EventStreamExecuteOptions`는 `{ abort? }`예요. `WebSocketExecuteOptions`는 WebSocket 조각에 `abort`를 더한 거예요.

## 전송별 결과

- HTTP → `[error, data, response]`
- SSE → `[error, stream, open]`. `open`은 Defjs 네이티브 handle이나 동일한 live `open` 객체를 그대로 전달하는 래퍼일 때 반환된 연결에서 처음 성공한 핸드셰이크의 스냅샷이며, 커스텀 handle이나 `open`을 재정의하는 래퍼는 재연결 뒤에도 현재 공개한 `open`을 사용하고 `stream.open`은 live로 유지돼요([SSE](/ko-KR/docs/sse) 참고).
- WebSocket → `[error, session, connection]`

`error`가 있으면 성공 값을 쓰기 전에 return 하세요.

정리는 호출하는 쪽이 소유해요. HTTP는 abort하고, SSE는 닫고 `await stream.closed` 하고, WebSocket은 닫고 `await session.closed` 해요.

## 서버 vs 브라우저 범위

서버에서는 옵션이나 interceptor 클로저가 인증, 쿠키, 사용자, 테넌트를 잡을 때 요청 경계 안에서 클라이언트를 만들어요. 클라이언트 정체성 자체가 보안 경계는 아니에요.

## 마이그레이션

| 이전                                      | 이후                                                     |
| ----------------------------------------- | -------------------------------------------------------- |
| `client.execute(getUser(input), options)` | `getUser(client(options), input)`                        |
| `execute(cmd, { timeout: 5000 })`         | `client({ abort: AbortSignal.timeout(5000) })`           |
| `execute(cmd, { signal })`                | `client({ abort: signal })`                              |
| `createClient(withTimeout(5000), ...)`    | 호출할 때 `abort`를 넘기거나, 애플리케이션 함수로 감싸요 |

## 참고

| Helper                                                                                                        | 효과                                                       |
| ------------------------------------------------------------------------------------------------------------- | ---------------------------------------------------------- |
| `withEndpoint(url)`                                                                                           | 모든 전송의 절대 base endpoint                             |

| `withSSEHandle(fetch)`                                                                                        | SSE의 Fetch를 바꿔요                                       |
