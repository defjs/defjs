# HTTP 작업

SDK는 `defineRequest`를 사용하여 각 HTTP 작업을 정의합니다: HTTP 메서드, 경로 템플릿, `input` 스키마, 동기 `builder`, 그리고 `output` / `error` 응답 스키마를 지정합니다. SDK를 사용하는 애플리케이션은 이 작업을 import하고, 자체 구성한 `Client`를 전달하여 반환되는 `[error, data, response]` 튜플을 처리합니다.

### SDK 설계 모범 사례

- **정의당 하나의 작업**: 사용되지 않는 작업을 애플리케이션에서 트리쉐이킹할 수 있도록 각 메서드, 경로, 계약을 개별 정의로 분리하세요.
- **고정된 `operation` 식별자 지정**: `"orders.read"`와 같이 카디널리티가 낮은 식별자를 사용하세요. 텔레메트리 플러그인(`@defjs/opentelemetry-server`)이나 로깅 인터셉터가 URL이나 사용자 ID를 유출하지 않고 안전하게 활용할 수 있습니다.
- **SDK 내부에 클라이언트를 포함하지 마세요**: 오직 정의, `struct` 스키마, 타입만을 export해야 합니다.

## 2. URL 해석 및 경로 매개변수

`withEndpoint(...)`에는 유효한 절대 URL을 전달해야 합니다. URL의 경로(pathname)가 기본 디렉터리로 동작합니다(엔드포인트의 쿼리 스트링이나 해시는 무시됩니다).

<include cwd>examples/http/resolve-url.ts#example</include>

- **경로 플레이스홀더 (`:name`)**: 단일 경로 세그먼트로 정확히 한 번 인코딩됩니다. 슬래시, `?`, `#`, `%`, 공백, 유니코드 문자는 해당 세그먼트 내부에 안전하게 유지되므로 값을 미리 인코딩해서는 안 됩니다. 빈 문자열, `.`, `..`을 전달하면 `REQ_BUILD_FAILED`로 실패합니다.
- **Origin 및 디렉터리 격리**: 정의 경로에는 절대 URL, 프로토콜 상대 URL(`//...`), C0 제어 문자, 백슬래시, `?`, `#`를 사용할 수 없으며 기본 엔드포인트의 디렉터리를 벗어나는 경로(`../`)도 허용되지 않습니다. 위반 시 인터셉터나 전송 계층이 실행되기 전에 즉시 `REQ_BUILD_FAILED`가 발생합니다.

## 3. `builder`를 통한 입력 배치

작업에 `input`이 선언된 경우, 반드시 `{ path?, query?, headers?, body? }`를 반환하는 동기 순수 함수인 `builder`를 **제공해야 합니다**. `input`이 없는 작업만 `builder`를 생략할 수 있습니다.

<include cwd lang="typescript">
  examples/http/place-input.ts#example
</include>

### `builder`의 필드 별칭 인코딩 방식

| Builder 표현식                                 | 전송 결과                                                       |
| ---------------------------------------------- | --------------------------------------------------------------- |
| `body: input.profile`                          | 타입화된 struct: `.alias()` 및 `Date` / `bigint` 코덱 자동 적용 |
| `body: { profile: input.profile }`             | 바깥 키 `profile`은 리터럴로 유지; 안쪽 객체는 struct 별칭 유지 |
| `body: { ...input.profile, role: "admin" }`    | 객체 전개 시 struct 별칭 유지; `role`은 리터럴                  |
| `body: { name: input.profile.customerName }`   | 익명 객체: 작성된 키 그대로 리터럴 유지                         |
| `query: input.filter` / `headers: input.trace` | 평면 타입화된 객체: 필드의 `.alias()`가 통신 키로 변환됨        |

### 커스텀 쿼리 직렬화

기본적으로 쿼리의 스칼라 값과 스칼라 배열(반복 키)은 직접 인코딩되며, 중첩된 쿼리 객체는 `REQ_BUILD_FAILED`로 실패합니다. 백엔드가 중첩된 쿼리 문법(`filter[status]=paid`)을 요구한다면 클라이언트에 `withQuerySerializer`를 구성하세요:

### 요청 본문 형식

`GET`과 `HEAD`는 본문을 가질 수 없습니다. 다른 메서드의 경우 `builder`가 반환한 값에 따라 본문 형식이 결정됩니다:

| `body` 반환값                                             | 전송 시 형식                                 | 기본 `Content-Type`                         |
| --------------------------------------------------------- | -------------------------------------------- | ------------------------------------------- |
| `undefined` / 생략됨                                      | 본문 없음                                    | —                                           |
| `urlencoded` / `formData` 코덱이 적용된 루트 struct       | `URLSearchParams` / `FormData` (별칭 적용됨) | 폼 형식 / 멀티파트 경계(boundary)           |
| 네이티브 `FormData` 또는 `URLSearchParams`                | 그대로 전달됨                                | 멀티파트 경계 / urlencoded                  |
| `Blob` / `File`                                           | 그대로 전달됨                                | `blob.type` 또는 `application/octet-stream` |
| `ArrayBuffer`, typed array, `DataView`, `ReadableStream`  | 원시 바이트 / 스트림                         | `application/octet-stream`                  |
| `string`                                                  | UTF-8 텍스트                                 | `text/plain;charset=UTF-8`                  |
| 순수 객체, 배열, 유한수, 불리언, `null`, `Date`, `bigint` | struct 인코딩된 JSON                         | `application/json`                          |

<include cwd lang="typescript">
  examples/http/body.ts#example
</include>

JSON으로 표현할 수 없는 값(`NaN`, `±Infinity`, `Map`, `Set`, 함수, `toJSON()`이 없는 클래스 인스턴스, 이터러블 등)은 `{}`나 `null`로 조용히 직렬화되는 대신 즉시 `REQ_BUILD_FAILED`로 실패합니다.

## 4. 응답 디코딩 방식

`output`은 `2xx` 응답을 검증하고, `error`는 비`2xx` 응답(`3xx`, `4xx`, `5xx`)을 검증합니다. struct의 종류에 따라 응답 스트림을 읽는 방식이 결정됩니다(`struct.string()` → 텍스트, `struct.blob()` / `struct.file()` → `Blob`, `struct.arrayBuffer()` → `ArrayBuffer`, 그 외 → JSON):

1. **`ok` (`200..299`)에 따른 분기**: `2xx`는 `output`, 비`2xx`는 `error`를 선택합니다.
2. **생략 시 읽기 건너뛰기**: 해당 측면에 struct가 선언되어 있지 않으면 응답 본문을 전혀 읽지 않습니다(`2xx`는 `data: undefined` + `HttpMeta`로 확인, 비`2xx`는 `data: undefined`인 `HTTP_STATUS`로 확인).
3. **JSON 미디어 타입 우선 확인**: JSON struct의 경우 본문을 읽거나 찾기 전에 `Content-Type`이 JSON이 아니면 `RES_MEDIA_TYPE_INVALID`로 즉시 실패합니다. 내용이 없는 응답(`HEAD`, `204`, `205`, `304`)도 다른 응답과 같이 선언을 따릅니다.
4. **본문 읽기 및 파싱**: 읽을 수 없는 스트림이나 잘못된 JSON은 `RES_DECODE_FAILED`(스트림 도중 끊긴 경우 `NET_BODY_INCOMPLETE`)로 실패합니다.
   내용이 없는 응답(`HEAD`, `204`, `205`, `304`)에는 읽을 본문이 없습니다. `struct.string()`은 `''`를, `struct.arrayBuffer()`는 빈 `ArrayBuffer`를, `struct.blob()`은 빈 `Blob`을 받습니다. 3단계를 통과한 JSON struct는 빈 바이트를 파싱하며, 이는 `RES_DECODE_FAILED`로 실패합니다.
5. **`struct` 유효성 검증**: 스키마와 일치하지 않는 경우 `RES_STRUCT_MISMATCH`로 실패합니다.

## 5. 작업 취소 및 마감 시간 설정 [#cancel-the-work]

단일 호출용 파생 클라이언트에 `signal`을 전달합니다: `client({ signal })`.

- **마감 시간 설정 (`NET_TIMEOUT`)**: `AbortSignal.timeout(ms)`를 사용하세요.
- **수동 취소 (`NET_ABORTED`)**: `AbortController`를 사용하세요.
- **신호 결합**: `AbortSignal.any([controller.signal, AbortSignal.timeout(ms)])`를 사용하세요.

## 6. 자격 증명, XSRF 및 전송 진행률

- **`withCredentials(true)`**: HTTP 및 SSE 요청에 대해 Fetch의 `credentials: "include"`를 설정합니다.
- **`withXSRF(options?)`**: `@defjs/core/xsrf`에서 가져옵니다. 브라우저에서 XSRF 쿠키(기본값 `XSRF-TOKEN`)를 읽어 동일 출처의 변경 HTTP 메서드(`POST`, `PUT`, `PATCH`, `DELETE`)에 해당 헤더(`X-XSRF-TOKEN`)를 주입합니다. `location`이나 `document`가 없는 런타임(Worker 포함)에서는 `withXSRF()`가 예외를 던집니다. 서버와 브라우저가 공유하는 코드는 이 옵션을 브라우저에서만 추가합니다. 다른 출처의 토큰은 인터셉터로 설정합니다. 동일 출처 검사는 라이브러리가 만드는 URL에 적용됩니다. Fetch는 리다이렉트를 스스로 따라가며, 다른 출처로 리다이렉트된 뒤에도 이 헤더를 유지합니다(`Authorization`만 제거합니다). 이를 거부하려면 [`withXSRF`](/ko-KR/api/core/withxsrf)를 참조하세요.
- **`onDownloadProgress` / `onUploadProgress`**: `client({ onDownloadProgress, onUploadProgress })`로 전달합니다. 다운로드 진행률은 `Content-Length`가 양수이고 `Content-Encoding`이 없거나 `identity`일 때만 `lengthComputable: true`를 보고합니다. 업로드 진행률은 요청 본문이 직접 넘긴 `ReadableStream`일 때만 보고됩니다. 그 밖의 본문(`Blob`, `File`, `ArrayBuffer`, `FormData`, 문자열, `URLSearchParams`)은 만든 그대로 보내지고, 모든 런타임에서 `onUploadProgress`는 호출되지 않습니다. `ReadableStream` 본문은 `onUploadProgress` 유무와 관계없이 스트리밍 요청 본문의 Fetch 규칙을 따릅니다. Chromium과 WebKit은 HTTP/2 이상에서만 받아들이므로 HTTP/1.1에서는 `NET_UNREACHABLE`로 실패합니다(Node.js와 Bun은 HTTP/1.1을 받아들입니다). Firefox는 요청 본문을 스트리밍할 수 없어 `ENV_UNSUPPORTED`로 실패합니다. 브라우저에서 교차 출처 요청은 캐시된 preflight 결과가 없으면 CORS preflight가 필요하며, 301, 302, 307, 308 리다이렉트는 실패합니다. 브라우저는 `Content-Length`를 보내지 않습니다. 로드 밸런서는 이런 실패와, throw하는 원본 스트림에 `{ attempted: false }`를 받습니다. `fetch`가 이를 도달할 수 없는 엔드포인트와 같은 네트워크 오류로 보고하기 때문이며, 따라서 스트리밍 업로드만으로는 다운된 엔드포인트를 감지할 수 없습니다. 자세한 내용은 API 레퍼런스의 `HttpProgressFn` 항목을 참조하세요. 진행률 콜백에서 예외가 발생하면 호출은 `EXT_OBSERVER_FAILED`로 실패합니다.
